## 3. D01–D08 v0.1 结构候选（未批准，按第0节重整）

下列 A 为推荐；B 为可行替代及主要代价。仅本节明确的逻辑字段组、关系和行为进入候选结构；不从示例推导未列出的字段、表或服务。物理类型、文件命名和 HTTP 路由属于落实这些语义的实现细节，不得借实现细节新增业务决定。

### D01：归属、存储与稳定身份

**建议 A：** 新资产使用 Host `dataRoot` 下独立 `personal-assets/` 增量根，保存版本化 JSON 元数据和受控内容文件；列表／关键词索引可重建。数据登记仍必须绑定现有 projectId；概念、知识和记忆属于当前个人本机资料根，保留来源项目／Case。现有 RAP、SAP、企业资料、Case、Board、Feedback、SimLab 继续原位存储，不复制成新权威，不合并现有 SQLite。

原因：当前资料模块已有文件与不可变修订模式；新根便于增量兼容，轻索引只承担查找。个人范围不是账号认证、团队授权或硬隔离承诺。

**替代 B：** 新增统一 SQLite 资产总库并把现有对象迁入；统一查询更直接，但扩大迁移、双写与回退成本，本轮不推荐。

推荐逻辑字段组：

| 字段组 | 必需性、格式与含义 |
| --- | --- |
| 库身份 | 新根首次显式写入生成并保留 UUID `storeId`，schemaVersion 初始为整数 1；未知 schema／损坏不重置 |
| 资产身份与粒度 | Host 生成 UUID；kind 仅 data／ontology／knowledge／memory。分别是一份项目数据登记、一个业务概念、一条可独立引用的知识、一条可独立判断适用性的经验；标题和路径不参与身份 |
| 归属 | data 的 projectId 必需且必须存在；其他三类归本 storeId 的个人范围。来源项目／Case 是 provenance，不变成所有者；不添加租户或角色字段 |
| 工作稿 | 名称必需且非空；说明、主题标签允许空。编辑修订为递增整数，用于陈旧编辑冲突；署名是可选用户文本，不假装认证身份 |
| 技术时间 | Host 写 ISO 8601 UTC 创建／修改／固定时间；业务发生时间、适用期另存用户说明或明确时间范围，未知可为空，不以保存时间推算业务时间 |

源位置由 Host 根据已核定身份解析；浏览器不能提交任意绝对路径决定读写位置。相同文件 hash 不自动合并不同项目的资产；相同名称不自动合并概念或经验。

### D02：引用、修订、来源与保留

**建议 A：** 新资产可编辑工作稿，概念／知识／记忆由用户保留时生成不可变修订，使用 UUID 修订身份和资产内递增展示序号；修改新稿不改变旧修订。数据任务采用时的固定规则见 D03。候选可以作为带明确性质的本次输入，但任务采用不自动使候选成为个人可复用的保留资产；其当时正文与来源沿本次交付记录固定，不冒用正式资产修订，不更新当前可用指针，也不进入个人默认召回。首次保留仍需满足该类最小内容，不要求填写所有可选项。

原因：历史能固定当时内容，工作稿又不必每次输入都形成正式修订；已有来源继续使用原 ID 和版本。

**替代 B：** 所有引用只存资产 ID 并读当前最新内容；编辑简单，但历史漂移，不能满足本轮验收。

- 版本化资产引用记录 kind、storeId、assetId、revisionId；本条约束数据固定修订及用户已保留的概念／知识／记忆。历史引用这些身份均必需，省略版本不表示 latest；新选择可以展示当前可用内容，发送前必须解析为明确修订。
- 未保留候选另以本次 projectId／taskId／requestId、候选 storeId／assetId／工作稿编辑修订、固定正文及其 SHA-256、当时来源和提供时间记录为请求支持快照。候选快照与资产修订引用在回执／sidecar中区分，不能为凑 revisionId 创建保留修订；它不进入默认资产召回。请求身份沿现有 native 回执，不另造会话或消息库。
- 来源引用采用现有类型的原生身份与最小适配：RAP／SAP 发布版、企业资料修订、Case／ProjectWork 固定上下文、任务／native entry、报告固定文件、核算记录、BoardItem／BoardTask／FeedbackRevision、推演快照。六类概念分类不限制 provenance 能引用哪些真实对象。
- 一条新资产修订可有多个来源；同一来源可支撑多个条目。知识与保留记忆至少一个可定位来源。缺失定位可以保存候选，并显示缺口，不能发布为“原文已核定”。
- 对没有不可变版本保证的报告／文件来源，在保留知识／记忆时按需固定已选择的来源文件；保留原项目身份、路径、字节数和 SHA-256，新副本只是该时点证据，不替换原件。不能仅保存旧 hash 后承诺旧内容可恢复。
- 精确文本位置沿用不可变 UTF-8 正文上的 UTF-16 半开区间，并显示实际片段。其他格式本轮可仅提供原件位置并显示“正文定位未取得”；不承诺 PDF／Office 自动精确抽取。
- 路径是 locator，SHA-256 是内容校验；二者都不替代逻辑身份。所谓不可变是 Host API 不覆盖、独立文件保存并读回校验，不宣称普通全工具 Agent 已获得操作系统级不可改保证。
- 首期保留已固定修订、来源副本及失败现场，无自动物理删除／空间回收。归档只改变发现与新选择，历史仍可回读；后续清理与保留期需要另定规则。

### D03：Data 粒度、扫描与采用时快照

**建议 A：** 首期登记项目 `020_clean` 中 UTF-8 CSV（含表头）和 JSON 对象数组；登记与浏览不复制全部数据，任务明确引用或用户明确为概念字段映射固定数据时，固定数据字节及对应描述。首次建立映射可在概念界面显式固定所选数据，复用同一校验与快照保存，不要求先启动一次分析任务。跨项目数据使用先由用户明确选源，通过受控复制进入目标项目 `020_clean`，创建目标项目自己的登记并保留源引用；不让 Case 当前项目校验接受任意外部路径。

原因：复用项目文件边界，避免一次登记就长期备份全部数据；任务的固定输入和报告来源可以一致。`010_draw` 继续沿现有原件／020复制规则，不借登记入口暗中读取原始区资料。

**替代 B：** 仅存路径与指纹、不保留字节；占空间少，但文件覆盖后只能报告无法恢复，不支持关键输入的历史回读。若选 B，须同步收窄验收中的可复现主张。

| 字段组 | 必需性、格式与含义 |
| --- | --- |
| 文件定位与观察 | projectId、项目内相对路径、格式、非负字节数、SHA-256、观察时间必需；mtime 只作文件属性。Host 校验真实文件、归属和路径，不能由客户端 hash 证明字节 |
| 结构观察 | 对应文件 hash、扫描时间和完整／失败／不支持结果必需；字段名与类型数组、非负整数行数仅在已取得时保存，未知为空，0 与未知分开。完整扫描才给准确行数，不把样本行数冒充总量 |
| 字段类型 | 使用本期解析器声明的结构类型，混合／空值如实表达；嵌套 JSON 值保留为 JSON 类型，不自动拍平或推定业务含义。重复／无法唯一定位的 CSV 列给出明确限制，不猜映射 |
| 业务说明 | 一行代表什么、关键字段、时间字段、单位、来源、限制均可为空；记录用户确认或待确认说明。自动扫描不自动把粒度、主键或单位标为已确认 |
| 固定修订 | 采用前校验预览对应的工作稿与文件身份，保存输入字节、指纹、当时结构观察与业务说明；实际提供的位置必须指向该固定内容。准备期间变化／复制不完整则不创建成功回执，不静默采用新文件 |

结构扫描是文件格式检查，不补经营计算。扫描或保存超过实际技术能力时准确报错，不裁剪后宣称完整；实施须以现有文件准入和实测资源约束为依据，不新增分析方法／工具次数配额。重发同 requestId 复用原固定结果或返回冲突，不能反复取新数据并改变既有请求含义。失败或取消后已生成的快照保留，不自动重放任务。

### D04：Ontology 与指标权威

**建议 A：** 一个概念保存名称、定义、别名、属性说明、来源和适用范围；轻关系是有方向的“本概念→关系说明→目标概念修订”，允许多对多，不预建关系推理体系。字段映射引用精确 Dataset 修订及字段名，确认程度区分已确认／推断／未知；指标关联固定现有 SAP 发布身份。

原因：能向 Agent 解释业务含义，同时避免概念库成为第二套指标引擎。

**替代 B：** 本期只保存自由文本术语表，暂不提供字段映射和轻关系；成本低，但无法完整满足文档的 Ontology 最小验收。

名称与定义为保留修订必需内容；别名、属性、关系、字段映射可空。映射双方必须存在且可定位；同一概念可映射多个字段，一个字段也可有多个明确解释，冲突显示，不由 Host 裁决。来源可为明确用户定义、SAP 或带原文位置的资料；“用户定义”保留为这种性质，不伪装外部权威证据。不复制可独立修改的正式指标公式。

### D05：Knowledge 来源与候选

**建议 A：** 条目保存标题、正文、陈述性质、主题、适用说明和一个或多个精确来源。陈述性质采用事实陈述／制度／观点／推断／假设；它描述内容性质，不表示 Host 已判断其正确。方法内容可以保存为知识解释，不因此加载可执行 skill。

原因：现有 EnterpriseMaterial 已能保存原文与修订，Knowledge 只需承载可引用的整理成果。

**替代 B：** 只给原资料添加分类、不建立条目；更轻，但不能单独引用某条知识解释及其原文依据。

标题、正文、陈述性质及至少一个可回读来源为保留修订必需；主题、业务域、适用期／范围允许未知。Agent 或用户可先存草稿；进入可供复用的保留修订由用户显式决定。用户修订文字不改来源原文；来源失效／内容冲突保留提示和历史，不自动把另一份资料设为正确。原文缺失不妨碍普通分析发消息，只影响这条知识能否声称来源完整。

### D06：Memory 的形成、性质与召回

**建议 A：** 从报告完成、明确决策或反馈等工作里程碑提炼候选，不要求整个 Case 已完成。每条摘要是可独立判断适用性的经验，保存标题、摘要、来源、主题、时间／范围和已知局限；用户保留、编辑、忽略或归档。候选生成沿用户显式发起的普通项目任务，不自动加模型调用、专用记忆 Agent 或第二套循环。

原因：长期 Case 也能逐步积累经验，选择性记忆能保留失败与未知，并减少全量历史污染。

**替代 B：** 仅在 Case 结束后由用户手写记忆；实现更轻，但长期事项难以及时复用。

标题、摘要、至少一个明确来源为保留修订必需；主题、适用范围和业务时间可未知但必须显示未知，不能强迫用户凑表单。反馈来源固定 feedbackRevisionId；没有反馈明确“未取得反馈”，不填成功。记忆不建立 Hypothesis／Strategy 独立实体，支持／反对／未知可以在摘要和来源中保留。

个人范围默认按关键词／主题找当前可用的保留修订；候选、归档、过期／冲突内容需显式区分和查看，不无提示混入当前结论。召回展示来源、业务时间、保存时间、范围和局限，不按成功次数自动评分或晋升。Agent 可自主查找并重新判断适用性，用户也可手动选入，不强制人工逐条批准普通检索。

记忆至少区分来源为用户陈述、分析判断、实际反馈、模型推演等性质；混合来源分别列明。SimLab 快照／导出报告保持推演性质；模拟反馈、合成工程场景不能进入“真实行动效果”陈述。保留记忆表示值得参考，不表示事实已证实或策略有因果效果。

### D07：读写入口、上下文与成果引用

**建议 A：** 用户通过登记／编辑／保留／归档入口写入；Agent 通过现有授权目录和工具自主检索，显式请求后形成候选，再由 Host 核验结构并保存。复用当前任务发送、请求指纹、原生 v1 `providedContext` 可选字段和历史读取。Case／任务关联以新根 sidecar 记录原 ID 与来源库身份，不改严格校验的 Case SQLite 或原项目 schema。

原因：已存在统一消息交付路径，能保留当前 requestId、owner 与取消语义；业务资料无需成为运行编排系统。

**替代 B：** 建立专用记忆／检索 Agent 和独立上下文台账；增加循环、生命周期和历史权威，本轮不采用。

- 关联为 Case／Task→零到多个精确资产引用；一个修订可用于多个任务。Case 绑定包含 caseStoreId；任务绑定包含现有 projectId/taskId。取消当前关联不删除修订，也不修改过去请求。
- 不混用草稿选择与实际提供记录。新字段缺失保持 legacy 行为；新选材参与原请求 fingerprint，同 requestId 选材变化返回冲突。只保存实际提供的修订／正文范围／目录位置和时间，继续标为 provided-not-adopted。
- 报告明确引用另记录为报告固定文件身份→来源列表及声明者；来源可由 Agent 明确给出或用户补充，展示声明性质。Host 校验可解析性，不从“已提供”、词语出现或工具次数推断采用，也不以引用不足驱动自建补分析循环。
- 报告工厂／PPT 可引用原报告来源链；生成演示稿不自动晋升知识或记忆，未记录的引用显示未记录。
- 工程规范 v1.3、Interface v3、IN01–IN07；复用 `project-tasks` owner/profile，即现有 projectId＋taskId。不注册四库域，不改变工具选择、模型、会话启停／恢复或固定出稿／冷读材料合同。
- 普通任务使用已授权可读目录；受管任务只能通过既有准备与受限执行边界提供已核定内容，不因新增资产而放宽到整个 dataRoot。若当前边界不能表达，须记录具体缺口并补最小接入决定；不得回落全工具或在可信驱动内执行 Agent 代码。
- 候选保存、版本核验、技术格式错误反馈由 Host 处理；语义选择、分析路径、计算与纠错由 Agent 自主处理。人工保留不成为普通分析前置门槛。

### D08：状态、兼容、失败与回退

**建议 A：** 本期只有可编辑工作稿、用户保留的不可变修订、当前可用指针及归档标志。Agent 候选是工作稿的来源性质；映射确认程度、知识陈述性质、业务失效／冲突说明分别表达，不揉成全域状态机。失效／冲突可以由用户标记并说明，Host 不自动裁定业务真伪。

原因：能准确表达本轮需要的差异，同时保留既有历史和旧代码兼容性。

**替代 B：** 全域统一 draft／approved／success 等状态和自动晋升；容易把保留、正确、执行与效果混淆，本轮不采用。

- 初次只读不创建新根；首次显式登记／保存才初始化。缺少新增记录表示尚未登记，不触发扫描全部旧项目或导入会话。
- 工作稿保存核对预期编辑修订；陈旧编辑冲突拒绝。单 Host 文件保存采用新内容先落盘、核验后原子发布指针；索引失败可重建，不能将半份修订设为可用。锁只覆盖短文件操作，不包含模型运行或分析步骤。
- 解析分别表达：对象不存在、修订不存在、来源缺失、内容已变、访问不允许、格式不支持、扫描不完整、正文位置未取得、未知 schema／损坏。明确所选材料不满足固定合同则拒绝该次交付并反馈具体问题；可选目录不可用不得伪装成“没有资料”，普通无资产消息仍可发送。
- 原项目归档规则保持：不新增该项目数据登记、快照写入或任务运行；已有历史固定内容可回看。个人知识／记忆的来源项目归档不自动删除其来源；归档与当前观点是否有效分别显示。
- 停用／归档资产不进入当前可用索引，不接受新的活动引用；历史引用保留。若需重新使用，由用户显式恢复可用性或基于明确来源另建条目，不能默默改回 active。
- 不改写原 Case／Board SQLite、项目 JSON、RAP／SAP 发布物、企业原文、native 会话／父链或旧 FAIL／UNKNOWN。新关联在 sidecar；新 native 回执只追加本次真实记录，旧缺字段不回填。
- 旧代码回退后可读旧业务对象但不展示新增资产；新增根和新回执保留，不覆盖为旧数据备份。不得在活任务中切换代码／存储。若实施需改变旧持久结构，本包不授权该变化，需补充具体迁移与回退决定。
- 主要索引是可重建列表／关键词 ReadModel；本期无 SQL 表、数据库索引或跨库事务，故对应 DDL／迁移不适用。各来源读回独立校验身份，缺失有明确结果，不假装跨域原子一致。

## 4. 推荐顺序与验收

依赖顺序：D01 归属 → D02 身份／来源 → D03–D06 四类对象 → D07 消费／回执 → D08 兼容及完整链路。阶段门是工程组织，不固定产品 Agent 的内部执行步骤。

| 标识 | 可观察验收 |
| --- | --- |
| PA01 | 六类分类映射明确；新增持久资产仅四类，不新增假设／策略结构、全局工作台、生命周期或业务执行 |
| PA02 | 支持格式的数据可登记／扫描／说明粒度，任务引用时固定字节；修改原文件后旧任务仍读原固定内容，准备时变化或缺失明确报错 |
| PA03 | 概念能关联精确 SAP 与数据字段；已确认／推断／未知不混淆，更新概念不改旧引用 |
| PA04 | 知识能从指定资料修订定位原文；候选与保留、原文与解释、定位未取得清楚可辨 |
| PA05 | 从明确里程碑形成记忆候选，人保留／修订；第二个 Case 通过关键词／主题找到并显式复用，来源／时间／范围可见；失败与无反馈不写成功 |
| PA06 | 可发现、实际提供、报告声明引用分别展示；Agent 在现有授权工具内自主工作，无新增逐步确认／固定方法／分析循环 |
| PA07 | 归档、过期／冲突、文件变化／缺失、版本缺失、陈旧编辑、保存中断、取消、重复请求、重开与旧记录兼容得到适用验证；无自动重放／换模型或旧资料覆盖 |
| PA08 | 本机真实入口可完成 Case A→来源清楚的报告→保留记忆→Case B 找回；跨项目数据经明确复制保留来源；SimLab 模型输出与实际反馈持续区分 |
| PA09 | 实施候选完成适用完整检查、原有 RAP＋SAP＋Case／反馈及受影响 PPT／推演回归、非作者独立复核与工程规范职责边界／SDK 复用检查；工程、模型专业质量、产品验收和 Git／部署分别报告 |

工程样例必须标注合成性质，不能把模拟反馈算真实效果。用户体验的具体 Case、数据／报告版本、反馈修订与判断基准尚待指定；未选择不妨碍设计和隔离工程检查，但不能宣称完成真实产品体验。新真实 Provider 实验保持暂停；没有该项授权时使用适用合成 Provider 验证工程接线，并明确专业效果未验证。
