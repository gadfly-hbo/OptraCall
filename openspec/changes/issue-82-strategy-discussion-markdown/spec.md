# #82 战略讨论回复的 Markdown 展示

[问题反馈](https://github.com/gadfly-hbo/OptraCall/issues/82) · 基线 `d05a7b3706b987f64d9d6fa72ea14869fba1efdd`

反馈中的「沿原讨论背景」「重读原讨论」定位到「与 Agent 讨论战略」。现有对话记录把已保存回复和实时回复放在纯文本段落中，`white-space: pre-wrap` 只保留换行。原截图未上传，开发和验收使用合成回复。

## 验收

| 编号 | 结果 |
| --- | --- |
| MD01 | Agent 回复默认渲染 Markdown 标题、中文行内加粗、列表及含分隔行的表格。用户沿现有方式阅读，无需模式切换或新设置。 |
| MD02 | 实时回复与保存后重新打开／重读的回复共用显示规则。未写完的语法依现有文本可读，表头和分隔行齐备后才形成表格。保留合法的同文回复及现有去重行为。 |
| MD03 | 宽表在回复内横向滚动；窄窗及深色模式可阅读。用户原话、准确来源原文、现有导航和输入操作保持现状。 |
| MD04 | Host 前端用允许的 React 元素展示模型文本。任意 HTML 按文字处理，图片不会自动请求，拒绝不安全的链接。显示不改写历史原文，不触发模型或外部操作。 |

## 范围与做法

正式改动限战略讨论消息体及样式、用到的 Markdown 展示代码、定向回归与本记录。其他对话未由本报告证实，先维持现状。直接声明 Pi TUI 已锁定的 `marked@18.0.11` 和 `marked-cjk-friendly@0.1.2`，处理中文引号和百分号紧贴加粗标记等输入，保留 Pi SDK、Runtime、模型和存储契约。Marked 仅负责解析语法，Host 以受限 React 元素呈现。Agent 仍自行决定回复内容。参见 [Marked 安全说明](https://marked.js.org/#usage)及 [Lexer 文档](https://marked.js.org/using_pro#lexer)。

UI Demo 使用合成文本，可对照当前显示、预览默认渲染并模拟实时输出。比较和模拟控件仅供审核。2026-11-18 用户明确回复「通过，按此实现」。获批 Demo 的 SHA-256：`477b55a965879db7f57b012c75e95bd29c6d49a2d3704b39249d632a960fe059`。
