## 接缝与权威

1. **准确目标。** 复用 `StrategyGoalsStore.read(ref)`，轻量 seed 和已确认项目执行上下文提供准确正文/来源身份；原 Goal 为唯一权威，原确认和 native 留当时实际交付记录。不把最新目标值回填旧确认，不增加通用目标库或用户重复输入步骤。
2. **方法影响。** 复用原 SAP 已知错误状态/准确读拒绝。准备和保存不因已知错误方法禁止 Agent 解释；实际执行按本 Task 的准确选版及当前治理检查。草稿是建议，确认才承接所选工作；Host 不代选替代方法。保留原未选/暂缓项、独立任务、失败与未知，不放宽 SDK 工具权限。
3. **GSA→Board。** GSA 管理安排保存目标准确版本、上层安排/检查、多个原行动引用及操作来源。原 Board 仍唯一维护具体行动和独立授权/反馈；沿原 Store 幂等/操作回执。无 Case 分支只扩原工具业务资格，已有 Case choose/auth/feedback 行为保留。Host 从真实当前请求/确认回读工作身份，模型不自填 owner、权限或任意目标资格。没有目标不能伪造 GSA；明确 Board 工作可单独安排并说明管理承接不适用/待确认。
4. **聊天成果。** 一次安全 native 扫描同时列原报告绑定及无报告请求最终回复。回复要绑定同 session/祖先链中的准确已完成 run/request/message/hash；实际正文沿原 `readPersonalSource`/native-reply 读口，不另解析/重建正文权威。发现不等于已读，前后重新核确认范围和身份。
5. **数据库。** 复用原 `DbLinkStore`、grant、connection revision/fingerprint、Task policy 和 model-export。新增 Host-only 元信息投影，严格白名单。准备时使用同一原租约实际捕获模型，不能读取一份全局快照后假定等于执行模型。确认记录引用只表达本次来源使用意图，不新建权限或替代 DB port。
