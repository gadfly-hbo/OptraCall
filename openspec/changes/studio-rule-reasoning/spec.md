# Studio 规则推理最小闭环规格 v0.1

2026-11-12 · 待用户审核 · 仅方案与静态 UI Demo，暂不开发

依据：[方案 v0.3](../../../docs/enterprise-foundation/foundation-proposal-v0.3.md)、[Demo](../../../docs/prototypes/studio-rule-reasoning-v0.1/index.html)、[状态覆盖](interaction-states.md)、[目标任务清单](tasks.md)。用户已认可方向，当前具体合同、UI 及实施尚待审核。原批准资产包和首批确认稿保持原字节，[52文件保全清单](baseline-manifest.json)是原件身份，不是新产品完成证据。

## 1. 目标与边界

让主数据、指标体系、本体建设中的部分共享规则具有可核定、可执行、可追溯的表示，建设 Agent 可试验候选，普通 Pi 可按企业资格自主使用准确正式规则；规则修订、新版再用及旧报告依据有完整记录。

首批仍为运动鞋服共享经营骨架＋会员运营核心、两条参考路线与企业基础层／任务演进层。企业规则由获准资料核定；参考、候选及演示不取得正式企业资格。不预设首购复购分析题，不要求所有知识形式化或全部资产先入图。

本轮仅允许新增本变更目录、`docs/enterprise-foundation/foundation-proposal-v0.3.md`、`docs/prototypes/studio-rule-reasoning-v0.1/`。不改产品源码、依赖／SDK、旧审核文件、正式企业资产、数据根、服务或设备；不模型实验、Git提交或CI。Demo只在内存中运行预置分支，无产品 API／网络 SDK调用。

| SAP 原定义、场景和方法，Binding及数据上下文 | 将准确规则引用及派生事实作为资格／计算依据，不复制公式或执行大表聚合 |
| 官方 Semantica 0.7.0、当前 Python worker／取消／准确来源检查接缝 | 公开 Reasoner 和约束校验调用及可解释回执，实际SDK行为由I01核；不自建推理器 |
| 企业目录及普通 Pi 自动发现、任务原会话／成果 | 让普通任务发现可执行规则的准确用途及数据条件，按需执行、解释并固定证据 |
| 原Studio工作台、检查、预览、使用及历史 | 按原位置增加可执行范围、事实缺口、结论／前提、失败及版本影响查看 |

当前 `qualifyFoundationBody` 只校原结构／准确引用及资格，不评经营真值；正式图仅识别顶层 entities／relationships，新 profile 不自动完整入图。原图及纯文本仍可用，最小执行可从准确源直接投影规则与事实。

## 3. 官方复用及支持范围

现有锁定目标为官方 Semantica 0.7.0。官方公开源码显示 `Reasoner` 可接规则／事实并返回结论、规则、前提；`OntologyEngine.validate_graph` 可执行 SHACL 校验。网页源码不代替本机 wheel／真实调用验证。[Reasoner](https://github.com/semantica-agi/semantica/blob/v0.7.0/semantica/reasoning/reasoner.py) · [OntologyEngine](https://github.com/semantica-agi/semantica/blob/v0.7.0/semantica/ontology/engine.py)

未来 I01 先对实际安装及公开接口核对、实跑最小正负／未知／链式边界，不改包、不升级。差异保留为不支持或阻塞项，不能以同名API或新文档假定已有能力。不引入新Python依赖；若实际必要，先列差额再取得相应授权。

首批执行合同只接受：有限获准事实、无环规则依赖、正向合取条件与显式结论。复用官方规则对象／事实接口；适配层核支持表达及准确引用，不另建规则语言、表达式解释器或调度循环。谓词参数与现有对象身份／命名空间对应，不把名称相同当同一实体。

不接递归、否定即失败、聚合／数值公式、任意函数／回调、引擎动作、自动身份归并或自动政策冲突裁定。日期／金额等已有计算工具产生的事实必须带计算依据和输入版；适配器不代算经营值。I01若无法以公开接口可靠支持上述子集，受影响用途保持不支持，不能静默放大或换引擎。

SHACL仅核所选用途明确的类型／关系／字段等约束；不从模板自动生成企业业务政策。规则表达核验、事实质量、引擎执行及经营解释分别验证，任一技术PASS不等于企业规则正确。

## 4. 内容、版本与事实合同

### 4.1 同一规则修订

拟以显式新 profile `studio-foundation/2` 承接原三类字段并可选增加 `ruleExecution`。它仍序列化在原 Studio body，沿原assetId／revision／hash管理；不是另一个主库。原 `/1` 和纯文本按原方式可读／修订，未选择执行化不自动改写。未来实现必须先验原解析器兼容，不直接把新字段塞进严格的 `/1` 或 SAP0.2。

以下是逻辑合同，不是当前可调用 API：

| 内容 | 必需语义 |
| --- | --- |
| rule item | 原稳定 itemId、可读定义、企业／用途、生效期间、来源、治理身份 |
| execution projection | 对应 ruleItemId、合同版本、官方引擎／版本、官方规则条件及结论表示、明确支持类别；与同一修订绑定 |
| predicate references | 谓词及参数对应的对象／关系／状态 item、类型和命名空间；常量／变量按公开接口支持范围校验 |
| fact requirements | 所需来源、字段／事件、Binding、粒度、单位、时间基准、覆盖／缺失要求、数据事实与外部计算事实区别 |
| evidence／readiness | 正常／反例／缺事实／边界的实际证据、所核用途；沿原定义／映射／计算／使用四状态，作者声明与独立结果分开 |

可执行表示由 Agent 起草，和制度含义逐项核查；只认结构正确不够。改定义、规则、事实需求或关联源即形成新候选，使相应旧检查及预览失效。旧原件、原失败、历史及正式指针保留。

### 4.2 事实与来源

事实从获准的实际数据／事件，或附有依据的原计算结果中投影。冻结输入版本／hash、粒度、身份、记录／字段定位、业务有效时间与提取截止；缺失不是零或false。跨系统身份关联沿已核Binding，不由规则引擎猜同人。

派生事实是执行结果，不能冒充原观察事实或自行写回源记录。一次执行中的结论可以被官方引擎继续用于同一获准无环链，保留依赖依据。不得跨企业、跨任务或跨输入版本复用活跃引擎事实内存。

Agent提供的外部计算事实及声明要保留其来源性质和产物引用；Host核准确来源及权限，不凭字段同名或作者声明认定事实已经独立核验。建设回执仅作核验依据时不自动成为普通消费者读取建设会话的必需依赖，沿原 evidence／required-dependency 区分；普通任务得到自身调用回执，不借此取得建设会话访问权。

## 5. 工具与生命周期合同

优先扩展现有语义工具接缝，逻辑 action 称 `reason`；它与原图查询操作区分，不把关系遍历说成规则执行。不先新增MCP服务或插件；具体薄接口在原Host port内实现，适配前按IN06核共享消费者。

### 输入（由 Host 和 Agent 分担）

- Agent：目标用途、原规则准确Ref＋itemId、获准事实输入及Binding准确引用、需要说明的目标对象。不得传SDK路径、凭据、业务动作或源代码处理器。
- Host：绑定真实 enterprise／project／task／operation、调用资格、来源读取与指纹、组件版本、资源预算及取消上下文。企业关联不代替数据许可。
- 建设写者：仅可试验自身合格候选及获准材料；普通消费：仅当前有资格的准确正式源。原只读工具不因此获得建设或发布动作。

### 输出

| 组 | 内容 |
| --- | --- |
| execution identity | 请求与真实任务、企业／用途、引擎与适配合同、规则修订／hash、事实与Binding／SAP准确身份、覆盖／截止及指纹 |
| completion | 完整／不完整／不支持／取消／失败；实际处理范围及限制。受限或中断不记完整 |
| conclusions | 派生结论及官方规则、前提，补原SourceRef与记录定位；引擎confidence不标成业务概率 |
| assessment | 对目标的已推出、显式不符合、事实不足、冲突等结果；未推出单独表达，不能当显式不符合 |
| receipt | 实际调用、读取范围、限制、错误及可访问证据，沿原任务成果／使用记录关联；不新建可编辑事实库 |

规则预算、事实量及推理边界由Host提供环境限制；完整性按I01所核支持合同确认，无法证明完整或达到边界则返回不完整。超时／取消不以空结果冒充完整零结论。不支持不自动改用LLM并包装成相同引擎成功。Agent可在原授权内选择其他方法，明确其不同证据性质。

接入沿[IN01–IN07](../../../docs/engineering-workflow.md#统一会话接入规范当前interface-v3兼容v1v2业务子集)及[公共会话说明](../../../docs/agent-session-integration.md)。Interface v3、主owner为真实project-task；复用现有worker及父operation取消／关闭接缝，不新增模型会话、Runtime或平行占用状态。SDK调用是工具工作，不把业务规则选择交Host。若现公共合同不足，实施前记录具体差额，不能绕过公共契约。

## 6. 发布、消费与演进

沿原预览冻结准确源修订／哈希、规则用途及支持范围、所需事实条件、三类关联与实际检查。先核必要依赖；定义参考、规则执行、指标计算用途分别表达。关键FAIL／UNKNOWN阻断对应用途，独立合格定义可排除受限部分后发布。发布不表示运行了引擎、事实齐全或实际使用通过。

普通任务自动取得同企业合格正式目录，按需读取／执行；调用前和结果返回前核原来源资格。目录可见、实际读取、引擎调用、作者采用及独立核验分别记录。执行不要求用户逐规则勾选，不强制所有问题使用引擎；图未刷新仅限制依赖图的用途。

新任务按当前合格正式组合发现；已运行任务的规则／SAP／输入版固定，来源失效需明确限制，不能默换latest。历史报告保留原依据和当时回执；历史可读不使失效来源恢复当前使用资格。

普通任务反馈沿原contribute形成仅本案或企业修订候选，不直接修改正式规则或自动启动建设。修订核三类影响，准确发布后由独立新任务验证新版。无自然变化可用明确合成情境验证工具，不能冒充目标企业政策变化。

## 8. UI 审核合同

延续原 Studio“企业基础资产／建设与演进／发布与使用”，普通任务仍在自己的工作台。基础层显示三类关联与规则支持范围；建设者查看候选／事实／检查；发布预览列用途和准确组合；普通任务按需展开实际读取／调用／前提与限制；历史固定旧版。自然语言目标、原资料／SAP管理继续复用，不增加必填规则语言或配置页面。

所有Demo企业、样本、规则、报告、回执及结果都是预置合成状态。样例从“正常＋宽限”变为“仅正常”仅演示版本，不代表Nike或目标企业政策，原版不是被故意制造的错误。自定义编辑不能借预置“检查通过”获得就绪资格；必须明确回到受控样例才能演示其固定结果。

细项见[交互状态与点击路径](interaction-states.md)。本轮不创建真实接口或运行工具，开发、Git／CI、设备及企业采用均未启动。
