# Studio 二期交互状态矩阵

版本 v0.1 · 2026-11-12 · 配套[设计规格](spec.md)与[可点击 Demo](../../../docs/prototypes/studio-phase2/index.html)

本表区分产品期望与原型可模拟的界面状态。Demo 只使用内存合成数据，展示的 Agent 活动、回执、报告和资格是预置演示，不能证明真实持久化、模型判断或产品接线。实际覆盖结果在[准备结果](result.md)记录，未走验项保留待验证。

## 原型评审控制

评审场景控件单独折叠，正常用户路径不要求选择场景。预期稳定入口为：

- 三视图：`tab-foundation`、`tab-evolution`、`tab-publication`。
- 企业切换：`company-select`，A 企业（合成）与 B 企业（合成）；B 企业显示空库。
- 分类、搜索与详情：`category-<id>`、`asset-search`、`asset-<id>`。
- 主路径：`create-foundation`、`open-task`、`open-candidate`、`prepare-preview`、`confirm-publish`、`query-receipt`。
- 场景选择：`scenario-select`，支持 `success`、`partial`、`unknown`、`conflict`、`archived`、`unassigned`、`empty`；切换场景会重置内存种子状态。
- `reset-demo` 恢复原型种子状态，不能影响业务数据。
- 合成旧报告 R01 固定指标 `1.2.0`，企业修订候选目标 `1.3.0`。

具体控件和场景与原型作者核对后，以实际候选及浏览器记录为准；DOM 调试状态仅辅助检查，不能代替点击路径。

UI19 中真实取消、迟到 owner 与持久化副作用，以及 UI17 中真实来源准入，本轮最多验证其界面表达；公共生命周期和访问拒绝不能凭演示状态标记产品通过。

## 后续产品验收需要补证的范围

| 范围 | 原型能核对什么 | 真实产品仍须证明 |
| --- | --- | --- |
| 企业身份与旧资料归属 | 可见范围、待核状态和候选归属体验 | Host 的准确准入、跨企业拒绝、历史兼容及来源字节保全 |
| 候选和版本 | 页面状态、差异、历史引用及分项结果展示 | 原专业库真实写入、CAS、并发、幂等回执和失败恢复 |
| Agent 与公共生命周期 | 主工作台、任务出处和运行状态的预置投影 | 原 SDK 原生会话、owner/profile、取消、迟到和关闭行为 |
| 新任务与运行任务 | 新旧版本显示及默认目录体验 | 准确来源资格、运行快照不漂移、实际读取和使用记录 |
| 会员专业质量 | 口径和限制应怎样展示 | 获准资料下身份、首购、观察期、复购计算、解释和修订再用正确性 |

原型未模拟的接口、安全和专业行为不列为浏览器通过；实现后的适用验证仍按[规格](spec.md#会员场景与验证分层)与工程规范独立执行。
