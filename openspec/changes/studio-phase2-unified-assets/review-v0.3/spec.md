# Studio 二期统一资产建设与实际使用规格

版本 v0.3 · 2026-11-12 · 完整设计候选，待用户审核

## 目标与当前授权

将 Studio 建设为企业统一的语义与分析资产中心，整合企业业务资料与 SAP 指标、分析方法的管理体验，同时支持企业基础资产的提前建设和 Case／项目／任务中的持续演进。建设管理和实际消费使用是同等主线：普通用户在 Case、项目或任务中直接提问，Pi Agent 自主发现与准确读取适用正式资产，使用获准数据计算、分析和形成有限决策建议，保留证据并按需回源。二期以会员运营验证两条主线贯通。

用户已认可统一管理与两层建设方向，并进一步授权完整补齐实际使用主线，更新方案、spec 和可点击 UI Demo。原方案与评审包保留；本候选的具体界面和推荐决定尚待审核。当前仍不开发产品、不生成企业正式资产、不启动真实 Pi／模型实验、资料迁移、Git 交付或运行采用。

输入为[二期方案 v0.3](../../../../docs/studio-phase2-proposal-v0.3.md)。原[初稿 v0.1](../../../../docs/studio-phase2-initial-proposal.md)、[方案 v0.2](../../../../docs/studio-phase2-proposal-v0.2.md)、[上一版规格](../spec.md)和[上一版 Demo](../../../../docs/prototypes/studio-phase2/index.html)保留原路径与字节。配套[新版可点击 Demo](../../../../docs/prototypes/studio-phase2-v0.3/index.html)、[交互状态矩阵](interaction-states.md)及[本版准备结果](result.md)共同构成完整审核材料；旧检查结论不移作本版通过。

本轮新增 `docs/studio-phase2-proposal-v0.3.md`、本目录文档和独立 `docs/prototypes/studio-phase2-v0.3/` 原型。产品 `src/`、`extensions/`、持久数据、依赖、锁文件、模型配置和既有验收记录保持只读。原型仅使用合成资料及内存状态；确定性计算在原型本地执行，目录、读取和 Agent 分析内容为演示投影，不调用业务 API、Pi SDK 或模型，刷新可重置演示状态。

## 两层模型与责任

### 企业基础资产

保存本企业有明确来源、适用条件及正式版本的资产，供同企业、相应权限下的 Case／项目／任务按需查找和使用。分类为企业资料、语义与主数据、数据映射、指标、方法。

企业资料属于依据，保留工作稿、已启用修订、停用和来源原件；“已启用”不表示业务含义已经核实。本体源稿、Binding、指标和方法保留各自正式规则与专业主库，统一界面访问同一对象，不能另造一套公式或方法权威。

### 任务演进

建设工作可以来自提前建设，也可以来自具体业务任务的新资料、发现、纠错和政策变化。候选保留来源 Case／项目／任务、原报告或原文、所基于的准确资产版本、拟修改内容、适用范围和检查结果。

两类建设共用项目任务和统一 Agent 会话能力。企业资产有持续归属，项目任务是实际执行和来源归属；本次不建立无项目 Agent Runtime。行业、领域和标杆公开实践是建设输入，不是第三层企业正式资产。

Agent 自主检索、比对、选择工具、计算、核查和修订。Host 管理身份、资源资格、权限、生命周期、准确保存、冲突检测及实际回执。人工提供获准资料，处理证据无法决定的业务取舍和必要正式发布决定，无需逐节点审批或搬运已有结果。

## 普通分析的实际使用主线

### 默认任务上下文与入口

用户可从 Case 或项目打开原分析任务，直接提出业务问题，无需先进入 Studio、逐资产选择或确认普通读取。单企业沿当前 Case／项目的明确归属默认企业范围；Host 提供真实任务 owner、已批准的企业范围、可用正式资产目录及版本位置、获准材料与现有工具能力。多企业归属不明时只处理必要范围决定，未确定前不借用其他企业资产。

目录只提供可发现线索，完整正文按需取得。Host 不把全部资产灌入上下文，也不替 Agent 预定必须使用哪些指标、方法或图。正常分析可先取数据、先读定义、先计算或回源补证；下述证据链用于观察结果，并非固定调用顺序。

### 准确读取与适用判断

Agent 根据问题检索候选，读取所需准确定义、数据映射、方法、适用条件、时间范围及原文依据。对结论和计算必要的定义，应读到足以核定规则的正文；出现分页、片段、continuation、partial 或缺口时按原合同继续读取或明确限制。只取得标题、索引、摘要或局部内容时，不得宣称已读全文。

读取身份包含原资产／来源 ID、确切版本或修订、已有可核内容摘要和实际交付范围；不将缺版本改为 latest，不把图派生 ID 当源记录身份。跨调用版本变化或 continuation 失效时，Agent 重新核对相应对象，不能把不同版本片段拼成完整定义。

Agent 说明本次采用、拒用、保留待核或使用临时依据的实际情况。是否适用由业务问题、企业范围、时间、数据粒度、字段映射和前提共同决定。同名资产、正式发布或查读成功均不能替代适用性判断。临时依据只能在原授权和充分证据内用于本次分析，明确来源、用途和限制，不自动进入企业标准。

### 数据计算与分析判断

Agent 从获准数据取得实际计算输入，核对会员身份、交易与退款关联、去重、状态和粒度，记录数据范围、观察截止、必要快照／字节身份、口径、公式及关键中间结果。原数据未被固定或完整复算条件不足时，如实保留该限制。

正式产品沿 Pi 已有文件、bash／Python／DuckDB 等实际可用工具，由 Agent 自主选用和复算。Host 只提供资源和保存事实，不从指标定义自动代算业务，也不把 Demo 本地计算器接成生产求解器。

报告应将数值、对象、数量、方向、比较条件及叙述结论对应起来，说明样本量、观察完整性、适用边界和不确定性。门店复购偏低可形成核查线索；原因断言、预测或措施效果需要相应证据，不能直接由排名推出。

### 有限决策与证据回源

Agent 可结合已绑定 Case 的准确判断和策略，形成有条件的核查建议或决策草稿，说明选项、依据、约束及什么证据会改变判断。建议、人的采纳、实际行动、观察效果和因果结论各自保留真实状态。保存 hypothesis／strategy 草稿不能代作人的选择、发券、派发经营行动或填报效果；无 Case 绑定时普通分析继续，Case 写工具保持不可用。

普通结果旁以轻量入口查看实际提供、实际读取、计算材料和作者引用声明。`record_analysis_sources` 或 Studio 使用声明仅证明作者提交了相应引用关系，不能当独立核验或正确应用的证明；没有声明时也不补造已采用记录。来源引用需对应准确报告版本、输入和实际使用版本，原native工具轨迹与独立复核分别核定。

本次计算错误先在原任务修正。核出源资产错误或可共享的新知识时，关联原输入、版本、报告、当前处理和影响形成贡献候选，进入任务演进层；正式修订仍经原权威核查与必要发布决定。后续独立普通分析新任务实际使用修正版，才可核定该范围的再用结果。

| SU14 会员贯通 | 在销售退款资产基础上补会员身份与交易映射、首购／复购口径、观察条件和 SAP 方法，普通 Agent 实际关联两主题并解释计算；一次实质修订后正确使用新版，保留旧报告依据和受影响原正确内容。具体业务口径和专业输入另据获准资料核定 |
| SU15 直接任务与上下文 | 从 Case／项目／任务直接提问，默认取得同企业授权范围、正式目录、版本位置和实际工具资格；不要求先进入 Studio、逐资产手选或确认普通读取。必要企业范围矛盾只限受影响材料，原正常分析入口保留 |
| SU16 自主发现与精读 | Pi Agent 自主检索并准确读取用途所需定义、映射、方法及依据；分页／片段有实际范围与续读状态，必要正文未完整取得时补读或限制结论。不得用索引、标题、调用成功或图命中冒充正文已读 |
| SU17 适用与采用 | 对实际使用资产核企业、用途、有效时间、粒度与前提，区分采用、拒用、待核和临时依据。正式与可读不等于适用；临时计算依据不冒充企业正式标准，未采用项不虚造实际使用 |

| SU20 有限决策 | Agent 可自主形成核查优先级及有条件建议，并在当前绑定 Case 的资格内保存判断／策略草稿；人的采纳、实际行动和效果分别记录。无 Case 绑定不猜目标，不阻断普通分析，不自动执行业务动作 |
| SU21 使用证据 | 界面区分目录供给、实际正文读取、计算、作者来源声明和独立核验；每项可回到原任务、报告、版本及实际轨迹。可选来源保存失败保留缺口，不假装独立核验或把保存当完成门槛 |
| SU22 失败与限定继续 | 缺失、不适用、权限拒绝、部分读取、同义冲突或来源失效时，Pi 明确该项原因，按原资格补读、重查、拒用或限定临时依据；无充分依据时不出受影响的重要结论，其他独立工作继续，不越权或借旧图恢复失效来源 |
| SU23 新版独立再用 | 正式修订后，用新的普通分析任务自主发现、精读并正确应用新版，明确新旧输入与口径差异；运行中任务不静默换版，历史报告保留原依据。旧版现已不合格时限制当前用途，不能用历史资格证明继续有效 |
| SU24 使用反馈闭环 | 将本次问题与源资产缺陷、数据缺口、方法不适用或个案例外分别定位，保存可核来源、版本、影响及处理；可共享增量进入贡献候选，修订、发布和再次使用逐步留证，不从候选或发布成功推断问题已解决 |

| D01 导航与整合 | Studio 内保留“企业基础资产／建设与演进／发布与使用”三个视图。资料、语义与主数据、数据映射、指标、方法作为基础库分类；专业编辑以工作区面板承接，不跳到独立 SAP 或企业资料产品 |
| D02 企业与旧资料 | 默认当前企业，存在多个企业时提供切换。未归属旧内容集中在“待核归属”，Agent 准备关联建议，用户只处理无法从证据确定的归属；不将全部历史内容自动划入第一个企业 |
| D03 执行工作台 | 提前建设使用自然语言目标和选材入口，任务演进从业务任务查看已形成候选。两者进入一致的 Agent／资源工作台，正常路径沿合理执行项目默认值；出处和技术身份按需展开 |
| D04 候选与差异 | 默认展示候选范围、依据、受影响资产和 baseRevision。局部约定可明确保留本案；企业修订先显示差异及冲突。归档来源可查看，通过新获准任务继续同一资产，不复制基础库 |
| D05 版本供给 | 企业当前正式且有资格的目录对新任务默认可发现。Agent 按需选择并固定实际版本，显式项目／任务限定继续清楚表达；新发布不改正在运行任务或原报告依据，不要求用户逐项目反复勾包 |
| D06 发布与维护事实 | 一个预览集中表达准确企业、资产和影响，必要发布决定集中处理；面板分别列各模块结果，UNKNOWN 仅先查原回执。图表示和实际使用单列，图未就绪只限制真正依赖它的用途 |
| D07 普通任务主入口 | 保留 Case／项目到任务的提问路径，与 Studio 管理并列。正常路径只需表达问题和已有授权；资产目录自动按范围供给，由 Agent 自主选择，实际读取与计算依据折叠查看 |
| D08 使用证据呈现 | 问题、分析回答、计算结果和有限建议为主；可展开实际供给／精读／计算／来源声明及限制。不让用户靠勾选资产制造“实际使用”，不将作者声明标成专业核验 |
| D09 消费失败与决策 | 缺定义、部分读取和冲突呈现可补证动作；企业或权限不足不露跨范围内容。Case 草稿和建议保持非执行状态，先核查或保留未知均可成为合格结果 |


### 管理三视图与普通任务

**企业基础资产。** 顶部为企业及范围、当前正式内容摘要和“建设基础资产”主动作。分类、搜索和状态筛选支持直接找到内容。打开首购复购指标可连续查看企业制度、会员映射、指标定义、适用方法及原报告版本；原文工作稿与正式资产状态分别标识。

**建设与演进。** 展示提前建设和业务任务贡献，记录真实来源、当前候选、等待资料、冲突和可继续工作。Agent 与资源在宽屏并排，窄屏顺序展开。候选存在不表示后台 Agent 正在运行；离开后回来不重发模型或发布。

**发布与使用。** 展示版本差异、必要业务决定、准确分项结果、后续任务可发现资格，以及实际使用任务和历史报告。确认成功前可取消预览；已确认操作遇未知时保留原请求身份供查询，不能靠再次点击制造新的成功。

**普通分析任务。** 用户从 Case 或项目直接进入任务，看到自然语言问题、Agent 分析和必要的计算／建议。企业范围与可发现目录由已有工作上下文提供，依据面板按需展开；管理面板不成为分析的入口门槛。用户可在问题修正或新知识出现后查看贡献候选，回到原任务继续工作。

原型沿现有中性背景、紫色主操作、系统中文字体与清晰层级，保留浅／深色和焦点可见。详情面板、对话框使用可访问名称、Escape 关闭及焦点回返；手机使用顺序布局与可到达导航，局部表格可滚动，页面不整体横溢。评审场景控制独立折叠，不成为正常用户操作前提。

| 冲突、回执与取消 | 复用原版本比对、准确发布预览、幂等请求、分项结果与公共取消；业务变更前核当前 owner 和版本，原 UNKNOWN 与迟到结果保持真实 |

## 四原则与最少人工作业前置核对

| 正常目标 | 用户必做动作 | Agent／Host 承担 | 失败与恢复边界 |
| --- | --- | --- | --- |
| 提前建设 | 表达企业建设目标、提供或授权必要资料；资料不能决定时作实质取舍；必要发布决定 | Agent 自动盘点、生成候选、比对和检查；Host 默认范围、执行归属及真实状态 | 缺资料只等待依赖部分，保留成果与接续位置，不要求重新建体系 |
| 普通分析与有限建议 | 从 Case／项目进入任务并提问，无需打开 Studio、勾资产或选固定方法 | Host 供企业范围、授权、目录及工具；Pi 自主发现、精读、判断适用性、执行计算、分析和形成有条件建议，保存实际来源 | 缺失／部分／拒绝／冲突／不适用明确处理；不足以支持的重要结论保留未知，其他独立分析继续 |
| 任务贡献 | 有需要时补业务反馈；必要纳入企业范围的正式决定 | Agent 保留出处、提出候选／差异、继续完善，Host 核 scope、版本与权限 | 本案例外不误并企业；冲突不覆盖；原建设归档可由新获准任务接续 |
| 使用新版 | 无逐项目重复勾包或引用确认要求；显式业务限定按需设置 | Agent 对后续任务选择适用正式版，Host 保留运行与历史准确依据 | 旧版有错保留历史但退出当前合格推荐；新发布不能改历史成绩 |

企业范围确认和必要正式发布有真实业务影响，因此保留。浏览管理、逐份选材、技术身份、引用和图操作按需展开，不作为享受普通分析能力的额外门槛。Host 不以硬编码步骤、专家配额或审批节点控制 Agent 内部方法。

## 会员场景与验证分层

本期业务问题为“哪些门店的首购会员复购偏低，值得优先核查”。企业首购或本店首购、会员去重、有效购买、退款影响、跨店归属、历史完整性、观察窗和核查排序依据，仍按获准资料确定。

Demo 中使用 A 企业（合成）、B 企业（合成），指标 `1.2.0 → 1.3.0` 以“全额退款不计有效购买，并核对首购顺延”作为实质修订示例。消费原型使用本地合成会员、交易和退款记录，固定企业首购队列、30 日观察、截止时间及门店归属规则，执行可检查的确定性计算；样本量或观察不足单列。具体数据和结果由本版原型及准备记录固定，均不作为真实 A 企业已确认口径。目录／读取回执和分析文案为模拟，计算执行为本地原型代码，不能据此声称 Pi 实际自主发现或正确应用。原报告 R01 继续绑定 `1.2.0`；新任务可发现 `1.3.0`，运行中的任务保持已采用版。

| 验证层次 | 本次准备验证 | 后续所需证据 |
| --- | --- | --- |
| 方案与原型 | 两条主线完整性、可点击状态、本地合成计算与期望结果、失败限定、真实浏览器、键盘／窄屏、独立只读复核、原稿及旧包字节保全 | 本次结果只证明设计候选与独立内存 Demo，模拟资产勾选或本地计算不能证明真实 Pi 使用 |
| 工程实现 | 本次不执行产品实现或产品工程验收 | 按正式确认范围做 SDD/TDD、接口／owner／取消与兼容、完整适用检查、原生接线、受影响回归和独立复核 |
| 真实 Pi 与专业／产品 | 本次不运行真实模型或企业数据验证 | 固定获准输入、准确资产和模型配置，使用独立普通分析新任务，检查原生轨迹中的实际发现、准确正文读取、适用判断、数据计算、解释与有限建议；一次实质修订后再用独立新任务验证新版，回读旧报告依据。不得由手选、目录供给、作者声明或模拟回放代替 |

后续真实 Pi 验收至少分别留存：默认提供的企业范围与目录；原生工具调用及实际正文／分页覆盖；所采用或拒用的准确资产与理由；数据输入、截至时间和计算过程；最终报告与建议的依据；作者声明和独立复核；源资产修订、正式发布及另一普通新任务的新版实际再用；原任务、运行状态和旧报告的历史版本保全。真实接线、专业正确性和用户产品验收各自给出通过、失败或未知范围。

工程交付、运行采用和专业／用户验收分别核定。首期限定通过、原 FAIL／UNKNOWN／NOT_RUN、原稿和会话按各自范围保留。
