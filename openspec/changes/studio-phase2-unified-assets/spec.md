# Studio 二期统一资产与两层建设规格

版本 v0.1 · 2026-11-12 · 设计候选，待用户审核

## 目标与当前授权

将 Studio 建设为企业统一的语义与分析资产中心，整合企业业务资料与 SAP 指标、分析方法的管理体验，同时支持企业基础资产的提前建设和 Case／项目／任务中的持续演进。二期以会员运营为贯通场景，验证普通分析对销售退款与会员两个主题的实际使用。

用户已认可上述调整方向，并授权更新二期方案、保留原稿、准备 spec 与可点击 UI Demo。本候选的具体界面和推荐决定尚待审核；当前不开发产品、不生成企业正式资产、不启动真实模型实验、资料迁移、Git 交付或运行采用。

输入为[二期方案 v0.2](../../../docs/studio-phase2-proposal-v0.2.md)，原[二期初稿 v0.1](../../../docs/studio-phase2-initial-proposal.md)保留原路径和字节。配套[可点击 Demo](../../../docs/prototypes/studio-phase2/index.html)、[交互状态矩阵](interaction-states.md)及[准备结果](result.md)共同构成审核材料。

本轮允许修改二期方案、新增本目录设计文档及独立 `docs/prototypes/studio-phase2/` 原型。产品 `src/`、`extensions/`、持久数据、依赖、锁文件、模型配置和既有验收记录保持只读。原型仅使用合成资料和内存状态，不调用业务 API 或 SDK，刷新可重置演示状态。

## 两层模型与责任

### 企业基础资产

保存本企业有明确来源、适用条件及正式版本的资产，供同企业、相应权限下的 Case／项目／任务按需查找和使用。分类为企业资料、语义与主数据、数据映射、指标、方法。

企业资料属于依据，保留工作稿、已启用修订、停用和来源原件；“已启用”不表示业务含义已经核实。本体源稿、Binding、指标和方法保留各自正式规则与专业主库，统一界面访问同一对象，不能另造一套公式或方法权威。

### 任务演进

建设工作可以来自提前建设，也可以来自具体业务任务的新资料、发现、纠错和政策变化。候选保留来源 Case／项目／任务、原报告或原文、所基于的准确资产版本、拟修改内容、适用范围和检查结果。

两类建设共用项目任务和统一 Agent 会话能力。企业资产有持续归属，项目任务是实际执行和来源归属；本次不建立无项目 Agent Runtime。行业、领域和标杆公开实践是建设输入，不是第三层企业正式资产。

Agent 自主检索、比对、选择工具、计算、核查和修订。Host 管理身份、资源资格、权限、生命周期、准确保存、冲突检测及实际回执。人工提供获准资料，处理证据无法决定的业务取舍和必要正式发布决定，无需逐节点审批或搬运已有结果。

## 可观察需求

| 标识 | 需求与完成条件 |
| --- | --- |
| SU01 统一产品入口 | 一级入口为“语义与分析资产 Studio”。企业资料、指标和方法可在其中查看、编辑和管理准确版本；原两项独立插件入口不再是管理必经路径，已有对象和引用能到达同一详情 |
| SU02 企业范围 | 单企业正常使用默认当前企业；Case／项目明确企业后，任务沿实际归属继承范围。多企业或归属矛盾时明确限定选择，不能混入其他企业。旧全局资料和 SAP 内容先盘点建议归属，未核定项不自动归入当前企业 |
| SU03 基础层供给 | 同企业合格正式资产默认可发现，由 Agent 按任务用途读取。正常分析无需先进入 Studio、先建齐资产或逐包重复手工启用；无资产时原普通分析仍可开展，未知与限制明确保留 |
| SU04 资料融入 | 企业资料在 Studio 内保留原文、来源、范围、生效时间、附件登记、工作稿、启用／停用及准确修订历史。启用新版不覆盖旧字节，停用后的历史依据与当前可用资格分开 |
| SU05 专业资产融入 | 语义、主数据标准与 Binding 能关联原文和 SAP 准确定义；指标与方法的候选、发布、问题治理、历史和使用入口统一进入 Studio。IR 与其他方法仍先保存、后发布，参考来源可追溯 |
| SU06 提前建设 | 从企业基础资产发起自然语言建设目标，沿当前企业可写执行项目的合理默认及获准资料进入原项目任务；无合格执行归属时才需要一次选择或创建。参考来源按需采用，不设固定专家、步骤或数量配额 |
| SU07 任务贡献 | 普通业务任务中 Agent 可形成自身获准范围内的候选，自动关联原任务、准确版本与依据；用户可查看、补充或继续完善。贡献候选不会直接改正式源或扩大普通任务权限，后续建设通过公共 owner 准入接续 |
| SU08 纳入基础 | 区分新共享资产、原资产纠错、企业新政策和仅本案约定。新候选先核已有资产；修订延续原资产身份；政策保留生效范围；本案例外可留本案。候选绑定 baseRevision，版本已前进时阻止直接覆盖，保留旧候选及差异 |
| SU09 发布结果 | 预览绑定企业、确切候选、版本、摘要、适用范围及各模块操作；必要确认后分别显示成功、失败和 UNKNOWN。只有准确成功对象进入当前正式供给；失败和未知不被整体成功遮盖，重复确认不重复发布 |
| SU10 版本与使用 | 新任务按当前正式资格发现资产，并记录实际选择的准确版本；运行中已采用版本和图快照不随新发布静默替换。历史报告保持原依据。已确认有问题或失去资格的旧版不再作为当前合格标准推荐，仍按权限保留历史查询 |
| SU11 长期维护 | 原建设项目归档后原任务与会话只读；企业资产保留，后续获准项目任务可接续同一资产维护。不得自动解档、复制一套体系、改写原会话或将旧 owner 的运行资源转给新任务 |
| SU12 三视图交互 | 企业基础资产、建设与演进、发布与使用在一个工作区内连贯导航。列表分类／搜索、详情来源／映射／版本／使用、Agent 工作台、差异与发布面板可到达；取消、空态、等待、冲突和只读状态有清楚动作，键盘与窄屏可用 |
| SU13 权限与回执 | 企业归属不自动开放建设项目原始数据；技术身份和来源资格由 Host 核验。取消或迟到结果不能继续发布；UNKNOWN 先查询原请求回执，未核清不盲重放。部分发布、图刷新、默认可发现及真实使用分别留证 |
| SU14 会员贯通 | 在销售退款资产基础上补会员身份与交易映射、首购／复购口径、观察条件和 SAP 方法，普通 Agent 实际关联两主题并解释计算；一次实质修订后正确使用新版，保留旧报告依据和受影响原正确内容。具体业务口径和专业输入另据获准资料核定 |

## 界面与推荐决定

以下是供本候选审核的具体落地建议，方向认可不等于此版本 UI 已确认。

| 决定 | 推荐呈现与行为 |
| --- | --- |
| D01 导航与整合 | Studio 内保留“企业基础资产／建设与演进／发布与使用”三个视图。资料、语义与主数据、数据映射、指标、方法作为基础库分类；专业编辑以工作区面板承接，不跳到独立 SAP 或企业资料产品 |
| D02 企业与旧资料 | 默认当前企业，存在多个企业时提供切换。未归属旧内容集中在“待核归属”，Agent 准备关联建议，用户只处理无法从证据确定的归属；不将全部历史内容自动划入第一个企业 |
| D03 执行工作台 | 提前建设使用自然语言目标和选材入口，任务演进从业务任务查看已形成候选。两者进入一致的 Agent／资源工作台，正常路径沿合理执行项目默认值；出处和技术身份按需展开 |
| D04 候选与差异 | 默认展示候选范围、依据、受影响资产和 baseRevision。局部约定可明确保留本案；企业修订先显示差异及冲突。归档来源可查看，通过新获准任务继续同一资产，不复制基础库 |
| D05 版本供给 | 企业当前正式且有资格的目录对新任务默认可发现。Agent 按需选择并固定实际版本，显式项目／任务限定继续清楚表达；新发布不改正在运行任务或原报告依据，不要求用户逐项目反复勾包 |
| D06 发布与维护事实 | 一个预览集中表达准确企业、资产和影响，必要发布决定集中处理；面板分别列各模块结果，UNKNOWN 仅先查原回执。图表示和实际使用单列，图未就绪只限制真正依赖它的用途 |

### 三个主视图

**企业基础资产。** 顶部为企业及范围、当前正式内容摘要和“建设基础资产”主动作。分类、搜索和状态筛选支持直接找到内容。打开首购复购指标可连续查看企业制度、会员映射、指标定义、适用方法及原报告版本；原文工作稿与正式资产状态分别标识。

**建设与演进。** 展示提前建设和业务任务贡献，记录真实来源、当前候选、等待资料、冲突和可继续工作。Agent 与资源在宽屏并排，窄屏顺序展开。候选存在不表示后台 Agent 正在运行；离开后回来不重发模型或发布。

**发布与使用。** 展示版本差异、必要业务决定、准确分项结果、后续任务可发现资格，以及实际使用任务和历史报告。确认成功前可取消预览；已确认操作遇未知时保留原请求身份供查询，不能靠再次点击制造新的成功。

原型沿现有中性背景、紫色主操作、系统中文字体与清晰层级，保留浅／深色和焦点可见。详情面板、对话框使用可访问名称、Escape 关闭及焦点回返；手机使用顺序布局与可到达导航，局部表格可滚动，页面不整体横溢。评审场景控制独立折叠，不成为正常用户操作前提。

## 接缝与版本约束

本规格沿[工程规范](../../../docs/engineering-workflow.md)及[统一会话接入说明](../../../docs/agent-session-integration.md)。源码基线中的 Interface v3、Pi 1.4.0、Semantica 0.7.0 作为复用核对起点，不代表本次已核实时运行环境，也不构成升级授权。

| 接缝 | 复用与拟补差额 |
| --- | --- |
| 企业与资产范围 | 补可追溯的企业逻辑归属和引用关系，原主库／资产 ID／准确版本优先保留；未归属历史不默认迁移，物理存储及兼容策略在实施前核定 |
| 执行 owner／profile | 提前建设和任务贡献使用真实 projectId／taskId，企业和候选身份为业务上下文；沿现有 `project-tasks` 主 Agent 及已核公开 profile。新维护任务有自己的配置与会话，不冒用原任务 lease |
| 原文、SAP、Binding | 复用资料库修订、SAP 库及方法发布、Studio 语义源和 Binding；统一前端与业务关联，不建立平行公式、方法库或自动推理循环 |
| 普通任务贡献 | 新增或整合贡献候选的业务接缝；普通任务只写自身候选与证据，正式源修改及发布仍核获准执行 owner。不得因 UI 合并移除原权限边界 |
| 供给与采用 | 收敛项目指标索引、正式目录查读和 Studio 使用资格，明确企业默认来源及任务实际固定版本。数据权限与来源失效仍沿当前权威检查 |
| 冲突、回执与取消 | 复用原版本比对、准确发布预览、幂等请求、分项结果与公共取消；业务变更前核当前 owner 和版本，原 UNKNOWN 与迟到结果保持真实 |

当前无新增公共 Interface、profile 或数据迁移实现。若后续确有既有公开能力不能表达的差额，按 IN06 明确范围、最小理由、owner 和兼容验证后再实施；不预先新增 Runtime、组织权限平台、全局调度器或第三方源码补丁。

## 四原则与最少人工作业前置核对

| 正常目标 | 用户必做动作 | Agent／Host 承担 | 失败与恢复边界 |
| --- | --- | --- | --- |
| 提前建设 | 表达企业建设目标、提供或授权必要资料；资料不能决定时作实质取舍；必要发布决定 | Agent 自动盘点、生成候选、比对和检查；Host 默认范围、执行归属及真实状态 | 缺资料只等待依赖部分，保留成果与接续位置，不要求重新建体系 |
| 普通分析 | 提问或发送原业务任务 | 默认企业目录按需可读，Agent 选用及计算，Host 固定真实使用身份 | 空库仍可分析；当前资格不足时限制相关结论，不隐式借用其他企业 |
| 任务贡献 | 有需要时补业务反馈；必要纳入企业范围的正式决定 | Agent 保留出处、提出候选／差异、继续完善，Host 核 scope、版本与权限 | 本案例外不误并企业；冲突不覆盖；原建设归档可由新获准任务接续 |
| 使用新版 | 无逐项目重复勾包或引用确认要求；显式业务限定按需设置 | Agent 对后续任务选择适用正式版，Host 保留运行与历史准确依据 | 旧版有错保留历史但退出当前合格推荐；新发布不能改历史成绩 |

企业范围确认和必要正式发布有真实业务影响，因此保留。浏览管理、逐份选材、技术身份、引用和图操作按需展开，不作为享受普通分析能力的额外门槛。Host 不以硬编码步骤、专家配额或审批节点控制 Agent 内部方法。

## 会员场景与验证分层

本期业务问题为“哪些门店的首购会员复购偏低，值得优先核查”。企业首购或本店首购、会员去重、有效购买、退款影响、跨店归属、历史完整性、观察窗和核查排序依据，仍按获准资料确定。

Demo 中使用 A 企业（合成）、B 企业（合成），指标 `1.2.0 → 1.3.0` 以“全额退款不计有效购买，并核对首购顺延”作为实质修订示例。该规则和任何展示的结果均为预置合成内容，不是 A 企业已确认口径、真实模型能力或专业验收成绩。原报告 R01 继续绑定 `1.2.0`；新任务可发现 `1.3.0`，运行中的任务保持已采用版。

| 验证层次 | 本次准备验证 | 后续所需证据 |
| --- | --- | --- |
| 方案与原型 | 文档一致性、可点击状态、真实浏览器、键盘／窄屏、独立只读复核、原 v0.1 字节保全 | 本次结果只证明设计候选与独立内存 Demo |
| 工程实现 | 本次不执行产品实现或产品工程验收 | 按正式确认范围做 SDD/TDD、接口／owner／取消与兼容、完整适用检查、原生接线、受影响回归和独立复核 |
| 专业与产品 | 本次不运行真实模型或企业数据验证 | 固定获准输入及模型配置，分别验证资产建设、发布、普通 Agent 实际使用和一次实质修订再用；用户对固定范围核定产品结果 |
