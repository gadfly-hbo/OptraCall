## 5. 业务关系合同（拟新增）

### 5.1 类型、方向和性质

- **共享项目**：从当前 CaseProjectLink 推导，不另存 Case↔Case 行、不创建“共享即依赖”结论；解绑后当前桥梁按真实关联更新，原关联历史仍可查。
- **前后续 `follows_up`**：A→B 表示 B 延续／深化／由 A 引出，A 为前项、B 为后项；说明必填。允许分支和汇合，不按创建时间排序推断。不是“前项已完成”的承诺。可不附外部材料，但依据必须可定位为这次明确声明：人的操作回执＋关系准确修订，或Agent的真实请求／会话／toolCall入口；界面标“依据为声明本身，未附外部资料”。不能把说明文字冒充独立证据。
- **支持 `supports`**：A 的明确判断／成果／经验为 B 的具体判断、策略或待核问题提供依据。必须有支持说明、至少一项可定位的源内容、目标范围；若目标已有卡片，绑定准确目标卡片修订。目标尚无卡片时保存明确文字范围并标“尚未绑定具体卡片”，不要求用户先凑卡片。
- 两类业务关系都是原声明者的关系声明，不代表 Host 已证明成立、因果或业务效果。可以保留相反观点；不沿路径自动传递支持，不投票、不级联改写人的选择。首版不新增依赖／冲突等独立关系类型。
- 禁止自环、未知对象／storeId伪造和同名合并；不把图规定为通用因果／无环引擎。可能存在的相互支持或前后续闭环保持可见说明，不据此自动裁决业务真假。

### 5.2 最少记录和修改语义

拟新增关系记录包含：稳定 `relationId`、原 `caseStoreId`、`fromCaseId`、`toCaseId`（同时为 owner）、`kind`；不可变 `revision`；`active / unlinked`；`explanation`、`targetScope`、可选准确目标 ref、源 refs、`changeReason`、声明性质 `explicit / inferred`；Host 绑定的真实 actorKind／可得 projectId、taskId、requestId、sessionId、toolCallId 及技术提交时间。声明入口引用由Host从实际来源绑定，人的声明至少有原operationId＋准确关系修订；Agent缺少原生正文时明确入口不可读，不伪造消息。正文与来源作者分开，未知不补造。Agent自主形成的推断显示“Agent推断／待核”，与来源已明确陈述的关系分别标识，不增加逐条人工批准。

同一 store/from/to/kind 只有一个稳定关系身份：重复创建已活动关系不制造新关系；已解除关系可显式恢复为同一身份的新修订。说明／来源／目标准确版的纠正追加修订；解除追加 `unlinked` 修订，旧记录可查。from/to/kind 不原位改写；改端点／方向／类型须明确解除旧关系并建立新关系。相同 owner 内可在原短事务完成；跨 owner 操作分别有回执，部分完成如实保留，不宣称共同原子。

关系自身做 expectedRelationRevision CAS，目标 Case 仅在写事务核开放状态；不递增两个 Case 的正文修订，不修改源 Case。新关系来源即使是已结束 Case，也只读取其获准历史。目标 Case 关闭与关系写入在原 Host mutate／同一 Store 事务内协调，不能从预览时开放推断提交时仍可写。

来源优先复用原 CaseLearningSourceRef 的准确决策／人的选择，以及原产物引用与原 resolver。支持成果须包含明确的原项目／引用身份及可得观察哈希；缺少不可变保存版时显示“当时观察／当前文件可能变化”，不能声称已保存历史成果字节。来源关系端点、项目归属、准确 ref、可读范围由 Host 校验；准确身份有效而正文失读的既有关系保留并标 UNKNOWN，不能换源为 latest。新建关系不得使用无法核身份／归属的来源；内容可用性和专业支持是否成立分别表示。

技术输入拟限：说明／目标范围各4000 UTF-16，来源0–8项（supports至少1项），每次请求≤64KiB，关系查询有 cursor／hasMore；这些是资源上限，不是方法或关系数量配额。原引用字段与截取规则复用，不新收任意绝对路径、凭据或外部 URL 正文。

### 5.3 企业与权限

复用现有 Case／项目企业身份读取：两个 Case 均有已知且不同的企业范围时，新建／改源拒绝 `case_enterprise_conflict`，不以关系自动关联项目、移动企业归属或开放文件。未知保持未知，不凭名称或当前默认企业补齐；可读性按原当前用户和任务准入分别核。既有关系因后续来源范围变化而不可读时保留受限占位，不泄露失权内容，不删除历史。跨企业业务经验能力若确需扩展，另补受影响准入，不在本包隐式授权。

### 5.4 幂等、迁移和兼容关闭

复用原 operationId／请求摘要／receipt。相同 ID同载荷先返回原成功结果，之后 Case关闭或来源变化不把成功改成失败；同ID异载荷冲突。业务修订和回执同短事务提交；取消／提交不明保留 UNKNOWN 和原ID，查回执，不换ID或重放模型。

拟 SQL schema3须显式扩充原 schema inventory、CHECK／索引／不可变触发器和 receipt kind；兼容只读 schema1/2，首次显式关系写入才在事务内升级。迁移核旧 SQL 值、Case／项目元数据及 native／文件保全；失败完整回滚或隔离保留现场。正常 GET／打开图不升级、不批量生成新行。具体DDL随实现 RED 固定，不改本产品合同。

兼容关闭候选须能读 schema3且关闭新写口／工具，原功能及已有关系可读；原v1/v2程序不承诺直接打开schema3。回退不恢复旧数据库覆盖新增记录，版本不兼容则保持数据根隔离。读到未来未知版本／损坏返回不可用，不伪造空图。

## 6. 读取投影、UI 与导航

### 6.1 投影和读取

组合原 Case list/projectLinks、项目／任务清单及拟新增的分页关系读取；不新增全局图数据权威。拟新增 `GET /api/case-relations`（可按Case、类型及游标筛选）和目标 Case 下的关系创建／修订／原回执查询入口。精确 HTTP 字段在实现契约固定，但须满足第5节；不建立通用图查询语言。

首屏不逐个打开 Case 决策、不递归读三目录或所有任务 native；Case节点先展示原标题／状态／下一步，决策和来源正文在详情按需读取。项目节点用原全局工作信息，任务用原 lastRun，缺字段显示未设置。完整页与部分载入／游标分别标明；两个Store不具共同快照事务，显示读取时点并在真正打开／写入时重核身份，不能声称全图历史一致性。

初始任务聚合；超过可见画布预算时保留概览计数和范围说明，以局部展开、聚焦、搜索和清单继续浏览。不得无提示截断，不能把未载入当不存在；布局坐标／过滤不是业务数据。产品性能验收用合成大图固定数量及环境，确认关系无丢失、交互可用后记录实际指标，不在原型阶段虚构毫秒收益。

### 6.2 页面层级与交互

- 原产品 shell、品牌紫色、中性表面及明暗 token；14px正文，12–13px元信息，20–24px标题；图按类型用文字／形状辅助辨别，不做装饰星空或持续漂移。
- 顶部为 Decision Case 标题与新建 Case 原入口；模式为 Star-Map／常规，常规内部方块／列表。搜索覆盖 Case／项目／分析任务；Case状态筛选只筛Case，不拿来判断项目业务／任务运行。
- 结构层显示所有通过当前条件的 Case，包括零关联；未关联项目有数量与可打开入口，不要求创建虚假 Case。任务匹配显露必要父项目，筛选无匹配与空库有不同解释及清除／创建入口。
- 关系类型筛选分别控制共享项目、前后续、支持的展示；筛选不修改数据。看某条业务关系时保留其两端上下文；共享项目不另画重复Case间边。
- Case／项目节点直接复用现有详情；项目详情需增加可定位到 projectId 的前端接缝。分析任务沿原 projectId+taskId打开，默认仅浏览；**点击任务不自动注入鼠标来路的Case**。需要“按此Case继续”时沿原显式动作及准确快照，不另设发送确认门槛。
- 用户返回图时恢复内存视图位置、展开、筛选及焦点；URL显式项目／任务定位、设置返回、未发草稿、SSE观察和现有导航离开保护继续有效。浏览不自动停止任务、切模型或发送消息。
- 点击业务边开关系详情：A→B、类型、解释、来源声明、准确目标／源版本、可用性、关系修订和可选管理。源Case已结束可作为历史来源；管理由目标Case当前开放状态决定。关系维护不是浏览前置。
- Case决策详情明确列出判断／策略、准确版人的选择、关联行动／反馈；“分析任务”与“行动任务”使用完整名称。没有关系显示未记录；任务运行完成不生成业务完成徽标。

### 6.3 状态、响应式与可访问性

必须覆盖：加载、从未启用、空库、无匹配、完整失败、部分失读、无关联、缺失对象、来源变化／失读、关闭Case、归档项目、并发冲突、保存未知、大图聚合。读取失败保留原上下文并给重试；局部失败不清空已确认结果。

390px时导航折叠，工具栏换行，图提供可用缩放和等价清单；详情占整宽，控件不挤压。节点、展开、边／等价关系清单、主题和关闭可用键盘操作；焦点可见，详情内焦点管理、Esc返回及返回触发点有效。支持减少动态效果；默认不持续动画。图上的小字不替代清单中的正常字号。

## 7. Pi 接入、职责与最少操作检查

遵守[工程规范IN01–IN07及官方包约束](../../../docs/engineering-workflow.md)和[统一会话接入说明](../../../docs/agent-session-integration.md)。保持声明 Pi1.4.0／Interface v3，**不升级／修改 Pi 或 Semantica 官方包**。开发前再核实际基线、安装身份与原未处理风险；本轮只核声明／源码，不声称运行采用。

拟新增 `ProjectAgentOptions.caseRelations` 窄业务 callback，工具暂名 `read_case_relations`／`save_case_relation`；读口只给获准关系摘要／准确来源，写口只维护本次绑定的目标 Case。真实 owner仍为原 projectId+taskId，profile为原 `project-tasks`；Host从本请求已完成的 task_context_prepare核目标，不接受模型自报owner、作者、配置／路径。源Case可经现有 M6只读发现，不把源Case变成本轮owner。

工具资格限原普通 unmanaged；受管ordinary／protected／独立workspace／cold／sealed／插件／核算及附属固定文本不因此扩权。沿原IPC、call-local SDK ctx、ActiveRun与取消信号，在现有Host mutate内核当轮资格与目标开放状态后短事务写入；取消、配置变化或迟到结果不得复活新写。原 `read_case_decisions`／`save_case_decision_draft` 和M5同Case限制不变。关系新read/save业务协议单列，不让新字段潜入旧工具输入。

Agent自主判断是否查询、如何使用明确来源、是否声明前后续／支持及如何纠正；可以零调用，不按Host固定步骤执行，不后台定时找关系。Host只核身份／来源／权限／预算、保存作者声明、投影状态，不按相似度／日期自动造业务边，不判断因果或替Agent补分析。新建、纠正、解除均以真实作者和关系修订记载，不覆盖前人声明。

| 场景 | 最简用户路径及额外操作 |
| --- | --- |
| 看关联并打开分析任务 | 进入Decision Case → 可选展开项目任务 → 点任务；无新增配置／授权／确认，任务本身不发送 |
| 看前后续／支持依据 | 点连线 → 读说明／准确来源；失读给范围和重试，不要求搬运材料 |
| 正常分析产生明确联系 | 原任务表达目标并沿既有Case背景发送；Agent按需调用关系写口，正常新增必做维护／审批为零 |
| 自愿补充或纠正 | 在关系详情或可选管理入口选择目标、类型、说明及必要来源；目标关闭需原重开，来源关闭无需重开 |
| 冲突／保存未知 | 保留草稿与原操作，核新修订／回执；这是异常处置，不变成每次保存前的确认流程 |
