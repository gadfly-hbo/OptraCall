## 推荐审核路径

1. 先看首屏Case/Project Map和左项目Task树、顶栏；切换Case星图/常规、Project卡片/列表，确认还是现有产品。
2. 从原Case详情查看新增目标关联；无适用目标时看候选理由/待补项并集中确认，旧历史保留。
3. 从原Project详情进入需求方案，核覆盖/重点、真实能力可改选、单/多Task与有效综合责任，对比仅创建和确认开始。
4. 从项目树进入原Task，查看继承背景、对话输入、文件区和结果综合；无Case不写其他Case，single不引用未参与Task。
5. 在原结果区打开右审查面板，核准确稿/意见接回/新稿未审/旧稿历史；进入原决策工作区核选择、授权、实际发生和效果分别留据。
6. 进入原Studio三个视图及SAP专业管理，核方法候选/发布/纠错入口；在原设置查看全局五节点及局部入口同值，再核市场过渡/返回原工作路径。

失败与恢复保留前版反例：无Case禁写、单Task准确来源、继续运行不准归档、无效综合责任不能提交、逐稿审查意见独立、IR关闭不绕道、开不补跑/关不杀/停不续、重复/UNKNOWN准确回读。演示状态只证明原型交互，实际并发/持久化/SDK/模型仍待正式实现验收。
