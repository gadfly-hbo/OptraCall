## 2. 工程范围和职责

七模块分别为 M1 战略与目标、M2 Project需求与任务管理、M3 分析执行与项目综合、M4 成果审查与决策反馈、M5 方法与业务资产管理、M6 自动模式、M7 导航与插件市场。验收条款为本规格 M1–M7 和 acceptance 中 A01–A28、J01–J12；它们是工程核对标识，不是产品运行时的固定分析阶段。

Host 提供原权威记录、准确版本与业务上下文、权限／预算／取消、资源和幂等保存。Agent 判断方法适用性、分析顺序、任务协作、补证、专业分歧、方法价值、综合及修订。不把 TOC/TP、MECE、交付、自查约定变成 Host 固定分析流水线、检查配额或评分裁判。人的经营选择、授权、实际发生和效果分别留据。

保留全部原项目、Task、会话／父链、草稿、文件、发布版本、人的决定及 FAIL／UNKNOWN／NOT_PROVED。只追加必要引用、版本及受影响记录；读取旧资料不批量回填。新增迁移须支持旧记录读取、缺字段未知、保存重开及兼容回退；不能恢复旧备份覆盖新工作。

范围不包含预建完整方法库、全套 TOC 树、全组织绩效平台、全局真值库、全局影响扫描、专业调度平台、后台新业务、自动经营执行或新 Runtime。场景组合及六项展示直接取消，不变成六项建设任务；其他原规划维持规划状态。保持Pi/Semantica原精确版本和官方原包；开发阶段仅按锁文件准备本工作树工程依赖，不调用真实模型或业务资料。用户后续已明确授权 Git／CI、合并 main、设备及服务更新，采用原锁定依赖和原更新入口，准确范围见 delivery；原 fetch／switch 本身不构成交付授权。

## 4. 七模块完整可观察要求

### M1 战略与目标（v1.1 第2、3、9节）

1. 支持营利、非营利、个人适用目标视角，目标关系、衡量依据和当期结果要求；不机械平均资源或把长期能力一律降为护栏。
2. BSC与企业GSA同源；部门／个人贡献目标按职责、协同及适用版本承接，不机械分摊指标。量化引用SAP原定义，非量化说明可核交付，缺基线保留待补。
3. 每个Case有主目标，可有关联目标，可从目标或问题发起；候选目标集中确认，已有目标复用。旧Case渐进补关联，查询／核对／Studio无Case正常开展，不要求先编完整组织体系。
4. 策略、资源、必要条件、执行／策略／战略假设三层反馈引用原记录；实质目标或经营取舍变化由用户确认，历史不追溯覆盖。

### M2 Project需求与任务管理（第3、4节）

1. Project必经轻量方案，已有有效方案直接复用，Task需求可选。准备仅用诉求、资料清单、已有说明、基本前提和连接权限状态，不全面读数据、试算、归因或做质量分析。
2. 分类开放，MECE核同层一致、父问题覆盖、边界和适当深度；覆盖、优先选择、暂缓／待核／范围外分别表达，不把整树建Task。
3. 推荐真实可用Skill、准确SAP/IR版本、连接器及权限状态；用户可接受／取消／更换／添加，一Task可组合，不要求三类齐备。
4. 一次“确认并开始”承接所选Task创建、准确上下文、既有权限和启动；“仅确认并创建”不运行。确认／创建／授权开始／实际执行各据实回执，部分失败可精确回读，不重复创建／发送。
5. 单Task和多Task均完整支持；综合责任明确并优先复用已有Task。无需逐Task重发、重复送入、再启动或先正式发布RAP。
6. 新增、归档、恢复核受影响覆盖和综合依据；沿原空闲准入，不删记录，不因恢复／浏览／归档改变自动重跑。

### M3 分析执行与项目综合（第2.3、5、9节）

1. 项目整体实质采用TOC/TP，具体树／工具、其他方法、顺序与协作由Agent安排；不强制每个子Task跑完整项目。所选Skill/IR实质使用，有核心方法实质改变且未获替代授权才集中确认。
2. 多类证据并用，不把全部分析归于运营数据分析Skill。资料不足主动在权限内补证，需人提供时说明具体材料、期间／字段、用途及影响，继续有独立依据部分，不伪造前提或根因。
3. 项目标准、专业Skill、输出约定三层分开；正式修订运营Skill的诊断建议／行动计划及完整报告／聊天摘要冲突。保留适用六段、原计算和必要检查，不把专业阈值变成所有分析规则。Skill本体及随包资料／脚本模板按分析类Skill规范、固定候选、用户独立测评通过回执后接入；提示词改动不等于正式契约生效。
4. 综合Task读取准确子成果与依据，核共同事实、分歧、交叉影响、重复归因和遗漏；用户直接读综合并回源。新关键成果／纠错在当前获准工作中更新受影响综合，不机械重写或扫历史。
5. 数字、事实、解释、方法实际采用、适配和限制可核；阶段交付、约定范围完成、项目综合、Case结束及目标达成分别表达，不预设找到根因或经营改善。

### M4 成果审查与决策反馈（第3.2、5.3、7.3–7.4、9节）

1. Agent决定内容、时机和未指定文件名；Host绑定真实项目与060目录、保存结果及准确入口。原稿及实质修订分别保留，同源同内容复用，不从发现文件推断工作完成。
2. 审查绑定准确稿、固定材料和范围，意见直回原Agent；Agent自主核实、修订或有据保留分歧。新版不沿用旧稿PASS，自查、独立审查、再审及未执行分别表达，无法进展交有边界成果，不无限返修。
3. 对用户一次明确原话，按准确版本代办相应Case判断／选择、GSA承接、看板安排／反馈，复用原记录，保留原话与来源。含糊选择集中澄清；仅策略选择不推定补货、调价、触达授权。
4. 选择、经营动作授权、实际发生、成熟效果验证独立留据；Agent不替人经营取舍，不从记录成功推断业务有效。跨记录部分成功／UNKNOWN先读回原请求，避免重复。

### M5 方法与业务资产（第7.3、8节）

1. 复用原SAP提炼／保存／发布：固定真实任务来源和截止位置，先比较已有方法，完整沿用引用原版，实质改进形成修订候选，真正新方法才新建，无复用价值不生成。不补隐藏思维、未做检查或把个案结论固化。
2. Studio指标／语义／映射、记忆候选各回原权威与写权限；发现、候选保存、核定、正式发布、实际读取／采用、专业验证分别表达，同一发现一次维护。
3. 错误与后来业务变化区分，沿本次已知真实引用核影响；报告回原Task，候选按实际影响修正，已确认错误方法先提示受影响版并停止默认推荐，纠正版仍须发布。无权／失读／未知保留具体待办，不扫全历史。
4. 记忆纠正／排除继续保留人的治理；固定旧引用不静默升级，也不继续以已知错误前提分析。新Task实际读适用版、避错后才能证明后续复用，不以发布通过代替。

### M6 自动模式（第7节及各模块节点）

1. 一份持久全局总控和五节点：报告保存、审查与修订、IR提炼、Case反馈、资产沉淀，初始全关；总控改全部、部分开明确显示，局部入口修改同一全局值并说明作用。无需逐Task偏好、重置或启动快照。
2. 每个新增动作实际开始前读当前值＋本次授权＋适用性；运行中其他Task未开始动作亦受影响。开不补跑、不立即触发、不唤醒已结束／停止／历史；关阻止未开始动作，已开始不强杀。停止撤后续派发并沿原生命周期收尾，停止后不提炼、不整理续跑。
3. 报告交付／保存、必要自查和所选方法检查属于原职责，不因节点关闭消失；停止则不借职责继续。用户明确点原操作不要求先开节点，开关也不扩大权限／预算／发布／经营动作。
4. 正常约定交付或明确“结束本轮并整理”才判断收尾；切页、沉默、断连、文件出现、一次模型回合结束不单独作为完成。未完成但要求整理须标限制，不并发读取变化中会话冒充最终来源。
5. 去重沿原业务请求、准确来源／版本与操作回执；保存、审查、方法、Case、资产分开复用，失败／取消／未委派／UNKNOWN分开。未知先核原文件和记录，不换ID盲重放，不从旧资格恢复写权。
6. IR关、资产开时只整理本次已发现问题或原纠错线索，不回看会话变相提炼方法／修订候选；明确手动提炼仍沿原授权。
7. 节点随M3–M5实际接入与验证；一个设置页、按钮或旧链存在不构成M6完成。原任务简短回执汇总完成／待确认／未完成，详情按需展开。

### M7 导航与市场（第6节）

1. 市场退出一级导航，设置保留“插件市场（过渡）”和原准确跳转；仅直接取消场景组合及S01–S06六项规划展示，其业务诉求仍可正常提出，其他规划不变成已实现或删除。
2. 业务入口归Project需求、Task、成果、方案比较、决策；低频Skill来源／版本／依赖、共享连接配置、模型包在设置；SAP/IR及企业资产回Studio原专业管理。不把技能、运行配置或PPT精修全部塞Studio。
3. 连接配置、环境可用、范围授权、显式启用和实际读取分开；缺配置给准确入口及返回原工作路径，不因迁移重复安装导入或丢历史。
4. 逐项验证原能力使用、管理、异常路径和旧定位准确版本／权限；满足v1.1第6.2全部判据后才移除过渡市场及改名兜底。导航可并行，最终退出依赖实际业务闭合。

## 6. UI前置和最少操作检查

Demo为虚构资料、内存状态，不连产品／网络／SDK，不表示实现、Agent采用或专业结论。见[Demo说明及审核范围](ui-review.md)与[真实UI基线](ui-baseline.md)。保留现有App壳、品牌/主题、项目Task树、Case-Star-Map/常规、Project Map、原Task对话/背景/composer/四入口/文件/右侧审查、原决策看板、Studio三视图及设置。不能以七个工程模块重排一级导航或用新摘要页替代原管理界面。只在原位置增加v1.1所需目标关联、Project方案/综合责任、成果/反馈、治理和全局节点；市场按既定范围移至设置过渡。

正常路径：用户表达目标/问题、提供获准材料 → Agent准备项目方案 → 用户一次确认并开始（或仅创建） → 原Task执行、综合与获准代办 → 用户查看成果，集中处理必要经营取舍/新授权。选定能力和有效背景直接沿用，用户不维护机器ID、不搬运每Task需求/报告、不逐条审批读取或方法内纠错。

| 路径 | Host职责 | Agent职责 | 人必须做及理由 |
| --- | --- | --- | --- |
| 已有目标的多维问题 | 交付准确目标/方案/资料和创建启动回执 | 推荐覆盖与重点/能力、安排分析协作及综合 | 确认本次范围及是否执行；目标/选择/权限不可凭空推定 |
| 无Case查询/Studio | 复用有效项目背景、原工作区和权限 | 完成查询/核对/建设，不造经营Case | 正常表达诉求，无需编全层级目标或新Case |
| 资料/配置缺失 | 准确配置入口/权限状态，返回原工作 | 主动补证、说明具体缺口，继续独立部分 | 提供Agent无法取得的资料或新权限，集中处理 |
| 审查与纠错 | 准确稿/回源/新旧版本和真实状态 | 核实意见、自主修订或说明分歧 | 影响原经营选择才由人取舍；普通修正不加批准 |
| 关闭节点/停止恢复 | 同源全局设置，真实停止/回读原请求 | 停止不续跑，明确续接后核已有成果 | 立即中止用原停止；UNKNOWN不靠重复点击赌成功 |

新增可选管理入口不成为必经表单；必要选择与授权合并到当前上下文。Demo及正式实现均核正常、失败和恢复路径，按需展示历史/来源/技术细节。设计前置结论仅覆盖本规格和Demo，不冒充最终四原则代码验收。

## 7. 验证、独立复核和产品PM协作

从验收导出行为测试，实施前保留真实RED及禁止副作用断言，逐切片GREEN和受影响回归。首个可运行切片即走隔离合成Host→真实Pi SDK→合成Provider/工具→保存重开/UI；公共入口变化覆盖旧消费者及第三合成接入、取消/配置变化/迟到结果。运行时/权限/持久化/公共契约影响广，完整候选执行届时完整适用 `npm run check`，不以静态导入或局部测试替代联合路径。真实模型/资料未获准则NOT_RUN，不伪造成已验证。

Skill正式接入需绑定候选目录身份及用户明确通过的独立测评回执；本轮准备不创建新测评平台，不改旧Skill后沿用旧版回执冒称新契约生效。实施前读取[分析类Skill规范](../../../docs/分析类Skill编写规范.md)。

产品PM负责解释已定方向，用户保留重要范围/取舍/授权最终决定。出现真实歧义才整理“条款、事实、影响、选项、建议”交用户带回，不臆造PM批准，不主动联系其他session或发送消息。普通技术实现持续自主推进。

工程通过、真实Agent采用、专业正确、运行采用、用户产品验收和业务效果分别记录；会员复购案例不要求找到根因或提高业绩。完整交付仍按工程规范第4、5节的候选、检查、复核、CI及有效授权办理。
