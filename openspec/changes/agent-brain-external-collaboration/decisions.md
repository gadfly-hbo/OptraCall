## 随整版规格提出的产品默认

以下为已决范围的具体化建议，随 spec/Demo 一并确认，不冒充额外逐项用户决定：

- 原 Task 下记录外派工作，不按六类任务硬编码执行者；首期保留普通可用任务资格和原受管/封闭边界。
- Host 业务记录裁定有效领取/交付/验收状态；GitHub Issue 和评论承担通信、展示与证据。
- 同一受保护 MCP 入口的资产能力只读；工作领取/续租/交回是独立的受限工作记录操作，不授予资产写入或执行权。
- 默认仅向指定私有业务仓库外派；使用公开仓库时需额外明确允许公开并确认确切出站内容。
- 原任务停止本轮会暂停自动续接；“取消外派”另行撤回后续资格并请求外部停止，不能宣称对方进程/副作用已被终止。
- 交付先作为外部来源保存，Agent 核验后沿原报告工具形成自身成果；正式语义/方法发布继续走原资产流程。
- WorkBuddy 本机接口只提供账号级消息游标，首期同一连接串行触发 OptraCall 工作；消息必须准确关联，人工聊天及无法归属的正文不送原Task/模型。通用协议仍支持多个独立执行者。
- 工程交付实现完整链路并完成隔离验证；真实账号、真实外部客户端、部署采用与用户产品验收单独留证，不用模拟通过冒充真实联通。
- 本版对齐Decision Case日常工作台：单一一级入口、Case总览/全部项目、Case四页签及原Task返回链；只在原Task、其原项目准确Task行和真实关联Case项目行展示外派摘要，不扩首页收件或改写人的待回应/ProjectWork外部等待。
- 外部接受不自动推进原Case轮次、取舍/观察、目标采纳、实绩或发布。准确返回origin、同owner外部上下文指纹和空闲时可选暂停是待开发最小接缝，不冒充新main已有能力。
- 依工程规范v1.17，正式实施时冻结三个基准，领取者先实际浏览器阅读/查看Demo和DOM/CSS并回执映射；逐项非作者复核、同视口产品对照，以及PM开PR前实际展示产品截图并取得明确确认均写入本单。
- 每份授权默认1项外派工作、最多3次WorkBuddy API触发（含修订）、24小时，较低原策略优先；UNKNOWN/已提交占额不盲重试，不能跨turn重置。费用沿已批准第三方账号策略，未知不当免费；无已批准资源策略不就绪。此项随整版确认，不冒充已获用户单项决定，不规定业务必须返工轮次，也不保证第三方内部计算或账单可由OptraCall强控。
