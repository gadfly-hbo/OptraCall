## 体验入口

1. 从 `#home` 日常首页的“继续工作 → 会员资料治理”进入原 Case；也可从 Decision Case 打开“Case 总览 / 全部项目”。首页两个已有人的待回应与项目外部等待分别保留，不增加外派收件。
2. Case 当前工作保留三个原事项及轮次，四页签为“当前工作 / 项目与任务 / 成果与依据 / 历史”。在“项目与任务”可按当前事项、全部当前 Case 或手选其他事项阅读准确关联 Task。原项目详情继续保留共用信息、原等待记录、六类用途筛选与原 Task。
3. 从准确的“打开原任务”进入分析 Task。原对话、报告 v0.3、UNKNOWN 和草稿持续保留。来源 Case 的事项、页签、手选范围及触发按钮有独立的浏览快照；“返回来源 Case”恢复该位置和焦点。“查看原关联 Case”则定位 Task 原 assignment 所在事项。独立打开原 Task 不自动带入 Case 背景或授权。
4. Task 内查看外派建议，在一个抽屉里确认目标、片段/禁做项、指定执行者、私有仓库、可缩小的准确资产版本、期限以及已配置资源/费用摘要，再点击“允许在此范围自主推进”。取消时不产生外派授权。
5. 授权后自动演示 GitHub 发布、WorkBuddy 本机助手 API 触发、Host 单一有效领取、MCP 只读查读/续租/交付、Agent 核验/接受及原成果保存工具。没有要求每次由用户点击的“接受成果”闸门。

原 Task、原项目的准确 Task 行，以及 Case“项目与任务”中明确关联的同一 Task 行可显示只读外派摘要；均标明本期拟新增。外部接受不会更新人的待回应、项目等待记录、Case 当前事项/轮次、目标实绩、业务采纳或原始观察。Case“成果与依据”只保留已有原报告/映射；外部附件仅在原 Task 外派详情回读，不自动成为 CaseArtifact 或本机正式报告。

## 授权与资源

正常演示明确预设模拟已批准的资源策略：一个工作片段，最多三次执行者 API 触发（含修订），资源窗口上限24小时；已提交或触发结果 UNKNOWN 仍占额，不盲重试。本次期限可进一步缩短；资源上限不是业务必返工次数。费用沿已批准的第三方账号策略，当前费用未知，不等于免费；本原型不宣称实号费用已核。

授权预览与已授权查看使用同一资源/费用快照，没有新增日常必填。首次接入需分开核对 API 授权/在线、MCP Connector、已批准资源策略与完整联通；未配资源策略不能自主触发。正常首次触发占一额，同 work 修订触发占第二额；达到额度或无获准策略时停止继续触发、保留原工作等待核对。

外派工单的 GitHub Issue 与业务 Case 事项分开；Host 工作台账承载有效领取、交付和验收。远端 MCP 的资产只读与领取/续租/交付是两组权限，资产留在实际 OptraCall 运行端，实例须在线并经受保护入口提供。WorkBuddy 本机助手官方 API 与远端 MCP 各自能力有官方依据，二者实号联用仍未验证；不使用云任务。

## 异常与回看

顶部“演示控制”可切换正常、未完成接入、补充一次、必要范围取舍、发布 UNKNOWN、重复领取、同执行者占用、模型忙、身份变化、离线、过期、缺件失败和迟到回传。这是原型验收控制，不是普通产品必做步骤。

- 原 Task 模型空闲等待外部时，Task 卡与详情均可选暂停/恢复本地自动续接；这不取消外部授权。正常路径无需使用这些控制。
- “取消外派”撤回后续访问并请求对方停止；对方是否停止和已有副作用继续待核，迟到材料隔离保留，不恢复权限或自动接受。
- 发布 UNKNOWN 只核对原回执，不盲重发。重复领取由 Host 保持一个有效领取。同一 WorkBuddy 连接已有工作时，下一项等待执行者，不按最近消息认领结果。
- 需补充仍属同一 work、同一 Issue 追加；新 revision 使用新有效领取，旧 delivery 和首次未通过理由可回看，授权不扩大。
- 资产依据页可演示跨任务、错版本、撤回、离线和到期错误；保留原文、报告与历史引用，不静默取最新版。采用声明须同时符合授权和实际读取，排除 mapping 时保留未取用/未核验限制。
- 正常交付 v1.0，补充交付 v1.1。每件产物分别显示模拟本机字节保全/摘要核对；缺件、仅链接或待保全时不接受。v1.1 重新保全、保留 v1.0 记录。所有字节数、摘要和保全回执均合成，不创建真实附件文件。接收后仅可提交待核定资产候选，不发布正式资产。

## 原型边界与证据

单文件无外部依赖、外部字体/图片或网络调用，保留 `connect-src 'none'`。企业、业务资料、身份、端点、工单、回执与资源策略均为合成演示。新版使用 `optracall.external-collaboration.demo.v2` 命名空间，旧 v1 保留；schema4 只重置旧合成状态，不是产品迁移规则。存储失败时使用内存。重开保留已知事实，不重演外部动作；没有持久后台。

代表场景为一个 Case、三个明确原事项、一个项目与六个原 Task；初始“资料一致性核查”是合成导航中明确保存的当前事项，不由“首个/最新事项”猜测。Case 创建、完整管理和专属会话不在本外派原型内实现；已有入口提供范围说明，不伪造创建或模型回复。
