## 先体验一条正常闭环

1. 以顶部“正常闭环”演示场景开始，从首页继续工作进入Decision Case，或打开“全部项目”，再进入准确原分析任务。Case保留当前工作/项目与任务/成果与依据/历史四页签及事项范围；六类用途仍为需求、分析、计划、决策、执行、反馈，浏览不新建任务。
2. 在原任务查看外派建议，打开同一授权抽屉，核对目标/范围/禁做项、指定执行者、私有仓库、可缩小的准确资产权限，以及已批准资源策略/上限/时效和未知费用提示。正常继承已批准策略，不新增日常必填；试着缩小一项，再查看预览，Escape或取消不会发出工作。
3. 选择“允许在此范围自主推进”。原型自动推进工单发布、WorkBuddy本机API受理、有效领取、MCP查读/续租/交付及Agent核验。普通接受不是另一个必须由用户点击的闸门。
4. 看工作详情的分项事实：GitHub Issue、API消息回执、Host有效领取、资产读取、外部交付及原Agent接受。Issue关闭和API返回均不代替验收。
5. 查看交付的准确版本、每件产物的模拟字节保全/摘要状态、实际引用的资产及未验证范围。缩小资产后不声明采用未读取的依据，对应部分保留未核验限制；缺件不能显示完整可验收。外部来源保留；原Agent接受后沿原保存工具形成新增成果，旧报告仍在。
6. 回原任务/报告/Case核对原事项、页签、手选范围、草稿及返回定位。需要资产演进时可“提交资产候选”，仍待原流程核定/发布，不直接生成正式资产。首页人的明确取舍/观察请求和项目外部等待保持原状态；外派接受不自动完成Case轮次、目标实绩或经营决定。

## 再检查几个关键边界

| 演示场景 | 应看到的状态 |
| --- | --- |
| 未完成接入 | API授权/在线、MCP Connector授权、已批准资源策略、完整协作测试分别显示；只完成单项不能自主派单。模拟完整测试通过只改变本演示状态，不代表实号已测。 |
| 发布 UNKNOWN | 可只读核对原回执，不因刷新或新工具编号直接重发；未核定状态保留。 |
| 重复领取 | 同工作仅一项有效领取，竞争者被Host拒绝；GitHub评论不能赋权。 |
| 需补充 | 同work和同Issue追加新revision/补充要求，旧交付与原不通过理由保留；新领取不扩大原范围。 |
| 必要业务取舍 | 目标/范围需要变化时交用户，保留原范围也可继续独立工作。 |
| 模型忙/本任务暂停 | 交付先待处理；原Task空闲且允许后自主核验。暂停本地续接不会假称外部已停或撤回资产权限。 |
| 取消外派/迟到回传 | 后续访问资格撤回、请求外部停止；对方未确认和既有副作用待核。迟到材料隔离保留，不恢复授权或自动接受。 |
| 身份变化/资产离线或过期/回传失败 | 明确显示问题及保留状态，不假报正常、换号成功或接受成果。 |
| 资产查读边界 | 查看准确版本、出处、范围；高级演示控制中的跨任务、错版本、撤回、离线及过期给出具体拒绝，原报告/历史引用保留。 |
| 新工作台导航 | 单一Decision Case入口、Case总览/全部项目与四页签可达；切换范围/进入原Task再返回保留事项/范围/草稿，独立项目不默挂某Case，共享项目不混入他Case资料。 |

顶部“演示控制”用来注入上述模拟事件，切换会重置本次合成场景；它不是正式产品要求用户操作的任务步骤。正常权限内推进由Agent自主，只有必要授权/取舍由人决定。

WorkBuddy API的message_id为账号级消息游标/触发回执，不能按消息先后认定工作或完成。正式实现按spec核对准确关联，未知或人工聊天不进入原Task/模型；首期同一WorkBuddy连接串行触发已知OptraCall工作，其他工作等待执行者，通用协议可使用多个独立执行者。

## 版式与保存

按 1440、1024、390 CSS 像素检查亮/暗主题；长内容、表格和授权抽屉保持可读，Tab可达、Escape可关闭、焦点返回原触发控件。页面在可用时用独立sessionStorage保存演示状态，失败时回到内存；可重置，不在原型中声称有真实后台服务。

上轮云环境Chromium策略阻止直接导航`file://`，原记录保留。本轮未重跑文件协议启动，仍记NOT_RUN，未修改策略；本轮实际使用本机HTTP完整加载同一HTML并检查无外网请求。用户可保存单文件后在自己的浏览器点验；本机测试localhost不是用户可访问的托管预览链接。正式产品的浏览器/设备检查仍在实现阶段执行。
