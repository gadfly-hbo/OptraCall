# 企业会员运营资产包建设 · 首期工程规格

2026-11-20　评审稿 1　｜　对应产品方案 v1.0　｜　状态：待用户确认本规格及 Demo

**目标**　会员运营负责人在现有企业 Studio 说出目标、给出手边资料，就能知道先建什么、为什么，以及建完能回答什么。用同一个企业包承接建设、分用途发布、跨项目采用、问题修订与新版再用。首期服务一家服饰零售企业的会员运营部门，以门店复购检验完整链路。

## 3. 第一份交付应让负责人看懂什么

首页回答“这次要支持哪个决定、现有材料能支持到哪里、最小的下一步是什么”。先显示品牌、渠道、期间、材料截止和经营目的。下钻后，每个经营问题各自呈现**业务开展情况**和**资产能支持的用途**，附资料版本、页／表／段、范围、事实或推断、缺口对决定的影响。定义、字段映射、样本计算、独立实际使用分别附证据。

只给三份资料时，制度可说明规则与明文未开通的机制；月报可证明列报了什么，只在获准范围内引用原数；字段表可产生映射候选。制度规定发券、月报有发放量、字段仅有到期日时，仍缺核销依据。门店月底补绑会员时，Agent 对照入会、交易发生、绑定日期及月报脚注；缺少取数依据，集团新招与门店新增服务关系保留两种解释。

优先级取决于当前决定与证据。若总部要比较门店，已能定位两店队列、退款关联的疑点会改变排名，建议先建门店复购；若眼前要定券预算且身份已核，优先级可改为生日券。每条建议给出可先交付部分、最小补证及由谁回答。点名题直接进入该用途和依赖。无需把所有栏目做齐，也不因只取得一个样本而断定全期覆盖。

门店复购按首购店分组时，核的是后续购买。要进一步评价门店招募贡献，另需入会或招募归属依据。判定品牌真实首购，要有能覆盖该账号相关渠道及门店历史的证据；只有本店开业以来的完整订单时，不能据此断定全品牌首次购买。部分账号有可靠品牌首购凭证时，承诺的用途可限定于可核人群，报告同时交代范围及未覆盖部分。

反馈入口允许知道问题的人提供线索。Studio 分别记录“问题从哪条回复提出”和“哪些报告实际读用错误版本或由其派生的汇总”。只用过定义的商品部回复可作为反馈来源；退款映射修订未改变定义时，该回复原结论继续成立。总部引用旧汇总的报告，则沿汇总的原版和上游依赖检查数值影响。

## 5. 如何走查本次 Demo

1. 进入虚构企业“织屿服饰”的体系工作台。宽目标和本项目三份获准样例已带入，可逐份点看。选“开始本轮建设”，看全景首页和每个经营问题的出处。若要检查点名起步，可重新演示并输入身份归属、生日券预算、购买活跃或沉睡召回，直接查看该用途的资料、缺口与完成条件。
2. 在全景选门店复购。对照行业与企业线、领域与会员线，点开参考版和企业草案。进入一份发布预览，用“星桥首购、柳岸再购”的例子选择考核含义，再核对定义、正式计算与“资料期内首次可见购买”的范围。也可以切换 SAP 分项失败或未知，观察哪些用途仍能用。
3. 从首版分项回执进入另一项目的独立分析任务。选择总部月报可看到引用汇总的结果；打开原回复“本次依据”查看实际取用。换角色另开任务，可比较商品部只看定义、店长核本店事实及获准核算岗读明细的差异。
4. 在原回复反馈跨月全额退款问题。回 Studio 读原资产核查，查看修订预览并确认；从独立新任务按新版核查，再回看首版报告和 Case。每个报告保留当时的角色、读用和结果。

**本轮点验范围。** Chrome 实走了项目三份样例 → 全景 → 门店复购 → 预览 → 首版分析 → 反馈 → 修订 → 新任务。按“任一获准直营店再购”演示，总部先从旧月度汇总引用 3/4，新任务用修订映射核到 2/4；这是虚构的四账号案例，附录 B 的两人验收对照留在验收侧。另查了同店口径、失败与未知回执、查看原段、小屏访问和按角色回看。交互状态仅保存在当前页面，刷新可重新开始。八份来源在此预置为已登记，完整主线是门店复购，其他点名用途演示至起步草案。产品持久化、真实多用户授权、Pi 自主找读和企业实际使用由批准后的候选取证。
