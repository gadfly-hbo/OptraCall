## 1. 从一个经营问题开始

会员运营负责人在本企业 Studio 的获准建设项目中提出“帮我建设本企业的会员运营资产包”，提供已有资料即可。首期服务一家企业的一个会员运营部门。最终交付的是一份可持续维护、可按用途发布、能被分析任务准确引用的企业会员包。门店销售与退款影响复购的案例用来验收整个产品链路。企业可以选身份归属、生日券或其他更急迫的问题作为首批用途。

| 你在 OptraCall 里怎么做 | Agent 和工作台应交付什么 |
|---|---|
| 说出目标，指出可用的企业资料 | Agent 找到当前可见的正式资产、在建事项和参考资料。目标较宽时，先交《本企业会员运营全景与首批建设建议》。你已点名具体问题时，直接从该用途和相关依赖起步。 |
| 选定一个当前要解决的问题 | 在原建议里写明经营问题、适用范围和什么答案算完成。Agent 核事实、补缺口、起草企业口径。你只需回答仍会改变业务含义的取舍。 |
| 查看一份发布预览，按已有权责正式采用 | 能直接看见哪些可供解释、哪些可以计算、谁能引用什么、还有哪些受限。各项沿原资产发布并留下结果。 |
| 下次在同企业、具备本次用途所需授权的项目中新开分析任务，照常提问 | 新任务独立于建设会话，自主找读和采用准确版本。你在首次实际使用结果上认可适用范围。发现有共享价值的问题时反馈一次，Studio 接回修订。 |

**领域包的权威。** Studio 管理包的身份、版本和组成。每个已采用条目可追到参考原段、企业决定、适用范围、生效期、例外和原资产准确版本。销售退款事实、会员规则、SAP 指标和原始数据各有维护位置。项目负责本次工作，企业包可跨项目接续。

**四项产品原则。** Host 管企业归属、环境、权限、版本、发布与证据。Agent 在已有授权内自主选择材料、方法及执行顺序，解释判断并纠错。沿用官方 Pi 的会话与执行能力，按需复用 Semantica 的语义能力，以及现有 Studio、SAP 和 Case。复用第三方 SDK 的公开能力，OptraCall 不直接改造 SDK。随官方版本升级须取得用户授权。用户沿用已有资料和决定，必要经营取舍集中处理，正式发布沿用一份预览。

## 2. 第一份交付与首批用途

### 2.1 企业会员运营全景

全景首页写明品牌、渠道、期间和资料截止，首先回答“当前哪些判断可靠、哪个缺口影响眼前的决定、首批做完可以回答什么”。下方按经营问题展开企业出处和下一步。业务开展情况分为已开展、未开展、开展情况待核。只有相应范围的执行记录、明确未开通的制度或可核说明才能支持前两项。资产按具体用途说明资料缺失、口径待定或已可用，分别标明定义、映射、可计算及实际使用的证据。

下表示例假设已取得直营和加盟月报、发券与活动记录。只有制度、月报和字段表时，按下一节的证据范围作判断。

| 负责人想回答的问题 | 业务是否开展、凭什么判断 | 资产可用于什么、缺口会影响什么 | 建议动作 |
|---|---|---|---|
| 招募与身份：本月到底新入会多少？ | 直营、加盟均有入会记录；加盟流程说明允许月底将销售补绑到会员 | 直营入会可按日期观察；加盟月报未交代补绑是否计入新增。“新增上升”可能含历史交易补录 | 对照入会、交易发生、会员绑定三个时间，核一笔月底补绑记录与月报取数说明 |
| 购买与价值：多少销售来自会员？ | 两类门店均有成交、退款记录 | 假设直营已有正式净额口径且普通任务实际用过，结论限于直营。加盟绑定延迟，当前两类门店的会员销售占比排名可能颠倒 | 复用直营口径，列出加盟在同一截止日已归属、待归属的交易及两者影响 |
| 权益与服务：生日券发出多少、用了多少？ | 发券记录证明本期开展 | 已核定的发放量可用，核销流水尚未取得。现有资料无法据此判断使用率、权益成本或是否削减预算 | 保留发放量准确版本；如负责人要定下期预算，优先取得获准核销记录 |
| 活动与活跃：参加穿搭活动算不算活跃？ | 门店有签到和购买记录，运营部与销售部的月报分别使用两种事件 | 事件可区分；“活跃”含义随用途而异。混成一个数字会误判活动参与和购买变化 | 先建议保留“活动参与会员”和“购买活跃会员”两个用途；需要统一考核时再请负责人裁定 |
| 留存与召回：谁回来买了，谁可联系？ | 回访有记录；历史交易自系统切换后才连续 | 完整观察窗内可研究首次可见购买后的再次购买；真实首购仍待补证。部分渠道的触达许可与退订状态待核，召回范围受限 | 把观察期、历史覆盖与可联系范围分别标明，仅在获准用途内取材 |
| 积分与付费计划：哪些机制在运行？ | 本期制度明确某品牌未开通积分；关于付费计划，现有材料未提供依据 | 该品牌本期积分标“未开展”，不形成建设欠账；付费计划标“开展情况待核”，保留适用范围 | 有新增依据时更新；只有答案会改变本轮范围或优先级时，才集中询问 |

总部近期要比较门店，而加盟销售按月补绑会员时，优先核身份、门店和交易归属。身份已可靠、下期要决定是否继续投放生日券时，优先核发放与核销。Agent 给出建议及其理由，用户可以修正范围或直接继续建设。参考包和现有覆盖盘点用于查漏，无需业务人员先填完所有栏目。

### 2.2 用已有资料交叉核对

| 手上的资料 | Agent 去哪里看、能确认什么 | 仍需什么才能再往前一步 |
|---|---|---|
| 会员制度 | 找生效日期、适用品牌与渠道、入会和享受权益的条件。可据此说明制度要求怎样办。 | 要判断门店本期实际怎样办，需要相应的业务记录或可核说明。 |
| 经营月报 | 找当月实际列报的指标、数值、期间、分组和附注，辨认负责人用它作门店比较、考核还是预算决定。 | 只有列名和合计时，可以引用原报数字。重算或跨店汇总还需知道计数对象、去重与归属规则。 |
| 系统字段表 | 找人员、会员关系、券等记录分别以什么为单位，相关标识如何关联，有哪些事件、日期和状态。可提出映射候选。 | 字段存在仍需核实有无填报、覆盖哪些渠道，以及该版月报是否实际取用。 |

**沿月报核一个指标。** 一位会员 5 月在甲店首次入会，6 月首次绑定乙店。集团招新可在 5 月计一人，乙店在 6 月可增加一个服务关系。Agent 对齐主体、品牌、事件、期间和去重范围，查实际报表脚注或取数说明。只有列名和两个候选日期字段时，现行月报算法待核。若核对这一区别会影响当前决定，只向经办人索取一份已有说明或一条能区分两种算法的脱敏记录。样本核对个案，整期结论另需覆盖依据。

**从制度反查遗漏。** 制度规定发放生日券，月报只有发放量，字段表只有发放时间和到期日，可引用已报发放数。核销情况仍缺依据。要支持预算判断，再找获准的核销汇总或可关联的发放与核销记录。到期日无法证明券是否已使用。

给业务人员的一份短清单可以为空。事实问题先由 Agent 回源，再找掌握原资料的人。究竟要把“集团新招会员”还是“门店新增服务关系”纳入考核，由有权负责人裁定。每个问题带出处、影响、可行建议和当前可继续的部分。新增答复并回原项。

### 2.3 怎样约定首批完成条件

| 首批用途 | Agent 可以怎样提出完成条件 | 可以先交付的阶段成果 |
|---|---|---|
| 核清会员身份归属 | “先核 A 品牌直营店这批账号。截至约定日期，每条有有效绑定依据的记录都能归到对应会员；关联不足的能单列待核并说明原因。”负责人要的是一份可使用的归属判断，允许有待核项。 | 找到会员号和绑定字段，尚未核实两者关系，可交字段对照。原范围包含全部直营店但只核了甲店，可交甲店结果，并列其余门店缺的证据。品牌内有据的关联也可先用，集团全量去重另需跨品牌依据。 |
| 用生日券核销率决定下期预算 | “先看 A 品牌上一批已结束的生日券。能按企业认可的口径复算净核销率，并结合本次预算采用的比较基准或约束，说明现有证据支持维持、调整还是暂缓决定。” | 只有发放月报，可先交发放量和指标定义。独立任务已正确复算核销率，但企业按投入产出作预算取舍且尚缺券成本或收益依据，经负责人认可可记“核销率已可用，预算用途待补证”。仅有定义或计算准备时，注明相应阶段以及首次使用是否已核。 |

用户选定后，完成条件随建设任务进入原发布预览。只完成了较窄范围时，同时显示已交付部分、原目标和剩余缺口。后续问题是新目标时再作选择。第一次真实提问即可核验，具体判断见第 6 节。

## 3. 两条参考路线与企业内化

**参考登记。** 在“设置 → 领域资产包”按原文登记来源、维护者、准确版本、适用范围和位置。同一来源同一版只登记一次，两条路线可共用。新版与前版分别保留，同版正文不同先核来源。整篇背景保留在原处，仅将需要采用、修改、排除或受升级影响的条目单独管理。用户可从企业 Studio 发起，也可从已登记参考进入同一企业建设任务。

| 路线 | Agent 怎样选择参考 | 带回企业草案的内容 |
|---|---|---|
| 企业线：运动鞋服行业 T01 → 标杆企业 → 我的企业 | 从行业参考梳理共享对象，用 Nike T03 对照渠道与触点。企业有多品牌、自营与经销等业务时，再查江南布衣同份研究中的集团和渠道段落 | 形成共享依据清单，标明纳入的门店与渠道、身份和交易粒度、退款与原单的关联，并挂上企业内原资产准确版本 |
| 会员线：会员运营领域 T02 及通用会员包 → 标杆会员业务域 → 我的会员部门 | 从首购、有效购买、复购和观察窗出发，用 Nike T04 检查各类参与事件；用江南布衣检查跨品牌身份、集团与门店范围及活跃口径。按与本企业问题的相关性选择其他领域参考 | 形成会员规则草案，说明统计谁、复购归哪家店、算哪个窗口、哪些退款或换货影响资格，以及缺什么才能计算 |

五份通用领域包和三份标杆资料的取用见附录 A。标杆帮助 Agent 发现值得问的问题。正式口径的依据来自本企业的制度、资料和有权决定。草案按“行业或领域建议、标杆做法与证据、本企业决定与依据”组织，可以采用、修改、排除、新增或待定。同一业务问题有多份来源时，合为一个企业条目。

例如，交易记录已经证明甲店首购、乙店再购，Agent 可直接引用两笔交易的发生店。若已生效的会员制度明确全额退款不算有效购买，Agent 按制度起草并标注适用日期。若只有财务冲销规定，会员资格仍待核。若部门还没决定考核的是“甲店获得的会员有没有再来买”还是“有没有回甲店买”，Agent 说明两种口径会怎样改变答案，由负责人一次裁定。

| 资产由谁维护 | 首期责任 |
|---|---|
| 企业共享底座和原销售退款资产 | 门店、渠道、客户与账号的关联依据，交易发生店与时间、支付、退款、换货及原单映射。原业务系统保留原始记录。 |
| 会员运营域 | 用已核共享事实确定入会资格、统计单位、有效购买、首购队列、跨店复购、窗口及局部例外。 |
| SAP 与 Studio | SAP 维护指标、公式和可复用方法的正式版本。Studio 场景说明适用问题、依赖、排除条件和交付要求，会员包引用各项正式资产。 |
| 原分析任务与 Case | 本次计算、临时假设及报告在原任务保留。Case 记录人的决策、行动与后续结果。 |

**部门可以先建先用。** A 品牌直营店只有品牌内可靠账号时，会员部可在获准范围内先核品牌内身份与购买，准备相应用途。部门可贡献已核的门店映射、资料出处和样例。企业原资产负责人核定跨品牌同人依据及共用映射，集团考核归有权负责人。集团疑点只限制依赖它的用途。

## 4. 发布、使用与接续同一个包

### 4.1 发布到什么程度

资产按用途取得发布资格。门店首购后 30 日有效复购率的示例分母是按首购店归组、身份可靠且已完整观察后续 30 日的去重会员。分子是其中在纳入渠道、首购次日起 30 日内再发生有效购买的去重会员。一人多次再购只计一人。购买资格、退款冲销、队列归属和窗口以企业核定版为准。

| 企业口径与资料现状 | 本次发布决定 | 普通任务能交付什么 |
|---|---|---|
| 首购、窗口、全额退款和跨店归属已核定；缺首购历史或退款关联 | 发布正式定义，标明“供定义参考”及所缺资料 | 解释指标含义、分子分母和缺口；真实首购复购率保留待算 |
| 只能可靠识别资料期内第一次可见购买；在限定品牌、渠道和期间内，身份、退款和完整后续观察均可核 | 将“资料期内首次可见购买后 30 日复购率”单独命名，按范围发布其计算用途 | 给出有限范围的结果、资料起点和截止日。甲乙两店的历史覆盖不同时，先找可比范围；找不到就分别描述，暂缓排名 |
| 指定范围内有真实首购依据、可靠身份和交易退款映射，观察窗完整，样本计算已核对 | 在核定范围内发布“首购后 30 日有效复购率”的计算用途 | 输出可复算的分子、分母及适用门店。未成熟会员单列，身份未知或退款关联不全的数量及影响另列 |
| 同一交易命中相互矛盾的两条规则，且企业未批准优先关系 | 受影响规则保留候选，独立合格的定义和用途可先发布 | 标明受影响门店、交易范围和剩余工作；不把冲突项放进正式计算清单 |

一份预览写清正式版本、用途、范围、生效时间、资料截止、排除项和缺口。已有有效经营决定随草案带入。有权负责人在这份预览确认正式发布。确认后各项沿原权威发布，保留分项回执；成功且依赖齐备的用途才进入本企业合格目录。必要依赖失败或发布结果未知时，仅挂起依赖它的计算用途，先查原回执，独立合格部分可先用。草案或依赖在确认后改变，只重新核对受影响项。

### 4.2 部门发布后，总部、商品部与门店怎样使用

同一笔交易中，会员在 A 品牌甲店首购、20 天后在乙店有效再购。按获准的跨店口径，该人计入甲店首购队列，第二笔销售仍归乙店。预览分别列出经营适用范围、谁能为哪种用途引用多细的汇总，以及重算所需来源与现有权限。

| 使用层次 | 总部、商品部或门店在什么条件下可以用 | 用这笔交易能回答什么 |
|---|---|---|
| 看指标定义 | 当前任务获准查阅正式定义，就可看相应版本的分子、分母、范围、观察窗和跨店规则。 | 商品部分析师或店长可以解释乙店再购为什么计入甲店队列。要回答甲店本月复购率是多少，还需要获准的结果或计算依据。 |
| 用汇总结果 | 按已授权的对象、用途、期间和汇总粒度引用。总部月报可引用获准的 A 品牌直营月度结果；甲店可看分配给该店的队列汇总。商品部想按品类比较，先找符合该问题的获准品类汇总。 | 月报注明实际引用的汇总、口径版本、品牌与截止日。只有门店总数时，品类如何分布仍未知；若尚无可用的品类汇总，可请有权团队按已核口径提供。 |
| 读明细重新核算 | 无论来自哪个部门，只有当前任务有权读取所需范围内的会员关联、首购、再购、退款等明细，且资料覆盖相应门店和完整观察期，才能重算整项。 | 甲店店长若只获准读本店订单，可核本店首购并引用获准的跨店结果。乙店明细不可读时，报告要注明引用汇总及已核范围；不能将乙店再购当作零，也不能声称已独立复算跨店复购率。 |

原用途和授权覆盖时，按新期间核对版本和资料截止，继续引用。改用集团按人去重考核时，需要适用的集团身份、渠道和政策，由有权业务负责人确认。需要扩大明细访问或分发更细结果时，由原数据或结果权责方处理。两种变化可以在原预览一次说明，各方只处理各自的决定。**验收按承诺的用途匹配权限。** 总部月报获准准确引用正式汇总，可凭同版、同期、同粒度的结果验收引用。只有承诺逐笔重算的用途才需相应明细和完整覆盖。

### 4.3 跨月、换人或换项目

在同企业的获准项目中找到适用的同一个会员包。Agent 依经营问题、企业、品牌、渠道和权限核查已发布资产、可见的在建事项和待补资料。只换月份出数，直接使用有效版本。已有草案，在原事项补证并沿用负责人。复购已发布、本月新增购买活跃，在原包增加该用途，引用已有身份、门店和有效购买规则。首次购买可以计入购买活跃。到店活动签到若已有草案，乙店新交的关联说明只补到原事项一次。

原项目归档后，获准运营人员可在新项目接续维护同一个包。原项目保留只读历史。接续的运营人员按当前授权访问私有附件和未共享草案。品牌包和集团包都可能适用且会改变月报范围时，再集中确认。原资料不可读时，先完成有依据的部分。跨企业发起则回到所在企业的授权目录；只有获准公开或共享的参考可以跨企业使用。

### 4.4 版本与例外

分析任务在开始时解析当时合格的正式版本，按企业、用途、权限和事件生效日期精读原文。数据截止和观察窗单独判断。“本次依据”分别记录目录供给、实际读取及其完整性、作者采用及独立核验。建设时用过的标杆可沿来源追溯。任务途中出现新版时保留本次准确依据，遇到失效、撤权或已知错误时说明影响，继续可行部分。按今日口径重算历史应另存并注明比较条件。

例外逐项记录替代的规则、事件、门店与渠道、生效依据的业务日期、依据与批准人、到期或复核时间。例：甲店 6 月 28 日首购，乙店 7 月 5 日换码。若乙店自 7 月 1 日生效的试点规则将全退重开认作同次购买，这次换码不增加复购人数。队列归甲店，例外按乙店事件日匹配；示例窗口到 7 月 28 日，数据只到 7 月 20 日须标未成熟。两条例外冲突时按已批准的优先关系处理，未定则列待核范围，其余可比部分继续。

行业或标杆更新后，Agent 对照已采用条目给出差异，企业负责人核定受影响的口径和用途后才发布企业新版，同时保留原版和已批准的局部例外。新增 60 日观察视角时，可与原 30 日用途并存。正式变更政策时，说明生效日以及跨期比较的限制。企业底座后来补齐时，若统计对象、粒度、业务含义、适用范围和期间相同，部门包下一版直接引用共享正式版，沿用原证据和样例。新增集团按人统计的用途时，保留原品牌按账号统计的用途。发现旧映射确有错误时，回原资产纠正。

## 5. 反馈、修订与真实闭环

| 发现及核查结果 | 处理归属与交付 |
|---|---|
| 会员指标已经规定按人去重，交易和退款映射也正确，但本次 Agent 把同一会员三次购买计成三个人 | **原任务纠错。** 按原规则复算，另存更正版，说明分子、排名或建议是否改变。若错误只在报告文字，纠正相应段落。企业资产沿用原版。 |
| 乙店组织活动带来了再次到店，负责人想先查导购执行；或这次临时想看“只算回原店”的情景 | 临时假设和试算保留在**原任务**；有关联 Case 时，把采纳、补证或暂缓的选择、实际行动和后续观察留在 **Case**。一次活动或一次试算只覆盖本案。 |
| 跨月退款已经发生，原报告截止时可以读到，多个任务共用的映射却把它漏掉 | **Studio 接手，修订原销售退款映射。** 定位受影响的交易、指标用途、门店、期间和报告，会员包引用修订后的原资产。若共享映射正确、错误实际出在已发布指标的公式，则回原 SAP 指标修订。 |
| 原交易事实准确，企业决定从指定日期起，某些试点店的全退换码重开合并算一次购买 | **Studio 接手，修订会员域规则。** 写明适用事件、门店、业务日期、依据及批准人，更新受影响的会员指标或包引用；销售退款资产继续如实保存退款和重开两笔事实。 |

用户从原回复反馈一次即可。Agent 可在获准范围提出贡献，受管只读任务沿原权限处理。Host 关联来源任务、准确报告和实际采用版本。建设 Agent 核查问题发生时的规则、数据截止、映射和材料可见性。同一版本同一问题已有记录，追加新证据。截止后才发生的退款应按新截止更新；认定旧映射有错，要能核实当时可见且按规则本应纳入的退款。

修订由原权威发布，会员包更新准确引用，只重核受影响的用途。旧报告保留原文、截止日和当时依据，可关联影响说明与更正版。Case 保留当时的选择和已发生行动，由负责人根据新依据决定是否调整。实质修订后，再用同企业获准项目里的独立任务核新版是否被正确采用，核对一笔应改、一笔应保留的结果。尚未发生真实修订，记“已可用，回补待验证”。

## 6. 首期交付与验收

### 6.1 范围

| 范围 | 首期产品决定 |
|---|---|
| 直接复用：建设与专业资产 | 沿用 Studio 的覆盖盘点、资料回查和版本依据形成首份交付。从原企业 Studio 发起真实建设任务，由 Pi Agent 自主盘点获准资料，并沿用逐项采用、修改、排除、新增或待定的处理方式。共享门店、交易、销售退款继续回原资产；指标和方法继续由 SAP 维护；语义查读按需使用 Semantica。 |
| 直接复用：发布、分析和反馈 | 复用发布预览、分项回执、企业目录、准确版本查读、普通任务“本次依据”、回复旁反馈、企业贡献、Case 与历史报告。用户仍从原分析窗口直接提问。 |
| 必须补齐：领域建设的首份交付 | 在企业体系总览中交付按经营问题组织的全景。每行分别呈现业务开展情况、具体资产用途、证据、缺口影响；首批建议说明优先理由、最小补证、本次经营问题的范围及完成条件。 |
| 必须补齐：参考与企业包 | 让设置中的“领域资产包”支持按原文来源和版本登记、查找及进入企业 Studio。同一来源同一版只登记一次。企业会员包能把实际采用的原段落、企业决定、适用范围、局部例外与原资产版本串起来；企业线和会员线共用同一份决定。获准运营换项目后，能定位适用的原包、已有用途与相关待补事项，沿同一资产接续。 |
| 必须补齐：场景与版本 | 给门店会员复购场景写明适用问题、必要依据、可用范围、排除条件和交付要求，沿用已有 SAP 指标及场景。按定义参考、受限计算、正式计算等用途接入发布和查读；新任务能取得准确版本。参考或共享资产升级时，能指出受影响的企业条目、用途和报告，保留历史。 |
| 后续再做 | 将商品、供应链、营销等其他领域完整企业化，增加标杆与场景，在第二家企业验证跨企业复用，再评估复杂的多品牌、多区域例外优先关系。首期先支持有依据、有生效期的局部例外；遇到重叠未决的规则，只限制受影响范围。 |

首期门店复购案例应交付可按用途发布的企业会员包、指向 SAP 和共享资产的复购场景、首次实际使用及修订后再用的依据。首次核定身份去重、有效购买、队列、跨店归属、退款换码和观察窗。真实企业可依其经营需要选择不同首批用途。现有 Studio 工程记录和企业实际采用分别取证。

### 6.2 首次真实提问与统一判据

首次使用可发生在**同企业、具备本次用途所需授权的项目**。新开分析任务，使其独立于建设会话，只提供经营问题、获准资料和截止日。Agent 自主找读企业资产并给出答案。负责人在这次结果上认可已证实的用途，无需另填验收表。若只承诺引用汇总，核准确来源、范围和引用；若承诺重算，由具备明细资格的人核数据覆盖、计算和业务解释。

| 按具体用途记录 | 判定依据 |
|---|---|
| **通过（复用成立）** | 实际采用准确资产，交付达到约定范围和完成条件，并有与用途相称的独立核对。核清能关联与待核的账号可以通过。 |
| **部分成立** | 已证实一个可独立使用的子用途，其余受资料、权限或未决经营规则限制。写明已证实部分和原目标差额，如“核销率已可用，预算用途待补证”。 |
| **待验证** | 尚无独立使用，或只见目录、自述及碰巧正确的数字，无法核实实际采用了哪个版本。指出还缺的证据。 |
| **未通过** | 有明确反例。已查实本次应采用修正后的退款映射却使用了错误旧版，即使汇总数字相同，该用途也判未通过。把不可读的乙店再购当作零、将退订会员列入短信候选，同样按受影响用途记录问题。 |

发布状态、待核的业务事实、验证结论分别记录。资料不足时正确限制结论，可以通过“能否识别使用边界”的检验；当承诺的整项计算仍缺依据，原目标继续待补。已查明的错误保留在对应失败项中。

### 6.3 三种交付结论

| 结论 | 成立条件 | 记录的范围 |
|---|---|---|
| **产品能力可交验** | 在获准的演练环境中，沿正常产品入口走通参考登记、无题发起交付全景、选定用途后的建设及其余环节，覆盖权限、版本反例；能出示全景建议的企业依据，以及发布、查读、反馈与再用证据。允许用合成资料演练退款修订。 | 记录候选或正式产品版本、环境、数据性质、通过项和待验证项，交用户验收。已有 Studio 工程证据可复用，本轮新增的领域包衔接仍需单独核对。 |
| **企业首轮已可用（按用途）** | 资产按获准范围正式发布。首次真实、独立的新任务自主找读准确版本，给出的答案达到首批约定的完成条件，并与本企业依据核对。身份用途核判断及覆盖，预算用途核计算和支持取舍的依据。负责人可在这次使用结果中认可适用范围。 | 发布后尚无使用证据，记“已发布，待首次使用验证”。若只有较窄用途通过，分别写明该用途与原目标的进展，如“受限用途已可用，真实首购复购待验”。首轮使用通过而尚无真实修订时，记“已可用，回补待验证”。 |
| **真实闭环已验证** | 在实际使用中出现真实的资料、映射或政策变化，经原权威核查修订、发布，再由独立新任务正确采用；受影响项得到纠正，无关项保持正确，旧报告和原决定可追溯。 | 只关闭有证据的企业、问题和用途。产品演练单列；经营改善、无改善或尚无反馈由 Case 持续记录。 |

产品按参考登记、首次全景、企业内化、按用途发布、首次实际使用、反馈修订、新版复用七个环节交验。角色、归档、资料不足、换题及版本变化的对照放在附录 B，按所验用途选取。企业日常沿第 1 节的四步使用即可。经营决定、是否执行以及效果另由实际 Case 记录。

截至 2026 年 11 月 20 日，仓库的目标企业落地记录 M01–M05 仍列为未启动；既有 Studio 官方 Pi 与合成 Provider 的验证可作工程参考。首次真实使用、企业专业正确性和真实修订闭环，以对应证据更新，产品最终验收由用户决定。
