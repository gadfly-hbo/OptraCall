## 身份、版本与来源

1. **参考在设置登记。** 以受维护的来源身份和发布方版本识别原版，另存维护者、标题、适用范围、证据性质、定位方式、可见范围及完整正文摘要。来自两个入口或同一原件的不同路径都解析到同一登记；首次并发登记也只落一条。同版摘要不同保留差异、待核冲突，继续指向原获准版本；新版另存并保留前版。原件无法取得或核准时显示待补字段，登记占位不取得“原文可回查”资格。
2. **八份参考分别登记。** 五份通用包为会员、商品、门店、供应链、营销；Nike 企业 T03 与会员 T04 为两份；江南布衣为一份，保留第三方研究、媒体转述、集团/品牌范围和数据分歧。行业 T01、领域 T02 作为两条路线的背景入口，共引时保留出处。隔离测试可用合成替身检查去重、冲突和升级机制。交验八份正式参考的产品回查时，由获准测试者从设置逐一打开原版和具体段落，与验收清单中的原件摘要逐份核对。任何缺件或不可读项单列待验证。
3. **同一企业包承接两条路线。** 使用原企业归属和稳定 Studio 体系身份作为包的归属锚点，明确绑定领域、包 ID 和稳定用途 ID；该企业已有多个共享体系时，包可准确引用其他体系的原权威。包修订保存前版、不可变的组成清单及摘要。清单按用途引用原资产权威、ID、准确版、摘要和项/原段位置。全篇背景留在原处。被采纳、修改、排除、待定或受升级影响的条目才留逐条取舍，企业新增条目也可只引用本企依据。每项关联企业原件或有权决定、范围、粒度、生效期、例外及已有样例。两条路线命中同一经营问题时归并到一份企业决定。指标公式和方法回 SAP，门店、订单、退款、换货与原单关联回原资产，共享数据仍由原业务权威保管。
4. **用途有业务含义和完成条件。** 写明要回答的问题、统计对象、品牌/渠道/门店、适用期间、必需依赖、窗口、证据门槛、排除及交付。区分经营已开展、明确未开展、开展情况待核，与定义、映射、计算、实际使用的证据互不替代。原目标、已交较窄的部分和剩余缺口同列。已点名用途复用相同资产和工作项，只省去首份宽题调查。
5. **跨项目续建。** Agent 在获准可见的同企包、用途与待办中定位原事项；仅当范围歧义会实质改变结果才集中询问。Host 先用企业、包、已核的用途含义和实际业务范围在同一写入操作中查找或建立原事项。即便两个项目的请求标识不同、发起时尚无事项 ID，相同用途和范围也只产生一个事项，可写双方取得其同一身份。不同统计主体或实质不同的范围分别保存；仅文字相近时由 Agent 核实经营含义。已有事项再用其身份、前版及请求标识处理补证、重试和并发，保留修订前提，拒绝用旧稿覆盖他人新证据。月份、人员、建设项目变化不改变包 ID。新项目有写权时成为维护执行方，原项目归档保持只读，原附件、未共享草案和会话在新项目按当前授权核读。跨企业只供应获准公开或共享的参考。[企业归属](../../../src/host/enterprise-scope-store.ts) · [现有体系与维护记录](../../../extensions/business-plugins/studio/contracts.ts)

## 发布与权限是两次不同的判断

**一份预览。** 经营负责人只处理会改变本次用途的未决项。例如跨店再购归初购队列，第二笔交易的销售仍归发生店；选择同店返回时标明服务的经营问题。已有有效决定和授权自动带入。预览按用途冻结企业包版、原资产及其摘要、经营范围、例外、事件生效日期、数据截止、排除、依赖、适用的发布/引用权及决定出处。一处确认送到各原权威，已有发布版可只核准确版本。需多个权责方时沿原决定及有效授权，只向缺决定的一方发起对应事项。

| 场景资格 | 所需条件与交付 |
|---|---|
| 定义参考 | 正式口径可解释。首购历史、完整退款或可比门店不足时，展示所缺依据及限制。 |
| 受限计算 | 采用独立名称“资料期内首次可见购买后 30 日复购率”。限定资料起点、品牌、渠道、去重、已核退款及完整后续窗口。历史覆盖不同时仅在可比范围内比较，余下分列。 |
| 正式计算 | 真实首购依据、身份及跨店/品牌归属、有效购买与退款冲销、成熟观察窗和样例核对均可查。资格绑定企业批准范围和有效期。 |

**逐项执行、逐用途供给。** 复用原预览内容指纹、`confirmPublication`、`publish` 与 `reconcilePublication`。每个原权威的操作保存请求身份、冻结输入、目标准确版、原回执或失败/未知事实。先核该用途的全部必要依赖和权责结果，再写入合格目录。预览过时需更新受影响项并显示变化，独立未变项的已得回执保留。网络中断、取消、重启、并发重复确认时先查原请求和目标；原请求未知与“准确目标已存在”分别显示。只有得到可核证据才能补记状态。某一必要依赖失败、未知或变稿时限制其依赖用途，已独立合格的定义或其他用途照常可查。原轨迹只追加，旧 FAIL/UNKNOWN 可回看。

**实际允许看什么。** Host 根据当前企业、实际人员/项目任务的获授权身份、用途、对象范围、期间及粒度，在原数据/结果/正式定义的权责方核验授权。部门名称、UI 选项、Agent 自述和建设项目的权限都不能充当凭证。看定义只提供获准规则与范围；用汇总要求准确结果版、口径、期间、粒度及分发目的相配；重算才要求相应明细和真实覆盖。汇总可有自己的授权来源和摘要，使用方无需取得汇总背后的明细。取不到乙店明细时不得把乙店记成零。预览、目录、搜索、正文、工具返回、附件和历史链接都按使用方身份过滤；用户可看到获准内容及其限制，受限行的姓名、路径或正文不可经摘要间接暴露。

**授权从哪里来。** 已有资源权责和授权仍有效时由 Host 直接解析。原记录若只能说明“项目属于这家企业”，此次须增加最小的资源授权记录或接入原权威返回的等价凭据。记录授予方及依据、被授权主体或项目、资源与用途、允许的操作、期间/粒度、有效期及撤回状态。Host 在任务创建、恢复和每次实际取用时核对当前主体与项目；客户端提交的角色名不产生权限。总部使用的汇总也必须指向已发布的结果版本、期间、粒度、原指标版本及授权来源。授权变化只作用于受影响部分。验收同时要求合法角色取得其应得结果、越权角色拿不到受限材料；一律拒绝不能通过资格检查。

现有 `enterpriseContextFor` 生成摘要时调用企业级目录；`port(...).catalog` 再带消费项目过滤。现有 `readStudio` 会递归核来源及依赖，源可读、可重算、可引用经授权发布的汇总需要拆开判断。新资格须同时作用于首次模型上下文、分页和准确查读；分发一个已获准的汇总，只交付该汇总及允许公开的口径引用。普通项目沿官方 Pi 的原生文件和执行工具运行，私有明细即使从页面或工具目录过滤，仍可能从原文件、连接器或其他执行能力读到。按任务实际可见输入交付最小授权资料。涉及受限明细的任务，只有底层文件访问、连接器和可用子工具均能执行相同限制才能接入；复用现有受管隔离能力，优先给可验证的授权视图/摘录和受控来源。无法建立必要隔离时，限制该数据的交付并明确原因。新包不得以普通 010 软提示充当隔离，不把所有旧项目切换为受管模式，也不以启用独立核算换取读权。兼容既有普通任务可自由使用获准材料。以正常分析会话、连接器和 SDK 工具进行允许/拒绝的端到端核验，并核受限任务的续接、授权缩减和下游分发。[资源边界说明](../../../docs/agent-session-integration.md) · [项目 Pi 接线](../../../src/agent/project-session.ts) · [受管工具](../../../src/agent/protected-tools.ts)

## 在哪个时间使用哪个版本

首次执行时，Host 固定合格目录的企业、包版、各用途有效期、必要原权威准确版本、授权范围与取数截止；只记录给该任务实际交付的可见范围，Agent 按问题查读需要的部分。固定包版不强制选用所有条目，也不冻结权限。续接/翻页时核同一版本、范围与正文完整性；任务中发布新版只向新任务供给。已撤权、失效或已知错误时停止供应受影响项，保留原历史并提示影响；其余有据部分可继续。按新政策重算历史另存，并给出所用政策版本与比较条件。

企业自己的政策日期、交易/换码发生日期、数据可见截止与成熟观察窗分别记录。局部例外写明替代的原规则、事件、范围、业务生效日、批准依据和到期/复核时间。优先关系仅使用已批准者，未决重叠只限制所涉交易/范围。参考或共享资产出新版，依“来源原段 → 企业决定 → 用途/依赖 → 任务实际采用或可能受影响的报告”查差异；分别显示已核影响和待核影响，由 Agent 解释并提交受影响项。旧包、例外与批准决定原样保留。共享底座在主体、粒度、含义、范围及期间相同后可供部门包下一版替换引用；集团按人与品牌按账号是不同用途，30 日与 60 日可以并存。

## 从原生回执到更正后的独立使用

- **本次依据分层。** 沿原会话保存目录供给、每次工具调用的原权威准确版本/摘要、返回片段和覆盖范围、作者声明的用途和准确报告、独立核对的依据与结论。报告/回复将这些证据按任务、原生会话、回合及具体回复或产物定位，避免把另一轮的读取归到本轮。补记较早读取时须指向实际发生的那一轮。重算需核输入覆盖、分子分母与关键逐笔依据；引用汇总只核准确结果、同版同期同粒度和报告引用。缺证据留“待验证”，发现实际用了错误旧版则该用途“未通过”。现有 `declare-use` 验证来源及报告并创建 `not_assessed` 声明；`assess-use` 的 Agent 记录也不能自动取得独立验收资格。旧原生记录不补造。[Agent 使用声明既有交付](../studio-declare-use-contract/result.md) · [本次依据组件](../../../src/host/ui/SemanticContextPanel.tsx)
- **反馈一次，复用原事项。** 由 Host 回读原生消息、准确报告、当时采用的包/原资产和截止日期。同一版本同一问题已有记录时，补证合并，重复提交不重复起单。有共享价值的问题由建设 Agent 核实发生时资料是否可见、映射/政策/公式何者有误。原映射漏连回原销售退款权威；公式问题回 SAP；从某日起变更的换码约定回会员域；仅本次误算在原任务另存；暂行假设继续留在原分析。人的决定、行动和结果保留在 Case。
- **历史保全。** 旧报告、旧包清单、原生会话、原截止日、回执、Case 的当时决定及已采取行动保持原身份和内容；可另挂影响说明、更正版及新决定。另起同企业获准项目的新任务，由 Agent 独立找读新版，核对一笔应变、一笔应保留。实施同时验当初截止后才发生退款时须随新截止更新，不能误列“当时漏连”；单有新版本、草案、登记反馈或作者声明，闭环仍待验证。

## 会话、公用组件和确认后的检查

沿当前 Interface v3、IN01–IN07，保留兼容 v1/v2 的调用子集。建设在当前维护项目的项目任务 owner（projectId、taskId）运行，体系、包、用途是业务上下文；普通分析在各自项目任务 owner 的会话独立使用。复用配置、原生会话、已有 port 与现行取消/恢复。可选 Semantica 文本作业沿 `studio-semantic-generation` 的独立 owner（projectId、taskId、systemId、jobId），不获得建设或发布资格。Host 管环境、权限、版本、证据和幂等写入，Pi Agent 决定取材、方法、核对、补证与纠错；Host 不凭固定步骤、关键词或数字评经营答案。包登记及变更通过 OptraCall 自有适配器和公开接口接入。基线依赖声明为官方 Pi 1.4.0；已有规则接入交付核过官方 Semantica 0.7.0。实施须核届时实际依赖与运行环境；本方案不要求 SDK 变更。[统一会话](../../../docs/agent-session-integration.md) · [Studio 语义资源](../../../src/host/studio-sessions.ts) · [Pi 依赖](../../../package.json) · [Semantica 接入证据](../studio-rule-reasoning/result.md)

| 确认后验证对象 | 失败或兼容处理 |
