# L2 后端语义支撑与首个 P1：UI 确认说明

v0.3 · 2026-11-04 · **待用户整体确认；这是虚构状态原型，不是产品已实现。**

入口：[单文件可点 Demo](../../../docs/prototypes/fourbase-l2-temporal-projection-ui-demo.html)；约束沿 [L1 spec](../fourbase-l1-semantic-trace/spec.md)、[L2最小边界](../fourbase-l1-semantic-trace/component-boundary.md)与[工程规范第2–4节](../../../docs/engineering-workflow.md)。全部虚构业务文本、修订和时间以本包[同源基线](synthetic-baseline.md)为唯一来源，用于检验交互，不定义产品持久结构或真实专业结论。

本版按用户新确认突出L2的后端语义价值：本体表达概念／范围／规则，知识图谱组织对象／关系／来源／版本，经原Pi工具供Agent自主取用与理解。关键口径、冲突和结论限制由Agent在回答正文主动解释，业务含义只留在依据详情内作为可选说明，没有独立业务含义页或必经查看步骤。

旧v0.2确认包已在本树`.local/fourbase-l2-preparation/history/confirmation-v0.2-before-backend-positioning/`保全，更早v0.1保全不变。本版不沿用旧稿静态PASS作为v0.3通过证据，变更候选由主Agent安排新的固定复核。后端语义理解、产品接线和真实收益均未验证。

## 两层展示与完整能力映射

**A方案审阅区**展示完整L2后端目标、组件候选与P1边界，供整体确认；**B原任务候选体验**展示正文主动说明和自愿核对依据。L2价值在后端帮助Agent正确理解与适用业务语义，界面可视化／详情是辅助。审阅区的展开、范围标签与情景控件不成为产品用户必须选择的阶段或组件。

| 完整L2能力 | 本页如何表达 | P1只核什么 | 后续按能力细化 |
| --- | --- | --- | --- |
| 业务语义组织 | 后端本体表达概念、指标、规则、对象范围与准确版本；目标回答在正文解释净销售额与退款归属 | 保留准确源身份，不把预置解释冒称组件已理解业务 | 语义组织及必要本体／约束能力的具体规格、结构与Agent正确理解实证 |
| 来源、规则约束与冲突 | 来源性质、适用范围、版本差异与未知；提示仍由Agent读原文判断 | 最小原生来源与显式关系映射 | 完整规则约束、冲突处理和治理，不能由结构通过推成业务正确 |
| 关系与事实演变 | 后端知识图谱组织对象、关系、来源与版本；有向支持／反对／依赖、原稿、后来留存与回溯声明 | 原生时间、必要路径、版本快照、重开与从源重建 | 持续更新、实体对齐及更复杂演变；遇明确缺口再比较Graphiti |
| Agent按需结构化检索 | 经原Pi工具由Agent自主取用、理解、核适用性并解释关键冲突；正文主动说明是可观察输出目标，不规定内部顺序 | 与L1的固定同源工程对照，不提供正式产品工具接线 | 有范围的正式读port／工具和Agent规则适用／冲突处理的实证评估 |

Semantica是后端语义支撑的优先路线，可从本体／语义组织、知识图谱、来源及时间模块逐项核原生复用，尚未实装；本轮P1锁定0.7.0的最小组合。Graphiti在持续事实更新、实体对齐或演变查询出现Semantica最小路径未满足的具体缺口后，才进入同源比较。二者来源、关系、检索、时间能力有重叠，不默认两个引擎同时运行，也不把它们各自固定为半套互斥业务能力；主源与静态限制见[研究](research.md)。原SAP、资料、M2／Case各持原权威，Pi继续唯一Agent运行入口，Host不接管推理或业务取舍。

P1是完整L2的首个小切片：整体确认后只做固定Semantica0.7.0、隔离合成源、来源／显式关系／时间／快照／重建及L1同源对照。完整本体治理、自动抽取、持续摄取、Graphiti运行、正式产品接线均有“未来能力／未纳入P1”标识；它们不是永久排除，也不表示某个后续阶段自动覆盖全部L2。后续逐项补规格、必要结构与有效授权。

P1只验证接入底座工程行为，不能由其通过、预置UI、图节点数量或可查看详情声称Agent语义理解提升。完整后端价值须在后续评估Agent能否正确理解业务含义、正确适用规则并处理冲突；本页仅展示目标回答，未提供这种收益证据。正文主动说明也不要求Host强制每轮查库、规定工具顺序或建立通用修正循环。

## 要确认的用户体验

1. 原任务填写问题并发送，回答正文主动说明本次沿直营门店SAP1.2回看，净销售额为支付金额减当期登记退款；渠道同名口径适用线上且含服务费调整，本次不混用。这些关键含义在普通正常情景即出现，不只放在冲突预设或详情里。没有先维护关系、补齐日期、创建Case或选择引擎的步骤，正常新增必做操作0。
2. 正文主动说明B1.3退款归原销售业务日、N-1日期粒度的回溯生效声明／11月2日留存分开、D-1迟到退款和E-1缺货限制，以及哪些未知妨碍量化或归因。不打开详情也能理解关键结论、范围与待核项，并可继续任务。若目标确需缺失材料，由Agent针对必要缺口核对或澄清，不要求先补齐资料库或每轮必查。
3. 回复旁沿用“查看依据”。抽屉默认看原稿与关系，内部`details`的“口径说明／业务含义（可选）”仅供核对A／B／C／D-1原声明，没有独立页面、路由或业务含义tab导航。原稿／今天回看保留；N-1不会改写10月10日原引用。路径存在不代表因果、证据充分或计算正确。
4. 同名的直营门店／线上渠道口径保持不同对象与范围。门店A按当期登记退款、后续B按原销售业务日归属；渠道C包含服务费调整。没有准确引用时应核清，不能静默合并或选latest。
5. 部分时间映射、无法表达的时间、准确原文失读、空语义资料和投影不可用各自披露。原分析与草稿入口仍可用；既有准确引用不因投影失效消失，不把失读原文改开新版。
6. 追问只预填同一任务草稿，不自动发送、不改SAP／报告／人的选择。图的更新或失效不自动撤销任何经营选择。

虚构源标签与本包三问保持一致：A为门店SAP1.2、B为10月28日发布的门店SAP1.3、C为渠道同名SAP1.2；R-10第2稿明确引用A；K-10绑定R-10／A／I-1／D-1。I-1不含足以识别因果的对照，D-1明确门店日汇总／元／上海业务日与退款可能迟到；E-1是缺货反证。C-17/J-1的原声明方向为`supports K-10`、`opposes E-1`、`depends_on K-10`，再沿K-10的sapRefs查回A，不新增当前Case类型不支持的直接SAP边，也不由标签推断反证已被裁决。N-1为退款归属通知第1修订，声明10月1日起适用；U-1为口头补充，发言／留存／提供时间无可靠证据。人的后续选择未记录，与小范围试验建议分开，不伪造人的已采用决定。

失读情景只将准确输入I-1标为原文不可读，来源详情保留引用而不呈现正文；D-1说明仍可读，回答与其详情可以引用原声明。两件源的状态分别表述，不因输入失读就声称数据说明也失读。正常技术详情只表示引用可映射，时间含未知，不把全套双时间映射标为成功。

该情景的回答正文与依据抽屉同样将I-1样本／对照条件标为未核，只保留可读E-1／D-1的原声明；可选业务含义说明只依据A／B／C／D-1，不借D-1冒充已读I-1。今天回看和I-1来源详情同样将正文／样本／时间标当前未核；目录中的旧留存声明只作为原引用元信息，不把它或旧摘要当本次原件读回内容。

全部样例留存时刻按基线、Asia/Shanghai（+08:00）：A为9月20日09:00、C为9月21日09:00，I-1为10月9日15:00、D-1为16:00、E-1为18:00，R-10为10月10日17:00、K-10为17:05、J-1为18:00，B为10月28日09:00，N-1为11月2日10:00；U-1未知。这些是虚构材料的声明，不是生产数据或实际保存回执。N-1的“10月1日起”只到日期粒度，不补出当时被知晓的时刻。

## 视觉与布局决定

- 假设：方案审阅者需要看清L2后端价值与本轮P1；普通用户在已有任务读到主动解释关键口径／冲突的回答，查看依据及其中业务含义说明完全自愿。本页不证明后端语义理解增强或完整L2收益。
- 页面类型／密度：方案审阅加现有产品任务候选工作区，balanced；任务区左侧输入、右侧回答。850px以下设计为单列，375px可发送与可读正文是待实际浏览器核对的目标。
- 视觉：延用L1原型的紫灰色、轻边框、6–8px圆角、系统中文字体和浅色／深色配对。现有产品模式优先，不新增图编辑器或组件导航。
- 层级：A方案审阅与阶段标签独立于B任务体验。B为任务上下文→普通提问→正文说明关键口径／冲突／限制；查看依据→原稿／今天回看→准确来源或可选口径说明，均是自愿分支。普通流程不露引擎API、字段表或维护成本表单，也不让用户承担语义理解工作。
- 状态：初始、完成、查找中、停止、partial、unsupported、源失读、投影不可用、空记录；语义颜色只用于状态。Demo审阅情景持续标注为审阅控件，不成为正常操作。
- 交互：原生button／textarea／details／dialog；表单有label与错误关联，动态状态有文本和live提示；对话框Escape关闭、焦点进入与返回触发点，tabs支持方向键、Home／End。
- 长来源：完整示例引用在详情折叠区换行展示，不靠截断掩盖准确身份。Demo没有实际hash，不伪造保存或保全回执。

## 相对现状的最小差额

L1已有准确依据／后来变化的按需入口。v0.3将关键口径、版本差异、范围及冲突限制放到Agent回答正文，原“查看依据”中只保留可选补充说明，不新增业务含义页面。后端完整目标由本体／知识图谱为Agent提供可理解、可正确适用的语义支撑；界面详情辅助查证，不能作为完成标准。方案审阅的完整四组能力、组件条件分工和P1边界保持；既有任务入口、Pi自主性与原权威保留。

P1尚未实施，本页候选产品交互也未接线。正式实施范围要依据P1证据、真实现有组件与后续确认再定；本文件不构成正式UI开发授权，不能以原型已写代替当前产品接缝或组件实证。

原型是单一HTML文件，可以本机直接打开。所有资料、ID、日期、关系和回答为预置虚构内容，只用内存状态；未连接Semantica、Graphiti、Pi、Provider、产品API、业务库、浏览器存储或真实文件，不演示引擎安装。切换审阅情景、打开依据、切换角度不自动发送；发送计数仅反映本页模拟提交。
