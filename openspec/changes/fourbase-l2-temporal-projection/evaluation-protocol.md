# L2 v0.3 后端语义定位、可选依据与 P1 验收

v0.3 · 2026-11-04 · 待整体确认后仅实施原P1；以下是预期，**不是已运行结果**。

完整L2按spec§1覆盖语义组织、来源／规则约束与冲突、关系／事实演变及Agent按需查询。Semantica／Graphiti是有重叠的候选实现；本协议L201–L210仅验证P1，不能外推完整本体治理、实体对齐、持续事实更新或Graphiti完成。其他切片须有各自任务／证据和适用验收。

v0.3核心价值是后端：优先借Semantica本体／知识图谱帮助Agent理解、取得和正确使用语义。完整后续验收看Agent概念理解、口径／范围适用、冲突／未知识别与解释是否有实际改善，同实际模型／内容／权限／预算下比较；该真实模型范围尚未获准。P1工程、来源保存、图节点数、页面／详情打开或预置回答不证明语义理解提升。UI只辅助解释，用户不承担本应由Agent完成的理解和冲突处理。

## 1. 固定输入与比较

P1以[合成材料](synthetic-baseline.md)为唯一业务内容。冻结题面／每份源／显式关系／准入／版本／hash／时区及未知，先记录L1三问基线，再给P1候选相同资料。两边公开同一结构材料与关系；人工答案只作评分预期，不给组件候选独占。L1保留原find/read/trace；本轮P1只增加必要派生查询，不故意削弱L1，这不是完整L2的全量能力定义。

P1当前不申请真实Provider。确定性协议检查与组件查询只证明该固定输入的技术行为；没有模型的运行不能写成自主回答正确率提升。若以后做真实模型对照，须重新固定实际SDK注册模型、Provider/协议/线路、reasoning/thinking、contextWindow/maxTokens/compat、相同内容、权限和预算；旧“模型名相同”不代表等价。

逐问记录准确源／方向／两轴判断错误、漏报／不确定、实际源读取次数与字节、查询及重复取材、首次建图与增量维护、关闭重开与重建、耗时／内存／磁盘和人工处置。运行记录保留脚本／参数／版本与首次输出。不要把首次建图成本移出L2账单或只比较查询时间；GUI预置回答不计成绩。

精确双轴／边界先用合成基线§5明确给定的API向量，L1/L2同样取得全部结构化声明；该结果只计组件原语验证，不能当作三问已有未知时间得到解决或业务收益。业务原材料不补机器时间，Case沿J-1→citation K-10→sapRefs A，不建当前类型没有的Case→SAP边。

继续门槛：至少一问较L1减少可核错误或重复取材，同时无新增严重错引／泄漏／原件破坏，维护和资源成本可解释且可接受。先测实际基线，再给出采用理由与成本取舍，不预设改善百分比。没有真实模型结果时，只能提出确定性工程增益；不能宣称专业、经营或用户收益已证。

## 2. 从需求导出的反例

| 对应要求 | 必须实际检查的行为 |
| --- | --- |
| L201 | 固定wheel hash／实际Python与依赖；import必要API；记录无extras实际imports是否可行；不可悄悄改main／旧版／额外服务 |
| L202 | 门店1.2与渠道1.2同名不合并；旧报告不换1.3；同端点同类型但不同来源的平行关系均保留；source/target方向、来源位置、hash缺口可回读 |
| L203 | 先按基线§5两轴向量检查不同截点、半开起止／recorded边界、端点与平行事实；显式开放不等于未知。三问中N-1不能提前成为10-10已留存，U-1不能填时间或消失，日期粒度／缺时区不升级；原语与业务结果分账 |
| L204 | query文本未执行不得冒称自然语言理解；路径方向／必要路径／截断，非因果、平行边及循环；mapped/partial/unsupported逐项核实，不能凭函数名通过 |
| L205 | 正确snapshot写入后关闭进程重开；新源更新／明确失效事件形成新代，旧snapshot可核；两库分别损坏／缺件／中断，禁止发布半代；同源重建语义比对不丢平行关系 |
| L206 | 计算／写库中取消、迟到／停止失败、重开损坏、未知保存结果；保留原输出／半成品及UNKNOWN，不自动模型重放或把原件回滚 |
| L207 | 同源L1基线、L2实际增量／成本；首轮失败与后续修正版分开；见过答案的候选用新冻结变体重核 |
| L208 | L2未装／停用／空集／错误、来源保存失败后原L1和普通计算可继续；必要选材不静默丢弃；权限不足／当前排除禁止返回正文、摘要及泄漏关系 |
| L209 | 计算阶段真实网络／模型请求、文件写范围、实际资源与取消闭合；无证据不写零外传、RSS硬限或ENOSPC已证 |
| L210 | 非作者从spec导出预期后只读检查候选及运行证据，规格／规范／四原则分别给结论；未运行、FAIL、SKIP、UNKNOWN和NOT_PROVED原样保留 |

工程固定查询可以先验证不同时间截点的原生组合；该脚本不是生产查询规划器。若原生路径不支持不同双轴或完整平行边，标partial／unsupported并缩小结果声明，不因需要“通过”而新增时间引擎。只在具体缺口有证据后才考虑Graphiti的另定比较。

## 3. UI 准备与产品验证分开

本次只对虚构[单文件Demo](../../../docs/prototypes/fourbase-l2-temporal-projection-ui-demo.html)做实际浏览器及相称静态检查：正常发送、三问入口、原稿／今天、准确来源、同名、反证、回溯／未知、partial／unsupported／源不可读／组件不可用、追问只填草稿、浅色／深色桌面和375px、键盘／Escape／焦点返回、无外部请求／持久化。浏览器QA是作者验证，不能写为独立复核或产品查询运行。

v0.3按L2D01–L2D06准备核对：后端本体／知识图谱语义理解价值、候选组件作用和P1／完整后续状态在spec／确认页／UI一致。方案审阅区不冒称已装；产品无独立业务含义页／导航或引擎／阶段选择。主回答主动给出相关关键口径、同名范围、版本／回溯冲突及对结论的影响，不只在ambiguous或详情内说明；不打开／关闭详情仍能理解关键限制并继续分析。原“查看依据”内口径说明仅可选复述A/B/C/D-1，非规则／本体引擎结果，打开／切换不查询、发送或保存。

反例：把关键冲突只藏在折叠区；先读含义页才准发送；Host强制每轮查L2／固定方法／自动补算；源不可读仍宣称该源内容已核；用Demo或P1技术通过声称Agent理解提升。均不得通过本轮设计复核。必要澄清只针对影响判断／权限的实质缺失，不要求所有任务填全语义材料。

P2如获采用，重新走真实Host→公共project-tasks→锁定Pi→实际组件／原源→原M2保存与重开及产品UI，覆盖原普通／受管／封闭消费者、当前资格、配置变化／取消／迟到，最后执行`npm run check`及必要CI。P1不动这些产品接缝，不在纯准备中安装运行整套产品来凑证明。
