# L2 后端语义支撑与 P1：整体决定包

v0.3 · 2026-11-04 · **D01–D10 待整体确认；本次仅获准备修订授权，没有已批准的新结构。**

建议整体确认v0.3 [spec](spec.md)、[UI Demo](../../../docs/prototypes/fourbase-l2-temporal-projection-ui-demo.html)及下列十项的A。确认内容包含后端本体／知识图谱语义支撑、Agent主动解释关键口径和冲突、业务含义仅作可选依据详情及分阶段边界；建议实施授权仍仅为 **P1隔离合成POC**。正式接线及其他完整L2能力不由此自动获准，本次修订指令不是开工批准。

## 第 D01 项：目的、owner 与实施阶段

**我的建议 A：** 完整L2主要是后端语义支撑：优先以Semantica本体表达概念／范围／关系类型／明确规则，知识图谱组织具体对象／事实／来源／版本，供Agent按原资格取得并更好理解、适用和核对业务语义。来源／规则、关系／事实演变及按需查询服务这个目标；详情UI只辅助解释。P1保持原最小来源／显式关系／时间／快照及同源对照，不证明Agent理解已增强或完整本体已交付。POC归本树工程，业务对象归原Store、会话归Pi；不新增已批准的生产本体schema。

原因：完整方向要明确，首个验证保持可控；P1未覆盖的本体治理／实体对齐／持续更新不是永久排除。替代B：以P1索引代替完整L2，产品定位不完整；替代C：一次实现全部L2，缺具体需求、结构与原生实证，不推荐。

## 第 D02 项：Semantica／Graphiti作用与本轮组件

**我的建议 A：** Semantica为后端本体／知识图谱语义理解支撑的优先路线，按需复用概念／本体、关系、来源、规则约束／冲突及时间模块；这不是已安装或效果保证。Graphiti仍在持续事件输入、实体对齐、增量事实更新／历史检索等具体缺口后同题比较。能力有重叠，不预设各独占一个部分或默认双引擎。完整本体／规则与动态更新按实际切片细化，不自动纳入P1。

P1保持原固定wheel `0.7.0`／SHA、兼容私有Python及锁定依赖，只验证core必要来源／显式关系／时间／快照和内存graph／原生SQLite。两原生库各自持有责任，不与Case／Board合库，不安装外部图服务器／all／LLM／embedding extras，不改正式DuckDB环境；Graphiti本轮不安装、不摄取、不运行。

原因：先查最小原生能力与成本，再按缺口选择；原研究main `0.8.0`不能替换固定发行身份。替代B：现在同时安装两套全部模块，增加模型、后端与维护责任；替代C：永久排除其中一个，证据不足。若P1 core无法独立运行，保留失败并回报差额，不静默扩安装范围。

## 第 D03 项：对象、粒度、身份与同名

**我的建议 A：** P1一个entity对应一个准确原对象修订；一个relationship对应一条有原作者／原位置的有向声明，或一条原citation显式引用。原类型化sourceRef及其中package/version、store/material/revision、project/dataset/input/description/citation、Case revision等字段完整沿原类型，不新编号业务实体。组件字符串id仅为该类型化引用的确定性编码，带原命名空间；不同修订及同名不同scope分开。此处不冻结完整L2尚未细化的本体或其他生产身份合同。

关系身份还包含起点原引用、终点原引用、原关系类型及**声明自身准确来源／位置**，避免同端点同类型的平行声明被去重。多对多，不对反向边、同名或新版作自动等价归并；hash只校验内容，不替代来源身份。Case只沿当前支持的citation／enterprise等目标，样例J-1依赖K-10，再由citation的sapRefs到A；不新增直接SAP目标。纯组件原语向量只有工程标签，不导入业务Store或成为产品身份。原因：原Store已有身份／修订权威。替代 B：按名称合并，会丢scope与历史。替代 C：新增全域实体ID／对齐审批，当前不需。

## 第 D04 项：字段组、类型、空值与来源性质

**我的建议 A：** P1只使用原生graph字典的`entities`／`relationships`、entity `id`，relationship `id/source/target/type`及组件支持的metadata。以下逻辑组构成待确认映射，不是给产品新建一套schema：

| 逻辑组 | 表达／类型依据 | 必需性与空值／默认语义 |
| --- | --- | --- |
| 精确来源 | 复制已有类型化sourceRef对象、原修订与可回读位置到metadata；原字段保持原类型 | 每个业务投影事实必需；无法定位则不冒称mapped，不猜ID／latest。纯API测试向量单列，不伪装业务引用 |
| 内容校验 | 原源合同中已有hash；存在时保留原算法／字节范围，SHA-256为64位十六进制 | 没有hash明确未知，不能用元数据checksum冒充文件hash |
| 来源性质／声明 | 原对象类型、原文位置、原作者／关系声明；原文与推断分开 | 不推定“正式／正确／采纳”；没有原声明则无边，不给置信度默认1 |
| 关系与范围 | 原`source/target/type`有向关系与原scope；准确引用端点 | 必需，不自动反向、合并或建立因果。没有原scope保留未知 |
| 原始时间声明 | 原文、位置及原合成样例明确给定的粒度／时区 | 可空，空表示未知／未声明，不表示永远有效 |
| 原生机器时间 | `valid_from/valid_until/recorded_at/superseded_at`，仅限来源明确的带时区时间；日期粒度仍保留原声明 | 未知项不进入声称精确的筛选；不以组件默认open／infinite、valid_from或now代填历史 |
| 当前读取限制 | 从原资格动态读取；查询映射／截断／缺失状态随结果返回 | 不把旧metadata中可读状态当今日授权；无可靠证明为未知／不可读 |

metadata只保存最小原引用／声明和必要原文定位，不镜像全量报告或JSONL，不供用户独立编辑。组件provenance checksum仅证明其记录范围。字段不能无损表达则标partial／unsupported；不得为了全部mapped另建通用sidecar／语义库。原因：原生字段和已有ref已足够表达最小候选；替代 B：另造通用九类对象及发布字段，重复权威。

## 第 D05 项：业务时间、留存时间与版本

**我的建议 A：** 分开原稿明确引用、可靠系统留存和业务有效声明。业务时间只有明确来源才映射；recorded_at只用可靠历史留存，索引构建时间另作为工程记录。禁止`from_relationship`自动回填或`apply_revision`把now当原历史known-time。双轴不同截点先验证原生两次筛选组合，不把单一`both/at_time`当完整asOf。

未知业务时间的事实仍可作为有界普通材料查询，但列出“时间未知”；不喂空起点给原生引擎后声称全历史有效。无可靠留存时间不能进入确定的“当次已留存”集合；缺时区／日期粒度不升级。快照只描述投影，不能重建当时全部认知。基线§5明确给定的原语向量验证两个截点和半开边界，显式开放与未知分开；其成绩不计业务增益。原因：组件默认值会制造业务含义。替代 B：保存时间代生效时间，不采用。替代 C：只做无时间关系查询，可在POC时间能力失败时收缩，并记录未达原目标。

## 第 D06 项：读写入口、更新与失效

**我的建议 A：** P1写入只由工程脚本从固定虚构源做确定性映射，读取只为固定查询和比较；不开放任意Cypher／SQL／模型写图入口。不做自然语言抽取、实体推断或Host选业务答案。变化构建新的候选代，旧原生快照及首次证据保留。图失效仅表示派生状态，不自动改源／SAP／报告／Case／choice。

未来产品若采用该组件查询，Agent仍在原工具资格内自主决定是否查询／读源／核算，Host仅核环境、权限、范围、取消和回执；打开UI／GET不触发建图／模型。现有L1和普通分析自主性保持。原因：工程固定测试不是产品强制分析流程。替代B：后台全量摄取／自动失效业务结论，扩大责任。替代C：用户手工维护图，每次新增作业，不推荐。

本项“不做抽取／实体推断”只约束P1；完整L2若需要这些能力，先明确组件原生路径、来源与不确定性、模型／数据出口、更新与取消、准入及受影响结构，再按有效授权实施。规则约束结果必须附规则／适用版本与证据，只能证明所检约束状态，不能自动发布SAP或裁决业务真值。

## 第 D07 项：持久布局、一致性、重开与重建

**我的建议 A：** 仅工程根`.local/fourbase-l2-poc/`，按固定实验／候选代隔离，原生provenance与snapshot SQLite各独立文件；原生graph导出、源清单和实际配置作为实验文件保留。不得向默认dataRoot／原Case库／Pi native建表或迁移。路径由工程固定，绝不信任模型或HTTP传入的任意path。

原生两库没有已证联合事务；候选全量写完、关闭重开核对及源hash一致后才更新工程的当前代指示。失败保留旧代与半成品，禁止半写数据冒充成功。原生`create_snapshot`持久路径须实测，`create_version`浅拷贝不算落盘；源内容改变创建新代，不覆盖旧snapshot。同源重建比较身份／方向／来源／时间和缺口，不用`compare_versions`忽略平行边的结果证明完整无差异。

原因：源可重建派生物无需先建业务迁移／历史事务引擎。替代 B：把组件库并入Case主库，回退复杂且重复权威。替代 C：仅内存，不足以验证重开／重建。生产持久根、原子切换与清理策略明确延期至P2实际采用决定，不从P1实验布局推广。

## 第 D08 项：验证、资源、取消与退出

**我的建议 A：** 按L201–L210先真实记录原生能力，再比较同源L1；全部首次失败／cancel／partial／UNKNOWN保留。工程安装只在确认后的固定依赖获取时用网；运行阶段记录实际网络／模型行为、磁盘、耗时、内存及停止结果。无真实Provider／凭据／业务数据。资源阈值先测基线再写依据；不伪造硬RSS／ENOSPC保证。

至少一问减少错误或重复取材且成本可接受才提出该P1路径继续采用；没收益则不用／收缩，不预写百分比。P1确定性适配先RED；原生探索不是产品RED。L201–L210不验收Agent理解提升、完整本体／治理或Graphiti。完整L2后续须以Agent理解概念、正确适用口径／范围和识别解释冲突的实际表现评价；固定实际模型／输入／权限／预算及有效授权，不凭图节点数、界面或预置回答通过。Graphiti比较仍需具体缺口。替代B：以安装／UI或切片成功代核心价值，不采用。

## 第 D09 项：用户路径、资格与兼容

**我的建议 A：** 方案审阅区说明后端语义支撑／组件／P1，未来能力标未纳入P1／未实现。产品不新增独立业务含义页面或导航：Agent在回答正文主动解释与本次判断相关的关键口径／范围、重要版本差异、实质冲突和未知及影响；用户只正常提问／发送。原“查看依据”详情内的业务含义／口径说明仅自愿深入核对，关闭或不打开仍可理解关键限制并继续任务，新增必做0。查看／切换不发查询或模型，追问仅草稿。解释要求属于Agent输出质量，不在Host添加强制查L2顺序、次数、逐步门禁或通用补算／修正循环；实质缺材料才针对性澄清。失败仍可继续，明确必要选材／权限不静默忽略。

P2沿Pi1.4.0／Interface v3原普通unmanaged `project-tasks`、Host真实owner/profile／IPC/call-local；受管／封闭／核算／需求／PPT无新增资格。当前治理在读时重新核对，跨项目不扩权。停用回到现L1，原SAP0.2／M2schema2／Case／Pi原件均可读；P1不需业务迁移。原因：本功能是可撤回辅助。替代 B：新增“先建图再分析”向导，不推荐。
