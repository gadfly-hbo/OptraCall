# L2：以本体与知识图谱支撑 Agent 语义理解

v0.3 · 2026-11-04 · **后端语义价值与可选依据详情确认稿；待整体确认，没有安装、运行或接线 L2。**

依据：[交接边界](../fourbase-l1-semantic-trace/component-boundary.md)、[主方案 v1.2](../../../docs/fourbase-doublebase-plan.md)、[工程规范 v1.6](../../../docs/engineering-workflow.md)、[统一会话接入](../../../docs/agent-session-integration.md)。本次从用户提供的 L1→L2 交接继续准备，不重做 M1–M8，不把历史开发／设备授权扩大到 L2。

## 1. 完整 L2 的定位、组件与阶段

### 1.1 完整 L2 要提供的能力

**L2 的主要价值在后端：优先借助 Semantica 的本体与知识图谱能力，让 Agent 更好地理解、取得和正确使用业务语义。** 本体表达概念、范围、关系类型和明确规则，知识图谱组织具体对象、事实、关系、来源与版本／时间；Agent沿原工具资格按需取得这些结构化上下文，再自主理解、分析和核算。此为待验证的建设方向，不代表组件已经安装或理解效果已证明。来源追溯、关系／时间索引是支撑手段，前端解释窗口是辅助呈现，都不能代替这项后端价值。

例如，用户问门店销售或促销问题时，Agent应在相关回答中主动说明本次采用的关键口径、适用范围，揭示影响结论的版本差异、实质冲突和重要未知；用户不必先打开“业务含义”内容才能发现这些问题。用户也可直接追问定义或来源。正常仍在原任务提问，不维护图谱、不先填全语义资料、不选择引擎。

这是一项Agent输出与质量目标，不是Host的分析流程：不强制每轮先查L2、固定调用顺序／次数或补全全部资料，不让Host解释冲突、挑选口径或补计算。Agent可根据现有获准材料继续；只有缺失实质影响判断或权限时才有针对性澄清。主回答说明与可选依据详情的职责见§5。

| 完整能力方向 | 用户可观察的结果 | 原权威与边界 |
| --- | --- | --- |
| 业务语义组织 | 查清概念、别名、范围、粒度／单位、指标与制度含义及关联；同名不同scope可区分 | 正式指标仍由SAP发布版定义；L2的概念／本体表达关联准确原版，不独立编辑另一套正式公式 |
| 来源、规则约束与冲突核对 | 定位原文／声明，按明确的规则或结构约束列出满足、冲突及未知，保留相反材料 | 约束校验不等于企业事实、专业正确或因果已证；规则及适用范围有准确来源，Agent／人解释影响 |
| 知识关系与事实演变 | 查有向关系、必要路径、适用范围及事实／前提变化，区分业务有效、系统留存和原稿实际引用 | 更新／失效不追改SAP、旧报告、Case判断或人的选择；未知时间、旧字节缺失仍披露 |
| Agent按需结构化查询与复用 | Agent取得可理解的语义结构、正确适用口径／范围并识别影响判断的冲突，再自主分析；关键解释直接在回答里出现 | Pi继续持有会话、上下文与工具循环；L2不强制查询或接管分析步骤，失败可沿L1与原工具继续 |

这是完整 L2 的能力方向，**不是本次一次性实现／安装全部模块的承诺**。每个后续切片按真实需求、组件实证、具体规格／必要结构和有效授权收敛；尚未进入本轮的能力不会被永久排除。本文目录沿用初稿命名以保留引用，目录名不限制上述定位。

### 1.2 Semantica／Graphiti 与 L2 的关系

**Semantica 是本体／知识图谱语义支撑的优先技术路线，Graphiti保留为具体事实演变缺口后的条件比较。** 两者是候选实现，L2是后端能力层；采用方向不等于全部模块、生产结构或运行效果已获确认。优先复用原生能力，OptraCall补最小业务来源／身份映射、准入、Pi工具接入、保存与必要展示，不自建平行本体平台、事实时间引擎或第二Runtime。UI不成为语义权威，也不把解释业务含义的常规工作交给用户完成。

| 候选／责任方 | 在完整 L2 中拟承担的作用 | 本轮 P1 的实际范围 |
| --- | --- | --- |
| Semantica | 优先评估其较广的概念／本体组织、有向关系、来源、规则约束／冲突核对及时间能力；按需要选择模块 | 只验证固定发行0.7.0的明确来源、显式关系、时间、原生快照／重建及同源对照；不运行全本体、OWL／SHACL治理或抽取路径 |
| Graphiti | 当持续输入事件、实体对齐、增量事实更新／失效和历史检索出现明确缺口时，针对同一问题比较其原生episode／实体／时间关系路径 | 不安装、不接线、不摄取、不运行；比较须先有具体缺口及另定后端、模型、权限、成本范围 |
| OptraCall／Pi | 原业务Store保留权威，Host提供环境／资格与实际记录，Agent自主查询、分析和取舍 | P1只有工程隔离验证，没有产品工具接线或第二Agent；未来沿Pi1.4.0／Interface v3原入口 |

两组件的能力有重叠：Semantica也有双时间／版本能力，Graphiti也支持实体／关系类型和来源。不能机械指定“语义只归Semantica、时间只归Graphiti”，也不默认两套引擎同时维护。拟先看Semantica必要模块能否满足最小问题；若仍有具体缺口再公平比较，结果可以是选一个、收缩范围或确有必要才分工配合。官网定位、静态实现与本产品运行效果分开，依据见[研究及官方来源](research.md)。

### 1.3 本轮只申请 P1，不以 P1 代替完整 L2

本轮固定一个虚构零售域，以语义中的“同名／范围／原口径”作为输入背景，先验证：**当时声明采用什么规则？哪些明确证据支持或反对？后来哪些前提需要重核？** 现有L1已可准确读源和展开一层显式引用；P1检验最小组件路径是否减少错引或重复取材。它只是接入底座的首个工程切片，**不证明Agent语义理解已增强、完整本体／语义治理、自动实体对齐或持续事实更新已完成**。本次定位修订不扩大原P1安装／模块／运行范围。

完整L2后续必须以Agent能否更好理解概念、正确适用口径／范围、识别并解释关键冲突的实证评价后端增益，固定相同内容／模型实际配置／权限／预算后再作对照；真实模型及材料范围仍另核有效授权。图谱节点数、保存成功、页面数量、能打开解释详情、预置Demo回答或P1工程通过均不能充当该增益证明。

推荐先做**隔离合成 POC**，采用已静态核身份的Semantica发行 `0.7.0`，保持原候选hash；原研究中的main声明 `0.8.0`，不能替换该发行身份。具体API缺口见[研究](research.md)。本包整体确认后建议只实施P1；后续正式接线及其他完整L2切片须依据P1实证和真实需求另定具体范围，不因确认完整定位自动获准。

| 阶段 | 可产生的结果 | 当前状态 |
| --- | --- | --- |
| 准备（本次） | 静态官方核验、现状核对、同源样例、spec／决定包、内存 UI、相称复核 | 正在准备；不运行组件／产品 |
| P1（本包申请整体确认的实施范围） | 仅本树 `.local/fourbase-l2-poc/` 内的私有安装、确定性映射、原生 API／重开／更新／失效／重建验证、L1 对照与成本记录 | 未授权／未运行 |
| P2（条件后续接线） | 若P1有收益，另定最小产品工具／UI和必要结构；不等于完整L2全部实现 | 候选方向；不由本包默认启动 |
| 完整L2的其他后续切片 | 按需细化语义组织／规则约束、事实增量更新与实体对齐等尚未验证部分，按证据选择组件 | 没有本轮结构／实施／运行批准，不预设必须启用全部模块 |

P1 不调用真实 Provider，也不以合成 Provider 的预置回答证明推理质量。若以后需要同模型真实回答对照，先固定线路／参数／预算并取得相应授权；本包不预留通用模型开关。若 P1 无收益、有损不可接受或需要新服务／模型才能成立，记录失败，收缩或不用，不为得到 L2 而建设平行图引擎。

## 2. 已有能力与本轮最小差额

[复用核对](reuse-audit.md)按当前 `57742b99d173bfa6413e83705682b0444359add4` 固定源码。继续保留 SAP0.2、Enterprise 修订、M2 input／description／citation、M5／M6、Case／Board SQLite 与 Pi1.4.0 原生 JSONL 的各自权威。

L1 的 `read_semantic_context(find/read/trace)`、`record_analysis_sources` 和原回复旁依据面板已存在；来源保存仍委托 M2 createCitation。本版不重建它们。**P1拟验证差额仅为**：把同一批已有准确引用与明确关系投影到组件，按源及两个时间轴查询、展开必要路径并回到原件。P1不运行自由文本抽取、自动消歧或业务时间推断；实体对齐等后续能力仍在完整L2候选方向中，不能在没有依据时生成或合并事实。

源分三类且保持性质：正式已发布定义；普通制度／事实／观点／人的陈述；明确标识的推断或关系声明。普通材料可以参与查询，不能因入图变成正式口径；支持／反对边、保留和人的选择不证明因果或专业正确。

## 3. P1 的可观察行为

### 3.1 同源而非给 P1 候选额外知识

[固定合成基线](synthetic-baseline.md)同时提供给 L1 与 L2：门店／渠道同名口径、报告明确引用、Case 有向关系、反证、回溯生效通知、未知时间和不完整历史。保留相同源字节与准入、题面、结果上限和读取预算。L2 只能增加派生索引，不能独占新增解释／答案／关系；所有结构化关系也向 L1 开放。UI 预置回答不计对照结果。

L1 按现有读取合同测量；L2 用组件原生 API 测量。工程脚本可驱动固定查询并核对确定性预期，不能模拟自主 Agent 后宣称模型收益，也不能固定产品 Agent 的步骤。完整比较见[验收协议](evaluation-protocol.md)。

原Case不支持直接SAP目标：样例沿J-1→K-10的原citation来源，再由K-10的sapRefs到A，不新增Case引用类型或压缩为直接依赖边。纯时间原语另用合成基线§5双方共用的显式双轴向量，单列工程结果，不为三问的未知业务时间补值，也不计作业务收益。

### 3.2 准确来源、方向与时间

- 一个投影对象指向一个原类型化身份／准确修订，附已有 hash 或明确未知；同名不合并、不改原 ID、不回落 latest。引用只能定位时不能声称旧字节可恢复。
- 关系保留原声明者、方向、目标版本、来源位置及性质；没有原声明时不按日期／词相似度补边。多个支持／反对来源并存，不投票裁决。
- 业务有效时间只来自明确的结构化声明或本合成样例的人工给定；原文和解释分开。系统留存时间必须有原系统证据，不以索引创建时间冒充历史已知，不以 valid-time 补 recorded-time。
- 未知／歧义时间保留原文并列出缺口，不用今天／0／无限区间填成“已知”；不进入声称精确的时间筛选。默认 `recorded_at=valid_from` 的组件转换路径不得直接使用。
- 两个不同截点（如业务 `10-01`、留存 `10-10`）须验证原生筛选组合；不能把 `time_axis='both'` 的单一截点误作完整双轴查询。时区缺失和仅日期粒度不升级为精确时刻。
- 原稿引用、可核留存与今天回看分开；图快照只是投影快照，不是当时全部材料／人的认知或 Agent 实际计算采用的证明。

### 3.3 原生能力、损失与重建

逐项报告 `mapped / partial / unsupported`；这是映射保真度，不是业务可信度。源码中的函数存在不等于已经通过 POC。

拟先复用组件图数据、ProvenanceManager、TemporalGraphQuery 与 TemporalVersionManager 的必要路径。`query_at_time` 的文本参数不是自然语言查询实现；路径函数默认“causal ordering”不证明业务因果、一次返回不证明枚举所有路径；`create_version` 不等于持久快照。必须分别验证正确的 snapshot／SQLite 路径、关闭重开及源重建，不先补一套 OptraCall 双时间存储或通用查询规划器。

每次工程构建固定源集合及 hash、组件／解释器／依赖身份和参数；输出留在 POC 根。源变化只形成新派生 generation／原生 snapshot，旧证据不覆盖。重新从同一源构建后比较规范化的身份、关系、方向、来源、时间、限制；组件随机 ID／排序／生成时间不能掩盖语义差异。重建失败／未知、取消与半成品保留，不能自动宣布新一代可用。图事实失效绝不改写 SAP、报告、M5 判断、人的选择或反馈。

P1 不建设后台同步、自动全库扫描、订阅服务、graph provider registry、全文正文镜像、第二消息库或实体解析平台。原生字段无法无损表达的部分应明确缺口；若最小 metadata 引用仍不足，暂停该能力并提出受影响补充，不用通用 sidecar 补成另一权威。

## 4. 环境、接入与授权边界

P1 的写入所有者是工程验证脚本，只能写本工作树的 `.local/fourbase-l2-poc/` 和明确隔离 QA 目录；输入为本包虚构资料的副本。不能将工程目录作为正式用户 dataRoot，也不改当前正式 Python／DuckDB 环境、Node lock、项目／Case schema 或 Pi JSONL。安装建议只含锁定 core 与所需依赖，不含 `all`、LLM／embedding／外部图后端；必须先记录依赖解析、解释器和包 hash，若不能满足原生最小路径则报告失败，不静默扩依赖／降级／升级。

P1 网络仅用于获确认后的固定包及依赖获取；组件计算阶段测试网络／模型／telemetry 副作用并如实记录，不能凭“本地”声称零外传。组件不得访问凭据或真实业务文件。锁版本可安装、imports 成功、安全取消和资源成本均尚未验证。

P2 若进入产品，继续工程规范 IN01–IN07／Interface v3／Pi1.4.0，沿原 `project-tasks` 普通 unmanaged owner 的真实 projectId/taskId、配置、IPC 和 call-local 资格；不新增会话域／Runtime／全局队列。候选读适配由 Codex 负责 Host／Agent 接缝，不改变 Qoder 本体归属。受管 ordinary、核算、cold、fixed-draft、需求、PPT 专用资源不因索引获得新工具／资料；人的历史查看与 Agent 新供给沿各自原规则。

产品查询将重新核当前源准入，不能因快照里曾有内容而泄漏已排除／无权的正文、摘要或关系路径；跨项目数据权限不因图命中扩大。只读查询不创建／恢复 Pi 会话，不解析凭据。取消、配置变更、迟到、ACK 不明及保存沿原公共生命周期；P1 自身只是组件工程进程，没有产品会话身份。

当前不修改产品源码、测试、正式依赖、持久业务结构、安装器、launcher、服务、MacBook 或 Git 交付状态；不启动真实 Provider／真实业务试验。现有 Mini PID40994 仅只读核对占用，未切换。旧 5239 WIP、所有 FAIL／UNKNOWN／NOT_PROVED 和 DuckDB 限定接受保留。

## 5. UI 与人的操作

[可点 Demo](../../../docs/prototypes/fourbase-l2-temporal-projection-ui-demo.html)是单文件、虚构预置回答、纯内存状态；未接组件、模型、产品或真实源。审阅区说明后端本体／知识图谱语义支撑、组件分工及P1边界；普通任务只呈现回答和原有依据入口。未来能力标未纳入P1／未实现，不能据此证明本体／规则引擎、Agent语义理解、产品性能或分析正确。

继续原任务直接提问并发送，正常新增必做操作 **0**；不新增独立“业务含义”页面、一级导航或必做查看步骤。

| 位置 | 必须承担的内容 | 用户操作 |
| --- | --- | --- |
| Agent回答正文 | 主动说明与本次判断相关的关键口径／范围、重要版本差异、实质冲突、未知及其对结论的影响；有明确来源，不自动选latest或替人取舍 | 用户正常提问／发送即可看到，不需要先点详情 |
| 回答旁“查看依据”详情 | 业务含义／口径说明作为可选内容，附准确原定义、版本、范围和来源；保留原稿／今天回看及来源链 | 用户想深入核对时自愿展开，不打开也可继续任务 |
| 追问／纠正 | 沿原任务草稿，用户正常发送；只在实质缺失时针对性澄清 | 不自动发送、重算、改SAP或人的选择 |

Demo正常回答应直接说明直营门店A的支付减当期登记退款、渠道C同名但范围不同，以及后续B／N-1的退款归属差异／回溯声明和可靠留存时间为何需要重核；不能只在特殊同名情景或详情里出现。可选口径说明仍仅复述A／B／C／D-1。它们都是预置Agent读源示例，不是组件规则校验或真实语义理解结果。原稿／今天回看继续区分声明引用、两个时间和未知，不把切标签当查询或新调用。

部分、无映射、失效、源不可读和组件不可用必须可辨认，且不阻断原 L1／Python／DuckDB 分析；可以继续并说明局限，不能伪造保存成功或静默放宽明确必要的选材／权限。Demo 中的情景／故障按钮仅供审阅，不能成为产品新增必经步骤。详细设计／状态／无障碍记录见[UI 核对](ui-review.md)。
