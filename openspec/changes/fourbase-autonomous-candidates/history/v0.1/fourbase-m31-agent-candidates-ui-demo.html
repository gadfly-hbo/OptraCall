个人资料

探索：Agent在工作中自选记录候选，人按需阅读、重点收藏、纠正或排除。无需每天写笔记，也不要求逐条审批；没有候选时也可正常工作。

候选是Agent声明，重点收藏是你的关注；两者都不证明内容正确。这里只阅读和管理资料，M4按需使用尚未实现。

方案审阅说明 · 当前产品差异与6项决定

本页问题：不增加每日维护或审批负担，能否让有来源的自主候选被发现，同时保留人对原文、纠正与排除的控制？本文件只是开工前交互提案，尚未成为产品。

当前M3已具备人工笔记、明确保留、版本／归档与来源查找。本页保留原入口和类别，新增的是拟定的Agent候选、原生引用收藏、独立纠正注记及排除；没有重做或完整模拟旧M3编辑／保留流程。原M3 Demo及其确认不被本页替换。

6项均推荐A · 全部待用户整体确认

  1. D01 原生正文：候选正文仅来自Pi原生工具结果details，人的控制只记引用。已有持久能力可复用，避免第二份候选正文。待确认
  2. D02 精确身份：小型版本化声明、真实任务身份和精确原生引用；资料来源沿M3读取。防止把Agent自述当用户确认或真实归属。待确认
  3. D03 原任务自主记录：仅核准的普通任务、同一轮Pi；正常发现要求原请求技术完成。保护、取消及不支持的任务边界保持。待确认
  4. D04 只读发现：按需汇总已保存的任务记录及其分支；历史单列、fork副本去重。无需另建持久候选索引，历史不冒充当前。待确认
  5. D05 人的控制：收藏仅关注；纠正追加独立注记；排除只影响本条及其分支副本。既不覆盖Agent原文，也不封禁同来源未来所有新内容。待确认
  6. D06 保存与退出：人的引用事件单文件并发保护、同操作回读；不迁移M3，不双写候选。停用保留历史，原生丢失明确不可读。待确认

发现依据为读取时已保存的task canonical指针对应完整磁盘快照，经SDK恢复出的分支；原生branch()内存导航不一定写盘，未持久导航的实时同步未知。普通任务的适用技术范围为unmanaged；受管ordinary／protected、封闭出稿、text-only、独立冷读和历史只读不注入。页面浏览不创建会话。哈希核字节，不是防篡改认证；重点收藏没有候选备份承诺。

本页未接通：真实身份／权限校验、JSONL读取、工具调用、磁盘落盘／恢复、CAS／幂等／满额、跨进程并发和实际模型质量。没有自动注入新任务、学习评分、语义搜索或经营效果结论。文件内状态不证明以上接线已完成。

演示控制 · 独立于产品流程，手工预置例文

只为了体验状态变化；这些按钮不代表Host给Agent规定流程、时机或条数。Agent可自行决定零条或多条。本页不会调用模型或持久保存任何内容。

模拟一次自主记录

每次点击载入一条预先写好的虚构声明；不是当前模型输出，也不表示每次任务必须产生一条。

读取与分支边界

同一原始occurrence仍是一条。若它已被排除，副本不会绕过排除；当前分支也不会因收藏而被切换。
