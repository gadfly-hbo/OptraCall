# M3.1：Agent 自主候选与低维护个人资料

2026-11-03 · 确认候选 v0.1 · **仅规格／结构／UI准备，尚未获准实施本模块。**

## 目标、依据与当前边界

让有价值的工作内容在正常任务中由 Agent 自主留下，用户无需每天写笔记或逐条批准。沿用已接受的三层：原生工作留痕 → Agent 自选候选 → 新任务按需复用。本模块补第二层及人的可选控制；第三层由 M4 接入。原生会话、报告、反馈已存在，不再开发一套工作日记。

用户已明确先提交本 spec 与可点击 UI Demo，确认后再开发，并再次提醒记忆相关能力优先复用 Pi 官方。原[研究](../personal-assets-phase01/agent-memory-research.md)、[M1盘点](../fourbase-reuse-validation/capability-audit.md)及本次[复用核对](reuse-audit.md)是证据依据。M3 已实现人工笔记／保留／查找；其固定代码、已确认 Demo、原 FAIL／UNKNOWN 及 UI 前置行为 RED 的 NOT_PROVED 均保留。

[整体方案 v1.2](../../../docs/fourbase-doublebase-plan.md)保持原字节；本包是针对其§4.3、§5.2人工保留边界的**待确认增量**：Agent候选可以自主形成和被人发现，人的“保留”转为可选重点收藏；候选、重点收藏、经核验事实仍分开。没有推翻旧 M3 人工记录的确认或把旧实现写成自动记忆。

## 复用后收敛的做法

直接复用锁定的 **Pi SDK 1.4.0**：同一普通任务、同一 turn，Agent 自行调用一个声明式候选工具；工具只返回结构化 `details`，由 SDK 原生工具结果持久化。候选正文不另存 Enterprise、不建候选正文库；也不同时写 custom entry 形成第二权威。`appendEntry`、官方 todo／bookmark 示例是已核对备选原语，本模块选择更窄的工具结果路线。

个人资料页按用户请求从原生记录读取候选，复用原搜索／详情壳。新增的最小持久对象只有**用户对精确候选的收藏、纠正注记、排除和恢复事件**，不承担消息、候选正文、运行或恢复权威。M3 原有人工笔记／保留照常使用 Enterprise 修订和原决定；新候选重点收藏保存的是原生引用，故来源丢失时会明确不可读，不承诺额外备份。

Agent 判断记什么、是否值得记、写几条、何时修正。允许整个任务零候选，不要求完成总结，不设每任务条数／方法配额。Host 只约束格式、归属、权限、资源、取消、版本及回读事实；不从自然语言猜候选，不在 task settled 后另调模型，不后台扫描历史生成摘要，不替 Agent 认定结论可靠。

## 用户行为与验收

| 标识 | 可观察行为与必要反例 |
| --- | --- |
| AC01 自主沉淀 | 正常任务中 Agent 可以自主记录知识／经验候选，无逐条审批。零候选也是正常状态；原会话仍留痕。工具失败将具体格式问题交还同一 Agent，不另开 Host 修正循环。 |
| AC02 官方原生权威 | 唯一正文来自实际 SDK 成功工具结果的 `details`。工具回调返回、HTTP202、事件到达或自然语言说“已保存”均不替代磁盘精确回读；读取个人页不启动会话／模型，不改原 JSONL。 |
| AC03 真实来源 | 候选显示 Agent 生成／未人工确认、实际项目／任务／生成记录、业务范围及局限。额外资料／成果／回复／反馈引用复用 M3 精确来源合同；其中native-reply也必须换用无写入读适配，不能直接沿旧`SessionManager.open`读取。缺失、变更、越权、不可核对各自呈现，不回落最新稿。原生生成记录证明产生过该声明，不证明业务真实。 |
| AC04 低维护发现 | 同一“个人资料”入口可浏览 Agent 候选、重点收藏和原人工资料；关键词默认标题／别名／范围，正文搜索显式选择。列表不设计成待审批队列，不催写日记，不因未收藏隐藏所有候选。 |
| AC05 人的控制 | 重点收藏仅表达关注；纠正添加独立人工注记并保留原文／注记历史；排除本条候选后从默认发现移出，其分支副本也不复活。只有人可恢复。新工具调用产生的另一条候选不作语义相同判断，可能来自同一资料；界面说明排除范围。 |
| AC06 原生分支／终态 | 默认候选来自读取时已保存的各真实任务canonical指针所对应native完整快照、由SDK恢复出的分支，且其原请求为精确 `settled:completed`；不承诺实时反映尚未持久化的导航。取消／技术失败／未收尾内容仅历史可读并标终态／UNKNOWN；技术 completed 中的失败教训仍可成为候选。跨 fork 复制按原始 occurrence 去重，原始归属无法核实则 UNKNOWN；不按正文哈希合并独立观点。 |
| AC07 保全与恢复 | 列表、详情及搜索均为只读；版本不明、损坏或超限明确给出部分／未知，不显示假空。人的写入单文件原子发布、revision并发保护和 operationId 幂等；ACK丢失只查询原操作，不重复模型或生成新候选。取消后迟到不晋升正常候选。 |
| AC08 权限与停用 | 本期仅核准的普通 unmanaged 项目任务获得声明式工具。受管 ordinary／protected、封闭出稿、text-only、独立冷读及只读历史不注入，也不因进入个人页开放。停用不删旧候选／人的控制，旧 M3／项目／资料字节不迁移。 |
| AC09 模块边界 | 本模块不把候选自动送给新任务，不注入系统提示词／冷读，不宣称已实际引用或效果提升。M4另核按需检索、重新判断适用／冲突／拒用与实际提供回执；M6成熟／增量评估、M7组件增强不提前实施。 |

## 运行时接入责任

适用[工程规范 v1.4 §2、IN01–IN07及§3–4](../../../docs/engineering-workflow.md)与[统一接入说明](../../../docs/agent-session-integration.md)，当前 Interface **v3，业务调用子集不扩版**。Codex 负责本增量 Host／Agent 接线，复用 `project-tasks` 域的真实 `{projectId,taskId}`、同一配置快照、lease、请求、取消和续接；没有 memory owner、第二会话域、SDK循环、全局队列或新RPC。

Host 在原 profile 初始化中传入真实 taskId 等只读 provenance；候选工具从现有当前 run 和 SessionManager 同步取得 requestId/sessionId，toolCallId 来自 SDK execute 参数，不接受模型自行填写 owner／request／“已确认”。候选只在有效原 prompt 工具调用中产生；native command、冷读和历史查看无该写入口。相同的既有 SimLab customTools 注入接缝可复用，但不把其 driver 内实例化误称为已有 Host-only RPC。

工具读取／传递最小声明式数据，不拿治理账写权、Host域管理对象、任意sessionFile或跨owner能力。新候选和其引用的native-reply共用最小只读快照适配；旧M3来源读口尚用`open`，不能称其已经满足本轮保全要求，实施须覆盖受影响旧消费者和旧格式不改写。既有未托管环境仍不是敏感隔离或防篡改认证；内容哈希只核精确字节与变化，不能证明原生文件从未被外部进程编辑。若实施发现需扩大 profile、保护根、公共 Interface 或新持久字段，先补受影响决定，不以本包概括授权。

## 实施切片与验证计划（确认后）

1. 先固定候选 envelope／只读解析与身份合同的行为 RED，再接同一 Pi customTools，验证零候选、有效候选、非法字段、重复引用、无效归属、取消与迟到；不以导入失败代替行为 RED。
2. 先为实际个人页公开行为留下 RED：默认候选／未确认、重点收藏、原文与人工纠正并列、排除／恢复、缺源与部分失败。测试驱动最小 UI 和纯读投影，不能等 UI 完成才回填测试声称前置。
3. 增量完成人的治理原子写入、CAS、幂等／冲突／满额／坏文件和重开；核对当前分支、历史、fork复制、不明终态与精确 hash，旧 M3 文件和原件保全。
4. 固定完整候选，执行届时适用 `npm run check`、受影响公共消费者与隔离合成 SDK／真实浏览器链路、全新上下文非作者复核及 Host／Agent 职责复用专项。真实 Provider 质量／新模型实验不在本准备授权内，届时明确已获准范围或标 NOT_RUN。

允许的本轮改动仅本目录规格／设计／记录、上级实施索引，以及新增独立 Demo；验证证据写 `.local/fourbase-modules/m31/` 和本模块截图目录。确认后产品允许范围将限于原 `project-runtime/project-session` 只读 provenance及静态工具、候选精确历史读适配、最小用户治理／路由、原个人资料 UI／客户端／样式及相应测试；不迁移 M3 schema1、不改原已确认 Demo／主方案、不安装依赖或打开新 profile。

本包确认不授予 Git／CI交付、安装、服务切换、MacBook操作或业务数据／凭据访问。当前进度和检查见[result](result.md)；开发开工以用户对本包及 UI 的整体确认记录为准。
