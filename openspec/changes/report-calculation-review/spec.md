# 主 Agent 自动委派报告计算复核

版本 v0.1 · 2026-11-11 · 产品规格待确认

用户已确认迭代方向。本稿供前置审核，产品开发、模型验证及既有计算准确性项目补测均未启动。本迭代沿现有报告、首答和任务记录入口交付，无新增页面、开关或必须点击的步骤，UI Demo 不适用。

## 1. 适用范围与发起时点

**RCR01｜一次报告计算复核。** 首版适用于普通项目任务生成含关键计算的正式报告。关键计算由原主 Agent 根据用户要求及其对结论的影响判断。短答、纯描述报告、临时过程文件及专属业务会话沿现有交付方式。在父请求准入时按同一任务 owner 和请求固定适用路径。旧自动核算未迁移且本请求已获准走旧链时，沿原授权执行旧流程。旧链最终是否发现报告变化，都不在同一请求追加本迭代的委派。旧开关的切换归迭代二规格。

**RCR02｜初稿后、最终答复前。** 原主 Agent 已形成可定位的报告初稿后，在同一父请求内自动调用一次前台计算复核子 Agent。主 Agent 明示一份主报告及其关联材料，由 Host 验证归属并固定版本。同一请求产出多份报告时，意见和复核状态只对应主 Agent 指定的那一份。Host 按该明确选择绑定，不从目录、写文件事件、文件名或报告关键词猜测目标，也不在父会话终结后补派发。子调用实际在途时，主 Agent 等待意见再完成最终答复。文件区已保存的初稿仍按原文件呈现，复核状态以实际回执为准。缺少委派回执时按 RCR09 处理。用户无需点选材料、开启旧自动核算或另发一条消息。

**RCR03｜一次委派，原作者完成交付。** 子 Agent 的意见作为原生工具回执返回正在运行的原主 Agent。主 Agent 自主核对并给出最终答复。每个父请求至多发起一次本功能的委派，主 Agent 的自查与工具调用次数由它自己决定。修订稿不会自动再发给子 Agent，第二项结论与建议审查仍有独立入口。

## 2. 材料、权限和版本

| 编号 | 契约 |
| --- | --- |
| RCR04 | Host 核对当前项目、任务、父请求与资料授权，固定初稿以及实际交给子 Agent 的材料版本。允许读取该版初稿、本任务获准的相关 `020_clean` 源数据、可用业务口径和与本稿关联的过程产物。本次实际送入的已确认分析框架或 RAP 也可作为只读材料，沿原交付回执固定版本与实际提供范围。已授权的共享材料按本任务的实际访问范围及确切引用核对。记录报告定位、版本或字节摘要、实际提供的资料与缺失范围。材料有截断、读取失败或版本冲突时如实反馈。 |
| RCR05 | 子 Agent 使用独立内存上下文，接收最小任务说明和固定材料。其它项目、父会话完整历史、`010_draw`、凭据及未授权文件不在其访问范围。子 Agent 对初稿、源材料、历史和正式报告只读，意见只通过父工具回执交回。运行中授权撤销或 owner 归属改变时，沿父请求既有权限与取消规则停止相关读取，拦截失去资格的意见回交，已记录内容按当前权限回看。只有当既有受保护能力实际证明可限定读取、仅写私有临时空间且无外部副作用时，才可给子角色使用相应计算工具。 |
| RCR06 | 普通 `bash`、通用文件读取和可间接执行的工具，仅靠角色说明、工具名列表或独立上下文无法限定文件访问。默认复用固定材料或受约束的只读来源查读能力。受保护执行接缝须在对应父 profile 及授权范围下验证后方可启用。边界无法证实或材料不可取得时，保留实际可读范围，返回证据不足或复核未完成。 |

## 3. 意见与原主 Agent 自主处置

**RCR07｜可核对意见。** 子 Agent 自主决定检查哪些关键数字以及用什么办法。它可依据原始记录、口径、恒等关系、已核计算证据或换一种方法核对公式、输入、结果及正文的数字、单位和方向。每项有影响的意见应可定位到稿件，说明现稿主张、依据或可复现差异以及可能影响。能证实的错误、口径分歧、证据不足和范围内未发现问题分别说明。审查意见只对应被审初稿及实际检查范围。

**框架覆盖。** 在同一次复核中，有本次实际送入且可核对的[分析框架或 RAP](../requirements-analysis-framework/spec.md#3-框架内容确认与-ui) 时，对照初稿检查约定的关键业务问题、范围与交付是否有回应。意见区分已回应、明确缩小范围或待补证、以及未说明的遗漏，并定位对应的框架要求与报告段落或缺口。框架缺失或版本无法核对时，说明覆盖未核实，计算复核按实际材料继续。该检查关注报告是否回应约定问题，证据能否推出结论与行动建议由独立结论审查处理。后续采用的具体计算方法仍由主 Agent 决定。

**RCR08｜主 Agent 决定。** 同一父请求内由原主 Agent 按授权资料复查意见。确认有误时，自主修正受影响的计算、表格、正文和首答。判断原值正确时，保留原判断并可简述依据。仍无法确认时，说明适用条件、缺口或分歧。通过已有保存入口另存修订，固定初稿与原始资料可回看。未证实修订保存时只引用实际存在的版本，并说明未完成事项。记录实际发生的处置及对应版本，不把子 Agent 的意见改写为最终事实，也不把初稿的复核结果标为修订稿已复核。报告采用和业务动作仍由用户决定。

主 Agent 确认可复现的计算错误或框架漏项时，可沿「先定位原差异、修订后用同一依据复查」闭合意见。可补足的遗漏由主 Agent 自主补充，证据不足时说明受影响的问题和缺口。复查沿主 Agent 自查与原交付记录。

**RCR09｜失败和取消。** 启动或回执失败、缺少授权材料、不可证实版本、没有实际委派或子资源状态未知，分别按事实记录，不能显示为已复核。可确认技术收尾的复核失败不阻塞普通交付，主 Agent 可交付已完成的部分并说明限制。父请求被用户取消时，沿现有停止路径取消子资源及后续交付，保留已保存内容。迟到结果不进入已结束、换配置、换版本或其他任务的会话。无法证实资源已收尾时按既有生命周期保留 `UNKNOWN`，不重放请求。

## 4. 与结论及建议审查的分工

本迭代核对数字是否由指定输入、口径和计算关系得到、稿件是否一致地引用结果，以及本次框架约定的问题是否得到回应。独立结论审查判断数字及其它材料能否支持具体结论或行动建议。比如「净流出减少」可由数值变化验证，「亏损减少」还需要损益证据。独立审查发现的数字疑点可交原主 Agent，普通交付和两类审查互不构成放行条件。 [迭代二规格](../conclusion-recommendation-review/spec.md)

## 6. 后续验收边界

- 适用的正式初稿在同一父请求中出现一次实际委派，回执绑定该版初稿，意见返回原主 Agent。临时文件、无关键计算的报告及不适用会话不触发本功能。
- 具有明确差异的意见可被主 Agent 核对并修订，误报可被驳回，证据不足可保留。三种处置均可按现有入口交付，修订稿和首答的相关陈述一致，原稿及历史可回看。
- 框架约定按渠道和品类拆解，初稿只完成渠道且无说明时，能定位到遗漏的品类拆解。初稿已明确品类数据缺失及影响时，按待补证记录。后续已发布的新框架不参与本轮复核。原框架未实际送入或不可读时，覆盖保持未核实，既有计算复核和普通交付路径仍可用。
- 篡改版本、越权路径、读取会话或凭据、改写初稿、间接调用执行工具及运行中撤权等反例应被权限边界拦截。新旧路径在准入时互斥，旧链未观察到报告变化时也不追加派发。取消、配置变化、迟到结果、恢复和重复派发按 Interface v3 核验。
- 技术验收与专业效果分开。后者须另经授权，分别记录检出、漏报、误报、主 Agent 实际修订与最终报告新增错误。当前均待验证。
