## 2. A05-01：可信来源与最小权限

### 信任与权限分别成立

“可信来源”指本人／部门或企业正式管理的数据源，其管理员、正式发布的视图／策略／扩展承担服务端实现责任。OptraCall不保证在源端管理员任意替换函数、索引或协议实现时仍构成无副作用沙箱。该边界在连接／项目已有授权说明中呈现，不新增每查询确认或强制信任向导；它也不代替实际权限检查。[S1–S3]

- Host保管凭据、TLS与配置修订，验证真实连接、数据库／登录身份、可用读取及单次保护能力。Agent只拿获准引用，不拿密码、任意DSN、控制连接或服务器会话身份。
- 权限核对包含当前有效身份、继承角色、PUBLIC及实际可达资格，不仅查看登录名或显式GRANT。依赖RLS声称隔离时，须验证实际身份确受策略约束；`row_security=on`不能消除owner／superuser／BYPASSRLS的绕过资格。
- 本地导入／建库与分析身份分开；企业使用现成分析账号。对分析数据不授予写／DDL／所有权、超级用户、BYPASSRLS或管理／信号权限；发现身份明显超出约定权限域时给出具体不合格原因，不用只读事务掩盖。不自动创建角色、修改GRANT、替用户SET ROLE或借高权限账号降权。
- 项目授权、任务收窄和模型出口仍由Host绑定；配置共享不等于数据共享。相同原生权限域可复用命名连接，不同域沿已有受限账号／正式视图／平台原生身份安排，不复制管理员凭据。远端权限是基础，目录隐藏、前端过滤或Host拼WHERE不能冒充数据库隔离。
- Host核查Agent显式引用的对象及工具资格；不能准确解析／核对授权的语法拒绝该请求，反馈Agent修正，不试执行后猜权限。通过函数或其他通道间接访问数据的边界须沿受信源端权限与已支持能力说明，不宣称AST掌握所有间接对象。
- 连通、读取可用、结果接收、取消能力分别记录。不能因目录注释／关系说明不可见而把整个来源判坏；也不能将“测试成功”冒充全部语法、所有对象或源端副作用已验证。

来源标识以Host保存的准确连接修订、验证的TLS端点／数据库／登录身份及实际可得原生标识组成；未知标识明确未知。`pg_control_system`、集群system_identifier、服务器文件权限不是普通读取的必要新增授权；不再将其缺失一概列为源不合格。相同端点不证明相同物理节点；这个限制直接约束第7节的远端观察及控制，不能靠连接字符串消除。

并发新增标准索引是正常源端运维，不要求用户暂停DDL或给分析账号MAINTAIN。原自定义opclass反例证明“预检后全部内部路径不会变化”不成立，原FAIL保留为本稿排除的更强保证；不将其写成已修复。源身份／权限／结构变化导致的实际拒绝或列变化，沿本次观察报错／形成新版本，不能沿用陈旧缓存或悄悄改旧结果。[S4–S5]

## 3. A05-02：企业正式视图与RLS

首批PostgreSQL验收应覆盖普通表、企业正式只读视图和RLS表。它们是源端提供的读取对象／权限机制，不要求Agent先改建为heap副本、导出全部数据或获得底表权限。[S6–S7]

| 情况 | 接入与准确说明 |
| --- | --- |
| 仅有正式视图SELECT，无底表SELECT／定义查看权限 | 按原登录身份读取已授权视图；不直查底表、不递归索取定义。保留“视图返回范围／底层口径未独立核查”等必要限制，不因定义不可见封闭已能合法读取的视图 |
| 默认owner权限语义的正式视图 | 接受来源管理方正式提供的视图安全模型；不能把所有此类视图一律当越权。视图owner的原生权限不等于OptraCall给登录账号提权，Host不得私建提权包装 |
| security_invoker视图 | 由PostgreSQL按调用者检查相关底表权限与RLS。已有账号权限不足即返回原错误，不切owner、备用账号或改写为绕过查询 |
| RLS表／视图涉及RLS | 在原登录／有效身份下让数据库执行策略；不设row_security=off、不切owner／BYPASSRLS，不尝试计数隐藏行。政策正文、隐藏行数可能不可见，按“当前账号／策略可见范围”标注覆盖 |
| 企业平台依赖会话用户／租户上下文 | 只消费现有正式、可验证的原生身份绑定；Agent不能通过参数伪造身份或自行SET会话租户。需新增身份注入／角色切换的端点本期明确不支持，不因此向企业索要扩大权限 |

每个操作使用独占物理连接；首期不池化复用，不让角色／租户会话状态跨任务残留。视图的owner／invoker、RLS及策略版本只记录可得事实，无法取得完整定义不假造哈希／版本。空结果只说明当前账号下该SQL本次返回零行，不证明全库无数据。

“完整”须分两层：**本次SQL对当前身份的返回结果是否完整接收**，以及**这些结果对分析问题覆盖了哪些业务范围**。RLS内结果完整不等于全企业数据完整，视图完整不证明口径正确；业务覆盖限制沿数据说明、报告及核算传递。

普通视图／RLS列入必须验证的目标，并不承诺所有云端点、分区、外表、自定义类型／扩展及其组合都已支持。缺少驱动／原生公开契约的具体能力局部标为未支持；不因为隐藏元数据而请求增加管理权限。

## 4. A05-03：Agent自主读取与SQL技术边界

继续使用获批官方`pg@8.23.1`、`pg-cursor@2.22.1`、`node-sql-parser@5.4.0`和原Pi`1.4.0`。MySQL／`mysql2@3.24.6`选型及原证据保留，本轮不加MySQL实验或用其缺口阻塞PG独立判断。不引入auto-ontology、JDBC／Java桥、COPY新依赖、私有fork、SDK补丁／运行时改写、容器或代理。Semantica继续承担原语义辅助职责，不做连接权限、查询执行或第二个Runtime。

Host提供原少量正交工具：列出可用来源、按需目录、参数化只读查询、读取准确结果引用及保存说明。Agent自选对象、字段、筛选、关联、聚合、排序、分批、分析方法和纠错。普通SELECT应能承载常见数值／时间／文本读取与聚合；不再要求Host证明每个表达式的最终字节和所有内部函数路径。

| 技术入口 | v0.5合同 |
| --- | --- |
| 可执行语句 | 单条参数化SELECT；列投影、过滤、JOIN、聚合／GROUP BY、排序／LIMIT及parser实际支持且可核授权的只读CTE／子查询。具体语法支持由公开parser和驱动验收，不建设通用SQL编译器／业务模板库 |
| 必须拒绝 | 多语句、数据修改CTE、SELECT INTO、锁定读取、DDL／DML／COPY／DO／CALL、事务／会话控制、PREPARE／EXECUTE、显式提权／外部执行／改变预算或身份的函数和已知有副作用入口；包括在SELECT内部嵌套set_config等绕过 |
| 表达式／函数 | 常用内建只读表达式按已有技术入口支持。不能识别用途／授权边界的直接函数调用局部拒绝，交Agent自主改法；不递归重建受信正式视图／RLS内部代码证明系统 |
| 原SQL与参数 | 核验后原样执行，准确保存原SQL与保真参数；Host不补业务WHERE、不偷偷增加LIMIT、裁剪列或改金额规则。Agent可依据工具错误自主提交新的SQL |
| 不支持／错误 | 给出有界、脱敏且可操作的技术原因、是否已派发、原结果状态及收尾状态。不用提示词或“Agent自觉少取”替代入口执行控制 |

元数据不完备沿DB19：Agent在已有授权内自主发现、核查并继续有据部分；不要求用户先补齐注释、外键、关系图／说明／Studio。目录事实、数据核查、关系推断与语义候选分开，缺口与结论限制明确。未知不填零、不伪造政策／约束，不强制先采样全部表；采样同样受结果和模型出口约束。

Pi原工具调用循环承担自主纠错，不新增Host推理循环、计数器、预算台账或“相同错误N次熔断”。**不设SQL固定纠错次数；跨次纠错累计时间、调用量、token、费用及返回量暂不设上限。** 可得消耗沿原请求／工具事实记录，未知费用不记为零；不改全产品Pi配置或关闭供应商原生机制。Agent可自主换方法、结束或说明限制，不被强迫无限尝试。

## 5. A05-04：单次查询保护

累计无上限只适用于跨次纠错；每次数据库operation从准入起仍有自己的有限预算。操作包括准备／连接／目录或权限核查、业务SQL／全部cursor read、保存交付；同一操作不能因新批次／新段／内部重连刷新deadline。新SQL仅在旧操作真实收尾、原请求有效且资格未撤回后，作为新观察建立新预算。

| 保护层 | 必须落实／可承诺的范围 |
| --- | --- |
| Host单调时钟deadline | 有限连接／操作／收尾期限；检查全部阶段，取消后撤后续派发；本地超时不冒充服务器已停止 |
| 数据库／平台原生执行控制 | 优先statement_timeout、lock_timeout、idle事务期限；有transaction_timeout则按实际版本采用并在事务前设置；平台已有等价控制可沿用但要证明实际生效维度。无法建立任何有效服务端执行期限的连接暂不开放查询 |
| 结果接收与消费 | 有限每批行数、累计行／字节、列数、SQL／参数输入、待消费队列和owner／来源并发；cursor每次至多一个read，消费／保存后再取下一批。达到额度停止继续取数并如实标记范围 |
| 预览／送模型 | 独立的小预览及工具输出预算；权威结果文件不自动全量进入模型、UI或冷读上下文。预览遗漏不等于权威数据丢失；准确报告实际已提供范围 |
| 来源平台限额 | 继承既有扫描／费用、排队、执行或下载限制，不擅自提高／关闭。扫描上限不等于返回上限，分页不等于总下载限制；未知维度保持未知 |

预算由Host依据已验证连接能力提供合理默认并记录在测试／操作事实里，复用原连接资源策略，不新增用户必填的技术配额问卷。具体生产数值在后续获授权代表负载验证中固定；不把测试短值、平台名称或0／Infinity当生产默认。Agent可在该次上限内选更小批次／范围，不能绕过或提高权限、期限、输出上限。

最初真实验证仍用已获准的隔离合成PG18.1组合，**不是本轮启动实验，也不是所有PG必须升到18**。其他PG版本／云兼容端点以实际可用的公开能力和代表账号验收，未验证标未验证。不得为了通过连接测试请求pg_control_system、pg_signal_backend、MAINTAIN等额外权限或替换官方驱动。

## 6. A05-05：大字段按需、结果保真与诚实限制

一期正常路径覆盖常见订单、会员、库存等结构化读取。长文本、JSON／JSONB、bytea不默认整列装入模型；Agent按任务需求选择原列、长度、明确前缀／片段或聚合。Host给出实际类型、工具限制及来源覆盖，不把它变成必须遵循的分析步骤。

- 原值、展示前缀、SQL派生值、完整分段值分别标识。前缀／片段保存其实际SQL、范围／表示及已知总长，不以原字段名暗示正文完整；不能静默截断后标complete。
- 结果保存继续使用原manifest＋普通JSON文件集／有序块引用，保留列序、真实类型、精确数值／时间文本、NULL及二进制区别。BIGINT／NUMERIC不经JS Number，JSON正文不盲目JSON.parse；格式保真沿已批驱动合同，不新增Host计算器。
- `pg-cursor.read(n)`约束行数，字段到回调前已加载解析；回调后字节检查、UI隐藏、LIMIT 1均不保证解码前内存硬上界。[S8] v0.5不再承诺当前pg组合能对任意巨值、错误／通知／启动消息提供该硬上界或精确进程RSS保证。
- 单次行／字节／单值检查必须在公开能力最早可得点实施，真实说明检查发生在接收、解析或消费哪个阶段；不把后验检查宣传为前验保护。已知巨大或无法在当前支持路径处理的整值读取返回具体“不支持／超限”，不连带把同源正常列一概拒派。未知巨大字段仍可能在回调前产生较大分配，这是受信分析连接的明确保留限制，少见或小库不是证明。
- 源端生成有界输出是按需减量方法；Host不自动改写Agent业务SQL。完整分段仅在后续真正有需求、明确稳定键／顺序／总长／一致性并验证全消费链时开放。现有分段WIP保留但不作为一期通用必需，也不默认将COPY全表拉本地替代SQL过滤／聚合。
- 元数据正文同样可按源端有界前缀／分页读取并标记缺失／截断；不要求完整加载巨型注释。错误及通知仅保留有界脱敏展示；该展示限制不等于当前SDK此前未缓冲巨型原消息。

读取超额、落盘失败、停止／撤权或格式无法保真，保留已知实际接收／保存范围及partial／failed／cancelled，不发布完整输入。权威文件完整、预览完整、本次SQL返回完整和业务取数充分分别表示。稀有巨值／异常消息的解码前保证不满足，记录为本版保证范围外，原反例继续FAIL／NOT_PROVED，不能因文字修订计为测试通过。

不为本版自行开发协议解析器、给SDK打补丁或换成JDBC／容器／代理。行业pgJDBC的maxResultBuffer仅为成熟能力对照，不是当前Node公开配置或新增依赖授权。[S9] 若实际任务频繁受巨值影响或确需更强保证，先提出具体成熟组件与受影响合同，再按用户决定推进；不私自追加默认基础设施。

## 7. A05-06：停止、终态与UNKNOWN

### 正常完成证明什么

一次操作独占原物理连接、不pipeline。成功要等待原命令／cursor真实终态、结果消费／固定完成、适用事务COMMIT或ROLLBACK完成和本地连接关闭。只依赖固定官方版本公开API的真实完成契约并作反例验证；资源状态不靠Promise名称推定。未真正排空／关闭的cursor不得提前释放或归还连接。[S8、S10]

这些事实足以在受信来源下说明**本次SQL不再执行、该事务已结束、本地资源已关闭**；不需要每次取得集群控制信息或观察backend从全局目录消失。关闭本地socket本身不证明远端会话已退出，成功结束本次只读SQL也不是审计服务器全部资源／函数副作用的证明。会话级锁等源端额外状态不纳入“事务回滚必然撤销”的承诺；不池化复用可避免把原会话状态交给下一个任务。

若已实际观察到会话级锁、后台任务等超出事务寿命的资源，不得以正常ROLLBACK或可信来源声明把它们核销；仍须按其真实结束事实收尾，证据不足保留对应UNKNOWN。原索引探针的会话锁反例不被本版正常终态合同覆盖为已释放。

### 停止流程与迟到

用户停止整个父请求或原owner关闭时，沿原Pi与公共生命周期撤销后续模型调用、全部业务工具及新保存派发；只有原操作技术收尾、合格只读核销及迟到事实记回原记录可继续，不触发新的分析工作。

单个来源撤权、任务排除、配置失效或连接异常，先撤销受影响的SQL／read／新保存。只有原父请求未停止、owner及独立工作的授权仍有效、该工作不依赖受影响来源时，才可继续其它已授权分析；一旦父请求也被停止，以上整个请求的停止规则优先。

对**同一个已派发且尚需收尾的操作**，继续处理：

1. 在官方公开能力、原账号权限及精确目标身份能验证时，才请求原生取消。`pg@8.23.1`的内部cancel／原始CancelRequest不纳入本期；不自写协议，不根据缓存PID发信号，不因同一DSN推断同节点。不为强取消增加控制权限。
2. 当前默认可靠退路是已建立的服务端语句／事务或平台期限；cursor.close只是portal关闭，不能当在途SQL即时取消。原read未结算时不排队关闭／ROLLBACK来假装已经结束，等待期间保持占用。
3. 收到原查询明确完成／取消错误后，再完成cursor／事务／本地连接收尾；取消控制命令（如有）也须独立结算。停止后晚到成功／错误只补原操作技术事实，不进入报告、Studio、说明或核算，不自动恢复Agent派发。
4. 收尾宽限耗尽或任何证据不足，进入UNKNOWN；不把本地超时、取消API返回true、end／close事件或“后台应该已超时”写成已远端结束。不承诺瞬时停止；界面显示实际“停止中／等待源端终止／UNKNOWN”。

### UNKNOWN占用与恢复

| 状态 | 可做 | 禁止／释放条件 |
| --- | --- | --- |
| 未派发的技术拒绝 | 返回`dispatched=false`；原请求未停、资格仍在时Agent可自主提交修正 | 不制造远端UNKNOWN；不因此清零父请求历史或设固定纠错次数 |
| 命令已明确结束，事务／本地关闭仍待证 | 沿原资源清理，保留已知各项事实 | 尚不能把操作判idle或新派同owner／资源工作 |
| 网络断开／原查询终态不可得 | 保持UNKNOWN、隔离原操作及受影响的连接权限域；沿原owner资源记录展示原因 | 不重放原SQL／模型，不重连重查原业务来“核销”，不把换任务／重启／新建同配置连接当清空占用 |
| 原生观察在现有权限内可用 | 显式重试原清理／只读核销；须证明同实例、原PID＋backend_start精确身份及控制连接自身结算 | 不追加权限；不对保存PID重复取消；负载均衡或身份不可证明时仍UNKNOWN |
| 无充分观察能力 | 只有单源异常／失效且父请求、owner和独立工作授权仍有效时，可继续不依赖受影响来源的文件／其它来源分析；父请求已停则只等原技术收尾，给出具体未证边界 | 不借UNKNOWN续发已停止父请求的模型／业务工具；不要求管理员操作作为日常必经；事件性人工处置或平台回执如被采用，须有可验证证据／独立决定，不能按用户一句“已处理”自动证明远端结束 |

原连接后来取得真实终态并完成收尾，或合格同实例观察证明原会话确已消失，才可释放对应UNKNOWN。释放只更新原资源状态，不重开已停止父请求、不补派查询或续写旧报告。能力不可得就保持未知；不把有限等待当自动清空策略。影响范围从原真实owner、来源配置／权限域和已有公共占用推导，不新建全局黑名单、后台查询watcher或第二套生命周期；无法安全缩小范围时保守阻止该域续派，其他无关来源不一概封闭。持久恢复沿已有原资源／会话恢复规则，证据丢失保持UNKNOWN，不以新进程无内存记录当已清理。

本版不要求“所有来源都支持强取消”才可普通查询；但**正常命令／事务／本地资源终态和基本服务端期限必须先验收**，且断线UNKNOWN不能旁路。要求严格远端会话消失／受管独立核算时，按第8节局部能力准入；不能将普通读取可用自动提升为完整受管能力。

## 8. A05-07：结果、说明、Studio与核算连续衔接

保留原DB06–13、19及[语义补充](semantic-discovery.md)分工：

- 每份结果记录原project/task／operation、连接修订、当前登录／有效身份、准确SQL／参数、对象／可得类型、查询与保存时间、原生版本／会话条件、实际行／字节／文件摘要及状态。目录／RLS／视图版本不可得写未知，不能编造全库快照或权限充分性证明。
- 每条SQL是一次观察，不默认多个独立查询同快照。仅在实际有需要且获验证的短事务内采用RR等一致性；不持有事务跨模型思考／纠错回合。同源新查是新版本，变化不覆盖旧材料。
- 数据说明保存当前账号可见范围、字段／粒度／单位／时间、依据和未知；目录发现／关系推断／语义候选归Agent，Semantica仅复用原派生图辅助。缺说明可继续分析，不把补图或人工确认全部字段作为前置。
- Studio继续候选、正式发布、项目采用、图刷新分别记录；发布定义不授予数据库读取权限、不更新旧报告依据。源端视图定义或RLS变化产生新观察／受影响映射待核，不伪装旧记录已验证最新规则。
- 核算仍沿现行报告计算复核／结论审查及原已批准的数据库独立链设计，不复活legacy、不在同请求叠加两种计算核验。文件集按准确引用整体固定并有界读取，不只交manifest；保留精度和partial状态。
- 对聚合SQL、视图、RLS下结果可做已提供材料内的计算核算；不能据此宣称核了隐藏数据、底层原始取数或所有业务条件。数据库独立冷读仍先事前语义／足够原始依据、后作者SQL／报告；后取新观察不能假称同快照原始对照。
- **受管独立／自动链保留更严格资格**：从首次执行前具备原Interface v3的可信起点、权限受控及要求的真实资源收尾。普通只读能力不足、UNKNOWN、旧任务、sealed／protected／cold等原排除情况不得绕过。无法提供所需活库资格时，仅使用已固定文件的既有核算路径，不封死整个普通分析来源，也不标自动链已完成。

| Host管环境 | 原生身份／权限、模型出口、单次资源、状态、保真文件和实际覆盖；共用Interface v3 owner资源 | 不推导业务口径、不代算、不靠目录裁剪／提示词伪隔离，不把身份不足改成隐式扩权 |

| 优先复用成熟能力 | 获批官方pg／cursor／parser、原Pi、原生权限／期限、现有说明／Studio／核算；Semantica维持原分工 | 不改SDK、不换驱动、不造协议／Runtime／预算台账，不为了极端字段引入新基础设施 |
| 减少人的操作 | 命名连接配置、项目／模型出口一次授权，任务继承；默认策略，异常准确反馈交Agent | 不逐条SQL确认、不要求暂停DDL／手工分页／维护配额表；可选管理不变成必经 |

与v0.4最重要的确认差额是：**受信数据源治理替代“客户端穷尽全部执行路径”；常规查询资源保护替代“任意巨大消息的解码前硬保证”；视图／RLS纳入代表目标；正常终态与断线UNKNOWN分别处理。** 这些是本次请求指定的规格调整，仍须用户确认具体稿；它们不是已完成的修复或已取得的能力。

本版保留单次保护、停止／撤权／UNKNOWN、准确来源／精度／覆盖、原owner和累计无上限原则，不设新的全局风险评分、能力注册平台或人工审批链。最终摘要／检查／独立复核及实际未跑项见[本轮manifest](spec-v0.5-manifest.json)、[任务清单](tasks.md)和[结果](result.md)。
