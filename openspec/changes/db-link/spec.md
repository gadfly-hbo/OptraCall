## 3. 用户可观察目标与领域划分

用户在同一 OptraCall 环境配置一次连接，为项目授权一次，然后直接提业务问题。Agent 按问题自主发现、查询、计算与纠错；被采用的结果成为带准确来源的项目材料；业务含义可沿数据说明与 Studio 积累；获准核算自动接续而无需导出再上传。

| 对象 | 权威与含义 | 复用规则 |
| --- | --- | --- |
| 命名连接 | Host 管理的连接配置、凭据引用、源身份、可用性与配置修订 | 项目引用连接资格；不复制密码或查询历史 |
| 项目来源授权 | 真实项目对某连接、数据范围及模型出口的有效授权 | 任务默认继承，可收窄／排除；不能扩大项目资格 |
| 查询记录／结果版本 | 某真实请求实际得到的数据、类型、完整性和出处 | 默认属于原项目；跨项目分享固定结果须沿明确材料资格 |
| 数据说明 | 观察、业务陈述、字段含义、概念／SAP 映射及推断／未知 | 沿现有项目修订与输入身份，不另造定义库 |
| Studio 正式资产 | 经既有授权发布的语义／Binding／关联及准确版本 | 可复用定义；活库资格和结果正文分别核对 |
| 核算记录 | 固定输入、首次依据、作者对照、意见、新稿和知情复查 | 输入与意见均绑定版本；结束不代表专业正确 |

连接配置修订、结构观察、业务说明／资产修订、查询结果版本分别表达，可扩展现有记录承载，不因此新建四套版本平台。密码轮换不等于业务定义变化；换目标库、表结构变化不得静默继承原映射的适用性。

## 4. 需求与验收

### DB01 连接配置

在连接器入口管理命名连接。用户提供必要连接信息与凭据／引用，查看允许范围和数据出口说明，测试后保存。保存的是已测试的确切配置；测试后修改影响连通／权限的内容，原测试不再适用。连接通只证明连通观察，不表示业务数据完整、权限足够或映射正确。具体字段随后续选型确定，Demo 使用示意地址及合成凭据引用，不收集真实密码。

### DB02 项目复用与授权

项目资料区显示文件与本项目获准数据库。登记连接不自动授权全部项目。项目引用时明确数据范围及允许进入任务模型的内容；Host 在目录、结构、试读、查询和结果读取各入口核验真实归属。数据库原生权限与连接器实际执行限制共同落实权限，不以 `SELECT` 前缀或 MCP 注释作证明。

### DB03 任务继承与收窄

已授权项目的新任务默认继承其来源，任务可排除／进一步收窄；正常查询不重复开启或逐次确认。运行中的任务捕获有效配置与来源身份，变更按公共生命周期处理，不静默替换在途来源。该语义是相对于原任务级开关的新合同，仅针对 db-link；不顺带改变商圈／天气等既有能力。

### DB04 Agent 自主发现

先提供精简可用来源索引；Agent 按需获取结构、注释及合格业务资产，选择表、字段、粒度、时间、关联、取样与方法。可见、提供、读取及实际采用分开记录。Host 不生成业务 SQL、不规定必经分析步骤、不要求先建齐数据说明或 Studio。来源内容作为材料，不能扩大工具权限。

元数据不完备不是分析开工门槛。Agent按DB19在当前授权、预算与可用材料内自主发现和核查，继续能支持的分析；关键缺口只限制依赖它的操作或结论，不强制先补齐全库结构、字段注释、外键、语义图或资料说明。

### DB05 只读取数与资源限制

提供少量正交的发现／结构／只读查询能力，优先沿成熟组件公开能力接入。实际数据、字段、行范围和外部副作用限制必须可执行；设置合适的超时、并发及返回规模。行数上限不替代数据库执行成本限制。Agent 可以在授权内聚合、分批、导出必要明细并自行纠错，不能把数据缺失填零或把截断结果当完整总体。

### DB06 来源与真实结果

结果携带连接／配置身份、原请求／项目／任务、实际对象、SQL 与参数、获取时间、实际类型和精度、行数、分页／截断、错误与取消状态及可取得的一致性条件。凭据不进入消息、工具参数、SQL 回执或日志；含业务信息的 SQL／参数按原项目数据资格保存与读取。时间戳不冒充数据库快照；同 SQL 再查询是新的观察，不覆盖旧版本。

### DB07 被采用输入的留存

探索结果可直接使用。Agent 交付报告依据／核算来源时，声明其实际采用的结果引用与必要范围；Host 固定确切结果字节和出处，并复用现有文件／证据及输入版本。数据与过程默认 `020_clean`，报告 `060_reports`；不改变 `010_draw` 软约束。Host 不扫描正文猜最终报告或业务依赖。用户无需手工搬文件；不足以复算的聚合表必须标明限制。

### DB08 数据说明

沿原数据说明入口处理粒度、单位、时间归属、对象含义、字段位置、概念／SAP 准确版本、推断和争议。增加数据库对象位置的最小表达；结果固定成文件后复用既有文件位置。Agent 可准备、保存及使用本项目说明，涉及真实业务歧义才请求人补充。编辑新说明产生新修订；旧报告仍引用旧输入和旧说明。

### DB09 Studio 连续承接

有复用价值的定义／映射可成为原 Studio 候选与 Binding，带确切来源。准备与核查由原 Agent 在授权内完成；正式发布、项目采用与图刷新仍走现有入口及有效授权，分别展示实际状态。候选保存／发布预览不等于正式发布；正式资产共享不复制凭据、原项目明细或活库权限。普通分析可以独立使用获准数据。

### DB10 变化与历史

连接配置、真实来源身份、观察结构、说明／资产和结果版本分别保留。结构变化使相关映射待核验；新增字段不自动获得权限，删除／改类型不自动猜修复。新任务选择合格新版本；正在运行的任务及历史报告不被后续授权、发布、图刷新或重新查询改写。

### DB11 现行审查与数据库独立核算候选

现行默认沿报告计算复核：主Agent在父请求内指定主报告及材料，前台子Agent一次返回意见，原Agent自主处理后交付，不加开关；修订稿不自动再委派。结论建议审查沿当前明确开始、固定版本与带回原分析的合同，来源材料可复用，两个审查触发彼此独立。

本包另提出“数据库独立核算”设计候选，保留用户本轮讨论的冷读与修订完整流程。原型清楚区分现行入口、该新增候选与旧记录只读。选择数据库独立核算时，预填 Agent 明确关联的源结果、问题、事前语义及作者产物，允许用户调整范围。固定输入后，核算 Agent 先自主形成首次依据，再看到作者报告／SQL／脚本／派生产物进行比较。来源回执的中性身份与覆盖说明可先供给；作者方法与答案不提前混入冷读。输入不充分时明确无法确认。固定、提供、读取、计算、解释和专业正确分别表达。

### DB12 数据库独立核算自动衔接候选

本项为本轮新增设计候选，采用显式开启及适用的可信新任务准入，不启用或恢复历史legacy设置／写接口。默认仍沿DB11现行报告计算复核，用户明确选择本项时，须在父请求准入捕获一种计算核验合同；同请求不叠加默认报告计算复核与数据库独立链，也不以材料未产生补跑另一条。结论建议审查仍按原独立入口使用。用户启用本项后，原任务从第一条可执行查询之前纳管数据库读取；请求准入绑定获准来源，分析实际交付后固定本次材料，沿同一公共 owner／lease 接续独立核算。意见交回原 Agent，由它自主处理；原件、旧稿及原 native 前缀保留，新稿另存，之后明确“知情复查”。沿原自动次数／停止边界，不新增裁判或 Host 专业放行分支。

当前普通 MCP 开关不能满足本条，旧链的保护范围也不自动适用于现行conclusion任务。实施前必须验证数据库能力的受管接线、凭据隔离、远端查询身份与收尾，以及动态来源对现有固定输入准入的适配。不能以无工具出稿或要求用户长期手工导出代替完整路径。能力不满足时自动链显示具体不可用原因，普通允许能力及历史仍按原策略使用。

### DB13 核算覆盖的诚实边界

固定结果上的重算只核这些输入，不能证明原取数没有漏时段、漏对象、错误关联、去重或过滤。要核取数，需足够原始的固定范围，或同一可复现数据库版本上的独立查询能力；核算方法仍自主。具体库能否提供该条件留待选型实证。不能以第二次实时查询冒充同源；不能把作者聚合表当独立原始来源。UI 分别显示计算核算与取数验证范围，保留分歧／未知，不展示“专业 PASS／保证正确”。

### DB14 撤权、停止与迟到

撤权立即拒绝新派发，不因查询忙碌而阻止撤权。停止仅作用于真实所属查询及资源，不关闭无关项目共享服务。SDK 请求取消、连接释放、数据库端终止分别核定；未证实保留 UNKNOWN 及相应占用，不自动重发。配置变化／晚到结果只可补原操作技术事实，不能流入新项目或触发后续核算。历史材料保留，后续可读资格按项目原材料规则处理。

### DB15 模型出口与凭据

项目授权时一次说明哪些结构／注释／查询内容可进入本项目模型及允许目标。普通授权内读取无需逐次确认；模型出口或数据范围扩大才补适用授权。凭据由 Host 与受信连接资源解析，Agent 获得非敏感引用。普通任务已有用户 MCP／bash 不因 db-link 授权就获得全环境隔离保证；只能对所实现接缝作如实声明。

### DB16 界面、归档与可访问性

复用现有产品 shell、项目对话／资料、Studio 与核算入口。默认以自然语言提问为主，配置／SQL／追溯和高级范围按需展开。归档项目只读查看已有连接依据、说明、报告与核算；禁止新查询、授权变更、固定材料、说明保存、候选／发布／采用与新核算。恢复走现有明确动作，本 Demo 只展示归档只读。桌面并排、窄屏纵向；浅／暗主题层级一致；表单标签、错误关联、焦点、原生 dialog／Esc 及状态播报可用。

### DB17 原型诚实与非线性使用

Demo 仅内存合成资料，刷新重置；模拟连通、查询、Agent 活动、固定、发布、采用、图刷新、核算和修订均标明演示。类型和组件显示后续选型。评审场景控件独立于正常路径，不要求先选场景。各模块可按目标单独使用；演示活动记录不作为 Host 固定分析流水线。

### DB18 工程复用与实施前置

优先复用现有 Pi 官方 `1.4.0` 的 MCP／工具注册与完整 Agent Runtime、Interface v3／真实 project/task owner／公共生命周期、现有数据说明、Studio 与核算；不新增平行 Runtime 或另一份运行状态台账。连接资源归属于原 owner 的 operation，项目授权由 Host 管理，连接器不自注册 Agent 域。不先冻结 DB schema、驱动、MCP 工具精确名称或新 Interface 版本；后续选型确认后补契约／适配／验收与 IN01–IN07，升级需用户指定精确目标，SDK 保持官方原包。

### DB19 元数据不完备时继续分析

本条所称元数据，是描述来源和结构的资料：库／schema／表／视图、字段及类型／精度、主键／外键等约束、注释及实际观察范围。它与业务数据内容、业务定义分开；字段存在或类型明确不证明单位、币种、含税／退款口径或时间归属已经明确。缺注释／外键不等同缺数据，未看见对象也不直接等同对象不存在。

**在现有授权内自主发现、核查并继续可做的分析，不强制先补齐元数据。** Agent自主选择读取相关结构、使用已获准样本／查询、查阅原数据说明／正式资产及调用现有合格Semantica工具，判断支持范围与还需什么依据。表中是处理原则和反例，不是每次必走的工具顺序、固定检验数量或资料填写清单：

| 缺口 | 可继续的工作与必要边界 |
| --- | --- |
| 字段注释、字典或描述不全 | 从获准结构、原说明／正式资产和必要数据观察补线索；有据的分析直接继续。推断标为候选，不凭字段名把未知业务含义写成事实 |
| 外键或关联描述缺失 | Agent可自主提出并按需核查候选关联，考虑完整组合键、租户／时间条件、重复匹配及输出粒度；不把同名字段、样本匹配或唯一率当已证约束／正式关系 |
| 已观察结构／依赖不完整 | 在权限内按问题进一步发现相关对象与实际字段；视图底层或部分对象不可取得时保留覆盖未知，不强制全库遍历或完整血缘才开始，也不推断未授权对象内容 |
| 关键业务定义不明 | 优先从合格资料和准确正式版本找依据。仍缺不可替代定义时只澄清影响判断的业务问题，其他有独立依据的分析继续；可明确条件性分析，但不得把未确认假设包装成确定结论 |
| 必要字段、真实历史或数据覆盖不足 | 这属于数据／材料缺口，不靠完善注释或语义图补造。完成有据部分，明确缺失范围及受影响结论；不填零、不将未匹配／未读取当不存在，不把截断当完整总体 |
| 权限、真实来源身份、安全执行或必要精度条件不满足 | 仍按DB02／05／06／14／15及驱动硬准入拒绝受影响操作／材料采用，不能因“继续分析”越权或把不可确认的值写成精确结果；其他获准且不依赖该缺口的工作可独立继续 |

**关键缺口与结论限制应在相关回答／结论附近明确说明**，包括当前实际采用的来源／范围、缺什么、哪些结果仍有依据、哪些判断只能条件性表达或无法确认。仅看见字段／取得样本／保存文件不等于已核完。未知不能藏在技术日志中，不能一边标“数据不足”一边给出不受限制的确定结论；也不要求列出所有与问题无关的目录缺项。

Agent按当前问题判断哪些缺口关键，自主在预算内核查和纠错；Host只核真实资格、资源、技术来源及留存，不打全库“元数据完备度”分数、不代作业务正确性裁决、不强制固定方法链。已有证据足够就继续；确需人决定的仅为不可替代业务歧义、有效扩权或原合同要求的正式决定，不让用户逐字段补表、逐关系认证或逐次审批普通读取。缺口确实阻断整个当前问题时如实说明无法确认及最少所需信息，不以“总要给答案”编造。

说明、关系候选及准确出处沿原数据说明／Studio保存，不新建引擎或权威；元数据不足时允许继续，不降低DB07／11–13的固定材料、充分原始范围和冷读隔离条件。作者在核查中新产生的关系／口径候选仍是作者产物，不能提前冒充中性事前语义。结果与缺口按原项目／任务／请求记录，撤权、停止、归档和迟到仍按原合同，不因恢复材料而自动重放或启动后续核算。

UI沿现有对话／报告、来源详情、说明中的推断／未知表达本条，无新增必经页面、补齐按钮或全局阻断开关，本轮不改批准Demo；旧Demo成绩不证明本条已实现。后续若出现实质新交互，先补受影响UI确认。

DB19的后续验收至少包括以下反例，**本轮仅作设计走查，未执行产品／数据库／模型验证**：

| 情境 | 应观察到的行为 |
| --- | --- |
| 有足够获准数据，但无字段注释／外键 | 不因目录不齐拒绝开工，Agent自主核查后交付有据部分，不先要求人补完整字典／语义图 |
| 单表订单粒度／日期含义已核，但会员身份或历史不足 | 可继续有依据的订单时序统计；复购率明确无法确认或仅作有条件分析，不交“准确复购率” |
| 关键币种／单位或退款归属期不明 | 查原合格定义，确需时集中澄清；不盲目跨币种求和或给出确定净额，独立有据部分继续 |
| 候选关联存在跨租户或多对多放大 | 保留候选及条件并由Agent自主核查／调整；不能因无外键就全局停工，也不能静默当已证关系 |
| 结构读取被拒、结果截断／真实历史缺失、技术精度条件不足 | 分别表达权限／覆盖／精度缺口，不把它们混成“元数据不齐”；受影响操作遵守硬边界，不采用缺失为零等伪完整材料 |
| 只剩与当前问题无关的目录缺项，或当前问题全部被关键缺口阻断 | 前者不增加补资料步骤；后者如实无法确认并说明最少必要信息，不伪造完成；两者均无完备度评分或Host业务放行 |

## 5. 最少操作与四原则专项

| 场景 | 用户必需动作 | 可由 Agent／Host 完成的工作 |
| --- | --- | --- |
| 初次连接 | 提供不可代猜的连接资格，确定范围与模型出口，保存 | 技术连通检查、状态与凭据引用管理 |
| 项目首次复用 | 选择连接并明确本项目范围 | 引用配置、不复制密码、任务继承 |
| 已授权日常分析 | 提业务问题／正常发送 | 发现、取数、计算、纠错、关联并保存依据 |
| 元数据不完备 | 不要求先补齐目录、注释／外键或语义图 | Agent授权内自主发现／核查，继续有据部分，关键缺口与结论限制明确说明 |
| 关键业务／权限缺口 | 仅补不可替代定义或作必要授权决定 | 先利用现有获准依据；其他可独立工作继续，不逐字段追问 |
| Studio 沉淀 | 沿既有权限作必要发布／采用决定 | 准备候选、来源、差异与准确预览 |
| 数据库独立自动衔接候选 | 任务中明确选择本设计候选与适用范围 | 固定、核算、反馈、原 Agent 自主修订与复查 |
| 异常 | 必要的凭据修复、权限决定或未知收尾处置 | 明确错误、保留现场、隔离旧操作及可独立继续的工作 |

四原则检查须逐条核对本规格、[UI合同](ui-spec.md)、[状态矩阵](interaction-states.md)与实际可点击 Demo，而不是仅检查口号：

| 原则 | 具体安排 | 必须拒绝的反例 |
| --- | --- | --- |
| Host 管环境 | 技术来源、权限、资源、交接和保存 | Host写业务SQL、代算、完备度评分代业务裁决、按核算意见裁决对错 |
| Agent 自主 | 自主选择源、方法、计算、核查／继续范围及回应 | 固定专家链、必用工具／检查数量、先补齐全库元数据才开工 |
| 优先复用官方已有能力 | Pi＋公共生命周期＋现有业务权威，最小新增接缝 | 修改三方 SDK、借包装重造 Runtime／全域版本平台 |
| 减少人类操作 | 项目授权任务继承，来源／材料自动衔接 | 每个任务重填凭据、导出再上传、先填完整映射才能提问 |

专项结论、实际反例、失败修正与独立复核记在[准备结果](result.md)。设计检查不证明真实权限、远端取消、持久化、模型质量或产品验收。

## 6. 本确认包需核对的呈现决定

- D01：共享连接登记、项目授权、任务默认继承，任务可收窄；不改其他连接器开关。
- D02：主对话与按需资源面板承接完整流程，来源固定、数据说明、Studio发布／采用和核算分项显示。
- D03：数据库材料默认接现行报告计算复核／结论审查；另保留v0.1已批准设计中的数据库独立核算及自动修订候选，显式选择且同请求不双算，尚未开发；历史legacy仍只读。
- D04：本v0.2新增DB19不要求元数据先完备，Agent自主核查／继续并明确限制；沿原按需资料面表达，不新增强制交互，待本增量确认。

## 7. 后续工程验收与未决事项
