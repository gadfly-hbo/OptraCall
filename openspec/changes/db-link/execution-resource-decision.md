# db-link 执行资源约束决定（保留硬准入）

2026-11-14。保留已批准spec v0.2／driver revision3及额外parser决定；本文件记录真实实现/实证后发现的边界，不改原批准稿、不替用户降低准入。

## 已经核实

首轮官方驱动有限执行候选在隔离PG18.1和MySQL8.4.0中完成第三轮19/19真实测试：TLS正反例、原生目录/复合关系、精确参数与BIGINT/DECIMAL/时间/JSON/二进制、真实服务器超时及停止后等待原命令/连接收尾。前两轮真实FAIL及修复分别保留，不覆盖为最终PASS。该成绩对应已固定的有限候选源码，并非当前产品已准入。

批准的[驱动说明第3节](driver-selection.md#3-查询权限与预算)要求单值规模受实际内存约束，执行预算具备可执行证明。当前未经修改的官方SDK在向公开行/字段回调交付之前，会先完整解码字段；游标/流背压和事后maxCellBytes/文件限额不能证明解码前Host内存硬上限。MySQL会话max_execution_time也不能完整覆盖准备语句阶段的总时间。技术parser允许/拒绝语法不能补这两项资源保证。

因此最终候选必须返回queryQualified=false及明确限制：PG db_receive_memory_budget_unenforced；MySQL额外db_prepare_total_budget_unenforced。允许范围内的目录观察/结构说明可继续，新的业务SQL不得派发；已固定项目材料仍按原owner和准确模型出口资格回看。取消/断线不能证明远端终结时保留UNKNOWN及原请求资源占用，不按缓存PID/connection ID盲重试。

## 两条明确路径及用户决定

1. **保留已批硬准入**：继续拒派业务SQL，先评估能实际强制资源约束的成熟隔离/执行方案，再提交组件与部署增量。未选型、未引入、未授权新组件或服务。原驱动仍是薄适配，不改其源码。
2. **调整一期合同**：明确maxCellBytes/结果bytes为驱动接收后及持久化预算，不承诺解码前单值内存硬上限；MySQL准备阶段完整总截止未证明；保留已证的原生SELECT执行/锁等待限制、本地不续派、精确结果、UNKNOWN和并发占用边界。在用户明确认可合同变化后，才按修改后的条件重做准入和验收，不能把此前19项直接宣布当前完整通过。

用户已明确选择“保留硬准入，先评估成熟的资源隔离方案（推荐）”。据此继续路径1，查询拒派，先做官方一手资料调研；不降低合同、不安装或引入新组件。该决定只授权方案评估，不授权SDK升级、代理/容器/系统服务安装、远端业务库访问或新方案实施。这里不是要求用户安装PostgreSQL：两个测试程序已在.local/db-link/native-fixtures的独立目录构建/解包，合成资料、127.0.0.1临时端口，不注册系统服务、不操作其他设备；每轮停止自有进程。
