## 2. PGS01：来源与可执行SQL范围

### 来源先具备真实资格

沿原TLS／真实实例／专用受限角色／项目范围／模型出口资格。READ ONLY不替代原生最小权限；Agent得不到密码、任意DSN、控制连接、会话PID或计时器控制权。只在实际验证的PostgreSQL版本、角色、对象类型和官方驱动组合开放能力；第一批验证复用既有隔离PG18.1，不在本稿决定安装或升级版本。

`transaction_timeout`自PG17提供，但“版本≥17”只是必要条件，不代表全部17／18来源已通过。旧版本、分流到未知节点、无法识别实例或无法核查必要期限／收尾的部署继续不合格；不静默降级为仅statement_timeout。[T1][T2]

现有限定普通heap表、已核实内建类型／访问路径、准确schema.table和`search_path=pg_catalog`作为首批候选。视图、RLS、外表、继承／分区、自定义类型／域／函数／运算符／collation、扩展与服务端钩子若带来未核实执行路径，暂不准入相关对象；未来逐项验证后再扩，不能只因账号有SELECT就放行。原合同允许的受限视图／RLS方案不等于本驱动候选已实现。源权限与DDL可并发变化：需要在同一事务中持有实际所需对象锁后核对身份／列类型，再执行；核查与派发之间发生替换、解析歧义或未知路径时拒绝，不凭配置缓存承诺安全。不能验证的竞态列为未通过。

### Agent决定业务，Host核技术合同

| 类别 | 本期可准入候选 | 明确拒绝／条件 |
| --- | --- | --- |
| 语句 | 单条参数化SELECT；显式列、准确授权对象；SQL字节、参数数／大小、AST深度／节点数均有有限上限 | 多语句、SELECT *、写／DDL／COPY／DO／CALL、SELECT INTO、锁定读取、递归、数据修改CTE、事务／会话控制、PREPARE／EXECUTE、管道／多结果入口 |
| 查询组合 | 普通过滤、INNER／LEFT JOIN、GROUP BY、ORDER BY、非递归CTE／子查询，仅限已支持且每个分支均可核实的形状 | parser能解析不等于安全；未知节点、未核实语法、UNION等未列入首批能力的组合默认拒绝，不实现通用SQL编译器 |
| 函数／运算 | 按准确内建签名、输入类型／实际参数、返回类型和诊断路径逐项准入；整型COUNT、固定类型比较和逻辑判断作为最小候选 | 不按函数名、IMMUTABLE／STABLE标记、SELECT前缀放行；自定义／同名遮蔽、任意cast、动态SQL、文件／网络／信号／角色／计时器函数均拒绝 |
| 聚合／算术 | COUNT；MIN／MAX仅对已证有界标量。SUM／AVG及其他算术必须另有具体类型、最终表示和错误路径证明，未证明的签名不开放 | string_agg／array_agg／json_agg、min／max(text)、无界拼接／重复、任意文本转数值／日期、CASE／COALESCE藏长值不能借聚合或白名单绕过 |
| 返回列 | 每一列的最终线上表示有已知上界；boolean／int2／int4／int8／uuid及明确格式的日期时间等按固定签名验证 | 不把NUMERIC、字符长度n、数组、JSON、表达式结果一概当小标量；未知OID／typmod／分支类型拒绝整值输出 |
| 行数／分页 | Host绑定有限批量、列数、总返回量、并发及一个未完成read；Agent可自主选择更小的范围和批次 | LIMIT只限行；批次不能重置整个操作期限。窗口LIMIT／采样／人为筛选必须保留SQL范围，不能当全业务总体 |

数值保真沿原合同：BIGINT／NUMERIC不经JS Number；时间保留微秒、时区条件和原返回语义。`numeric(p,s)`须按真实p／s与输出表示计算上界，无typmod的NUMERIC或表达式不能按几十字节估计；不为减小输出强制cast到更小精度／标度。无法安全在库内聚合时，Agent可自主取获准且精确的有界明细，用原Python／计算工具继续；Host不代写业务SQL、不补算。[N1]

Host使用已批准parser的公开AST检查，但不依赖`sqlify`改写；通过后发送Agent原SQL及准确参数。实际对象／类型／运算解析和参数值也须校验，不能只查AST语法。若固定parser不能无歧义表达一个安全形状，返回具体不支持原因，由Agent改写；不补另一parser、私有PG协议或完整类型推导系统。

校验错误提供“哪个对象／输出列／表达式／参数不支持、允许的安全替代及当前限制”，不包含越权信息。Agent按以下PGS07在同一Pi正常工具调用循环中自主调整；不将SQL纠错等同于SDK网络重试，不新增Host纠错／重放循环，也不每次转给人批准。

### PGS07：Agent自主纠错与跨纠错累计预算

**Host把技术拒绝作为原工具调用的可理解结果返回，Agent读取原因、自主修改SQL或改选已获准办法，再调用原工具。** 再失败仍可自主调整；无SQL专用“最多3次／5次”等固定次数，也不以连续同错次数自动强制换方法或转人。Host每次只核当前真实权限、SQL／参数、资源及操作资格；不会因尝试次数增加而逐步放宽门槛，更不替Agent补SQL、选业务条件、计算或裁决专业结论。技术通过不保证业务口径正确，Agent仍负责检查结果并判断是否有据继续。

这是Pi正常的“工具结果→Agent继续推理→新工具调用”过程，沿原会话、父请求、真实owner和工具调用身份。SDK针对Provider连接／传输失败的重试有自己的事实与语义，不能用其次数作为SQL纠错次数，不能依赖网络重试自动重放数据库SQL。工具适配器只返回原结果，不另建提示词修复器、纠错会话、for／while调用模型的控制器、自动SQL改写器或新Runtime。既有工具组合／嵌套仍沿原资格，不因本条另加专用执行方法限制。

接入仍为工程规范v1.10／Interface v3／官方Pi 1.4.0，工具沿原项目任务及已合格受管profile、真实project／task／request owner工作；原前台子调用只继承权限交集。不新增SQL纠错profile、会话域或持久请求身份，不把原核算专属有限次数／一次委派合同移植成SQL纠错次数。本条实现由Codex沿原Host／Agent接缝承担，验收仅限PGS07及V13–17和受影响回归。

本期两层预算明确如下：

| 层级 | 当前合同 | 不得混淆的边界 |
| --- | --- | --- |
| 单次数据库operation | 从本次工具操作准入到查询／续段／收尾，沿PGS02–04的有限期限、有限在途／工作缓冲／返回量及并发资格；数值按后续授权验证固定 | 同一查询的分段／分页／清理不能新开事务刷新旧预算；一次超时不证明远端已结束 |
| 同一父请求中的跨纠错过程 | 按用户本轮决定，**暂不设累计上限**；不新增累计耗时、模型token／费用、SQL调用次数或跨次结果总量的SQL纠错专用停止阈值，也不预设失败后必须转人的次数 | 累计无上限不是单次操作无超时／接收无界；不能把此政策编码为传给驱动的Infinity／0，不借此绕过权限、并发或UNKNOWN |

跨次仍应关联并保留**实际累计事实**：原请求内已发生的工具尝试、拒绝／已派发／已收尾状态、实际耗时、结果引用，以及原Pi／Provider已有的用量事实。沿原request／toolCall及事件／使用记录查询或汇总即可；不为此新增必经预算预估、计费系统、预算账本或第二生命周期台账。无法取得的费用／用量保留unknown，不能填0；不能把未核账单推算成实际费用。跨次记录不因为重新生成SQL、重开合法的新operation而清零，也不被拿来实施本期未授权的累计停止阈值。

当前**没有启用的累计额度可供“扣剩余量”**；因此不虚构父请求剩余deadline、token余量或未来固定次数。若后续出现具体成本／反复无进展等问题，再根据证据提出调整交用户决定，本稿不提前启用默认累计上限或隐藏熔断器。官方SDK／Provider自身的单次请求、上下文及故障限制仍按实际能力如实处理，不因“累计无上限”宣称模型能够无限上下文／必然成功，也不改其官方实现或全产品配置。

| 本次结果 | Agent是否可自主继续提交 | Host必须确认的事实 |
| --- | --- | --- |
| 派发前技术拒绝 | 可以修改／选择其他已获准方法后再调用，不需用户逐次确认 | 明确本次SQL未发给数据库；若校验已创建本地资源，须按原生命周期释放，不能把带资源的在途操作伪装为空拒绝 |
| 数据库明确报错，含单次操作超时 | 原命令、事务、连接及必要远端身份均确认收尾，父请求未被停止且资格仍有效时，可提交自主决定的新尝试 | 旧操作先收尾；新SQL／新参数是新的真实观察，另记操作，不重用旧快照、不补写旧结果；每次新操作有自己的有限预算，跨次不设累计上限 |
| 该表达式／来源无法满足硬准入 | 可改用已获准且不依赖缺口的分析；不存在合格办法时如实说明限制 | 不靠反复尝试绕过同一硬边界，不因多次失败自动扩权／放行；不要求用户先补齐全部元数据 |
| 用户停止父请求／父请求已取消 | 不得继续为该父请求发数据库或模型纠错请求；迟到错误也不能触发下一次 | 先撤派发资格，按原operation收尾；用户后来恢复权限不自动复活已取消请求 |
| 某来源撤权／配置使该来源资格失效 | 拒绝该来源新SQL／续段；父请求仍有效时，Agent可按原资格继续其他不依赖该来源的有据工作 | 受影响操作先收尾；不因某来源失效误停所有独立工作，也不新建模型纠错循环恢复旧来源 |
| UNKNOWN／结果丢失但是否执行或远端终结未明 | 不得重发原SQL，也不得以“改写后的新尝试”旁路同owner占用 | 仅允许原合同的明确安全清理／只读核销；不自动重跑模型、重连续读、按旧PID取消；未知解除也不自动续跑旧链 |

Agent可以自主识别反复无进展，改方法、继续有独立依据的部分或如实结束；Host不强迫它无限循环，也不替它决定“第N次就必须换方法／提交结果”。停止／撤权／实际故障不被累计无上限取消，完整／partial／failed／cancelled／UNKNOWN分别保留，禁止把“纠错最终通过”写成先前查询或业务结论均正确。

## 3. PGS02：接收规模与大字段分段

### 必须在服务器形成有界的最终输出

首批长值仅针对**获准表原列及已核实的固定表示**：text按确定UTF8表示、bytea原字节、JSON／JSONB按服务器实际文本表示；数组、未知类型和任意生成式表达式暂不支持整值分段。JSONB表示不冒充原始录入字节；可保留原类型、编码与此限制。

Agent明确选取业务行、列及需要的范围，提交符合支持形状的原SQL。大字段SQL须明确返回稳定行身份／列身份、NULL标记、总字节长、段偏移／段长和有界bytea段；长度／身份控制列也要有界。Host只检查技术格式并推进已声明的offset／length传输参数，不改业务过滤、JOIN、列含义或统计口径；传输参数与业务参数分开校验及记录。未经证明的通用表达式即使外层substring也不放行。[B1]

分段是**同一工具operation内的短时传输**，不是长期游标会话或等待下一轮模型的后台任务。沿原owner资源保持同一独占连接、同一READ ONLY REPEATABLE READ事务、固定业务参数与操作总截止；在同一operation中自动按授权范围推进段，保存准确SQL与每次参数。只允许为相同值推进传输偏移；不自行发现／改选业务行。新接缝属于原db_query／db_result的最小传输适配，后续实施先固定准确输入／回执及行为测试，不新建全局游标Map、运行队列或会话平台。

稳定行身份需原生合格唯一键或在同一事务内已核实的唯一选择；复合键、租户条件须完整。结果不唯一、身份字段本身未能有界读取或原生资格不满足时，拒绝该整值续段，不按第一个匹配、OFFSET排名或ctid跨观察拼接。元数据缺失只限制依赖这个证明的完整重组，DB19中其他可做分析继续。没有一致快照／稳定身份时，可明确取得一次有限片段观察，但不拼成完整值。[I1]

| 传输规则 | 完整性要求 |
| --- | --- |
| bytea按字节切段 | PostgreSQL hex文本输出的N字节段占`2N+2`字节；按最终线上表示计预算，不能把N误当解码字符串长度 |
| text固定编码后切字节 | `substring(text,n)`是字符长度，不能直接当字节上限；一段可切在UTF8字符中间，按连续字节增量解码、保留有限未完成字符，不逐段替换坏字符，也不要求先在内存拼全值 |
| 控制范围 | offset非负／长度有限正值／加法无溢出，SQL的一基起点转换明确；Agent不能用参数绕过段长或列数上限 |
| 同值分段 | 记录来源／配置／事务观察、对象和稳定键、列ordinal／类型／编码、总长、每段offset／字节数／摘要及提供范围 |
| 完整判定 | 无重复、缺段、越界、冲突、长度不符，以有序文件块／受限块引用连续覆盖所需全值并增量校验摘要后才可标该值完整；摘要只证本次确切返回字节，不独立证明业务真值 |
| 预算到期／只要预览 | 返回明确`partial`／提供范围／缺失段；NULL、空串、空bytea、未提供、超限分别表达，不能用NULL或零替代 |
| 文件与模型出口 | 原manifest＋JSON文件集承接段引用／摘要与完整性，沿020_clean及原出口资格；模型预览有界，不能把大段全塞提示词 |

**完整是逻辑字节覆盖，不要求Host把整值装入内存。** 段按顺序增量摘要／编码／写入有界文件块，逻辑行中的大值保存有标签的段引用、源类型和完整性；段数不增加业务行数，不把技术段当新业务列或普通字符串。读回、摘要校验、导出、UI预览及RCR／CNR固定材料读取同样遵守有界消费，不能在这些接缝偷偷整值加载。仍用原JSON文件集及有限预览能力，准确表示／兼容接缝在后续实施前固定，不新造存储引擎。

传输与重组共用一个**独立于整值长度**的有限工作缓冲预算，覆盖段队列、UTF8 carry、Buffer／字符串／JSON编码副本；总值超过该缓冲也须能在原累计结果／时间资格内流式完成。禁止先累计所有段再`Buffer.concat`、拼接巨型JS字符串、对完整长JSON做`JSON.parse`或整值`JSON.stringify`后才检查。只有事先已证明整值及并存副本处于明确小值预算内，才允许整值物化；未知大小不能走此例外。预算／停止／写入失败时保留准确partial，不能用失败后的内存增长当保护已执行。

**不得用WHERE长度过滤静默丢行，不得截断金额、标识或时间精度后声称完整。** 大值未提供不妨碍独立的有据统计，但依赖该值的结论须说明限制。两次独立READ COMMITTED查询的“先查长度后取值”有变化窗口；新事务／新任务再取是新观察，不补写旧版本。即使REPEATABLE READ也不令任意volatile表达式相等，因此首批只分段已核实原列表示，不支持动态生成式整值拼装。[I1]

### 接收边界必须覆盖所有路径

参数、SQL／列名、列数、每字段最终字节、每行、每批、段数、累计返回、在途read／待消费批次和owner／来源并发均由Host绑定有限预算，默认不由Agent提高。证明须覆盖线上消息、Buffer、UTF16解码、JSON序列化及保存阶段可同时存在的副本；下一批在前批落盘／消费后读取，不能只有每字段上限而累计无界。

这仍不足以自动证明完整接收安全：ErrorResponse／NoticeResponse中的message／detail／hint／context等也先被驱动解码。禁止Notice监听器、减少日志、错误回调截字、公开type parser及事后maxCellBytes都太晚；`client_min_messages=ERROR`也不屏蔽全部消息，INFO仍可发送。[E1][E2]

每个准入签名须同时核查：失败时是否把长输入写进错误；对象／类型输出、参数转换、目录注释／默认表达式／定义文本、通知、连接／认证消息是否可无界。目录与结构读取也用已核实的有界投影／分段，不因它是Host SQL就豁免。错误路径、源侧扩展／钩子或启动诊断未知时继续拒绝相应来源／能力；不能仅测正常DataRow就消除`db_receive_memory_budget_unenforced`。本方向针对可信且受限、实际验证的PostgreSQL来源，不声称防御恶意服务器任意协议帧；若所需保证必须覆盖该威胁，本方案尚不满足，回到用户讨论，不能暗加SDK补丁／代理。

## 4. PGS03：期限不可被查询重置

**本节的“总deadline”只属于一次数据库operation，不是整个Agent纠错父请求的累计deadline。** 一次操作从Host准入开始使用一个单调时钟总deadline。以下单次参数必须为有限正值并在调用前固定、回执记录；具体生产数值在授权验证后依据负载确定，不在本稿伪称已实测合理：连接截止、业务操作总期限、statement／lock／idle事务期限、收尾宽限，以及第3节各传输预算。零／负值／Infinity／溢出／未知单位拒绝。测试可用更短值，但不能以测试值直接宣称产品默认。PGS07的累计无上限不适用这些单次安全参数；本版不为纠错父请求另设总计时器。

| 阶段 | 约束与事实 |
| --- | --- |
| DNS／TCP／TLS／认证 | 原公开连接超时＋Host固定总截止；尚无业务事务，transaction_timeout不覆盖这些阶段。未取得足够实例身份的连接失败也不能假装已证明远端无会话 |
| 连接建立／环境核查 | 连接启动参数或实际专用角色默认值应在首个可执行操作前生效，并由Host核对；不先跑无期限目录查询再补timer。配置、身份、权限核查也消耗同一总预算 |
| 第一业务事务前 | 按本次数据库operation的deadline剩余量确定正的transaction_timeout，使其在事务开始即生效；不虚构父请求累计剩余额度。设定并核对READ ONLY、search_path、输出编码／格式以及statement、lock等期限。设置失败或读回不符拒派 |
| 业务事务中 | 同一只读RR事务覆盖相关核查、cursor和续段；transaction_timeout封顶整个事务，statement_timeout辅助约束单次命令，lock_timeout只管锁等待，idle_in_transaction_session_timeout仅作空闲辅助 |
| 读取／续段／原命令收尾 | 每步前核原signal、owner、授权和剩余量；至多一个未完read，不pipeline。不得新开事务、重连、恢复读取或反复SET把旧预算刷新 |
| 本地超时 | 即刻停止新派发／结果采用，进入第5节收尾；不能因客户端超时回调就标远端终结 |

`transaction_timeout`会终止超时事务所在会话；statement_timeout可仅使事务进入错误状态。后者不替代回滚／会话核销，暂停portal也不能只靠statement_timeout。事务中重设较小正值不能假定已缩短正在运行的事务timer；本稿采用事务前一次确定、事务内不重置。timer关系按实际PG行为验证，不能用长于总体期限的值宣称覆盖更完整。[T1][T2]

这些timer属于可由会话改变的参数，初始SET／READ ONLY／REVOKE SET ON PARAMETER并不能自动证明Agent不能改。必须拒绝SET／RESET／set_config、事务控制、角色／search_path调整、prepared transaction，以及间接调用它们的函数／对象路径；不能仅限制工具名字或顶层语句。用户其他bash／MCP能力不因db-link得到全环境安全隔离，但不得获得本连接凭据／原生client／控制port绕过相同入口。[T1][P1]

数据库异常、网络隔离或服务器不可响应时，这套方案不作任意故障下严格实时时间保证；它规定可验证来源的有限服务器期限和诚实未知，不承诺数据库CPU／内存／磁盘总成本硬配额。

## 5. PGS04：停止、收尾与UNKNOWN

复用现有Interface v3、原project／task／request owner、signal、registerCleanup与占用。一个操作独占物理连接；不池化，不因跨项目配置复用就共享在途连接。默认不新增控制账号，不用未公开Client.cancel、内部activeQuery／密钥／wire CancelRequest；本期不依赖裸PID的pg_cancel_backend／pg_terminate_backend作为主要取消路径。它们的返回或事前身份核对不能消除目标重用竞态。

| 可见状态／技术事实 | 必须发生的行为 |
| --- | --- |
| 运行中 | 仅原operation可派发、read、保存／提交；最终完整结果还须满足原输入留存及remote终结条件 |
| 已请求停止 | 用户停止、撤权、配置失效或截止使资格立即失效；拒后续派发／续段／新保存和核算触发。已在途动作无法撤回，晚到数据仅补旧操作技术记录 |
| 正在收尾 | 若无在途Execute，公开cursor.close后回滚、client.end；若有原命令／read待结束，不在同连接并发塞清理命令，不把cursor.close当抢占器，等待服务器期限及原命令终态再清理 |
| 已释放 | 原命令已终结、事务已回滚／由会话终止、所属连接已关闭，并取得同实例原会话已消失的足够证据；事实分别记录后才释放相应占用 |
| UNKNOWN／收尾待确认 | 原命令、事务、连接或远端会话任一必要事实无法核实；保留原资源资格和失败原因，隔离该owner未收尾操作，不标idle／complete，不启动依赖后续 |

远端核销由Host沿同一来源的受限观察能力完成：捕获实际实例标识、postmaster_start、准确endpoint／database，及原backend PID＋backend_start原始精度；观察连接须核同实例，采用独立autocommit观察避免缓存快照。PID用于**只读定位核销**，不作重新发信号的长期资格。若原会话已不存在或同PID已是不同backend_start，可在同实例核实后说明原身份消失，不能操作新会话。最小观察权限能否取得、实例识别所需函数权限及其信息暴露均须实测，不要求业务账号superuser／广泛信号权限；做不到继续不准入。原会话消失不是整个服务器所有并行／其他会话资源已审计的证明。[M1]

收尾宽限届满只转UNKNOWN，**不等于清理成功**。可由现有明确清理动作重试只读核销／原持有句柄的安全关闭；不能重跑原SQL、模型、重连续读旧快照，不能按缓存PID盲取消。恢复权限、修复网络、切库或服务重启只提供新事实，不自动解封旧结果／接续核算。新问题／其他不相干owner沿原并发策略工作，不引入全产品串行队列；同一受占用owner不得旁路再开替代请求。

UNKNOWN跨Host重启时不能凭旧内存句柄、JSONL或历史timer值恢复可信资格；沿原未收尾／中断记录保留，并在来源可识别时只读核销。重启不是证明远端结束；无足够身份／证明的旧操作仍UNKNOWN，不重放、不将其包装为“重启已清理”。需要的最小技术收据归原operation，不新建业务版本平台或第二生命周期权威。

可承诺“停止后不再授权新工作、状态如实显示并核实原资源收尾”；**不承诺点击后任意远端SQL立即结束**。原生实验里本地退出与PG SQL自然结束之间有数秒间隔的事实继续保留，不改写为取消成功。

## 6. PGS05：数据说明、Studio、核算和最少操作

结果仍沿原manifest／JSON文件集、准确版本、RCR／CNR能力和现有DB11–13承接，不建立新的计算／语义权威。技术回执增加必要的传输表示、段覆盖、预算及收尾事实；Agent决定实际采用范围、专业方法、业务解释和报告。完整文件传输不证明取数总体完整；分段摘要不证明源查询正确；核算读了预览不等于读完整值。

数据说明可记录类型／表示、片段范围及业务含义未知。语义候选沿原说明／Studio，Semantica仅在已有资格内支撑语义依据，不替Host放行SQL或接管计算。固定输入中缺关键段、快照条件不足或停止UNKNOWN时，不能假称全量输入、独立取数已核或继续新的自动核算／修订；已获准固定历史材料仍按原资格可用。新数据库独立链的冷读与作者材料隔离合同不降低，也不借本稿恢复legacy。

正常路径仍是：配置连接并授予项目一次 → 用户提出问题 → Agent自主发现／查询或改写不支持的SQL → Host准确留存 → Agent使用数据说明／Studio／核算的原入口。不给用户新增逐条SQL审批、手动分页、导出上传、段拼接、填timer／PID或补齐全库元数据的必做步骤。人只处理不可代猜的凭据、真正扩权／模型出口及不可替代业务歧义。

本轮不改布局／导航／入口和批准Demo。原对话、来源详情、结果完整性及停止／UNKNOWN状态承载限制；实施时需准确文字和状态，不加技术向导。若后来出现实质新交互，按工程规范只补受影响Demo再实施；旧Demo未展示本增量，不算其运行验证。

| V12 完整产品接缝 | 合格SQL拒绝后Agent自主修正；固定结果→说明→Studio→RCR／CNR；完整值／片段／UNKNOWN三类输入 | 不增加用户审批／搬资料；范围／精度／冷读／采用／核算限制准确；旧文件／会话和失败字节保留，原消费者受影响回归通过 |
| V13 多轮自主纠错 | 同一Pi父请求中连续多个不同可纠错技术拒绝，末次改为合格SQL；测试轨迹可设超过常见3／5轮，有限样例轮数不是运行上限 | 每次原工具错误回到同一Agent；新SQL由Agent决定，无Host自动改写／自调用模型／用户逐次确认；不在固定第N次拒绝；最终通过仍保留先前失败 |
| V14 累计无上限／事实关联 | 有限合成轨迹中每次操作合格且实际收尾，多次累计耗时／调用量／返回量超过任一单次额度；用量有可得与unknown两类 | 不因新增SQL纠错累计时间／token／费用／次数／跨次总量阈值停止；同一父请求的实际记录不清零，不造费用0；无限政策不下传为驱动Infinity／禁用timer，不新造预算台账 |
| V15 失败后新尝试与旧操作收尾 | 操作内多批／多段接近截止，或原SQL超时；分别有确认终结和仍在途两类结果 | 不能刷新旧operation期限；只在旧资源真实终结、父请求有效后允许Agent自主发起新观察及独立有限预算；不因累计无上限重用旧快照、释放未收尾占用或覆盖partial |
| V16 停止／UNKNOWN阻止纠错续派 | 拒绝回传前／Agent生成修正时／新派发前停止父请求、单来源撤权；数据库响应丢失／原会话未明；晚到成功或错误；同owner换SQL重试 | 停止父请求后原signal／owner检查阻止新SQL／模型调用，不把取消当可恢复SQL错误；单来源撤权仅拒该资格，其他有效且不依赖其收尾的工作沿原策略。只读核销／安全清理不重放业务SQL或模型请求，改SQL不能绕过UNKNOWN占用 |
| V17 无进展与职责 | 多次相同拒绝、未支持表达式／未授权来源、模型选择结束或改用已有计算工具 | 不把反复失败变成Host固定分析链／强制换方法／扩权，也不以无上限强迫继续；Agent可自主结束并说明可做范围。模型原生故障／传输重试与SQL纠错事实分开记录 |

接收安全须有源码／协议／类型界限论证与代表性真实消息验证，不能靠某次RSS未涨或仅测试几种字段宣布通用证明。停止须保存原命令、事务、client终态与同实例原会话核销的分别证据，覆盖正常、超时、断线、取消及观察失败，不能用进程退出／信号返回替代。首次PG18.1实验仅是历史技术参考，V01–17不能标继承PASS。V13–17未来沿原官方Pi／Host及合成Provider的真实工具结果闭环验证，不用Host测试脚本代替Agent纠错后宣称已证明自主性；合成Provider轨迹只证明结果反馈、无固定次数和权限／收尾接缝，不证明真实LLM纠错成功率、真实费用或任意SQL都能修正。本轮均NOT_RUN，不调用真实Provider。

### 准入与停止线

1. 先固定真实部署与原包身份、权限／对象范围、有限参数和源码可论证子集；无法满足的能力维持拒绝。
2. 逐项完成V01–11及V15–16相关真实正反例以及连续TDD；任何必要消息路径／来源身份／单次预算绕过／收尾事实未证，`queryQualified=false`；不能把当前没有累计上限误记为缺少累计阈值而拒派。
3. 完成V12–17、适用完整check、公共生命周期消费者回归及最终全新非作者／四原则复核，再按用户有效授权决定交付；工程通过、业务正确、用户产品验收与运行采用分别报告。
4. 若核心消息有界性或强制期限仍无法由成熟公开能力与最小适配证明，记录具体失败并回到用户讨论；不私改SDK、不暗加代理／容器，也不把Agent承诺遵守规则改写成硬保证。

## 8. 四原则专项与待确认决定

| 原则 | 本稿实际安排 | 拒绝的反例／最少操作 |
| --- | --- | --- |
| Host管环境 | 原owner资格、来源／类型／SQL技术准入、单次有限传输／期限与真实收尾，跨纠错累计事实沿原记录 | 不写业务SQL／修改业务条件、不代算、不凭摘要／类型判断专业正确；不私设累计预算阈值 |
| Agent自主执行 | 自选业务对象／关联／方法／SQL，依据具体工具错误多轮自主调整或结束，缺元数据继续有据部分 | 不固定SQL纠错次数／分析步骤／方法配额，不要求先建语义图；不能用“无上限”绕过停止／UNKNOWN或硬准入 |
| 优先复用第三方已有能力 | 固定官方pg／cursor／parser，Pi1.4.0正常工具调用循环／Interface v3／原signal／cleanup、原文件／说明／Studio／核算 | 只补已证缺口；不改原包，不新Host纠错器、模型循环、预算台账、Runtime／生命周期Map／SQL编译器／协议或语义权威 |
| 减少人类操作 | 连接／项目授权一次，分段与技术纠错自主完成，异常准确表达；本期不反复要求人批准纠错预算 | 无新增每次审批／失败第N次转人／手工拼段／搬文件／填timer或PID；只保留必要业务／权限决定 |

待确认的具体增量为：**保留“原SQL不改写＋窄SQL子集、短时只读RR分段、单次服务器期限和真实收尾”；新增Agent复用Pi正常工具调用循环自主纠错，不设SQL固定次数；整个纠错过程当前累计预算无上限，沿原请求保留实际累计事实；停止／撤权／UNKNOWN仍禁止受影响操作续派或重放。** 当前不等待一个累计限额数值才能实施；需要后续固定的数值仅为原单次操作安全参数及精确传输契约。必要反例未通过前queryQualified=false。本稿确认也不自动授权开发、升级、部署或真实业务访问。
