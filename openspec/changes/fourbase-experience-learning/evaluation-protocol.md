# M6 可选增量验证协议

2026-11-04 · v0.1已整体批准 · 这是工程／专业评阅约定及原成果表达，不是Host分析流程，也不启动实验。

## 需要回答的问题

相同问题下，额外提供经验、方法说明或二者，是否改善判断、反证修订及使用负担，代价是否值得？先明确比较哪项增量，不预先承诺提升比例。

| 可选比较 | 共同条件 | 真正变化／限制 |
| --- | --- | --- |
| 原Agent基线 vs 仅记忆 | 同一任务问题、基础材料／准确版本、模型设置、权限、预算与主要环境 | 新增经验及其召回工具／实际上下文／延迟／成本；不是最终上下文完全相同 |
| 原Agent基线 vs 仅方法 | 同上 | 新增参考方法资产及其实际可用性／版本；不强制Agent执行某方法，不自动安装skill |
| 必要时再看组合 | 同上 | 同时提供已固定的经验与方法，仅可称组合差异，不把全部收益归给一项 |

没有适用的方法候选时方法组未运行；四种组合不是产品必跑步骤。可选通用证据提醒只作诊断，不增加强制第三组。

## 共同基线及干净起点

复用原任务创建、配置快照、项目文件、固定资料／成果引用和Pi原生执行记录。各组使用新任务的干净会话起点；同一旧会话继续提问不能伪装独立基线。任务创建只建立草稿，普通发送才开始Agent。实际模型／Provider／协议／线路、reasoning／thinking、contextWindow／maxTokens与限制以运行时真实配置为准，不能仅凭名称相同。

固定共同问题与材料身份／版本、可用权限与预算，列明额外资产／工具。新任务仍可能通过工作区、skills或既有查找读到候选；在可审计范围核对实际native调用及交付，包括可能泄露答案的目录标题／摘要、片段、全文和历史消息，而不只检查一次正文读取。接触到候选答案、组间基础材料／权限／配置不一致、费用或输入限制不可核，均如实记录。无法证明可比就记“本轮不能归因／待验证”，不以Host禁工具、固定方法配额或伪造无污染来得到好成绩。若需要额外隔离环境，应先另定最小范围，而不是暗改普通profile。

## 原报告中的最少逻辑栏目

沿原Markdown报告，不另建持久评估实体或要求用户填写机器字段：

1. 问题／比较因素、共同材料与准确来源、真实已知配置／权限／预算及未知。
2. 实际各组与相对差异，包括没有运行的组及理由、输入／上下文是否可比。
3. 每次原任务／native／固定成果的准确引用，首次、重复、取消、失败与UNKNOWN原样保留；修订报告另存新稿，不能覆盖最初结果。
4. 业务评阅：事实错误、无依据因果、冲突／约束、方案可行性、反证修订、用户维护及介入负担；定性尺度须有定义和实例，能隐去候选名称时做盲评。
5. 技术观察：来源可回读、计算产物／口径、恢复表现、实际延迟和成本。SDK估计／实际用量／供应商结算分开，缺数据保持未知，不填0。
6. 结论与局限：改善／无增益／退化或不可归因，适用范围、失败和未解释差异；可缩减、不采用或继续待验证。

正文是作者／评阅者的表达，不因报告保存成功就被Host认证。固定共同输入与结果引用优先用现有M2成果／M3修订／M4原生／M5准确来源。没有可回读的旧字节时说明缺口，不以hash、同名文件或最新报告替代。原始证据留在获准位置，不因整理报告删除。

## 何时能够说什么

| 证据 | 允许结论 |
| --- | --- |
| 合成输入、loopback Provider与实际产品工具／保存／UI | 只证明该工程接缝及保全行为，不证明语义召回、专业推理或业务成熟 |
| 固定真实模型及合成业务材料、独立专业评阅 | 仅证明该任务／配置／候选范围的专业表现，不自动证明真实经营效果 |
| 获准真实事项与后续真实反馈 | 在对象／时间／执行及比较条件明确后评估业务适用；仍不凭单次改善宣称因果 |

伪造来源／数值、越权动作或静默覆盖历史阻断相关候选通过。其他门槛在取得基线后确定；不得选看到结果后的门槛再称预先设计。看过结果后修改候选，重新准备未见变体，旧失败仍保留。

真实Provider／模型、业务材料、费用和经营动作沿有效授权；“继续M6”或确认本协议不默认启动它们。产品普通任务可以照常工作，评估与真实试点分别记录，不把它们设为所有分析的前置。
