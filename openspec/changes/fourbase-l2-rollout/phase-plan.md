## 0. 首个场景和首批建设范围

**推荐 SC-01：线下直营可比门店，两期零售额同口径拆解与核查决策。**先核是否下降、成交与退款各影响多少金额，再支持人选择先核交易端、退款端或补证／观察。具体匿名门店集合、两个等长已结束期间、真实金额与反馈安排仍待指认，不断言企业已经发生下降。

- **SAP：**首批3个核心指标（终端成交额、零售退款额、零售额）和1份新整理参考方法；沿已有发布／项目准入，不以候选摘录代替正式版本。
- **本体：**除核心概念与版本，还表达匿名范围、业务时间／数据截止与成熟度、单位／粒度、方法条件、字段角色、来源及未知／冲突。
- **图谱：**将准确依赖、适用条件、字段映射及脱敏来源组织为可查读关系，按需连到原 Case／反馈／经验，不逐笔搬经营数据或建企业主体网络。
- **分界：**GMV 独立辨义；零售量的定义歧义先解决，市值／折扣随依赖暂缓；客单价在渠道与分母等条件成立后扩展。这不缩减完整 L2 的能力方向。

完整的建设清单、查询题面与数据缺口见[首场景范围](scenario-scope.md)。退款额源摘要写按订单支付时间，不能沿旧 Demo 的虚构退款登记月规则；跨期回补、截数与观察成熟度仍待核。

## 1. 全部阶段共同指向的结果

1. Semantica 在约定的 OptraCall 环境真正采用，Pi Agent 可查询和使用，重开、刷新、维护及停用有证据。
2. 首个服饰零售 Case 必需的 SAP 指标／方法、背景与数据映射、小范围本体和有来源知识图谱实际可用。
3. 首个真实分析决策 Case 留下人的决定、真实后续、反馈和复盘。没有反馈时保持开放。

完整 L2 的主要价值是后台语义支撑：帮助 Agent 理解概念、对象、范围、规则与关系并用于分析。来源、时间、引用及前端解释为其服务。六阶段是工程／业务交付安排，不是 Host 强制 Agent 逐步执行的分析流程。

## 3. 各阶段实施边界与退出证据

### S1：把首个问题和复用底座说清

- 首场景题面采用 SC-01 的同口径金额拆解与核查决策建议；实际线下直营匿名集合、两期及反馈安排仍需指认。促销不作为首场景默认决策，真实是否下降由经营数据核定。
- 重新核定届时实施基线与实际运行版本；原准备树`57742b9…`保留历史；已实施工程底座为`2b9800bc…`加本地L2变更，D16固定候选见原回执，均不代表届时main／正式运行。S1已核方法复用，后续沿现有保存、发布和准确版本规则，不重写方法系统。
- 以已获准去标识摘录盘点3核心、GMV辨义及扩展限制，核准确发布版与项目启用、实际输入及说明、背景、RAP／Case／经验，列“现成可用／需补齐／未知”。不迁入真实主体信息或先填完整行业库。
- 形成最小来源集合、维护分工、运行环境与数据出口／模型范围、业务反馈安排；汇总不能由已有依据解决的实质歧义，不让普通用户选择技术参数。

退出：SC-01 实际对象／期间／准入和缺口清单可核对，必要的币种／税口径、退款类型／去重、跨期回补／截数／成熟度及字段映射有依据；经营材料、模型及环境权限明确。现有脱敏候选、已发布的隔离场景资产与合成输入不代替真实经营事实；真实材料与反馈缺口按spec第8节保持开放，Demo不代填。缺项只阻止依赖它的后续，可继续不依赖它的方案与合成工程准备。

### S2：先证明选定后台路径可用

- 以既有固定发行研究为候选依据，验证兼容 Python、必要模块与依赖，不默认安装全量 extras、图数据库、embedding 或额外 LLM。
- 围绕 SC-01 核概念／准确版本、金额依赖、匿名范围、支付归属与截数、字段映射、条件未满足及回源；不得只测关系连通。图查询、规则推导、SHACL 与 OWL 分别报告。
- 用脱敏实义材料核GMV／成交额区别、金额依赖、未知截数、别称冲突；必要异常再用明确标注的合成反例，不能制造经营真值。构建→保存→重开→查询→源修订／撤回→刷新／重建，不能只测 JSON 解析。
- 选一个明确的数据发布／装载／刷新路径；先验证原生能力，缺口确立后才做最小适配。多个组件／进程指同一 JSON 不当作一致性方案。
- 准备并确认适用的持久结构、查询合同及生命周期决定，再写入新结构；不据虚构示例冻结正式本体。

退出：固定环境与组件结果、能力缺口／选择理由、往返及失败证据、适用结构决定。旧[来源／时间 P1](../fourbase-l2-temporal-projection/spec.md)的合成探针在这里复用并扩充到语义需要，原结果／未运行状态保留；它不再是整体交付终点。

### S3：真正建成首场景所需语义资产

- SAP 目标为3核心指标＋1份“同口径零售额变动拆解与核查”方法，先复用准确发布版并补齐缺口。方法是本次整理候选，非原字典已给完整方法；保存不等于发布，发布后核项目可用性。方法条件供自主参考，不是 Host 执行计划。
- 明确本场景概念、业务对象身份、适用范围、粒度、单位、规则来源与关系方向；分开类型、指标／方法的具体版本、企业对象、带源声明及 RAP 任务假设。
- SAP、数据字段映射、已有显式引用优先确定性映射；背景文档的候选抽取保留位置、来源性质和不确定性。额外模型路径只有确需且获准才启用。
- 按[本体／图范围及6类查询](scenario-scope.md)建图并回源：GMV不混同成交额、支付归属不混同截数、字段不混同概念、要求不混同已满足；数量歧义及扩展状态保留。原始经营明细留原计算路径。
- 核从源重建、保存重开、查询保真、约束负例与源更新；语义错误修正其原权威或映射，不直接改图里的“正式公式”另造权威。

退出：V402／V403 的内容证据与代表查询结果齐全；仍需 S5 检查真实 Agent 是否正确使用。必要词表、关系和字段因实际 Case 收敛，不预设固定节点数或完整行业分类。

### S4：接入原任务，不增加一套工作方式

- 沿普通项目任务的真实 owner、现有统一会话和显式 MCP／业务 port 接线；选一条满足来源及准入的最小主路径。
- 必要语义及来源进入模型可见 content；界面 details 只作补充。保留实际数据版本、查询和结果边界，不用当前启用列表伪造历史采用。
- 覆盖权限变化、配置变化、取消、迟到结果、重开、刷新、输出限制、失败回源及已有消费者回归。普通任务接入不扩权专用 profile。
- 前端仅原回答与可选依据中的必要差额；解释重要口径／冲突／未知是 Agent 回答目标，不由 Host 硬拼分析结论。

退出：工程检查和全新非作者复核有证据；UI 审核与实现验证分开。此时仍可只有合成演练，不能填成 S5 已上线／真实分析。
