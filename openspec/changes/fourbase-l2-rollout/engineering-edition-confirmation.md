## 2. Semantica与Agent的责任

Semantica通过本体与知识图谱组织可复用业务语义，帮助Agent找准**定义、方法前提、适用范围和来源**。Agent自主执行包括自主调用Semantica、计算和复核工具，并复用适用结果，**不要求LLM每次从头推理、重建关联或重算已有结果**。

| 产品原则 | 本包细化 |
| --- | --- |
| Host管环境 | 接通Semantica，管理权限、来源准入、资源、生命周期、版本和保存；业务结论由Agent判断 |
| Agent自主执行 | 自主选择查图、回源、计算或复核，复用结果、解释判断和修正错误；数值／文字一致性、条件能否支持结论可委托适用工具验证 |
| 优先复用Pi | 工具／扩展沿统一Pi接入，会话、工具调用、上下文及恢复保持原机制 |
| 减少人的操作 | 普通用户表达目标、提供资料；授权内的查口径、适用性判断与纠错由Agent完成，人的真实取舍沿原入口 |

没有每题强制查图、固定核查顺序或Host业务裁判；语义结果和计算结果需要适用于当前问题，也不以一次检索／约束通过替代正确结论。

## 4. S6最小范围

1. 一个首Case与固定成果／定义／条件的准确引用，复用原Case、判断和策略修订。
2. 人的取舍、获准行动／补证／观察及理由，复用原Case／Board和历史。
3. 对应反馈关联原分析事项，复用原Feedback修订与handoff进入同项目的新普通任务；另存和需求草稿沿原入口。
4. Agent在该普通任务复盘，原分析会话保持；复用语义与计算工具，必要修订和少量经验沿原资产、候选、保留与归档入口。
5. 补齐已有维护说明中的责任人、更新／撤回／刷新、失败与停用回L1路径。

这些是最小业务范围，**不预设都要新增开发**。本次已核固定候选的实际工具资格和引用接缝，未发现必要产品差额；固定L2附件、Case、人工行动／准确反馈及经验候选沿既有入口完成合成组合核对。已有Case只读／草案工具不代作人的选择，Board／反馈写API未自动授予Agent，受管任务权限未扩大。没有新增schema、页面、Store、Agent或服务。

S6本次只核工程接缝：反馈沿原handoff进入新普通任务并准确关联原分析，原会话保持；图查询的partial／source-validation-gap随固定附件保留，不冒称语义全ready或专业正确。原V405仍需真实决定、实际后续、反馈和复盘。拒绝建议、失败或无改善可以诚实闭环；无反馈保持开放，不抵销S5专业FAIL，也不强制第二真实Case。
