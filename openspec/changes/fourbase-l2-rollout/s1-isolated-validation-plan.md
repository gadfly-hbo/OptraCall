## 2. 装载、持久与查询的单一路径

1. **构建侧先走Python原生API。**用脱敏定义、范围／单位／时间条件、字段角色及已知歧义构造小范围语义输入；完整经营明细仍留合成input，不逐笔搬进图。暂存图身份明确为工程候选，不伪造正式SAP发布Ref。
2. **存储侧先验证ContextGraph原生JSON往返。**单个工程构建者输出一个可识别版本，原生加载后比较身份、方向、条件、来源、未知与平行声明。每次输出新版本，旧输入／快照保留；先核既有格式兼容，不先造转换平台或图数据库。
3. **查询侧先验证现成stdio MCP的query_graph。**仅由工程客户端对该run合成图调用必要读取，不把官方server当默认只读或接入产品。官方含写工具的事实仍保留，当前测试不调用它们，不声称已完成产品授权过滤。
4. **刷新采用显式关闭、重载新版本。**测试先读v1、发布v2、关闭当前客户端／子进程，再明确加载v2；记录更新前后身份及旧引用。原生缓存和多入口不共享的限制未被“同指JSON”消除，不建Explorer／MCP／REST并发写同一文件的方案。
5. **主路径选择由证据决定。**若原生查询不能保留准确来源、条件、字段或必要本体查询，记录缺口，后续S4沿既有semanticContext port薄适配Python能力；不同时叠两套产品机制，不另建Runtime／语义主库。

GraphBuilder将明确采用不自动实体合并／不自动冲突覆盖的设置候选，并核是否实际生效；API不支持时记能力差额，不退回静默合并。单例核心概念不能被默认词频过滤后仍记通过。OntologyValidator的通用valid不作完整规则／OWL证明；真实SHACL需非空target和违规负例。

## 3. S2验证清单与判据

下列是工程验收覆盖，未规定产品Agent每轮的工具顺序。当前状态全部NOT_RUN。

| 编号 | 验证对象与可观察判据 | 失败反例／限制 |
| --- | --- | --- |
| E01 环境与来源 | 固定解释器、组件／依赖身份、输入hash可核，导入所需模块及构建路径可用 | 下载／导入成功不证明语义可用；不为凑通过启用模型／服务 |
| E02 本体语义表达 | 核心概念与准确版本角色分开；GMV区别、范围／单位、支付归属／截数、方法条件、字段角色和未知均能表达 | 不能只得到3个指标名；单例被丢、条件被抹平或候选被标正式发布即失败 |
| E03 构图与往返 | 原生构建→保存→关闭→重开→查询，身份、关系方向、源位置、性质和未知逐项保真；从同源重建可对照 | JSON能解析、节点数量一样不算语义保真；不覆盖同名／相反声明 |
| E04 查询覆盖 | 原生接口取得SC-01的6类相关语义和脱敏依据；保留C03支付归属、C04依赖、数量歧义及对扩展的影响 | keyword命中不算正确适用／完整GraphRAG；原生接口不足必须如实记录，不预写可接Pi |
| E05 真实约束路径 | 用实际RDF及SHACL，正例确实命中目标、违规负例被检出；选源身份／必要关系等有依据的最小约束 | 零target、空shape、placeholder valid或图路径不证明约束执行；未知条件不能被检查器补成已满足 |
| E06 刷新／失效 | v1／v2显式装载、源撤回和损坏路径可核；旧版回执与准确引用保持，失败不静默用当前版代旧版 | 多进程共指文件不证明同步；失权／撤回源不能供新查询，旧历史按原合同保留 |
| E07 协议与停止 | initialize／tools-list／读取调用及有界结果；记录错误、请求取消、关闭stdio、子进程实际退出及迟到结果 | 取消不等于退出或回滚；超时／清理不明记UNKNOWN，不盲重放有副作用动作 |
| E08 数值与语义职责 | 字段／依赖查询与SC-01S独立数值参考分别核：核心金额、跨期退款、门店上升反例可解释 | 工程Python算对不写成Semantica已分析正确；S2无真实模型，不计V404／V405 |

工程读取调用初始采用单次30秒期限，单次停止观察10秒；超过记TIMEOUT／UNKNOWN并停止本run继续派发，保留现场，不扩成全局进程清理或产品分析时限。该期限仅约束组件探针，不限制未来Agent的分析方法或总工具次数。

## 4. 证据、职责和后续接入

每run记录实际解释器／依赖、组件版本、输入／图版本、调用参数与有界结果、原始失败、实际约束执行者、目标命中、时间／资源及停止结果。Semantica原生行为、工程核对与未来Agent专业采用分别报告；不把工程适配补出的结果说成组件原生能力。

工程在其已获准环境执行并维护；Host／Agent／公共Pi接线继续沿原project-tasks／真实owner、Pi1.4.0／Interface v3。S2不新增产品profile、不注册生产MCP、不发模型消息；S4再验证准入、模型可见content、取消／迟到和原source保存接缝。实际字段／持久结构变更仍先按已确认范围与适用决定收敛，不由工程探针格式自动晋升生产合同。
