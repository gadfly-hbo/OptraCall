## 既有能力与引用方式

| 接缝 | 复用及实际边界 |
| --- | --- |
| L2→固定成果 | Agent按需用`read_semantic_context`取得指标定义、准确方法与条件，用原Pi文件工具产出报告／依据附件，再用`record_analysis_sources`沿原M2冻结准确字节、hash和来源声明。保存不证明实际正确采用 |
| 固定成果→Case | 原`citation`报告／附件引用进入Case修订；附件可保留图快照、原sourceRefs、方法版本／publishedHash、条件、限制及partial／gaps。Case不需要新增Graph目标类型。`sourceHandle`与查询cursor是临时传输身份，不能作为长期业务引用 |
| Case→人的决定／行动 | Agent只起草和查读。人的取舍沿原Case选择；Board采纳、行动状态及反馈沿人的原入口保存，记录对应修订和理由。API存在不代表已授予Agent执行权 |
| 固定反馈→原分析事项复盘 | 原Feedback修订／preview／handoff保留准确反馈及观察范围，回到同一项目的**新普通任务**；原分析会话保留。没有把“返回原分析事项”写成自动续写旧会话或改写原稿 |
| 复盘→候选／保留／召回 | 普通Agent可用`read_case_sources`读取准确Case修订、人的选择及该修订引用的原附件，并自主记录候选；沿既有个人资料流程选择保留。候选不是正式经验，保留也不证明因果或效果 |
| 维护 | 更新／撤回／刷新、加载失败、关闭及移除binding后回L1沿[S5维护交接](s5-engineering-handoff.md#已有入口与维护顺序)，没有新增维护控制台 |

接口继续为Pi1.4.0／Interface v3、原`project-tasks`的真实projectId／taskId／request／operation。现有普通非托管任务与托管任务的工具资格不同：托管普通主任务可获原图只读能力，**不会因此获得Case草案、跨Case经验及候选工具**。本次不放宽这条边界；组合验证覆盖已有非托管普通任务入口。正式采用时仍须核定目标环境的模型配置、显式图绑定及任务路由；不会因安装Semantica而自动接通全部已有任务。
