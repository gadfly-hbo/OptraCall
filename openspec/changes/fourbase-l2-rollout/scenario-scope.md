# 首个服饰零售场景与语义建设范围

v0.2 · 2026-11-05 · SC-01 推荐方案，待整体确认；未开发／未发布／未建图

本包沿[完整 spec](spec.md)与[六阶段计划](phase-plan.md)推进完整 v0.4，首场景控制首次建设规模，不取代其完整产品能力。[候选指标资料](data/metric-candidates.v0.1.json)来自已获准的去标识整理；原企业工作簿不进入仓库、Demo、建图输入或 Agent 工具结果。

## 1. 首场景和决策问题

**推荐 SC-01：线下直营可比门店，两期零售额同口径拆解与下一步核查决策。**

用户在原任务问：“这组门店两期零售额是否下降？终端成交额和退款额的变化分别影响多少金额？我应该先核交易端、退款端，还是先补证？”

本包推荐单一线下直营口径、同一匿名可比门店集合、两个等长且已结束的统计期间。具体门店代号、日期、是否真的下降、数据、责任人及反馈窗口尚未指认，S1 从实际材料收敛；不虚构某企业、某月已经发生下降。若真实可用材料需要变更渠道或可比规则，补充受影响范围再采用，不静默跨渠道套用。

“先查交易端／先查退款端／补证或观察”是待人选择的核查方向，不是 Host 自动路由；Agent 可以提出其他有依据的解释与建议。促销收益与经营根因不属于这次三个金额指标可以直接证明的结果。仍可形成实际业务决定、核查／补证行动、结果和复盘，不要求用促销动作凑闭环。

## 2. 已有材料与脱敏边界

- 已有依据：去标识候选源 `SRC-METRIC-01 / r1`，包含8个通用指标的摘要、文字公式、适用限制与源单元格定位。源字典有944条记录、44字段；它是指标目录，相关结果栏的勾选不提供真实经营数值。
- 姓名、公司／品牌／平台真实名称、部门／人员归属、原企业业务编码及版本标识不提取。通用维度词“品牌”和匿名对象类别不表示导入真实主体名单。匿名代号不能是可反查名称的可逆拼写或原编码。
- 具体主体特例未迁入时保留“存在未核适用限制”，不能删掉主体后改成全域通用规则。发布前确认选定匿名范围是否触及特例；若需要规则，只补不含主体身份且保持条件逻辑的说明，不自动读取或分发原件。
- 仓库只保存本次脱敏资料和方案；原件及其私人定位继续留在附件／获准本机范围。本包的数据版本是脱敏摘录修订，不冒充原企业发布版或已发布 SAP 版本。
- 图、模型可见 content、来源详情、日志和后续对照使用同一获准脱敏范围。查看依据只读该范围内的摘录或将来准确的 SAP 发布版，不提供打开企业原附件的隐性入口。需要额外材料时先按原权限准入。

## 3. SAP 建设清单

这里的 SAP 是 OptraCall 的分析资产。下表是内容建设范围，不是新增资产类型或已创建／发布实例。

| 候选 | 首场景角色 | 需要建设与验证什么 | 采用边界 |
| --- | --- | --- | --- |
| C02 终端成交额 | 核心指标1 | 退款前成交金额、直营范围、订单支付时间、维度／粒度／单位及实际字段映射 | 源特殊业务／渠道归属条件须核齐；不能与 GMV 因名称近似直接合并 |
| C03 零售退款额 | 核心指标2 | 退款类型边界、按订单支付时间归属、金额符号、去重及截数／回补条件 | 脱敏源未给跨期回补和观察成熟度规则；不能沿旧虚构 Demo 的退款登记月定义 |
| C04 零售额 | 核心指标3 | `终端成交额 − 零售退款额`、别称、同范围／同粒度／同币种和税口径、准确依赖 | 只存减法不够；正式定义关联准确的两个核心发布版本 |
| C01 GMV | 辨义参考 | 保留独立概念、来源及适用限制，回答为何不能默认等同终端成交额／零售额 | 本批不作为核心计算输入；特殊条件未齐时不发布为已可执行指标 |
| C05 零售量 | 暂缓计算采用 | 保留候选及其依赖定义歧义：被引用数量是否已扣退货尚需核 | 不将歧义改写为确定公式；不据此算数量贡献 |
| C06 零售市值、C07 零售折扣 | 随依赖暂缓 | 先解决 C05、商品吊牌价及商品粒度／加总方式，后核比值及除零条件 | 不先发布为首 Case 可执行指标，也不以其估计促销收益 |
| C08 客单价 | 有条件扩展 | 分开渠道及分母；线下订单数与电商买家数不同，需时间／去重／字段 | 不作为首 Case 必做或先建全量渠道模型的理由 |
| MTH-01 同口径零售额变动拆解与核查 | 首批1份参考方法候选 | 用途、输入、可比条件、金额分解、独立核对、局限、补证／反馈及来源 | 本次根据指标与分析需求新整理，非声称原字典已有完整方法；供 Agent 自主选择／调整 |

首批交付目标为 **3个必要指标＋1份参考方法** 的可参考发布版及项目准入。若已有准确资产就复用，不另建同义包。保存先为未发布，成功发布后才可供后续任务参考，IR／手工／提取来源一致；当前候选资料不算已发布、项目可用或正确采用。

这里的3指标／1方法是内容数量，发布和引用沿既有 SAP 包／方法资产的粒度；指标可复用同一包的准确发布版本及包内指标身份，不要求三个独立发布物，也不新增逐指标发布或版本机制。后续方法模块先核实施基线再复用，不据本树缺项重建一套。

方法可参考下列金额关系，不固定 Agent 的工具或执行顺序：

```text
期间A：N_A = T_A - R_A
期间B：N_B = T_B - R_B
变化： ΔN = (T_B - T_A) - (R_B - R_A)
成交项金额变化 = ΔT；退款项金额影响 = -ΔR
```

其中 N／T／R 分别代表零售额／终端成交额／退款额。这是同口径下的金额恒等分解，不证明退款或成交变化的经营根因及因果。首 Case 默认交付金额拆解，不强制计算贡献比例；净变化为零或两项方向相反时不能套一个默认百分比。

如有独立源零售额／控制合计，核其与构成项是否一致；没有时明确“净额为本次派生计算，尚无独立源净额对照”。由同一减法再算出的零残差不能证明原始金额或业务口径正确。

## 4. 小本体建设范围

本体要让 Agent 区分“是什么、适用于哪里、依赖什么、缺什么条件”；不只定义几条连接线。下表为拟议逻辑角色，具体类名／属性／字段及物理表示在适用结构决定中收敛，不据此创建 schema。

| 逻辑角色／粒度 | 首批表达内容 | 身份与权威 |
| --- | --- | --- |
| 指标概念 | 3个核心概念、GMV 辨义、其余4个候选的未就绪原因及别称 | 概念不等于具体公式发布版；名称／别称只供发现，不自动合并 |
| 指标／方法准确版本 | 核心定义、参考方法的范围／条件／局限及准确依赖 | SAP 原发布权威；源摘录 r1 与 SAP 发布版分开 |
| 匿名业务范围 | 单一线下直营口径、可比门店集合；必要时匿名对象和维度类别 | 从实际获准材料映射，不预填真实门店、品牌、公司或关系 |
| 时间及可比条件 | 订单支付归属、两个业务期间、数据截止／刷新、退款观察成熟度、单位／币种／税口径和粒度 | 已知与待核分开；源时间字段不自动变完整历史有效区间 |
| 字段与输入说明 | 固定输入／说明版本、字段角色到概念／SAP 的映射，争议及来源 | M2 原权威，原始经营明细仍在文件／计算路径 |
| 带源知识声明 | 定义摘要、业务条件、来源定位、支持／反对、未知及推导性质 | 脱敏整理／原声明／本次推导区分，删除私名不增加真实性 |
| Case 判断、方案及经验 | 本次报告的依据、核查备选、人的准确版本取舍、实际后续／反馈及经验 | 复用原 Case／Board／Feedback／个人保留；选择不等于执行／效果 |

必要约束包括：核心依赖的方向和身份正确；金额维度可比；未知币种／时间／截数不能默认为一致；不同口径别称并存；待核数量依赖不用于计算；准确引用在更新后不漂移；隐私／来源准入贯穿派生内容。规则检查发现问题交给 Agent 与必要责任人，不由 Host 裁决口径。

## 5. 知识图谱建设与查询

**首批图的内容边界：**从已准入的脱敏源、成功发布的必要 SAP、M2说明及已有 Case 接缝确定性映射，必要文本只作有来源候选；不摄入944条全部指标、不导入所有经营明细，不建立真实人员／公司／品牌网络。

| 关系含义 | 方向及限制 |
| --- | --- |
| 概念由准确版本表达 | 具体发布版 → 指标／方法概念；保留多个版本，不用当前版改写旧引用 |
| 公式或方法依赖 | 零售额发布版 → 成交额／退款额准确版；方法版 → 所需指标及条件，不能变成强制执行计划 |
| 适用／要求／尚未满足 | 定义或方法版 → 匿名范围／粒度／单位／时间条件；已证、未证与未知分开，不把“要求”写成“已满足” |
| 字段映射及回源 | 固定输入说明 → 字段角色 → 概念／SAP；各声明 → 脱敏源修订／位置，不从名称猜已读或已采用 |
| 区分、别称与冲突 | 概念／声明之间保留别称、差异与相反依据；GMV不能默认并入成交额，歧义不被自动覆盖 |
| 结果和经验依据 | 原成果／Case／反馈 → 实际声明依据及限制；不新增 Case 直接 SAP target，可沿成果引用的 sapRefs 回源 |

上述是关系语义而非生产枚举。S2 核所需原生表示、保存加载与查询是否保真；S3 用相同逻辑范围建设实际图，源更新后核刷新／重建和访问变化，原权威不因入图被替换。

首批语义检索至少能支撑以下问法，并将必要定义／条件／来源带入 Pi 的模型可见 content：

1. 零售额与 GMV／终端成交额分别是什么，为何不能直接互换？
2. 退款按哪个业务时间归属？截数和回补条件哪些已知、哪些还未知？
3. 本次匿名门店集合和两期数据能否采用该定义／方法，需要补什么证据？
4. 相关输入字段指向哪个准确定义，缺失或争议会影响哪些计算／判断？
5. 零售量为何尚不能用于市值／折扣分析？这是否影响核心三个金额指标？
6. 源或映射更新后，本次报告用了哪个版本，哪些后续判断需要复核？

这些问法是验收覆盖，不是要求每轮先查6次图或固定工具顺序。图查询、结构／条件检查、显式规则推导和经营因果分析分别取证，不宣称已经完成完整 OWL、GraphRAG 或自动业务推理。
