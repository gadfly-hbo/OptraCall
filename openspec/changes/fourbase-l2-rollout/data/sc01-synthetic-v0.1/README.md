# SC-01S 合成经营数据

2026-11-05 · 数据版本0.1 · 仅工程／分析演练材料

[input.json](input.json)全部对象、日期、金额、事件和控制合计均为人工合成。指标含义参考[获准去标识候选资料](../metric-candidates.v0.1.json)中的 C02终端成交额、C03零售退款额、C04零售额；样本条件是本次演练假设，不是企业正式规则或已发布SAP。

本轮没有读取企业原件或真实经营数据，没有生成真实姓名、公司／品牌／平台名称或人员归属。`SYN-`编号仅由本例顺序生成，不映射实际门店或原业务编码。

## 1. 范围和记录粒度

- 4家匿名合成直营门店、32条支付订单、16条退款事件，门店集合在两期不变。
- A：2026-09-01至2026-09-28；B：2026-10-01至2026-10-28，各28天，都是演练选定的已结束窗口，不标成完整自然月。
- 数据截止：2026-11-04 23:59:59，时区Asia/Shanghai。币种CNY，金额单位为元，全部整数；同一含税口径，不计算税率／毛利。
- 订单表一条为一笔有效支付，退款表一条为一笔退款事件。退款通过订单ID回到原支付日期，不能直接按退款发生日期归属期间。
- 本例只造支付后7日内、已进截止快照的退款，两期所有支付已完成该观察窗。此设定只为样本可核，不证明企业没有更晚退款或现实成熟度相同。

## 2. 字段与候选指标的关系

下列为人读字段路径，**不是已保存的M2映射、生产JSON Pointer合同或新增数据库schema**。将来导入沿既有M2固定输入和说明结构，具体定位再按实际文件版本建立。

| 字段路径 | 本例含义与使用边界 |
| --- | --- |
| `scope`、`periods` | 本例匿名范围、币种／单位／税口径、截止和两期窗口；均为合成设定 |
| `orders[].order_id`、`store_id` | 关联与分组用的合成身份，不是实际企业ID |
| `orders[].payment_time` | 支付日期，作为本例成交及关联退款的业务期间归属 |
| `orders[].gross_amount_yuan` | 退款前支付金额，范围核定后按支付期间合计，对应C02 |
| `refunds[].refund_id`、`order_id` | 唯一退款事件及其原订单；本例无重复，累计金额不超原支付 |
| `refunds[].refund_time` | 退款事件发生时间，供检查跨期／截止，不代替支付归属 |
| `refunds[].refund_kind`、`refund_amount_yuan` | 两种互不重复的样本退款事件类别及正金额，对应C03；其他退款类型本例为零，不代表现实不存在 |
| C04零售额 | 同一门店／支付期间的C02减C03；数据中未预填两期差额 |
| `synthetic_net_controls` | 同批合成的门店×期间净额控制数，供工程核对；不是真实独立报表／业务对账证据 |

两期退款事件均包含发生在业务支付窗口之后的记录，用于检验“支付归属”与“退款发生时间”是否被混淆。某合成门店净额上升，另有门店下降，不能由整体下降推定每家都下降。

## 3. 参考结果与评估隔离

[参考结果](../../evaluation/sc01-synthetic-v0.1.reference.json)保存金额合计和变化项，只用于工程核对，**不作为被评估Agent的业务输入或预置回答**。未来沿M2选材时，只选输入及获准定义／方法；不要将整个变更目录连同参考结果一并送入分析。

同源L1／L2比较使用相同输入、定义、合成条件、权限与模型实际配置。不能让L2独占样本解释或参考答案，也不能把已知造数结果当未见专业能力证明。

该样本不证明：真实企业是否下降、经营根因、真实促销／核查效果、完整类型覆盖、真实模型质量、Semantica可用或真实业务闭环。原v0.4的真实采用与反馈目标仍分别留待相应资料和运行证据。
