# L2 结构与接入决定边界

v0.2 · 2026-11-05 · SC-01推荐草案，未确认、未创建产品持久结构

关联：[总体 spec](spec.md)／[阶段计划](phase-plan.md)／[SC-01场景范围](scenario-scope.md)。这是 S1／S2 要收敛的完整问题范围和当前有依据的推荐；本轮已用[去标识候选源](data/metric-candidates.v0.1.json)明确场景、资产与逻辑角色，不是正式实体／字段／API 合同。实际输入映射与原生路径验证后，形成一次完整、可审阅的受影响结构决定，再实施新增产品持久结构或实质合同变化；材料 JSON 不构成生产 schema。

沿 agentharness-structure-grill 的结构检查方法，先核业务含义／粒度／身份／权威，再定字段与保存方式；不要求普通用户设计 SQL 或组件参数。已有业务结构及已确认决定直接复用，不重复审批。

## 1. 当前推荐

D01–D09、D11 为待整体确认的推荐，无例外授权；D10的脱敏限制是用户已明确要求，沿用而不重复询问。A 为推荐；B 是实际能力不满足时评估的替代，不要求用户逐项选择技术细节。

## 2. S1／S2 需要形成的具体合同

不能只批准上表概念就写入下列未定结构。形成结构决定时，每个适用对象和字段组一次列清推荐、原因、替代、实际源例子、用户决定及一致性；实质新变化补受影响项，未变部分沿用。

| 检查类别 | 提交内容／目前为何尚未冻结 |
| --- | --- |
| 业务、owner 和粒度 | 哪个原 Store 负责、表示一个类型／对象／准确版本／声明还是查询投影；先有真实源清单 |
| 字段／逻辑字段组 | 实际名称、含义、类型／格式、必填／可空、默认、值域／分类、单位和有源例子；原生组件格式不必另造一套，但需核映射不丢语义 |
| 身份和连接 | 稳定身份与源定位区别、业务键／去重依据、两端／方向／基数、拥有者与源撤回影响；不能以名称猜实体 |
| 时间和状态 | 已知／未知、业务有效／系统留存／更新、精度／时区；无新全局状态机，沿原业务状态投影 |
| 来源和构建 | 原件位置、准确版本／hash、声明性质、整理／推断区分、构建版本及可重建依据；哪些内容不得进图／模型 |
| 入口、约束和性能 | 获准读写入口及权限／错误／分页／限制；唯一性、必要索引、约束执行目标、正负例及回源；先核实际组件能力 |
| 并发、刷新和兼容 | 正在分析时采用哪个版本、更新后何时可见、损坏／中断／权限变化的行为、迁移／回退的数据影响；旧引用及消费者不被改写 |
| 跨源共同合同 | SAP／M2／企业／Case／个人资产之间的 ID、发布／引用规则及权限不被语义层扩大；不增加 Case 不支持的直接 SAP target，可沿成果引用中的 sapRefs 回源 |
| 阶段归属 | 新对象是主业务权威、支持结构还是派生 ReadModel；本轮只允许必要派生支撑，后续扩展不伪装成本轮必需 |

当前不新增 SQL 表／列／索引／迁移，不冻结服饰零售类名、枚举、实体编码、字段映射或部署目录。SC-01表格给出有业务依据的逻辑角色与关系含义，基数／格式／缺省／引用字段等在实际输入与组件路径确定后补受影响决定；不能以“待确认”名义省略本次已能确定的场景范围。S1／S2 合成探针也只在获准隔离位置写入，不把试验格式晋升生产合同。
