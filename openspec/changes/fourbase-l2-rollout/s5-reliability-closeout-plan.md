## 3. R0：定位与有限工程修正

### 3.1 信息先在哪一层丢失

按实际可观察路径核对：原发布定义／方法／M2条件 → 构图与资格检查 → 工具实际 content → Agent 实际阅读／调用 → 报告主张 → 核算、修订与复查。区分材料缺少规则、接缝未交付、模型未读／误用、评估不充分，不能先认定都是本体字段不足或模型能力问题。

当前静态复用核查有两条具体依据：

- `verification-sessions.ts`、`verification-context.ts` 与 `automatic-verification-context.ts` 已要求独立核算、未知、全文新增主张及作者可拒用错误意见。**再加同一句提示不算修复。**先核已交付内容／片段预算／完整文件定位是否足够，再决定最小业务 context 差额。
- `scripts/fourbase_l2/sc01s.py` 已将新信封 `conditions` 声明为 `synthetic-input /conditions` 的 Condition／requires 来源；`semantic-graph-authority.ts` 的该输入回源白名单目前只有 `/scope`、`/periods`、`/synthetic_assumptions`。由代码可推得 `/conditions` 会被拒，**尚未执行 source 查询复现，也不能把它认作上轮17个聚合 source-validation-gap 的根因**。

确认后，用全新公开合成 fixture 经原 builder→准确声明→原Host sourceHandle→source 实测；若复现，保留真实 RED 后，只补获准的准确语义片段路径。不得开放整个输入或 `/orders`、`/refunds` 明细，不放宽owner、声明、hash、当前来源资格、handle有效期或输出预算。负例覆盖未声明源、错owner、撤回、旧handle、非语义路径和明细路径。

逐一定位聚合来源警示的可核原因，区分“可用但有资格警示”与撤回／缺失／损坏。在原 gaps／source 回包等已有合同内保留安全、实际的资格说明；不能安全确定就保留 UNKNOWN／限制，不伪造 confirmed、不清 gap 凑 ready、不以本地hash代替来源资格。若确需新增持久字段／公开结构，先补受影响结构决定，不在本A中临时扩大。

### 3.2 语义资产和方法怎样补

先核届时实际发布方法与已启用版本，不把旧模板或索引当当前全文。必要修正用原保存→发布→项目准确启用，保留旧版、旧图与Ref；当前没有发布新版本。新内容只表达可复用业务规则和限制，不含旧样本答案、题号、具体金额或新未见gold。

重点是：固定截止快照与终局不同；时滞／暴露不直接证明成熟；两期未来比较保留两侧变量；有限支付／退款约束不能被忽略；税／币种兼容前提未成立时只限制受影响的比较。沿现有 Condition、claimKind／conditionState、时间／范围、来源、字段角色和方法内容表达，不预设新增本体类型／属性或另建规则执行器。

Agent 自主选择方法和代码计算；方法是参考，不变成 Host 的计算公式或固定分析顺序。必要的形式反例用于工程／专业回归，不作为模型必须逐步照做的流程。

### 3.3 原图查询与修订怎样验

| 反例 | 要观察的正确行为 | 不能偷换成的通过 |
|---|---|---|
| 有 continuation | 为判断所需自主续页，或把结论限于已返回子集并保留未穷尽说明 | 无条件强制全部读完；未续却声称全图完整 |
| complete=true 且有来源gap | 分页结束与来源资格分开，保留影响判断的警示 | 用分页完成、Ref／hash一致消掉gap |
| 未返回 confirmed 字段 | 只在原声明范围表述未确认／推断状态 | 把保存材料状态推广到所有图节点 |
| 查询为空 | 限于该query／type／当前范围无匹配，必要时自主换查法或回源 | 推成全图不存在某类知识 |
| 正确稿接受核算反馈 | 作者核对证据后可改、保持或反驳，新增重要主张也需核 | 强制采纳核算意见或删旧好稿 |

graph 工具仍只给原普通父任务；独立核算、修订、复查和子Agent不新增图资格。工具调用可以为零，零调用／无记录只能记未观察，不能补写采用或以此强制重跑。

## 5. 冻结：不是只固定Git SHA

在新未见首次真实请求前封存一个完整候选：

- 应用运行文件、配置适配、SDK及Node/Python依赖实际字节／模式／清单，包含已修的出站参数接缝；不跟latest、不补SDK私有patch。
- 3指标与1方法的业务版本／内容、准确发布／启用Ref、企业与M2合法来源、字段映射、建图程序／本体／各链快照及输入hash。
- 实际MiniMax provider／协议／原线路、revision映射、SDK有效thinking／context／maxTokens／compat；沿原default high，无暗中降档／fallback。
- 题面、合法材料、预定金额与全文重要主张核对标准、gold、原配对／首测重复身份和执行顺序，以及单链观察／关闭条件。

每链原Store生成新身份；跨链UUID／Ref可以不同，业务内容与准确身份映射清单必须固定。不能以UUID不同断言材料不等，也不能把业务差别当技术归一化删掉。代码作者不读新私有金额／gold，准备者不当最终评分员。

**R2启动后若发现必须改代码／资产／模型／评分标准的缺陷，停新派发并保留本批，不在本批换版续跑或重新拼pair。**该批不能再宣称完整固定候选收益；本包不自动启动第二个新未见批次。纯额度恢复且所有冻结身份未变时，可续原未启动项，不重跑已占额项。
