## 4. 独立环境、固定身份与原资产

### 4.1 新环境布局与归属

建议未来在本工作树 `.local/fourbase-l2-s5/<unique-run>/` 留固定输入／执行证据，实际独立运行根放在本机任务专属 `/private/tmp/optracall-s5-<unique-run>/`，避免普通SDK从嵌套仓库的工作目录继承工程AGENTS。两个根均非正式服务目录，运行根关闭后保留，非授权不清理；系统临时目录被外部清理时按固定清单重建新环境，不能宣称运行采用仍在。使用固定候选文件清单而非只写 base SHA；运行根共享只读 source 目录仅纳实际运行／构建代码与锁定依赖，排除 .git、.local、测试／参考答案、评估器／生成器、旧日志及含答案的 openspec／文档，不直接把当前整工作树当 codeRoot。

每条正式链、重复、开放冒烟和取消探针均使用独立的中性编号链根，分别拥有 dataRoot（含原模型配置／企业资料）、projectsRoot、原 M2／SAP／方法库、D12 派生根和日志／临时目录。不同链不能通过项目三目录、全局企业目录／正文／文件、配置根、原生记录、缓存或链接互读。只共享经过批准的固定只读应用代码／依赖／Python环境；不共享任何链的业务 Store。参考答案根独立且在所有允许根之外，目录名和 UUID 开工后记收据，不预造业务身份。

顺序运行一个原 createHost 实例：关闭上一链后用下一链的新根启动，不增加平行 Runtime 或全局生命周期账。使用独立 loopback 端口和 instanceId，先核占用，不停／替换其他实例。S5 的安装、构建、每链环境 HOME／TMPDIR、Pi资源目录和缓存均限定获准根；模型前检查实际context文件和skills／MCP清单，不自动加载原用户全局资源／工程AGENTS或评估资料。需要普通 SDK 测试的临时根同样放在任务专属系统临时目录，避免 S4 已证的祖先 AGENTS／.git 干扰。新环境重新安装原 package-lock；Python 沿已验证兼容基线准备，不自动跟 latest。Semantica0.7.0 wheel 原已核 SHA-256 为 faf27d6259ae813ddb44c5213e2f8867592f27e6e3d6b47cea10f1844513799f；依赖闭包重建、可获得性和安装结果在新环境实际核验，不能以回执常量当安装证据。

Host-only binding 继承 `{runRoot,snapshotId,python,codeRoot}`；projectId/taskId 来自真实原任务，启动器使用显式任务 allowlist。L1 对照 binding 为 undefined，L2 为明确快照；未知任务不授 graph。allowlist 必须在首次 /open 或 /messages 前填入，不能等到首次 graph 查询才补：原 agentOptions 在 ensureOpen 时决定是否注入 port，查询服务随后才捕获该 run 的准确 binding。模型及前端不能传根、UUID 或配置回调。没有新公共 schema、全局 current、权限目录、业务队列或并行 Runtime。工程配置只是选择已确认原语，不创造业务事实或用户模式。

### 4.3 构建、更新、停用

构建是工程维护操作，不是 Agent 的必做分析步骤。每链采用以下顺序：原 API 建 tasks:[] 的新项目和源资产（尚不建评估 task）→ 成功关闭该链 S5 Host／Store → 单一离线构建者按显式源码、原 Store 根、准确 Ref 和分析输入字节／hash 冻结9输入并构新 UUID → 原生保存、加载及准入正反例 → 用同链根启动最终 Host → 原 POST /projects/:id/tasks 创建第一个任务并由原 registerFresh 登记 → 取返回的真实 task.id 填可信 allowlist → 首次 /open／messages。L1无需构图，但同样按最终 Host 的新任务和独立根准入，取得同源合法材料。

不在维护前预建任务，也不在已有重启前任务的项目里加新任务冒充可信新起点：freshRegistered 是进程内状态，旧 writer／兄弟任务会影响 managed 准入。原 POST 仅保存任务并登记 fresh，不立即构造 Agent；以上顺序无需新 API、猜UUID或可信历史升级。复用原 S3 映射／D12布局，最小去除旧路径／receipt／输入硬编码，不增加在线建图代理或全库自动抽取。

一个 run 首次查询固定快照，后续不自动追新代。更新原源或映射后按相同步骤建新 UUID，旧输入／图／回执不改；新任务或明确新 run 采用指定新代。来源禁用、confirmed 方法问题或失权立即约束新查询／原文，不等重建。重启不恢复旧 managed owner 的可信起点：历史保留，正式 managed 评估新建原任务，不用旧 JSONL 标记升级资格。

停止等待原 Resource 的实际 job／子树／在途 authority 收尾；不能证明则 UNKNOWN、隔离原 owner，不重放任务。回退先停妥后选择兼容的固定候选／完整快照并重核当前源资格，或移除该任务 graph binding 继续有权 L1；不覆盖数据库／native 为旧备份，不静默切旧实例／latest，不扩大 L1 读取资格。

### 6.2 原 profile 与答案隔离

正式两臂统一用本机支持的、具有可信新起点的 managed ordinary 原任务，并**显式同设原自动核算开启、maxAuthorTurns=1、同一模型选择**。这只是本次对照条件，不更改产品默认；若本机不支持原受管能力则正式评估未开始，不退成 unmanaged 盲测。graph 仅供原普通父任务，原核算／修订／复查／子角色不新增 graph 权限。

原自动链可能引入冷读、对照、修订及复查的额外模型请求，均纳入预算与记录。主指标固定在首次主分析完成的准确报告／native；整条自动链另作次指标，不能用修后稿替首稿，也不能把核算改善称为核算 Agent 直接用了图。工程采集与独立评估不参与产品分析、补计算或决定模型该选何种方法。

私有答案／控制／评分材料及其他链的输入、报告、native和缓存必须在本链所有项目、全局企业资料目录／正文／文件、managed readRoots、Runtime／node_modules及依赖可读根之外；也不能经链接、旧附件、source pointer、公开计划／S1收尾金额等间接到达。各链不共用dataRoot／projectsRoot，不能凭“不同taskId／sessionId”宣称材料隔离。启动真实模型前，以既有受管工具作实际拒读／越界／跨链负例、同源材料正例并核完整允许根。仅“没放入附件”不构成隔离证明。污染或无法证明隔离的样本标为污染／UNKNOWN，不记合格盲测；保留首次执行，不删分母另挑好稿。

unmanaged 只做1对开放冒烟，验证真实模型在另一普通模式仍能查询、计算和保存；因为没有同等 OS 隔离，不加入未见专业对照。另1条 L2 取消探针沿原单任务 stop，保留实际 usage／迟到／退出证据；不拿取消稿评分为正确或合法未知。19次上限内不自动追加实验；失败后若需要新批次／新未见材料，另给结果和受影响范围。

### 6.3 同源比较和观察指标

两臂的差别仅为 graph 派生查询是否可用；计算工具、发布资产及合格语义材料同样可用。正式 managed 对照沿 D13 不新增旧 find／read／trace 或 record 权限：两臂均在原获准项目资料中取得同一份带准确来源的合法平面语义表示及索引，使用原可读文件工具；L2 再增加 graph。unmanaged 开放冒烟才沿原资格保留旧读动作。平面材料是本次冻结源的有源表示，不是新的业务权威；在途撤权／更新测试使用另份工程任务，不与该固定材料质量比较混合。不得给 L2 独享退款解释、字段关联、样本条件或参考答案。对于合法语义需要，Agent 可自主查询、组合工具、零调用或多次调用，不规定六操作的调用次数／顺序，不按专业分数在 Host 内自动重试／修稿。

分别报告：①工具实际交付内容；②报告采用／解释的可追溯证据；③全文重要命题是否正确。只有工具成功不能证明采用；零调用也不强迫补调用，应记“提供 L2 能力”条件下的表现及本次使用未证。native 的嵌套结果缺失按 UNKNOWN，不推测没读／已读。

评价既核预设关键命题，也核报告新增的重要主张：数值、单位／范围、时间归属、依赖、冲突、未知与建议边界。独立评估人员在运行时之外核数、阅读全文及可得过程，先以中性ID冻结评分，再揭两臂；争议保留理由。不向被评模型提供私有核对结果，原自动核算与该独立评价分开。

预注册结论分三层：工程可用、合成专业质量、L2相对收益。合成专业“本题集通过”要求 L2 六个首次样本均无重要错误、正确保留必要 unknown／条件；未交付／污染／缺关键证据不算通过。4条额外重复为 L1／L2 各2条，不提升首次分母；两臂均按6个首次＋2个重复报告。若任何重要错误保留 FAIL／部分通过，不以核心公式正确抵销。

收益按每题配对比较首稿和整链的实际交付率、重要错误、语义采用证据、时延、模型 input/output/cache usage、请求／工具次数和可核费用。记录图初建、每个变体重建、维护更新及人工成本；两臂共同的实验环境／材料准备另记，L2构图不伪加到L1自然运行成本，先完成两臂共同准备再测主分析／整链时延。小样本只作描述，不给泛化准确率／显著性或“L2必然更快更准”。L1 同样正确时可以比较效率；结果不稳、无差别或退化都如实交付，不能用速度抵销重要错误。
