# Studio 企业基础层三类资产协同建设规格

版本 v0.1 · 2026-11-12 · 审核候选，暂不开发

用户已认可三类资产同步建设的方向，现授权保留 v0.1、更新方案和四份模板，并准备本规格、可点击 UI Demo 与目标任务清单供审核。该授权不表示本规格或 Demo 已批准，也不启动产品实施、真实企业内化、模型实验、Git 交付或运行采用。

## 1. 目标与审核包

让 Agent 根据通用行业／领域、标杆公开参考及目标企业获准资料，同步建设企业基础层的**主数据模型、数据分析指标体系、本体及三者关联**，可按准确版本核查、发布、由普通 Pi Agent 使用，并在任务演进中修订。基础层先覆盖约定的企业与领域知识范围，不绑定某一道首购复购分析题。

- [新版方案及四模板](../../../docs/reference-templates/v0.2/README.md)：v0.2，参考与方案草稿。
- [可点击 UI Demo](../../../docs/prototypes/studio-foundation-v0.2/index.html)：虚构资料及本地交互，不调用 Host、模型或正式库。
- [交互状态与验收对应](interaction-states.md)、[目标任务清单](tasks.md)。
- [旧稿保全基线](baseline-manifest.json)：冻结旧四模板、来源研究、v0.1 调整稿及既有方案／清单；新稿独立保存。

当前审核三项：三类成果与两条路线的覆盖、最小内容契约与工具复用、界面和异常恢复路径。企业实际规则、真实数据映射和模型业务结果仍需后续材料与执行证据。

## 2. 建设内容与边界

两条路线保持：运动鞋服行业 → Nike 企业公开参考 → 目标企业；会员运营领域 → Nike 会员运营公开参考 → 目标部门／业务域。每一站都包含三类内容，共享对象通过准确身份连接。Nike 会员运营指公开可见功能域，内部部门、字段、身份算法及未公开 KPI 不填成事实。

三类成果并列且互相校验：主数据提供对象、标识、属性、粒度及值域；指标体系表达主题／指标族、用途、定义、分析条件和关系；本体表达对象、事件、关系及规则。基础对象可因经营本身需要而保留，不要求每个对象先被某个指标引用。

产品仍为“企业基础层＋任务演进层”。行业与标杆参考是建设输入，不新增第三层正式企业资产。提前建设及任务贡献共用原项目任务与统一 Pi 会话；企业资产身份独立于某一建设任务是否归档。

本增量覆盖最少结构约定、逐项引用与内化差异、联合核查、原 Studio 的必要展示及普通读取。完整 MDM 黄金记录治理、批量身份归并与分发、拖拽 OWL 编辑器、指标执行引擎、新发布中心、新 Runtime 和 SDK 升级均不作为本轮前提。文稿资产和未知项继续可保存，不强行形式化全部经营知识。

### 修改范围

本轮仅允许新增本变更目录、`docs/reference-templates/v0.2/` 及 `docs/prototypes/studio-foundation-v0.2/` 的审核材料。基线清单所列旧文件只读保全；不修改 `src/`、`extensions/`、`scripts/`、产品测试、依赖或正式运行目录。

未来获准实施的预期影响集中在原 Studio 的 contracts／store、Host 接缝与 UI、原 `studio_assets` 工具的内容解释，以及相应检查。三类资产内容解析放在 OptraCall 自有薄适配中；M2、SAP 指标与方法保留原权威及公开合同，因明确接缝需要修改时应在对应实施项列出实际差额。未来实施不以本规格自动取得 SDK、真实企业资料、服务或设备权限。

## 4. 内容与关联契约草案

### 4.1 沿原源资产保存

优先将可识别内容序列化在原 body，原资产 ID、修订、来源、依赖和哈希继续由原 Store 管理。该内容的解析结果是原正文的投影，不能成为另一份可独立修改的权威。旧纯文本及其他未采用此约定的资产保持原准确读取、编辑为候选和历史行为，不静默重写为新格式。

拟用一个显式版本化内容 profile 表示必要结构，名称和字段作为本次待审草案；实施前按现有合同做最小兼容核对。未知 profile 保持可读并说明结构检查未支持，不以未知格式冒充结构校验成功，不执行正文中的公式或代码。

沿用现有资产种类：模型概念／本体使用 `concept/ontology`，业务规则使用 `rule`，实际数据映射使用 `binding`；指标体系组织与关联索引可使用 `business`。正文内的 item 类型不扩成新物理主库。未知或未支持的 profile 不能获得“结构化模型已核验”资格，其正文能否作为一般参考仍按原用途与来源核定。

| 内容组 | 最少信息 |
| --- | --- |
| item | 稳定 itemId、kind、名称、定义、企业／业务范围、有效时间、证据性质与准确来源；实体、属性、键、值域、事件和规则分别有明确类型 |
| metric reference | 原 SAP 包 ID、准确版本、metricName；有必要时引用准确 scenario。引用可核原文及哈希；不复制可独立编辑的定义、公式、用途和方法 |
| relation | 稳定 relationId、两端准确 item／指标引用、关系类型、范围与期间、依据；目录归属、公式依赖、统计分解、分析用途分别表达 |
| adaptation | 准确参考版本及 item、目标项、采用／修改／排除／新增／待核、差异与企业依据；参考资格不授予目标企业正式资格 |
| binding link | 实际输入版本／字段位置、被映射对象或属性／事件、粒度、转换或解释、证据及缺口；实际数据质量由 Agent 核查 |
| readiness evidence | 定义、数据映射、计算资格、实际使用分别记录状态、范围、来源与证据性质；资产候选／正式身份另行管理 |

SourceRef 按原权威原义复用，locator 不能全局重定义为 itemPath：当前 Studio 源用 locator 定位所属 system，方法源另有候选定位用途。项定位另用内容内 `ItemRef = {sourceRef, itemId}`，指标用 `{sourceRef, metricName}`；准确来源版本、哈希和稳定项必须一致核验，不以字符串拼接伪造原库身份。原来源范围与读取资格由原 reader 核定，再由内容解析器对该准确正文定位项，不绕过原源级检查。

当前正式图构建只识别正文顶层 entities／relationships；仅含 items／metricLinks 等新字段的 JSON 会作为整段来源陈述。新增内容约定不自动得到完整领域图或 OWL／SHACL 校验。本轮以准确源正文为权威，图仍可选；确有用途时才对明确条目作带来源的声明投影或最小兼容适配，并单列覆盖、保全及回读验收。派生图不能独立编辑成第二份权威，也不能借既有 graph-success 宣称新结构已完整投影。

### 4.2 代表性片段（逻辑示例）

以下是审核用内容结构，不是现有 API 的可执行输入。`sourceRef` 占位需由 Host 核定的准确来源替换；示例企业 A、标识和包均为虚构。

```json
{
  "contentProfile": "studio-foundation/1",
  "items": [
    {"itemId": "md.program_membership", "kind": "entity", "definition": "主体或账号加入一个明确计划的关系", "grain": "一条计划内会员关系", "sourceRef": "<准确来源>"},
    {"itemId": "ont.membership_valid_at", "kind": "rule", "definition": "按时点及政策版本判断资格有效性", "sourceRef": "<准确政策版本>"}
  ],
  "metricLinks": [{
    "metricRef": {"packageId": "demo-member-foundation", "version": "1.0.0", "metricName": "active_memberships"},
    "entityItemIds": ["md.program_membership"],
    "ruleItemIds": ["ont.membership_valid_at"],
    "bindingRef": "<准确Binding版本>"
  }],
  "adaptations": [{"referenceRef": "<参考准确版本及item>", "targetItemId": "md.program_membership", "action": "modify", "reason": "以企业制度核定资格范围", "evidenceRef": "<企业获准依据>"}]
}
```

“有效会员关系数”仅为用于验证契约和演进的片段，不是把企业基础层缩减成该指标。统计自然人数、账号数或会员关系数必须分别核定，不能因同名合并。Demo 用“正常＋宽限”至候选“仅正常”的受控资格变化演示依赖影响；它不代表目标企业或 Nike 规则，也不要求正常建设先发布错误口径。

### 4.3 四类关系和四项状态

目录归属表达主题分类；公式依赖引用 SAP 的准确计算构成；统计分解明确是否互斥、完备和可加；分析用途关联表达诊断或场景角色。outcome／driver／guardrail 是用途，不构成已证实因果，父子目录也不意味着数值可相加。明确因果假设需要原假设资产及相应证据。

状态最少区分：

| 维度 | 准确含义 |
| --- | --- |
| 定义已核定／待核 | 指定范围内的概念及规则有证据和核定记录，不等于所有用途可算 |
| 数据已映射／待映射 | 有准确输入及字段／事件对应与核查依据，不因字段同名推断连接正确 |
| 当前可计算／不可计算／待验证 | 对某用途与输入具有足够条件；缺资料、时间或资格影响明确 |
| 实际使用已验证／未验证／失败／未知 | 绑定具体任务、报告、输入、版本和独立核验；作者声明与独立结果分开 |

参考／候选／正式是另一条身份轴，图就绪也是独立事实。一个经核定的模型可以在“定义参考”用途发布，数据未映射则限制计算用途，不能宣称可计算。原关键检查的 FAIL／UNKNOWN 不得通过改名、藏入限制或移成非阻断绕过门禁；预览应冻结本轮用途、所需检查、未包括部分及原因。

## 6. 界面与流程

保留 Studio“企业基础资产／建设与演进／发布与使用”三主视图。企业基础内按需查看“体系总览、三类资产、参考内化、关联核验”，资料、数据映射和原专业编辑从原入口继续到达。总览默认显示范围、分项状态、待处理业务问题和一个主动作，不用节点数或总百分比判完成。

建设基础资产使用自然语言目标、原可写执行项目的合理默认和获准资料。主题可为行业或会员运营基础模型，无需先填写单道分析题。Agent 准备逐项采用与差异，人只处理真正待裁定事项；查看或筛选差异不是正式发布决定。

候选详情默认解释含义、来源、精确 SAP 引用、关联和限制；结构字段可按需展开。指标内容回到原 SAP 专业编辑，新视图不提供第二份可独立编辑公式。联合检查同时显示 Host 结构／资格结果和 Agent／独立业务核验依据，能继续查资料或转交原责任任务，不显示按钮一按即已证明业务正确。

发布预览展示准确组合与受影响用途，确认前可取消；来源变化后重新核验与准备预览。UNKNOWN 保留原请求身份并只查询，不能自动重放。普通任务视图以问题、回答、限制及建议为主，三类来源与实际读用证据按需展开；目录自动按范围提供，不让管理成为分析必经步骤。

原型统一使用虚构示例企业 A 和预置回执，明显标注“审核 Demo／本地演示”。“运行检查”“发布”“读取”“贡献”等交互均不能被解释为真实 Host 操作。Demo 不调用模型、不读取企业文件、不写产品库、不产生业务行动，刷新或重置回到演示状态。

## 7. 运行时与四原则核对

## 8. 未来验收与当前停点

未来产品实施先以可检出错误的结构／引用／状态测试覆盖 FA02–FA15，再走真实 Host／官方 SDK 的固定最小片段及适用 UI。关键反例包括同名不同对象、缺失引用、错包版本、公式与用途关系混淆、数据映射不完整、来源变化、UNKNOWN、只读与跨企业拒绝；失败证据保留。

真实模型验收另固定获准企业资料范围及输入身份、Provider／协议／线路、模型与 reasoning／thinking／上下文和 token 等实际配置、预算及取消条件。普通执行 Agent 不接建设会话或预期答案，自主找读、应用三类资产；独立预期核统计对象、单位粒度、资格时间、计算与业务叙述。若用旧样本修订候选，新验收准备未见变体。案例通过只证明限定范围，不推断企业基础层完备。

至少一次实质资料／规则变化需要体现受影响三类关联、准确新版、新普通任务实际应用及历史依据；无自然变化可在清楚标识的合成情境验证工具演进，不能冒称目标企业新版已验。图完成与使用、计算和叙述、作者声明与独立核验各自留事实。
