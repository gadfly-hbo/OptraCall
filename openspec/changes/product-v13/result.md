## 四原则专项核对

- **Host 管环境。** 原入口固定当前 owner、范围、操作编号、可读版本和接收模型。GSA 的采用、Case 取舍和行动授权分别留原业务凭据。撤权、失读和前次状态未知有独立测试，非作者发现与处置见 [双轴复核](review.md)。
- **Agent 自主执行。** 实际 Pi 请求中能看到准确版本的角色提示词和本次可用工具。经营分析、因果判断、工具顺序、是否提议新安排及如何解释数据由 Agent 承担。作者试答和受控协议回复的证明范围见 [角色记录](agents.md)。
- **复用第三方 SDK。** 本工作树的仓库校验器以官方 registry、锁定完整性与官方 tarball 逐文件核对 7 个 Pi 1.4.0 包，共 2,530 个文件，变更、缺失、多余文件和符号链接均为零。收据为 `.local/product-v13/official-pi-comparison.json`。会话、角色和工具沿原 Pi 扩展与资源接口。
- **减少用户操作。** 普通 Task 手建后即可首发，确认共用约定只写约定；模型提出的候选可在原表单修改。已送达的消息、已建的 Case、已存的同文稿均可核原记录，原编号重试各有证据。重要取舍、采用、启动工作与真实经营执行仍有各自明确操作。
