# 原 Teach 向上游复核与本地文稿导出

对应 [PM 修正清单](pm-repairs.md) 的 PM-04 和 PM-11。开发、测试及 Chrome 点验使用独立数据根、合成资料、本机协议端和官方 Pi 1.4.0。证据根为 `.local/product-v13/pm-repair/role/`。

## PM-04　从所见复盘到目标或战略

Case 原事项的每条已保存复盘均可「提交策略复核」或「提交战略假设复核」。前者进入目标管理 Agent，后者进入战略选择 Agent。复核页呈现当时的目标版本、策略、方案、用户取舍、原看板授权、所选反馈以及准确 Teach 原回复，可返回原事项或打开所涉 GSA。存在战略原讨论依据时可定位原讨论。

两处复核沿 Interface v3、原 role/profile 和 Pi 原生会话。会话归属含角色、准确 Goal ID／版本、Case、事项、取舍与复盘编号。Host 根据原记录重读方案与 Teach 的项目、Task、原生 session、entry 和摘要，核接收模型及来源权限。战略假设复核另读所涉目标准确版本当时存在的同范围目标关系。明确发出消息后才运行 Agent。复核动作本身不增改 Goal、采用、取舍、授权或反馈。

## PM-11　读取所见版本并导出

Host 先沿原生条目与摘要确定文稿及其实际依赖。人工读取无外部依据的固定本地战略稿、由其形成的 GSA，均可在更换旧模型配置或清除凭据后完成。带目标 Agent 建议的 GSA 也核原生建议、归属与准确稿。对再送模继续核当次模型配置和实际接收者。原生记录失读、外部资料排除、受控依赖资格不明仍会阻断。定量 GSA 的衡量字段同时给出 SAP 包 ID、版本、指标名称和目标要求。

| --- | --- |
| 原候选反例 | 清除凭据后战略预览返回 409；同名同版包的导出缺 ID。见 `01-red.log`。 |

本项与角色恢复、目标原来源、实际模型与接收 Task 出口权限共 22/22 通过。新增的当前配置修订、受控资料直接撤权补验分别为 3/3，通过项存在重叠。全仓 TypeScript 检查见 `types-final.log`。外部模型的经营判断与审批、用户产品验收、正式运行采用未在这两项核定。

### 非作者补充反例与修正

非作者在原候选上独立复现了另一条正式入口路径。战略讨论选择一个本地可读、已采用的 GSA，默认方法只有名称，未调用资料工具。删除原模型凭据后，原 GSA 导出返回 200，战略稿预览及导出均返回 409。首次失败保留在 `.local/product-v13/pm-repair/independent-spec/local-goal-export-first.log`，新增工程用例的 RED 见本证据根 `10-exact-goal-red.log`。

现从原 Pi 请求收据和提示还原当时的 Goal ID、版本、业务正文、关系版本与反馈依据。读取来自 `read-goals` 的准确交付也核对原记录。Host 用请求正文摘要验证原生提示，按冻结的 GoalBasis 重读关系与反馈，再核对准确来源、实际接收模型和 Project／Task 权限。递归核查沿当前操作的依赖路径有界执行。供应商调用仍须有效出站资格。
