# PM 第二轮 · 战略操作回执与版本导出

本项对应 2026-11-19 PM 报告第 2 组、PM-11 和 C4。原产品候选为 `36bd1c96a42b3d8ff56a4593fead6af7aae3545f`。所有经营资料、操作、项目及模型回复均在隔离测试根中合成，使用 Host 的正常 HTTP 入口、官方 Pi 和本机回环 Provider。各项原始回执在 `.local/product-v13/pm2/operation/`。

## 实施与范围

1. 把原生 `strategy_goals(operation)` 的查询编号、请求、工具调用与实际返回正文关联。成功的空回执只记录当时没有结果。晚于查询才写入的同号业务操作不能改变旧稿。没有 `details` 的历史记录仍可由原调用、结果与业务权威核对。旧记录缺失必要身份、原件丢失或内容不一致时拒绝读取。
2. 非空回执先与 GoalStore 的原操作比对，再按实际结果识别依据。创建、修订与采用核当时的 Goal；反馈只取该反馈、该 Goal 和源引用；关系按回执实际携带的历史修订与对应端点逐版核查。行动安排另回原看板操作、项目、任务和已有授权记录核对。原存储格式与原生 Pi 文件无须迁移。
3. 采用原有冻结 Goal 与资料的资格检查。战略工具向当前模型返回操作时先核查，历史再次发送及 Project／Task 承接时按实际接收方重核。人工读取的本地资格与模型派发分别判断；公开检索及受控资料沿用原有来源要求。
