# PM 修订后的项目来源、创建回执与普通 Task 接收

对应 PM-01、PM-08 及双 Task 同版约定联合验证。固定依据为产品复核单、v1.3 规格和已确认 Demo。沿 Interface v3 的项目／Task owner、Pi 原生会话、GSA 原版本库、Case 事项与授权、数据库和文件的既有出口规则。Host 负责来源、模型、会话与回执，Agent 自主决定是否用材料、如何工作。以下日志均位于 `.local/product-v13/pm-repair/project/`。测试仅使用隔离的合成库、回环协议端及官方 Pi。

| Do／Teach 下游与旧历史 | 新原生 run 保存各自的准确权利清单及 Plan 原回复身份。普通 Task 接收或转交这些成果沿原生祖先追溯，复核原项目、事项、所选轮次、当前授权、版本及接收方。旧账本缺少这四项时，通过原 run 保存的整段 SHA、原生用户消息和当时 Host 放在首行的准确委托取得原轮证据。失读、身份不符或损坏的历史不会自动替换。 | 真实 Pi 工具分别读取 Do 与 Teach。新格式与仅缺四字段的历史合成格式均可合法重开。撤回 Do 授权后两种格式中的 Do 下游均被拒，过去的 Teach 观察仍可回看；原 Plan 归档后两种 Teach 下游均拒绝。原请求 SHA 损坏也被拒。保全合成新原件再做格式复验，未写任何产品数据。见 `round-checked.log`，其中打印包含原件副本和收据的隔离目录。 |

原整仓曾报 direct／codemode 的权限用例失败。将新操作的来源校验限制在未运行的委托后，已有会话重新依其原生实际读过的材料判断；此次针对性旧用例通过（`nested-old-regression.log`）。项目、Case、准确来源、原生轮询及跨修订联合回归 23/23，见 `combined-final.log`。类型与 SDK 会话接入边界通过（`type-final.log`、`session-final.log`）。五个专项 Skill 的独立测评、真实模型业务表现、远端 CI、服务采用与用户产品验收沿原任务独立记录。

新增的项目来源和 Task 创建指纹均为可选字段，既有无来源项目及普通 Task 不迁移。兼容查询以现存的历史创建指纹和原生证明为准。回退按总包安排在停写后恢复升级前的完整根，另保全新版根和会话；避免旧程序回写后丢失新增字段。

同一事项改选其他仍可读的 Plan 后，原 Project Agent 会话继续使用。Host 根据该会话实际收到的权利，分别复核原轮次和当前接收方，只把当轮材料写入本次新消息。解除旧 Plan 项目关联后，即使当前轮仍可读，原会话也拒绝重开与继续派发；恢复关联读回同一原生会话。新事项的起始业务背景取建立该事项的 Case 事件修订，可以核到建立 Case 后、建立该事项前补录的描述、判断与下一步。正式回归见 `tests/v13-project-role-history.test.ts`。
