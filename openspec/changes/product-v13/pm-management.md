# 管理界面与工作区修正

本页承接 PM-05、06、09、10。以下浏览器操作均从产品 App 进入，使用同一工作树上的真实 React、Host 和隔离数据根。可运行 `node tests/browser-v13-pm-management.mjs http://127.0.0.1:<隔离前端端口> <场景>`；strategy 需要本地合成模型，native 使用原 `tests/fixtures/command-browser-environment.ts` 启动并传入其协议端地址。结果与过程中未通过的记录位于 `.local/product-v13/pm-repair/ui/`。

| 修正 | 修前观察 | 产品入口及修后结果 |
| --- | --- | --- |
| PM-05 已保存的准确战略稿 | 在重开的原讨论内选 v1，已能看到其原意见和导出按钮，页面缺接收范围与交接入口。见 `strategy-baseline.log`。 | 战略选择 → 原讨论 → 版本与导出 → 已保存版本 v1 → 选择接收范围 → 将此版带入 GSA。已有 v2 时实际送达所选 v1 的原生引用、全文摘要、原选择和目标范围。再次从所见版打开原草稿，同编号版本交接复用原目的地。版本总数保持 2，v2 仍为未交接。原文失读时按指定版本报错。 |
| PM-06 GSA 一次采用 | 普通采用对话无法显示当前正式策略与候选策略；浏览器在原确认窗口复现，见 `adoption-red.log`。 | 目标管理 → 核对与采用 → 选候选目标 → 核对并采纳此版本。同一个对话展示「当前采用 v1」与「本次候选 v2」的 G、衡量、期限和各条 S。策略有增删时列明原文，双方均使用建 Case 时相同的 G 口径。三组实例分别只改 G、只改 S、同时改 G 和 S，各经原决定输入和一次确认后，Host 读回采用版本 2。 |
| PM-09 项目阶段 | 只填写阶段目标，保存按钮仍禁用，见 `stage-red.log`。 | 独立项目 → 阶段目标 → 设置阶段目标。先只填目标，保存并结束，再只填结束条件，保存并结束；刷新后 Host 仍有 v1–v4，对应两次保存与两次结束。无阶段项目可直接建 Task，未强加填写；两项都空的表单继续禁用保存。 |
| PM-10 项目文件入口 | 固定候选展开对话后 CSS 隐藏了整个步骤栏，Chrome 可访问性树只有编辑区文件按钮，详见 `files-baseline.log`。原步骤栏按钮也缺少收起抽屉的接线。 | 在任务对话点击「放大对话」，可从「资料准备／上传或查看项目文件」与编辑区「＋ 文件」进入可操作的原文件栏；已附带资料的「查看项目数据说明」使用同一处理。关闭文件栏返回触发控件，原会话与草稿保留。Chrome 在宽 1320 和 390 两个视口均操作了两条入口并刷新文件；窄屏还从放大的同一对话发起真实 Pi 原生提问，点稍后回应、填写下一轮草稿、从步骤栏查看文件、返回后答复。同一请求仅一次命令、一次人工答复，原草稿仍在。 |

设置 → 业务模型包的回归使用合成计算包。浏览器首次给出引用系统符号链接的目录，原验货按 `UNSAFE_PATH` 拒绝；改用同一目录的真实绝对路径，浏览器导入成功，Host 可以按准确包 ID 和 v1 读回 Staging。仅覆盖本次隔离合成包及正式导入入口。原始回执为 `model-first.log`、`model-second.log`。

非作者另用两个独立窗口重现了一个并发差额。第一个窗口正比较采用 v1 与候选 v3，第二个窗口采用 v2，最新候选编号仍是 3。原确认会覆盖 v2。现有确认把实际所见的采用版本与最新候选版本一起核对，已有生效变化时返回 409，保留原决定输入并重新显示 v2。用户核对并再次确认后才采用 v3。已固化到同一 adoption 浏览器场景。

从 GSA 打开创建项目并转到模型设置后，在侧栏另行点「新建项目」会清掉已退出的 GSA 来源。浏览器由旧目标创建项目并核到首轮 Pi 收件，随后另建独立项目，核到后者没有 goalOrigin。
