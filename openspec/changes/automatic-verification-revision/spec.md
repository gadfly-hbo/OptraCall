## 1. 用户决定、范围和大白话

用户已确认下一步事项，并明确：主Agent的计算错误不靠堆专业参考解决，应发挥独立核算Agent的作用，自动反馈、自动修订，类似代码测试发现问题后交回作者修正。本规格落实该方向，不承诺模型核算等同于有确定真值的代码测试。

**大白话：** 主Agent做完，把明确选定的报告交给另一位Agent独立算；核算意见自动交回原主Agent，由它自己判断、重算和改稿；新稿再核。核算也可能说错，主Agent可以有依据地反驳。系统管交接、权限和记录，不代算、不替双方裁决。达到事先设定的返修次数后，把仍未解决的问题留出来。

本轮只新增本spec、[验证计划](validation-plan.md)、[交互原型](../../../docs/prototypes/automatic-verification-revision-ui-demo.html)和[交付记录](result.md)，并在原方向页追加本次入口。**不改产品源码、提示词、依赖、配置、持久业务结构或旧原型，不调用模型、不重跑旧实验、不Git/CI交付、不切服务、不操作MacBook。** UI为合成内存状态，没有真实API、模型、文件读写或浏览器持久存储。

基线为本工作树`codex/decision-feedback-loop`，HEAD `b36a42b43e86a279b1931770022c50b306ceeb36`；现有A/B/C未提交工作保留。之前B/C专业FAIL、旧原件破坏FAIL、取消和UNKNOWN继续有效，不能由新规格或演示覆盖。

## 2. B调整、C保留及责任边界

| 部分 | 本轮方向 | 明确边界 |
| --- | --- | --- |
| B分析可靠性 | 从增添专题参考转为独立核算反馈和原主Agent自主修订；评价最终全文及新增主张 | R1/R2继续不推广，不新增单位计算器、企业公式库、按题型路由、必用skill或固定分析检查表；不另加一轮“更认真”的提示充当改进机制 |
| C核算材料 | 保留源数据/作者产物两组选材、事前语义、固定全文、实际片段范围和读取线索 | 不扫描正文提取专业命题IR，不强读全部文件，不重跑作者脚本来代替独立计算 |
| Host | 用户授权范围内的触发、材料身份、会话交接、资源权限、运行停止、保存和版本记录 | 不计算经营指标，不解释专业意见决定谁对谁错，不按专业分数、关键词或读取次数派发，不改写报告 |
| 主Agent | 理解问题、选方法、执行计算、自主判断核算意见、修改或保留原判断、说明分歧 | 核算意见不是事实或命令；无需照抄、凑改动或写固定章节，不自动执行经营动作 |
| 独立核算Agent | 先自主形成首次依据，再对照作者稿；核查修订稿及自己的新增判断 | 方法与工具自主，可以一致、无法确认或提出分歧；不被要求每次找出错误 |
| 产品外评估者 | 判断原稿错误、检出/漏报/误报、核算新增错误、修订收益和错误传播 | 评分/真值不送入产品Agent，不成为Host放行或继续返修的条件 |

这是用户授权的Agent间工作交接自动化。固定的是材料开放与资源交接，Pi仍运行各Agent内部的完整探索、工具调用、自修复和上下文管理。Host不另造推理循环、平行Runtime或第三裁判Agent。自动结束只表示操作结束；没有“专业通过/保证正确”的产品状态，不妨碍用户继续普通分析或自行决定采用。

## 3. 一次设置，后续自动交接

### 3.1 开启与适用范围

在原任务核算面板内增加“自动核算与修订”，旧任务和新任务默认关闭。用户可一次开启本任务后续普通分析请求的自动交接，并选择：

- 核算问题与`020_clean`源数据；沿C选择RAP/SAP、企业语义和用户确认的事前Case背景，不自动带入反馈、当前判断或后验资料。
- 一个明确的`060_reports`待核报告路径，及可选作者过程产物路径。报告路径可在首次分析前指定；作者脚本、结果表和报告均只在首次依据保存后开放。源数据须已存在，首次报告可尚未生成；不因文件名像脚本就替用户判断其来源。
- 独立核算配置。主Agent仍使用原任务绑定配置；各自配置版本在本次操作开始捕获，不自动换模型或fallback。
- 最多自动返修次数：推荐默认2次，可选1/2/3次。原主Agent接受一次核算/复查意见请求计一次，不要求实际改稿；首次独立/对照及每稿对应复查不另计返修。已接受但终态未知也占已尝试次数，停止且不重发。这不是每个Agent的工具次数、推理回合数、模型费用或分析方法限制。

设置前可沿C预览材料和限制，保存设置不调用模型。开启后不要求用户逐次点击“发起核算”“生成新稿”或“复查”。关闭/停止后不再启动下一阶段。手动核算和原附属只读出稿入口继续独立保留，原记录不迁移为自动链。

### 3.2 自动触发的技术条件

当前`SessionResult`和主任务终态没有报告交付清单；不能宣称已有可直接复用的报告提交协议。首期以**用户明确路径+真实请求身份+文件字节版本**为触发依据：

1. 仅用户正常分析消息的本次运行可触发；返修请求、核算请求、GET、配置探针、命令和历史恢复均不作为新的自动链入口。
2. 普通分析实际完成且终态归属可证，主任务仍是同一原生会话/配置/上下文；在本次观测窗口内指定报告新增或发生字节变化，且能稳定固定，才启动核算。`completed`只是技术条件，不表示报告完整或正确；SHA变化只证明文件版本变化，不证明该字节一定由Agent写出。任务选择与真实请求绑定是材料交付归属，不冒称文件作者身份；已知其他任务/用户并发改动或无法确定本次选定版本时暂停。
3. 同一请求、设置版本和报告SHA只登记一次。报告未产生、字节未变或缺少实际请求归属时，不猜另一个文件、不读取旧报告冒充本轮结果，显示“未触发”及原因。
4. 自动链登记时捕获本链设置版本、报告/材料身份、模型/会话和次数上限，之后每次派发前核对固定身份。变化即暂停，不静默换同名文件、重新取材或重试；用户核对后可明确开始新的链。编辑设置只影响后续新请求，旧链和旧稿显示始终读取自身快照，不能用当前设置重建历史。

自动开启不意味着所有目录中新文件都会触发；新任务/新对象也不继承旧任务设置。旅游店等新任务须有自己的设置和报告版本。原任务下一份指定报告可触发新的链，但前链的设置快照、旧稿与意见仍可回读。无需新增要求主Agent按固定报告格式声明“提交”的专用工具。

## 4. 自动交接的实际行为

### 4.1 首次核算

复用现`independent-verification`两业务turn：先交固定源数据与事前语义，首次回复保存后才开放作者固定报告和选定过程件。首次结果可以是有依据的未知，不以得到确定数字、读满文件或用了Python作为开放条件。固定可用、主动附带、可观察读取和Agent声明继续分开。全文位置、4k/12k请求片段及原20k消息限制如实显示，不能截断身份或把摘要当全文。

独立核算不续接主Agent历史；共享工具/技能不等于OS隔离，不宣称绝对独立。新自动化不加载R1/R2或新的专题计算工具。

### 4.2 自动交回原主Agent

对照意见保存且技术身份有效后，**不论意见是有分歧、一致还是未知，都自动交回同项目、同任务、原主Agent会话**。Host不解析意见来判断“有错才返修”。交付包含本次固定材料定位、核算首次依据、完整对照意见、对应报告身份和剩余自动返修次数；材料超限不得静默丢弃，可交付完整固定文件位置与明示片段，实际提供范围保留。

原主Agent保有正常分析所需的Python、bash、文件与获准资源能力，可自行查证和重新计算。它判断哪些意见成立、是否需要修改，也可保留正确结果、指出核算误报、请求补资料或说明未决分歧。Host不要求固定回应字段/章节、不把拒绝某条意见记为失败、不替它生成修订正文。

此处不能使用`verification-author-draft/fixed-draft`代替：那个资源没有执行工具，也不是原主Agent。新返修是原任务真实native中的合法新增请求，历史前缀不改、父链不重建、不伪造旧assistant记录；交接中原会话变更、fork或配置变化时暂停，不能把旧意见塞到另一上下文，也不能悄悄另建作者。

### 4.3 新稿、再核与结束

每次返修开始前，Host给出一个未占用的新增报告位置和新的计算工作区位置；只属于输出/权限安排，不规定分析算法或报告内容。主Agent自行决定是否提交新稿。新稿由Agent生成，Host只稳定观察并固定，不替它补内容。

- 新稿存在且有新字节：固定该稿和本次明确交付的过程件，自动交给已见作者稿的核算会话复查。界面和记录明确“修订复查，不是新冷读”，不得复用旧独立性标签声称再独立计算。
- 主Agent未提交新稿：结束，显示“主Agent未提交新稿”，保留其原文理由；不能从这件事推断已无错误。另存同内容稿则标“内容未变”，不作为修订成功，也不重复同稿复查。
- 每份有变化的新稿均须有自己的复查身份和实际结果。复查意见在自动返修次数尚有余额时，自动交回原主Agent；之后仍由其自主决定是否再改。不根据Host对专业结论的理解决定分支。
- 达到次数上限：本次复查结束后停止自动派发，显示“已达自动返修上限”，展示最后稿、核算原文及仍需用户处理的事项；可以有分歧，也可以一致。最后意见可在主任务展示，但未实际派发就不得称主Agent已经读取。用户可继续普通对话或另行发起核算，不自动重开另一条链来绕过上限。
- 无论流程怎样结束，采用报告、关联Case、提取看板、发布SAP或执行经营动作仍走原有显式入口，不自动联动。

上限内没有强制凑满返修次数的要求；主Agent可以不提交新稿，各Agent在单次运行中的自主计算和自修复不受上述业务次数限制。需要从新数据重新独立核算时，新建记录，不将知情复查改名为冷读。

## 5. 原件保护、会话与故障

### 5.1 必须同时满足的保全合同

旧全工具修订曾覆写原报告并删除合成项目，见[旧事故及权限收尾](../../../docs/verification-revision-preservation-followup.md)。本次重新让主Agent执行计算时，不得把问题重新引入。

自动操作开始前已有源文件、原稿和既有目录必须原位保留；新稿与过程结果只新增，普通native历史只合法追加。固定副本不能替代原件保全；SHA事后告警、备份恢复、另存提示词或限制工具名称都不是已经证明的保护。自动链不得拥有删除项目、覆盖历史稿、发布资产或扩大经营动作权限。

**实施前必须解决并验证的技术前置项：** 明确在同一主Agent上下文保有真实计算工具的同时，如何对原文件和历史执行写保护、允许新计算/新稿写入，并覆盖直接/间接工具调用和异常收尾。具体执行环境/权限机制不在本轮假定已存在；不能虚构OS沙箱，也不能用全工具无保护或无执行工具另行出稿两种方式替代本合同。须在实施前随结构决定包给出选定机制和最小可行证据；若无法同时成立，自动返修不具备开工/交付条件，不能降低保全验收。

这里约束资源副作用，不约束Agent采用哪种公式、统计方法或查证顺序。不改普通分析现有010软约束及全工具策略，不借此重启全产品沙箱改造。

### 5.2 Interface与owner

遵循[工程规范v1.1 IN01–IN07](../../../docs/engineering-workflow.md)、[统一接入说明](../../../docs/agent-session-integration.md)和Interface v1。普通分析/返修沿`project-tasks`、真实`projectId/taskId`及原sessionFile；核算/复查沿`independent-verification`、真实`projectId/taskId/verificationId`。自动链业务身份关联上述实际请求，不自建SDK、ProjectAgent、全局队列或另一套生命周期Map。现`fixed-draft`资源及旧记录仍按旧合同使用。

建议在同一原任务公共lease内维持自动操作占用，核算子操作只接受本链绑定owner和材料；现核算对busy任务的拒绝需增加严格的同链资格，不得泛化为允许任意并发。普通用户续聊/命令在自动操作期间明确busy；停止并收尾后再续聊。占用、代际、取消及配置关闭复用公共实现，主Agent/核算Agent不同时写共享结果；不另建可自由插队的运行队列。

Interface v1是否足以表达同链资格、父子停止及请求归属，须实施前核对；如需实质契约变化，按IN06共同维护，不能预填“不改接口”。结构决定包需整体说明：设置与链记录的持久位置、身份/粒度/生命周期、新旧稿与核算对应、原件写保护、owner/lease、取消/未知及旧版本读取。此处只定业务合同，不在未确认前创建表/字段/迁移。

### 5.3 失败与停止

| 情形 | 行为 |
| --- | --- |
| 用户停止/关闭自动化 | 撤销整链后续派发资格，通过公共入口停止当前实际owner，收尾期间仍占用；迟到结果只能如实记录，不能再交回下一位Agent |
| 用户切换项目/任务 | UI解绑观察；不把另一任务回执挂入当前页，不因此自动停止或重启原链 |
| 已选源/语义/当前会话变化 | 暂停并说明变化；保留原固定材料与结果，不静默重新取材 |
| Provider、保存失败、配置关闭 | 标失败/中断/未知，停止后续派发；不自动换模型、补算或重试业务请求 |
| HTTP响应不明/断线/重启 | 先按原意图读取真实记录和native回执；GET不调模型。未经确认不重发，不承诺跨重启exactly-once |
| 请求已接受但保存未证实 | 保留实际请求编号/部分结果和UNKNOWN，不把completed当作保存成功，也不为出绿色状态重放 |
| 已归档/跨owner/重复意图 | 延续原归档只读与owner校验；同意图同载荷只回读，异载荷冲突，不建立第二条链 |

## 6. UI范围与状态

只扩原任务核算区域与对话时间线，不新增侧栏层级、专业模式、质量审批或评分控制台；保留原需求、指标、企业资料、Case、决策看板与A反馈能力。

- 设置显示源数据、事前语义、报告/过程件路径、模型、次数上限及关闭方式；路径和授权一目了然，默认关闭。预览/取消不发请求。
- 状态使用“等待指定报告、独立核算中、对照中、已交回主Agent、主Agent修订中、修订复查中、未提交新稿、内容未变、已达上限、材料变化暂停、已停止、结果待确认”。不显示“正确率/专业通过/全部错误已修复”。
- 每稿显示原稿/第N次修订、对应核算意见和请求来源；主Agent解释原文可展开，不由Host替它归纳采纳清单。旧稿与意见可回读，不覆盖。
- 材料区保留C的固定可用、主动提供、有限读取线索和Agent声明，未知如实；“已交回”依据真实请求回执，“已读取/采用”不能由Host推断。
- 主操作随状态为启用、停止、查询原记录或普通续聊，不设置每阶段确认按钮。Demo推进按钮放在明确独立的演示控制区，不属于产品操作。
- 简体中文、现有紫色强调/中性工作台、亮暗一致、390px可用、Tab焦点可见、dialog的Esc/取消还原焦点，错误关联label；分析/决策切换保留本页模拟状态。
