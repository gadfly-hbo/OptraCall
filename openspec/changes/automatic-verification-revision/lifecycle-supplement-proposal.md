# 生命周期补充：从首次执行起托管，交接前核定收尾

2026-11-01，Asia/Shanghai。状态：用户已整体确认本页A边界；候选4本地适用工程检查及两位非作者复验已通过，旧资源仍拒绝自证升级。分层证据、保留失败及后续真实模型结果见[补齐记录](lifecycle-supplement-result.md)，本页机制本身不代表专业收益或运行采用。用户要求先补齐生命周期机制，并用大白话说明、评估是否符合“Host管环境，Agent自主执行”。本页复核现有源码、已确认九项A合同及非作者反例；不修改运行服务、已有项目/会话/文件或原失败。

## 结论与大白话

建议把本次计算从一开始就放在Host能管理归属和停止的执行环境里，而不是等分析结束后再追查后台程序。适用范围先限定为**显式开启自动核算的任务**；未开启的普通任务沿原策略。

Agent可以自己选择算法、写Python、运行bash、并行算几份、调试和重算。Host负责：这些程序都属于这次任务；需要停止或交接时，能确认它们已结束，旧稿和数据不再被后台程序继续写。关掉聊天窗口或主进程，不等于后台计算已停止。

**该机制属于Host的环境职责，符合产品原则。** 但它确实调整部分进程与外部执行权限，不能说普通执行能力的所有语义完全不变，也不能把尚未验证的托管环境称作已经补齐。

## 已核实的问题

现普通worker仅清理其进程组，Agent启动的脱组程序可以继续存活。非作者已有隔离反例，见[实施结果](implementation-result.md)。新受限执行器已经防止其内部直接及间接脱组，但保护从核算/返修才开始，不能追溯保护此前普通分析创建的资源。

当前候选还会在每次工具结果后清理该调用的进程组。这能避免遗留，但不能直接扩展为普通分析的完整后台计算合同。新机制须允许本操作执行期内的后台和并行作业，将统一收尾放在已授权的停止/关闭/阶段交接时；不能为了容易清理而要求Agent所有计算都在单次工具调用里完成。

Apple的launchd说明仅承诺清理同一PGID中的进程；Node的detached路径会调用setsid。这些证据支持当前问题，不能把launchd或PID扫描当成完整收尾方案。[Apple说明](https://github.com/apple-oss-distributions/launchd/blob/main/man/launchd.plist.5)、[Node源码](https://github.com/nodejs/node/blob/v25.9.0/deps/uv/src/unix/process.c)。

## 具体机制

### 1. 从第一段可执行代码之前建立归属

开启自动核算的任务，在启动普通分析的工具、可执行扩展或本地MCP之前，就建立受操作系统约束的执行范围。可信监督代码负责创建执行资源、登记真实归属和收尾；不是在普通分析已经结束后补一张PID表。

沿原公共会话入口、owner及lease使用同一Pi SDK。SDK继续负责模型请求、原生会话、工具选择、内部迭代和上下文管理。执行监督器不创建另一位Agent，不增加分析循环或全局运行队列。

任务查看、设置读取和历史回读不得抢先运行未托管的用户代码。若此前打开任务已经启动了旧未托管资源，启用前须先核定其收尾；不能因为尚未发送业务消息就默认没有副作用。

### 2. 执行范围可管理，分析方法不固定

bash、Python、codemode及间接启动的本地进程继承本任务的生命周期边界。禁止自行脱离范围成为无人管理的常驻服务；可以在本操作有效期内并行、后台运行和读取实际结果。

复用现受限执行器已验证的防脱组方向，补齐从初始普通分析到核算/返修的覆盖，并让可信监督资源保持存活，直到本阶段收尾可证。不能简单把当前每工具后清理的实现整体套到普通分析。

普通分析与核算/返修可以有不同文件、网络和资源权限。原件只读与另存新稿继续遵循已确认自动操作合同；**不把返修的全部文件/网络限制直接复制成全产品普通分析限制**。每种profile的实际能力要列清并验证，不能只宣称工具名称相同就认定兼容。

Host不检查公式正确与否，不按代码内容选择方法，不要求专用计算工具、固定报告格式、检查数量或必做步骤。

### 3. 后台计算由本操作持有，交接时才核定收尾

Agent单次工具返回，不自动表示整份分析已经结束。合法后台计算在同一操作/阶段的资源使用权内继续运行，结果仍可由Agent自主读取；不额外限制模型内部的工具次数或自修复次数。

进入已授权的核算交接，或用户停止/关闭时：

1. 先撤销本操作继续派发及启动资源的资格，阻止旧回调再创建下一阶段。
2. 正常交接先通过公共入口drain，等待本owner后台作业自然结束，不发送终止信号；显式停止/关闭则取消模型及实际拥有的本地执行资源、已登记连接。
3. 核定这些资源确已终止，相关文件写入已收尾；发送信号成功、工具返回或主进程退出均不能单独当证明。
4. 成功后固定本次实际材料，并由原公共入口进入下一阶段。无法证明则保持UNKNOWN及占用，不自动重放。

正常分析仍在进行时，不为赶进度强行触发上述交接；后台作业未收尾不能伪称材料已稳定。正常完成与用户取消的结果分别记录。

“写入已收尾”的证明限于真实纳管并核定的资源。共享项目中，其他任务已知未托管的写入者也须阻断本次交接，不能因其不属于当前owner就忽略，更不能归为无关外部进程后宣称材料稳定。不能把本任务进程已停扩大为全机或所有共享写入者已停。

### 4. 扩展、MCP与外部执行如实划界

| 资源 | 托管要求 |
| --- | --- |
| 原生本地代码及子进程 | 从创建起受可继承边界约束，具有真实owner；禁止绕过监督器脱管 |
| 只读skill资料 | 继续提供获准正文及附件；资料存在不代表已使用 |
| 执行扩展、本地MCP | 实际执行须纳入同一边界；不能在可信SDK驱动里留下任意代码执行旁路 |
| 已有代理、远程MCP、外部计算 | 不称作本机子进程；需明确运行身份、访问/副作用范围及结束/取消语义。不能核定的执行能力明确不适用于自动链，不悄悄回退至无托管运行 |

不能把“本地资源已停止”扩大为“远端所有工作或计费已结束”。共用服务不因为某任务停止而被整体杀掉；远端不明结果保留UNKNOWN。通过launchd、AppleEvents或既有代理代启动程序，也不能成为逃离本任务归属的通道。

### 5. 旧项目和会话保留，旧运行不伪迁移

项目、数据、报告、原canonical会话及父链保留。计算进程关闭与会话历史删除是两件事；安全重新打开仍由SDK续接原会话，不造新作者、改写旧assistant或复制历史冒充续接。

旧未托管资源只能按其实际归属核定收尾。证据不足的旧运行继续保持不能自动交接；换worker、重启Host或复制会话都不是清场证明。也不承诺单次OS重启必然解决所有外部常驻服务。若某种过渡确需额外OS操作，先提出具体范围，不能静默重启、安装或全UID清理。

新运行从创建起进入托管，并不自动证明此前所有旧资源已消失。因此需单列旧运行过渡验收；不能为适配新机制而删除现有项目、会话或失败记录。

## 产品原则评估

| Host可以管的环境事项 | Agent继续自主的分析事项 |
| --- | --- |
| 进程属于哪个任务、存续范围及停止 | 理解问题、选择算法、编写Python与bash |
| 可读/可写位置、原件与凭据权限 | 探索数据、变换方法、并行计算与调试 |
| 本地/外部资源的授权和结束事实 | 判断资料是否足够、是否需要重算 |
| 固定材料、请求身份、交接及版本 | 采纳、反驳核算意见，改稿、不改稿或保留未知 |

判定标准是Host是否在管理资源副作用，还是开始决定分析内容。前者属于已确认产品职责；强制某个公式、必用工具、分析顺序、专业结论或由Host补算，均不在本建议内。

不能同时承诺“代码可以任意脱管并委托无法管理的外部执行者”与“Host一定能停止全部资源”。拒绝脱管不等于拒绝Python、并行或自主分析；但其兼容影响须公开说明并实测，不能以原则上合规代替功能验证。

## 如何验收

- Agent通过实际SDK自主运行Python/bash，跨工具读取结果、并行/后台计算、自修复；证明工具返回后合法作业未被提前杀掉。
- 直接/间接脱组、子进程再派生、扩展/MCP旁路、外部代理启动、任务停止/崩溃及阶段间隙：要么仍在可收回边界内，要么启动即拒绝；不产生不可核定的遗留写入者。
- 验证父子owner停止、UNKNOWN占用、迟到回执、显式清理重试及PID复用；停止A不误伤B或共享服务。
- 验证原native前缀、旧项目/源文件/报告保全；新稿与实际复查版本对应，普通分析及旧手动入口兼容。
- 旧未托管运行单独验证；不足时明确拒绝自动交接，不通过重开会话制造绿色状态。
- 非作者独立复核确认可执行边界和能力清单后，才恢复自动能力、重验此前10项NOT_RUN，再冻结并运行真实模型合成全链。工程通过与最终报告可靠性分别评价。

大白话要点：**Agent自由做分析，Host负责给计算程序登记归属、提供权限，并在停止或交接时真正确认收回。需要取消的是脱管权限，不是分析自主权。**
