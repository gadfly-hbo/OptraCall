# 迭代二 · 独立审查结论与建议

v0.1 · 2026-11-11 · 待确认。用户已确认迭代方向，本轮交付规格与[可点击 UI Demo](../../../docs/prototypes/conclusion-recommendation-review-ui-demo.html)。Demo 使用合成内容及内存状态。产品实施、模型调用、测试重启及运行切换均须另行授权。

## 1. 产品目标与边界

把原任务的独立核算入口改为「审查结论与建议」。用户可选一版已保存的报告，独立 Agent 判断重要结论和行动建议是否有证据、在什么条件下成立，以及证据缺口会怎样影响采用。主 Agent 保留解释、核实和修订权，用户决定是否将意见带回分析、是否采用建议。

当前手动独立核算会先用源材料形成依据，再看固定作者稿做对照。现有自动核算与修订是任务级显式开启的旧流程，会把对照意见交给原主 Agent。本迭代复用独立会话、任务归属、固定材料、历史回看与保存机制，新审查直接读取被审稿。旧冷读、返修与复查流程按第 5 节处理。 [现有核算入口](../../../docs/verification-agent-integration.md#用户操作) · [旧自动开关](../automatic-verification-revision/spec.md#31-开启与适用范围)

**CNR01 · 分工。** [迭代一](../report-calculation-review/spec.md)由原主 Agent 在同一普通分析请求内委派子 Agent，负责公式、计算口径、数值、单位、排序及相关出稿一致性的复核。本迭代审查报告所述事实、业务推论、适用前提和行动建议。审查 Agent 可以回看引用数字的出处、对象、期间及其论证作用。需要重算才能判断的疑点，标出原文、证据缺口和影响，交回原主 Agent 按需处置。本审查角色只读材料并返回意见，不复算、不直接改稿。两项迭代分别触发，结论审查无需取得计算复核回执才可开始。

## 2. 发起、固定版本与材料边界

- **CNR02 · 发起。** 从原项目任务的结果区打开「审查结论与建议」，任务空闲时可开始。有可证明属于该任务、可回读的当前交付报告时预选其版本。没有当前交付绑定时，仅在当前任务已获准的候选唯一且可证时预选。其他情况由用户选一次。候选来自现有 `060_reports` 及其已核验归属，文件名、更新时间或列表位置均不足以证明当前交付版本。没有可审报告时说明原因。用户点击「开始审查」才创建本次操作，正常路径无需再填写核算问题。
- **CNR03 · 绑定。** Host 在准入时按现有权限和固定材料接缝核对原项目、任务、明确报告路径、版本与实际字节。审查身份关联本次请求和固定报告，选中的是保存时的版本。开始前若选材、配置、权限或报告字节变化，保留选择并提示重新确认受影响项。开始后同路径内容更新且原权限仍有效时，可完成固定旧稿的审查，结果只归旧版。活动期间若撤权、owner 归属或可用性变化、配置失效，按公共生命周期取消与读取权限处理，停止后续读取及不再合资格的结果交付。已有记录只在仍获授权的范围内保留与回看。换新版须重新选择并明确开始。旧链接按绑定身份回读固定稿。
- **CNR04 · 依据。** 固定稿是必有材料。用户可以展开「审查依据」，查看已关联且当前仍获准使用的来源，按需增减与该主张有关的证据。候选可含 `020_clean` 的相关原表、已保存计算证据及已授权的业务规则、RAP、SAP、Case 或企业资料。原会话完整历史、无关项目资料、`010_draw`、未授权资产及凭据在此权限外。界面分开列明固定材料、实际送入模型的正文或片段，以及可证的读取范围。材料不足时可提交结论审查，意见注明哪些判断尚缺依据。超出技术限额或不支持的材料须明确提示实际可审范围。若固定报告本身无法完整可靠审查，保留原稿可读并让用户重选可审版本。

## 3. 证据判据与交付

**CNR05 · 审查单位。** 逐条选择会影响理解或行动的重要结论与建议。意见至少记录原文定位、报告版本、所用证据或缺口、适用条件、判定理由和可能影响。审查 Agent 可按「证据事实 → 适用规则或业务前提 → 可推出的结论与建议」组织，也可用反例、替代解释、代表性或适用范围来检验，形式和顺序由 Agent 决定。报告重述本身不能补足缺失的外部依据。多项观察共存也需要相应证据才能支持因果、扩大范围或具体经营动作。

| 判定 | 适用情形 |
| --- | --- |
| 证据支持 | 同对象、期间、口径和范围内有可定位依据，推论强度与证据相符。 |
| 有条件支持 | 现有依据能支持一项较窄或附条件的结论，意见明确适用条件及仍需确认的前提。 |
| 证据不足 | 缺可信来源、对照、定义或适用前提，或超出实际审查范围。说明需要补什么或可以把结论收窄到哪里。 |
| 与证据冲突 | 可定位的证据在同一适用条件下反驳该主张，说明冲突位置及影响。 |

**CNR06 · 结果和回交。** 面板按主张展示意见、证据和条件，并保留审查范围。未核查的内容维持未核查状态。流程「已完成」只表示本次审查已返回结果。页面提供「查看本版报告」及「带回分析」。后者把本次意见摘要、所审版本及来源定位追加到同一项目任务的聊天草稿，保留已有草稿，同一审查记录重复点击不重复追加，由用户使用原有发送入口。只对原任务仍具发送资格的用户开放带回，失败时保留意见与草稿。主 Agent 收到后自行决定查证、修改、说明分歧或保留原判断。采用报告及执行经营行动走原有显式入口。

## 4. UI 合同

任务页的「结果与核算」改为「结果与审查」，复用对话框下方结果区及原「核算关键结论」入口。Demo 的桌面右侧审查面板和窄屏顺排是本次拟议呈现。输入框上方的「配置自动核算」执行入口撤下。原自动核算折叠区的设置事实和记录移入审查面板的「历史记录」。任务、结果和报告入口继续沿用，无新增主导航。 [原核算面板](../../../src/host/ui/VerificationPanel.tsx#L213) · [原自动配置与结果区](../../../src/host/ui/App.tsx#L477) · [原自动记录](../../../src/host/ui/AutomaticVerificationPanel.tsx#L270) · [原上层文案](../../../src/host/ui/help-content.ts#L103)

| 情景 | 可见状态与操作 |
| --- | --- |
| 空闲 | 从原任务结果区打开「审查结论与建议」。显示所选报告及版本，可查看原稿、展开审查依据、选择报告并开始。没有可审报告时解释原因。 |
| 审查中 | 显示固定版本和运行状态，防止重复提交。提供「停止审查」，停止范围限本次审查，原分析任务保持原生命周期。 |
| 已返回 | 按主张展示四类判定、证据及限制，可查看本版报告、带回分析。无整体正确率、全局通过或自动采用状态。 |
| 失败、停止或未知 | 显示可确认的状态和可继续操作。只读刷新原请求，不自动重放。原稿、已记录意见和草稿仍可按权限回看。取消、旧请求或旧版本的迟到结果不得标成本次成功。用户明确发起的新审查另记身份。 |
| 有更新版本 | 旧意见保留原版本和结果，明确标出当前报告已有更新。新版通过明确选择和再次开始获取新意见。带回旧意见时须在草稿中明示所审旧版。 |
| 历史 | 新审查记录按对应报告版本回看。原独立核算、自动链、旧意见、稿件与回执按原类型只读。旧开关显示曾开启或关闭及当前「已停用」。历史入口仅回看，归档任务仅可读。 |

[UI Demo](../../../docs/prototypes/conclusion-recommendation-review-ui-demo.html)覆盖选择、审查运行、分条意见、带回分析、失败或停止、版本变化及旧记录回看。原型的状态切换使用预置数据，产品实际完成与权限以日后实现证据为准。

## 5. 旧入口与自动开关切换

**CNR07 · 新操作改入口。** 从原任务结果区以「审查结论与建议」取代新发起的独立核算。旧「自动核算与修订」配置作为历史事实读取。曾开启的值既不转为新审查的自动启动，也不成为迭代一的适用开关。原自动链、原手动核算与原附属新稿记录保持原身份，历史链接回看固定版本。切换后的旧写入口和旧客户端不得重新创建或自动排入旧核算链，须反馈入口已更替并提供新入口。历史读取的兼容性继续保留。

**CNR08 · 安全交接。** 在准入时为对应 owner 和请求固定旧核算或新审查的业务合同。等待切换时只让已准入的旧操作沿原生命周期到终态，暂停发起新的旧核算或新审查。旧操作正常结束或按原生命周期明确停止且收尾可证后，才切换对应 owner。状态不明时保留未知并等待确认。报告事后发生变化或没有变化都不能成为补跑另一路的依据。切换本身不触发强制取消、重启、重放、模型请求或批量写回旧设置，也不追改源文件、已保存报告或历史会话。

## 6. 四原则与接入

| 原则 | 本迭代约束 |
| --- | --- |
| Host 管环境 | 管理真实 owner、版本绑定、材料访问、取消与记录。模型意见原样关联其证据和版本，Host 不评定业务真值。 |
| Agent 自主执行 | 审查 Agent 自选证据、论证与表达方法。原主 Agent 自主处理用户带回的意见。 |
| 优先复用官方 SDK | 复用锁定的官方 Pi SDK 1.4.0、统一会话入口、已有独立审查、固定材料与只读能力。既有 `source-reader` 是只读接缝参考，需核实与本域的适配及实际权限。 |
| 减少人类操作 | 可信当前报告可预选，一次启动。依据可按需展开，历史可直接打开，意见沿原草稿发送。 |

依据[工程规范 v1.9 IN01–IN07](../../../docs/engineering-workflow.md#统一会话接入规范当前interface-v3兼容v1v2业务子集)及[统一接入说明](../../../docs/agent-session-integration.md)。沿现有 `independent-verification` 的 Host 静态注册、真实 `projectId/taskId/verificationId` owner 和 Interface v3 兼容业务子集，复用独立会话、只读固定材料、取消／关闭与保存。新的审查身份和旧核算类型可区分，资源只可访问绑定的固定报告与依据。权限由可信能力约束，独立上下文或提示文字不能充当权限隔离。若既有接口无法表达本合同，后续实施前按 IN06 补最小适配及兼容依据。拟改范围为原核算侧栏和状态、审查适配和角色合同、旧自动入口迁移及其验收。普通分析、经营采用入口与 SDK 包本身维持原契约。
