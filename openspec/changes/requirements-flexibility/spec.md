# 需求梳理四项纠偏

2026-10-30 · IMPLEMENTED，本地完整检查与固定候选非作者双轴独立复核通过；最终状态与兼容限制见[结果记录](result.md)，文档同步身份由本地最终回执记录。用户在只读评估后明确接受表格四项：允许未确认框架草稿、取消澄清/假设凑数、允许描述性分析不引用假设、有限格式自修。基线为最新 `main 51910be`，工作分支 `codex/requirements-flexibility`。沿用工程规范、统一 Pi Runtime 和上一轮可靠性修复；不纳入会话管理通用去重、统计资产或沙箱建设。

## 已确认的产品与契约边界

| 项 | 决定与理由 | 用户决定 / 一致性 |
| --- | --- | --- |
| F01 | 框架生成使用当前工作稿；无快照或 stale 也可形成未确认提案，展示来源与未决事项，避免把探索当正式发布。允许明确保留缺失结构的部分草稿，不逼模型编造指标或数据；正式发布与无版本送入仍检查四主结构组非空。模型结果仍需用户显式采纳。 | 用户接受表格第1项，一致 |
| F02 | 不规定澄清/新增假设的最低数量；允许模型明确表达无需新增，并给出原因。缺字段、无结构和错误类型不冒充合理空结果。 | 用户接受表格第2项，一致 |
| F03 | 保留现有 analysisPaths.hypothesis 必填 string 字段；空字符串表示描述性子问题无假设引用，非空必须引用该实例真实假设，数据引用仍完整校验。目的仅是支持不需要假设的任务。 | 用户接受表格第3项的无引用语义，一致；沿用字段的最小兼容表示 |
| F04 | completed 输出格式/结构不合格时，向同一 Agent 反馈具体错误，最多一次修正；保留原 native 输出与错误。首次 failed/cancelled/unknown 不自动重放；修正失败明确结束。 | 用户接受表格第4项，一致 |

结构核对：对象仍为原需求实例、不可变确认快照、RAP发布物；粒度、ID、目录、关系、版本标签、来源与读写入口沿用现状。F03仅放宽已有 string 的无引用语义，不增加列、对象、索引或持久化字段；旧非空引用、旧 YAML canonical 与指纹不变，不重写旧实例、快照或release。新生成无引用框架需要本版本或更新代码读取；不承诺降级到旧严格校验器后仍可读取新内容，不以旧副本覆盖后续资料。

生成响应的 source fingerprint / 输入确认状态、noChangeReason、修正次数为临时提案信息，不进入实例或RAP。采用现有 upstreamFingerprint 标识生成时上游输入；采纳请求可带 proposalSourceFingerprint，服务端对照当前输入，变化时拒绝旧提案而保留原结果供查看。正式发布、未指定版本送入继续要求有效确认及框架；指定发布版本始终使用原不可变 release。旧已发布 RAP 不被新草稿替换。

其余结构审查类别：无新的业务键、默认枚举、跨库身份、汇总视图、删除、迁移或存储布局决定；不属于本增量。资源 lease 仅为现有需求会话提供短期运行归属与取消，不落盘、不建立新的业务会话或Runtime。
