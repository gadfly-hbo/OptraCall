# 托管执行优化：已确认内部合同决定

2026-11-01。状态：**用户已整体确认 D1–D8 均采用 A，授权开始实施、检查、性能对照复测及非作者独立复核。** 暂不 Git/CI 交付或切换运行服务；原九项 A 与生命周期补充 A 保持有效。

本页按 `agentharness-structure-grill` 方法集中记录本次适用决定，D1–D8 的用户选择均为推荐 A，不新增业务持久表或旧数据迁移。细节见[方案](proposal.md)和 [spec](spec.md)。

| 项 | 推荐 A | 原因与代价 | 替代及本轮取舍 |
| --- | --- | --- | --- |
| D1 复用归属 | 原公共 Resource 内，同 immutable execution scope 最多一套按需文件执行组 | 原 owner/profile/代际管理占用；不能跨阶段借用旧权限，不能另建全局池 | 跨任务／主核算共用可少启动，但扩大权限与上下文串扰，不采用 |
| D2 工具范围 | 复用原 read/write/edit/ls；bash/codemode/grep/find 保留原隔离路径 | 优先消除 48 次 read 的重复成本，保留任意代码与子进程取消隔离；12 次 bash 仍有启动开销 | 全工具共享会引入同步 JS 阻塞与取消串扰；shell broker 增加控制面，本期不采用 |
| D3 内部调用身份 | 显式内部协议版本＋可信通道身份＋scope/执行代际＋toolCallId；原去重边界不变 | 防交错、迟到、重复与旧代际消息；每次 signal/进展/结果独立 | 仅删除旧 worker 的 used 标记不足以安全复用，不采用 |
| D4 取消与停止 | 单文件调用走 SDK signal，不杀共享组；公共 stop 才清全部本 scope 组 | 保持其他工具／后台存活；调用取消返回不等于底层尾部已结束，最终仍核实际退出 | 单调用取消杀共享进程会误停其他调用；隐蔽重启会产生重复，不采用 |
| D5 自然收集 | 仅组真实自然结束后无信号提前回收，保留 pinned leader 直到证明 | 去掉已完成组积累；实际后台继续持有自身 guardian | 按 result/超时/零 pending 收组会截断后台，不采用 |
| D6 退休权威 | 单组内部一次退休归原 Resource，失败资格由原公共 retryFailed 决定 | 防 stop/drain/自然收集竞争、重复清理与 PGID 重用误杀；失败记录保留 | 新全局清理器／自动失败重试与第二份 busy 权威，不采用 |
| D7 持久及兼容 | 公共 Interface v3、既有业务 v1/v2、native execution v1 和 codemode store 格式不改 | SDK 只在整个 scope 全部实际闭合后写 closed；不改旧项目/会话/文件 | 逐组写新业务事件／恢复证书、跨重启复用需要另议，本期不采用 |
| D8 安全与效果 | 保留逐调用保护检查；按同批固定工作量测收益，数值门槛仅实验建议 | 防以权限降级、少做计算、取消后台或计量换口径制造提速 | 目录安全缓存／强制单工具／专用分析方法不纳入 |

内部组／调用对象只在当前 Resource 内存中存在；运行身份不持久化为恢复授权。原生 opened/closed 仍是原粒度，主分析与核算的业务版本、材料和结果来源不变。

本页不替用户决定专业分析方法，不添加专业工具或分析范式。后续即使确认并实施本方案，仍需先验证共享执行器取消／自然退出及原件保护，不能因性能目标回避 UNKNOWN。
