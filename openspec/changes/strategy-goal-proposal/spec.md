# 战略讨论保存目标候选

在原战略讨论中，用户说清目标和职责后，Agent 可直接提出可核对的目标候选。项目关联为可选项。首次保存、修订候选和明确采用沿用各自已有操作。此次范围为战略讨论中的 `strategy_goals / propose-goal`。[问题 #90](https://github.com/gadfly-hbo/OptraCall/issues/90)

## 分工与接入

依工程规范 v1.12 IN01–IN07，沿用 Interface v3 的 `strategy-discussion` profile、讨论 ID owner、原生 Pi 1.4.0 和现有队列、工具及 GoalStore。Host 提供当前可核对的目标范围，核验准确版本、来源及写入权限，返回字段错误和持久化回执。具体目标、衡量依据、专业判断及是否补充资料由 Agent 根据用户原话和可用资料决定。模型通过现有 Pi 工具纠正草稿，用户只在职责归属或业务取舍确实不清时补充。现有会话、项目、采用权限和第三方 SDK 沿用原有契约。

## 验收

1. 以无关联项目的原讨论开展合成回归。Agent 能取得准确范围并按公开工具字段提交；保存的候选可由原讨论重读，保留已提交的业务字段和准确原生来源。
2. 字符串范围、缺必填项、结构或引用错误须说明受影响字段和原因。无效提交应在新建候选、追加版本和记录成功回执之前失败；既有库与历史继续可读。Agent 可在同一讨论提交修正稿。
3. 档案已经确定的范围和修订目标使用其原有身份，不能误用其他目标或企业。部门上级未知仍可按已声明的职责开展，个人使用无需新增项目或企业。多个可能的范围须可辨别。
4. 用本地合成模型完成真实 Host/Pi/工具/存储回归，另行检查兼容、非作者复核、PR 和 main CI。两端按合并版本更新并做只读现场核验；涉及模型或候选写入的点验在隔离根执行，原讨论由用户自行继续。

## 范围与回执

战略工具从本轮上下文或 `read-goals` 的 `goalScopes` 取得可引用的范围。绑定目标的身份固定。独立讨论中的用途表示业务背景；个人用途或唯一可确定的组织可提供默认范围，部门用途和未指定用途均不会自动选中个人或企业。Agent 可依据用户原话声明尚无上级的部门。对齐已有记录时使用原有身份。模型不需让用户填写内部 ID。

Pi 在调用工具前检查候选的标题、预期结果、适用视角、负责人、基线和衡量方式。业务内容和修改选择仍由 Agent 负责。Host 在写入前核对范围、已有目标、准确来源和版本；草稿保存为候选，采用仍用原来的明确用户决定。

候选全部字段符合约束时，保存与回执必须一致。单份长候选或多份候选超过现有工具回复长度时，沿用原存储保存全文，返回准确版本和内容哈希。Agent 可在原讨论核对操作，并按准确版本有界读取；读取和续谈继续核验原有资料权限。
