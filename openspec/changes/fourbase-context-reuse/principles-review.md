# M4 v0.2 四点产品原则核对

2026-11-03 · 设计／原型准备，**不是产品运行验收**。

用户要求：Host管环境、Agent自主执行、优先复用Pi已有能力、减少人的操作，并在后续spec／UI中充分考虑和验证。共同规则已固化于[工程规范v1.5](../../../docs/engineering-workflow.md#四点产品原则)，AGENTS仅留简短原则和同源指针；本文件只记录本次M4的具体应用与证据。

## 为什么要修订v0.1

v0.1已经允许零读取／零声明、未收藏可读，没有开发出Host硬编码分析链。但旧复核主要证明合同与演示对应，未证明每一项新机制都值得做或操作最少。本轮三项只读挑战发现：

1. 第三声明工具带出了成果hash核验、双receipt、deliveryRef／nativeProof和额外回查port；主要收益是机器核定成果—来源关系，尚非第二事项找到／读懂／自行判断的必要条件。
2. 将M31候选持久化所需的direct-only套到所有M4只读工具，会让证据格式限制Pi正常的工具组合。Pi1.4.0有受校验的ctx.executeTool；子结果不独立保存是证据覆盖限制，不等于禁止合法调用。
3. spec的正常路径本可零人工选材，但Demo从个人列表／人工引导开始，容易把可选资料搬运变成默认认知；当前任务加入还重复经过详情与目标确认。

因此本轮是**必要性与操作负担重新收敛**，不将未实施的设计风险说成既有产品运行FAIL，也不抹掉旧检查。原[v0.1](history/v0.1/README.md)、报告／manifest／原错误与M31 NOT_PROVED均保留。

## 四项逐条检查

| 原则 | v0.2具体约束／删减 | 设计证据与后续运行反例 |
| --- | --- | --- |
| Host管环境 | 只核真实owner／ctx／run、来源版本、人的供给治理、资源／取消／保全和展示。删除报告采用核定链，Host不代作摘要／方法／真假／是否采用判断。 | D02／D03／D05；读口只search/read、不加reportIdentity或整dataRoot权限。未来反例：伪owner／旧run／排除／close迟到须拒，源专业观点不触发Host裁决。 |
| Agent自主执行 | 默认正常提问，Agent自选找／读／换词／范围／拒用／零调用及正常直接／nested组合；没有必须声明／总结／补读。缺子结果证据如实UNKNOWN。 | RU01／RU02／RU09；原生nested/hooks一手源码。未来反例：只为日志无独立entry而禁合法nested、要求人审批普通读取，均不通过。安全绑定不能保证时仍需具体差额验证，不盲开口。 |
| 优先复用Pi | 保留同一会话、SDK customTools、参数／权限hooks、ctx.executeTool、取消、原生toolResult与历史投影；只补当前Host→worker串行化无法传函数的受限反向读口。 | 26项一手源摘要；D03真实IPC缺口，M3/M31原精确reader。没有新Runtime／消息库／摘要模型／索引／准入账；payload正文放实际content，details不是正文替身。 |
| 减少人的操作 | 当前工作为默认、普通unmanaged正常新增记忆操作0；当前任务一击加入／其他任务次入口；技术范围和身份按需展开；准确全文／最新纠正默认，失败可明确合并撤项与发送。 | D01／D04／更新Demo与操作计数。未收藏、未选材、未声明仍可分析；不要求用户日常维护，必要授权／准确目标／未知ACK不得为省操作绕过。 |

### 操作计数口径

只计完成指定路径的点击，不计输入问题文字。正常发送属于用户原本的目标操作，不是新增记忆维护；可选管理与异常处置分别计算。

| 固定起点／目标 | v0.1实测 | v0.2原型实测 |
| --- | --- | --- |
| Demo初页发送普通问题 | 切当前工作＋发送=2击；spec本已不强制选材 | 默认当前工作，发送1击；新增记忆专属操作0，仅普通unmanaged自助范围 |
| 个人列表加入已明确当前目标 | 详情→用于另一件工作→确认=3击 | 带准确目标的快捷加入=1击并回工作；无合法目标不默选 |
| 个人列表加入另一个目标 | 详情→另用→选目标→确认=4击 | 其他任务→选准确目标→加入=3击 |
| 已确定未发送的坏资料撤项再发送 | 撤项＋发送=2击 | 明确“移除不可用资料并发送”=1击；ACK未知／权限错误不适用 |
| 回看已保存原文 | 当前工作到原文2击；来源摘要内1击 | 沿用2／1击，未减少；删去声明证明入口。无独立子正文记录则显示UNKNOWN |

v0.2已在同一浏览器对原v0.1归档和新版实际交互回放；原始动作序列见`principles/demo/browser-operation-comparison-final.json`（本地完整路径见result）。10项对照观察通过，typing／滚动／模拟设置／Agent内部动作不计；正常记忆特有必做操作一直是0→0，没有把旧版的可选管理误称强制。产品实际效果仍待确认后的UI与SDK验收。受管ordinary仅接受人选固定文本的既有边界未扩大，不能声称所有profile都新增自主记忆，也不要求用户关闭保护。

## 复用核对的准确范围

- `.local/fourbase-modules/m4/principles/reuse-autonomy-audit.md`和`reuse-autonomy-source-evidence.json`：本机锁定Pi1.4.0、26项代码／随包文档hash，图谱优先核当前调用链。
- `complexity-cut-review.md`：按ponytail只列删减，不把必要权限／hash／只读／取消guard算成过度设计；root另行修订包。
- `human-operation-audit.md`及8张原始截图：区分旧spec本已可零选材、旧UI默认层级与真正必做动作，推导简化路径，不冒充产品实测。

Pi已有文件read不能自动处理OptraCall保留decision、candidate排除和最新纠正；SDK有工具机制也不替现进程凭空提供Host callback。两项业务工具和窄读桥有具体缺口，不为了删代码把dataRoot或人的管理API直接交给Agent。反过来，机器级成果关联不是因为“少个字段”就必须预建，故延期。

## 保留的必要边界与未验证项

准确版本／来源hash、归属／profile、人的排除、不可读／未知、预算／取消和原件保全保留。减少操作不能让Host暗中忽略明确选材、给冷读主分析答案、改旧记录、伪造全文或自动替人作业务选择。旧M2声明、M3人工保留、M31候选权威不改。

本轮只能验证规则是否写明、设计／可点击路径是否对应和本机SDK已具备哪些原语；M4新端口、nested安全绑定、真实Provider正文、取消／并发／容量、专业收益均未实施验证。未来按spec先真实行为RED、再实现、合成SDK／实际UI／非作者最终复核；不沿用M31限定例外。原始检查、复核与新完整候选身份见[result](result.md)。
