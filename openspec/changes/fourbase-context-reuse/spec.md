# M4：下一件工作的按需复用

2026-11-03 · 已批准 v0.2 · **用户整体确认spec／UI Demo、D01–D06全A，现进入产品开发；严格执行四点原则与SDD／TDD。**

## 目标与当前决定

用户正常提出问题，Agent在同一任务里自行决定是否找回旧资料、读哪些内容、比较或拒用。用户无需先维护笔记、收藏、选材或确认引用。人想指定某份资料时，有一个快捷补充入口；原文、人的纠正和本次判断分开。

本轮按用户明确的四点原则重审：**Host管环境、Agent自主执行、优先复用Pi已有能力、减少人的操作**，并固化到[工程规范v1.5 §2／§3](../../../docs/engineering-workflow.md#四点产品原则)和AGENTS简短入口。用户要求的spec／UI前置确认保持；M3.1限定例外仅保留其历史NOT_PROVED，不放宽M4流程。

依据仍为已通过的[整体方案v1.2](../../../docs/fourbase-doublebase-plan.md)与[模块索引](../personal-assets-phase01/tasks.md)。[v0.1原字节与原审查](history/v0.1/README.md)保留；旧PASS仅证明当时合同与演示对应，不能证明每项机制必要或人的操作最少。具体新取舍见[6组决定](structure-decisions.md)、[四原则核对](principles-review.md)和[更新Demo](../../../docs/prototypes/fourbase-m4-reuse-ui-demo.html)。

## v0.2的收敛

- 默认进入当前工作，用户输入问题并发送。Agent可自主查找／读取或完全不用，新增必做记忆操作为0；人工资料页是可选补充，不是分析前置作业。
- 只增加`find_personal_context`与`read_personal_context`两项业务只读工具，沿同一Pi运行资源和现有IPC补最小Host读口。SDK已有工具循环、参数／权限hooks、取消、直接／嵌套调用与原生保存继续复用。
- 延期第三个成果声明工具及其reportIdentity、deliveryRef／nativeProof、第二receipt定位块和声明专用payload hash。作者可在正常回复／报告说明参考、冲突或拒用；本期不声称有机器核定的成果—来源关系。
- 不为了日志整齐普遍要求直接调用。安全绑定真实owner／SDK ctx／run／manager／signal仍必要；Pi嵌套读取的历史只展示SDK真实保存的parent／nestedCalls范围，子正文无独立记录就记UNKNOWN，不迫使Agent重读补证。
- 手选当前任务从“详情→目标→确认加入”缩为“加入当前任务”一击，显示准确目标；其他任务为次入口，身份、范围和长hash按需展开。不会默认选择不明的首项／最后任务。

## 产品行为与验收

| 标识 | 目标行为及必要反例 |
| --- | --- |
| RU01 正常零维护 | 用户正常提问／发送即可，Agent自选何时查、读零条或多条、换词、引用或拒用；没有每任务必查、必读、必须声明、总结或逐条批准。Demo模拟选择不写成产品Host执行配方。 |
| RU02 Pi正常执行 | 新工具沿原SDK customTools及校验／权限／取消hooks。直接与原生嵌套／组合都按真实授权ctx接入；不能只因子结果没有独立entry而禁止正常读取。实际新嵌套读port安全性待确认后验证，不以任意ctx对象放行。 |
| RU03 目录与原文 | find只查标题／别名／范围，单总体页与一个继续游标，返回目录，不先向模型灌正文。read按需返回模型可见content中的准确原文／片段、最新独立纠正和局限；只在details里写“已提供”不算正文送达。 |
| RU04 准确身份 | 人工绑定原store/material/decision/revision/body hash，候选沿M31 ExactCandidateRef。不同项目同名不混，fork不换原身份，不回落当前稿／同名latest／缓存正文；sourceIndex只引用该准确对象的M3业务依据，不开放任意路径。 |
| RU05 人的可选补充 | 有明确、合法且已展示的当前任务时，列表／详情一击加入并回当前工作，原问题草稿不改、Agent不启动。其他任务直接选准确目标，无需先强制预览；没有合法上下文就先选目标，不默选首／末项。正常发送仍由原任务入口发起。 |
| RU06 当前治理 | 未收藏的有效候选可读；收藏不作准入。读取时自动附最新独立纠正，不要求人先维护／重审；排除先于本次治理快照核对已生效则拒绝新提供，晚于不撤旧交付、不改报告、不强制停Agent。恢复不修复UNKNOWN。 |
| RU07 失读与少操作 | Agent自主读失败收到具体错误后自行调整，不自动叫人接管。人明确选材发送前失败保留问题／选择；在确定请求尚未接受、具体坏资料已列出时，可明确“移除不可用资料并发送”，一步合并撤项与发送；不静默省略、不用于ACK未知、归档目标或权限错误。 |
| RU08 归档／profile | 人工已保留即使Enterprise未启用仍可读；人工归档默认不查，Agent可用includeArchived按历史参考读。来源项目归档只读另标；目标归档禁止写。新自主工具仅普通unmanaged主分析；受管ordinary仅人选固定文本，不开放执行权、不自动给冷读，不教用户关闭保护换便利。 |
| RU09 原生历史与引用 | 目录信息、实际记录的正文、作者普通文字说明分开。回调／事件／HTTP202／run-start不单独证明已保存交付；直接结果按真实native内容回看，嵌套仅parent元信息则明确子正文未单独记录／UNKNOWN，不说读取没发生。无结构成果关系就不展示“系统已核采用”。 |
| RU10 保全与兼容 | 历史看当时原文／纠正／治理，今天排除／失读另列。无证据旧记录不回填，坏native／旧版本不迁移，读取不开Agent／Provider。沿原请求fingerprint及同ID回查，不按今日来源变化重发已接受请求；停用不删M2/M3/M31、新native或业务文件。 |

## 最小接入与资源边界

沿[工程规范IN01–IN07](../../../docs/engineering-workflow.md#统一会话接入规范当前interface-v3兼容v1v2业务子集)和[统一接入](../../../docs/agent-session-integration.md)，Interface v3业务子集保持。Codex负责Host／Agent接缝；仍是project-tasks真实projectId/taskId、原配置、lease、ActiveRun和SessionManager。Host只负责准确来源、当前供给治理、权限／资源／取消及展示；Agent负责使用方法与业务判断。

Host函数不能直接序列化到现worker，现IPC缺反向业务读口，故仅补search/read的受限请求响应；不新开记忆服务／HTTP／MCP、会话域、运行队列或持久准入账，不交整个dataRoot给Agent。SDK ctx、当前child／owner／run／manager在异步前后核对，取消／关闭后迟到结果不放行。调用方式的安全绑定与历史记录完整度分开；新接入若证明某路线确实不能安全绑定，应补具体缺口决定，不以证明格式方便代替风险理由。

find默认20项、最多50项总量，单opaque continuation封装内部进度，不对Agent暴露两套游标；无语义排序／中文近义召回承诺。首期新find不加全文扫描，M3现有人的全文查找保持。read默认有界内容／续读，准确片段不冒充全文；候选与人工目录、额外来源及fork读取共用每次操作的原生20文件／50MiB预算，模型可见文本≤32,768 UTF-16、传输≤256KiB。限制是资源边界，不是任务内调用次数／方法配额；SDK已有offset／limit／截断／取消行为尽量复用，业务ref／治理校验只补最小差额。

## 人的路径

**默认工作。** 输入问题→发送；Agent自主决定是否用历史资料。查看来源／管理资料都可不做，不额外确认读取或引用。工具说明将旧资料和人的意见作为有来源的参考，不升级为本次系统指令、权限或已证实事实；Host不语义删改原文或替Agent作专业判断。

**可选指定。** 当前工作可进入个人资料，点带准确项目／任务标识的“加入当前任务”即可返回。需要别的任务时用次入口选择。同名显示短ID，完整ref／hash／UTF-16范围在高级详情；预算内默认准确全文和最新意见，显式片段仍保留。选材是原taskKey内存引用，不改问题、不自动发送／收藏／启用；刷新不承诺保留未发送选材，问题草稿沿原保存，不另造handoff Store。

**看历史。** 来源摘要的一次“查看当时提供”直接打开确有记录的原文与当时意见；今天状态另列。嵌套子结果未保存、首次未知文件或旧记录缺字段分别显示，不造原文、不迫使Agent走一次直接调用补证。普通回复／报告的引用和拒用说明照常保留，原M2人的来源登记不改；结构化成果—来源机器关联延期。

## 确认后的开发与验证顺序

1. 在改产品UI前，逐垂直切片留下公开动态行为RED：正常0记忆操作、可选快捷／准确目标、草稿不改、失败明确合并处置、profile／治理、历史当前与当时。不能用一次SSR缺按钮冒称全部交互前置RED，观察器／导入失败不是产品RED。
2. 先核真实SDK直接与nested ctx、owner、取消／重绑／关闭；再接两项读工具与窄port。合成Provider下一请求检查实际可见正文／纠正／局限；nested仅转摘要或未记录子正文时，界面不得宣称完整逐条交付。零读取、拒用、替代原生工具和普通文字引用正常，不强制多做一次read。
3. 验证准确旧decision、source丢失／hash变化、排除／恢复、归档／未启用人工资料、分页／共享预算、ACK丢失／同ID恢复、旧native与mtime保全；历史查看Provider新增0。实测正常路径和可选路径操作数，不以“自动化”文案当通过。
4. 固定完整候选、适用npm run check／公共消费者回归、真实Host→SDK→合成Provider→native→产品浏览器链路、全新非作者复核及四原则专项。真实模型质量／业务收益另授权；不重评旧FAIL、不沿用M31流程例外。
