# M4 v0.2 UI审阅

2026-11-03 · **四原则精简候选，待整体确认；仅虚构内存。**

[可点击Demo](../../../docs/prototypes/fourbase-m4-reuse-ui-demo.html)默认当前工作：用户输入问题／发送，Agent自主决定是否查／读／拒用。个人资料与技术详情都是可选补充；原v0.1从人工列表开始的叙事不再作为默认路径。

## 请体验这些路径

1. **直接提问。** 不选资料、不收藏，正常发送。演示模拟Agent的一种选择；在默认收起的Demo控制中也可改为零读取／拒用。产品Host没有固定搜索／读取步骤，没有第三声明工具或必做引用确认。
2. **自愿指定资料。** 个人列表一击“加入当前任务”回工作，按钮明确当前项目／任务短ID，原问题保持。其他任务为次入口，直开准确目标；没有合法上下文就先选目标，不默选首末项。原新建任务流程仅简化模拟，不重建产品完整创建。
3. **少做一次错误处置。** 明确选材发送前发现具体坏资料，问题／选择保留；可明确“移除不可用资料并发送”。它不用于已接受／ACK未知、权限或目标归档；Agent自主读取失读则自行处理，不默认弹人工审批。
4. **直接看当时内容。** 来源摘要一次打开确有记录的原文／最新纠正快照，今天的排除／不可读另列；历史不被改写。nested原生只有父元信息时显示子正文未单独记录／UNKNOWN，不伪造全文、不要求Agent重读。
5. **原权限不变。** 普通unmanaged可自助；受管ordinary只接人选固定文本，冷读／封闭／插件不是目标；不提示关闭保护。范围／长ref/hash在高级区，默认预算内准确全文加最新意见；片段不冒称全文。

## 原型与产品的边界

全部项目／内容／Agent选择／profile／故障均虚构内存，刷新全部重置，无业务API、storage、SDK、Provider或真实文件。Demo的自动回复是预置的“Agent选择”例子，不是产品Host强制流程。原M2/M3/M31产品功能与已批准Demo不改。

源码hash变化、真实nested ctx安全绑定、取消／并发／容量／Provider文本及新Host读口都未在本原型验证；确认后按spec先动态行为RED再开发。新增未发送选材仍taskKey内存，刷新不保证恢复，问题草稿在真实产品沿原保存；不为减少操作虚构持久Store。
