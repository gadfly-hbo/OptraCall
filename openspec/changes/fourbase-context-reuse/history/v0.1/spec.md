# M4：下一件工作的按需复用与历史可靠性

2026-11-03 · 确认候选 v0.1 · **仅规格／结构／UI Demo准备，尚未批准或开发M4产品功能。**

## 要解决的事情

M3让人保留知识／经验，M3.1让Agent在正常工作中自主留下候选。M4让这些内容进入下一件工作：人可以选一条作为本次参考；Agent也可以在同一任务里自主查找、按需读取，判断适用、冲突或拒用。减少重复解释和日常维护，不把旧经验当新任务的标准答案。

依据是用户通过的[整体方案v1.2](../../../docs/fourbase-doublebase-plan.md)§5／§9与[模块索引](../personal-assets-phase01/tasks.md)。用户现已接受M3.1限定流程例外并要求“保留NOT_PROVED；M4先准备spec和UI Demo给我确认，后续严格按开发流程执行”。例外只覆盖M3.1的特定历史缺口，不放宽M4前置确认或TDD；不追认为M3原流程通过。本包提交完整[6项决定](structure-decisions.md)及[交互Demo](../../../docs/prototypes/fourbase-m4-reuse-ui-demo.html)，确认前不修改产品源码、测试、业务结构或数据。

## 复用现状和真正差额

详见[复用核对](reuse-audit.md)。M3个人查找、Enterprise精确修订、M31原生候选／治理、M2材料送入、普通任务草稿／显式发送、请求fingerprint和Pi原生历史均存在。反馈→任务／需求也已有业务链，但它绑定BoardTask和原项目，不能把个人候选伪装成反馈，或重造通用交接Store。

当前缺少：Agent可调用的个人资料只读消费口；人工保留decision的完整精确ref；跨worker的owner绑定读能力；本次实际交付与可选成果声明的可核对联系。现个人页查找虽分页返回，却可能先读取全部正文／来源，不能直接充当有界目录工具；`toolResult.details`用于结构和原生记录，不自动进入Provider可见文本。部分旧历史投影仍调用`SessionManager.open`，本模块新回查必须沿既有无写入快照适配。

推荐沿锁定 **Pi 1.4.0** 和 Interface **v3业务子集**，只增加同一普通任务的声明式工具、现有IPC的受限只读请求／响应，以及原`providedContext`的可选personal字段。正文交付放模型实际可见`content.text`／显式prompt中，原生记录就是交付历史；没有第二份候选正文库、后台摘要、检索模型、embedding、语义索引、运行队列或新会话域。

## 产品行为与验收

| 标识 | 可观察行为及关键反例 |
| --- | --- |
| RU01 自主按需 | 普通unmanaged主分析在同一prompt可自主查找、读零条或多条、换关键词、比较或拒用。不强制开工先查、命中即读、逐条确认或结束总结；其它原生工具／自然语言引用仍正常，不为补结构证据强迫再读。 |
| RU02 目录与正文 | 查找只交目录元数据、准确身份和状态；正文／原文片段与人的最新纠正由明确read或人选材送入。模型可见文本确实包含交付内容，details仅有回执不算正文已提供。目录命中不能显示“Agent已读原文／采用”。 |
| RU03 精确来源 | 人工条目绑定store/material/decision/revision/body hash；候选沿M31原occurrence及完整details hash。不按标题、materialId当前稿或viewer fork重新绑定，不将候选伪装native-reply。额外业务依据按M3已有准确sourceRef读取；不接受任意sessionFile/dataRoot。 |
| RU04 人的显式选入 | 从个人资料选择真实目标项目／任务，加入taskKey隔离的本次选材，不改已有问题草稿，不自动发消息或打开Agent。同名项目用稳定ID区分；新任务沿既有创建，归档目标禁止写。用户仍从普通任务显式发送。 |
| RU05 最新人的意见 | 原文固定，发送／read时核当次治理快照并附最新独立纠正；旧意见可按需查。收藏只关注，不作消费准入；收藏变化不强迫重审。排除在这次快照核对前已生效则拒绝新交付；后生效不撤销已交付、不改旧报告、不强制停止Agent。 |
| RU06 草稿、归档与失读 | 人工草稿不是稳定长期来源，不由M4新送入；人工已保留即使Enterprise未启用仍可读。人工条目归档默认不查，显式纳入时按历史参考标注；来源项目归档只读并展示，不自动等于经验无效。损坏／变化／越权／治理不明／超限各有提示，不回落latest或缓存正文。 |
| RU07 三种证据 | 可发现、实际交付、作者主动声明引用分开。人选材仅在原生请求正文与起始回执可核对后称已交付；后续工具交付沿真实成功toolResult。没有正文证据保持UNKNOWN，不把HTTP202／run-start／回调返回当保存成功；也不从交付推出理解／正确／因果。 |
| RU08 可选成果声明 | Agent可以自主声明某个准确成果版本参考了哪些实际交付，沿同一Pi工具结果保存。Host只核成果hash、原生交付和归属，不裁定真实采用。零声明正常；目录／片段／全文的声明范围不能升级。成果改稿后旧声明仍指旧hash，不自动给新稿背书。原M2人的声明流程不改造为自动采用。 |
| RU09 历史与并发 | 旧任务始终回看当时来源、片段、注记快照与声明；当前纠正／排除／源丢失另列。已有接受请求的同ID回查优先原生历史，不因今天变化重送模型。首次未知文件只报文件级UNKNOWN，不猜身份／数量；无新字段的旧历史记未记录，不回填。 |
| RU10 profile／兼容 | 新自主查找／读取／声明工具只给普通unmanaged主分析。人的明确固定文本可给普通主分析（含现有受管ordinary），不开放新执行权、不自动给冷读。fixed-draft/text-only、独立核算、业务插件与历史查看不继承新能力。停用不删M2/M3/M31、新native或业务文件；原数据不迁移。 |

## 三条真实路径

**人选入。** 个人资料→准确详情→“加入本次资料”→选择真实普通主分析任务→仅增加准确引用和显式范围。目标已有问题草稿保持；选择／切换目标不启动会话，用户在原任务发送。发送沿已有材料准备和请求指纹接缝，核原文与当时人的意见。失败保留草稿和引用，可明确移除不可用项再发送，不能悄悄漏掉所选资料。未发送选材只在现有App taskKey内存保留；刷新不承诺恢复选材，问题草稿沿原保存，界面明确这一区别。本期不新增持久选材／handoff／pending库。

**Agent自己找。** 只提供可选的`find_personal_context`、`read_personal_context`和`declare_personal_context_use`。工具说明指出旧资料是带来源／范围／局限的参考，纠正是人的意见；不规定分析步骤。来源文字（包括旧行动／“代用户批准”之类陈述）是带边界的参考数据，不提升为本次系统指令或Host管理授权；不通过语义删改原文冒称已消除模型注入风险。query默认人工已保留知识／经验和有效非排除候选，未收藏候选可见；概念／项目数据沿M2原入口，不把数据目录命中变成跨项目原始数据授权。read重新核准确原文与最新治理，失败给具体错误由Agent自主处理，不另开Host修正／重试模型。

**回看证据。** 普通任务来源区并列起始人选资料、后续工具目录／正文交付、可选成果声明。原生成功保存才有“已交付／已声明”记录；没有记录就明确未知。只读详情可看当时交付和原始位置，另提示当前状态。候选原文件丢失没有独立正文备份；已发生的原生交付快照仍可能可读，不能把该快照当当前候选权威。成果文件丢失或换hash则原声明保留、工件回读UNKNOWN。

## 接入责任与权限

工程规范v1.4 §2／IN01–IN07／§3–4及[统一接入](../../../docs/agent-session-integration.md)适用。Codex负责Host／Agent与主接缝，复用`project-tasks`真实projectId/taskId、配置、lease、ActiveRun、SessionManager、取消与重开。公共SessionRef／withSession／执行语义沿Interface v3；新增Host-only只读业务port和IPC消息合同v1须共同维护、进入静态边界检查。若实现需要扩大公共执行权限或Interface，则补受影响决定，不借本包扩大。

跨worker无法把Host函数直接序列化给Pi。拟在已有IPC加入窄的search/read/report-identity请求响应，Host绑定真实owner、当前child与原operation；模型只交声明参数，不能交owner／管理端口／绝对路径。SDK工具仍在原driver执行，前后核同一run／manager、prompt、未closing／cancelled／signal未abort和真实直接toolCall；迟到不得形成有效回执。短期请求关联只承担传输，不另建Agent生命周期／持久代际／admission账／全局队列，也不新开HTTP／MCP服务。

显式人选材沿当前普通请求prepared text；受管ordinary只得到所选固定文本，仍无这些新工具。独立核算的固定输入与冷读独立性保持，不把主分析记忆或专业答案自动复制过去。普通unmanaged仍不构成OS隔离或原生文件防篡改认证。

## 资源、确认与阶段边界

query默认20行、最多50行，人工与候选分组并各自继续，不承诺语义排序。原生正文读取沿M31每批最多20文件／50MiB；一次find/read/声明或人选准备的嵌套核对共用该预算，不按每target重复重置；人工目录沿已有2MiB单文件完整性guard、分批投影，不再先逐项读正文／readSource。全域项目元数据发现仍可能遍历原目录，不承诺常数时间或把原生正文预算冒充全系统IO总量。

单次read默认准确前4,000 UTF-16字符，明确片段／全文及可继续位置；显式范围最多20,000字符，不切断代理对。最新单条纠正≤4,000字符随内容提供，旧注记按需分页。每次模型可见交付文本≤32,768 UTF-16，序列化传输≤256KiB；超出返回明确预算／部分结果，不静默漏掉纠正或冒充全文。人选每请求最多8项，是载荷上限，不是每任务方法／记忆配额；与已有RAP/SAP/Case等共用原消息总预算，超出保留输入并请减少范围，不由Host摘要。

M4不修改主方案v1.2、批准的M2/M3/M31 Demo、候选与人工账schema、正式SAP／Case／Board权威；不安装记忆组件／数据库、不后台整理、不做成熟晋升／效果评分。源失效和相互矛盾交给Agent判断，Host不按时间、票数或评分裁决业务真伪。M5–M8不提前实施。

## 确认后才执行的开发与验收顺序

1. 在改产品UI前，以现有公开页面／交互留下能检出目标行为缺失的真实RED：选材不改草稿／不开会话、目标隔离、排除／失读拒交付、目录与正文／声明不同、归档／profile、刷新选材说明。按垂直切片先RED再实现，不把一次SSR缺按钮当全部动态场景TDD，不以导入／定位器错误或事后撤功能造历史RED。
2. 先测同一Pi工具及Host读port的真实行为RED再接线。合成Provider下一请求必须实际含所读原文、最新纠正和局限；零查找／零声明、替代原生读取都可正常结束。测跨owner、旧run／fork／cancel、managed／fixed／cold拒绝、关闭时待决关联清理，不增模型循环；正文含旧指令／伪授权时，核消息角色与Host port权限未扩张，不拿合成Provider证明实模型抗注入能力。
3. 覆盖准确旧decision／candidate、同名项目、源归档、未启用人工资料、缺失／坏账／hash不符、分页／预算、首次失读、注记／排除并发边界、显式发送ACK丢失／重开／原指纹，以及改稿后旧声明身份。历史阅读前后比原字节／mtime、Provider请求数0。
4. 固定staged／unstaged／新增完整候选，执行适用`npm run check`、公共消费者回归、实际Host→SDK→Provider合成请求→原生→真实浏览器链路；全新上下文非作者完整复核与Host职责／SDK复用专项。真实Provider质量另授权，工程合成不证明业务增益。
