# M4 UI Demo审阅说明

2026-11-03 · v0.1 · **待整体确认；仅虚构内存交互，未接产品或模型。**

Demo：[下一件工作的按需复用](../../../docs/prototypes/fourbase-m4-reuse-ui-demo.html)。本次按已确认产品视觉壳准备单文件LOGIC原型，回答“从找到资料到本次提供、再到作者声明引用，怎样既好用又不混淆事实”；不是多套视觉重设计，也不是实际功能截图。

## 建议审阅路径

1. 从个人资料打开准确原文及人的意见，选同名但ID不同的目标任务；已有问题草稿保持，选材不启动Agent。明确发送后再看其实际提供证据。
2. 在演示控制区模拟Agent自主只查目录、按需读片段、读全文或零读取；目录已交付不能点亮正文已提供。
3. 原文不变时新增纠正、收藏变化、排除／恢复。发送时附最新意见；排除只拒后续新提供，历史仍在；没有强制逐条维护／重审。
4. 缺原文件、只读归档目标及不支持profile：草稿／引用保留，UNKNOWN不回落最新，不猜未知候选；人工草稿不新送入。source hash变化的真实精确读拒绝另按spec留待产品验证，本Demo不声称已实测原件变化。
5. 普通unmanaged允许新自主工具；受管ordinary仅可接人选固定文本；独立核算／封闭目标不可用，历史阅读不调用模型。
6. 模拟作者主动声明参考目录／片段／全文，绑定准确成果hash；改稿后旧声明不变成新稿声明。未声明正常，交付不等于理解／正确／因果。

## 界面与状态约定

沿OptraCall中性紫色、个人资料列表、准确详情抽屉和普通任务壳；以“个人资料／新工作／来源记录”展示同一产品内的去向，不新增独立记忆应用。主操作为加入本次资料／原任务发送；模拟Agent动作只出现在明确的Demo控制区，不伪装产品强制阶段。

未发送选材只在现有taskKey内存，刷新不承诺保留；问题草稿沿原产品保存。这是确认包的明确取舍，若用户需要持久选材，应在本轮决定包反馈，不悄悄新增Store。人工原账、候选治理与M2的来源权威保持，目标选择不自动恢复／启用来源。

响应式与可访问性按1440、390、320宽及浅深主题检查：抽屉可滚动，固定footer不遮底部内容；键盘Tab／ShiftTab、Escape和返回触发点，错误与状态可读，禁用项说明原因。预览用系统字体与内联样式／JS，不依赖外部库、图片、远程字体、fetch、storage或真实账户。

## 当前演示／产品差异

项目／任务新建表单沿原产品；本Demo以已有目标选择为主，新任务只简化模拟原创建入口，不重建原有完整流程。所有项目、问题、原文、注记、运行状态、文件丢失、时间／短ID和hash均为显式虚构示意；“发送／读取／声明／恢复”等只改变内存。刷新重置，不连接SDK／HTTP业务API／Provider，不写项目／任务／文件。产品尚无M4工具、personal提供字段、来源页或新声明能力，本页不能证明已实际提供／引用。

M3.1已批准Demo、M2／M3原Demo及主方案不改。当前HTMLhash、实际浏览器观察／布局／键盘与非作者整包结果以[result](result.md)为准。前置批准待用户整体确认spec、6组决定及本UI；准备阶段浏览器点验不充当未来产品UI前置RED。
