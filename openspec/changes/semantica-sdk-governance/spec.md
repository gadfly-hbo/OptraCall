# Semantica 官方组件治理规则

2026-11-06 · 文档变更 · 用户已明确授权

## 目标与范围

将 Semantica 纳入与 Pi SDK 同等的官方组件治理：官方原包保持原实现，精确升级目标由用户指定，差异在 OptraCall 自身适配，升级验证既有资产兼容及回退安排。详细规则集中于[工程规范](../../../docs/engineering-workflow.md#semantica-官方组件来源与版本约束)，AGENTS、架构与会话说明只保留同源入口。

本次只更新规范。保持 Pi 1.4.0、Semantica 0.7.0 和所有依赖／锁文件；不安装或执行 SDK／Semantica，不读取业务根／凭据、不操作设备／服务、不启动真实模型，不做 Git 提交／推送或 CI。现有工程、运行采用、原 FAIL／UNKNOWN／NOT_PROVED 与专业验收结果分别保留，不据规范新增推断实现已全面合规。

## 验收要求

| 标识 | 规范必须表达 |
| --- | --- |
| SG01 原包 | 官方发布包；禁止源码／安装产物补丁、私有 fork、替包及绕过公开契约的运行时改写；公开 API 操作业务图与自有实例合法 |
| SG02 版本 | 用户指定精确升级目标；提醒、latest、机器人、重装不构成升级／降级决定；依赖变化有锁定与兼容依据 |
| SG03 适配 | 官方公开接口优先，Host／Extension／薄适配层负责差异；内部只读例外逐版记录，无法解决提交用户，不改官方实现；Semantica 不另建 Runtime 或接管业务权威 |
| SG04 验证 | 官方发布说明、来源／实际安装／依赖证据；在隔离候选回归既有本体、图快照、来源 Ref、版本／绑定、原资产读取与新代刷新、权限／取消／错误；不能用安装或图约束通过替代专业验收 |
| SG05 回退 | 固定代码＋解释器／依赖＋配置／兼容图资产组合及触发条件，隔离核新增记录兼容；保持当前来源资格和升级后成果，不用旧数据覆盖；关键验证失败／未知不标完成或直接采用 |
| SG06 流程与范围 | 执行既有四原则、SDD/TDD 和独立复核；候选安装、Git／CI、服务／设备采用及用户验收分别核定，不为正常查询增添必做操作；本次仅文档 |

## 检查与完成标准

文档差异、范围及锚点／本地链接检查；核对原跟踪文件清单，变更仅为四份入口／规则文档及本规格和结果，源码／依赖／锁文件与历史记录保持。固定候选后由未参与创作且不继承作者会话的复核者只读检查 SG01–SG06 和四原则。无产品行为或 UI 变化，UI Demo、产品 TDD、SDK 执行及完整产品测试不适用；不以文档检查称运行或升级验收通过。

## 后续 Git／CI 与双机采用授权

用户在本地规范及独立复核完成后，明确授权本变更提交、推送、PR／CI、合并main，然后切换Mac mini服务并更新MacBook。合并前重核最新main和实际候选检查；本地main只安全快进，不覆盖WIP。上文不Git／不采用是原文档阶段边界，不撤销后续明确授权。

本次仍为规范变更，不升级Pi1.4.0／Semantica0.7.0，不改官方包、依赖或业务实现，不启动新的真实模型实验。用户同时询问是否需要类似Pi的追加整改，因此补有限只读接入核对，发现与未验证分别记录；规范已建立不证明实现全合规，也不自动授权发现后的代码整改。

双机沿现有独立产品副本、干净main／官方来源及固定成功CI目标，只快进、锁文件安装与构建，按原实例身份正常停启。保全各机原配置、凭据、项目、任务／native、报告、语义配置、图根与准确绑定；既有私有Semantica环境保持，不复制跨机业务或凭据，不重建图、自动迁移或重放任务。MacBook只单向接收main、试用与反馈，push继续禁用。采用回读须核health实际commit／tree／实例、原绑定与数据身份，工程／服务采用与专业／用户验收仍分别记录。旧兼容代码及私有备份保留，回退不覆盖新数据。
