# 业务覆盖审核原型：交互与状态合同

2026-11-13 · 待用户审核。全部状态是合成预置，仅页面内存；不代表实际Host／SDK／模型／企业盘点结果。

| 场景 | 动作与可观察结果 | 不得发生 |
| --- | --- | --- |
| 基础层入口 | 原Studio页内打开“范围与资料”，默认显示本次范围、六问及重点未决项 | 新建顶级EA平台、先要求完成36格 |
| 证据下钻 | 点六问或证据项，查看具体片段、准确版本、范围、标注理由；可多视角或未标 | 整文件唯一归格、类型直接决定唯一格 |
| 高级矩阵 | 按需展开36位置，默认14关注、可调整关注显示；计数仅表示证据条目 | 完成率、填满评分、把未关注等同不适用 |
| 状态并列 | 同时看到原治理身份、资料观察、四维作者记录及独立使用依据 | 正式即业务通过、可计算即已使用通过 |
| 合法范围差异 | 不同渠道／期间版本并列，显示各自范围和出处 | 自动mark-issue／改正式资格 |
| 待核矛盾 | 同范围期间疑似矛盾列待核，可在演示中记录原工作项，正式源状态不变 | 用标签自动停用资产或替人裁定政策 |
| 定义无需映射 | 概念定义可作为定义参考；映射“不适用/未核”与计算用途分别说明 | 所有采用项强制Binding |
| 用途缺必需映射 | 展示受影响计算／规则用途与精确缺口，独立定义及其他分析仍可继续 | 全库停用或把缺失补成0/false |
| 无报告 | 清楚空态，普通任务仍能发送并走原资产工具 | 新增必填报告、选格或方法选择 |
| 只有候选报告 | 建设owner可看，普通任务说明未采用候选报告，仍可沿其他合格资产分析 | candidate报告默认供给／伪造读过候选 |
| 方法资料不可读 | 显示未读及限制，原分析入口可继续 | 虚称已按该方法完成盘点 |
| 当前依据变化 | 报告仍固定旧准确版本，提示当前适用需重核，可演示另存新稿 | 后台切latest、重写旧报告或原生记录 |
| 普通任务使用 | 不选格直接发送；预置轨迹说明原catalog／read-source／reason及准确版本、限制 | Demo发网络请求、预置结果冒充实际调用 |
| 历史 | 打开旧报告仍见其报告／SAP／规则／输入的旧依据；新任务可用合格新版 | 修改旧依据以显示“最新版已通过” |
| 搜索无结果 | 显示当前过滤及清除入口，清除后恢复 | 把搜索无结果判企业未建设 |
| 加载／读取错误 | 在评审情景切换，保留明确状态与重试／原文路径，不能生成假的覆盖结果 | 错误时显示成功或覆盖百分比 |
| 亮暗／窄屏／键盘 | 稳定shell，表格容器内滚动；焦点可见，Esc关闭并返回触发点 | 页面横溢、弹层焦点丢失或键盘无法关闭 |

以上为规范性预期。实际原型覆盖／走验与缺口在review.md和任务清单按事实记录；未来产品必须重新按spec验收，不能用本演示替代。
