## 1. 目标与范围

分析结束后，用户可在分析窗口点击一次“提取分析方法”。Agent 回看该任务的确定 Session 来源及有权访问的相关记忆，提炼可迁移的方法、流程和明确的判断依据；结果自动保存为 SAP 方法的未发布版本。用户可以查看、编辑，再沿 SAP 统一规则发布。**IR 与非 IR 来源的方法都先保存、后发布，只有已发布版本可供后续任务参考。**

本期覆盖：分析窗口后置提取；SAP 方法列表、来源及发布状态筛选；内容查看、编辑、保存与发布；基础版本、去重、派生和纠错关联；准确来源；同一 SAP 策略下的已发布方法供给接缝。

本期不建设独立 IR 库、IR 调用／检索／路由系统、Compiler、DSL、DAG、图引擎、运行调度平台、评分或自动晋升服务。自动 hook、批量历史提取、批量导入、复杂分类、字段级 diff、分支合并和自动影响传播留待后续；非 IR 来源先兼容手工整理及既有方法来源，不承诺新增导入转换器。正常分析无需开启本功能、先发布方法或完成提取。

当前用户已确认本spec、UI Demo及D01–D08推荐，允许在本隔离工作树实施批准功能、必要持久化适配、真实RED-TDD、适用完整本地检查、隔离合成Host／Pi／工具／保存重开／UI和全新非作者及四原则复核。仅安装锁文件指定工程依赖、使用合成资料及loopback合成Provider；不读真实业务根或凭据，不调用真实Provider，不切运行服务、不操作MacBook，不提交／推送或启动CI。具体技术闭合及唯一写入归属见[实施合同](implementation-contract.md)。

## 2. 已有能力、差额及责任

实码证据以[复用核查](reuse-evidence.md)为准，不能把目标设计写成当前已实现能力。

| 已有能力 | 本期复用 | 需要补齐 |
| --- | --- | --- |
| SAP 0.2 指标／场景、不可变库版本及发布入口 | 资产库身份、不可覆盖的发布、明确用户操作、原项目采用和精确版本查读原则 | 完整的方法资产、未发布修订、方法列表与发布接缝；原 `method_refs` 字符串不是完整方法对象 |
| SAP 项目启用固定包版本，以及全局已发布资产精确查读 | 保持两条原有使用策略，由原 SAP 入口扩展方法种类 | 方法索引及准确版本读取，不因 IR 来源另建采用入口或额外逐次审批 |
| Pi Session／候选记忆及治理、准确来源读取 | 原生记录、相关记忆、纠正／排除及来源定位 | 后置提炼业务动作；不能把普通记忆候选当作已发布的 SAP 方法 |
| Interface v3 公共会话生命周期、附属 owner/profile 模式 | Host 静态注册、配置捕获、占用、取消、关闭、事件及脱敏 | 附属提炼资源和授权来源的按需只读接缝，不占用／替换原任务会话指针 |
| 当前分析窗口及资产管理页面 | 现有工作台、项目／任务上下文、成果入口 | 一个可选提取动作、方法列表／详情及清楚的保存／发布反馈 |

Host 管真实归属、权限、材料访问、资源、状态、版本与成果保存；不选择分析方法、推断隐藏思维、补算业务数值或判断方法专业成熟。Agent 自主选择读取哪些获准来源、怎样整理／组合／纠错、是否有可迁移价值。SAP 方法适配器负责业务格式与版本校验，不另写 Agent 循环。

### 2.1 资产、记忆和项目边界

- 方法作为当前用户 SAP 资产统一管理，IR／非 IR 是来源分类，不是两套库、权限或生命周期。
- “发布后可参考”限定 SAP 方法资产；普通 Agent 记忆及其既有候选查读、收藏、纠正和排除规则保持。
- 已发布仍需原访问资格；项目启用和全局准确查读沿各自原 SAP 策略，不把“项目已启用”新增为所有读取的共同门槛。
- 项目归档限制该项目的新提取／写入。SAP 全局方法管理沿自身资格，不因来源项目归档一并冻结；历史来源可否读仍核原资格。来源项目归档不删除方法、旧报告或 Session。
- 现有 SAP 发布人的文本字段不等于独立 RBAC 已实现。方法复用现有单用户明确发布操作，不照搬指标专用必填审核字段，不增加用户手填技术身份。

## 3. 可观察行为

### 3.1 分析窗口后置提取（SAM01–SAM03）

1. 正常分析沿原入口完成。用户自愿点击“提取分析方法”，该点击授权本次提炼和保存，不自动发布。
2. 用户告知任务结束或 Agent 明确交付完成，可作为完整任务来源；普通一轮结束、切页、沉默、发现报告文件不能被 Host 自动当成任务完成。
3. 开始前固定实际 project/task、源 Session 身份及截止位置，相关记忆保留实际读取版次。源在运行／配置关闭／项目不可写时，按原资源资格拒绝或说明状态；不悄悄等待后自动运行。
4. 原任务停止／取消／未完成时，保留记录。用户仍可明确要求整理已有材料，入口应说明“来源不完整，分析未完成”；这种显式操作不能伪装完整提取。原任务在途时不并发读取一个仍变化的完整 Session，不替用户停止它。
5. Agent 整理有价值的分析逻辑并通过业务保存入口另存为未发布方法；成功反馈提供查看／编辑入口。提取过程中不强制先维护日记、IR 草稿、目录或逐条确认普通读取。

没有价值的可迁移内容时明确说明，不生成空方法。完整沿用已知方法时关联实际使用的准确版本，不重复生成；只是换期间、门店、文件或临时参数时留在原任务语境。Host 不通过相似度阈值、最低字段数、方法配额或固定分析步骤替 Agent 判断。

### 3.2 方法内容与来源（SAM04）

方法应能说明：回答什么问题、适用与不适用条件、输入与 SAP 口径要求、问题拆解和方法选择理由、关键步骤的关系、明确判断依据及取舍、检查与局限、原任务／Session／记忆／报告和可复用材料引用。采用可读正文与必要元信息，不把每个栏目变成必填问卷。

实例中的数值、结论、文件、期间、门店及经营建议主要留在原任务和报告，通过来源关联。方法保留可迁移逻辑；缺失理由标为未知，不补造隐藏思维、未做过的检查或当时未采用的方法。后续整理明确属于后来版本。

来源引用固定到确定对象／版本或原生 entry／截止位置及可核对内容身份；不能只存标题、当前路径或 latest。一个方法版本可引用多个来源，一个来源可支持多个方法；被引用对象继续由原模块维护。来源缺失／权限不足／变化／截断和不完整分别展示，不静默补替代资料或回写旧来源。

### 3.3 SAP 方法统一管理（SAM05）

SAP 保留分析指标入口，新增同层级的“分析方法”。方法使用一个列表，来源为“IR 提炼”或“非 IR 提炼”，支持基础搜索／筛选，状态区分已保存未发布与已发布。详情展示内容、可参考的发布版本、待发布新版本及按需展开的来源／版本／纠错信息。

来源分类保持原始含义：人工编辑 IR 方法不改其初始来源；非 IR 方法经 Session 提炼改进，在该次修订增加来源，不为此复制到另一类库。来源未知不猜测，不强迫用户填写机器 ID 或引用指纹。

方法首期编辑沿统一编辑器。非 IR 方法与 IR 方法使用相同保存／发布入口和限制；现有未适配的任意外部格式不伪装支持导入。

### 3.4 保存、发布和正常复用（SAM06–SAM07）

| 操作／状态 | 必须显示的结果 | 后续任务可参考 |
| --- | --- | --- |
| 提炼或编辑，尚未保存 | 未保存输入，关闭前保护编辑内容 | 否 |
| 保存成功 | 确定未发布版本，可查看、编辑 | 否 |
| 保存失败／结果不明 | 输入和失败／UNKNOWN 保留；不得标保存成功 | 否，除非另有原已发布版本 |
| 对确定已保存版本明确发布，发布成功 | 该版本已发布，可沿 SAP 策略提供给有权 Agent | 是，仍需权限和适用性判断 |
| 发布失败／结果不明 | 已保存版本仍保留，失败或待核清楚显示 | 新版不可；原发布版按原策略保持 |
| 已发布方法再次普通复用 | 引用实际使用的确定版本，无需逐次审批或重发 | 是 |

普通保存不自动发布，提取／hook／后台整理都不能替代明确发布。发布动作沿同一 SAP 单用户规则；可选“保存并发布”顺序完成两个动作，只有第二步成功才进入可参考范围。第二步失败不回滚已成功的保存，也不显示整步成功。保存结果不明时不能继续发布一个猜测版本。

发布表达正式采用意图，不等于专业验证、自动注入所有任务、Agent 已读取／采纳或经营动作获准。SAP 统一供给已发布且有权访问的版本；Agent 自主决定是否使用和怎样调整，原任务结论、人的选择及验证结果不能自动变成本次事实。SAP 正式指标口径的原发布边界保持。

### 3.5 修订、派生和纠错（SAM08–SAM09）

- 修改同一方法：保存为同一身份的未发布新版本；原发布版保持，新版发布后按 SAP 版本采用规则提供。旧项目的固定引用不自动升级。
- 用途不同且需并存：Agent 可提出派生方法，保留派生来源；新方法仍先保存、后发布。
- 已保存的确定版本不静默改写；并发编辑／过期基版明确冲突并保留输入，不最后写入者覆盖。
- 疑似错误保留意见及依据；确认错误标明受影响版本，停止默认推荐，保留历史和替代版关联。纠正后的新版本也必须发布后才可参考。
- 已知错误提示应立即可查，不等待纠正版发布；仅保存未发布的纠正版不能充当后续任务替代方法。提示不自动撤销旧报告、选择或行动。
- 正式指标错误回原 SAP 指标权威处理；方法不另存一份指标正式定义，不自动重算或改写历史成果。

### 3.6 失败、取消和只读历史（SAM10）

提炼、保存、发布与原分析交付分开。原报告已完成但提取失败、保存成功但发布失败都可如实存在；各阶段分别反馈，不以 HTTP 200／accepted／completed 或模型文本证明已保存／发布。

一次提取请求绑定实际来源与目的；重复点击复用同一在途请求或明确忙，不重复起资源。重试模型必须由用户明确触发，不能自动重跑来源任务。保存／发布使用各自原幂等和冲突机制；已知同请求同载荷回读结果，不确定副作用保持 UNKNOWN，先核记录再重试，不自动复制出新资产。

取消撤销后续派发资格，等待本次实际资源收尾；取消之后若保存已实际发生，反馈确定版本及未发布状态；不谎称全部撤销。迟到结果只能补技术事实，不能写入另一 task／方法或自动发布。来源项目归档、模型配置变化和 Host 退出沿统一关闭范围处理；失败关闭保持隔离／未知，不将 driver 退出当资源已核清。

历史查看不打开模型、不续聊原 Session；缺来源不伪造恢复。源 Session／项目／文件、首次失败、专业 FAIL／UNKNOWN 和未采用稿均保持，不执行迁移清洗或重放。

## 4. 最小结构与会话接入

完整逻辑决定、字段组含义／可空／关系和兼容策略见[D01–D08](structure-decisions.md)。本稿提出“SAP 方法身份＋不可变确定版本＋未发布／已发布状态＋准确来源及修订／纠错关系”的最小差额；两种来源共享一套结构。物理表名、存储布局及技术工具名未作为产品稿的既定要求，批准前不创建 schema／migration。

### 4.1 Interface／owner／profile 候选

- 遵守工程规范 IN01–IN07，沿现有 **Interface v3、Pi 1.4.0**，不升级 SDK。公共生命周期保持；若实际实现显示公共类型需要变更，先提出受影响补充，不以业务分支塞入公共层。
- 原普通分析继续 `project-tasks`。提炼采用 Host 静态注册的附属业务 profile，候选名 `sap-method-extraction`；owner 逻辑上包含真实 source project/task 和单次 extraction 身份，独立原生会话目录。新身份是提炼操作归属，不是新的原任务 ID；不把原 native 路径作为续聊 sessionFile。
- Host 捕获当前所选来源任务的有效配置，通过公共 port 的一次操作占用调用；选择、版本、预算与权限可见，不暗换模型／provider。不得调用原 ref 后让 snapshot 事件改变原 task 会话指针。
- Agent 按需读取授权的固定 Session 材料、准确记忆／已有方法来源；复用 Pi 原生查读、上下文管理及原 source reader，补必要的窄读源 port。Host 不预先选分析结论或拼一个摘要冒充完整 Session。
- 现有 `text-only` 没有工具且有 65,536 UTF-16 传输上限，`fixed-draft` 有 20,000 全文合同；不能直接宣称支持完整长 Session 与按需记忆。首期提炼 profile 的只读来源能力已随D07批准，按实施合同闭合，不放宽旧封闭 profile，也不静默截断／回落到全工具会话。
- 来源快照及读源 port 只用于本次授权；不加载执行型扩展／外部 MCP、不授予任意原件写入、凭据或跨项目路径访问。只选择 read 工具选项不等于已实现文件权限，须以实际能力与资源边界验证。正常分析原工具策略保持。
- 原公共 start／withSession／stop／close／配置关闭、迟到校验及脱敏继续复用。业务仅持自己的 port/ref；跨 owner 管理、配置密钥和资源创建留在 Host，不建第二份生命周期 Map、调度队列或全局运行台账。

### 4.2 兼容与采用

方法作为 SAP 资产的新逻辑种类，通过统一资产入口做最小扩展；旧 SAP 0.2 指标包的格式、发布字节、启用和指标口径不变。不能把方法字段硬塞进旧严格 parser 并宣称兼容，也不能另建 IR 持久根。

只在显式提炼／保存／编辑／发布时新增本功能记录，GET 不升级旧 JSONL、记忆或项目。原引用是历史事实，旧项目不回填已采用的方法。实现阶段固定可读新旧资料的兼容候选；停用新写与提取入口后，仍能准确回看已保存方法、版本和来源。原始旧程序未认识新资产种类时不得导入它，不以旧副本覆盖新数据作为回退。

### 4.3 允许路径与维护归属

当前允许本变更文档及[实施记录](implementation.md)列出的SAP方法适配、Host／Agent／UI与永久测试。批准产品稿和Demo／旧批准包保持；仅安装现有锁定依赖，不升级。原“仅准备”范围保留在批准快照，不覆盖本次明确开发授权。独立复核者仍对候选只读。

后续实施的候选范围为：SAP本体 `extensions/business-plugins/metric-factory/` 内原sap／library／project／api／ui的受影响适配；Host中的方法资源注册／薄路由、原 `server.ts` 配置及关闭接缝；Agent中的来源工具／profile参数及原 `project-runtime.ts`、`project-session.ts` 最小能力适配；现有分析窗口／SAP导航及对应永久测试。公共生命周期本身原则上复用，涉及公共类型变化仍须受影响补充。

维护归属沿工程规范：Codex负责Host／Agent与集成；SAP Extension本体沿Qoder责任或明确交接安排，不能因本spec擅自写入他人的长期分支。开工前固定实际文件清单、唯一写入者及相应profile注册位置；增加模块、结构或数据出口时补受影响决定。本节由本次用户明确开发授权启用，当前实际文件及唯一写入归属见实施记录；不扩至其他工作树或无关Extension。

| 让方法供以后参考 | 在确定版本上执行一次 SAP 发布；编辑时可选保存并发布 | 不逐次读取审批，不另建 IR 启用步骤 |
| 以后提出新问题 | 原问题发送，沿 SAP 策略供给 | 不先选 IR 路由、拼方法或填机器字段 |
| 修订／纠错 | 按需编辑保存；新版正式供给前发布 | 不改旧报告，不强制先生成纠正版才能展示原错误 |

列表／详情沿当前工作台；版本、来源及技术身份渐进披露，主页面不展示 owner/profile 等实现术语。根目录没有 `DESIGN.md`，本次采用中央 SaaS 标准并参考现有产品／原型，不新增全产品设计规范。中性底、单主操作、亮暗主题、桌面／窄屏、原生表单标签、键盘可达、对话框焦点／返回及失败状态均在准备范围核对。
