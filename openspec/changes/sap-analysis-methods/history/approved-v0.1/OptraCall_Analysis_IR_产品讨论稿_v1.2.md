# OptraCall Analysis IR 产品讨论稿

> **文档版本：** v1.2
>
> **更新日期：** 2026-11-04
>
> **文档性质：** 产品讨论稿，汇总本轮讨论收敛的方向，供用户继续审阅；不构成开发、部署或产品验收授权。
>
> **适用阶段：** 个人分析与决策工作台。
>
> **本版主线：** SAP 统一管理分析指标与分析方法，分析窗口负责后置提取；复用既有 Agent 记忆和会话能力。
>
> **本轮已确认边界：** IR 与其他 SAP 方法统一先保存、后发布，只有已发布版本可供后续任务参考。

---

## 1. 本版产品定义

**IR 在本方案中指从 Agent 的 Session 记录及相关记忆中，后置提炼出的分析方法、分析流程和决策判断逻辑。提炼成果纳入 SAP 的分析方法管理，保存后供用户查看、编辑，发布后由有权访问的 Agent 在后续任务中按需参考。**

本版保留“提炼分析逻辑”的独立价值，收缩独立 IR 库与重复基础设施的建设范围：

- SAP 由分析指标和分析方法构成。
- 分析方法按来源分为“IR 提炼”和“非 IR 提炼”两类。
- 提取按钮继续位于分析界面窗口。
- 查看、编辑、版本与复用管理统一进入 SAP 分析方法区。
- 保存、查找、来源与治理优先复用已有能力；真实缺口再补，不预设一套独立 IR 存储、记忆或运行系统。

IR 能力可以由业务插件／Extension 承载，但不因此增加一套独立的方法管理入口。工程模块是否独立拆分，不在本稿决定。

## 2. 为什么仍然需要“提炼”

Agent 记忆能够自主留下知识和经验，但自主记录未必已经完成方法、流程及判断逻辑的整理。

用户点击提取按钮，是要求 Agent 回看记录，回答：这次怎样拆解问题、为什么选择这些方法、哪些依据改变了判断、下次有哪些做法可借鉴。

提炼成果应形成有逻辑关系、能够迁移使用的方法记录。通用摘要、工具调用清单和报告结论，不能单独替代这项价值。

这里的“决策思维”具体表达为可说明、可核对的判断依据：比较了哪些方案，依据什么取舍，存在哪些限制，什么新证据会改变判断。来源未记录的理由保留未知，不补造模型隐藏思维或历史事实。

## 3. 与已有产品能力的关系

| 能力 | 继续承担的责任 | 与提炼成果的关系 |
|---|---|---|
| Session／运行记录 | 保留实际发生的对话、工具活动和工作历史 | 提炼的主要来源，原记录不改写 |
| Agent 记忆 | 自主记录、选择性保存及按需找回知识和经验 | 提供相关背景，复用已有保存、查读和治理能力 |
| RAP | 表达问题、目标和预期交付 | 可引用原始需求，并说明分析中实际发生的范围调整 |
| SAP 分析指标 | 维护正式指标定义、口径及其版本 | 方法引用适用口径，不复制成另一份正式定义 |
| SAP 分析方法 | 统一管理可复用方法及其适用条件 | 承接 IR 与非 IR 来源的方法，统一先保存、后发布，发布后才可供后续任务参考 |
| Case／决策与反馈 | 承接经营判断、人的选择、行动和实际反馈 | 提炼引用其依据，不接管经营决定或改写行动历史 |
| 数据、概念、知识、记忆四类能力 | 组织数据、语义、规则、知识和经验 | 为查找与复用提供已有通路，不新增“第五库” |

## 4. SAP 方法的两类来源

| 来源分类 | 含义 |
|---|---|
| IR 提炼 | 从实际任务的 Session 和相关记忆中提炼形成的方法 |
| 非 IR 提炼 | 通过人工编写、外部导入、既有方法整理等方式形成的方法 |

**来源分类与发布状态分开。** 两类方法统一先保存、后发布，只有已发布版本可供后续任务参考；保存不等同于发布，来源类型不代表可信度、有效性或成熟程度。

建议采用一个方法列表，加来源标签和快捷筛选。分类列表也是可选呈现方式，具体界面尚未冻结；两类方法共享编辑、版本和纠错规则。

方法的原始来源分类保持稳定。非 IR 方法经任务提炼得到改进后，不需要复制到另一类库中；在该次修订中记录提炼来源。IR 方法被人工编辑或正式发布后，也继续保留其原始来源。

来源标签根据明确来源形成，不要求用户逐条维护；导入材料已有来源信息时应保留，未知部分不猜测。

## 5. 提炼成果包含什么

以下是内容重点，不要求每次填写全部栏目。

| 内容 | 要表达的逻辑 |
|---|---|
| 问题与适用条件 | 适合回答什么问题，在什么条件下使用 |
| 输入与口径要求 | 需要什么资料、数据、字段和业务定义，引用哪些 SAP 口径 |
| 分析逻辑 | 怎样拆解问题，为什么选用这些方法，关键步骤之间有什么关系 |
| 判断与取舍 | 哪些证据支持或削弱解释，怎样比较方案，判断受哪些条件约束 |
| 检查、局限与经验 | 哪些检查影响结果可信度，遇到什么陷阱，哪些条件下不适用 |
| 来源与复用材料 | 原任务、Session、记忆、报告、SAP 方法版本，以及可复用代码或材料引用 |

“分析流程”表达可借鉴的分析顺序和依赖关系，不变成 Host 强制执行的工作流。对已发布且有权访问的方法，后续 Agent 可以调整、组合、部分采用或拒用。

### 本次实例与可复用内容分开

- 本次文件、期间、门店、数值、结论和行动建议，主要保留在原任务和成果中，通过来源引用关联；必要时附简短实例说明。
- 可迁移的问题拆解、方法选择、检查经验、判断条件和局限，进入方法内容。
- 正式指标定义、已有 SAP 方法、企业资料、Case 判断和运行记录继续保留各自权威，方法只保存本次选择、调整和解释。

例如，“本月复购率为 18%”是本次结果；“比较新客复购前应核对观察窗口是否完整”可以成为方法检查项。新任务仍需重新验证该检查项是否适合当前问题。

## 6. 提取时点与分析窗口入口

合适时点是一个任务 Session 明确结束，例如用户告知本次结束，或 Agent 明确交付最终报告并说明完成。

首期以分析窗口中的“提取分析方法／提炼分析逻辑”按钮为主。点击后，Agent 回看本任务及相关记忆，提炼并保存为 SAP 方法区的未发布版本，再给出可查看、编辑的结果入口；无需另做一次普通保存确认。提取和保存不自动发布，发布另沿 SAP 统一规则处理。

按钮名称可在后续界面讨论中确定。任务结束不等于必须产生新方法：完整沿用既有方法时关联原方法；没有有价值的提炼内容时，明确说明，不为凑记录生成空洞方法。

用户切换页面、没有回复、普通一轮运行结束、目录中出现报告文件，都不自动等同于任务明确完成。停止、取消或中断任务仍保留已有记录；若用户主动要求整理可用材料，应说明来源不完整和分析未完成的局限。

自动 hook 可以作为后续可选触发方式，复用同一提炼能力。它依据明确结束信号触发，内容提炼仍由 Agent 执行；Host 不自行判定分析重要性、补写逻辑或编排分析。

## 7. 先保存、后发布，发布后才可参考

### 7.1 保存形成未发布版本

保存用于留存提炼结果，允许查看、编辑和修订。成功保存的方法仍为未发布版本，不进入后续任务的方法参考范围；提取、普通保存及自动 hook 都不自动构成发布。

整理、查看或编辑未发布内容属于方法管理，不等同于将其作为后续任务的方法参考。编辑中尚未保存的内容不影响已保存或已发布的确定版本，也不改写 Agent 已读取的版本。

### 7.2 发布后进入可参考范围

用户希望让某个确定版本供后续任务参考时，沿 SAP 统一规则发布。Agent 可以准备内容、来源和变更说明，发布权限与操作复用 SAP 既有规则；只有发布成功的版本，才可供有权访问的 Agent 按需检索、读取和参考。

已发布方法的普通复用无需逐次审批或重新发布，也不要求每个已保存方法最终都发布。未发布的方法可以继续保留、编辑和整理。

“可参考”不表示自动注入所有任务，也不表示已验证有效。Agent 仍需结合新问题检查适用性。发布表达正式采用与维护意图，不代替专业验证，不保证方法在所有场景中正确。

**IR 与非 IR 来源的方法统一遵循上述发布边界，不因来源分类而获得保存即参考的例外。SAP 正式指标口径继续保留原有发布边界。**

为减少操作，后续界面可提供“保存并发布”，一次操作顺序完成保存与发布；普通保存仍不自动发布，只有发布成功才进入可参考范围。具体界面不在本稿冻结，也不机械复制所有指标专用审核字段。

## 8. 后续使用沿用 SAP 策略

IR 提炼成果作为 SAP 分析方法管理。后续如何向 Agent 提供、按需读取和使用，统一沿用 SAP 的资产使用策略，不为 IR 另定调用、检索、路由或采用流程；IR 与非 IR 来源适用同一套策略。

本稿只明确方法应携带的产品信息：来源分类、确定版本、适用条件、局限和纠错提示。资产提供方式、项目可用范围、权限与版本采用，沿 SAP 既有规则及后续方法能力的必要扩展处理，不在本稿重新设计。

第 7 节统一采用 SAP 的发布边界：方法先保存为未发布版本，发布成功后才进入后续任务的可参考范围；IR 与其他 SAP 方法适用相同规则，不另设未发布方法可参考的通道。正式指标边界保持，旧任务结论不自动成为新任务事实。

## 9. 重复使用、编辑与版本

| 情况 | 产品处理 |
|---|---|
| 方法未变，只换本次数据、期间、对象 | 关联使用的原方法版本，不生成重复方法 |
| 本次临时参数或处理差异，没有可迁移价值 | 留在本次任务记录中 |
| 完善同一方法的逻辑、条件或检查 | 保存为同一方法的未发布新版本，说明变化原因；发布后才可供后续任务参考 |
| 形成用途不同、需要与原方法并存的独立方法 | 派生新方法，保留来源，统一先保存、后发布 |
| 编辑未发布方法 | 保存后仍为未发布版本，旧版保持可追溯；发布后才可供后续任务参考 |
| 编辑已发布方法 | 保存为未发布的新版本；原发布版继续可参考，新版发布成功后再沿 SAP 版本策略采用 |

Agent 在后置提炼时先对照已使用或找到的既有方法，判断本次是否只是复用，避免每个 Session 都生成一份相同方法。

同一份已保存版本不静默改写。后来提炼或人工补充的逻辑明确属于后续整理，不能冒称原分析当时实际采用。

本版需要基础历史与变化关联，但不预设独立 IR 草稿系统、完整字段级差异或 Git 式分支合并。

## 10. 纠错与避免再次误用

- **疑似错误：** 记录问题及依据，供后续读取时判断，不把单次意见自动认定为事实。
- **确认错误：** 明确受影响版本、问题和替代版本，错误版停止默认推荐，历史仍保留。
- **纠正后的方法：** 先保存为未发布版本，发布成功后才可供后续任务参考；替代版本与受影响版本保持关联。
- **已经引用旧版的任务与成果：** 保留当时依据，提示已知问题及可能影响，由 Agent／用户评估是否修订，不静默改写旧报告或人的决定。
- **SAP 指标本身有误：** 回到原指标权威处理，方法记录保留发现与影响，不另维护一份正式指标修正版。

已有纠正、排除、资料修订与来源能力优先复用；若方法修订与旧版提醒之间仍有缺口，只补必要关联和提示。保存或发布失败应分别明确展示，不能把未保存内容或仅保存但未发布的版本标成可供后续任务参考的纠正版。已知错误提示不等待纠正版发布才展示。

## 11. 最简产品体验与人工操作

### 分析窗口

正常完成分析后，用户按需点击一次提取按钮；Agent 提炼并保存为未发布版本，结果旁提供查看、编辑入口。用户希望供后续任务参考时，再沿 SAP 统一规则发布。原分析无需为 IR 维护过程日记、草稿或保存节点。

### SAP 方法区

一个入口管理两类来源的方法，按需搜索、筛选、编辑和发布，查看原任务及版本／纠错信息；清楚区分“已保存未发布”与“已发布可参考”。来源与状态可以渐进展开，不要求用户填写机器身份、版本关联或技术字段。

### 正常复用

用户只提出新问题，已发布且有权访问的方法作为 SAP 资产沿既有策略提供和使用，不另套 IR 调用流程，也无需逐次采用审批。未发布版本不进入后续任务的方法参考范围；发布是确定版本首次进入该范围的前提。

提取、保存或发布失败与原分析交付分开：报告可以已完成，同时方法尚未保存，或已经保存但尚未发布。已有 Session 继续作为后续整理依据，分别展示保存与发布状态，不伪装保存或发布成功。

## 12. 最小增量：复用什么，只补什么

| 直接复用已有能力 | 需要补齐的产品差额 |
|---|---|
| Session、记忆、资料与成果来源 | 分析窗口后置提取入口，以及清楚的提炼结果反馈 |
| SAP 既有资产使用策略及 Agent 整理能力 | 从 Session／记忆后置提炼分析方法、流程和判断逻辑的要求，区别于普通摘要 |
| 现有资产与资料管理基础 | SAP 分析方法区及两类来源的查看、编辑和筛选 |
| 现有修订、纠正和排除机制 | 方法持续修订、来源与替代版本的必要关联和查读提醒 |
| 原 SAP 资产使用与发布边界 | 方法“保存未发布／发布后可参考”的状态表达及必要接缝，两类来源规则一致，不放宽正式指标口径 |

不新增独立 IR 调用或检索流程；方法统一先保存、后发布，发布后才可参考，见第 7 节。“复用”不表示现有 API、存储或页面已完整满足目标。具体差额需在后续获准的设计阶段核对；本稿不决定表、字段、接口、物理存储或模块拆分。

## 13. 首期必须有与后续范围

### 首期最小可用

1. 分析窗口手动提取，保存为未发布版本，反馈保存状态与方法入口。
2. 能提炼实际分析逻辑及判断依据，引用原来源，兼容量化和定性分析。
3. SAP 方法区统一管理两类来源；基础查看、编辑、搜索／筛选。
4. IR 与其他 SAP 方法统一先保存、后发布，只有已发布版本可供后续任务参考；后续使用沿 SAP 统一策略，不另建设 IR 使用链路。
5. 完整沿用不重复生成；基础版本、来源和必要的改进／派生关系。
6. 已知错误版提示与停止默认推荐，纠正版可查；旧任务历史保持。

### 后续按需要增加

- 明确任务结束信号上的可选自动 hook。
- 批量提取历史 Session、复杂分类和批量整理。
- 字段级差异、分支合并、复杂多人协作。
- 自动合并相似方法、跨任务效果评分、自动推荐或晋升机制。
- 完整影响关系图和批量处理受影响成果。

不建设 Compiler、DSL、DAG 调度器或新的 Agent Runtime；不把方法库变成 Host 指挥分析的流程控制台。提炼不成为普通分析的前置或完成门槛。

## 14. 一条完整的使用例子

用户分析本月复购变化。Agent 参考 SAP 指标口径，检查观察窗口，比较渠道结构和渠道内变化，并说明证据不足的地方。

任务结束后，用户点击提取。Agent 形成“复购变化分析”的逻辑记录，保留为何先检查可比性、怎样区分不同解释、什么证据会改变判断，以及原任务来源。该方法标为 IR 提炼，成功保存后为未发布版本，可查看和编辑；用户沿 SAP 统一规则发布后，才可供后续任务参考。

下个月，用户只问新的复购问题。Agent 沿 SAP 统一策略参考该方法已发布且有权访问的版本，结合新数据及条件使用；方法没有变化时只关联来源。发现新的可迁移检查项时，先保存为未发布的新版本，原发布版继续可参考；新版本发布成功后，再沿 SAP 版本策略采用。

后来确认某个比较步骤存在错误。旧版本保留问题提示，默认不再推荐；纠正版先保存，发布成功后才可供后续任务参考。纠正版尚未发布时，旧版的错误提示仍保持。旧报告仍保留当时内容，是否修订另作判断。

## 15. 本版相对 v1.1 的主要变化

| v1.1 的较宽设计 | v1.2 的收敛 |
|---|---|
| 独立 analysis-ir 模块及较完整的 IR 对象管理 | SAP 统一管理方法；保留提炼能力，优先复用已有基础 |
| 分析过程中的渐进 IR 草稿与提交 | 正常分析沿原 Session 留痕，任务结束后提炼 |
| IR 作为独立分析资产库 | 提炼成果进入 SAP 方法区，不再另设一份方法主库 |
