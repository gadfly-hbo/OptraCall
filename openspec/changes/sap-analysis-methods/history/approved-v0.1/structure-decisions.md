## 2. 各项建议、理由与替代

### D01：资产归属、粒度、身份及去重

**建议 A。** 一份方法表示一种可迁移的分析方法、流程或判断逻辑，由当前用户的 SAP 方法区维护。稳定方法身份与版本身份分开；一个方法有多个确定版本，一个版本只有一份确定内容。来源分类为 IR 提炼／非 IR 提炼，由明确的创建来源产生，不靠标题或正文猜测，也不因后续编辑改变原始分类。

同一方法只换数据实例不新建方法／版本；逻辑完善形成同一方法的新版本，用途需并存则派生新方法。Agent 提出语义关系，Host 核真实目标、版本存在及写入冲突，不自行做语义去重或按相似度覆盖。

**原因：** 沿 SAP 统一资产管理，保留稳定引用，避免每个 Session 生成重复方法。原指标包／场景 `method_refs` 本身尚不是这种对象，不能冒称现有实现已足够。

**替代 B：** 每次提炼作为独立文件，无方法稳定身份，工程较少但无法可靠区分修订／重复。**替代 C：** IR 与非 IR 各建一套库，会违反已确认统一管理方向，不采用。

### D02：逻辑字段组与空值语义

下表是本轮待审核的业务字段组，未指定数据库列名、JSON key、SQL 类型或新技术枚举。正文参考产品稿栏目，不据此要求用户填满表单；工具／解析器字段应在批准范围内从真实消费者导出。

| 字段组 | 形式／业务含义 | 必需／默认与未知 | 边界 |
| --- | --- | --- | --- |
| 方法身份与确定版本 | 不透明的 SAP 资产引用、准确版次／内容身份 | Host 产生或沿 SAP 原身份机制；不由用户填；无 latest 默认替代 | 方法身份不等于 Session、项目或指标 ID；方法＋版次唯一，同版不同字节拒绝 |
| 标题与方法正文 | 非空可读文字；表达问题拆解、方法选择及明确判断依据 | 可保存有价值的部分逻辑；无内容不创建空资产 | 后来整理与原任务实际做法分开；不保存或补造隐藏思维 |
| 输入、适用条件和局限 | 可读文字／原 SAP 口径引用；可在正文中表达 | 已知即保留；未记录显示未知，不默认“通用适用／已验证” | 不复制正式指标定义，不将所有栏目改成强制字段 |
| 原始来源分类 | IR 提炼或非 IR 提炼；独立于发布状态 | 来自明确提取／人工整理来源，无猜测默认；来源详情未知单独说明 | 人工编辑和发布不改变初始来源分类 |
| 准确来源引用组 | 零到多条原对象／版本／entry及内容身份；本次IR至少有源Session身份 | IR必须有源Session定位；相关记忆／报告不强求凑数；非IR缺来源说明未知 | 引用未知不能伪造标题匹配；原对象继续由原模块维护 |
| 修订／派生／纠错关系 | 指向准确原方法版本的有向引用及变更原因 | 新建可无父版本；明确修订／纠错必须定位受影响版本 | 不自动构造复杂图谱；多个来源可支持一个版本 |
| 保存／发布事实 | 系统记录的保存版本及时间、发布成功对应的确定版本及时间 | 新保存默认未发布；发布结果不明保留UNKNOWN | 系统留存时间不等于业务有效期，发布不代表质量认证 |
| 问题提示及替代关联 | 疑似／确认问题的说明、依据、受影响版本及存在时的替代版本 | 无记录表示未记录问题，不等于已经证明无错误；替代版未发布需明确 | 提示不要求等替代版发布；不静默修改旧正文 |

**建议 A。** 容纳上述最小信息，正文可读、来源可核、生命周期明确；技术形式复用 SAP 与原 native/source ref 的确切含义，不新增成熟度分数或业务时间引擎。

**原因：** 能回答“什么方法、哪一版、从哪来、为何适用、是否已发布、哪里有问题”，又不把整理变成字段维护工作。

**替代 B：** 仅标题＋正文，最轻但版本／来源／可用状态难准确。**替代 C：** 完整 IR schema、节点／步骤对象、方法配额，当前无必要依据。

### D03：来源、读取与留存

**建议 A。** 本次提取固定原 project/task、canonical Session身份及截止位置；确切可读内容从原 SDK／source reader 获取。相关记忆、报告、已用 SAP 版本沿实际读取身份绑定；没有相关对象可省略，不因其缺失阻断原分析。必要的授权只读快照属于该提取资源材料，原引用仍为权威，不建第二份消息或记忆库。

一个来源可支持多个方法，一个方法版本可引用多个来源；引用指向原版本，不把源对象重命名、改 ID 或删除。后续治理与原内容分别读取，原来源失效时保持原引用并说明缺失／权限／变化，不回落 latest。来源快照、提取结果与首次失败按现有资源／证据保留规则保存，不新增自动清理或删除规则。

**原因：** 方法可追溯到实际分析，长会话仍可按需读取；不能以一段 Host 摘要冒充完整来源，也不暴露当前无权访问的记忆／项目。

**替代 B：** 仅来源标题／路径，开发少但无法证明历史版次。**替代 C：** 完整复制到独立 IR SourceStore，产生第二权威且扩大存储。

### D04：保存、发布和部分成功

**建议 A。** 保存是一次确定内容留存；发布是让该确定版本进入 SAP 后续任务可参考范围的明确操作。普通保存不发布，提取、自动 hook 和整理也不发布。已发布版修改后产生未发布新版本，旧发布版保持原固定引用；新版发布后沿 SAP 策略采用。

“保存并发布”是可选的一次交互，内部先保存，得到确定版本后再发布。保存失败或不明不继续发布；保存成功、发布失败则保存结果保持，提示未发布及失败／UNKNOWN。不得靠模型自述或HTTP成功证明任一阶段完成。发布权限沿现有单用户明确操作，不增加手填审核人、身份 ID 或逐次复用审批。

**原因：** 实现用户刚确认的统一发布边界，减少操作仍不混淆两个副作用。

**替代 B：** 保存与发布两个独立按钮，语义同样成立，但编辑后正式采用多一次操作。**替代 C：** 保存自动发布，与已确认决定冲突，不采用。

### D05：版本、纠错和历史

**建议 A。** 确定版本不可静默改写。修订指向同方法的准确基版，派生指向原方法版本但拥有新方法身份；已确认问题指向受影响版本，存在替代版时精确关联。旧报告、人的取舍、来源和原发布字节保留。

疑似问题是意见；确认问题停止默认推荐，原错误提示即时可查。纠正版先保存、后发布；未发布纠正版只能管理查看，不能被后续任务当成替代方法。提示及替代关系本身不自动级联改变来源、历史报告或业务事实。

**原因：** 避免“纠正版已保存”绕过发布，也不为等待新版本而隐藏旧问题。

**替代 B：** 只另存新稿、不关联原版，历史容易混淆。**替代 C：** 自动级联失效／重算／改报告，超出本期范围。

### D06：供给、采用与跨模块合同

**建议 A。** 方法通过 SAP 统一的资产发现／精确读取／项目采用接缝提供。已发布且有权访问是前提；IR 来源不多一套入口。现有项目启用固定包版与全局已发布资产精确读取分别保持，不能把其合并成“只有启用才可读”的新规则。一次实际方法采用保留准确版次，不从当前启用列表推造历史采用。

旧指标包／正式指标定义、RAP、Case、M2／M3／记忆候选仍各守原权威；只增加显式方法引用及必要适配。原普通记忆不因此改成发布后才能读取，方法草稿也不能伪装记忆绕过发布供给。

**原因：** 遵守产品稿第8节，同时覆盖现有两条 SAP 使用路径，避免新增 IR 路由或无必要审批。

**替代 B：** 本期只管理方法，暂不接后续任务使用，改动少但未达首期目标。**替代 C：** 新建 IR 检索／推荐服务，与已确认方向冲突。

### D07：附属提炼资源、原件与工具权限

**建议 A。** 沿 Interface v3／Pi1.4.0新增 Host 静态业务profile候选 `sap-method-extraction`，逻辑owner为真实源project/task＋本次提取身份，原生会话目录独立。来源任务的当前有效配置在操作开始捕获，凭据留Host，取消／关闭／日志沿公共port，业务不获得全局domain。不能用原 `project-tasks` ref跑提炼，避免原snapshot接线改变task的会话指针。

源 Session 固定为只读材料而非续聊参数；沿原SDK及source reader补按需查读，Agent自主决定读取顺序。现有text-only/fixed-draft限额和无工具语义不冒充完整长会话支持；新profile所需来源只读能力单独实现和核验，不开放任意执行扩展、MCP、凭据／原件写入或新业务数据读取。工具选项白名单不是文件权限证明，必须核真实来源port／资源加载和输出边界。

提取中的稿件由Agent输出、Host经同一SAP方法业务入口另存。来源任务busy／归档、配置关闭或原件变化在派发与落盘前重核；取消／迟到不切换另一owner、不自动发布。附属操作状态沿公共会话资源投影，不建第二套运行队列。

**原因：** 复用已有完整生命周期，保护原任务原生指针与历史，同时解决长来源按需读取的真实缺口。只“new ProjectAgent”或套text-only标签不能满足此合同。

**替代 B：** 只允许完整材料在封闭文本上限内的小Session，超限明确不支持，范围较窄。**替代 C：** 续接原任务全工具会话进行整理，可能改变原指针和来源，不推荐。

### D08：持久化最小扩展、兼容及回退

**建议 A。** 方法是现有SAP资产库内的新业务种类，沿同一管理根和明确版本发布原则扩展；未发布稿与发布版分别有准确状态，不为IR单建持久根。不改原SAP0.2指标包字节／schema、不改变原native JSONL／记忆总账和原项目引用；旧严格parser不直接接收新增方法格式。

现有指标草稿与项目绑定，不能未经适配冒称已满足全局方法草稿。方法草稿的归属及CAS、同版唯一、原子保存／索引更新和幂等需要在SAP业务适配层补足；沿已有保存机制做最小扩展，不创建跨库事务／存储平台。源项目归档不应冻结无关全局方法维护。

仅显式新写产生方法记录，GET不升级旧数据。不新增SQL表、图引擎或业务时间结构。逻辑上需要方法内容格式／版本、草稿与发布版身份及必要关联；具体文件布局、格式版本号和API形状必须从消费者闭合后写入本包补充，若涉及本包未覆盖的重要合同，先报受影响项，不暗中决定。当前没有已有方法库可批量迁移；未来旧方法字符串引用不能凭标题自动转换为已验证方法对象。

实施时先固定可读新旧资产的兼容候选，功能停用关闭新提取／新写／供给扩展，历史版本及来源仍可准确查看。旧程序不认识新格式时不向它提供方法对象，也不能用旧副本覆盖新增成果。保存／发布不明和格式坏保留原件与UNKNOWN，不以清理或重新运行恢复。

**原因：** 统一产品入口不代表原有存储已全部满足；明确只补真实差额，旧资产不被为了新功能重写。

**替代 B：** 保持仅仓库文件、不接SAP资产保存，无法完整交付首期。**替代 C：** 新建IR数据库或同时改造全部SAP／记忆存储，当前无必要。
