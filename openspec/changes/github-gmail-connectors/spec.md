# GitHub、Gmail、腾讯邮箱与飞书连接器

版本 v0.2 · 2026-11-27 · 四服务整合版已获用户确认

## 目标与确认范围

用户在 OptraCall 中建立自己的 GitHub、Gmail、腾讯邮箱和飞书连接，在获准的项目任务中用自然语言读取外部资料、处理工单、邮件和协作内容。入口放在现有「设置 → 连接配置」，任务沿现有「Pi 能力与命令」显式开启。界面与交互见[可点击 Demo](ui-demo.html)，执行清单见[tasks.md](tasks.md)。

本次准备基线为 `d4a62a64e791016f83e1afbd408fe541a053230f`，遵循《工程规范》v1.15、Interface v3 与官方 Pi SDK `1.4.0`。这份确认包固定界面、权限与技术验证范围。确认后推送确认版规格及 Demo，在 GitHub Issue 发单，再进入产品实现。

四项服务按同一个变更统一发单、分项验收并集中交付，在同一 Issue 中记录进度、回执和结案证据。

2026-11-27，用户明确确认方案并要求「发单实施」。确认的 Demo SHA-256 为 `ebdd9a02552fa20ed6e1c6c9d418ac69c25595494c18479843f1272c5ae88fb6`，工程交付沿本规格推进。

## 用户路径

1. 在「设置 → 连接配置」选择所需服务。GitHub 使用注册应用或细粒度访问令牌，Gmail 使用 Google 应用 OAuth，腾讯邮箱选择 QQ／Foxmail 或腾讯企业邮并配置客户端授权码，飞书使用官方托管 MCP 的用户 OAuth。应用信息只在首次配置或更换应用时处理。
2. 连接成功后显示实际账号、获得的权限和最近一次连接核验结果。授权取消、失效、缺少权限与网络不可达分别显示。
3. 回到原项目任务，空闲时勾选所需服务，核对具体账号和允许动作。四个连接各自开启，新任务默认关闭。
4. 直接向原任务提问，例如查询某仓库的待处理 Issue、整理某封邮件，或起草回复。Agent 自主查找和调用获准工具。
5. 发信、覆盖文档或合并 PR 等需要确认的操作，展示本次具体目标和内容，接收用户决定后继续同一个调用。普通读取沿已确认范围执行，服务端策略返回的审批请求在原调用中如实处理。

首版每项服务连接一个当前账号，任务保存其明确绑定。账号连接的作用域为当前 OptraCall 安装实例，两台设备分别维护自己的授权。开发交付与真实账号连接验收分别记录。

## 功能与权限

| 服务 | 读取能力 | 可选操作能力 | 首次连接所需信息 |
| --- | --- | --- | --- |
| GitHub | 获准仓库的文件、Issue、PR、提交与 Actions 状态 | 创建／更新 Issue、PR、评论与评审，按授权执行 PR 合并 | 仓库范围及细粒度访问令牌，或已注册的 GitHub OAuth／GitHub App 客户端信息 |
| Gmail | 搜索邮件、读取邮件和会话、查看草稿及标签 | 创建／更新草稿、管理标签、发送／回复／转发邮件 | 已启用 Gmail API 与 Gmail MCP API 的 Google Cloud 项目，以及标记为 AI Agent 使用的 Desktop OAuth 客户端 |
| 腾讯邮箱 | 读取邮件与文件夹、检索、读取附件 | 在任务中准备草稿，按授权发送／回复／转发 | QQ／Foxmail 的 IMAP／SMTP 授权码，或腾讯企业邮按组织策略取得的客户端专用密码 |
| 飞书 | 本人获准的云文档、消息与群组的读取／搜索工具 | 按官方实际开放的工具创建／更新云文档、发送消息 | 个人 OAuth 授权，企业管理员安装官方飞书 MCP 应用并放行账号和所需工具 |

GitHub 以明确的仓库集合限制产品连接器，调用时由 Host 核对实际 owner/repo。权限分为「读取」「Issue／PR 协作」「另含 PR 合并」，账号的组织策略和令牌权限仍由 GitHub 执行。Gmail 以实际授权邮箱为身份，按「读取」「草稿与标签」「发送邮件」提供能力选择，OAuth scopes 与工具集合共同约束调用。

腾讯邮箱首版提供读取与发送两种访问范围，草稿可在本任务中编辑。QQ／Foxmail 和腾讯企业邮使用各自的预置 TLS 服务器配置，邮箱类型也是任务绑定的一部分。远端草稿、文件夹写入及标签在明确核验相应服务能力后增补，本版任务草稿明确显示其本机性质。

飞书以用户身份连接到明确企业，权限按读取、文档写入和消息发送区分。实际开放集合取官方 MCP 工具、企业管理员许可和当前用户授权的交集，授权后还需核对实际工具列表。缺少管理员放行时，保留可用范围并明确指出缺少的能力。云文档、消息与群组是当前官方托管服务明确列出的场景，多维表格和日历按后续实际需求及官方开放情况扩展。[飞书当前托管 MCP 接入说明](https://open.larkoffice.com/document/mcp_open_tools/end-user-use-remote-mcp-server)

工具以确切名称的允许列表开放。首版聚焦表中能力，GitHub 仓库文件写入、仓库管理、邮箱规则／垃圾箱治理及飞书管理类工具如需加入，须补充本规格的权限与验收范围。远端工具目录增加新工具时，保持现有授权集合。

GitHub 绑定可信账号查询返回的稳定 user ID，登录名只用于显示。Gmail 在 OAuth 时请求身份核验所需的 `openid email`，通过可信 OIDC 身份渠道取得稳定 subject 和已核验邮箱，subject 用于绑定，邮箱用于显示。飞书使用可信用户信息回执中的企业标识、用户标识及相应应用身份绑定。腾讯邮箱按邮箱类型、已通过 TLS 认证的完整登录账号和本机连接身份绑定，别名改变按重新选择处理。用户填写的显示名称或工具目录不能作为账号身份核验结果。

发送邮件的确认展示 From、To／Cc／Bcc、主题、正文及附件身份。用户需修改内容时结束原待审批发送，回到草稿形成新版本，再对新调用确认。原参数保持一致时，用户决定才可携带相应 `requestState` 续接原调用。取消确认结束本次待发送请求。响应丢失时保留待核状态和原请求关联，查询服务端实际结果后再作决定，恢复连接不会自动重发。

Gmail 与腾讯邮箱分别保存发件账号、草稿和发送结果。邮件来源须明确选择，某个服务失效时保留该来源并显示不可用。腾讯 SMTP 的成功回执表述为服务器已接收，收件人送达情况按实际回执另记。提交后断线、IMAP 已发送文件夹没有查到邮件、页面刷新或重新认证均不能作为自动重发依据。

飞书写入展示企业、用户、目标文档或会话、操作及具体内容。修改已有文档时展示已读取版本与拟修改范围，按工具支持的版本校验或可核对的冲突处理执行。发送消息展示具体接收对象及用户／应用身份；本版的本人账号连接只使用已核验的用户身份，缺少相应身份或工具资格时返回不可用。结果未知时保留原目标和请求，恢复连接后先核对实际结果。

用户已明确授权、目标和内容确定的普通新建文档沿已有授权执行。工具要求确认、覆盖已有内容或发送消息时，展示一次针对实际内容的明确决定。Demo 的写入预览演示该确认场景。

GitHub 发单、评论、评审及合并属于外部动作，须与用户当前任务中的指令及所选权限相符。合并操作展示准确仓库、PR 编号和 head SHA，按当前工程授权处理。

## 界面与状态

全局连接卡展示未连接、等待用户授权、已核验、授权失效、连接错误、断开处理中及结果待核。保存凭据或登录命令结束均不足以显示「已核验」，须由可信路径实际核对服务、账号与获准工具。

高级设置按需展开，包含应用配置、所授 scopes、最后核验时间和服务地址。访问令牌及客户端密钥使用密码输入，保存后只展示是否已配置。浏览器授权跳转只使用预置服务的可信地址。

任务保存 `connectionId`、服务账号绑定身份及获准能力版本。更换全局账号、腾讯邮箱类型或飞书企业后，已开启任务显示绑定已变化并等待重新选择。重新授权到相同身份可恢复原绑定。断开连接时保留任务的开启意图和旧账号说明，调用资格立即失效。

任务运行、停止、资源关闭失败或写入结果未知时，沿现有占用状态处理能力变更。用户在全局设置主动断开时，先撤销后续调用资格，再通过公共生命周期停止并关闭实际使用该连接的资源。界面展示受影响任务及真实收尾结果。

任务方案创建的新任务和其他任务的权限互相独立。方案继承商圈／天气能力的现有逻辑不自动授予个人账号访问。

## 技术接入

### 共用现有 Pi 与 Host 接缝

Host 继续注册 `project-tasks` 域的既有 owner/profile，owner 为真实 `projectId/taskId`。`ProjectAgent`、Pi 原生会话、工具循环、历史及 Interface v3 生命周期继续承担运行管理。连接器自身只提供服务访问和必要协议适配。

账号、仓库与工具权限由 Host 保存并解析，通过非敏感绑定交付给 worker。通过既有 `createMcpExtension`、`registerMcpServer`、`tool_call`、`getAllTools` 及 BrowserUI 接口接入。产品命名空间增加保留规则，阻止同名项目配置替换产品连接器。直接工具、codemode／嵌套调用及通用 MCP resource 入口均核对同一绑定与允许范围。

封闭文本、固定稿件、需求／策略等受限 profile、受管执行与会员资产包受限工作区继续按现有资格判断。保存的任务选择只有在普通项目任务当前具备接入资格时才生效。

### GitHub

使用官方远端 MCP `https://api.githubcopilot.com/mcp/`。首版保留 Pi 1.4.0 原生 HTTP 传输与 MCP OAuth 路径，访问令牌方式由 Host 解析后用于可信服务连接。工具组限定为仓库读取、Issue、PR 和 Actions 的规格内操作。GitHub 远端 MCP 不提供登录服务，OAuth 路径使用用户配置的注册应用，令牌路径使用用户自行核定的账号和仓库权限。[官方 Host 接入说明](https://github.com/github/github-mcp-server/blob/main/docs/host-integration.md)

### Gmail

优先使用官方远端 MCP `https://gmailmcp.googleapis.com/mcp/v1`。最新官方工具目录包含发信、回复与转发。上次可行性答复将发信列为需要额外 Gmail API 的能力，现按新版官方目录修正。[官方工具目录](https://developers.google.com/workspace/gmail/api/reference/mcp)

2026-11-27 静态核查发现，Google 文档采用 `2026-07-28` 无状态 Streamable HTTP、`server/discover` 和 `input_required` 多轮输入；锁定的 Pi 1.4.0 最高声明协议为 `2025-11-25`，其 MCP 连接未注册 elicitation handler。当前证据不能证明换一个 URL 即可直接接通。[官方交互协议](https://developers.google.com/workspace/guides/mcp-elicitation)

选定方案是在 OptraCall 自有代码中通过 Pi 公开 `createTransport` 接缝适配 Google 协议，继续使用 Pi 提供的 OAuth `AuthProvider`。Google 的表单交互映射到现有 BrowserUI，对应原调用的输入、确认、取消与续接。适配器不创建 Agent 会话或另行安排分析流程。

准备阶段已用真实 Pi 1.4.0 客户端及公开扩展工厂完成内存服务替身探针，证明该接缝可完成协议发现映射、工具注册、单表单输入续接、取消及响应丢失时不重放。探针只实现一种表单结构，未运行真实 OAuth、Google 服务或完整 BrowserUI，不代表 GG07／GG08 已通过。

正式产品接线前先完成隔离兼容验证，核对初始化／发现、工具列表、内容、分页、OAuth 挑战、审批续接、取消及副作用语义。新协议和旧协议之间的请求关联必须由原调用持有，普通错误和网络失败不能触发副作用重放。表单不受支持时显示明确错误并结束本次调用。

审批等待仍受原请求的超时与资源生命周期约束。过期、停止或关闭后，迟到的用户决定不能恢复执行。用户确认实际目标即可作决定，界面采用一次明确确认，供应商返回的具体选项如实呈现。

若公开接缝无法保持所需语义，保留失败证据并补充技术方案供用户确认。SDK 版本变化仍按用户指定的精确版本执行。Google 官方 `gwscli` 可作为后续替代评估，但当前未发现可直接复用的标准 stdio MCP 服务入口，其动态命令、账号和审批交互需要另外验证。[官方 CLI 说明](https://developers.google.com/workspace/guides/workspace-cli)

Gmail 的 Desktop OAuth 使用 Google Cloud Personal mode 或适用的组织配置，浏览器与本机回调配合完成授权。真实授权由用户在运行 OptraCall 的设备上完成。云端工程验证使用合成凭据和本地服务替身。[官方账号设置](https://developers.google.com/workspace/gmail/api/guides/configure-mcp-server)

### 腾讯邮箱

本版连接用户现有邮箱。QQ／Foxmail 采用 `imap.qq.com:993` 和 `smtp.qq.com:465`，腾讯企业邮采用 `imap.exmail.qq.com:993` 和 `smtp.exmail.qq.com:465`，均使用经证书验证的 TLS。企业的协议开关、成员状态与安全登录要求按实际账号策略核对。界面直接选择邮箱类型，服务器参数由可信配置提供。[腾讯 QQ 配置手册第 33 页](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf#page=33) · [腾讯企业邮配置手册第 25 页](https://main.qcloudimg.com/raw/document/product/pdf/613_46019_cn.pdf#page=25)

QQ 用户先在官方邮箱设置中开启 IMAP／SMTP 并生成客户端授权码，OptraCall 通过专用密码输入接收该授权码。身份核验按供应商当前密码或扫码流程完成，界面提供官方帮助入口。授权码撤销或账号密码变化导致失效后，显示需重新配置。腾讯企业邮按管理员要求使用客户端专用密码。[QQ 邮箱授权码官方说明](https://help.mail.qq.com/detail/106/985)

自有邮箱适配器复用成熟 IMAP、SMTP 和 MIME 库，经现有 Pi 工具／MCP 接缝提供能力。协议连接、凭据和服务出口归 Host 管理，调用绑定当前任务及服务账号；用户名与授权码通过受控私有通道交付，业务插件得到获准的读取／发送 port。实际采用的库、精确版本和来源在安装前记录并核对。

只读检索使用只读文件夹资格和 `BODY.PEEK` 等无已读标记副作用的接口。邮件身份包含邮箱类型、连接身份、文件夹、`UIDVALIDITY` 与 UID，`Message-ID` 仅作为辅助来源。重建连接或文件夹 UID 发生变化时重新核定，禁止将旧 UID 当作另一封邮件。工具结果包含邮件来源、分页及正文／附件的实际读取范围。

读取资格与 SMTP 发送资格分别核验，IMAP 可读不能单独证明 SMTP 可发送。邮件提交保留每次明确用户操作的关联及内容身份，SMTP 在 DATA 提交后响应丢失的结果保持待核。发送服务不因网络故障自动重放。任务本机草稿与远端草稿分开标识，本版不把本机编辑表述为腾讯远端已保存。

腾讯的 Agently Mail 是单独的 Agent 专属邮箱产品，当前官方说明其与个人邮箱隔离。本版连接现有 QQ／Foxmail 与腾讯企业邮，Agently Mail 的账号和邮箱内容另按独立需求评估。[Tencent 官方 Agently Mail 说明](https://github.com/Tencent/AgentlyMail)

### 飞书

首选当前官方托管 OAuth MCP `https://mcp.feishu.cn/mcp`，复用 Pi 原生 MCP 配置、HTTP 传输和 OAuth。连接页引导用户授权官方应用并选择工具，企业管理员负责安装官方 MCP 应用、用户可用范围和工具放行。真实连接须核对 OAuth、工具发现及使用当前用户身份的完整路径，已有原生 HTTP 能力只作为接入基础。[当前官方接入方式](https://open.larkoffice.com/document/mcp_open_tools/end-user-use-remote-mcp-server)

当前托管 MCP 与官方本地 OpenAPI MCP 的能力集合分别核对。旧专属 Token URL 的官方页面已标为 Deprecated，本版使用新的 OAuth 端点。[旧远端服务说明](https://open.larkoffice.com/document/mcp_open_tools/end-user-call-remote-mcp-server)

官方本地 `@larksuiteoapi/lark-mcp` 可作为后续有明确能力缺口时的替代研究，其应用配置、用户 OAuth、包版本、进程及凭据渠道需另行纳入具体接入范围。[飞书官方本地 MCP](https://github.com/larksuite/lark-openapi-mcp)

云文档与消息工具按实际授权时发现的确切 schema 冻结。工具名称、描述、参数或身份模式变化时先撤销相关派发资格，读回新目录后在原权限内重新核定。消息发送与文档写入按本规格的准确目标和确认规则处理。企业或应用身份与本人用户身份不能互相替代。

### 生命周期、凭据与结果

连接变化并入现有 `policyFingerprint`／`policyCurrent` 和公共资源关闭路径。断开或范围收窄先撤销派发资格，再处理在途调用与刷新，保留失败收尾状态。关闭结果未知时不显示完整断开成功。

优先复用 Pi 原生 MCP 凭据持久化、刷新及旋转。MCP OAuth 的账户绑定包含服务、server namespace 和服务 URL，避免不同账号共用同一授权记录。若为了设置页接入确有公开接口缺口，在实施记录写清相应薄适配和复核依据，保持本轮 SDK 原包与精确版本。

新增 access token、refresh token、客户端密钥及邮箱授权码不进入任务正文、普通 API 响应、前端持久存储、SSE、native JSONL、工具结果、诊断或命令行参数。MCP 日志也需覆盖新凭据脱敏。凭据留在现有 Host 私有资源根的受限文件中，明示普通 unmanaged 会话仍具有同用户原生文件与 Shell 能力这一现有边界。

工具结果和出处进入本任务所选模型上下文。首次启用说明实际外部服务、调用发送的信息与模型出口。Host 按既有授权直接执行普通读取，供应商或组织策略要求的审批由原调用展示并处理。

## 四原则前置核对

Host 管理账号、工具准入、资源关闭和确认交互。Agent 沿原任务自主决定查询对象与工具组合。Pi 复用范围包括会话、MCP 工具循环、原生 OAuth、历史与 BrowserUI。Gmail 协议适配的新增理由是已核实的官方协议版本与交互能力差额。

正常用户必做动作是首次连接账号、按任务开启，以及对确需确认的实际外部动作作决定。应用注册来自供应商账号接入要求，放在首次高级设置中提供可操作指引。协议和工具发现由实现承担，用户不填写运行版本、请求编号或工具 schema。

本确认包的检查仅覆盖准备材料与虚构交互。正式产品接通、真实账号使用和工程合并按后续阶段分别验证。
