## 3. 目标管理兼容验收

1. **候选与确认。** 缺 A、检查点或观察依据时，标题旁操作应聚焦缺项；齐备候选可直接确认。编辑弹窗取消后，还原计划、确认人和说明。示例中的 Agent 推荐／优化由产品真实 Agent 处理；多条计划 A 各自保留唯一行 ID，删除后新增不会覆盖其他行；撤销建议后保留随后手改的文字。旧版和 Case 保留准确引用。
2. **草稿与正式版。** Agent 协作区和拆解结果在桌面同时可读，手机能在两区间跳转。责任、业务维度、时间计划、测算依据和补缺策略可核对。草稿按所选目标、版本、GSA 和修订号保存；预览只读，显式发布后形成冻结表。重开默认正式表，进入修订可恢复草稿。总 GSA 更新后须明确承接旧稿；保留原冻结版、负责人和历史。
3. **阶段与复盘。** 所选实绩须对应冻结计划、原范围、截至原句和证据；部分出数、未知、矛盾分开显示。期末实绩空白显示待补。复盘支持修改、舍弃、恢复和勾选，恢复项保持未勾选；下期候选或回送战略只携带所选结论及原证据。与 Case 的联动保留用户明确的经营取舍。
4. **#141 草稿工具回归。** 继续执行原目标规格 §10 的 DC01–DC05。按真实 owner 分别覆盖 `goal-decomposition` 和 `goal-estimate`；Agent 可见嵌套字段契约，使用顶层写字段。手动比率目标可在无 SAP、无脚本时保存，原已绑 SAP 保持准确版本。未知测算和差额保留 `null`。错字段／错误差额返回可定位的字段错误，原请求所属会话能继续纠正；失败无部分写入，revision 保持。保存成功、可发布、专业验证分别有证据。沿用原 CAS、取消、权限与只读回查。参见[合并差异](https://github.com/gadfly-hbo/OptraCall/pull/141)及[契约测试](../../../tests/goal-decomposition-contract.test.ts)。

## 4. 数据、职责与落地方式

- **日常工作。** 做出决定、选定责任人或期限后，由原决策／行动写入口保存，按真实回执刷新首页。Demo 的“核查三家门店”用来检查聚合和来源关系。项目实际可能没有可分组的门店，或只有局部依据，此时展示可解释的原始记录、范围和下一步。担当者、期限或进度缺失时保留待定。已有数据优先做只读投影；如确有读取缺口，记录字段、来源、作用域与刷新策略，采用最小兼容的查询接缝。
- **两条管理路径。** 战略发布 → 明确承接目标 → 采纳准确 G/S → 创建 Case；业务问题 → 就地采纳 G/S → Case／项目／任务 → 复盘材料 → 目标或战略回顾。既有 Case 与产生时的版本、已保存报告、绩效检查均可复查；每项新关联及发布按原权限判断。
- **Host 与 Agent。** Host 提供授权范围、原始数据、版本持久化和操作回执。模型组织方案、使用工具和纠错，继续走官方 Pi 1.4.0 / Interface v3 与既有会话 owner/profile。目标拆解、确认前测算和项目任务按各自已实现的 owner 恢复。首页聚合、通用导航和原文回看仅作读取。目标到期复盘沿用首次或证据变化时按条件自动拟稿、同证据去重及原在途请求恢复；选用实绩报表沿用即时核对。明确采纳、发布、授权、经营决定由对应负责人操作。[会话接入](../../../docs/agent-session-integration.md)
- **数据与兼容边界。** Demo 的模拟 Agent、场景切换、`sessionStorage` 和 hash 是演示设施。生产复用本机保存、既有导航、读写模型和来源权限；沿用旧数据、归档记录、多人授权及失败恢复。超时、结果未知、版本冲突等回到原请求；演示中相同按钮的提示不能替代生产回执。实现若需要新增业务写模型、修改状态转换或改变已确认 UI，应在本单给 PM 记录具体差异和受影响路径。
- **交付证据。** 31 项 DOM 交互、80 条唯一 hash、重开恢复及 GSA 修订承接是对确认件的检查。真实 Host/Pi 回执、桌面／手机渲染和独立产品复核由开发候选提供。以[工程规范](../../../docs/engineering-workflow.md#github-开发任务外发与交付)执行发单、领取和交付。
