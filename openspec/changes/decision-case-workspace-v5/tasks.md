## 实施顺序、交付与审核

- [ ] **领取。** 读回原单及实时评论，确认分支占用，以最新远端 `main` 建独立 worktree。按规范留言领取并回读。把本确认包原样带入候选，通过固定提交取得文件；保持实现分支基于实际领取的主线。
- [ ] **范围盘点与 TDD。** 先核对普通启动、深链恢复、首页所需的真实读模型，以及已有组件／写入口。用合成业务资料和现有入口复现适用差距；留存这些路径的改前证据，已成立的主线契约作回归。按 W01–W04 完成日常主路径，再完成 W05–W08 的接入，W09 随各阶段验证。
- [ ] **工程验证。** 在候选运行 `npm run check` 与改动接缝的定向测试，记录命令、候选 SHA 和结果。可复用 `tests/browser-goal-ui-alignment.mjs`、`tests/browser-issue-138-goal-trial.mjs`、`tests/goal-decomposition-contract.test.ts` 及现有 Case、项目、报告、设置、Studio 浏览器用例；首页聚合、深链优先和跨页返回缺少覆盖处补回归。隔离 Host／合成 Provider 与真实产品 UI 结果分别记录，列出失败、跳过与未验证项。
- [ ] **交回 PM。** 在任务分支提交源码、适用测试和仓库内结果，记录四原则专项（Host 环境与权限、Agent 自主执行、Pi 原生复用、最少用户操作）。说明兼容及回退路径，回读远端完整候选 SHA，在原 Issue 交接并停止向该分支写入。
- [ ] **PM 审核与结案。** 对最终候选组织非作者独立复核，按原单处理返工与二审。集成最新主线复验，以关联 PR 的实际 head CI 为依据；在获授权范围内合并，核对主线 push CI，再回填原单并结案。工程结案、双端设备更新和用户体验确认分别记录。[工程规范](../../../docs/engineering-workflow.md#github-开发任务外发与交付)
