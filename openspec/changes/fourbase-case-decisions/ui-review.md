## 优先审阅的三个情景

1. 在S1“扩大门店补货授权”点“小范围试行”，随后在左侧正常发送预填新材料：Agent追加H1 v2／S1 v2，解释原前提被反证；S2仍为原版。S1旧v1选择及A1进行中均保留，当前v2未被自动选择。
2. 展开“更多选择”，可选先补证、暂缓、不行动等并附可选理由。折叠的并发示例中，新稿到达会保留选择草稿；历史明确选v1仍准确落在v1。选择不会执行真实动作、改Board状态或当作效果证明。
3. 从左侧看原行动／反馈，对明确策略关联准确F1 v1再请Agent重看：关联会留下新的卡片修订，访谈做过但日志未齐，效果仍未知；原处已有F1 v2也不会替换旧依据。来源详情同时演示准确版本正文失读，保持UNKNOWN而不偷偷读latest。

可选的“整理这条记录”放在详情中：人的归档／恢复追加新修订，当前列表隐藏归档条，历史保留。人的关联／治理操作与沿用的Agent正文作者分开，原来源不会因为卡片升版而改变。不新增完整人工正文编辑器；专业纠正继续沿原任务提问。

底部默认折叠的“演示情景”提供五个引导和自由点选，仅帮助审阅，不是Agent内部固定步骤。可同时体验无Case普通分析、Case零记录、只读保护、冲突及业务已保存／native ACK未知后查原操作；这些是内存逻辑表达，不证明产品的原子写、回执、迁移或取消已实现。

## 交互与合同核对

| 正常行为 | UI表达与对应规格 |
| --- | --- |
| 原任务继续问即可 | 主输入始终突出，不先填假设／计划表；有Case也可零草案，无Case不创建Case。CD01、D01/06 |
| 判断和方案可逐渐变 | H1/H2与S1/S2各自身份、版本及作者；有明确未知和来源，策略可无单一依赖。CD02–04、D02/03 |
| 真正决定时人再选 | 常用动作直达，更多动作／理由按需；未选≠拒绝，旧版选择不自动沿用。CD05/07、D04 |
| 原行动／反馈只维护一次 | 原入口／关联时观察／当前状态分开；人的关系新增留新卡片版本，不修改原行动／反馈；拟议计划、真实执行与效果未知分开。CD06、D02/05 |
| 历史和异常可理解 | 原选择、旧稿、来源失读、并发草稿和原operation回读分别展示，不静默覆盖或重放。CD07/09/10 |

身份／hash等技术字段置于按需详情；没有新初始化按钮、方法配额、每日维护或为了继续操作而关闭保护的指引。允许自由查看旧记录，真正写入仍受Case／项目／profile等边界约束。

## 产品实现核对（2026-11-04）

产品复用原Case详情对话框、原任务聊天和原看板，原型的独立演示页面不复制成第二套导航；不声明逐像素一致。已批准的正常续问、准确版取舍、旧选择、来源／历史、关联及归档恢复行为均有实际HTTP／产品浏览器证据。作者10片真实动态RED及root追加缺省理由第11片、非作者9组实际UI与最后6项理由／首稿边界通过；详见[实施记录](implementation.md)。1440／320布局和键盘／Escape按报告范围验证。

产品额外按真实接口披露指定反馈交接范围及正文片段；未说明变更理由的后续稿显示“作者未说明”。人的待核意图由现有App临时状态保留，支持同App关闭／重开和页面切换，不承诺硬刷新／崩溃恢复，也不增加持久运行账。批准Demo原字节、准备阶段虚构边界和所有原反例保持。
