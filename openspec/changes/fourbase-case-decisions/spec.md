## 要解决的问题

一次分析形成的判断和方案不应只散落在聊天、报告和行动备注中。新证据出现后，用户应看清：原来哪项前提被修改，哪些方案被作者明确建议重看，自己当时选的是哪一版，原行动和实际反馈又是什么；旧判断、旧选择和原文都保留。

M5沿[整体方案v1.2 §6](../../../docs/fourbase-doublebase-plan.md#6-决策学习假设策略行动与实际反馈)和[模块索引](../personal-assets-phase01/tasks.md)增量补齐。进入本次准备的依据是用户明确要求继续M5，不宣称已经读取真实业务库、证明持续使用频次或选定真实经营试点。M4本地工程已完成，固定输入见`.local/fourbase-modules/m5/baseline.json`；原真实专业FAIL／UNKNOWN、M31 NOT_PROVED和M4流程证据范围保持。

## 现有能力与新增差额

复用原Case／项目关联／成果／操作与历史、RAP发布、Board建议／行动、精确FeedbackRevision与复盘回流、Pi原生会话及M3.1／M4。Case的judgement／nextStep／notes可写叙述，但没有多条业务假设／策略的稳定身份和独立修订。BoardItem是报告建议及其当前采纳状态，不是完整策略对象，也没有完整选择历史。BoardTask已有owner／dueDate／note，Feedback已有修订，不新建替代系统。

本期只新增Case内两种有版本的业务记录（假设／策略）、作者声明的准确证据／依赖、人的独立取舍及原行动／反馈关联。它们是Case业务语义，不是第二份Agent消息／记忆库。原生候选或RAP只是可选来源，不自动晋升为正式假设、真相或人的选择。详见[复用与四原则核对](reuse-audit.md)。

## 产品行为与验收

| 标识 | 可观察结果与反例 |
| --- | --- |
| CD01 正常低操作 | 从已明确Case的原任务直接提问／发送，Agent可自主保存零条或多条Case草案；不先填假设表、审批读取、收藏或逐条确认草稿。无Case任务仍正常分析，不强制建Case。 |
| CD02 准确业务记录 | 假设和策略各自稳定ID、独立追加修订、作者及原依据可回读。Agent生成／修订明确标Agent草案；判断标签不是Host真值评分，不从Board confidence或引用数判成立。 |
| CD03 证据与未知 | 支持／反对／背景／限制是作者声明的关系，准确原文版本与当前可读性分开；范围／业务时间／未知可空。不回落latest、不以材料缺失证明主张被推翻。来源不足仍可保存有边界草案。 |
| CD04 依赖与反证 | 策略可依赖多条准确假设修订，也可零依赖。Agent／人明确说明哪些前提、结论、方案改变及哪些未受影响；Host只展示已记录关系和版本更新，不自动推断因果、撤回选择、改旧报告或重新派发行动。无显式说明不显示“没有影响”。 |
| CD05 人的取舍 | 对看到的准确策略版一次选择，理由可后补；试行、补证、暂缓、不采用、不行动、继续、调整、停止考虑各自表达。未选择不等于拒绝；新Agent版本不继承旧版人的选择。允许不同策略各有取舍，不强造唯一赢家。 |
| CD06 行动／计划／反馈 | 原BoardTask／Feedback仍各持权威，M5只关联；责任、范围、实施或补证时间、复核／退出、观察及风险可逐渐补充。已有owner／dueDate／note只在原行动维护，不复制成可独立编辑字段。选择≠执行≠效果，正向反馈／SimLab≠因果成立。 |
| CD07 并发与UNKNOWN | 卡片按自身expectedRevision；人的取舍按稳定策略跨版本的最后choice事件CAS。出现新版本保留草稿，不静默选新版。已完成同operation先读原结果，随后Case关闭／源失读也不改成新意图；不自动重放模型／业务动作。取消前已提交记录保留，未提交的晚到写拒绝。 |
| CD08 权限与连续分析 | 沿原project-tasks／Interface v3、Pi1.4.0。当轮真实Case绑定及project/link/owner决定写范围，模型不能填写用户作者／任意Case／路径／权限；无绑定不猜首末Case。普通unmanaged可读／写草案；managed ordinary／cold／sealed／插件不增工具权，不教用户关闭保护换便利。 |
| CD09 保全与兼容 | Case关闭／项目归档及卡片归档保持各自只读边界，历史与原文件不删。原Case schema1严格库存导致直接加表会阻断旧程序；候选明确schema2迁移与兼容回退，不以恢复旧DB覆盖新工作。GET不升级。 |
| CD10 状态可信 | 保存的Case业务修订／operation回执、Pi实际原生结果、人的取舍、原行动／反馈分别报告。nested子正文没保存只记UNKNOWN，不为了日志禁合法组合。Demo为虚构内存，不当产品／迁移／模型验证。 |

## 推荐最短路径

Case原任务输入新材料→正常发送；Agent自主查读、分析并按需要保存草案。用户可直接看当前判断／备选及清楚标注的未知，历史／来源／计划按需展开。只有真正要作经营取舍时，对准确版本点一次“先补证”等操作；它不创建／采纳Board建议、不改行动状态或派发真实动作。若要承接行动，继续原看板入口，或把明确已有行动关联回来。

新反馈在原入口保存一次；Case引用指定反馈修订及可得的原交接范围，再由人／Agent解释是否改变判断。到复核日期不自动跑模型或提醒；日期是记录。M5不做M6成熟晋升／增量评测平台、M7数据库／图服务、团队审批、全局依赖引擎或外部执行。
