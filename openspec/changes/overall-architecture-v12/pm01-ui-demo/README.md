## 查看与运行

从仓库根运行：

`node openspec/changes/overall-architecture-v12/pm01-ui-demo/run.mjs`

默认隔离地址 `http://127.0.0.1:43131/`，不占用4173/4174/4175。可用`--port=43133`选择其他隔离端口。运行PID/停止方式保存在 `.local/v12-pm01-fix/ui-preparation/runtime.json`；仅停止自己的PID，保留证据。原产品来源sha在source-manifest.json；来源漂移时Demo拒绝启动，不能偷偷使用另一版。构建及内存变换回执只写 `.local/v12-pm01-fix/ui-preparation/`，不写原`.local/v12-implementation/`或旧Demo证据。

入口仍为原App“战略与目标”→“与Agent讨论战略”。打开“调整本次背景、模型与资料（按需）”。页面顶部灰色演示条清楚标识替身。无资料项目时，只沿当前说明/准确Goal讨论，不开放全局项目。

## 相比当前产品具体只改哪里

1. 原“资料所在项目”仍是本次明确背景所在范围。其下新增一个范围选择：
   - **在本项目获准背景内自主查找**：新讨论明确选择资料项目后采用此默认；不要求逐项勾选。只开放原资格允许的背景目录，不等于全项目、业务明细或新增grant。
   - **仅使用我手选的资料**：用户自愿收窄；空清单就是不使用项目背景，不能退化为自动模式。
2. 原“查看可选背景资料”是可选管理入口，正常自动查找无需先点。目录行在自动模式的手选标为“优先参考”，在限选模式标为“本次使用”。明确“排除”是独立选项，与手选互斥、优先于两种模式。
3. 目录项文案明确“尚不代表已读取”；演示回复区分别说明目录数、实际一项读取及返回范围。真实实现的准确native来源/下游核权由Root补原接缝，Demo不伪造其证明。
4. 旧讨论缺少新scope字段时保持原手选限选，不自动扩大。用户可对**后续请求**明确调整范围；原native、准确来源与已采用目标不回填、不改写。

只有上述原资料区交互变化；不改主导航、GSA/BSC、模型设置、目标采用、Case/Plan/Task或专业方法页面。不新增普通读取逐项审批，不增加正常使用必做理论/表单。

## 可点击场景

| 场景 | 操作与期望 |
| --- | --- |
| 默认自主查找 | `/?scopeScenario=auto`；展开资料区，选择“会员复购改善（合成）”，不点目录、不手选，发送“沿本项目经营计划讨论战略”。合成回包展示发现3项、仅读取经营计划准确v1/按合成正文实际长度计算的范围，其他目录项未读 |
| 显式限选 | 同页选择“仅使用我手选的资料”，可选点目录，勾“会员口径说明”的“本次使用”，发送；只能从该准确选择回包 |
| 明确空限选 | 选择限选但不勾任何项，发送；没有背景正文返回，仍可继续当前说明并说明缺口，不默认全项目 |
| 排除 | 自动模式→查看目录→排除经营计划；即使另有偏好也不读被排除项，合成回包只能选剩余背景。排除后该行偏好不可勾；显式取消排除可恢复 |
| 无项目/无目录 | 不选项目直接发送，或`/?scopeScenario=empty`选项目；准确说明当前范围无可用背景，不能称资料齐备 |
| 旧讨论 | `/?scopeScenario=legacy`，原讨论下拉选择“原讨论 · 保持原手选范围”；展开资料区显示仅限手选与原一项。不得默认扩大，后续明确调整才生效 |
| 修正前对照 | `/?before=1`保留现有产品资料区及手选行为；sources空时合成find目录为空，可说明本次修复的操作差别，不当实际运行故障复现 |

“查看演示范围/实际回包”只看本页内存状态，目录记录的`bodyRead:false`与`actualReads`分开。它不是产品新增后台账本。

## 待确认及复核边界

工程规范第3节要求实质UI/关键交互先出可点击Demo并由用户确认。这里新增了区分自动背景与明确限选的控制，影响原手选语义，属于该门适用范围；不是仅换一个文字。因此只补此处确认，不重新讨论产品方向或为普通后端读取逐项审批。Root可在等待此处确认时继续已授权、无UI依赖的后端TDD/集成。

当前构建已通过；实际浏览器点验/截图由Root统一执行并另留收据，不能以构建冒UI通过。没有修改src/tests、SDK、Skill、依赖或旧Demo。正式UI实现待此受影响Demo确认后由工程接续。
