## 3. 工作台与正常路径

四个一级页签依次为「战略共创」「战略检验」「战略发布」「版本管理」。共创承载启动和方案成型两个阶段。顶部定位事项与适用范围，主区域承载当前阶段与同一事项的主对话，右侧显示该事项的文件。检验显示准确锁定版和两道检验进度。发布集中呈现方案与证据，决策者审核后操作。版本管理提供开题、候选、检验与发布的历史回看及原讨论入口。

文件视图复用分析工作区的组织方式。每个事项拥有 `010_draw` 原始资料、`020_clean` 整理资料和过程产物、`060_reports` 报告。右栏展示有权限的事项共用资料及当前范围专属资料。已锁开题可在获准范围内分别应用，切换范围保留各自的应用指针、访谈及新上传材料。可选关联既有项目，Host 先核对真实 projectId、当前权限和允许引用的来源。版本使用固定文件引用。上传、查看、记录材料及导出沿既有权限处理。目录名称用于组织材料，原始文件权限、产物写入范围和候选间隔离由 Host 单独核对。分析工具接入使用获准项目工具和明确作用域，文件树本身不授予工具权限。

最短正常路径为「持续对话 → 核对并锁定开题 → 应用开题 → 生成并比较候选 → 锁定候选 → 执行两道检验 → 集中审查并发布」。历史、资料指定、模型切换、展示模板与执行侧承接按需使用。

### 3.1 阶段一 · 战略开题

1. 主 Agent 使用 `grill-me` skill 多轮追问，配合顾问的核心高管访谈确认研究边界，重点追问会改变战略判断的歧义。根据获准资料、来源和任务需要使用 `deep-research`，覆盖外部环境、内部能力、业绩差距与机会差距。如有历史经营资料，可显式选取并用于诊断。对于新业务或资料暂缺，允许沿用公开资料、用户已知事实及明确的假设开题，未知随报告保存。
2. 开题报告有稳定字段和版本。包括战略事项、组织与业务范围、时间视野、现状及外部变化、3–5 个待回答的关键战略问题、可核查依据、事实与假设、缺口及后续方案形成要求。关键问题说明为什么影响选择。来源精确到获准文件或公开来源依据，资料不足时如实记录依据强弱。
3. 决策者可在主对话提出限定修改，核对变更后按 §4 另存。锁定前展示当前确切内容及来源。锁定为已保存报告版本及其内容指纹追加人工凭证。点击「应用开题」后，所选锁定版成为阶段二的固定输入。另行锁定开题修订版仍须明确应用，已有候选保持原开题引用。

开题 Schema 校验版本、事项与范围引用、时间视野、诊断摘要、战略命题、来源和待补证字段。每个命题有稳定 ID、问题、为何影响选择和依据／缺口。命题数量及引用关系均有效才可提交人工审核。上期经营复盘允许标记不适用；缺失证据可记为未知。Schema 通过表示结构完整，事实和经营判断由审核及后续检验核对。

### 3.2 阶段二 · 战略方案

1. 候选基于同一份已应用的锁定开题报告，各自说明公司层与业务层方向的关联、使命／定位、3–5 年增长逻辑和目标、明确的选择与放弃、资源倾斜与取舍、成立条件、关键假设与风险。分阶段战略动作、战略地图、既有方法或模拟可作为方案的内容与佐证。执行侧的部门任务与行动授权沿原流程确认。
2. **每个新候选版本独立使用一个可持久重开的 Pi 会话。** 同一版本准备过程中可以在原 owner 内继续对话。确认立新的候选或修订版本时，Host 为其分配新的 owner 与 native 记录并冻结基线。同一请求核对或重试沿原操作与会话归属。两个候选带回各自的来源、依据、候选稿和状态。主窗口展示进度和可回看的会话入口，成果回来后由主 Agent 按同一开题比较候选、分析取舍和不确定性。
3. 决策者在候选详情中核对内容和证据，可要求限定修改或锁定所选准确版。锁定后原正文和来源作为检验基线。主 Agent 的汇总、候选生成完成和候选选中均无锁定效力。

### 3.3 战略检验

以人工锁定的方案内容指纹为输入，串行执行两道检验。决策者在发布页集中审核两道 Agent 结论，检验页负责启动、查看进度与证据。
现有地图因果连线审查、战略假设比较和经营情景模拟可按需作为检验材料，试算数值标注参数与口径。

| 顺序 | 检验 | 可核对输出 |
| --- | --- | --- |
| 1 | TOC／TP 因果检查 | 根据约束、诱因、干预与目标结果检查关键因果链，列出有证据支撑的因果关系、缺环、反例及可能的副作用，给出结论 |
| 2 | 战略假设逻辑检验 | 对关键战略假设、边界和备选解释检查逻辑及支持强度，明确可反证条件、仍未知的证据与需要监测的方向，给出结论 |

每道检验给出通过、不通过或依据不足／无法判断，附关键发现、来源、准确版、执行时间及原会话。第二道在第一道有效通过后自动启动。技术状态另外可见，包括等待、运行、失败、取消、中断与结果未知。技术完成须有可读的业务结论，技术失败或未知保留实际状态、原始依据及已取得的中间结果。业务不通过或依据不足均停止后续检验和发布，保留原报告，可改选候选或回到共创修订。需要新增证据时，将证据写入新候选后重锁与重检。技术中断先读回原操作结果，再按实际状态继续或显式重试。Host 验证两道通过凭证同属本方案指纹及同一条串行检验链，Agent 依据检验材料自主选择分析方法。

### 3.4 战略发布、承接与版本管理

发布页供决策者集中审查开题引用、锁定方案及结构化内容、两道 Agent 结论及证据、未决条件和发布影响。可选切换展示模板，模板只改排版和呈现，沿用准确正文、结论和证据。决策者选择「正式发布」时，Host 再核对锁定、两道通过凭证、事项与治理范围。

- 同一战略事项加同一范围同时最多一条有效发布。新版本在通过检验和明确发布后原子替代旧有效版，保留两条记录与替代关系。范围通过稳定归属标识区分，单纯改显示名称不会另开一个有效发布。
- 撤销需要明确确认，记录保留。已经撤销的同一锁定版不可重发。恢复发布取新候选版本并重新锁定、检验及审查。撤销停止新增承接，已有承接、已采用目标和已关联执行材料继续按准确来源回看。
- 发布后可选择「带入目标管理」，明确承接范围、目标与关联策略，按现有机制保存为目标候选。目标采用、Case 绑定、项目／任务启动与经营动作授权各走其原有入口。发布和撤销本身仅变更战略发布记录。
- 「版本管理」按事项查看开题版本、候选及父版、检验批次与结论、发布与撤销记录、承接回执和原会话。部分来源不可读时保留版本身份及原因，限制受影响动作。历史失败或 UNKNOWN 仍以原事实展示。

## 4. 限定式修改合同

适用对象包括开题报告和战略候选正文。用户在对话中描述修改意图。能映射到明确对象时带出目标和拟议修改，有歧义时只追问变化范围。系统展示基线版本、修改目标、旧值及新值、可能相关的待核项。超出授权的联动内容须先在对话确认扩大范围，用户依然可以只采纳原范围内的修改。

Host 从准确基线装载正文，校验版本、内容哈希、有效权限、目标 ID、预期旧值和操作类型。结构化内容按稳定字段／章节／节点／连线 ID 应用许可补丁，明确区分新增、更新、删除及移动。叙述正文按稳定文本块定位并核对原字节哈希，Host 仅替换已授权片段；其他文本块以原字节和顺序复用。合并后生成实际差异，越界、歧义、旧值冲突或结构不合法均拒绝保存，原候选及原件继续可核对。典型负例包括无授权改写标题、删除相邻段落、重排未选节点、改写原引用或重写整篇正文。隐含关联规则只用于提示影响，作者或 Host 都不能顺手修改其他位置。

按已核对的差异另存新版本，保留父版、用户原请求、修改范围、差异、作者及来源，原文件、锁定版、原生历史、检验及发布证据保留。开题修订的独立凭证须再次人工锁定和明确应用。候选修订还遵循每版新会话，重新进入候选态。可借用现有固定材料修订与新稿另存形态，以及地图冲突对照组件，Host 局部白名单校验属于本次新增要求。

## 5. Host、会话与资产契约

### 稳定身份与状态

| 记录 | 最小准确引用及变更约束 |
| --- | --- |
| 事项及范围 | `initiativeId + scopeId`。范围持有实际组织／业务归属，文件、主会话和下游承接做归属核对 |
| 开题版本 | 事项、版本、内容 SHA-256、来源引用、父版、生成回执。锁定单独记录操作者与时间，应用结果引用准确锁定版 |
| 候选版本 | 事项和范围、候选及版本、父版、开题准确引用、内容 SHA-256、候选会话与原生回执。锁定后仅追加治理记录 |
| 检验记录 | 候选准确引用、检验批次与门次、前序通过凭证、Agent 配置修订／会话／请求、依据、技术终态及业务评价 |
| 发布及承接 | 事项与范围、候选内容指纹、两道检验准确回执、人工发布动作、状态及替代／撤销链。承接引用发布与目标候选准确版本 |

候选、锁定、检验与发布按各自权限推进。每道检验及发布只对命中的准确版本生效。换版、来源撤回和冲突应明确提示，定位失败时保留原选择。撤回原资料影响对它的再次读取、验证和新承接，历史记录保留已发生事实。可按准确存储身份撤销原发布。无可承接目标时仍可发布，通过目标承接入口提示缺少目标。并发发布、撤销与承接沿现有 Host mutation queue 串行校验，落盘前重验归属、前置状态与期望版本。发布替代在同一原子变更中完成。重复操作按动作、准确引用、操作 ID 和请求指纹读回原回执；回执不明先只读核对，刷新、断线重连和应用重开不隐式触发新 Agent 请求。

### 统一会话及四原则

- 工程规范 v1.12，统一 Agent Session Interface v3，官方 `@earendil-works/pi-coding-agent` 锁定 `1.4.0`。沿现有 Host 的会话注册位置与依赖入口适配，复用 `createAgentSessionDomain`、owner-bound Ref、受限 Port、原生会话读回与生命周期；暂以「战略事项」「候选版本」「检验环节」描述业务 owner，实际类型名由后续实施核定。主 owner 绑定事项与范围，候选 owner 再绑定其独有版本，检验 owner 再绑定锁定候选、检验批次与门次。Host 按已准入配置 ID 和 revision 冻结会话的配置，按 owner 控制订阅、停止及关闭。资源管理由统一 Host 入口持有。
- Host 负责资源、许可、固定材料、流程与写入门禁。Agent 负责澄清、资料选择、研究、可行方法、战略方案、对照汇总与检验结论。决策者负责关键范围、开题锁定与应用、候选锁定、发布、撤销和按需承接。保留工程可靠性路径中的安全错误、技术限额、原输入与失败回执。
- 优先借用分析项目文件、既有研究资产、需求框架的人工确认与固定来源、目标角色会话的候选回传、核算修订的只读另存以及现有战略发布和目标承接原语。前台内存 subagent 可服务研究内部委派。候选独立会话由现有统一生命周期承载。分析能力与工具挂载按已准入环境复用。基线已有 `deep-research` 分析资产，`grill-me` 产品资产来源与接入待核定，新增或变更 Skill 沿工程规范完成测评与接入。两项 Skill 的实际激活和可用工具在隔离环境验证。无可引用检索结果时报告事实状态。
- 新增人工步骤限开题锁定与应用、方案锁定和集中发布等具有治理效力的动作。普通生成、检验步骤、权限内资料读取和运行状态回读由系统与 Agent 完成。配置细节、原生 ID 与历史按需展开。

### 兼容与失败边界

既有战略讨论原生历史、地图版本、模拟、老文稿交接、地图发布记录、已承接目标与下游关系原位保留并可定位。历史产物按旧契约读取、核查来源和导出。建议将已经生效的旧地图发布继续留在旧流程，可按旧版准确身份和现有权限完成承接。旧入口仅处理原有记录。旧发布不补造新制开题、锁定或检验凭证，也不计为新工作台的当前有效版。旧成果进入新事项时，沿新候选、锁定、检验及发布流程确认。既有历史文稿的 GSA 交接沿原合同处理。数据接入优先读旧结构及增加带版本的记录，仅在实施证据确有需要时采用显式、可核对的迁移。应证明回退产物可读性，保护升级后新增材料和原版；有不兼容时提交可核定范围与回退路径。

错误区分权限或来源失效、版本冲突、业务未通过和运行失败／未知。提示带回目标、原输入和接续位置。迟到结果以 owner、请求、版本和当前会话代际核对，取消后的迟到回执不推进状态。原生历史与正式资产不由恢复脚本伪造或覆盖。用户授权、工程验证、真实专业质量、CI、设备运行采用分别核定。

## 6. 验收

| ID | 可核对验收条件 |
| --- | --- |
| SS01 | 四个页签、共创的两阶段和原位的右侧文件树可定位。切换事项／范围不串材料或运行状态。复盘与重构仅可查看占位说明 |
| SS02 | 有历史经营资料和无历史资料两种输入均能开题。报告真实呈现 3–5 个关键问题、依据、假设与证据缺口，显示多轮对话与研究来源 |
| SS03 | 草稿不能用于阶段二。锁定并明确应用后，候选请求传入准确开题版本及指纹。换用开题新版后，旧候选仍能定位旧开题 |
| SS04 | 用同一开题生成至少两个候选，证明拥有不同持久 Pi 会话、相同开题引用和独立输出。停止一条、关闭主窗口再重开或重连、失答均可读回，未经显式操作不产生重复派发 |
| SS05 | 主窗口在正确事项下收到准确候选，可打开各自原会话，主 Agent 展示同口径的战略比较。候选含公司与业务层、使命／定位、增长、选择与放弃、资源及假设 |
| SS06 | 对开题和方案各做一次限定修改，验证所选字段或文本片段变化，未选内容、顺序、原件字节与旧证据保留。有效修改另存，越界、基线错版、来源被撤回、重复回执与迟到结果均按合同处理 |
| SS07 | 锁定行为绑定准确版本与指纹。编辑锁定内容时始终建立新候选并新建对应会话，旧锁定及检验记录可回读 |
| SS08 | 启检后按 TOC／TP 因果与战略假设逻辑串行执行，第二道仅在同批第一道有效通过后启动。两道均落证据、来源和结论，运行状态与业务判断分明 |
| SS09 | 检验不通过、依据不足、技术失败、取消、失答、配置变化及迟到结果均不能制造通过或发布资格。改稿、改选及核对后重试可按明确状态使用 |
| SS10 | 发布页集中显示两门证据、准确版和未决项，切换模板的内容指纹一致。跳过人工确认或绕过页面提交旧版／错指纹／旧检验或未通过结果，发布凭证与有效态零写入 |
| SS11 | 同一事项同一范围仅一个有效发布。新版替代、其他范围并存、撤销后不可同版重发、重复和并发请求都按准确身份和实际已存状态处理 |
| SS12 | 发布不创建目标。当前有效正式版经用户选目标后仅保存目标准确候选与发布来源。撤销或替代后拒绝新承接，旧目标及执行侧关联可按准确版本回读 |
| SS13 | 版本历史可查看、筛选和回到原讨论，区分未发布、新历史、旧记录和失读。旧地图、模拟、战略文稿、既有发布及 GSA／Case／项目历史经兼容验证 |
| SS14 | 用正常 UI、公开 HTTP 和隔离的真实 Host 接缝验证权限负例。未获准文件、越界路径、跨事项候选、旧配置及撤回来源按合同拒绝。与论证无关的旧证据仍可如实保留 |
| SS15 | IN01–IN07 验证统一入口、准确 Pi 版本、取消、配置切换、晚到事件、保存、重开和受影响旧消费者。使用真实 Pi SDK 的隔离合成链路，收录实际测试输出 |
| SS16 | 同一候选通过适用浏览器、完整 `npm run check`、独立规格／标准复核和四原则专项检查。分别记录通过、失败、跳过、未运行及结果未知。产品验收、真实业务质量、远端 CI 和运行采用以对应证据为准 |
