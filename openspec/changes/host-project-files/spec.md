# 项目文件绑定能力复用

2026-11-11 · 用户授权实施、验证及 Git／CI 后合并。五份已审核设计按[固化基线](../../../docs/analysis-decision-workflow-baseline.md)保留，后续另开会话开发。

## 目标与接缝

把隔离试验中已验证的确定性资源绑定接回正式普通项目任务。Host 从真实项目和任务提供目录、权限及准确回执，Agent 自主选工具、方法、保存时机、文件名和正文。复用项目共享的三目录及现有 Pi 1.4.0 公开文件工具、原 Host 会话与 IPC、`ProjectStore.captureFeedbackFile` 同句柄捕获和原企业资料目录。

工程规范 v1.10，Interface v3，owner 为原 `project-tasks` 的 `projectId/taskId`，当前父请求、会话及 call-local 资格经既有工具上下文和 Host 回调核验。只对已有非受管普通项目任务提供本次可选窄能力。受管、核算、固定文本、source-reader 与需求等专用 workspace 沿原工具和执行边界，不通过新文件回调绕开受管执行器。Bash 已从 `020_clean` 启动，保留原生配置。

## 可观察合同

| 标识 | 结果 |
| --- | --- |
| HPF01 可选保存 | `write_report` 只收单一文件名和正文。Host 绑定当前项目已有的唯一 `060_reports`，精确保留合法文件名，同名冲突报错且不覆盖。保存使用 Pi 公开 write operations 和现有 Store mutation。回执关联项目、任务、请求、会话、实际原生调用、路径、字节和 SHA-256。正常直接与合法 `codemode` 嵌套调用均可用。原生父投影会省略嵌套结构详情，成功回执另沿同一 Pi 会话的 `optracall.project-report-write` 自定义记录保留，内容不追加给模型。 |
| HPF02 可选读输入 | `read_input` 绑定当前项目 `020_clean`，Agent 自主选一个文件名，可按 Pi 原生 offset/limit 分页。同句柄捕获实际字节，Pi 格式化和截断后过 IPC。原生 read 自主发现、读取子目录和其他获准资料的路径继续可用。 |
| HPF03 可选读目录 | `read_catalog({})` 读取本机现有企业资料 Store 的当前可用目录，只含原 enabled 范围。原目录权威和权限继续生效，空目录可正常返回，来源内容作为资料。无新增资料授权或试验投影真值。 |
| HPF04 原能力与自主性 | 普通 read/write/edit/Bash/组合能力继续可选。工具描述说明用途。普通文件写入也可保存最终报告，Host 只记录实际操作，避免按文件名或最近更新时间猜主报告。正式提示不要求最终报告必须调用 `write_report`，不规定工具顺序、复核次数或新用户审批。 |
| HPF05 生命周期 | 新能力复用现有 Host callback、IPC 与 call-local 资格。Host 文件操作计入父请求占用，停止／关闭会取消并等待安全收尾。发布前重核资格和 signal。发布后若仍具备当前调用资格，则把成功回执保留在原生会话，沿现有净化规则。若停止发生在发布与回执之间，实际文件保留，回执按未知处理。取消、旧会话、跨任务和迟到内容不进入新请求。未知状态下按实际文件核对，无自动重放。 |

## 实施与验证边界

允许修改项目文件能力适配、ProjectStore 的精确不覆盖保存、原 project-runtime／project-session／server 薄接线、准确 SDK tool factory 消费规则和相应测试。复用成熟的公开 SDK 能力，官方包与版本按原锁定规则。旧试验指引和隔离脚本作为证据保留，试验执行器、平台沙箱和供应商试验路由留在原试验目录。

验收从项目 Store 公共方法、工具合同和真实 Host HTTP → Pi → 本地合成 Provider 入口核对。先保留缺失能力的 RED，再实现 GREEN。覆盖精确自选／指定文件名、同名并发和冲突、路径与链接拒绝、文件变更、长输入分页、只读授权目录、原生普通写入、直接与嵌套、取消及同会话续接、各 profile 不增权。最后运行完整 `npm run check` 与相称依赖审计，做独立规范／规格双轴和四原则最终检查。无新增 UI 操作，UI Demo 不适用。工程合成证据与真实分析效果分开记录，本轮不重启已收尾的准确率对照。
