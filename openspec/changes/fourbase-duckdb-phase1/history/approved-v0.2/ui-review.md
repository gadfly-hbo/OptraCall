## 用户路径与现状差额

| 路径 | 人必须做什么 | Agent／Host职责与可删除步骤 |
| --- | --- | --- |
| 正常分析 | 原任务表达目标、发送；查看回答 | Agent选Python/DuckDB/混用并核查，Host给原环境／文件／状态。新增必做动作0，不先选库／写SQL |
| 查看计算依据 | 用户有需要时点“查看计算依据”，按需打开文件／版本 | 沿原成果／文件，只展示实际来源与记录。不要求先固定所有表、填写运行manifest或逐条核准读取 |
| 自愿长期固定来源 | 沿原“记此稿来源”及原回执 | 用户明确需要时保存原已产出材料的固定副本；不自动发布或把未固定普通文件标成长期证据。此为原可选管理，不是DuckDB前置步骤 |
| 文件上传／超限 | 沿原上传；错误时用户可换获准文件或继续现有资料 | 普通main22类型/50MiB与拟议M2五类/50MiB、文本来源100MiB分开；XLSX按原二进制、MD按UTF8，不以上传／固定成功冒充解析／公式重算 |
| Excel／Markdown分析 | 原提问与已有授权材料，无需先转CSV或逐次选sheet | Agent自主选表／范围、读取原文，需抽表时按任务处理；Host只核文件／位置／留存。XLSX原件与派生表分开，MD文档不强制SQL或字段表单 |
| 环境缺失 | 普通用户无需pip／配venv | Host给Agent准确依赖错误；Agent决定用已有Python、调整方法或说明限制，无Host自动fallback/重跑。环境维护属工程 |
| 原输入版本不可用 | 可查看说明；普通分析不被强迫补技术身份 | 不替换成最新文件；Agent可在已有其他授权资料上另作明确新分析，不能伪造此次复现 |
| 取消／未知 | 沿原停止按钮；有需要时只读核收 | 公共生命周期收本owner；保留旧报告与部分输出，不能显示取消已回滚或重跑补成功。收尾未知保持UNKNOWN |
| 保存ACK丢失 | 可点“核对保存状态”（只读） | 原operation查回原引用或仍待核，不能触发新查询／新版本，不要求用户填写id/hash |
| 受限资源 | 说明当前资格 | fixed-draft/text-only不能执行；managed加载须另实证，不能要求用户“关闭保护继续” |

Demo沿现有项目任务＋文件区、紫色主色与原020／060命名；只为审阅把相关资料放同屏。当前产品没有本版“查看计算依据”聚合接缝；它不是已接线截图。M2仍为现有长面板，原已记录Demo差异继续保留，不在此借机改版。文件／引用复用原语义，Demo没有创建另一个SQL工作台。

## 必须可体验的情景

1. 虚构自然语言问题→Agent自主选择DuckDB关联／汇总→原成果；查看SQL／参数／实际版本、固定输入身份与结果。全部值明示为虚构，非真实查询。
2. 等价问题使用纯Python／零DuckDB；界面不降级、不要求再确认引擎。
3. 环境不可用；准确显示错误与Agent可自主改方法的边界，未实际运行不伪造替代成功。
4. 原版本缺失、SQL或版本未记录／片段：不显示完整已核依据，不选最新替代。
5. 长任务取消／收尾UNKNOWN：既有成果保留，无重跑／新成功回执。
6. 来源保存ACK丢失：只读核收原保存、可查到原件或仍待核；无隐式查询／写新版本。
7. 受限profile不可执行；普通任务可用与fixed-draft不可执行明确区分。
8. 类型／容量边界：main现有22类型/50MiB；拟议固定CSV/TSV/JSON/MD文本与XLSX原二进制/50MiB及文本来源100MiB；XLSX损坏／压缩大小与资源限制、Word/PDF原范围准确说明。
9. Excel与说明材料：虚构XLSX sheet/A1范围／原版本与派生表、MD原文位置与可选抽表、公式缓存缺失/新鲜度未知说明。来源附件仍仅文本七类，XLSX原件以精确inputVersion另查，不增加XLSX结果附件／导出。

## 四原则：条款、动作与反例

| 原则 | 对应设计与UI动作 | 已排除反例／后续必须实证 |
| --- | --- | --- |
| Host管环境 | spec§3.1/3.2；提供依赖、原权限、取消、文件保全与状态 | 不按表数/行数强制引擎、不推主键/公式、不从成功猜业务正确；权限与资源收尾仍要真实验证 |
| Agent自主执行 | 原提问／发送，Agent选择方法、SQL和纠错；可零DuckDB | 不强制SQL步骤／调用配额、Host自动fallback或补跑；原Pi工具自由组合保留 |
| 优先复用Pi已有能力 | Pi1.4.0工具／JSONL与Interface v3；原任务／文件／M2 | 不新建会话库／查询服务／RunStore／取消队列；M2 v2和按需UI明确属于新增接缝，非Pi官方现成业务UI |
| 减少人的操作 | 普通新增必做0；依据／来源固定按需；技术配置工程维护 | 不手填SQL／参数／版本，不逐读取审批，不把自愿管理变必经步骤，也不省必要授权或丢用户选材 |

## 点验与结论范围

浏览器应覆盖1440桌面、390/320窄屏、深浅色、键盘可达／原生dialog／Escape、当前情景状态和虚构边界；记录console／pageerror及任何定位器／fixture失败，不能当产品RED。静态核外部依赖／网络／持久写入与本地链接；Demo自身无fetch、业务API、CDN、浏览器持久存储或真实文件上传。

作者点验、准备阶段全新非作者与四原则专项只证明此spec/Demo可审阅，不证明产品接线或性能。实际结果、截图／候选hash、保全及剩余缺口见[result](result.md)。整体确认前不实施任何产品UI／schema／依赖。
