## 必测边界与禁止副作用

| 验收 | 确定性行为／准确反例 |
| --- | --- |
| DB01依赖 | 实际解释器/import路径/包版本/wheelhash匹配；依赖缺失／漂移／不兼容明确错误；无隐式pip、全局污染或读写root扩大；managed真实加载/动态库闭包/资源收尾 |
| DB02执行 | 原SDK工具实际SQL查询、纯Python、混用、零DuckDB均成立；无Host方法分支、第二循环/队列/强制工具步骤；原subagent和原生search能力无回归 |
| DB03输入 | CSV/TSV/JSON UTF8、空/重名列/引号/换行/编码错误/JSON嵌套由Agent和实际方法明确处理；Host不替统计解析。50MiB与+1byte、100MiB与+1byte、19附件与超额、原元数据限制、路径/symlink/owner/hash/CAS/归档拒绝均准确 |
| DB03兼容 | legacy v1全部原字节/hash/指纹不改、GET不迁移；v2新写升index、混合精确引用、TSV位置与格式匹配；新代码停新功能仍读全部，旧二进制不宣称支持v2；不恢复旧副本覆盖新增工作 |
| DB04依据 | SQL/参数/实际engine/client/扩展/配置/输入和结果由实际工具文件供给；完整与片段／未记录分开，native截断/大小边界/快照变化不误作完整；固定保存后重开仍同hash；普通文件修改不改固定旧件 |
| DB05资源 | 同项目并发连接/spill/输出无串；大查询超内存spill、磁盘不足/拒写、显式取消/close/配置变化/迟到与未知；原件/旧报告/他owner保全；取消不回滚/重放/伪造idle，确认本owner进程结束再按授权范围处理其临时物 |
| DB05回执 | 保存ACK丢失、响应延迟、并发冲突，先只读原operation；必要原事务重试同身份和不可变字节，无新计算或新版本；不明保持UNKNOWN |

额外扩展不发生自动下载，输入文件／SQL按代码与材料风险处理；不因为DuckDB `read_only`或`enable_external_access`名字就认定原件／网络保护完整。受管OS scope按原合同验证；普通unmanaged软边界如实披露，不以新全局沙箱扩大本次范围。

## 正确性与性能的分开记录

使用隔离合成CSV/TSV/JSON/XLSX与MD说明材料及明确期望结果，保留原版本/hash、业务口径、关联键／空值／重复键／时区／单位、SQL/参数、Python脚本、实际解释器/engine/client/扩展/配置、结果及核对规则。XLSX原件的sheet/范围、公式缓存缺失／未知以及派生表对应、MD原文位置／抽表与文档角色分别验证；不覆盖或重算原件。常见关联放大、类型推断、舍入与NULL语义必须独立核对，不能从读取／SQL成功或另一段相同逻辑断定正确。

若评估速度／资源，在**同机、同输入字节与相同结果语义**下比较现有Python基线、DuckDB及必要混用。固定版本、线程/内存/temp、冷暖条件和数据规模；记录wall time、可获得的峰值RSS、spill/磁盘和输出大小、失败/中断，进行足够重复并保留每次观测。配置差异和不可测项如实记UNKNOWN。工程侧准备/采集，不要求用户填性能日报；不强制产品Agent每题执行对照或采用某种方法。

第一版采用目标为“多一种经过验证的可用计算路径及准确依据接缝”。更快/更省不作先验承诺；持平、更慢、资源竞争或错误都保留，不从合成结果推真实业务全部获益。真实Provider/用户材料和产品试用另按授权、固定条件取证。

最终报告分别给出：工程合同/兼容、独立复核和四原则、专业结果正确性、性能/资源、Git/CI、安装/运行采用及用户产品验收。未做标NOT_RUN，关键未证标NOT_PROVED，失效/未知保留；不把一类通过升级为另一类完成。
