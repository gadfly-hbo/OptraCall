## 1. 授权、目标与基线

用户确认[总体方案](../../../docs/workflow-closure-and-analysis-reliability-proposal.md)，A反馈闭环已完成工程实施，随后要求推进B/C，并明确本轮“先交spec和UI Demo”。本期输出本规格、[评估协议](evaluation-protocol.md)、[交互原型](../../../docs/prototypes/analysis-verification-reliability-ui-demo.html)和[记录](result.md)。产品、提示词、资源接线、测试、配置和持久结构均不改，不调用模型、不重放旧任务、不Git交付／部署／操作MacBook。

本修订落实[产品原则复审](product-principles-review.md)：明确材料交付与Agent内部分析的边界，沿用同一核算记录一次显式修订，将知情复查绑定这份新稿，并移除产品区工程计分措辞。只修改文档及独立原型，原评审发现与旧候选证据保留，不把原型修正表述为产品修复。

上述为spec／原型阶段的授权及保全记录。用户现明确通过本版spec和UI，授权实施B/C、相应检查和非作者独立复核，严格保持Host材料交付／权限／记录与Agent自主分析的边界，保留现有项目、会话和文件。仅在本机隔离工程根实施和验证；不自动Git／CI交付、切换用户运行服务或操作MacBook。实施文件归属、技术只读合同、模型矩阵及未完成项以实施记录为准，不将旧模型结果升级为本轮成绩。

B的目标是减少影响决策的计算、方法与解释错误，并能回读采用依据；C的目标是让相关材料进入核算可用范围，增加对重要错误的检出，同时减少漏报、误报和核算自身新增错误。**先证明有效增量，再将有效能力纳入产品；不承诺只靠参考材料消除模型错误。**

**Host只管理材料交付、权限和记录；分析执行由Agent／Pi自主完成。** 普通分析不设固定阶段。核算的两个业务turn只界定作者材料何时开放，不限制各turn内的探索、工具调用、计算、验证与自修复，也不要求固定工具、公式、中间表、报告章节或检查数量。输出有依据是质量目标，不是Host放行条件；Host不得因专业意见不合格、未读参考或未读满文件而拦截保存、补算、静默改答、强制再分析或换模型。

RAP保留目标／约束，SAP保留业务口径与精确版本，企业资料保留制度／字典，Case保留本案背景／例外；通用专业参考不另建业务真值。A的反馈／当前判断／后验经验不自动进入冷读。不同对象的版本号不作同一修订序列比较。

普通任务沿`project-tasks`、真实`projectId/taskId`及绑定配置；核算沿`independent-verification`、真实`projectId/taskId/verificationId`及原两turn lease；修订沿`verification-author-draft`及`fixed-draft`无执行工具资源。Interface v1不变，不新增Runtime、第三审查Agent或全局队列。未来允许修改路径限下述B/C接缝及必要消费者／验收；公共入口变化按IN06共同维护。

## 3. B：可选专业能力与依据回读

### 候选与实施顺序

R0保持现有共享证据指导。先在隔离实验根通过原生资源机制提供可选参考，目录／描述可发现，全文按需读；不复制覆盖用户skills目录，不强制`/skill`，不由Host执行样例。当前SDK有`additionalSkillPaths`类型能力，实际接通、资源读取与收益仍待后续实施验证。

可选性同时约束最终系统上下文、资源描述与正文，不能只在UI标“可选”而在接线中要求必用。Agent可不读、部分读、改用例子或使用其他方法；Host不以读取／调用回执作为交付资格，不自动补跑。未加载新参考时，普通分析仍按原能力工作。

| 候选 | 只改变什么 | 范围限制 |
| --- | --- | --- |
| R1 | 可选结果引用／数值呈现参考：从已有计算结果形成段落／表格、保留单位／比较对象／文件定位的通用例子 | 不提供企业公式，不把“引用了结果”当结果正确；不固定报告模板。 |
| R2 | 可选专业反例与工具参考：边界／舍入、粒度／分母／合计／并列、方法自洽与适用前提、证据和权限边界 | 只提供通用反例、标准库使用和查证思路，不包含评估题数值／答案，不按题型自动路由方法。 |
| R3 | R1与R2的固定版本组合，仅在单臂比较后尝试 | 组合收益单列，无增益内容不纳入正式资源。 |

方法自洽可涉及量纲、互逆、极限、独立推导／实现及来源核对；这是可选专业资料的内容，不是产品强制检查流程。统计设计、单／双侧、每组／合计等前提不明时，合理结果包括条件化说明或保留未知，不靠Host选定某个系数兜底。

B首期不新增产品页面、“专业模式”开关、质量审批门、业务持久库或资源安装管理中心。成功的参考最终可以沿原生资源机制提供；是否进入产品以冻结实验收益决定，不以“安装成功／列出skills／模型用了它”判定。

## 4. C：选材、实际范围和检错责任

### C1 复用两类选材，提供可读预览

保持原`dataFiles`与`authorFiles`，沿用当前每组1–32件及路径／大小／同路径或同SHA重叠校验。data用于原始数据／原始字典；作者结果表、报告、检查摘要、计算脚本属于author。**Host不按扩展名／文件名裁定业务来源**，候选目录可见不表示用户已选择。

新预览在原入口内列本次数据、事前语义、作者产物、技术身份与可读限制；选择／预览／取消均不创建核算、不调用模型。用户可人工补充“还要核对的相关文件”说明，支持查看遗漏和取消；不是必填字段、不要求作者固定报告格式。首期不自动解析报告、不递归搜项目、不新增选材Agent、不自动勾选或将作者过程表挪到原始数据组。

人工相关清单只给用户核对，不送冷读。缺失／变化的已选文件在开始前明确拒绝并保留选择；用户可重新选择或明确取消，再重新预览，不静默换同名新文件。未选附件只提示本次未提供，不阻止有边界的核算。文件不可文本解码不等于全文字节不存在，分别说明能否固定、能否预览、能否用其他原生工具读取。

### C2 保持先算后比，如实说明摘要与全文

首次请求、初始workspace不含作者文件名清单／摘要／过程结果／本次反馈／当前Case判断。Case仅沿用户明确确认的事前description及必要身份／来源构造本次交付正文；“事前”由用户确认，Host不按字段名、修改时间或内容自行裁定。Host可保留完整Case作为原经营记录，但不得整包序列化给冷读；当前判断、nextStep、后验经验及人工相关文件清单不进入该交付正文。未选内容不因项目关联而自动带入。

首次请求运行completed且其回复成功保存、输入技术完整性核对后，才揭示作者固定副本并发原第二个业务turn；失败／取消／配置失效／迟到不得越阶段。技术完整性只核对owner、路径、来源及固定字节，不判计算正确、专业覆盖或分析是否充分。首次回复可以是有依据的条件不足、无法计算或保留未知；Host不得要求得到某个数值、指定中间产物或读满文件才允许保存／揭示。两个是材料交付的业务turn，Agent／Pi在每个turn内自主安排工具调用、自修复与迭代，不是两次推理／计算机会。

第二turn保留定位摘要的现有技术预算：单文件最多4000、全部正文片段合计最多12000 UTF-16；预算针对正文片段，来源说明另计且受原完整消息限制。实施须避免拼接后任意slice导致身份／尾部说明半截：先确定每文件实际片段，再完整列出所有所选文件身份与固定全文位置。后续文件可能主动正文为0，必须标“仅定位，本请求未主动附正文”。非BMP字符不从配对中间截断；换行／BOM／原字节身份分别保留。

每个主动片段在实际请求中明示 `[start,end)`、原解码总长度、实际固定副本和SHA；严格UTF-8失败则明确“没有文字摘要”，不使用替代字符伪造原文。**固定全文可用不等于主动附带全文，更不等于已读。** Agent可原生read、bash或其他获准工具自主读取／核对；不得由Host自动重跑作者脚本或替Agent完成计算。

UI作者预览现有100000字符上限也须标实际范围／截断与固定全文入口。旧记录没有范围元信息保持未记录，不按当前4k／12k／100k常数回推旧请求。不能定位当时请求时，也不能靠当前文件重建“当时提供”。

### C3 在原详情区分四种信息

| 信息 | 可展示的依据 | 不代表 |
| --- | --- | --- |
| 本次固定可用 | 原record中的data/author文件SHA／bytes、语义正文／来源、首次依据保存及authorRevealedAt | Agent已读取／理解全部材料 |
| 当时主动附带 | 可定位的真实native请求原文及片段标注；没有则未记录 | 完整作者报告已主动全文送入 |
| 捕获读取线索 | 原events/native中与本owner固定文件可核对的调用、offset/limit及可得结果线索；执行失败另列 | 一次read证明全文覆盖；未捕获证明未读；bash无法定位时强判未读 |
| Agent专业说明 | 原cold/comparison/recheck全文及其自然语言范围／依据／分歧说明，标“Agent声明” | Host已认可该结论／测出专业覆盖率 |

首期不从报告提取专业claim清单、不算“覆盖百分比”、不把检查行数当问题数。原文可如实有错；Host不改写成结构化专业PASS。能独立观察到的读取范围有限，不能以目录隔离声称OS沙箱。

这些记录仅供观察和回读，不驱动必须逐文件读取的门禁，也不增加证明理解的专用工具或固定声明模板。产品区使用材料已提供／未提供、核查范围未知或Agent声明未覆盖等说明；工程计分、检出／漏报分母及资源推广判断只留在产品外的评估协议，不进入产品状态、预置Agent回复或运行控制。

核算对新增数字、排名、解释及采信建议承担同样的依据责任；正确稿允许一致／无需新增，资料不足允许不可核，未检查可坦言未覆盖。工程评估仍把“全文已可读但未检查”的可核重要问题算漏报，不能用Agent一句“不可核”移出分母。

### C4 原修订、知情复查和采用继续独立

保留原显式修订／另存、一次显式知情复查、导出和用户采用。不新增自动修稿、反复审查、换模型兜底或自动通过。文本修订资源保持无执行工具／资源扩展，完整输入20k上限拒截断，不为补算退回全工具。要新增资料／计算，用户明确开始普通分析或新核算；知情复查不改称新冷读。

同一核算记录沿用**一次显式修订**，生成后保留唯一新稿及其来源，不提供重复出稿覆盖入口；原稿、固定作者副本和原会话保持原位。唯一一次知情复查明确对应该记录内这份新稿，详情显示对应关系；再次操作只保留原结果，不覆盖新稿、不将旧复查挂到另一个版本，也不自动再核。已有记录不能证实对应关系时显示未知，不按当前文件补回历史。原型以本页内存身份演示，正式实现优先使用现有唯一修订／复查关系；不因此预先批准新持久字段或多版本功能。

## 6. 持久化与接口决定边界

**优先最小增量：不建新表、专业覆盖数据库、claim注册中心、会话库或方法平台。** 固定文件／阶段产物继续原VerificationRecord，读取线索继续原events/native；新UI展示是只读投影，不回写成新的“专业事实”。候选参考和实验收据属于隔离工程证据，不是产品业务schema。

本规格先固定行为与逻辑来源，未提前批准新公共持久字段。实施前若现有证据足以表达，应使用原native实际请求原文展示片段范围，不靠新版代码重算旧范围；若确需可解析的逐文件providedContext回执、缓存、人工相关清单持久化等，则把新增逻辑组、owner/request绑定、范围单位、未知／旧记录兼容、物理落点和消费者列入完整结构决定包，整体确认后再写合同／迁移。

新只读API同样先明确实际证据来源、归属和缺失语义；不能从“仍叫formatVersion1”推断任意字段已确认。spec／原型阶段未创建这些API、表、字段、生产资源或测试；本轮实施优先复用原记录，只读投影及临时请求校验的来源／归属／未知语义先记入实施记录，新增持久合同仍遵守本节决定边界。

拟实施接缝：`src/agent/output-evidence.ts`（R0控制，不在多变量实验中同时改）、普通`project-session.ts`原生资源接线、`verification-host.ts`选材／预览、`verification-sessions.ts`原两turn上下文、`verification-store.ts`原证据回读、原核算UI/client以及必要公开入口测试。具体文件归属和持久合同在获准实施时固定，不扩大原分析工具或修订权限。

## 8. 大白话

- **B：不再只提醒“认真检查”。** 给Agent可选参考，看它是否更能把方法、算出的数和报告里的话对上；没有收益就不加进去。
- **C：先把该给的材料交清楚。** 报告、结果表、脚本分清；没给就说没给，给了全文也不能假装已核完。
- **核算也可能错。** 除了看它抓到多少作者错误，还要看误报、漏报和它自己新增的错误。
- **Host管材料和记录，Agent决定怎么算、怎么查。** 不加宿主补算，不把用户锁进固定分析流程。
- **两次交材料，不是只准思考两次。** 每轮内部怎样探索、用工具和纠错由Agent决定；Host不评判“算够了”才放行。
- **新稿和复查一一对应。** 本记录只出一次新稿，复查明确针对它；不能把旧复查套到后来另一稿。
- **用新固定题目和未见变体检验。** 不把旧错误报告悄悄修好，也不把多跑几次挑出的最好稿叫首次通过。
