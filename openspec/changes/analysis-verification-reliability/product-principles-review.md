## 1. 结论与范围

**当前B/C规格在“Host管环境、Agent自主执行”这一轴上符合产品原则，未发现Host补算、固定方法路由、强制skill或专业审批门的明确设计。** C有材料交付阶段，不能据此称“完全没有编排”；其正当范围仅是独立核算的输入开放、保存和生命周期，不得扩成Agent内部的推理、计算和自修复步骤。

复审同时发现一处可复现的Demo版本归属缺陷，另有产品文案和未来接线的误用风险。因此，自主性原则通过不等于Demo功能无缺陷、实施已合规或专业收益已验证。上轮独立报告仍按其当时检查范围保留，本次新增发现不能被旧PASS覆盖。

## 3. 实施前应写得更明确的边界

以下是防误落地澄清，不是已发现的实际Host越权。本轮仅提出文字建议，没有改写原spec。

1. **两个业务turn不限制内部工作。** 建议在spec第77行补明：每个turn内的工具、计算、验证和自修复由Pi／Agent自主安排；Host不按工具次数、文件读取数或特定中间表推进分析。
2. **保存首次依据不是检查专业合格。** “输入完整性核对”只核对owner、路径、固定字节和来源。Agent可以形成有依据的“条件不足／无法计算”结果；Host不能判定必须算出特定数值或读满文件才允许保存或揭示作者材料。
3. **全文可用不是强制全文逐项读完。** spec第25行的核对目标与第96行允许坦言未覆盖应共同解释。质量不够可被用户或外部评估指出，但Host不能据此自动拦截交付、补跑、换模型或循环到通过。
4. **可选性须体现在实际资源内容中。** 未来接入原生skill时，要核对最终系统上下文、描述和正文，不能只在UI写“可选”，实际却要求必用skill、固定工具、公式、报告章节或检查数量。未读取参考仍可正常交付；不加载参考也能普通分析。
5. **记录只供观察，不驱动专业裁判。** 读取线索只复用原events/native，不增加为了证明理解而必须调用的专用工具或回执。工程评分、重要错误分母和是否推广资源均留在产品外。

这些边界的未来验收应检查真实配置／提示与公开入口行为。错误内容可以如实交付并接受后续反馈；Host不得为了让验收变绿而代算、静默改答或重试。

## 4. 本次新增发现

### F01 · P2 · Demo新稿可被再次覆盖，旧复查未绑定版本

HTML第97行`REVISION`只判断阶段完成及非legacy，可反复替换`revision`；第98行`RECHECK`只允许第一次；第115行仍展示旧复查且禁用再次复查。

纯内存复现：`START → COLD_SAVED → COMPARE_DONE → REVISION → RECHECK → 修改revisionDraft → REVISION`。第二次说明已变化，`recheck`对象仍与第一次完全一致。实际产品现有核算适配器使用`revisionCount`限制再次修订，不能让Demo成为扩大原合同的依据。

影响：用户可能将旧版本的复查意见理解为新稿的复查结果。这是Host应负责的版本／记录归属问题，不是Agent内部自主性问题，也不证明真实产品发生过同类错误。

建议：本期优先与现有一次修订合同一致，禁止同一记录重复覆盖新稿；若将来另行支持多版本，必须保留各版并明确复查对应版本。**不能自动再核或循环到通过。** 本轮未修，保持OPEN。

### F02 · P3 · 产品材料区带入工程计分措辞

HTML第86、114行出现“应计入检出／漏报”“仍纳入检出与漏报”等表达。当前代码没有实际评分或专业门禁，不能据此认定Host已经接管专业裁判；但这类措辞更适合外部评估协议，容易令产品用户误以为Host在计算专业覆盖。

建议：产品区只说明“本次未提供”“全文可用但核查范围未知／Agent声明未覆盖”“完成不保证正确”；检出、漏报、分母等保留在工程协议或独立演示说明。未要求Agent增加固定声明模板。本轮未修，保持OPEN。

### R01 · 实施风险 · Host侧Case对象不能被整包送入冷读

HTML第73、81、91行的模拟Host载荷保留Case完整对象，含`judgement/nextStep`；第110、121行实际展示只投影背景说明。Demo没有模型请求，**Host保存完整Case对象本身不违反原则，也不能作为实际泄漏证据**。

未来如果将整个`selection`直接序列化为冷读上下文，才会违背spec第75行排除后验判断的约定。建议发送时从用户确认的事前正文、身份和来源显式构造上下文；原Case仍保留原位，不需要删除其判断字段。应验证实际首条请求不含未选择内容，而不是仅检查UI提示。此项归为接线风险，不列现有P2违规。

## 5. 主审与独立复核

本轮新开三个非作者只读复核上下文，分别检查规格自主性、Demo控件／状态、评估规则与产品边界；未沿用上一轮PASS作为本轮结论。三者均未发现明确的固定分析SOP或Host补算设计。

Demo复核者首次指出F01，主审通过同一HTML的纯函数在无DOM／无网络／无模型的Node VM中独立复现。Case完整对象也经纯函数读回核实；主审将其严格归为“Host存储可合法、未来发送须投影”的风险，不将对象存在误报为模型泄漏。产品计分用语经源文件逐行核对。

另通过代码图谱核查现有核算适配器，确认首次结果以运行完成、保存和字节完整性控制后续材料交付，没有本期新增的专业公式裁判。此处是当前接缝的有限核查，不是全产品自主性审计。

本轮浏览器API虽能列出原预览页，但读取页面受工具可用性错误阻断，因此没有重做浏览器交互；上轮浏览器证据仍为历史范围，不充当本次新增问题的交互证明。F01证据为静态控件条件与纯内存状态复现，不是点击实测。

## 6. 大白话

- **B是给Agent添可选参考书。** 看不看、怎么用、用什么算法由Agent决定，不能变成照表执行。
- **C是先交数据，再交作者答案。** Host管材料何时交和有没有保存，不负责判断Agent怎么算、算得对不对。
- **显示读过什么，是方便回看。** 不能变成“必须读满这些文件才能结束”。
- **考卷和评分留在测试场。** 用户日常分析不需要过关，也不必强行找出错误。
- **Demo有一处旧复查跟着新稿走的问题。** 应修好记录归属，不能让Host替Agent重算或多审几遍来掩盖。
