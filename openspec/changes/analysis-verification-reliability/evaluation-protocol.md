# B/C评估协议：冻结任务、范围与评分

v0.2 · 2026-10-31 · 已随spec／UI由用户确认。规格阶段未生成盲题或调用模型；当前材料资格与执行状态见[实施记录](implementation.md)。本文是工程验收协议，**不进入产品Host，不变成Agent固定分析模式**；下文计分措辞不出现在产品状态或预置Agent回复中。题数、重复、评分及推广条件保持原批准内容，不因运行结果调整。

依据：[规格](spec.md)及已确认总体方案第8节。候选、任务、作者包、实际模型参数与保管职责在执行前固定；不能先看结果再改分母、重复单位或通过线。

## 1. 任务、重复与历史

保持12类，每类一开发变体和一未见变体，共24业务题：

| 类别 | 主要检验 | 预定重复 |
| --- | --- | --- |
| T01 方向 | 增减、比较对象、触发方向与建议一致 | 各变体1次 |
| T02 严格阈值／舍入 | 精确值与展示值、等号归属、条件改变 | 各变体3次，含首次 |
| T03 混合明细／总计 | 粒度、重复合计、明细与汇总边界 | 各变体3次，含首次 |
| T04 加权分母 | 合并率／平均率、金额率／订单率及单位 | 各变体1次 |
| T05 零基期 | 不可定义增长、合理替代表达 | 各变体1次 |
| T06 并列排名 | 并列、阈值和不等名次 | 各变体1次 |
| T07 样本结构 | 计数相同不证明结构／真实性、推断前提 | 各变体3次，含首次 |
| T08 因果边界 | 相关／共现、对照不足、等效与无效区别 | 各变体1次 |
| T09 制度／例外／时效 | 业务语义来源、范围、制度冲突与旧版 | 各变体1次 |
| T10 资料／执行权限 | 可读取、建议复核与经营执行授权分开 | 各变体1次 |
| T11 未决前提 | 条件情景、合理未知／不作建议 | 各变体1次 |
| T12 缺失／矛盾证据 | 方法前提、互逆／量纲／实现／解释矛盾 | 各变体3次，含首次 |

完整条件输出数：24份首次＋4类×2变体×2份额外重复＝**40**；不是40个不同业务题。开发／盲测各12题、各20输出，分开统计，不将开发题冒称未见。

A样本量错误、无根据占位推断及不同对象版本混比是已见回归。新变体改变背景、布局、问题及干扰项；仅换数值不保证未见。方法题须在真值中预先明确设计、功效／单双侧、单位、每组或总量、可接受近似及缺前提时的容许答案；不把某系数当无条件标准答案。

## 2. B：开发选臂与正式冻结比较

| 阶段 | 预定范围 | 作用 |
| --- | --- | --- |
| 开发筛选 | 12开发题，R0/R1/R2各取1次，共36输出 | 判断可选呈现参考／专业反例各自收益；记录全部失败及资产版本，不使用盲题。 |
| 可选组合 | R1/R2单臂比较后，若有依据再做R3，同12题各1次，共12输出 | 只评价组合，不反推单项贡献；无依据不为遍历矩阵而强加R3。 |
| 冻结正式比较 | R0与一个已冻结B*，每条件24题／40输出，共80输出 | 同问题／输入／实际参数／工具／业务语义；独立新会话，预先交错顺序。开发部分是固定回归，盲测部分单列。 |

筛选和正式矩阵是两个预先命名的实验，不能把筛选最好稿替换正式首次稿。筛选版本变过则各版本保留；正式B*只用一个固定版本。B*冻结后才释放未见题输入。正式运行期间不据早出评分改参考、补提示或换模型。

正式80份中，40份是开发变体固定回归，40份是未见变体对照。全量成本收据包括36份筛选、可选12份组合和正式80份，不只报被采用条件。已有开发失败用于修正后，新的版本是新实验身份，旧失败不改PASS。

B*可为R1、R2或R3，也可无有效候选。无增益或重要退化时不推广该资源；普通分析继续可用，不通过Host强制调用资源补偿。

## 3. C：固定作者包，拆开专业增量与范围增量

由非候选作者准备24个固定包，对应同12类×2变体；建议固定12正确包、12有重要问题包，开发／未见各6正确＋6问题。每类一正确一问题，具体对应不交候选作者。问题包中8份报告可见、4份只在相关过程产物；开发／未见各4＋2。正确包含合法未知／无需新增结论负例。所有植入问题必须与题目决策相关，不把文风问题算重要错误。

包内固定：任务、原始数据／事前语义、同一作者报告、同一组过程表／脚本／相关说明、重要正确论断、缺陷及位置、允许答案／严重度／容差、仅报告及完整材料范围。作者文件不命名“错误版／金标”，不把作者结果表伪装成原始数据；真值由独立计算／语义依据得出，不以重跑作者脚本为准。

| 条件 | 能力 | 作者材料 | 用于比较 |
| --- | --- | --- | --- |
| C0-full | 现有核算指导／接线 | 固定报告＋完整预定过程产物 | 专业基线 |
| C*-full | 已冻结C*及所选有效参考 | 完全相同报告＋相同过程产物 | 与C0-full比较专业增量 |
| C*-report | 与C*-full完全相同 | 只给同一报告 | 与C*-full比较范围增量 |

每条件40个新核算记录，共**120次两业务turn会话、240个预定业务turn**。这只计算Host材料交付请求，不限制Agent／Pi在各turn内的探索、工具调用、计算、验证和自主迭代；工具调用或SDK原生重试数量不等于业务turn数，应按实际另记。C*-full作为两项比较的共同参照，预先约定此复用，不事后挑某份替代。三个条件的原始事实／问题／事前语义相同，差异只在表列项；冷读不见作者清单、反馈或当前判断。

C候选开发用开放包，参考／对照说明冻结后再执行完整正式矩阵。未见包不能用来选C*。C专业比较固定作者稿，不接B新作者输出改变难度。端到端另用两个新合成情境（会员试点、条件不同的新对象）走普通B*分析→C*核算→A下一轮材料选用，只证明合用表现，不计入单项检错提升。

## 4. 实际模型与输入冻结

首轮建议采用本机已成功跑工具／多turn的MiMo V2.6 Flash配置；执行时再核当前实际配置，不能只看同一model ID。记录Provider／baseURL／API协议、thinking/reasoning、contextWindow、maxTokens、compat、SDK版本、系统指导、工具与用户资源清单／SHA。未明确或不等价的参数保持UNKNOWN，不与正式对照混成绩。

同一比较不静默fallback或换模型；其他模型可另作完整分层，未运行记NOT_RUN，不用另一个模型的成功关闭当前失败。只用合成或明确获准材料，模型调用无预算上限，但试验次数按协议固定；不无限加跑、串第三Agent或直到通过。供应商结算、SDK估算和费用未知分别记录。

每次新任务／核算新会话和工作区，不能继承前次答案、比较结果或评分。普通Agent工具保持原能力，不为防看到答案临时削弱产品工具，再声称代表正常自主分析。

Host只核对材料身份／字节、交付资格与运行保存状态，不以专业分数、参考读取、固定工具次数或中间产物作为交付／保存／揭示的门槛。条件不足或无法计算可以是合法首次回复；专业收益由产品外评估者判断。可选参考的实际系统上下文、描述和正文都必须允许忽略或换方法；不得因没有读取而补跑。同一记录的一次出稿及知情复查只验证记录对应关系，不增加专业审批或自动复查回合。

## 5. 保管、盲测与评分职责

| 角色 | 可见与职责 |
| --- | --- |
| 候选作者 | 协议、开放开发题、开发评分；只接收未见题ID／数量／封存摘要，不取未见正文／真值来调实现 |
| 非作者保管人 | 生成并保存未见任务、固定作者包、允许答案与缺陷，释放执行输入时不释放真值 |
| 非作者真值复核者 | 独立核计算、边界／假设／单位及容许答案；不只复用同一脚本或让同一模型自评 |
| 执行者 | 按预定顺序给产品合法输入，不补答案／评分／缺陷定位，不手改首次报告 |
| 非作者评分／仲裁者 | 先按中性输出ID读冻结全文和真值，评分后再揭实验臂，保留分歧和裁决依据 |

执行前真值／材料／程序身份须封存，公开收据只含ID、类别、数量、摘要、保管／复核责任。规格阶段未生成完整未见题；当前实施的材料资格、冻结与保管收据见实施记录。共享文件系统＋full-tools不是OS保密沙箱；至少实行角色、运行上下文和材料交付隔离，不在项目资料、资源或Host路径提示中暴露答案。若仅能做到这种隔离，如实披露，不能声称技术上绝不可读。发现泄漏则该题成绩失效，保留原结果并更换未见包。

一旦具体未见题／评分理由用于作者定位修正，该题转已见回归。修正候选再验收须换新未见变体；不把反复调同一盲题写成首次通过。预定三次重复期间不插修复或评分反馈。

## 6. 评分单元、分母与通过条件

重要论断是会改变判断、数量级、对象、方向、建议、适用条件或权限的业务命题，按命题去重，不按表格行／检查标签数／重复句子计量。真值预设目标命题，产物额外引入的新主张也按同一规则评价，不能只评核心表。数字容差、单位、精确阈值、方法条件和合理拒答在看输出前固定；不能靠舍入放宽方向／等号／权限。

| 分类 | 判定与计量 |
| --- | --- |
| 可核且检出 | 必要材料本条件可得，正确定位重要错误及方向／边界或具体证据缺口；泛称“需谨慎”不算检出 |
| 可核但未覆盖／漏报 | 全文／材料已可读而未看、只看摘要、漏查、误称一致或不可核；仍留在可核漏报分母 |
| 本条件不可核 | 必要事实未提供、技术不可读，或材料本身不足以推出；单列原因／缺什么，不算该问题检出或漏报 |
| 正确／一致 | 正确论断、合法未知和无需新增为负例；不能要求核算凑错误 |
| 误报 | 错判正确论断、编矛盾、把无根据怀疑升级为确定错误／行动限制；重要误报单列 |
| 核算新增错误 | 自新增的数字、排名、解释、取舍或采信建议错误；检出作者错不抵销，错误采信另标传播 |

摘要没包含但全文可读，属于未覆盖，不是不可核。仅报告与全产物两范围同时报告共同可核集／扩展可核集的绝对数及分母；不利用分母变化制造专业能力提升。没有资料时强答确定结论本身仍可评价为无依据错误。

B报告首次正确交付题数／24（未完成仍在交付分母）、开发／未见分项、重要错误数与类型、依据可回读程度、核心表与全文新增推断。C分别报告冷稿正确性、可核重要错误检出／漏报、正确重要论断误报、不可核／未覆盖、核算新增错与错误传播。三次重复按每变体0/3–3/3报告，不能多数投票或选最好一次替代首次。

模型发起后的失败、超时、取消、截断、无报告均保留并分类，不只剔除失败算正确率。尚未发模型的环境／脚本设置故障保留原记录和原因，修正后按协议新尝试；不是产品或模型RED。正常自主迭代属于本次首份交付，评估者指出错误后的改稿不能回填成首次稿。

最终B*/C*冻结重要集无未关闭的重要错误、可核漏报、重要误报或核算新增重要错；主要指标相较基线改善、各类别无重要退化，才推荐推广。基线天花板或样本不足不能证实改善则NO_MEASURABLE_GAIN/PARTIAL；有重要问题FAIL。零观察错误只支持这些题与实际配置，不保证普遍正确或经营有效。

按预定批次执行；若已明确关键退化可停该臂，剩余NOT_RUN，不能用未跑部分宣称完整通过。所有首次产物、失败、人工介入、耗时及可得token／费用保存在明确本地持久目录。该评分表只用于工程评估，不落成产品Host的专业IR或审批器。

## 7. 运行前与运行后的收据

运行前：规格／候选／R0身份、参考SHA、实际模型参数、工具／资源清单、24题与四类重复计划、作者包／材料范围、真值封存和复核责任、重要性／容差、执行顺序、允许人工介入及保留位置。

运行后：真实task／verification／request／native身份、提供／可观察读取／Agent声明、首次全文及过程产物、全部预定重复、未完成和费用未知、评分原文位置与独立仲裁、版本变化及污染／退役记录。

工程check、非作者复核、专业收益、CI／Git、运行采用和用户验收分别报告。规格阶段全部模型矩阵为NOT_RUN；当前实施按实际收据更新状态，Demo预置结果始终不纳入任何成绩。
