# 商圈接缝结构与兼容决定

2026-11-03。依据已确认 D7/D8/D13、四场景 Demo，以及用户要求按移交包执行 Host 接缝。移交包明确“任务字段或能力集合由 Codex 决定”；以下是该授权内的实现决定，不虚构用户逐字段确认，也不扩大数据、模型、设备或 Git 授权。

| 项 | 决定与理由 | 生命周期、兼容与验收 |
| --- | --- | --- |
| S1 任务能力 | 沿用 schemaVersion 2 的可选布尔字段。保留 `simulationTools`，新增同粒度 `tradeAreaTools?: boolean`，缺省/false 均关闭。两个字段各为其能力唯一权威；UI 通过固定能力清单统一展示，不增加持久集合或双写别名。 | owner 仍为 projectId/taskId，项目只共享文件；旧元数据读取不补写。新建与显式空闲切换才保存字段；关闭省略该字段。合法旧 false 保持可读，不改 native 指针、路径、历史字节或默认模型。 |
| S2 开关入口 | 新建任务独立勾选；统一 `PUT .../capabilities` 接受一个已知能力名和 boolean。既有 `simulation-tools` API 保持兼容并走同一关闭/保存逻辑。 | Host mutate 内核对归档/公共域及修订占用；变化先经公共生命周期 close，成功后持久保存，下一次 open/send 重建。相同值不关闭资源；在途或关闭失败不保存新开关。受管、封闭与 fixed-draft 即使保存开启也不注入。 |
| S3 版本呈现 | 只读连接器状态 API 只交付快照 digest、总数、来源 HEAD、生成时间、评分引擎身份，不交付商圈数据、凭据或绝对数据路径。 | 供目录/任务能力面板显示；未导入或校验失败明确不可用，不猜版本。工具结果自身携带实际会话所读版本，不能拿面板当前版本伪造旧轮引用。 |

不新增域/profile/owner/会话库；Interface v3 与旧业务子集不变。所有 Agent options 仅传可 IPC 序列化的任务开关和 Host 构造路径，连接器本体不创建 SDK。stdio 是 SDK 支持的既有传输，非新增独立产品端口/服务。后续若发现快照归档或契约尚不满足既定 R1，先记录修正决定与验收再改受影响部分。

## S4 · 闭合既定 R1 的完整版本保留

原导入只归档旧manifest，随后覆盖index/details；已用“先加载旧manifest、更新后再懒读index”的用例证实旧digest会错误标注新数据。修正采用已有 `importerVersion=2`：每一版完整manifest/index/details写入 `versions/<完整digest>/`，独占导入锁下先完成并核对内容，再原子发布根 `snapshot.json`。digest仍绑定原文件字节、来源、生成时间、总数、引擎与importerVersion；因importer版本变化，正式导入digest会区别于Qoder开发根原v1摘要，原证据保留。

旧v1根只读兼容；首次更新前将其完整内容保存到对应版本目录，原平铺文件不覆盖，旧已打开reader仍读原版。旧manifest另外保留在history，完整版本目录不删除。v2 reader以首次读取的manifest绑定版本目录，读入文件核对清单SHA与长度；缺失/篡改/未知格式明确不可用。显式选择 `versions/<digest>/` 仍可独立只读回溯。幂等重导也验证已存字节，不用相同digest掩盖损坏。失败不替换当前指针、不自动修补或清理既有版本；遗留导入锁须诊断，不盲目删除。回退旧代码不能保证理解v2布局，不覆盖新数据来模拟回退。

这是用户已确认“快照不可变、更新显式、旧版可追溯”的R1/D7落实，不增加业务实体、自动刷新或天气能力；产品dataRoot正式导入在此修正及适用检查后执行。
