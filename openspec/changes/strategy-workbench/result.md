## 独立复核及曾经失败的检查

- 产品轴在隔离 Host、原生 Pi 和 Chrome 上点验。复核发现主辅指标并存时原交接遗漏主指标，无稳定编号的 Excel 换序后可能误修订另一目标，同名项目原件的选择也可能扩大授权。修正后 6 个相关测试文件 16 项通过，浏览器重查了两类模拟、目标树与 BSC、失读后另选可读地图和刷新后的比较。
- 工程轴独立复跑了 12 项权限与旧会话检查、1 项工作台全链与请求恢复检查，并核对统一会话边界。测试包括被拒上传时原件数不变、权限丢失前后 Provider 请求数、未见过旧版的对照组及旧版交接。更早的兼容组 13 项通过。首轮历史重放曾错误返回 202，最终修正和旧版交接对照均已复验。
- 初次全量运行 3,079 项，通过 2,953、失败 15、跳过 111。14 项涉及旧战略讨论读取尚未初始化的 Case 存储，1 项涉及 Excel 无缓存公式的错误位置说明。保留了首轮结果并修复。第二次全量运行 3,089 项，通过 2,977、失败 1、跳过 111。该失败暴露仓库手册和产品下载手册的内容不同步，于 `3fa232a` 按同一手册源重新生成。Chrome 实际从帮助入口下载的 37,789 字节与仓库手册逐字节相同。

- 最后一次边界复核从 HTTP 复现了两项问题。地图修改后清空指标周期能保存，但交接时返回 500。两个方案均固定覆盖率时，试算要求填写对计算无影响的共同覆盖率。`074ea08` 修复后，Chrome 实际保存含空白的 v2、刷新并交接成功，主辅指标的零值仍可读，两个原地图版本和散列均保留。另一组固定覆盖的会员方案中，A 为 50%、B 为 70%，输入 1,000 人时各预计新增 10、28 人，只保存人数，重开仍得原数。

- 最终候选的独立工程轴复核覆盖相对基线的 76 个差异文件，10 个重点测试文件 26 项通过，另有历史兼容组 37 项通过。独立 Chrome 复现、修复后再验及公开 HTTP 检查覆盖了上述两项边界。

- 最终候选的独立产品轴沿两个入口再次核对，专项 9 项通过。在 Chrome 清空主指标口径及辅指标字段后，将 v2 带入目标管理，保存后的主指标基线为 0、目标为 8，辅指标名称和 v1 原口径可读。另用固定 0% 与 50% 覆盖、2,000 人的例子，实际结果为 0 和 40，重开后结果一致。

## 本地核验方法

- 用空的临时安装目录运行 `npm ci --offline`，由锁文件还原 372 个包。正式 Pi 原有版本为 1.4.0。本轮新增的文件解析能力在 OptraCall 侧接入。
- 用隔离的 Host、项目根和配置运行真实产品界面，使用官方 Pi 与本地合成 Provider 对照请求、原生结果与业务存储。`tests/browser-strategy-workbench.mjs` 可复查共创、试算及历史，`tests/browser-v13-pm-management.mjs` 的 strategy 与 adoption 场景确认历史稿交接、仅 G/仅 S/两者修订和并发采用冲突时仍能读回准确版本。

本开发机的完整运行输出保存在工作树的 `.local/strategy-workbench/regression/`，包括两次失败的全量结果、历史入口浏览器实测、最终全量结果与独立工程抽验。公开测试和本页结果可以随提交查看。

## 四原则和验收边界

Host 提供原讨论与项目的权限、准确文件/地图身份、版本、读写及回执。选择与解释方法、提出备选、修订地图和解释因果由同一战略 Agent 完成。共创沿用统一会话 Interface v3、strategy-discussion 和官方 Pi 1.4.0。结构化导入与只读查阅无需调用模型。带入目标管理后由用户明确采用具体目标。试算、采用和建立 Case 有各自的记录。

本轮用合成文件、本地测试 Provider 和真实产品入口核对了模型请求、原生工具调用及保存结果。模拟示例为假设条件下的计算。商业模型的战略专业质量、真实经营效果、两端正式采用和用户最终验收分别留待实际验证。

若以后需要从采用后的新版回到旧版，应保全新数据，并用采用前对应的服务版本、数据及项目快照恢复到单独位置核对。旧版可能在写回时丢掉新地图关联或新增的目标字段。本轮未在实际设备执行数据恢复或运行切换。
