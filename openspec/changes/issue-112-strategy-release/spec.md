## 1. 阶段与目标

当前为**阶段一：规格与可点击 UI Demo**。本阶段只交付设计候选，不修改产品源码、测试、依赖、Host 契约或持久数据；用户确认本页设计与待确认决定后，才进入阶段二实施。

基线中「战略地图」与「版本与来源」都能把所选地图带入目标管理；地图版本已有来源、作者、版本号和 `contentSha256`，但没有发布态。现有 Host 承接入口会核对归属、准确指纹和目标选择，未校验发布资格。本变更目标为：

1. 在「战略选择」新增与「战略共创」「战略地图」「战略模拟」「版本与来源」并列的「战略发布」页签。
2. 所有地图从候选开始；用户在「战略发布」核对所选地图及准确版本后，明确执行「正式发布」。
3. 地图「带入目标管理」入口集中到「战略发布」，且仅对当前有效发布的准确版本开放；其他页签移除地图承接按钮。
4. 复用既有「核对承接的目标与策略」、归属／视角／目标选择、关联策略核对、期望版本冲突检查和「保存目标候选」流程。发布本身不创建目标。
5. Host 在创建目标候选前校验讨论、地图、版本、内容指纹、发布状态、归属和目标选择，防止绕过界面直接承接候选版。
6. 保留地图历史、目标历史、旧承接记录和「版本与来源 → 将此版带入 GSA」的历史战略文稿路径；后者的去留作为设计决定交用户确认。

## 3. 设计方案

### SR01 导航与入口边界

「战略选择」页签顺序调整为：

`战略共创 → 战略地图 → 战略模拟 → 战略发布 → 版本与来源`

- 「战略发布」承载地图发布的唯一人工入口和地图「带入目标管理」唯一入口。
- 「战略地图」保留查看、编辑、导入、原稿对照、因果链审查和继续原讨论；不再显示「将此版带入目标管理」。
- 「战略模拟」保留候选比较与返回原地图；不新增承接入口。
- 「版本与来源」保留修订记录、来源、导出、原讨论和历史交接状态；不再显示地图「带入目标管理」。
- 「版本与来源」中现有历史战略文稿「将此版带入 GSA」走 `StrategyChoicePanel` 的文稿交接路径，本变更默认**只加说明、不改行为**：文案提示「历史战略文稿交接，非地图发布承接」。是否进一步改名、迁移或保留原样，待用户确认。

### SR02 候选与发布状态

所有 Agent 共创、人工编辑、文件导入产生的地图版本均从 `candidate` 开始。发布状态不写回地图版本正文，作为独立发布记录叠加在不可变地图版本上：

| 状态 | 含义 | 可否带入目标管理 |
| --- | --- | --- |
| `candidate` / 未发布 | 已保存的地图候选版本，尚未正式发布 | 否 |
| `active` / 当前发布 | 该地图当前唯一有效发布版，绑定准确版本和 `contentSha256` | 是 |
| `superseded` / 已被替代 | 曾正式发布；同地图后来发布了新版 | 否 |
| `withdrawn` / 已撤销 | 用户明确撤销发布，记录保留 | 否 |

发布记录建议字段：`publicationId`、`discussionId`、`mapId`、`version`、`contentSha256`、`state`、`publishedAt`、`supersededAt`／`withdrawnAt`、操作说明、发布时目标／策略摘要。记录按地图版本和指纹回读，不修改原地图 JSON 的 `contentSha256`。

### SR03 发布语义（已确认）

1. **冻结准确版本**：正式发布绑定当前所选 `mapId + version + contentSha256`。地图版本本身已经追加式保存；发布后继续编辑会生成下一版候选，不覆盖已发布版本。
2. **同地图单一当前发布**：同一 `mapId` 只有一个 `active` 发布记录。发布新版时，旧 `active` 自动转为 `superseded`，仍保留在发布记录中。
3. **修订另出候选**：修订后的新版先回到「战略地图」人工核对并保存候选，再回「战略发布」核对新版指纹并发布。
4. **撤销保留记录**：「撤销发布」需要二次确认；仅把该发布记录标记为 `withdrawn`，不删除地图、发布记录或目标历史，也不再允许新的目标候选承接。
5. **同版重发布**：不允许撤销后重新发布同一准确版本。恢复承接需要先按既有地图编辑流程产生新的候选版本，再核对并发布新版本；旧目标记录仍按当时发布身份保留。
6. **无目标节点的地图**：可查看和发布为正式地图，但「带入目标管理」禁用并提示无可选目标。

### SR04 发布页交互

页面分为主核对区和记录区：

1. **版本选择器**：按地图分组显示「地图标题 · v版本号 · 状态」；默认选中最新候选；不可读版本沿用现有不可读提示，不能被选中发布。
2. **准确版本摘要**：显示标题、版本号、模板、作者、修订理由、创建时间、完整版本身份和 `contentSha256` 摘要；展开取舍、成立条件、待核依据、目标／策略表和来源。
3. **发布确认**：候选版显示「核对此版并正式发布」。确认对话框再次显示版本号、指纹、目标／策略数量和后果说明：
   - 发布不创建目标、不采用目标、不启动 Case 或项目；
   - 后续编辑会另出新候选；
   - 发布后才能在本页带入目标管理。
4. **取消**：关闭确认框，不写发布记录；状态区明确「已取消，未发布」。
5. **发布成功**：当前版本转为 `active`，刷新／重开仍能从发布记录读回；同地图旧发布转为 `superseded`。
6. **带入目标管理**：仅 `active` 版本显示主入口。点击后复用现有「核对承接的目标与策略」对话框，subtitle 增加发布记录身份；目标归属、组织视角、目标复选框、关联策略、期望版本和保存按钮沿用现有行为。
7. **撤销发布**：仅在 `active` 版本提供二次确认。撤销后入口消失，记录保留并标明撤销时间；已保存目标候选和历史引用不被改写。
8. **发布记录列表**：按地图显示全部版本与发布状态，区分「当前候选」「当前可承接发布」「历史发布」「已撤销」「未发布」。列表提供查看此版、返回原讨论和导出，不提供承接。

### SR05 Host 门禁与数据契约

Host 是发布资格和写入门禁的权威，UI 隐藏只是辅助：

1. 新增发布记录的读写契约，发布、撤销和承接均进入现有 Host mutation queue，保持幂等、关闭保护和失败保留。
2. `handoff` 请求仍携带准确 `map: {discussionId,mapId,version,sha256}`，另携带本次发布记录 `publicationId`。Host 不信任客户端状态，按以下顺序校验：
   - 讨论与地图归属存在且可读；
   - `mapId + version + contentSha256` 完全匹配；
   - `publicationId` 对应同一地图准确版本；
   - 发布记录当前为 `active`，未被替代或撤销；
   - 目标归属／视角合法，所选节点均为该版 `goal` 且不重复；
   - 既有目标期望版本无冲突。
3. 未发布、已撤销、已被替代、指纹错误、越界归属或无可选目标均拒绝写入，返回明确错误码；候选请求保留输入，不静默切换最新版或另选发布版。
4. 保存成功的目标候选 `structured.map` 继续保留准确地图引用，并新增本次 `publication` 身份；发布本身不生成目标。
5. 旧目标记录不回填发布身份。缺少 `publication` 的地图来源在 UI 显示「历史承接（发布功能上线前）」；有 `publication` 的记录显示对应发布身份。同一旧版本之后正式发布，不改变旧记录的历史标识。

### SR06 兼容与历史

- 地图版本 JSON 保持不可变和可读；发布记录独立追加，不改变现有 `contentSha256` 校验。
- 既有地图导入、编辑、撤销导入草稿、模拟、导出、原稿回读、来源检查和历史读取不因本变更阻断。
- 既有目标候选、已采用目标、Case 绑定、项目引用和反馈按原准确版本继续读取。
- 旧承接记录保留并标记历史承接；不迁移、不重跑、不自动升级到最新发布版。
- 独立目标表导入和目标管理内直接新建目标不受地图发布门禁影响。

### SR07 文案与帮助

- 页首路径改为「战略发布 → 带入目标管理 → 核对承接的目标与策略 → 保存目标候选」。
- 明确「版本与来源」用于查看修订、来源和历史交接，不是地图承接入口。
- 帮助和手册同步解释候选、当前发布、被替代、撤销和历史承接；提示发布不等于目标采用。
- 「版本与来源 → 将此版带入 GSA」若默认保留，则文案补充「历史战略文稿交接」，与地图承接区分。

## 6. 四原则与 IN01–IN07 前置检查

- **Host 管环境**：Host 负责发布记录、准确版本／指纹校验、归属权限、mutation queue、持久化和错误回执；不替用户判断战略内容是否正确。
- **Agent 自主执行**：不改变 Agent 地图共创、资料选择、分析方法和内部迭代；发布与承接是用户对业务资产的显式治理动作。
- **优先复用既有能力**：复用地图版本存储、`contentSha256`、既有 `MapGoalHandoff` 人工核对、目标候选保存、期望版本冲突检查、目标管理和 Case 绑定；不新建平行目标库或 Agent Runtime。
- **减少人的操作**：用户只需核对所选准确版并确认发布；后续目标选择沿用一次人工核对对话框，不新增逐条策略审批或机器身份填写。
- **IN01–IN07**：无 Interface 版本、owner/profile、Pi SDK、会话生命周期、模型配置或插件接入变更；阶段二若实现中发现现有 Host 契约无法表达发布记录，先按 IN06 补契约与验收，不扩大 Agent 权限。
