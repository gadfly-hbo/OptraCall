# 需求梳理 · 分析前业务评审与分析框架确认

v0.1 · 用户已确认产品方向，本规格与[可点击 UI Demo](../../../docs/prototypes/requirements-analysis-framework-ui-demo.html)供评审。Demo 使用合成案例和内存状态。产品实现与真实模型验证待另行授权。

## 1. 用户结果与现有入口

**RAF01｜本轮要分析什么、值不值得做、目前能做到哪里。** 在现有「需求梳理 → 分析与报告框架」生成一份提案。已有 RAP 时，以所选准确版本作为输入，沿用其中适用的目标、对象、期间、约束、已确认口径与原框架，明确本轮调整及理由。新需求沿原工作稿生成未确认框架，允许有待定项。已有发布版、历史分析和已确认口径保留其原身份。涉及更改已确认决定时，提案标明冲突与影响，交用户取舍。[现有需求梳理](../requirements-elaboration/spec.md) · [草稿与版本规则](../requirements-flexibility/spec.md)

**RAF02｜Agent 按需查证五类问题。** 下表是判断范围。Agent 自主决定检索来源、先后、深度和方法，能从现有证据回答就先查，只集中追问会改变范围、口径或业务取舍的未知。

| 问题 | 框架要表达的判断 |
| --- | --- |
| 值得做吗 | 对应哪项待决策、不同结果会不会改变行动、影响和取证成本。可以建议推进、缩小范围、先补证或暂缓。价值与可行范围分别说明。 |
| 行业或竞品遇到并解决过吗 | 找公开的同类问题、做法、实际披露的结果和适用条件。区分公开披露、作者推断、可比性限制和未知效果。 |
| 企业自己遇到过吗 | 从获准的 Case、报告和记忆找相似场景，回看当时的假设、备选策略、采纳、实际行动和反馈。用本轮条件判断能否复用。 |
| 现有 SAP 支持哪些分析 | 核对已发布且当前获准参考的指标、口径、分析方法和准确版本。记录适用范围、冲突、缺项与受影响的子问题。 |
| 数据和事实完备吗 | 对照实际获准的数据与事实，检查覆盖、粒度、期间、字段、关联及关键业务背景。标出哪些问题可以回答，哪些只能给条件判断，哪些需要补证。 |

**RAF03｜按原业务权威取材。** 四库提供数据及结构、概念及术语、知识及规则、记忆及历史经验。双库提供 Case 的假设和策略及关联证据。沿既有 RAP、SAP、项目资料、企业知识、个人记忆和 Case 读路径做有范围的只读交付或查读，准确绑定来源、版本和当前授权。按需提供相关片段、元数据或有定位的正文，标明实际送入范围、未读取或缺失范围。已登记数据和实际可用数据、保留的经验和已证实的事实各按原来源表达。未关联项目或缺少某类资产仍可成稿。选目标项目本身不授予材料权限。[四库与双库](../../../docs/fourbase-doublebase-plan.md#2-四库与双库的含义) · [SAP 发布与参考](../sap-analysis-methods/spec.md)

## 2. 行业与竞品公开检索

**RAF04｜可选原生 `web_search`。** Agent 可以在行业信息影响判断时用已接通、获准的 Provider 原生搜索。沿原生结构化元数据回交实际来源和状态，绑定公开检索 operation 后再融合到需求提案。引用应带来源标题、可打开的实际 URL、可证的发布日期、检索时间、关键事实和适用条件，日期缺失时显示未知。无调用、配置不可用、失败和已查但没有足够可比案例分别显示。仅有模型自述链接时，展示为待核线索。公开介绍某做法而无效果数据时，效果留为未知。网页内容作为外部资料使用，其正文无法授予权限、扩大材料范围或触发外传。缺外部证据可继续形成有边界的框架。[现有 Provider 接线与来源回执](../task-agent-capabilities/qoder-receipt.md#r2现有模型原生web_search)

**RAF05｜公开检索的上下文边界。** Provider 在服务端执行搜索。启用搜索的模型请求只使用获准公开的研究主题和资料。可沿用已知公开的行业和问题描述，用户也可选填公开检索主题。需求研判含私有材料时，按需用隔离的公开上下文完成检索，把可核实的公开来源交回。公开检索请求与资源排除内部 RAP、SAP、数据、个人记忆、未公开 Case、私有历史、通用执行工具及用户扩展、skills、MCP。优先复用原 Pi 会话工厂、配置和 Provider 钩子，公开检索资源由 Host 绑定原需求实例与当前 operation，按同一取消／收尾规则管理。正式接入前验证实际请求、资源加载、历史隔离、回执和取消。缺少可用公开主题、已核实的隔离接缝或受支持配置时，保留相应状态并继续框架，不自动换 Provider、端点或引入 MCP。真实出境权限按现有授权执行。

## 3. 框架内容、确认与 UI

**RAF06｜一份框架提案。** 提案首屏并列显示「是否值得做」和「当前能分析到哪里」，随后给出本轮问题、范围与口径、拟用 SAP／材料、比较路径、预期交付、关键假设及待补证问题。每项重要判断可回看来源、版本和适用条件。清楚说明缺口影响哪个问题及如何补证。比较路径是给用户确认范围的建议，后续分析 Agent 自主选择具体方法与工具。

**RAF07｜一次确认本轮框架。** 在原框架提案区提供「确认分析框架」，沿原显式采纳路径保存所见框架版本、范围及当时依据。允许确认带边界的可行范围或待补证框架。确认框架只代表用户接受本轮提案，原需求确认、RAP 发布及显式送入仍按既有合同和状态处理。送入本轮框架时，在原发送路径绑定并核对所选已确认版本与依据摘要，回执记录实际送入内容。显式选择旧发布 RAP 时交付该版本原内容。已满足的确认无需重复点击。保留原 RAP 0.2 格式与旧版本读法，来源与审查附注随本轮提案或既有记录关联。现有格式不能承载所需记录时，实施前以兼容性证据确定最小增量；不把旧记录无依据回填为已审查。

**RAF08｜保护提案和历史。** 复用工作稿指纹，另绑定确切提案版本、已选 RAP 及实际引用来源的身份、版本和权限。确认时在原业务写入口原子重核。生成后修改工作稿、变更已选来源版本或撤销关键授权，旧提案保留其可读部分，明确失效并停止采纳或新送入。已撤权资料的正文与片段停止展示和交付。用户可检查变化后显式生成新提案，已采纳的历史按原版本与当前权限回看。无关资产更新和新发布但仍有效的固定版本不使提案失效。失败、取消、收尾未知和迟到回执按原 operation 资格显示。原框架、草稿和发布版保全，明确取消后不会迟到采纳。用户另行发起时生成新请求。

| 用户情景 | 拟议界面与操作 |
| --- | --- |
| 准备框架 | 复用「需求梳理」四阶段和原生成入口。默认显示已有工作稿或明确选择的 RAP 版本，来源与权限详情按需展开。 |
| 框架待确认 | 首屏给出价值建议、可分析范围和关键缺口；按需展开行业案例、内部经验、SAP 和资料。用户可确认本版或回到工作稿补充。 |
| 搜索不可用或未找到可比案例 | 在公开来源区显示真实状态与影响，保留内部依据和其他可确认内容。 |
| 依据已变化 | 显示变化项和旧提案，原确认动作失效。用户可重新生成，生成后可确认新提案。 |
| 生成中、停止或失败 | 复用原运行状态、停止和错误提示；不重复派发。原有内容仍可查看。 |
| 已确认框架 | 显示确认版本与范围，发布和送入继续由用户经原入口显式操作。 |

## 4. 接入与四原则核对

| 原则 | 本方案的边界 |
| --- | --- |
| Host 管环境 | 校验需求实例、目标材料权限、版本和 operation，提供实际可读上下文与公开搜索资格，保存真实回执并处理停止、失效、并发。专业判断由 Agent 作出。 |
| Agent 自主执行 | 自主查证、评估需求价值、适用口径、比较路径与缺口。五类问题用于说明结果，Host 无固定检索顺序、工具配额、分数或统一业务放行判断。 |
| 复用 Pi 已有能力 | 按工程规范 v1.9 与 Interface v3 兼容业务子集。复用 `requirements-elaboration`、真实 `instanceId` owner、独立需求 workspace、原配置快照和会话 lease。确认实际锁定的官方 Pi `1.4.0`，沿公开接口与现有 Host 适配；当前专属需求 profile 未注入原生搜索或普通任务工具，新增能力须验证所需最小接缝，保留其他 profile 的边界。 |
| 减少人的操作 | 正常路径沿原生成与提案采纳，用户对本轮框架作一次集中确认；不要求逐项审批查读、手填六库引用、切换 Provider 或维护额外资料。仅在既有授权或关键业务取舍需要时让用户介入。 |

按[IN01–IN07](../../../docs/engineering-workflow.md#统一会话接入规范当前interface-v3兼容v1v2业务子集)、[统一会话接入说明](../../../docs/agent-session-integration.md)和[SDK 治理](../../../docs/engineering-workflow.md#官方-pi-sdk-来源与版本约束)验收。未来获授权的改动限需求插件的 `api/`、`session/`、`contract/`、`ui/` 及确有缺口的 Host 需求会话、来源与原生检索适配、对应检查与文档。其他 Agent 入口、第三方 SDK 源码和版本、正式服务和封存评估不在本轮实施范围。已读工作树基线为 `70d932c9acc7`，现有源码中[需求会话](../../../src/host/requirement-sessions.ts)与[原框架页](../../../extensions/business-plugins/requirements-elaboration/ui/RequirementPage.tsx)为具体接缝。

## 5. 验收判据

以下是实施后的可观察判据。设计验收只检查本文与 Demo 的交互、文案和边界一致性。

| 标识 | 可观察结果 |
| --- | --- |
| RAF-A1 输入与适用性 | 用合成案例覆盖已有 RAP、无 RAP 工作稿、RAP 与当前事实冲突。已发布 SAP 和同条件历史可定位复用，未发布 SAP、不同项目未授权资料和不适用的历史不被冒充为本轮依据。 |
| RAF-A2 价值与可行范围 | 覆盖价值高但证据不足、有足够数据但价值低、部分可回答三种情形。提案能指向具体决策、受影响的问题、证据缺口及下一步，且允许保留未知。 |
| RAF-A3 公开检索与隔离 | 通过实际 SDK 接缝和隔离合成 Provider 核对支持／不支持、真实结构化回执、零结果、失败与未知。验证公开请求排除合成私有标记和前次私有历史，伪造正文 URL 和旧 operation 回执不能成为本轮原生来源，带指令的摘要无法扩大材料权限。检查无自动切线路。 |
| RAF-A4 确认与失效 | 浏览器验证一次确认实际显示的提案并回读其版本和范围。改稿、替换来源、授权撤销、竞争确认及迟到结果不覆盖新草稿或已发布版本。确认不触发普通分析或发布。显式送入后的模型首请求及历史回读与实际选版一致，旧发布 RAP 不混入新稿。 |
| RAF-A5 生命周期与兼容 | 原需求会话生成、有限格式修正、停止、关闭、配置切换、刷新、原 RAP 0.2 读回和普通项目路径回归。设计检查、工程检查、真实检索／专业效果与用户验收分别记录。 |

## 6. 与另外两项评审的接缝

本环节交付用户确认的分析框架。进入分析后，正式报告按适用范围走[主 Agent 的计算复核](../report-calculation-review/spec.md)。保存报告后，用户可按需发起[结论与建议审查](../conclusion-recommendation-review/spec.md)。两项审查可引用本轮获准的框架与 RAP 来核对问题和口径，各自沿原触发与权限执行。

## 7. 评审候选检查

Chrome 用合成场景验证了框架确认、四种公开检索缺口、无 RAP 工作稿、来源变更、停止后保留旧稿及显式重新生成，桌面及 390 像素布局均可用。非作者按规格与四原则检查了公开检索隔离、实际送入版本和旧记录回读，相关发现已补入 RAF04、RAF07、RAF08 及验收判据。当前结论只覆盖文档和原型，实际产品请求与权限以实施后的 RAF-A1 至 RAF-A5 证据为准。
