# Studio 使用声明的参数契约修复

## DU01 模型可见的数组契约

沿用工程规范 v1.9、统一会话 Interface v3、项目普通任务原 owner/profile、Host 注入的 Studio port 和官方 Pi 1.4.0。新案例原生 MiniMax 四次把 `declare-use` 的 `payload.sources` 写成对象包装，原工具仅返回 `invalid_studio_sources`。从现有工具注册把引用列表表达为数组。继续接受原来可省略的引用列表和 Host 对 null 的既有处理。元素、最多 200 条的限制及权威资格仍由原 Host 校验，保留原业务错误码。

## DU02 可修正的工具错误

在官方工具参数准备入口识别错误形状，指出 `payload.sources`、期望数组、实际类型及直接数组写法。先于 SDK 类型转换。保留稳定错误码和原业务端校验，不接纳包装对象、自动展平或代填来源。修正调用后仍由原接口验证项目、报告字节、准确引用及资格并保存真实作者回执。该回执与实际使用、专业核验分别判断。

修改范围限 Studio 工具 schema、现有会话工具注册、回归和本记录。状态仍使用现有发布和采用回执，UI Demo 不适用。验证原生工具 schema、错误回传和原接口落单，并用原普通 Agent 和同一 MiniMax 线路在隔离续接副本另存修订，验证真实声明及报告摘要。保留原稿、失败、业务资产和会话历史。修复与实模续接阶段暂缓 Git 交付及服务切换。后续获准单独交付 Git。
