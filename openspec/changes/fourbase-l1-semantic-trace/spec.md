## 1. 产品目标与第一版边界

**本轮用户追加并确认的强制边界：只作辅助、不阻断原分析流程、正常新增必做操作为零。** 在相同可用数据与权限下，原本能完成的分析增加L1后仍须能直接完成。空语义资料、未发表资料、辅助查询不可用或来源留存失败不构成Host的运行准入／完成门槛；不强制先检索、补全资料、确认引用或成功保存来源才继续计算。Agent按任务需要自主决定是否使用，失败可据现有材料继续并说明局限，留存缺口与分析完成分别记录。用户明确指定的必要材料／权限及原件保护仍沿原合同核对，不能为省操作静默忽略选材、换latest、扩大权限或伪造来源。

用户在原项目任务直接问：“当时采用什么规则？哪些证据支持？后来哪些前提变了？”Agent 可以沿已保存的精确引用找回原规则、数据说明、报告和 Case 判断，解释新旧依据的差别、支持／反对材料与未知，并在原任务继续分析。不要求先建设语义资产全集、维护日记、整理图谱或逐条确认读取。

**L1 是现有业务定义、数据映射、来源及精确版本引用构成的业务语义基础。** SAP 是正式指标口径权威，企业资料承载概念和规则原文，M2 保存输入／说明／成果来源，M5／M6 保存判断、关系与历史引用。本次补可用的查询接缝及 Agent 主动保存明确成果来源的差额，不另建 Semantic Registry、ConceptStore、九类通用对象、统一 ID 或业务时间历史库。

**L2 是后续可选的派生语义／图查询增强。** Semantica 是优先验证候选，Graphiti 是有条件的比较项。当前不安装、不接线、不启动其运行时；最小采用范围与进入条件见[组件边界](component-boundary.md)。L1 不能依赖 L2 才能工作。

本版不承诺：任意多跳图查询、对自由文本执行可靠的业务时点过滤、完整历史“当时所有已知信息”快照、自动识别全部受影响判断、已验证因果、全套 Binding 注册／发布平台或旧任务真实计算采用的机器证明。没有证据时回答未知，不补造历史。`analysis-ir` 未核得现成接线，且原批准方案明确不建 IR；它不是前提。

## 3. 可观察行为

### 3.1 原任务自然提问

原任务、选材和普通发送保留。Agent 可不查语义、只读一份资料，也可多次读引用链并使用 Python／DuckDB 复核；没有规定先查询、再验证、再计算的必经步骤。无 Case、无 SAP、未发表资料或只有制度／观点时仍可分析；不存在的正式口径、正式引用或业务时间如实说明。

新工具 `read_semantic_context` 提供 `find/read/trace` 三种只读动作，供普通 `project-tasks` 使用。它是业务工具适配，不是第二个 Agent 或查询规划器。`find` 从已准入的原目录／索引查找，`read` 读准确对象，`trace` 只展开显式 refs；自然语言材料中的关系由 Agent 阅读解释，Host 不抽取成隐藏 JSON 图协议。

### 3.2 三种时间问题分别回答

| 用户关注 | 本版依据 | 禁止推断 |
| --- | --- | --- |
| 原稿写明用了什么 | 准确成果／citation／Case revision 中的作者声明及原文 | 提供过、项目启用或检索命中不等于引用，更不等于真实计算执行正确 |
| 截至当次有哪些留存依据 | 可核定的原保存／发布／事件及 native 提供记录；披露范围不完整 | 不声称重建了当时全部知识；不由当前启用、归档、权限反推过去 |
| 今天回看，哪些前提可能变化 | 原、新准确修订／新增资料，业务时间声明及来源，Agent 的影响解释 | 新文档回溯生效不能改写旧报告实际引用；新日期不自动胜过旧证据 |

例如 10 月 10 日报告明确引用规则 1.2；11 月 2 日才保存一份“10 月 1 日生效”的通知。历史视图保留报告／1.2；现在回看可指出新通知的追溯适用声明，同时说明当时是否已获知未必可证。业务生效、系统留存和实际引用分别展示。

第一版不新增有效期持久字段。`effectiveTime`／`business-time` 返回原文及准确来源；没有明确日期／时区就保留未知或歧义。`recordedBefore` 只筛有合格系统留存证据的记录，未知项另列，不将其当“不存在”；不提供假的通用 `asOf`。已有库没有历史目录状态时，结果说明只能追溯已定位的原件，不能宣称完整历史搜索。

### 3.3 证据、关系与 Binding

从 M5 判断沿原 `supports/opposes/limits/depends_on/...` 读取准确目标，再从 M2 citation 获取其输入、说明、SAP、概念资料和附件清单。作者的关系声明与原文并列，方向保留；不把 supports、用户收藏或结构验证升级为事实／因果证明。不自动创建跨 Case 写关系、级联失效、重算或撤回人的选择。

Binding 沿 M2 字段位置与映射读取，报告“已声明／可观察／未知”的粒度、键、单位、时区和重复计数风险。需要数据核查时 Agent 自主用获准输入和 SQL／Python 完成，检查说明及查询／结果按原附件保存。Host 只验身份、格式及固定字节，不替 Agent 做 JOIN、统计、业务校验或生成结论。不新增完整 Binding 状态机或机器可读约束库；本版缺口暴露与可追溯核查不宣称已具备任意自动 Binding 验证。

### 3.4 明确引用可由 Agent 留存

新工具 `record_analysis_sources` 只委托原 M2 `createCitation`：普通 Agent 选明实际成果、附件和精确来源，显式说明引用关系，Host 按同一哈希、大小、路径、版本和 CAS 合同另存。本项改变原 M2-D06“仅用户显式记录”的准入，须整体确认 D05 后才开发。Host 不在每轮结束时自动补清单，也不从 read／providedContext／调用成功推断采用。

回执始终是“作者声明引用，真实计算采用／专业正确性未因此获证”。同一文件修订形成新 citation，旧稿和旧来源不改。无需新采用账本、分析 IR、独立评分或用户逐项审批；正式 SAP 发布、资料保留、Case 人的选择仍走原授权。仅查资料时无需保存 citation。

## 4. 接入、边界及兼容

- 规则：工程规范 v1.5 第2–4节及 IN01–IN07；Interface v3；当前锁定／安装 Pi `1.4.0`，不升级 SDK。
- owner/profile：原 `project-tasks` 的真实 projectId/taskId，由 Host 从当前操作绑定；不接收客户端自造 native 路径、Provider 或管理资格，不新增会话域／排队器。native 工具结果、取消、分支、恢复、压缩仍由 Pi 和原统一入口持有。
- IN06测试入口最小例外：仅`tests/semantic-context-runtime.test.ts`按既有M4／M5运行测试模式直接构造ProjectAgent，验证真实锁定SDK的嵌套资格、取消、迟到与辅助失败后计算；该单一测试路径加入边界检查精确清单，不给产品模块或其他测试放行，生产仍只走原公共生命周期。原边界FAIL与修正后检查分开保留，最终由非作者复核该例外。
- 新查询仅普通任务、已准入目录／对象；受管、独立核算／冷读、fixed-draft、需求和 PPT 专用资源不增此工具，也不引导关闭保护。人历史查看沿原读取资格，不能从 Agent 新供给的限制推导删除历史。
- 原010软提示与敏感资料提示保留；引用命中不授予另一项目数据读取。跨项目数据字节继续原受控选材／复制，目录 metadata 也须走原资格。
- 结果分页／正文上限沿资源边界，披露部分、未知、失效、排除、权限不足、缺失和哈希冲突；不回落同名或 latest。无模型的 HTTP 历史查看不打开／恢复 Agent。
- 来源保存幂等及未知复用 M2 操作合同，同 operationId 同载荷回读，换载荷冲突；取消／迟到只记录真实结果，不自动重放写入或模型。写前重新核 owner、当前操作和项目可写性。
- 无新持久对象、SQL 表、业务时间索引、统一状态或批量迁移；旧项目／Case／SAP／Pi JSONL 不因 GET 回填。新 citation 仍用现有 schema2。回退时保留其字节，禁用新工具，原 UI 能准确读取新记录；不能回滚旧副本覆盖新增成果。
- 允许未来实施路径：`extensions/business-plugins/semantic-context/` 中无存储／无 Runtime 的业务读适配；`src/host/semantic-context-*.ts` 薄路由／资格接线；`src/agent/semantic-context.ts` 工具定义；现有 `project-session/project-runtime/server`、M2 read／citation 接缝、原任务 UI 依据组件与相应永久测试。是否拆文件以真实接缝为准，不新建可安装插件平台或独立存储根。不需要改 SAP 发布格式、Case／Board schema 或既有引用枚举。
