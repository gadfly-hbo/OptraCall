## 4. 四原则前置检查（设计范围）

| 原则 | 本设计的证据／正常路径 | 必须拒绝的反例 |
| --- | --- | --- |
| Host管环境 | spec§2／4：核归属、原引用、权限、CAS、资源与保存；领域读适配不选专业答案 | 每轮结束自动拼采用清单、代做JOIN、替人裁定哪份制度为真 |
| Agent自主执行 | spec§3：普通提问→Agent自主find/read/trace或不用；可比较、补证、计算或保留未知 | 固定先后步骤、调用次数配额、强制先发表或无必要逐读确认 |
| 优先复用Pi与已有能力 | reuse-audit，Pi1.4.0＋Interface v3，原citation／M5／M6；组件原生时间留给L2验证 | 新会话／消息／压缩／恢复引擎，统一Registry／采用证明账本／图历史库 |
| 减少人的操作 | 用户目标＋正常发送，新增必做0；D05Agent明确保存，查看／纠正可选 | 日记维护、先填全部语义资产／时间表、让用户搬运来源与机器ID |

失败／恢复路径：缺失可据现有材料继续并说明局限；冲突由Agent／人按证据解释；保存未知沿原操作核对，不重放；权限问题沿原必要授权，不建议关闭保护。组件不可用不影响原普通任务。准备检查只能判“设计范围通过／待验证”，最终专项按实际代码、调用链、运行记录及全新非作者证据重新判定，不能复制本表冒称最终PASS。
