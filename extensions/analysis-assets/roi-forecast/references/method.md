# 投放 ROI 测算方法

引擎版本 `optracall-roi-1`。数学与校验语义承接 target-forecast 原仓 `roi_tool`（MIT，业务基线 `df5acd6`），以 OptraCall 分析资产形态纯 Python 重实现；等价性由黄金案例自检证明（见文末）。

## 1. 链路公式（单计划）

```
点击   = 消耗 ÷ CPC
订单   = 点击 × CVR
GMV    = 订单 × 客单
净毛利 = GMV × (1−退款率) × 毛利率 − 消耗
ROI    = GMV ÷ 消耗
保本 CVR* = CPC ÷ (客单 × (1−退款率) × 毛利率)
gap   = CVR* − CVR        （>0 即低于保本线）
```

- 情景增速只作用于 CVR 与客单（乘以 `1+growth`），其余参数平推；
- `cvr_star`/`gap` 不做舍入：舍入会破坏与精确值的比对及"below_breakeven 判定 = (CVR < CVR*)"不变量；
- 显示字段舍入规则：金额/GMV/净贡献 2 位、点击/订单 1 位、CVR 6 位、ROI 4 位。

## 2. 参数校验（结构与语义）

必填字段：`name, spend_cny, cpc_cny, cvr, aov_cny, gross_margin, refund_rate`。

| 字段 | 约束 |
| --- | --- |
| spend_cny / cpc_cny / aov_cny | > 0 |
| cvr | ∈ (0, 1) |
| gross_margin | ∈ (0, 1) |
| refund_rate | ∈ [0, 1) |

校验失败抛 `PlanError`，消息格式 `计划名: 字段 说明（当前值 x）`——转述给使用者，不替其改数。

## 3. 跨情景稳定性

计划在各档情景下净贡献**符号一致**（全正或全非正）才算结论稳定；符号翻转的计划结论是"随假设翻转"，应建议先收窄假设（小规模实测）再决策。

## 4. 未建模边界（报告必须声明）

- 消耗与 CVR/客单独立：无边际递减、无频次控制、无素材疲劳；
- 无时间结构：不分日/周节奏，不建模学习期；
- 毛利率与退款率视为常数，不随 GMV 规模变化；
- 结果是情景推演非预测；演示/示例参数为合成假设。

## 5. 输出身份

每次输出携带 `engine_version`（`optracall-roi-1`）与 `input_digest`（输入 canonical JSON 的 SHA-256 前 16 位）。同输入 + 同引擎版本 = 逐字节一致输出；引擎逻辑变更须递增版本。报告中照抄这两项，供复盘与复核。

## 6. 黄金案例

`scripts/roi.py selftest` 用原仓 GRILL G1 合成演示计划集（4 计划 × 保守/基准/挑战三档）对照 `scripts/golden/roi-expected.json` 逐字段核对——期望值由原仓 `roi_tool.engine.evaluate` 在固定输入上计算生成。任何环境跑一遍即可验证移植等价性与确定性。

黄金案例数值节选（基准档，元）：

| 计划 | 净贡献 | ROI | verdict | 跨档稳定 |
| --- | --- | --- | --- | --- |
| 天猫直通车-搜索 | 44,131.20 | 6.2400 | 净贡献为正 | 是 |
| 抖音千川-信息流 | −10,700.00 | 3.3000 | 净亏损 | 否（挑战档转正） |
| 京东快车-站内 | −53.33 | 2.9333 | 净亏损 | 否（基准贴零、档间翻转） |
| 小红书聚光-种草 | −1,027.50 | 2.0250 | 净亏损 | 否（挑战档转正） |

（基准档仅搜索计划稳定为正；其余三个计划结论随假设档位翻转，是稳定性判据的现成示例。）
