# 投放 ROI 测算

你在为投放决策做盈亏测算。输入是各计划的假设参数（消耗、CPC、转化率、客单、毛利率、退款率）；产物是**给定假设下的情景推演结论**——不是预测承诺，也不是投放建议。数字一律出自脚本输出，你的职责是口径确认、参数收集、结论解读与边界声明。

## 一、红线（违反即无效测算）

1. **不心算**：任何进入报告的数字必须来自 `scripts/roi.py` 的输出（含 `engine_version` 与 `input_digest`）；改参数就重跑脚本，不在旧输出上做手工加减。
2. **参数是假设**：CVR/客单/毛利率是使用者给出的情景估计，不是行业真值；结论必须带"情景推演 · 非预测承诺"声明。
3. **允许净亏损**：`verdict` 为"净亏损"是合法结论，如实呈现，不用乐观情景粉饰基准情景。
4. **稳定性如实**：跨情景符号不一致（`stable: false`）的计划必须标注"结论随假设翻转，需先收窄假设区间"，不得只报有利档位。
5. **保本口径**：`cvr_star`（保本转化率）与 `gap`（与假设 CVR 的差距）成对呈现；`below_breakeven: true` 的计划不得被描述为"接近盈利"。
6. **无执行环境时不硬算**：任务环境无法运行 python 脚本时，明确声明本 skill 不适用，不要凭公式手推数字交付。

## 二、测算流程（方法指引，非强制步骤）

1. **理解问题**：确认要比较哪些计划、决策口径（投/不投、排序、预算分配），以及使用者对 CVR/客单的假设依据。
2. **收集参数**：按 `template` 生成的模板收集每计划六参数；缺字段或数值越界时脚本会报出计划名与字段名——如实转述给使用者，不要替其猜数。
3. **情景设定**：缺省用保守/基准/挑战（CVR 与客单各 ±20% 增速）；使用者有明确判断时按其口径设档，增速含义（对 CVR/客单的乘数）先讲清。
4. **运行脚本**：`python3 scripts/roi.py run --input plans.json -o out.json`；把 `engine_version`/`input_digest` 写进报告。
5. **解读结论**：每档排名与汇总、每计划保本差距与稳定性；对"结论随假设翻转"的计划建议先做小规模实测收窄假设，而不是直接给投放建议。
6. **产出报告**：中间结果存 `020_clean`，最终报告存项目 `060_reports`（Markdown），含参数表、分档结果、稳定性表与边界声明。

## 四、边界

- 链路假设消耗与转化率独立：不建模边际递减（加预算 CVR 下降）、频次控制、素材疲劳；结论外推到更大预算前必须声明该边界。
- 单位：金额为元（CNY），比率是小数（0.06 = 6%）。
- 本 skill 不做归因、不读投放平台后台；输入参数由使用者提供或从其资料中整理并经确认。
