# 优惠券复盘方法（预测 vs 实际）

本文件是**方法文档**，不含脚本：复盘由 Agent 按此方法与用户协作执行，预测误差不自动写回参数。顺序固定：先口径核查，再对比，再讨论参数。

## 1. 前置条件

- 存在一次已保存的测算结果（候选比较输出，含所选方案的 metrics）；
- 实际结果至少包含：订单数、券前 GMV（分）、商家券补（分）、观察窗口；建议另有：券后支付额、核销量。

## 2. 第一步：口径核查（不通过不进入数值对比）

| 检查 | 判定 |
| --- | --- |
| 观察单位一致性 | 实际订单数 > 场景 N 时大概率"订单≠用户"口径错位，先对齐 |
| 窗口一致 | 预测窗口（如 7 天活动期）与实际统计窗口文本核对 |
| 退款口径 | 实际值未声明退款口径时先确认（预测默认未扣退款口径） |
| 金额单位 | 双方都是整数分 |

## 3. 第二步：描述性对比

对齐口径后逐指标对比（预测取自所选方案 metrics）：

| 指标 | 预测来源 |
| --- | --- |
| 订单数 / 最终转化率 | orders / conversion_rate |
| 券前 GMV / 客户支付商品额 | gmv_pre_cents / gmv_paid_cents |
| 商家券补 | merchant_subsidy_cents |
| 核销量 | natural_redemptions + topup_redemptions |

记录每指标 diff 与百分比；**这是描述性对比，不升级为因果结论**——无对照组时不识别真实增量（活动效果 ≠ 券效果）。

## 4. 第三步：偏差归因（七类，逐类记录证据与结论）

1. **流量偏差**——N 或触达与假设不符；
2. **基准转化偏差**——C₀ 本身偏了；
3. **客单结构偏差**——篮子分布（Aᵢ/wᵢ）与实际不符；
4. **触达/核销偏差**——e / r / r⁺ 与实际不符；
5. **加购/流失假设偏差**——q 曲线或 d 与实际不符；
6. **成本/结算偏差**——毛利率、费用、退货口径差异；
7. **未识别剩余差异**——以上解释不完的部分，如实保留，不硬凑归因。

## 5. 参数新版本（人工确认，旧版本不可变）

归因清楚后如需修正参数：基于原场景派生新版本（scenario_id 加 `-vN` 后缀），逐项记录变更路径与依据，`parameter_sources` 标注来源为本次复盘（historical_descriptive）与确认人；**旧版本文件永不覆盖**。修正后必须重跑 compare，新旧结果并排呈现。

## 6. 纪律

- 预测误差不自动写回；每个参数修正都是用户显式确认的动作；
- 复盘结论保留双方口径与窗口描述；
- `causal_claim` 恒为 false：除非另有对照实验，不宣称增量效果。
