# 优惠券四子模型测算方法

引擎版本 `optracall-coupon-2`。数学与校验语义承接 target-forecast 原仓 `coupon_tool`（《优惠券测算工具 v2.0 方案》§4 逐式实现，业务基线 `df5acd6`），OptraCall 分析资产形态纯 Python 重实现；等价性由黄金案例自检证明。

## 0. 单位与对象约定

- 输入名义金额为**整数分**（int 进入校验）；概率加权后的期望金额以分为单位，用 float 计算并输出至 6 位小数，不先取整；概率与比率为 0–1 float；
- 观察单位：独立访客的首次支付订单（`unique_visitor_first_paid_order`）；N=访客数，缺 N 时按每观察单位口径并提示；
- 篮子（basket）：一笔基准成交的券前可用商品金额 Aᵢ 与条件权重 wᵢ（Σwᵢ=1）。

## 1. 子模型① 命中与核销（Aᵢ ≥ T，自然达标）

三分支（概率合计=1）：

| 分支 | 概率 | 金额 |
| --- | --- | --- |
| 未触达·按原计划购买 | 1−e | Aᵢ |
| 已触达并核销 | e·r | Aᵢ |
| 已触达未核销·按原计划购买 | e·(1−r) | Aᵢ |

e=触达率、r=自然核销率（可逐篮子给列表）。不估计超门槛加购与反向流失。

## 2. 子模型② 凑单与流失（Aᵢ < T）

五分支（概率合计=1）：

| 分支 | 概率 | 金额 |
| --- | --- | --- |
| 未触达·原样购买 | 1−e | Aᵢ |
| 加购达标并核销 | e·q·r⁺ | Bᵢ |
| 加购达标未核销 | e·q·(1−r⁺) | Bᵢ |
| 未加购·仍原样购买 | e·(1−q)·(1−d) | Aᵢ |
| 未加购·放弃原本购买 | e·(1−q)·d | 0（流失） |

- 凑单概率 q：`curve` 模式 q = q_cap·exp(−λ·g)·min(1, (F/T)/d_ref)，g=(T−A)/A 为缺口率；`table` 模式按 (gap_max, ftr_max) 首个匹配行；`zero` 恒 0。曲线是**演示情景参数**，须可替换；
- Bᵢ（加购后金额）缺省按"恰好凑到门槛"（B=T）简化，可显式给 topup_amount_cents；触发简化时 limitation 如实提示；
- 流失 d 产生损失：流失订单贡献为 0，损失经 ΔΠ 体现。

**桶穿提示**：粗桶输入（bucket_min/max）当 T 落在桶内时，结果基于桶均金额，触发"穿过粗桶"警告——建议细分或提供上下界。

## 3. 子模型③ 转化响应（新增成交 ΔC⁺）

- `relative`：s⁺ = min(k·F/T, s_max)，ΔC⁺ = min((1−C₀)·e⁺, C₀·s⁺·e⁺)；
- `absolute`：直接给 ΔC⁺，超出可触达非购买者上限时 limitation 告警；
- 新增成交落在新篮子分布 vⱼ（金额可为 `at_threshold`），权重合计=1；无券候选不运行券诱导行为（ΔC⁺=0）。

## 4. 子模型④ 统一账本与贡献

每分支一行账本：`contribution = 毛利G − 商家券补 − 可变费用V − 退货调整H`，其中：

- G = 原篮子 A·m + 加购部分 (B−A)·m_addon（新增成交按自身毛利率整额计）；
- 商家券补 = u·ρ·F（u=该分支是否核销 0/1，ρ=商家承担比例；平台承担 (1−ρ)F 另列）；
- V = 固定费用 + 费率×收费基数（基数 customer_paid=券后支付额 / pre_coupon=券前额，必须显式）；
- H = 每单退货结算期望净减少额（情景估计）；
- K = 相对无券方案的新增固定活动费用（只对 enabled 候选计）。

汇总指标全部从账本行求和：订单、券前/券后 GMV、商家券补、总贡献 Π、无券基准 Π₀ = N·C₀·Σwᵢπ₀ᵢ、**增量贡献 ΔΠ = Π − Π₀**、转化率 = C₀·R + ΔC⁺（R=1−Σwᵢ·流失率）。

**不变量（selftest 断言）**：互斥分支概率合计=1；贡献拆解（自然核销/凑单/其他保留/流失/新增/固定成本）求和 = ΔΠ（对平，容差 1e-3 分）。

## 5. 候选生成与约束（决策层）

- 候选集 = 人工候选 ∪ 自动生成（分位数锚定 40/50/60/70/75% × F/T 档位 3/5/8/12/15%，取整到元），**始终包含无券候选**，按 (T,F) 去重；
- 约束过滤（违规标不可行、保留原值）：增量贡献底线、商家券补预算（预估过滤非投放限额）、最低转化/ΔC、最低券前 GMV、单均贡献底线、F/T 折扣上限；受控亏损须显式 max_loss_cents，不得静默退化为底线 0；
- 排序目标：incremental_contribution（默认）/ conversion / balanced（须显式给尺度与权重，禁止从候选集推导）；
- Pareto 前沿：ΔΠ 与 ΔC 双维非劣。

## 6. 四类结论

| 类型 | 含义 |
| --- | --- |
| feasible | 当前候选/模型/参数/约束下的**条件性**建议 |
| no_feasible_coupon | 建议不发券（或无可行解）——合法结论，如实呈现 |
| needs_validation | 参数证据不足（synthetic/historical/business 输入），先小范围验证 |
| invalid_comparison | 候选全不合法，先修输入 |

## 7. 回本分析（盈亏平衡）

对每个可行券方案计算"回本所需毛新增成交率"：d_BE = max(0, (Π₀+K−Π_不含新增)/ (N·π_new_avg))；对应转化 C_BE = C₀·R + d_BE。d_BE 超出可触达上限（(1−C₀)·e⁺）时结论是"当前假设下不可回本"；π_new_avg ≤ 0 时无法靠新增成交回本。预算在 d_BE 处复核。

## 8. 未建模边界

单期期望值模型：无券动态扩散/叠加频次/跨期复购；凑单曲线与转化响应是可替换假设；退货按每单期望净额处理，不建模结算时序；平台补贴只记账不分摊。

## 9. 黄金案例

`python3 scripts/coupon.py selftest` 对照提案 7.1 合成场景（N=100k、C₀=8%、五桶分布、30% 毛利、商家全额承担）：10 行黄金表（转化率/商家券补/总贡献/ΔΠ，±1 分容差）+ 4 情景压力黄金值 + compare 全行结构与拆解对平不变量。期望值由原仓实现在固定输入上生成（见 `references/golden-cases.md`）。
