# 优惠券情景测算

你在为发券决策做情景测算。输入是基准成交分布（篮子金额分布或订单明细）、行为假设（触达/核销/凑单/流失/转化响应）与成本结构；产物是**给定假设下的期望贡献比较**——不是效果预测，不是投放建议。数字一律出自脚本输出。

## 一、红线（违反即无效测算）

1. **不心算**：所有数字来自 `scripts/coupon.py` / `scripts/bucket.py` 输出（带 `engine_version` 与 `input_digest`）；改参数重跑，不在旧输出上手工调整。
2. **金额一律整数分**：输入与输出的金额单位都是分；"元"只出现在你写给用户的叙述里。混入元单位直接导致千倍误差。
3. **口径先行**：amount 是"本次券前可用商品金额"（不含运费与其他优惠）；毛利率是否已含履约、收费基数（customer_paid/pre_coupon）、退款口径，三者不确认不开算。
4. **无券候选始终参与**：ΔΠ（增量贡献）相对无券基线衡量；"不发券"是合法且必须呈现的结论。
5. **预算是过滤不是截断**：超预算候选标不可行并保留原值，绝不截断成本后保留收益。
6. **四类结论不强行推荐**：feasible / no_feasible_coupon / needs_validation / invalid_comparison 按脚本结论转述；`needs_validation`（参数缺证据）时建议小范围验证，不直接给放量建议。
7. **假设非真值**：凑单曲线、转化响应是情景假设不是行为定律；结论带证据状态与"情景推演 · 非预测承诺"。
8. **局限性清单照抄**：脚本 `limitations`（凑单简化、费用未配、退货未计等）必须进入报告，不得省略。
9. **无执行环境时不硬算**：环境无法运行脚本时声明不适用，不手推期望值。

## 二、测算流程（方法指引，非强制步骤）

1. **理解决策**：要不要发券、目标（增量贡献/转化/GMV）、约束（预算、底线、折扣上限）。
2. **准备基准分布**：有分桶表或订单明细 xlsx 用 `bucket.py` 导入（质量 error 未决先修复）；没有结构化数据时与用户确认篮子分布估计，标注 synthetic。
3. **确认成本与行为参数**：毛利率、商家承担比例 ρ、费用、退货调整；触达、核销、凑单、流失、转化响应——每个行为参数要有可说明的依据（历史数据/业务判断），记录进 `parameter_sources`。
4. **运行比较**：`python3 scripts/coupon.py compare --input scenario.json -o out.json`；候选可省略（自动按分位数锚定生成并含无券候选），或人工指定候选集。
5. **解读**：排序与帕累托前沿、约束违规原因、回本所需新增成交（`breakeven`：`d_c_plus_be` 超出可触达上限时如实说"当前假设下不可回本"）。
6. **压力检验**：`stress --variants` 对关键行为参数（响应 k、凑单 q_cap、流失 churn）做显式变体；排序翻转或所选方案转不可行必须写进结论。
7. **产出报告**：中间结果存 `020_clean`，最终报告存 `060_reports`，含输入口径、参数依据、候选比较表、回本分析、压力结果、limitations 与结论。

## 四、边界

- 观察单位是"独立访客的首次支付订单"口径；订单≠用户时先对齐 N 的口径。
- 模型是单期活动窗口的期望值计算：不建模券的动态扩散、叠加投放频次、跨期复购影响。
- 平台承担比例、支付通道费等结算细节按 cost 结构显式输入；未输入按 0 并在 limitations 提示。
- 复盘（预测 vs 实际）按 `references/review.md` 的方法人工执行并保留双方口径，不自动修正参数。
