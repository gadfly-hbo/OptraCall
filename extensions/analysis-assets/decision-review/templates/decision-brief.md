# 决策说明模板（Decision Brief）

> **轻量为默认**：普通决策用轻量版；完整版适用于高影响、难撤销、需多方共同审阅或用户明确要求完整说明的场景。模板只提供结构，详细规则以 `SKILL.md` 与专项参考为准；用轻量版无需解释为何不用完整版。
>
> **首行状态契约**：落盘首个非空行只写一个合法状态——`draft`（判断仍在形成）或 `ready_for_review`（建议已可供审阅），两者都**不代表已提交或已获批**；`accepted`／`rejected`／`deferred`／`superseded` 仅在相应事实发生后使用。状态行纯文本、不加行尾注释；标题、日期、依据随后。**用户明确采纳什么，就只记录该对象的采纳**——采纳补证建议不等于试点已获批。交付前读回实际落盘文件核对首行。
>
> 业务正文只引用业务材料、数据版本与实际使用的测算产物，不自引本 skill 名称或版本。

## 轻量版（默认）

```markdown
状态：{按证据选择一个合法状态}

**建议**　{现在怎么选，或当前能决定到哪一步}
**依据与取舍**　{关键来源、主要代价和最影响选择的未知}
**下一步**　{谁在何时核对什么，什么结果会改变建议；涉及启动时把必要条件写在同一段}
```

## 完整版（八模块；适用条件：高影响、难撤销、多方共同审阅或用户明确要求）

```markdown
状态：{合法状态}

# {决策问题一句话}

日期：YYYY-MM-DD · 依据：{业务材料、数据版本与实际使用的测算产物}
（状态枚举：draft / ready_for_review / accepted / rejected / deferred / superseded）

## 一、决策问题
要决定什么、何时要定、谁是决定人；区分业务现象与实际选择。

## 二、目标与约束
希望改善什么（用户表述标【用户】，推测标【推测】）；哪些条件不能突破。

## 三、候选方案
列全可行选项（相关时含不行动／暂缓／小范围试行），每案一句话。

## 四、事实与证据（三分列）
- **原始输入及来源**：转述保留[用户转述·原件未见]，已读文件标[原件已阅]，各带适用范围。
- **派生算式及成立条件**：「算式可复算」标注在此项下；派生值保留输入的来源与限制，不写入已核验。
- **独立核验事实**：仅放交叉核验或脚本输出的[已核验·出处]条目。
数字写全口径（指标·来源·单位·分母·适用范围）；未知项全文同一口径。

## 五、假设与未知
未证实判断（含成立条件）、关键缺口与获取计划；费用构成、样本范围、口径未说明即未知；补齐路径见 SKILL「证据与数字」。

## 六、方案后果
各案收益、代价与不确定（已知后果与预测分开，缺依据用定性或区间）。回本与周期换算用 `references/decision-analysis.md` 的权威算式：先算各情景绝对值、再比倍数，全文复用同一结果；分母未知的比率不作排序理由。

## 七、取舍与建议
推荐什么、牺牲什么、适用条件；条件式表述或"信息不足以推荐"。涉及启动、签约、追加投入、延长或扩围的行动句，按 SKILL「建议与行动」写清**该行动自己的批准条件**，条件与行动同段（缺条件→补证＋待批草案；获批→批准范围内启动；扩围/延长/追加须另行授权）。

## 八、验证与调整
观察指标（与目标同口径）、复查时点、触发重议的条件；试点写止损线与判定时点；观测值不写成推广后概率。
```

## 填写纪律（两版通用）

结论与行动在前；审批条件写在提出行动的段落里，文档级审批状态集中在状态行与「取舍与建议」；摘要、可转发话术与备选分支单独读时能判断当前可以做什么（详见 SKILL「建议与行动」「默认交付」）。
