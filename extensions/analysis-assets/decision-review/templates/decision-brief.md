# 决策说明模板（Decision Brief）

> 复制本模板填写；按决策重要性伸缩——轻量问题用"轻量版"单段直答，重要决策用八模块完整版。**状态行是文档内文字标注，不是产品状态系统**；用户采纳/拒绝/暂缓后更新该行或另存新版并标注 `superseded`。

---

## 完整版（八模块）

```markdown
# {决策问题一句话}

状态：ready_for_review          # draft / ready_for_review / accepted / rejected / deferred / superseded
日期：YYYY-MM-DD · 依据版本：{引用的分析/测算产物与 skill 版本}

## 一、决策问题
要决定什么、何时需要决定、谁是决定人。区分"业务现象"与"实际选择"。

## 二、目标与约束
希望改善什么（用户明确表述的标【用户】，推测的标【推测】）；哪些条件不能突破（资源/政策/时间）。

## 三、候选方案
列全可行选项，含不行动/暂缓/小范围试行（相关时）；说明每个方案是什么、谁提出。

## 四、事实与证据
已知什么——逐条标注：事实/证据（来源·时间·核验状态）/经验（适用范围）；每条证据加来源级别：[用户转述·原件未见] / [原件已阅] / [已核验·出处]。
引用测算与分析的数字注明出处（如"coupon-forecast 输出：回本所需转化提升 X%"）；决策用数字写全口径五要素（指标名称·来源·单位·分母·适用范围），口径不全就标"口径不全"。
材料未给出的样本范围、比较对象（单店/同店/全店/全渠道）、统计口径（单位/分母/期间/含税退货）→ 不默认补写，列入第五模块"未知"并给核对动作。

## 五、假设与未知
哪些判断尚未证实（含成立条件）；关键缺口是什么、对结论的影响、获取计划与成本。
转述类证据的待核对项单列（例：门店范围——哪些店？比较口径——同店/同期/同口径？同期对照——未调整门店或上一期间？原件——报告名称与导出时间，由谁核对）。
量化缺口注明由哪个现有测算流程补齐（data-analysis／target-forecast／coupon-forecast／roi-forecast）。

## 六、方案后果
各方案的收益、代价、风险/不确定（已知后果与预测分开写；无依据处用定性或区间，标"估计/未知"）。

## 七、取舍与建议
推荐什么、牺牲了什么、适用条件；默认条件式表述（"若X成立则倾向A"）；或明确"信息不足以推荐"。
**试点建议分级**：成功标准或业务投入上限任一缺失 → 建议仅限补证与准备待批方案（写明待补项与由谁确认），启动留待确认，不因业务方催促而提前；两项齐备但未获批准 → 可给"可审议的试点方案"（含投入上限、止损条件、判定时点、确认人），状态仍为待批（ready_for_review）；用户明确批准后才记 accepted（已批准）。
涉及用户未表态的价值取舍 → 列出问题请用户确认，不代答；催促不等于批准。

## 八、验证与调整
观察什么指标（与目标同口径，写全五要素：指标名称·来源·单位·分母·适用范围）、何时复查、什么情况触发重新考虑；先行试行的判定标准（若采用）。
试点结果只报告该试点的观测值（如"观测达标率 3/10，样本＝该试点 10 场"）；规模化预期另行标注"待验证，由 X 测算流程/后续数据补齐"，不把观测频率写成预期概率。
试点须写明止损条件（触发即停的损失线）与判定时点；未获批前本模块只是待批方案的组成部分。
```

## 轻量版（单段直答）

```markdown
**决策问题**：{一句话}。**关键依据**：{证据1/证据2，注来源}。**关键假设**：{尚未证实项}。
**建议**：{条件式建议}。**验证**：{看什么、何时复查、什么情况重议}。
（本问题轻量，未展开完整八模块决策说明；需要时可升级。）
状态：ready_for_review
```

## 填写纪律

- 六类信息（事实/证据/假设/经验/偏好/未知）不混写，逐条对号；
- 数字出自脚本输出或用户材料，注明出处，不转写失真；
- 不编概率、效用、权重；缺依据用定性/区间/情景并标注；
- Agent 建议永不在文字上写成"已决定"；`accepted` 只在用户明确表态后标注。
