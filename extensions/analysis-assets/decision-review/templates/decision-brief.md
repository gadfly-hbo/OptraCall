# 决策说明模板（Decision Brief）

> 复制本模板填写；按决策重要性伸缩——轻量问题用"轻量版"单段直答，重要决策用八模块完整版。**状态行是文档内文字标注，不是产品状态系统**；用户采纳/拒绝/暂缓后更新该行或另存新版并标注 `superseded`。
>
> **首行纪律**：落盘文件的**首个非空行只含「状态：<一个合法枚举>」**——纯文本、不加粗、不加行尾注释；标题、日期、枚举说明都放在状态行之后。**交付前读回实际落盘文件，核对首行**再交。

---

## 完整版（八模块）

```markdown
状态：ready_for_review

# {决策问题一句话}

日期：YYYY-MM-DD · 依据版本：{引用的分析/测算产物与 skill 版本}
（状态枚举：draft / ready_for_review / accepted / rejected / deferred / superseded）

## 一、决策问题
要决定什么、何时需要决定、谁是决定人。区分"业务现象"与"实际选择"。

## 二、目标与约束
希望改善什么（用户明确表述的标【用户】，推测的标【推测】）；哪些条件不能突破（资源/政策/时间）。

## 三、候选方案
列全可行选项，含不行动/暂缓/小范围试行（相关时）；说明每个方案是什么、谁提出。

## 四、事实与证据
已知什么——逐条标注五类：**转述**（[用户转述·原件未见]）、**已阅原件**（[原件已阅]）、**已核验事实**（[已核验·出处]，出自脚本输出或经交叉核验）、**假设**（未证实的推断）、**拟议验证**（我们建议的验证设计，单独标明）。
引用测算与分析的数字注明出处（如"coupon-forecast 输出：回本所需转化提升 X%"）；决策用数字写全口径五要素（指标名称·来源·单位·分母·适用范围），口径不全就标"口径不全"。
材料未给出的样本数量、覆盖范围、比较对象、统计口径（单位/分母/期间/口径界定）→ 不默认补写，列入第五模块"未知"并给核对动作。
来源标签与未知项**贯穿全文**（正文、摘要、表格、汇报话术）——同一证据在任何位置复述都带原标签；复述保留原材料给定的范围，不添不缩。
**输入核验与派生核验分开**：转述输入保留[用户转述·原件未见]及适用范围；派生算式可独立复核时只标"**派生值可复算（算式成立）**"，不升级输入的来源级别；材料未说明的成本构成、费用包含项列入未知——三层分别标注：**输入仍是转述、派生值可复算、包含项未知**。
**计数不等于样本量**：记录条数、汇总组数或对比次数不能直接推成样本数——材料只给汇总结论或对比次数时，样本数量与覆盖范围保持未知，不代填。

## 五、假设与未知
哪些判断尚未证实（含成立条件）；关键缺口是什么、对结论的影响、获取计划与成本。
转述类证据的待核对项单列（例：覆盖范围——涉及哪些对象？比较对象与口径——和什么比、什么口径？费用构成——总成本包含哪些项（税费/杂费/分摊）？原件——报告名称与导出时间，由谁核对）。
量化缺口注明由哪个现有测算流程补齐（data-analysis／target-forecast／coupon-forecast／roi-forecast）。
未知项同样贯穿全文：摘要、表格与话术中用「未知」占位保留，不因排版或简洁而省略。
拟议的验证设计（对照、试验、抽样核对等）单独标注**拟议设计（待执行）**——与转述、已阅原件、已核验事实、假设分开表述，读者能分清"材料说了什么"与"我们打算怎么验证"。

## 六、方案后果
各方案的收益、代价、风险/不确定（已知后果与预测分开写；无依据处用定性或区间，标"估计/未知"）。
**回本类测算三指标**（金额只与金额比较；计算前核对期间、单位与成本范围——是否含其他新增固定成本）：**投入金额**（一次性或分期）；**每月需覆盖的增量贡献额**＝投入金额÷目标回收月数（无其他新增固定成本时；单位：元/月）；**对应的新增销售额**＝增量贡献额÷增量贡献率（贡献率缺失时销售额门槛列为**未知**，交现有测算流程补齐）。注意：投入÷回收月数得到的是**贡献额门槛**，不是销售额。
**比较先对齐**：观测值与门槛比较前确认**同一方案、同一对象范围、同一期间、同一指标与单位**；需汇总或换算时写明换算依据并复用现有测算能力（脚本复算）；缺任一关键输入保留未知、**暂不判定达标**。
**各推广层级分列**：每个层级（如试点与全面铺开）写一行自己的三指标（投入／月贡献额门槛／月新增销售额门槛，各带单位）——本层级只用本层级的投入与回收期计算，**本层级投入或回收期未知→本层级门槛整行保持未知**；验证指标只与**本层级**门槛比较，不跨层级。**单位纪律**：金额门槛用元或元/月；百分比阈值只配比率指标——金额指标不配百分比阈值，比率指标不配金额阈值。

## 七、取舍与建议
推荐什么、牺牲了什么、适用条件；默认条件式表述（"若X成立则倾向A"）；或明确"信息不足以推荐"。
**启动条件分级（同一条件贯穿全文）**：**成功指标及阈值**或**投入上限**任一缺失 → 建议仅限补证与准备待批方案（写明待补项与由谁确认），启动留待确认；用现有设备、低成本、可逆、时间紧迫都不构成例外，含截止期的备选分支同样只能给补证或待批方案。两项齐备但未获批准 → 可给可审议方案（含投入上限、止损条件、判定时点、**有权决策人**），**提交有权决策人审议**，状态仍为待批（ready_for_review）；**获有权决策人明确批准后才可在授权范围内启动**并记 accepted（已批准·未执行）。**行动句核对**：可单独转发的摘要、汇报话术与备选分支自带当前审批状态（待批／已提交审议／已批准·未执行），方案名称与编号与正文一致，**每段行动句与所标状态一致**——仅标「待批」不能抵消正文中的启动建议；没有提交/执行的可查依据不得写「已提交」「已执行」；**批准与执行分开表述**（获批＝取得启动许可，不等于已启动）。不得弱化待批表述（"原则上先跑起来"这类说法不允许）。
涉及用户未表态的价值取舍 → 列出问题请用户确认，不代答；催促不等于批准。

## 八、验证与调整
观察什么指标（与目标同口径，写全五要素：指标名称·来源·单位·分母·适用范围）、何时复查、什么情况触发重新考虑；先行试行的判定标准（若采用）。
验证指标若来自回本测算，按第六模块三指标口径书写（贡献额门槛与销售额门槛分开、各带单位），贡献率缺失时销售额门槛标"未知（待增量贡献率，由 X 测算流程补齐）"；各推广层级的验证指标对齐**本层级**门槛（同方案/同对象范围/同期间/同单位），不跨层级比较；换算依据缺失或口径未对齐时**暂不判定达标**，保留未知。
**期间换算写明依据**：日均与月度（或反向）互转时，按同一对象范围内的**实际营业日数或可核验期间明细**换算，写明换算依据与结果单位并复用测算能力；缺营业日数且无期间明细 → 换算结果保留**未知**，不得拿日均值直接比月度门槛。
试点/试验结果只报告该试点的观测值（写明分子分母与样本口径，如"观测达标率 X/Y，样本＝该试点 Y 项"）；推广预期另行标注"待验证，由 X 测算流程/后续数据补齐"，不把观测频率写成预期概率。
试点须写明止损条件（触发即停的损失线）与判定时点；未获批前本模块只是待批方案的组成部分。
```

## 轻量版（单段直答）

```markdown
状态：ready_for_review

**决策问题**：{一句话}。**关键依据**：{证据1/证据2，注来源与[来源级别]}。**关键假设**：{尚未证实项}。
**建议**：{条件式建议——附当前审批状态（待批/已提交审议/已批准·未执行）与方案名称编号，行动句与所标状态一致；成功指标及阈值或投入上限缺一时只给补证与待批方案；摘要与话术同样受启动条件与证据来源规则约束，不得比正文更强}。**验证**：{看什么、何时复查、什么情况重议}。
（本问题轻量，未展开完整八模块决策说明；需要时可升级。）
```

## 填写纪律

- 六类信息（事实/证据/假设/经验/偏好/未知）不混写，逐条对号；
- 数字出自脚本输出或用户材料，注明出处，不转写失真；
- 不编概率、效用、权重；缺依据用定性/区间/情景并标注；
- Agent 建议永不在文字上写成"已决定"；`accepted` 只在用户明确表态后标注。
