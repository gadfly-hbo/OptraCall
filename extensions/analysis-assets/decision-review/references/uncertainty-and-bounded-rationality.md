# 不确定性与有限理性

## 一、风险与不确定性的区分

| | 可度量的风险 | 不可度量的不确定性 |
| --- | --- | --- |
| 形态 | 有频率/历史数据（次品率、季节波动） | 无先例或分布未知（新市场、政策突变） |
| 表达 | 概率、区间、波动幅度 | 情景（乐观/基准/悲观各写发生条件）、稳健性问句 |
| 应对 | 对冲、余量、验收线 | 退路（止损条件）、小步试行、保持可逆 |

**纪律**：不要给不确定性编概率。问"最坏情况能不能承受"与"方案在哪些情景下翻车"，比一个假数字更有用。

## 二、情景表达法

每个重要方案给 2–3 个情景：每个情景写**触发条件＋后果＋应对**。情景不是预测，是"如果…那么…"的结构化演练；用户能看到建议在哪个情景下失效。

## 三、分析停止条件（有限理性核心）

继续挖信息的判断标准——**新信息还可能改变选择吗**：

1. 两个方案的关键差异已经有足够证据支撑倾向 → 停，输出建议；
2. 剩余未知**不改变排序**（无论哪个答案都选 A）→ 停，把该未知列入验证项；
3. 剩余未知**可能翻转排序** → 值得继续获取，先估算获取成本与时限；成本过高或时限不允许 → 按现有信息给条件性建议＋先行试行安排。

把"为什么现在停"写进决策说明——停止理由是决策的一部分。

## 四、信息价值的直觉判断

不算期望值也可以问三个问题：

- 这个信息**可能改变选择**吗？（不改变就不用买）
- 获取它要多少**钱/时间**，赶得上决策期限吗？
- 有没有**更便宜的代理**（小样本试验、访谈几个典型用户、行业公开数据）？

赶不上期限的关键信息，转入"验证与调整"作为决策后监测项。

## 五、决策期限

明确期限的决策，把"何时必须定"写进决策问题模块；期限临近时按第三节第 3 条处理，不无限延期分析。
