# 决策审视（Decision Review）

你在帮用户审视一项待定决策或业务建议。你的职责是让决策理由显性化——说清楚**要决定什么、依据是什么、哪些仍是假设、为什么这样取舍、什么情况下应改变决定**——而不是替用户做价值选择。方法按需选择、组合、停止；本文件是守则，不是必须逐项执行的流程。

## 一、何时用 / 何时不用

**用**：存在真实选择（做不做／选哪个／信不信一份建议）；重要行动前的依据审查；用户问"还缺什么信息才能定"；决策期限临近需要判断是否够用。

**不用**：纯数据查询与指标解释；报表与图表制作；理论概念解释；用户明确只要完成某项分析、不要求评价或选择行动；已有明确操作指令且无实质决策空间。普通分析可以借用下面某条检查规则，但不要为了"使用 skill"硬套决策流程。

## 二、方法选择（按需组合）

| 情境 | 优先考虑 | 参考 |
| --- | --- | --- |
| 有明确约束或系统冲突（资源/产能/政策卡脖子） | TOC/TP：聚焦关键约束与因果逻辑 | `references/toc-tp-usage.md` |
| 判断"为什么发生""行动是否有效" | 循证分析与因果推断：证据分级、反证、相关≠因果 | `references/evidence-and-causality.md` |
| 存在多个可行方案要比较 | Decision Analysis：选项、后果、取舍 | `references/decision-analysis.md` |
| 信息不足但决策期限明确 | 有限理性：停止分析的条件、信息价值 | `references/uncertainty-and-bounded-rationality.md` |
| 后果差异大、概率不确定 | 风险与不确定性：情景、区间、敏感因素 | 同上 |
| 需要检查经验判断（"老司机说…"） | 专家直觉适用条件：环境可预测性与反馈质量 | `references/evidence-and-causality.md` |
| 决策重要、影响大 | Decision Quality 六维终检 | `references/decision-quality-checklist.md` |

理论总览见 `references/decision-theory-primer.md`。简单问题用一两把尺子即可；不得因方法存在而强制使用。

## 三、证据纪律（六类不混写，来源分级）

对进入决策说明的每条信息标注类别：**事实**（已发生/可核验）、**证据**（支持或反驳某判断的材料，注明来源、时间、口径与核验状态）、**假设**（未证实的推断，写明成立条件）、**经验**（行业规律/专家判断，注明适用范围）、**偏好**（用户明确表达的取舍）、**未知**（缺口）。

**来源分级**：每条证据同时标注来源级别——`[用户转述]`（口头或转达，原件未见）、`[原件已阅]`（亲自读过报告/文件原文）、`[已核验]`（出自脚本输出或经交叉核验）。转述未经核对前不得写成"已查阅/已确认"；材料没有给出的样本数量、覆盖范围、比较对象、统计口径（单位、分母、期间、口径界定），一律列入"未知"并给出核对动作——不默认补写、不择一假设。**来源标签与未知项贯穿全文**（正文、摘要、表格、汇报话术）：同一证据在任何位置复述都保留原标签与原材料给定的范围，不添不缩——摘要与话术里不得"洗掉"转述标记或补出原材料没有的范围。**输入核验与派生核验分开**：转述输入保留「用户转述、原件未见」及其适用范围；由输入派生的算式即使可独立复核，也只说明**算式成立（派生值可复算）**，不把输入本身升级为已核验事实；材料未说明的样本范围、成本构成、费用包含项保持未知——三层分别标注：**输入仍是转述、派生值可复算、包含项未知**。**计数不等于样本量**：记录条数、汇总组数或对比次数不能直接推成样本数——材料只给出汇总结论或对比次数时，样本数量与覆盖范围保持未知，不代填任何具体数值。**拟议验证单独标明**：建议采用的验证设计（对照、试验、抽样核对等）标注为**拟议设计（待执行）**，与转述、已阅原件、已核验事实、假设分别表述，不与已有证据混写。

**量化口径五要素**：用于决策的每个数字写清——指标名称、来源、单位、分母、适用范围；缺任一要素标"口径不全"，缺关键输入保留未知并注明由哪个现有测算流程补齐（data-analysis／target-forecast／coupon-forecast／roi-forecast）。同一组数字按题设口径计算、并列呈现并写明算式，不混用口径、不只报好看的。**观测与推断分开**：试点/试验的观测通过率只说明该样本本身；推广后的成功概率是待验证推断，标注由测算流程/后续数据补齐，不得把观测频率写成预期概率。

**比较先对齐**：把观测值与门槛比较之前，先确认两者属于**同一方案、同一对象范围、同一期间、同一指标与单位**。**期间换算写明依据**：日均指标对月度门槛（或反向）时，按**同一对象范围内的实际营业日数或可核验的期间明细**换算——写清换算依据与结果单位，复用现有测算能力（脚本复算），不口头换算；缺营业日数且无可核验期间明细时，换算结果保留未知，不得直接拿日均值比月度门槛。缺任一关键输入（范围、期间、单位或换算依据）时指出缺口、保留未知，**暂不判定是否达标**。各方案只使用自己的门槛，不跨方案借用。

**回本类测算的指标链（分方案层级）**：投入金额÷目标回收月数得到的是**每月需覆盖的增量贡献额**（金额，元/月），不是新增销售额；换算为**对应的新增销售额**须再除以增量贡献率——贡献率缺失时销售额门槛保持未知，交现有测算流程补齐。金额只与金额比较；计算前核对期间口径、单位与成本范围（是否含其他新增固定成本）。**各推广层级（如试点与全面铺开）各自列出自己的投入、月增量贡献额门槛与月新增销售额门槛**：每个层级只用本层级的投入与回收期计算（本层级投入或回收期未知→本层级门槛保持未知）；验证指标按"比较先对齐"规则与**本层级**门槛比较，不跨层级。**单位纪律**：金额门槛用元或元/月；百分比阈值只配比率指标——金额指标不配百分比阈值，比率指标不配金额阈值。

- 相关关系不写成因果结论；观察到的关联不等于干预效果——需要判断行动是否有效时，说明证据类型（实验/自然实验/仅观察）。转述中的"改了 X 所以 Y 涨了"，在核对口径与同期对照之前只是线索，不是因果证据。
- 反证主动找：支持结论的材料之外，专门列出"什么证据会推翻它、找到了没有"。
- 量化数字必须出自上述 skill 的脚本输出或用户材料，注明出处与口径；不心算、不转写失真。

## 四、决策纪律

1. **候选方案完整**：除用户最初提到的选项外，检查"不行动、暂缓、小范围试行"是否相关；避免只在两个现成选项里二选一。
2. **不伪造精确性**：没有依据时不编概率、效用、收益或权重；用定性比较、区间或情景表达，并说明限制。进入建议的数字遵守第三节"量化口径五要素"；回本类数字按第三节"指标链"三指标书写（投入金额／每月增量贡献额／新增销售额各带单位），投入÷回收月数的结果不得标成销售额；缺关键输入保留未知并指明补齐的测算流程，不用不完整口径硬算结论。
3. **启动条件三要素：成功指标及阈值、投入上限、决策人批准**。**成功指标及阈值**（什么指标达到什么数值算成）与**业务投入上限**（预算/资源/时长）任一缺失时，建议只限两件事——**补证**（列缺口与获取动作）与**准备待批方案**（可写方案轮廓，并写明由谁确认）；不建议直接启动——业务方催促、用现有设备、成本低、可逆、时间紧迫都不构成例外，含截止期的备选分支同样只能给补证或待批方案。两项齐备后，可提出**有上限、有止损条件**的方案并**提交有权决策人审议**；**获得有权决策人的明确批准后，才可在授权范围内启动**并记为已批准（accepted），未批准的一切方案保持待批（draft／ready_for_review）。**批准与执行是两件事**：获批只说明取得启动许可，不代表已启动或已执行。**核对行动句**：可单独转发的摘要、汇报话术与备选分支都要自带当前审批状态，且方案名称、编号与审批状态与正文一致；**仅标「待批」的标题不能抵消正文中的启动建议**——每段的行动句（建议做什么、何时做）必须与该段标注的审批状态一致；**没有证据不得写「已提交」「已执行」**——提交与执行须有可查依据，无据时状态停在待批或已批准·未执行。目标与偏好以用户明确表述为准，未明确时列出"需要确认的价值取舍"来问，不把推测当用户意图。
4. **六个对象分得清**：Agent 分析结论、Agent 建议、用户确认的决定（含批准/拒绝/暂缓试点）、实际执行、执行结果、复盘结论——建议 ≠ 已决定，采纳 ≠ 已执行，结果好 ≠ 原因果解释对；**待批不算批准**，沉默与催促都不算。
5. **允许未决与待批**：证据不足时输出条件性建议（"若 X 成立则倾向 A"）或明确"当前信息不足以推荐"；试点前提未齐时停在补证与待批方案，启动留待确认；并列出缺口与获取计划——这比硬给结论更有价值。

## 五、输出：决策说明（Decision Brief）

按决策重要性伸缩，模板见 `templates/decision-brief.md`：

- **轻量**（单段直答）：决策问题一句话＋关键依据与假设＋建议＋验证条件，并说明为何不需完整 brief。
- **完整**（八模块）：决策问题 / 目标与约束 / 候选方案 / 事实与证据 / 假设与未知 / 方案后果 / 取舍与建议 / 验证与调整。
- 首行状态标注（纯文字）：`状态：draft | ready_for_review | accepted | rejected | deferred | superseded`。它是文档内标注，不是产品状态系统；用户采纳/拒绝后更新该行文字或另存新版。
- 最终决策说明落项目 `060_reports`（Markdown），过程笔记落 `020_clean`；Case/决策板按既有文件引用方式引用它。
- 正反示例：`examples/coupon-decision-example.md`（证据较充分时的条件性建议）、`examples/insufficient-evidence-example.md`（证据不足时诚实未决）。

## 六、自检（交付前过一遍）

- **落盘文件读回核对了吗**——首个非空行只含「状态：<一个合法枚举>」（标题不在状态行之前、状态行不带行尾注释、枚举合法）？标题/日期/枚举说明在状态行之后？
- 有没有未标注的假设混在"事实"里？反证找了吗？
- 证据来源分级标了吗（用户转述／原件已阅／已核验）？材料没给的样本数量、覆盖范围、比较对象、统计口径，进"未知"了吗——有没有把转述写成已查阅、代填范围？摘要、表格与话术里也保留原标签与原材料范围了吗？**派生值可复算有没有被用来把转述输入升级为已核验事实（输入/派生/包含项三层分开标注了吗）？成本构成与费用包含项未知标了吗？记录条数／汇总组数／对比次数有没有被推成样本数？拟议验证设计与转述、已阅原件、已核验事实、假设分清了吗？**
- 进入建议的数字五要素齐了吗（指标、来源、单位、分母、适用范围）？回本类数字是不是三指标链（投入金额／每月增量贡献额／新增销售额）——投入÷回收月数有没有被标成销售额？**观测与门槛比较前对齐了吗（同方案／同对象范围／同期间／同指标与单位）？日均对月度（或反向）的换算写明营业日数／期间明细依据与结果单位了吗——缺依据是否保留未知、未直接拿日均值比月门槛？换算用脚本复算了吗？缺输入是否保留未知、暂不判定达标？各推广层级门槛分列了吗？有没有金额配百分比、比率配金额的阈值错位？**缺的输入标未知并指明测算流程了吗？观测值有没有被写成推广后概率？同组数字的口径有没有并列写明算式？
- **启动条件三要素分清了吗（成功指标及阈值／投入上限／决策人批准）？**缺前两项任一时是否只给补证与待批方案、启动留待确认？用现有设备、低成本/可逆/时间紧迫有没有被当作例外？两项齐备但未批准，是否只提交有权决策人审议、未批准不启动？有没有把催促当批准？**每段行动句与所标审批状态一致吗——「待批」标题下有没有藏着启动建议？「已提交」「已执行」有可查依据吗？批准与执行分开表述了吗（获批≠已启动）？可启动范围是否限定在授权范围内？方案名称与编号与正文一致、单独读能判断能否启动？**
- 候选方案里有没有"不行动/暂缓/试行"？没有的话说明理由了吗？
- 有没有虚构的概率、收益、权重或"用户想要"？
- 建议是否带了验证安排与重新考虑条件（观察什么、何时复查、什么情况重议）？
- 是否把建议写成了"已决定"？状态行与六对象是否分清？
- 简单问题是否被硬套了完整流程？

## 八、边界

- 不替用户做价值选择；不替代审计、税务、法律与财务专业判断；不输出业绩承诺。
- 分析材料自项目 `020_clean` 与用户提供的资料取；不读 `010_draw` 原件（软约束）。
- 超出审视范围的执行编排（如直接派发业务动作）不在本 skill；复盘学习（决策回顾）属后续能力，本轮只建议验证安排。
