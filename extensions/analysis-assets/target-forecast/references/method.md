# 目标测算方法（人/货/场三视角）

引擎身份：`optracall-forecast-1`（测算，本文件）与 `optracall-forecast-ingest-1`（导入）。数学承接 target-forecast 原仓 `target_forecast` 引擎（原引擎 forecast-engine-1.1，业务基线 `df5acd6`），OptraCall 形态纯 Python 重实现；等价性由黄金案例自检证明（数值容差 1e-9，去 pandas 化的求和次序可能引入远小于该容差的浮点差异）。

## 1. 三视角公式

| 视角 | 公式 | 启用条件 | 地位 |
| --- | --- | --- | --- |
| 人 | GMV = 新客数×新客客单 + 老客数×复购频次×老客客单 | 恒可用 | 模式A主口径 |
| 场 | GMV = UV × 转化率 × 客单 | 该平台有 UV | 模式B主口径（有流量数据时优先） |
| 货 | GMV = Σ(品类×梯队基期 × (1+梯队增速)) | 有订单明细结构 | 校验视角 |

主口径 = 有流量数据用场，否则用人。三视角对同一笔 GMV 负责，互为校验（差异>5% 打标"需复核"）。

## 2. 基线（最近 baseline_months 个月，默认 12）

- 流量型指标（新客数、老客数、UV）取**月均**；
- 价值型指标取**加权均值**：新客客单 = Σ新客GMV÷Σ新客数、老客单 = Σ老客GMV÷Σ老客订单、复购频次 = Σ老客订单÷Σ老客数——一律分子分母重算，**不对均值求平均**；
- 基期年化 GMV = 月均 GMV × 12：窗口恰 12 个月时与求和恒等；短历史不低估、长窗口不翻倍（`annualized` 标记如实输出）。

## 3. 季节性分摊

历史 GMV 按日历月（1–12）求月均占比，合计归一为 1；历史不足 12 月或缺月用全均值补齐（目标月不清零）。目标期 = 共同基期末月（各平台历史末月的最大值）之后连续 N 个月；某平台历史末月早于共同末月时在 `coverage.trailing_gap` 如实标记，不静默错配。

## 4. 情景增速（作用于基线年化口径）

- 人五杠杆：新客数 / 新客客单 / 老客月活 / 老客复购频次 / 老客客单；
- 场三杠杆：UV / 转化率 / 整体客单；
- 货按梯队：爆款 / 腰部 / 尾部 / 新品各一档增速。
- 人视角目标月 GMV：`(基线×(1+增速))×12×季节占比` 分摊到月；场视角同法分摊 UV；货视角按基期结构逐 (品类×梯队) 分摊。价值型参数（客单/频次/转化率）平推不分摊。
- 各档情景共用同一份数据与口径；档位数量由决策需要定，不限于三档；选档是讨论选择，不自动构成推荐。

## 5. 全渠道汇总

- GMV / 新老客 GMV / 订单数跨平台**直接加总**（用户跨平台不去重——打通需 unionid，属另一工程）；
- 全渠道客单 = ΣGMV÷Σ订单数；全渠道转化率 = Σ订单数÷ΣUV——比率一律分子分母重算；
- 转化率仅覆盖填报 UV 的平台，`转化率覆盖口径` 如实标注；全无 UV 时不产出 UV 列。

## 6. 货维度梯队划分（模式A结构）

- 结构基期 = 最近 goods_window_months（默认12）个月，品类×梯队聚合（gmv、款数）；
- 首次售卖距基期末 ≤ new_product_days（默认90）的款记「新品」，不参与帕累托、单列一行；
- 帕累托：范围内按单款 GMV 降序累计 ≤ tier_pareto_pct（默认0.78）为爆款（首名恒为爆款）；末段累计 ≤ tier_tail_pct（默认0.20）为尾部；其余腰部；tier_scope=platform 全平台统一排 / category 品类内排。

## 7. 未建模边界（报告必须声明）

跨平台用户去重、账期、退货 retro 调整、概率分布与随机仿真、月度路径依赖、库存与供给约束。结果为给定假设下的情景推演，非预测承诺。

## 8. 输出身份与确定性

每次输出带 `engine_version` 与 `input_digest`（输入 canonical JSON SHA-256 前 16 位）；同输入+同引擎版本输出逐字节一致。黄金案例：`ingest.py selftest`（明细→月度 4 月+结构+聚合+4 类 blocker 消息）与 `forecast.py selftest`（2 平台×3 情景×12 月三视角+汇总 36 行+平台年度），期望值由原仓实现在同一输入上生成。
