# 目标测算输入规格与质量规则

## 1. 模式A：通用订单明细（一行 = 一个订单行，订单号可重复跨商品）

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 日期 | ✓ | 订单日期（YYYY-MM-DD / YYYY/M/D / Excel 日期） |
| 订单号 | ✓ | 订单标识；同订单跨商品多行共用 |
| 用户ID | ✓ | 买家标识（新老客口径按此） |
| 商品ID | ✓ | 商品/款标识（货维度按此） |
| 实付金额 | ✓ | **支付净额（已扣退款），元**；不做退款抵减 |
| 品类 | — | 缺省「未分类」 |
| 件数 | — | 缺省 1 |
| 原价金额 | — | 不参与测算仅存档 |

模式A不含 UV（流量数据在生意参谋/罗盘类后台，不在订单系统），主口径为人货驱动；货维度结构可启用。

**blocker（拒绝产出，消息定位 Excel 行号）**：缺必填列；日期无法解析；实付金额空值/非正值（含净额口径说明）；同一订单号对应多个用户；实付合计 ≤ 0。

**处理链**：订单行 → 订单级（按订单号聚合金额件数）→ 滚动窗口新老客分类 → 月度统一指标 →（基期品类×梯队结构）。

**新老客滚动口径**：下单前 `new_customer_window_days`（默认365）天内无购买 → 新客；用户当月身份由当月首单决定，当月订单计入同一桶；**左截断**——数据起点前的购买史不可见，首单一律记新客（quality 提示如实声明）。

## 2. 模式B：聚合指标（一行 = 一个平台一个月）

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 月份 | ✓ | YYYY-MM（支持 2026-01 / 2026/1 / 2026.01 / 202601） |
| 新客数 / 新客客单 | ✓ | 新客 GMV = 新客数 × 新客客单 |
| 老客数 / 老客复购频次 / 老客客单 | ✓ | 老客 GMV = 老客数 × 复购频次 × 客单 |
| UV | — | 填报则启用场视角（该平台主口径=场） |
| 新客订单数 | — | 缺省按新客数计 |
| 转化率 / GMV | — | 仅一致性校验，不参与测算 |

GMV 由人公式派生，不直接取填写值。

**blocker**：缺必填列；月份无法解析/重复（一行=一平台一月）；必填数值空值/非法；派生 GMV 合计 ≤ 0。
**confirmable（需确认口径）**：填写 GMV 与派生差 >5%；填写转化率与隐含（Σ订单÷UV）差 >10%。

## 3. 统一月度指标层（两种模式汇到同一张表）

`platform, month, gmv, orders, units, buyers, uv, new_customers, new_gmv, new_orders, old_customers, old_gmv, old_orders`

uv 仅模式B可能有（模式A为 null，场视角自动降级缺席）。模式B的 units 为 null。

## 4. quality 级（如实披露不阻断）

- 历史区间**缺月**清单（影响基线与季节性）；
- **短历史**（<12 月）：基期年化为月均×12 外推，季节性不完整；
- 新老客**左截断**说明（模式A）；
- 多平台共同基期末月不齐时的 `trailing_gap`（目标期对齐规则见 method.md §3）。

## 5. 输入选择规则

- 同一平台同时存在模式A与模式B输入且未显式选源 → 拒绝（不得静默覆盖），须用户逐平台指定来源；
- 平台名由 `--platform` 指定（与文件名无关）；跨平台用户不去重；
- 输入文件为 `.xlsx` 第一张工作表（表头首行，空行跳过）。
