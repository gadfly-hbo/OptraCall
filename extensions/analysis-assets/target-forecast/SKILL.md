# 经营目标测算（人/货/场三视角）

你在为业务做经营目标测算。输入是各平台历史数据（订单明细或月度聚合指标）与情景假设；产物是**给定假设下的情景推演**——不是经营预测承诺。数字一律出自脚本输出，你的职责是口径确认、假设依据收集、交叉校验解读与边界声明。

## 一、红线（违反即无效测算）

1. **不心算**：所有数字来自 `scripts/ingest.py` 与 `scripts/forecast.py` 的输出（带 `engine_version` 与 `input_digest`）；改数据或假设就重跑，不在旧输出上手工调整。
2. **口径先行**：开算前确认——实付金额=支付净额（已扣退款，不做退款抵减）；新老客=滚动口径（365 天内无购买，数据起点前购买史不可见，左截断如实声明）；跨平台用户不去重（全渠道=各平台直接加总）。
3. **输入校验不硬算**：blocker（重复月份/非正金额/订单身份冲突/日期不可解析）由脚本定位到 Excel 行号拒绝；confirmable（填写 GMV 与派生差>5% 等）须用户确认口径；quality（缺月/短历史/左截断）如实进报告。
4. **主口径规则**：有流量数据（UV）的平台用场视角为主口径，否则用人视角；这不是可以按偏好挑选的。
5. **交叉校验不粉饰**：人 vs 货（vs 场）差异 >5% 必须显示"需复核"并解释可能原因，不得静默取用单一视角。
6. **情景非预测**：结论带"情景推演 · 非预测承诺"；增速假设须有依据（历史趋势/业务计划），报告注明依据来源。
7. **过期即作废**：数据、口径或假设任何变化后，旧结果即声明过期，不得引用。
8. **无执行环境时不硬算**：环境无法运行脚本时声明不适用，不手推测算。

## 二、测算流程（方法指引，非强制步骤）

1. **理解目标**：目标 GMV 量级与期限（年度/季度）、平台范围、当前基线与业务计划（投放、上新、大促）。
2. **准备数据**：每平台选一种输入——订单明细（模式A，可得货维度结构）或月度聚合指标（模式B，可含 UV 启用场视角）。没有结构化数据时用 `template.py` 发模板给用户填。同平台两种输入都有时须用户显式选源，不得静默覆盖。
3. **导入校验**：`python3 scripts/ingest.py detail/agg --input <xlsx> --platform <平台>` → 统一月度指标层；处理 blocker/confirmable，quality 提示进报告。
4. **设定情景**：按 `target-input-template.json` 组织 caliber 与各档情景（各杠杆增速：人五杠杆、场三杠杆、货按梯队）；档位数量不限于三档，由决策需要定。
5. **运行测算**：合并各平台 unified/structure 进 `platforms`，`python3 scripts/forecast.py run --input input.json -o out.json`——逐平台三视角月度+年度、全渠道汇总、平台年度对比、交叉校验表。
6. **解读**：目标 vs 基期年化的差距由哪些杠杆贡献（新客/复购/客单/流量/转化）；交叉校验差异的解释；对目标可达性的**条件性**判断（哪些假设是关键，压力点在哪）。
7. **产出报告**：中间结果存 `020_clean`，最终报告存 `060_reports`，含数据口径与覆盖、假设及依据、分平台与全渠道结果表、交叉校验、引擎版本与 input_digest、未建模边界。

## 四、边界

- 未建模：跨平台用户去重（需 unionid）、账期、退货 retro 调整、概率分布与随机仿真；这些不进入结果。
- 情景增速作用于基线水平，不建模月度路径依赖与库存/供给约束（经营推演类逐日账本仿真属 sim-lab 能力，不在本 skill）。
- 单元：金额元（输入实付金额为元）、比率为小数；月度粒度。
- 本 skill 不做页面直算；任务内测算由你自主完成，向用户呈现口径、结果与边界。
