# 深度研究方法

本文件是方法库：按任务取用，不是必须逐步执行的流程。你的判断优先于任何模板。

## 三个阶段组

**初调 → 大纲 → 逐章研究（审稿修订循环）→ 框架 → 组装**

| 阶段 | 产出 | 要点 |
| --- | --- | --- |
| 1 初调 | 500–1000 字研究摘要 + 来源池（8–15 条） | 覆盖：定义背景、主流观点与争议、关键数据、主要参与者、最新进展 |
| 2 大纲 | 报告标题 + 3–5 章章节列表 | 完整模式向用户确认（含调整往返）；快速模式 3 章、免确认。章节按同一维度切分（时间轴/利益方/技术栈/地域），标题收窄为名词短语，不含引言/结论/参考文献 |
| 3 逐章研究 | 各章草稿（800–1500 字）+ 审稿结论 | 每章：聚合多源证据 → 草稿 → 审稿 → （REVISE 时）修订 → 复审；循环最多 3 轮，第 3 轮强制通过、遗留问题记入"待完善事项" |
| 4 框架 | 引言 + 结论 + 目录 + 参考文献 | 引言 300–500 字带引用、提出问题；结论回答问题、提炼跨章洞察（不复制各章小结）；参考文献去重排序 |
| 5 组装 | 完整报告（Markdown） | 按 report-structure.md 拼装并逐项终检；不改动已通过的研究内容 |

## 三种模式

| 模式 | 触发 | 与完整的差异 |
| --- | --- | --- |
| 完整（默认） | "深度研究/研究报告/竞品分析/行业综述" | 全流程 |
| 快速 | "快速研究/简要分析/草稿即可/不用审核" | 3 章、免大纲确认、跳过审稿；报告显著标注"快速研究，未经审稿" |
| 单章 | 只要某个子课题 / "只要某一章" | 跳过大纲与框架；参考文献直接从本章引用抽取；不生成引言结论 |

用户未指定模式时按完整处理；轻量问题（"查查X"）不必启动全流程，直接一次检索回答即可——方法为问题服务。

## 研究参数卡（跨阶段上下文）

你（父 Agent）维护一张精简参数卡，逐阶段更新；每次委派子角色时**整张卡随任务说明下发**（子会话不继承对话）：

```markdown
## 研究参数卡
- 课题 / 报告语言 / 模式（完整|快速|单章）
- 时效窗口：近6个月 | 近1年 | 近2年（默认） | 近5年 | 不限
- 来源池：1. [标题](URL) — 一句话摘要 …（初调建立，逐章增补）
- 大纲：报告标题 + 章节列表（阶段2后）
- 已完成章节摘要：每章 ≤100 字（阶段3逐章补记）
```

时效窗口按课题选择：快速变化领域（AI/政策）近 6 个月–1 年；行业趋势近 2 年；学术综述近 5 年。窗口外来源仅作历史对比并标注年份。

## 委派模式

三形态互斥，每批 1–8 项；每项回传 `{agent, outcome, text}`，outcome 为 completed/failed/cancelled；chain 仅在前项 completed 时继续。

- **单章调研**：`{"agent":"deep-research/researcher","task":"{参数卡}。本章任务：「{章节标题}」，覆盖要点：{…}"}` 
- **并行多章**（章节独立时；章数多时可分批）：`{"tasks":[{"agent":"deep-research/researcher","task":"{参数卡}。本章：第1章…"},{ …第2章… }]}` —— 所有草稿收回后串行审稿，保跨章一致；并行批内共享同一张参数卡。
- **调研→审稿链**：`{"chain":[{"agent":"deep-research/researcher","task":"{参数卡}。本章：…"},{"agent":"deep-research/reviewer","task":"审稿（第1轮，current_round=1/3）。章节任务：{…}。草稿：{previous}"}]}`
- **修订**：REVISE 后由你按意见修订（或再委派 researcher 并附草稿+意见），复审时向 reviewer 提供：新稿、上轮意见、修订说明、current_round。

并行与链式都会等待全部子任务收尾；分支失败不静默丢弃——失败章节要么重派、要么在报告中如实标注未完成。审稿轮次由你在每次委派 reviewer 时显式给出 `current_round = N/3`。

## 编排原则

- 子角色的价值在隔离上下文：调研不被父对话污染、审稿不带作者先入之见。规划、修订、汇总、组装由你完成，不必委派。
- 单章 >8 项时分批；总章数 >10 时建议分批交付并告知用户。
- 子角色不可用（受保护会话等）时：你自行完成研究与自审（对照 review-checklist.md），并在报告中说明"未做独立审稿"。
- 用户中途改需求：更新参数卡；受影响章节重做，已完成且不受影响的部分不推倒重来。
