# 运营数据分析

交付可复核的统计事实、解释边界及建议。关键数值绑定来源、口径、可比基准和计算依据；数量效应、统计相关、因果解释与人的经营选择分别表达。方法、工具、分析顺序和内部纠错由 Agent 在本次许可内自主决定。

## 1. 承接本次任务与三层约定

先读本次已有的准确项目方案、Task范围、资料与权限、所选Skill/IR及交付约定。项目标准规定共同目标、范围、整体方法与综合责任；本Skill规定适用的运营数据分析检查；输出约定规定完整报告、聊天摘要或项目综合的载体。三个层次分别履行：

- 项目整体约定TOC/TP时，按本Task贡献和实际证据使用适用工具；不要求每个子Task重做全部项目分析或全部树。
- 已选Skill/IR须在实际适用部分使用，并留下准确来源、版本、采用方式及限制；目录可见或读取一次不等于实际采用。组合专业方法沿各自契约，方法内纠错自主完成，核心方法的未获准实质改变集中确认。
- Project需求准备只初判诉求和清单；本Skill用于已获准的执行期分析，不把全面读数据、体检、试算提前到需求准备。

## 2. 分别确定分析内容、建议类型和交付载体

先沿已有约定，合理明确时直接继续；只有会改变范围或经营承诺的歧义才集中问。

| 判断 | 适用结果 |
| --- | --- |
| 单指标查询或核对 | 直答所问，给数值、口径、期间、来源与必要限制；不套六段 |
| 归因、异常或结构分析的专业报告 | 保留第4节适用六段；因果未证实就交诊断和待核线索，不预设找到根因 |
| 正式汇报 | 适用六段加方法说明、重要假设及保留意见；不把汇报自动理解为已授权行动 |
| 聊天摘要 | 简述主要结论、关键依据/限制和下一步，链接或引用准确完整成果；不重复全文 |
| 项目综合 | 引用准确子成果，处理分歧、交叉影响、重复归因与遗漏；不复制每份报告全文或虚构未参与Task成果 |

**诊断建议**可提出建议角色、试点范围、优先级、建议期限及待确认条件。责任人、执行日期、资源或授权尚未确认时如实待定，仍可交付有依据的诊断；建议不代表已选、已授权或已执行。

**正式行动计划**只把已真实确认的责任、时限、授权/必要资源及跟踪依据记为确定安排，保留原话和来源。缺项时先交诊断建议或明确的计划草案，集中列待确认项，不编造人名、日期、预算或经营授权。

报告文件是约定的正式交付物时，完整内容存入获准位置并读回，聊天给摘要与准确入口。若约定正文就是完整报告，正文交完整内容；不能把文件一概当副本，也不能声称尚未写入/读回的文件已交付。双轴模式及示例见[交付契约](references/delivery-contract.md)。

## 3. 输入与缺证

核对分析目标、来源与观察/导出时间、统计期间、指标定义及单位、样本/覆盖范围。优先复用已有清晰信息；缺失项在首段说明内容、影响和待补材料。基期只有在需要比较时才是必要条件。

材料不足时，主动查获准资料；需要人提供时说明具体对象、期间/字段、来源和用途。继续有独立依据的部分，对受影响结论标限制。缺失、零、未发生、不适用、未核实分别表示。样本 <30 或分组 <5 时说明适用置信限制，不把阈值当所有业务方法的通用结论。

用示例数据试用时读[合成资料](references/sample-data.md)；仅做表体检时先交实际体检结果，不强制追加经营归因或行动计划。

## 4. 适用专业报告的完整结构

六段表达内容，不规定执行顺序；某项方法不适用或资料不足时保留该项及理由、已核范围和限制，补造检查不算完整。

1. **数据口径与质量说明**：定义、期间、来源、样本/覆盖、缺失/去重及实际体检结果。
2. **趋势与结构**：适用的可比变化、构成和分组差异。
3. **异常识别**：异常项、偏离度、方法、候选解释及核实建议；无异常如实说明实际核查范围。
4. **指标拆解**：适用的下级因子、拆解顺序与精确闭合；数学闭合不证明业务因果。
5. **洞察结论**：区分事实、推断、假设及未知，绑定数字/证据、基准和适用条件。
6. **诊断建议/行动建议与跟踪指标**：按第2节区分建议、计划草案和已确认计划；具体证据强度及未确认事项明确。

示例销售额＝成交笔数×客单价；利润＝收入＋(−成本)。销售额÷客流是人均消费，只有销售额÷成交笔数才是客单价，字段名不能替代定义。公式及选型按需读[方法库](references/method.md)。

## 5. 计算与证据检查

- 本Skill覆盖的比较、期间对齐、指标拆解、异常、加权与趋势计算使用`scripts/calc.py`复算并保留算式/产物；`--list`看支持范围。其他专业计算沿其已选方法和可用工具验证，不以本脚本未覆盖为由免检。
- 拆解差额>0.01（脚本退出3）先查输入/口径/运算，受影响结论暂不交付。保留必要精度，不先舍入再求和。
- 期间不等长先等长或按天对齐，分母定义一致才能比较；不同定义下可分别列结果，保留不可直接比较及所缺依据。
- 组样本不等时按真实分母加权，异常先核录入错误与真实波动；相关关系声明未做因果检验。预测/经营承诺需要明确假设与证据，不能由数量闭合、相关或样本量推导。
- 缺失值只标注，不用插补数据支撑趋势。工具不可用时说明未完成的检查与受影响判断，不伪造脚本运行或成功。

CSV体检适用时查完全重复、主键重复、月份缺口、率值区间/单位及疑似合计行；JOIN行数与基数用已有工具另核。DA4只提示数值区间/单位疑点，业务分母是否变化须据定义和取数说明核实。

## 6. 确定性工具与交付自查

| 工具 | 使用与边界 |
| --- | --- |
| `scripts/calc.py` | 验适用数字；`--selftest`自检，纯Python标准库 |
| `scripts/quality_check.py` | `--report 成果.md`检查声明的完整报告/摘要及建议类型；`--data 表.csv --key 主键列`体检；`--self-test`自检。只核有限结构/文本规则，不能证明业务正确、真实授权或文件已保存 |

新交付在正文开头用`交付形态：完整报告`或`交付形态：聊天摘要`，并用`建议类型：诊断建议`或`建议类型：正式行动计划`声明本次所检内容。直答沿`输出形态：直答`。元信息是检查输入，不是额外用户表单；完整报告和它的聊天摘要分别检查，各自不冒充对方。未声明的新旧文本沿旧六段检查兼容，不因候选规则自动更改历史结论。

交付前分开核数字、事实/解释、实际方法采用、格式和载体；本Skill适用检查仍须完成，不因新增自动节点关闭取消。正式计划字段检查通过仅说明字段呈现，真实性回原确认核实。体检error先修正或限制受影响分析，warning说明影响；不为通过格式规则添加虚假责任或事实。

用户资料从项目`020_clean`取，过程产物写`020_clean`，正式报告写`060_reports`；按原软约束不读`010_draw`数据。保存时机与未指定文件名由Agent按实际交付决定，Host绑定项目/目录和保存回执；沿原权限及停止规则，不绕道续跑。示例见[同一分析的不同交付](references/examples.md)，作者自检场景与未测项见[自检说明](references/selfcheck-cases.md)。
