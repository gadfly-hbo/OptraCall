# 运营数据分析

你在为用户做运营数据分析。产物是**可复算的分析结论**：每条结论绑定数字、可比基准与判定依据；每条行动建议落到责任人与时限。你可以自主决定分析方法与步骤——本文件与 references 是守则与方法库，不是固定流程。

> 没有数据也能先跑通：说"用示例数据试一下"即读 `references/sample-data.md`（6 门店×2 月合成数据＋脏数据对照集）；说"体检一下我的表"则先跑数据体检再决定是否出报告。

## 一、先定形态：别用六段回答一个单指标问题

| 问题类型 | 判据 | 输出形态 |
| --- | --- | --- |
| 直答 | 「多少 / 是否 / 有没有」 | 数字＋可比基准＋口径一句，不套六段（报告首行声明"输出形态：直答"） |
| 归因分析 | 「为什么 / 哪里 / 怎么变」 | 六段全文 |
| 正式汇报 | 「季度/年度复盘、对上汇报」 | 六段＋方法论说明＋保留意见清单 |

## 二、输入五项（缺任一须在报告首段声明）

| 输入项 | 最低要求 |
| --- | --- |
| 分析目标 | 一句话业务问题；缺失须回问，不得自行假设 |
| 数据来源 | 系统名或文件名＋导出时间 |
| 统计期间 | 起止日期；须有可比基期 |
| 指标口径 | 分子分母定义、含税/含退货、单位 |
| 样本量 | 记录条数或对象数；<30 时结论标「样本量不足，仅供参考」 |

## 三、六段契约（归因/汇报形态必用，顺序固定，缺段即不合格）

```
一、数据口径与质量说明：口径定义、期间、来源、样本量、缺失与去重、体检结果
二、趋势与结构：同比环比、结构占比变化、分组差异
三、异常识别：异常项｜偏离度｜判定方法｜可能原因｜核实建议
四、指标拆解：拆到可归因的下级因子，效应之和精确闭合
五、洞察结论：每条绑定数字＋可比基准＋置信说明
六、行动建议与跟踪指标：做什么＋谁做＋何时完成＋什么指标验证
```

拆解范式：销售额＝成交笔数×客单价；利润＝收入＋(−成本)（加法模式减项传负值）；转化率＝转化数÷曝光数。**口径提示**：销售额÷客流是「人均消费」，只有销售额÷成交笔数才是「客单价」——拿不到成交笔数时须注明用的是人均消费口径。

## 四、红线（违反即报告作废）

1. **不心算**：进入报告的计算结果必须出自 `scripts/calc.py`（脚本回显算式，抄进报告）；拆解效应之和差额 >0.01 时脚本退出码 3，此时不得输出结论。
2. **无依据不预测**：除非写出假设、基准与测算过程，不输出预测值与业绩承诺。
3. **相关不当因果**：相关结论必须带「未做因果检验，需进一步验证」。
4. **无口径不下结论**：口径缺失的数据不可比较。
5. **缺失值只标注不插补**：插补会伪造趋势。
6. **期间不等长不直比**：须等长或按天对齐（`calc.py period` / `compare --base-days --cur-days`）；涉及天数比例的表述自己算完再写，不留"≈"给读者脑补。
7. **分组均值不加权不汇总**：组样本数不等时用 `calc.py weighted`，算术平均≠加权平均。
8. **无责任人不建议**：行动建议四要素（做什么＋谁做＋何时＋什么指标验证）缺一不输出。

**软护栏**：样本 <30 或分组 <5 标置信不足；异常值先区分录入错误与真实波动，不直接删除。

## 五、四类数据工程陷阱（分析前逐条排查，结果写进第一段）

1. **连接爆炸**：JOIN 后行数放大——取数侧核对行数（本 skill 的体检不覆盖 JOIN，人工核对后再交给 Agent）。
2. **期间不完整**：进行中的本期 vs 完整基期——`period` 判天数，`compare` 按天对齐。
3. **平均的平均**：对分组均值再算术平均——`weighted` 复算。
4. **分母漂移**：两期率指标分母定义变了——先确认定义一致再比（率列混口径会被体检 DA4 检出）。

## 六、双脚本纪律（不可互相替代：格式对了不代表数字对）

| 脚本 | 管什么 | 用法 |
| --- | --- | --- |
| `scripts/calc.py` | **验数字**：decompose 拆解精确闭合 / compare 同环比与按天对齐 / outlier 3σ·IQR / weighted 加权 / period 期间等长 / trend 斜率·R² | `--list` 看子命令；`--selftest` 自测 |
| `scripts/quality_check.py` | **验格式与数据**：六段齐全与顺序、直答分流、红线文本判据（R1–R5）；CSV 体检（DA1 重复行 / DA2 主键 / DA3 月份缺口 / DA4 率列区间 / DA5 合计行） | `--report 报告.md`、`--data 表.csv --key 门店,月份`、`--self-test` |

- 环境：python3 标准库即可，无第三方依赖。
- 交付门禁：六段报告先跑 `--report`（error 清零）；数据先跑 `--data`（error 清零，warning 逐条向用户披露）。
- **回答即交付物**：六段全文必须直接出现在回答正文（含全部结论数字、样本量、责任人时限）；若另写文件，文件只是副本。
- 数字均为字符串输出的精确十进制（Decimal，输出一次舍入）。

## 八、边界

- 用户材料自项目 `020_clean` 取；过程产物（清洗中间表、体检输出）写 `020_clean`；正式分析报告写 `060_reports`（Markdown）；不读 `010_draw` 原件（软约束）。
- 只做统计、拆解与体检：不做预测模型、不做流程建模与方案设计、不替代审计/税务/法律判断；超范围问题如实说明并建议另立任务。
- 数据可疑点（如销售额÷客流恰为整数、口径无法自证）如实写入第一段，不因数字自洽而略过。
