# 作者自检场景与覆盖边界

这些是公开合成作者夹具，不是独立测评留出题。模型实际激活、专业增益和误触发均未运行，须由用户按既有流程组织独立测评并出具绑定候选版本的确认回执。

| 场景 | 输入与所问 | 独立预期、禁止结果及验证位置 |
| --- | --- | --- |
| 正向A：完整诊断 | `sample-data.md`六店月表；问两期经营变化与待核方向，未给经营人选或行动授权 | 基期609500/28天、本期612950/31天；总量+0.57%、日均-9.17%；报告保留六段、候选解释及诊断建议，角色/期限待确认可交付。禁止总量微增直接当经营改善、数量拆解当因果、编造责任人。`examples.md` full-diagnostic正文及calc compare/quality report |
| 正向B：正式计划与摘要 | 在A资料外，合成用户另明确给定U-01/U-02责任、时限、授权范围/资源及跟踪指标；要求正式报告文件和聊天简述 | 完整计划仅列已确认安排；摘要引用同一准确成果，不重复六段或全部计划字段。检查完整计划不缺真实确认字段；摘要的格式PASS不能替代计划或文件验收。`examples.md` formal-plan/chat-summary及quality自检 |
| 边界：首购历史不足 | 仅窗口内交易，缺会员首次购买历史；用户问完整复购率原因 | 可交已核窗口内描述，明确缺首购/资格/观察窗口及影响；停止完整复购率/因果判断，继续独立部分。不得把缺失视作零或编造首购。quality自检只证明`输入不完整`的有限声明规则；语义处理待独立模型测评 |
| 失败：正式计划缺授权 | 已写责任人和期限，未给授权或仍待确认 | 不能称正式行动计划；脚本R2拒绝缺字段/待确认，Agent应改交诊断/草案并明确待确认事项。quality自检与作者RED/GREEN回归 |
| 反例：模式冲突 | 同一待校正文同时声明完整报告/聊天摘要或两种建议类型 | F0拒绝冲突，不据较松模式跳过检查。quality自检 |
| 相邻负向：术语翻译 | “把会员复购率翻译成英文” | 直接完成翻译；不启动数据体检、六段报告、方法提炼或行动计划。description和SKILL分流静态核对；实际误触发率待测 |

确定性自检入口：`python3 scripts/calc.py --selftest`和`python3 scripts/quality_check.py --self-test`。calc公式/精度/输入失败保持原公开脚本；quality保留旧数据/红线对抗并新增交付/建议模式反例。正式报告例子按`examples.md`起止标记提取正文后运行`--report`，整份参考文件不得当一份报告。

所有脚本均只用Python标准库，无模型调用、凭据、依赖安装或文件发布能力。运行样例校验成功不证明报告已经保存、Agent实际采用方法、真实授权或经营结果有效。作者原始RED/GREEN、逐文件身份和结果保存在本变更的本地证据根，公开工程说明仅给可复现的合成条件与结论。
