# Extension 正确性补强建议

2026-10-30 · 待用户确认，未授权实施

来源：本轮咖啡合成案例出现的计算结构、口径、报告解释与经验草案错误。工程可靠性收尾只解决诊断、观察和采用版本；本建议不宣称专业正确性已经解决。

## 建议一期：先覆盖已出现的错误

| 标识 | 建议能力 | 可观察结果与验收 |
| --- | --- | --- |
| EC01 口径检查 | Extension显式声明输入文件、时间窗、粒度、金额单位、分母、退款处理及缺失值含义；Agent选择适用口径 | 用合成资料检出整单金额又乘数量、分/元混淆、会员/全体分母混用。口径来源与独立样例预期分开记录；缺失、未知或冲突不由Agent默认补成已确认。 |
| EC02 确定性计算校验 | 提供可调用的小工具，核对完整分组、分项加总、人数范围、差额桥、合法JSON、程序退出状态 | 检出本轮渠道字典键覆盖、先舍入再计算；对接入的计算工具分别取得计算退出码、产物和断言结果，避免外层命令成功掩盖内部失败。任意Bash只记录可观察证据，无法判定则UNKNOWN。校验失败交回原Agent显式修正，Host不补算。 |
| EC03 报告一致性 | 优先核对明确关联结果字段的金额/单位/正负/排名/预算声明；无法结构化判断的自由文本解释列待复核 | 能检出“利润仍正却写转负”、费用排序与量纲错误；不能因数字一致自动宣布因果成立或报告全部正确。 |
| EC04 方法及经验边界 | 提供针对已暴露问题的可审查说明；经验草稿带来源、适用条件、反证和未知，采用沿用现有显式流程 | 不将对照组变化直接判为方法失效，不把费用构成变化直接判为描述不可比，不把缺失字段推成事实；不自动发布全局规则或自动长期召回。 |
| EC05 运行环境检查 | 按具体工具声明必要Python库/版本并做能力探针；缺依赖明确返回 | 区分依赖缺失、脚本错误、计算校验不符和解释待审；不以补装库代替修复逻辑，不自动安装技能或改系统环境。 |
| EC06 联合回归 | 固定本轮错误最小样例、正确样例和边界样例，覆盖原会话修正/另存版本/显式采用/RAP+SAP+Case | 每个样例有独立可复算预期，失败原件保留；模型自检与确定性检查及独立复核分别记录。不虚报逐场景覆盖或真实经营效果。 |

## 接入与分工

按工程规范IN01–IN07及Interface v1：Qoder负责Extension工具、口径和专业说明，Codex负责Host/Agent接缝与联合回归；具体任务派发另行授权。Extension使用统一会话入口，不新建SDK接入、会话管理台账或宿主分析循环。

建议输出最小校验结果：检查对象/输入来源、通过/不符/未知/未运行、具体差异和检查版本；具体接口、必要字段和保存位置在确认实施范围后再细化，不在本建议中冻结新的持久结构。

一期不建设通用统计平台、自动因果识别、全报告语义裁判或第二个LLM自动修复循环。完整样本量/MDE/功效与其他统计方法，按实际任务逐项确定假设、输入和独立数值基准后另行建设；DuckDB下一项、Semantica后置的顺序不变。

## 待整体确认的建议

EC01–EC06是本建议内部的一期范围，控制在本次已出现的错误类型；不自动调整DuckDB计划，是否在其之前或并行开展待用户确认。完整统计方法库后续分项。确认前不修改Extension功能、不调用真实模型、不更换配置、不新增数据表或安装依赖。需要真实模型验证时，在适用授权下另列固定输入、模型及实际结果，不以确定性测试替代真实模型验收。
