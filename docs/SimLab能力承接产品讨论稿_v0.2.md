## 2 要解决的问题与产品理念（继承自 sim-lab 的思想内核）

业务决策者面对"这次大促怎么备货、怎么定价限量"这类问题时，缺的不是数据，而是**把假设严谨展开成可审计结论**的工具。拍脑袋给结论无法复盘； Spreadsheet 推演无法保证口径一致与可复现。

经营推演的三个理念（来自 sim-lab，值得继承）：

1. **仿真不是预测，是假设的严谨展开**——确定性规则把"如果需求涨 80% 会怎样"变成可复算的逐日账本，并诚实声明假设边界（未建模退货/账期/税等，不冒充预测）；
2. **口径先行**——先讲清规则与参数，再跑数；口径混乱的推演没有证据价值；
3. **证据不可变**——决策时点的假设与结果被冻结成快照，日后可精确复盘"当时基于什么做的决定"。

不继承的（原仓具体设计）：13 个工具的划分、三情景硬编码、30 天固定窗口、独立实验室式产品形态、宿主凭据授权机制。

## 3 产品定义：能力清单

产品成功的标准是以下能力在 OptraCall 内原生可用：

| # | 能力 | 说明 |
| --- | --- | --- |
| C1 假设成账 | 把经营问题结构化为参数化假设（需求、库存、产能、价格、成本、提前期、现金…），引擎按明确规则推演出逐日账本（进销存 + 现金流） |
| C2 确定性可复现 | 同一假设 + 同一引擎版本 = 逐字节相同的结果；结果带引擎身份标识，可作证据 |
| C3 方案对比 | 任意多个方案变体并排对比（不设预设情景数量），差异一目了然 |
| C4 压力测试 | 对引擎支持的假设维度做自定义幅度扰动分析，观察结论稳健性；扰动维度与幅度由使用者指定，不预置固定清单 |
| C5 证据沉淀 | 推演结论经用户确认固化为不可变快照，进入项目与 Case/决策板证据链 |
| C6 双模式 | 业务人员在推演页面直接操作（零模型费用）；Agent 在项目任务中工具化推演、自主迭代。页面是用户直接使用的通道，不用于替代或补跑 Agent 任务内的分析；任务内推演由 Agent 用工具自主完成 |
| C7 人在环 | 正式记录（固化快照）由用户确认；探索性推演自由进行 |

## 4 产品设计

本节设计遵循"Host 管环境，Agent 自主执行"：Host 提供工具、存储、权限边界、展示与固化确认；推演方法、工具选择、调参次数、对比方案与结论解读均由使用者/Agent 自主决定。唯一的人为介入点是固化快照（正式记录动作），不阻塞任何探索性推演。

### 4.1 产品形态：项目内的推演资产，不是独立实验室

推演资产（假设草稿、推演结果、快照）归属**项目**，与任务、文件、Case 同一工作空间。用户入口在侧边栏能力目录（工作名"经营推演"），页面呈现该项目下的推演资产。这与 sim-lab"独立实验室"形态的根本差异：推演是决策工作流的一环，不是旁挂工具。

### 4.2 使用流程（全新设计）

**探索自由、固化从严**——这是对 sim-lab 三道授权门禁（确认口径/采纳提案/存快照）的重新设计：

1. **建草稿**：用户或 Agent 创建推演草稿，自由填写参数与方案变体；未确认前可随时改；
2. **探索推演**：草稿上随时可跑（页面点按，或 Agent 调工具），结果标注"探索性"，不设门禁——Agent 可以自主反复调参对比，不被确认门槛阻塞；
3. **固化快照**：把某个草稿状态+推演结果变成正式证据时，用户在页面一次性确认（口径+参数+结果一并冻结），生成不可变快照；这是唯一的盖章点；
4. **进决策链**：快照的关键指标（贡献毛利、最低现金、期末库存、履约率等，按快照实际内容）可被 Case/决策板引用为决策证据。指标是引擎输出的标准汇总数据；哪个指标重要、结论如何解读，仍由 Agent 与用户在分析和决策中自行判断，呈现不预设结论。

sim-lab 的 CAS 乐观锁、幂等、UNKNOWN 阻断盲重试等纪律，按 OptraCall 既有存储模式（参考 [project-store](../src/host/project-store.ts)、[case-store](../src/host/case-store.ts) 的做法）重新实现，不搬原实现。

### 4.3 Agent 驱动（一步到位，走统一 Runtime）

Agent 推演工具为 OptraCall **原生设计**，遵循"少量、正交、可组合"，初步方案（最终以规格为准）：

| 工具 | 性质 | 职责 |
| --- | --- | --- |
| `simulation_inspect` | 读 | 引擎规则、参数口径、能力边界（含未建模声明） |
| `simulation_draft` | 读/写 | 创建/读取/修改推演草稿与方案变体 |
| `simulation_run` | 执行 | 跑一次推演（单方案或对比集），返回结构化结果 |
| `simulation_stress` | 执行 | 对指定方案跑扰动分析；扰动维度与幅度由 Agent 指定（引擎能力范围内校验），不预置固定扰动清单 |
| `simulation_evidence` | 读 | 读取已固化快照及其指标 |

- 经 [project-session.ts](../src/agent/project-session.ts) 现成的 `customTools`/`extensionFactories` 接缝注入项目任务域，不新建会话域、不建平行 Runtime；
- `simulation_freeze`（固化）**不设为 Agent 工具**：Agent 完成全部准备并在对话中给出建议，固化由用户在页面完成（C7），Agent 通过 `simulation_evidence` 读到固化回执——相比 sim-lab 把盖章动作也做成工具再靠凭据拦截，直接不给工具更干净；
- 工具报错为结构化信封（参数越界、草稿不存在、引擎不支持等），供 Agent 自主纠错。

### 4.4 引擎

引擎是**本仓原生模块**（`extensions/business-plugins/sim-lab/kernel/`），设计自由、随本仓演进：

- **v1 起点吸收 sim-lab 验证过的数学**：FIFO 逐日离散事件、进销存与现金守恒校验、采购在途、超期取消、敏感性单变量扰动——这套数学有 417 次守恒回归验证，是最有价值的素材，但作为参考重实现，不做字节冻结、不绑定原仓指纹；
- 引擎自带**版本标识**（如 `optracall-sim-1`），快照记录产出引擎版本，满足 C2 可复现；引擎变更走本仓受控变更+回归测试；
- **放开原仓限制**：推演窗口参数化（建议 7–90 天）、方案变体数量不限、扰动维度可扩展；超出 v1 能力（多仓、账期、退货、概率分布）继续显式声明为未建模，错误信封明确拒绝而不是算出错误结果；
- 守恒校验作为长期测试纪律迁入本仓测试基线。

### 4.5 UI（全新设计）

按 OptraCall 现有插件页的设计语言全新设计（视觉水准进入验收），核心界面：资产总览（草稿/快照）、参数与方案编辑、推演结果与逐日账本、多方案对比、扰动分析、固化确认流。交互细节在规格阶段出低保真结构后实施。

## 5 与现有插件的联动（原生设计）

- **Case/决策板**：快照指标作为决策证据的一等来源（呈现方式与 Codex 对齐：新证据类型或复用现有结构）；
- **项目任务**：任务对话中 Agent 用推演工具验证分析假设；推演资产在项目中可见；
- **指标体系（metric-factory）**：远期可让推演参数引用项目指标口径，v1 不强制联动（避免范围膨胀）。

## 8 范围与非目标

- 不做独立进程/服务/CLI、跨机部署、公共云 SaaS；
- v1 不建模：多仓、账期、退货退款、概率分布、随机仿真、外部数据源接入；
- 不迁移原仓 vendored 依赖与 Pi 层；不为本能力建独立模型配置或会话域；
- 不改变既有四个插件行为。
