# 个人账号连接

OptraCall 使用自己保存的账号连接。当前聊天平台或其他 Agent 已连接的账号不会自动成为 OptraCall 的授权。

先在「设置 → 连接配置」连接并核验账号，再回到原任务展开「任务账号连接」，为该任务选择服务及允许范围。新任务默认关闭，各任务分别选择。工具查询和操作所需信息会发送给对应外部服务，返回内容会进入该任务所选模型的上下文。

| 服务 | 首次设置 | 可选任务范围 |
| --- | --- | --- |
| GitHub | 自有注册应用 OAuth，或本人核定权限的细粒度访问令牌，并填写明确的 `owner/repository` 仓库集合 | 读取、Issue／PR 协作、PR 合并，可进一步缩小仓库范围 |
| Gmail | Google Cloud Desktop OAuth 客户端，按官方要求启用 Gmail API／Gmail MCP API 并完成 AI Agent 使用设置 | 按实际开放目录提供读取、草稿与标签、发送 |
| 腾讯邮箱 | 选择 QQ／Foxmail 或腾讯企业邮，填写完整邮箱和客户端授权码 | 读取、发送 |
| 飞书 | 本人 OAuth，企业管理员安装官方托管 MCP 应用并放行用户与工具 | 按实际开放目录提供读取、云文档写入、消息发送 |

保存配置只表示 Host 已保存输入。实际账号、权限和工具核验通过后才显示「已核验」。授权码、令牌和应用密钥保存后不回显，专用密码框留空不会把占位文字当成新凭据。

Gmail 的发送、回复、转发及部分更新工具目前需要 Google partner access，尚未普遍开放。以 [Google 当前官方说明](https://developers.google.com/workspace/gmail/api/guides/quotas)和账号实际开放的工具为准。读取可用不代表发送已获准。Gmail 发信按绑定邮箱账号确认，不提供独立 send-as 身份选择，真实使用时还需核对 Gmail 的默认发件身份。

腾讯邮箱的回复和转发会核对原邮件的稳定来源，需要同时开启读取与发送；单独发新邮件可仅授予发送。

QQ／Foxmail 需先在邮箱设置中启用 IMAP／SMTP 并生成客户端授权码，具体核验方式以当前账号界面为准。腾讯企业邮使用管理员允许的客户端凭据。两类邮箱的服务器分别固定，不互相代替。参见 [QQ 邮箱官方帮助](https://help.mail.qq.com/detail/106/985)。

飞书的工具由企业管理员及当前授权共同决定。当前用户、企业或应用身份未核实时保持不可用。已有文档修改还要求实际工具提供明确版本前置条件；未提供该条件的覆盖工具不会开放。参见 [飞书官方接入说明](https://open.larkoffice.com/document/mcp_open_tools/end-user-use-remote-mcp-server)。

发信、发送消息、合并 PR 和覆盖已有内容时，产品会要求核对本次具体账号、目标及内容。修改内容后需要新的确认。Gmail 的可变草稿编号、自动签名和隐含回复对象不能代替完整内容预览，Agent 会先读取并组成明确内容。GitHub 合并固定本次 PR 的 head SHA 和合并方式，head 变化后原确认不会合并新的提交。

更换账号、邮箱类型、飞书企业或权限后，旧任务保留原账号说明，等待重新选择；不会自动改绑。相同身份和权限的重新授权可恢复原绑定。任务运行或资源收尾期间不能切换任务授权。

断开连接会先撤回后续调用资格，再收尾受影响任务的资源。界面会列出受影响任务，原草稿和任务选择保留。出现 UNKNOWN／结果待核时，先查询原操作和外部服务记录，不自动重发。腾讯邮箱「服务器已接受」只表示 SMTP 服务器接收成功，不代表收件人已经收到。

每项连接属于当前运行设备。用户更新 Mac mini 或 MacBook 服务后，应在实际运行的设备上完成自己的授权并核对可用范围。本次工程验证使用合成身份和本地协议服务，不代表任何真实账号已经连接成功。
