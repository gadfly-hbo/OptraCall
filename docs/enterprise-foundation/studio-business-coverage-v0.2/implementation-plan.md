# Studio 业务范围与证据覆盖结合实施方案

版本 v0.2 · 2026-11-13 · 修订审核候选，暂不开发

本稿修订学习目录中的《Zachman36格与Studio结合实施方案》v0.1，并吸收对八份资料的当前代码评估。原稿与旧批准方案保留；此次用户授权为修订 D1／D2／D3、结合实施方案，准备 spec、可点击 UI Demo 和目标任务清单，交审核后停止。当前不修改产品、不运行模型、不启动企业资料盘点／内化／正式建设，也不执行 Git、服务或设备交付。

## 1. 目标与不变的建设主线

让建设 Agent 更容易说明“本轮范围内已有何种证据、哪些内容缺失或存在实质歧义、影响哪些用途”，帮助用户处理必要业务决定。Zachman 是可选观察方法；Studio 继续是建设、发布、使用与维护资产的统一产品。

- 两条参考路线保持：通用行业 → 标杆企业 → 目标企业；通用领域 → 标杆部门／业务域 → 目标部门／业务域。
- 每站同步准备主数据模型与字典、数据分析指标体系、本体与业务规则三类成果，保持准确关联和原权威。
- 企业基础层与任务演进层保持；参考材料和派生盘点报告不成为第三个正式业务层。
- 首批仍为运动鞋服共享经营骨架与会员运营核心；基础范围不被首购复购或另一道分析题预先裁剪。

## 4. 最小产品候选

### 4.1 报告是派生资料

报告保存到现有 `business` 类 Studio 资产的准确修订正文。可选 `reportProfile:'studio-coverage/1'` 只声明报告格式；与基础资产的 `contentProfile` 独立，不将报告解释为第二个主数据／指标／本体模型。

报告仅汇总本次范围、关注坐标、来源片段／断言的准确引用与理由、问题和状态。它可以说明某项依据支持什么及存在何种限制；业务定义、SAP 公式、规则投影、实际主记录仍回原权威读取。报告条目或编号不是新的正式实体身份，不因“引用已有”自动认定实际读过或采用。

具体字段、约束及读取形状由[本次 spec](../../../openspec/changes/studio-business-coverage/spec.md)统一定义。本稿不另建一套规范性字段合同。没有报告、未标坐标、关注集为空或资料只够一部分时，原普通分析继续沿获准材料与工具执行。

### 4.2 Host、Agent 与人工

| 责任方 | 承担内容 | 明确边界 |
| --- | --- | --- |
| Host | 报告结构、大小和引用形式检查；沿原来源读者核版本、权限及资格；准确保存和只读渲染；原生命周期和回执 | 不按类型自动认定唯一格，不裁定同人／政策冲突，不补业务事实、计算分数或授予新权限 |
| Agent | 查获准资料，按范围提出关注集、片段标注和理由；核用途、遗漏和实质冲突；选择原计算／规则工具并修订报告 | 结构通过不冒充业务核定，未完成和未知如实保留，替代判断不冒称原工具成功 |
| 人工 | 提供或授权资料，处理影响范围／规则的实质业务选择，作必要正式决定及审核 | 无逐格、逐字段、逐资产标注审批；例外可由 Agent 依据资料自行处理 |

### 4.3 原工具与供给

发现仍走原企业目录及 `catalog`，准确正文仍走 `read-source`，规则执行仍走 `reason`。必要时，报告作为辅助来源由 Agent 自主选择，精读其引用的原正式资产及适用条件。现有贡献、候选核查、发布用途、分项回执和历史机制原样复用；不新增目录资格开关、独立 MCP、Agent Runtime 或覆盖率引擎。

报告引用的来源变化后，应显示相应限制，不能自动改成 latest、重算原报告或停止所有正式源。新候选保留原准确基础及差异；旧报告和当时依据可回看。原已确认有误、失效或超范围来源的资格继续由原权威处理，报告不得将其恢复为当前合格依据。

### 4.4 只读呈现

默认围绕六问显示范围、证据与未决项。用户可展开片段与准确版本，也可按需切换高级矩阵；不把矩阵放到普通分析必经路径。

展示并列保留：原资产治理身份，资料已查／部分／待查／缺资料／不适用等范围观察，定义／映射／可计算／使用四项作者记录，以及原工具与独立核验事实。同一格可有多种并行状态。数量仅说明当前记录，不显示完成百分比、排行榜或“填满即通过”。

## 5. 关键情境与检查方向

| 情境 | 预期行为 |
| --- | --- |
| 14格以外存在有用依据 | 可从全36坐标选取，也可以只用六问描述；没有唯一合法子集 |
| 一份材料或一条关系涉及多个视角 | 引用具体片段／断言及多坐标理由，不复制业务定义或重复计为完成度 |
| 不同地区或期间有不同政策 | 合法并列并说明边界；未核定冲突不自动 mark-issue |
| 只有概念定义、尚无实际字段 | 定义参考可继续；映射与计算按适用用途保持待核／受限，不伪称已可算 |
| 源报告已正式但实际使用失败 | 正式身份、原四项声明、实际失败和独立核验分别显示，不压成“格已完成” |
| 资料不可读、引用变化或返回不完整 | 沿原资格限制与准确续读处理；未知留存，不静默换版或借坐标恢复权限 |
| 报告缺失或旧文本未采用 reportProfile | 普通源阅读、SAP、规则执行和任务贡献照常沿原权限使用 |
| 人工编辑报告／原资产 | 原候选、修订与检查失效规则继续适用；不把旧声明或预览用于变稿 |

以上是待审完成条件方向，不是当前已运行测试或已取得产品结果。具体前置用例、界面状态和验收边界由本次 spec、Demo 与任务清单统一核定。

## 6. 方法原件与后续采用

原学习目录中的八份资料作为本次研究原件保留，不在本轮移动或覆盖。新修订是本目录的独立审核版本，不能宣称原件已更新。

未来实际任务需要方法时，先经用户授权，再选择现有获准项目资料、企业资料或适合的 SAP 方法入口提供准确可读版本与来源。核实际环境能读到的正文、版本、范围及完整性；不依赖 MacBook 个人绝对路径，不自动复制私有或公开资料到公开仓库。方法资料的可读版本和其原始出处可以分别记录，无需为“唯一来源”制造跨设备强依赖。

## 7. 准备、审核及未来顺序

本次交付为 D1／D2／D3／本方案修订，以及独立新 spec、可点击 Demo 和目标任务清单。文档完成、独立复核及原型观察按实际证据记录，演示中合成企业、报告和状态不当成目标企业资产或模型成绩。

本轮用户审核完成前停止，不进入产品实现。后续若明确授权实施，按工程规范核实际基线和 SDK 原包约束，围绕上述最小差额做适用 SDD/TDD、原权限与历史兼容、准确引用、取消／UNKNOWN、界面状态和独立复核；Git／运行采用按届时授权分别核定。
