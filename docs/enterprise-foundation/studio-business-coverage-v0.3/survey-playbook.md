# D2｜企业基础层资料盘点参考作业指导

版本 v0.3 · 2026-11-13 · 36格全景修订候选，待用户审核

本稿修订学习目录 `survey-playbook.md` v0.1及独立v0.2稿，旧稿冻结保留。供未来获准的建设 Agent 使用：围绕“运动鞋服共享经营骨架＋会员运营核心”，沿两条参考路线同步盘点主数据、数据分析指标体系与本体的依据。本稿不预先绑定某一道分析题。

本次仅准备方法、[原报告合同基线](../../../openspec/changes/studio-business-coverage/spec.md)、[36格视图增补](../../../openspec/changes/studio-business-coverage/amendments/36-cell-view-v0.2/spec.md)、[Demo v0.2](../../prototypes/studio-business-coverage-v0.2/standalone.html)及[增补任务清单](../../../openspec/changes/studio-business-coverage/amendments/36-cell-view-v0.2/tasks.md)审核包，不实际盘点目标企业资料、内化或发布企业资产。

## 与现有流程的关系

企业基础层保存合格共享资产；业务任务发现的新资料或问题，沿任务演进层形成贡献，经核定并入基础层。两条参考路线是建设输入，不是两个新的权威库或第三个正式层。

Agent 自主选择取材、检查工具、先后顺序和内部迭代。下列八项是可并行、回访或跳过的参考动作，不是 Host 强制的状态机，也不是新增审批链。用户只提供或授权资料、处理证据无法决定的实质业务取舍及必要正式决定。

## 八项参考动作

| 动作 | Agent 可做什么 | 留下什么依据 |
| --- | --- | --- |
| 1 明确范围 | 沿用户已确认的企业、经营／会员领域、两条路线和用途确定本次盘点边界；范围可先有待核部分 | 范围、排除、未决项及本次关注问题 |
| 2 盘点已有材料 | 先查获准企业资料、项目资料、现有 SAP、模型字典、本体及获准参考资料；保留原始权威与准确版本 | 来源清单、版本、读取完整性、资料可得范围；不要求先收齐全部资料 |
| 3 查看全貌及关注范围 | 参考[36格逐格对照](lattice-map.md)，完整理解六行六列及各格含义；区分首批14参考建议、本报告范围及临时查看高亮 | 全36格始终可读；实际关注集及理由另列，未重点不等于不适用或缺资料 |
| 4 定位证据片段 | 对具体片段、断言、item 或指标引用提出多坐标标注；逐格记录为何相关；保持未知和未标注 | 准确引用、定位、理由及正反向对应；不同的同列格不共用无依据的落位 |
| 5 比较差异与冲突 | 核对象、粒度、范围、期间和含义后比较；列出参考采用／修改／排除／新增／待核建议 | 相关来源、差异理由、疑似冲突及影响；不因同格多版本自动确认有误 |
| 6 按用途查依赖 | 定义参考用途核定义与出处；数据计算或规则执行用途核其必需 Binding、规则、SAP 和事实条件 | 用途所需依赖、已有／缺失／未知与具体影响；纯概念不强制有数据映射 |
| 7 整理盘点报告 | 以36格全景为主要查看入口，逐格下钻到范围、证据与问题，保留反向来源对应；资料、三类资产及方法独立去重 | 派生盘点报告草稿，内容来自准确引用；治理身份、四项作者记录和独立使用依据并列，不复制第二业务定义 |
| 8 接续工作 | 集中提交真正影响范围或规则的业务决定；独立部分继续；后续内化和正式发布沿原工具与权限 | 待提供资料、可继续内容、必要决定及接续位置；不设每一步用户确认 |

动作没有文档数量、字段数量、每格条数、时间限制或必须填满的配额。只要范围、依据、缺口及后续影响足够清楚，即可交付盘点结果；资料尚缺不要求把所有内化工作同时停止。

## 几类容易混淆的情况

| 情况 | 本次如何处理 | 沿原权威处理的时机 |
| --- | --- | --- |
| 同格有多个来源或版本 | 比较对象、范围、期间和含义；可以合法并列 | 确有实质冲突时先记录问题；核定正式源有误后，才作原治理决定 |
| 新政策与历史政策不同 | 引用各自生效范围，说明新旧关系 | 按原修订、发布与历史规则维护，不覆盖旧报告 |
| 概念已定义但无业务字段 | 记录定义参考用途及映射未知／不适用理由 | 数据计算需要该字段时再核映射；不把定义自动说成可计算 |
| Host 引用校验通过 | 只证明相应结构、准确目标与资格通过 | 企业语义、同人关系、政策和计算仍由 Agent 查证并留依据 |
| 报告未标某格 | 保持未标、未关注或待查的准确状态 | 不停止普通分析，不自动将原正式资产标为受限 |
| 非重点22格没有企业报告证据 | 仍可查看固定含义、关联参考及首批边界；证据未知或未标另列 | 不将非重点直接写为不适用、无资料或未建成 |
| 无报告、读取失败或正文不完整 | 框架36格和首批14参考建议保持可读；本报告证据及数量未知 | 不用上次成功结果或0冒充当前读取，不向普通任务开放候选 |
| 报告出现作者“使用通过”声明 | 回到绑定准确版本的工具与报告依据 | 没有独立核验就明确待核，不能由报告标签生成独立成绩 |

## 建议盘点报告内容

报告内容结构以本轮 spec 的待审约定为准。以下是人可读的参考布局，不是新强制表单。

```markdown
# 〔企业／业务域〕范围与证据盘点

范围与用途：〔沿用户当前决定；未定事项单列〕
参考版本：〔行业、领域、标杆及企业材料准确身份〕
全景：〔完整36格标题、具体含义及固定坐标；来源为框架阅读说明〕
首批建议：〔14格参考建议；不是报告实测资料数〕
本报告关注：〔准确报告中的坐标及理由；与临时查看高亮分开〕

| 准确坐标与具体问题 | 证据片段、资产准确引用及对应理由 | 本次观察及限制 | 缺口／疑似冲突／不适用理由 |
| --- | --- | --- | --- |
| 待查 | 待提供或读取 | 未核定 | 说明影响及接续 |

来源反查：〔每个准确来源／资产修订所支持的坐标、片段和理由〕
来源资料数／三类资产修订数／方法输入数：〔分别按准确身份去重；未知不填0；不累加各格数量〕

原资产治理身份：〔按原来源，不能从下表反推〕
四项作者记录：〔定义／映射／可计算／使用分别引用〕
实际使用与独立核验：〔准确依据或明确未验〕

需要用户决定：〔证据无法决定的实质选择；可无〕
后续可继续：〔哪些内容可独立内化，哪些用途等待具体资料〕
```

候选产品拟将这类报告保存为现有 `business` 类资产正文，可带独立的 `reportProfile: "studio-coverage/1"`。这是待审核产品提案，当前未实现。报告只保存盘点范围、证据定位、标注理由、问题与状态引用；具体业务定义、公式、规则与实际主记录沿原权威保存。

本版只调整视图与证据投影要求，原报告body、profile及引用合同保持。上面的全景、清单和计数是阅读投影布局，不是新增报告必填字段。[D1计数说明](lattice-map.md)明确旧Demo六问3＋2＋2＋1＋2＋3的合成硬编码不能核定13份独立资料，也不能与14关注格混用。新版显示数量必须有逐条准确身份和片段映射支撑；一个来源多片段、多格时，汇总只计一次，不能为每格另造一份文档。

## 方法资料怎样进入未来任务

原三份 Zachman 方法文档继续保留在用户原学习目录，本轮不移动、覆盖或自动挂载。个人设备绝对路径不作为产品或普通任务的长期依赖。

未来用户明确授权实际使用后，可以通过现有获准项目资料、企业资料入口，或适合的方法库保存准确可读版本及来源引用。应先核任务实际能读到的版本、权限和完整性；可登记资料来源和采集身份，不能假装另一台设备的路径已可读取，也不能把来源登记当正文已读。公开仓库中的引用不自动授权复制私有资料或公开内容。

## 使用与演进

盘点报告是辅助输入，普通分析不以报告存在、填格或发布为前置。Agent 可沿原 catalog 发现正式资产，按需 read-source 或 reason，并保留真实依据。需要共享的补充仍沿原 contribute、候选核查及发布；报告发现缺口不自动改变原资产资格。

以后若数据或政策改变，重新读取准确来源并形成报告新候选，保留旧报告及其当时版本。报告“可能过时”与原正式定义“确认有误”分别处理。用户无需为了更新坐标而逐条维护资产。
