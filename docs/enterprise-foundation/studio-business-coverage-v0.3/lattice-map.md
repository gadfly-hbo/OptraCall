## 六个观察问题

| 视角 | 检查什么 | 可用依据示例 | 与三类资产的关系 |
| --- | --- | --- | --- |
| What | 对象、身份、组成和信息分别是什么 | 商品／组织／会员字典、对象粒度及编码依据 | 可关联 entity、attribute、key、value-domain，以及指标统计对象 |
| How | 业务活动、事件和变化怎样发生 | 业务制度、流程说明、交易和服务事件定义 | 可关联 event、domain relations、规则及方法适用条件；不要求建设流程编排器 |
| Where | 哪些地点、市场、渠道及分布条件适用 | 门店、渠道、市场和设施资料；经营关系与有效范围 | 同一地点或渠道可同时涉及对象、组织、时间和业务约束 |
| Who | 谁参与、负责、使用或获得资格 | 组织职责、角色、账号及身份关联依据 | 参与者身份、责任和资格分别表达；方法坐标不授予系统访问权限 |
| When | 什么时间、周期、顺序及截止成立 | 业务日历、事件时间、记录时间、有效期与期间规则 | 可关联 time、事件、规则和指标期间；字段有日期不等于时间语义已完整 |
| Why | 目标、动机、约束及判断依据是什么 | 经营目标、政策、资格制度及解释依据 | 可关联规则、策略、指标用途；某指标衡量目标不证明指标公式只属于 Why |

表中的类型是可检查的连接点，不是 `item kind → 单格` 自动归类规则。主数据、本体与指标之间的原准确关系继续使用现有 items、metricLinks、relations、adaptations、bindingLinks 表达。

## 行视角与坐标范围

坐标可以在 `R1` 至 `R6` 与 `What/How/Where/Who/When/Why` 的组合中选用，共 36 个可能位置。中文行名称在此用于阅读，不作为新的企业类型或运行时层级。

| 行 | 本稿工作称呼 | 使用方式与边界 |
| --- | --- | --- |
| R1 | 范围识别／Identification | 描述需要关注的对象、活动、地域、参与者、节奏和目标清单 |
| R2 | 业务定义／Definition | 核对企业如何定义业务对象、关系、活动、规则及适用条件 |
| R3 | 逻辑表示／Representation | 有资料时核对逻辑对象、功能、连接、职责、时间和规则表达 |
| R4 | 技术规格／Specification | 有关技术设计与业务语义、数据映射或实际使用相关时，引用相应资料 |
| R5 | 具体配置／Configuration | 可引用实际表、字段、组件或配置作为证据，不因此扩建部署平台 |
| R6 | 运行实例／Instantiation | 获准实际业务对象和活动可作为实例依据；工具执行回执仅在确有关联时提供观察证据，不概括整个企业 |

本版保留 **OptraCall 首批建议重点关注14格**：R1六格、R2六格、R3:What与R3:Why。这是本产品首批建设范围的建议选择，不是“语义资产理论上只涉及14格”的结论；以后可随范围增减。其余22格同样可打开含义、相关参考入口及本轮边界。**不重点建设、不适用、缺资料、尚未调查是不同事实**。未关注或未标注的内容照常沿原 Studio 资格使用，不要求填满36格。

首批14参考建议、本报告实际记录的关注集、用户临时查看高亮分别标识。无报告或报告不可读时，14只能显示为参考建议，不能冒充本报告实测范围。改变临时高亮或筛选不修改报告、企业建设范围或正式资格。

## 按内容片段与断言建立对照

一份文档可以覆盖多个格，一条关系或断言也可以带多个有理由的坐标。先确定其含义、范围、期间和出处，再提出标注；资料名称或 item 类型不能代替判断。未能可靠判断时保留未标注。

| 示例内容 | 可能关注位置 | 应保留的理由与准确引用 |
| --- | --- | --- |
| 门店的经营主体与生效期间 | R2:What、R2:Who、R2:Where、R2:When 中与具体片段相关的位置 | 对象身份、经营责任、地点与期间可能分布于不同片段，不要求把整份门店资料归为一格 |
| 会员资格规则的业务说明 | R2:Who、R2:Why、R2:When | 根据具体规则分别说明主体、资格依据和期间，引用规则来源版本及位置 |
| 指标定义、用途及期间 | 可涉及 R2:What、R2:Why、R2:When；系统表达另按证据确定行 | 指标定义与公式仍归原 SAP；坐标只说明盘点观察角度，不复制公式 |
| 系统逻辑字段与实际数据库字段映射 | 可涉及 R3:What、R4:What、R5:What，按资料抽象程度选择 | “Binding”本身不足以决定行；记录逻辑、技术或物理实现所指的实际内容 |
| 推演或普通分析的准确执行回执 | 可能关注 R6 的相应问题，也可不标格 | 执行事实、作者采用声明和独立评估分别保留，不能以坐标代替事实身份 |
| 分析方法 | 可以不标格；与某个业务说明有明确联系时只关联相应片段 | 方法继续归原 SAP 方法库，不强行把整种资产塞入某一格或禁止其提供范围检查依据 |

## 两类检查

**跨视角依据追溯。** 对本轮准备声明的用途，核对参考内容、企业决定、实际定义及必要数据／规则依赖是否可追溯。采用或修改一个纯概念不必有 Binding；准备声明可计算或规则执行时，才核相应用途需要的准确数据与规则依赖。缺口记录影响，独立可用内容继续。

**同范围业务一致性。** 先按对象、粒度、业务范围、有效期间和含义比较两条路线及各来源。准确 item 引用、类型与来源资格复用现有结构检查；同义、同人、规则适用或实质冲突由 Agent 回源核查。不同期间或地区的规则可以合法并存；同一格出现多个版本不自动意味着有错。

疑似问题先进入报告或现有问题／缺口工作项；只有有证据核定某个正式源确实有误，才沿原正式源治理处理。本方法不自动调用 `mark-issue`。

## 全景、逐格下钻与反向来源对应

“36格全景”是首个主要页签，默认全36格可见，首批14格高亮，其余22格保持可点击。六问可用于辅助阅读与筛选，不把全景藏在高级折叠区。筛选重点时仍能恢复完整全景，并明确当前筛选范围。

点开任一格可看固定坐标与具体含义、首批关注边界、关联参考，以及本次报告真实关联的资料片段、三类资产准确修订和未决项。反向从某个来源或资产打开时，列出本报告中它关联的所有格、片段定位与理由。资料、片段、资产和格子是多对多关系，不要求每格造一份文档。

无报告、读取失败、未知格式或正文不完整时，框架36格含义与首批范围仍可看；报告证据和数量分别标未知或待读取，不把没有返回的数据填成0。候选报告只沿建设者原权限查看；普通 Agent 继续原正式来源资格，不能因全景存在而读取候选或越权来源。

以下状态并列保留，不压成一个“格已完成”标签：

- 资料覆盖：已查到、部分、待查、缺资料、不适用或当前未关注，并附范围和理由。
- 治理身份：原工作稿、候选、当前正式、历史、受限等；发布身份不推出定义或使用通过。
- 四项作者记录：定义、映射、可计算、实际使用各自的状态及依据；缺项保持待核。
- 实际与独立证据：目录供给、准确读取、作者采用声明、工具执行、独立使用核验分别回原记录查看。

本稿不定义填满率、覆盖百分比、自动完成分数或固定字段配额。盘点结果只说明约定范围的证据和缺口，不能证明企业基础层整体完备。

## 格数、资料数与资产数分别计算

旧 Demo v0.1 六问上的 `3＋2＋2＋1＋2＋3＝13` 是合成硬编码数字，没有独立准确来源集合支撑，不能核定为13份不同资料，也不能与首批14格建立一份资料对应一格的关系。本版去掉这种混合口径；旧原型保留其历史身份，不追改其证据。

| 数量 | 口径 |
| --- | --- |
| 框架格数 | 固定36；首批重点14、非重点22，表示关注范围而非资料份数或完成数 |
| 关注格数 | 本报告准确可读的关注坐标集合去重数；首批14参考建议、临时查看高亮及筛选数量另列 |
| 来源资料数 | 在本报告用于资料盘点的实际可读来源集合中，按原 SourceRef 身份与版本去重；保留 authority、id、version、必要 locator／归属及原来源提供的 hash，不能按标题合并不同修订 |
| 资产修订数 | 按原权威中的准确 asset 身份与 revision／version 去重；同一修订含多个 item 或 metric 时，可另列有标签的条目数，不冲作多份资产 |
| 方法输入数 | 本次实际采用的方法准确版本单列，不混入资料数或三类资产数，不因登记引用就声明已读 |
| 片段与对应数 | 可另列片段、断言或格关联条数，但明确标签；同资料多格只在汇总资料数中去重计一次，不累加各格计数 |

资料、三类资产和方法分别列清单及口径，即使某资产也被当作来源引用也不能把各集合相加当总覆盖。三类资产可分主数据、指标体系、本体显示，合计仍按准确资产修订去重。逐格数量说明该格的关联集合，全局汇总用去重并集；不同修订分别保留。未读到、无合格报告、来源失权或正文不完整时数量未知；只有准确范围及完整读取已核且确无条目时，才可说明“本报告已标注0”，不能说企业没有资料。
