## 接缝与实施位置

`Host UI → Node Host → src/agent 唯一接入 → Pi SDK`。浏览器只能获取序列化状态与事件，不能导入 SDK 或读取密钥。Host 维护当前配置和修订；内部会话使用创建时配置快照，变更不悄悄替换在途模型。清除配置会停止并释放 SDK 会话和相应内存密钥。

新增 Host 配置／HTTP／启动代码、Agent 接入、启动脚本及永久测试；修改既有设置 UI、package/lock、Vite proxy、阶段与启动说明。保留工程／产品原文、Extension 标记和第 2 项证据；原独立结论只覆盖其原候选。

SDK 1.4.0 接口使用 ModelRuntime、SessionManager.inMemory、SettingsManager.inMemory 和自定义空 ResourceLoader。密钥通过 `setRuntimeApiKey` 按字面量注入，不进入支持环境／命令展开的 provider `apiKey` 字段。以 SDK 实际 idle／prompt 完成及完整消息判定结果，不把 `agent_end` 或请求被接受当成功。

Host 实际运行要求 Node 25+（本机 25.9.0 验证），以 Node 权限限制代码／依赖之外的文件读取，不授予文件写入、子进程、worker 或 addon 权限；网络只用于用户主动指定的模型调用。该机制限制可信 SDK 的意外访问，不作为运行恶意插件的沙箱。SDK 使用中性虚拟 cwd，不将工程路径带入连接测试。

SDK 原始依赖中的 undici 8.10.2 被审计报告关联已知漏洞；定向固定为 8.12.2，并作为直接 HTTP 依赖在隔离 Bootstrap 中先安装其 Web API／Dispatcher，再动态导入 Host／SDK，避免仍使用 Node 自带旧 fetch。没有降级 SDK 或执行 audit fix。原审计、官方来源及修复后结果保留在本地研究证据。

自定义模型使用保守的 SDK 预算元数据（32k 上下文、1024 输出上限）；成本字段的零值是未配置占位，不代表真实免费或结算结果，界面不展示该费用。真实服务的上下文限制、协议与模型效果需在相应配置上验证。

只开放本地同源使用的配置／连接测试与内部会话入口，校验 Origin、请求类型和体积，错误不回显凭据或 Provider 原始响应。没有文件上传、任意文件读写、业务工具、插件安装、远端服务或生产发布。
