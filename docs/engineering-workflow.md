Codex 与 Qoder 在同一工程规范下协作。每项变更明确修改范围、文件归属、接入责任和验收；一般并行实现使用各自分支和独立工作目录，避免同目录切分支、重叠写入或覆盖对方 WIP。同目录协作必须明确不重叠的文件归属，不并发切换分支；独立复核保持源文件只读并使用隔离验证根。原批次Git暂缓例外已结束。公共边界按具体任务协商并记录，不单方面变更另一方的契约，也不预建完整插件平台。

### 产品 Agent 与工程 Agent

产品运行时由 Pi Agent 自主分析；Host 负责交互、业务上下文、资源与权限、产物保存和决策学习环境。Host 不指定分析步骤，不代替 Agent 补跑计算或另建分析循环。这里的自主性不改变 Codex、Qoder 的 SDD/TDD 与独立复核责任。

整个 OptraCall 产品统一采用 **pi-coding-agent SDK** 承担 Agent Runtime，由 Codex 维护产品级 SDK 接入与运行管理入口。Extension 通过统一入口使用 Agent 能力，提供工具、skill、上下文及专业能力，不自建 Pi SDK 接入层、会话运行管理或平行 Runtime。

统一底座允许按任务隔离会话与上下文。所需会话的创建、续接、停止及事件处理均经过统一入口；具体接口与并发方式随实际任务确定。宿主不直接组合 pi-agent-core + pi-ai 自建运行底座；SDK 内部的传递依赖不受此限制。实施时核对并锁定兼容版本，不能将“已声明同一依赖”当成实际共用 Runtime 的证明。

### 统一会话接入规范（Interface v1）

以下IN01–IN07适用于Codex、Qoder及其他开发者。准确类型及Interface版本以`src/host/agent-sessions.ts`为准；最小使用方式、业务差异和验证示例见[接入说明](agent-session-integration.md)。本节是强制规则唯一来源，AGENTS及工具专属项目入口仅放同源指针。

| 标识 | 必须遵守的接入规则 |
| --- | --- |
| IN01 开发前必读 | 新增/修改Agent交互、SDK接入、会话启停/恢复、模型配置或插件接入前，读取本节及接入说明；本变更规格记录规则/Interface版本、owner/profile、修改范围、业务差异和验收。旧任务授权不替代当前范围。 |
| IN02 Host注册与注入 | Host静态注册域/profile并注入能力受限的port及绑定owner的Ref；业务前端保留自身入口。域构造、跨owner管理留在Host，插件只取得自己的会话资格，不接收可自行注册域或清理全局会话的管理对象。 |
| IN03 共用生命周期 | 启动、占用、取消、关闭及订阅经公共入口；业务层不直接创建SDK会话、new ProjectAgent或另写opening/operation/代际Map、配置监听及全局清理。公共实现创建多个隔离实例属于正常复用，业务Store和业务集合仍各自维护；同一资源只有一处权威生命周期状态。 |
| IN04 保留业务差异 | profile仅声明真实差异：准入、模型选择、工作区/工具和续接参数。业务上下文、RAP/SAP/Case校验、保存/回执、事件投影及有限修正留在业务适配器。多turn明确结束与取消条件；公共层按技术能力工作，不按业务名加入流程分支。 |
| IN05 Host资源权限 | 凭据解析、原生资源创建和跨owner清理由核准Host路径负责。插件只使用非敏感引用及获准能力，不通过消息中的任意workspace/sessionFile、密钥或Provider绕过配置；事件与日志继续脱敏，会话port不扩大数据或经营动作授权。 |
| IN06 契约共同维护 | 新能力先补契约、消费者适配与验收。Codex负责Host/Agent集成与主链路，Qoder交付Extension接入及证据；不单方面改变另一方契约。不兼容变化或范围扩大先补适用决定；底层导入例外的新增/变更须说明理由并独立复核。 |
| IN07 交付验证 | 交付覆盖正常路径、取消、配置变化、迟到结果、保存/恢复与兼容范围；公共改动复测现有消费者及第三合成接入。导入约束加入`npm run check`及CI，合规样例通过、受控绕过样例失败、恢复合规后通过；不能靠跳过检查、删除断言或扩大白名单制造通过。 |

两类策略继续保留：项目任务使用绑定配置和已保存sessionFile；需求梳理在operation开始捕获当前配置，生成与最多一次修正期间固定，重建沿用原新建native策略。各owner的原生会话、上下文、配置快照与占用独立；Host只持域管理引用，协调明确的Provider/真实项目/退出范围，不另建资源台账或全局Agent运行队列。需求的目标项目不是需求会话归属。SDK原生历史读取及固定连接探针只由检查中列明的路径承担，不能借例外接管业务会话。

迁移采用原位换接线；本期不新增会话库、业务ID、持久代际或需求续接指针。旧资料保全与正常追加分开验：迁移不改写既有内容，显式续聊及原有证据校正仍可产生合法更新；回退兼容代码读取最新资料，不恢复旧副本覆盖新增工作。未知结果保留UNKNOWN/中断，不自动重放或换模型。共享代码与同进程资源仍有共同故障风险，逻辑隔离不等于进程/安全隔离。

规范完成验收须分别记录当前Codex/Qoder版本、实际项目入口及读取证据；文件存在或加载器支持某文件名不等于任务已读取。未实际验证的工具项记NOT_RUN，不能宣称固化全部通过；不得为凑通过改全局配置、调用未获准模型或启动MacBook开发。静态导入检查只覆盖已知绕过形式，仍需实际调用链、行为回归及非作者复核。

## 3. 连续 SDD 与 TDD

每项非平凡变更在 `openspec/changes/<change-id>/` 维护一份简洁规格和现有结果记录；首次实际变更时再创建目录。必要设计和证据用链接关联，普通纠错更新原记录。最少写清：完整可观察结果、需求/验收标识、范围与不做事项、允许修改路径、关键边界、适用检查和未决问题。

工作顺序：明确目标与验收 → 维护规格并实施适用 TDD → 最小可运行切片与真实路径反馈 → 同一责任方持续修正和受影响检查 → 完整候选集中复核与验证 → 适用验收及获授权 Git 交付。

- **确定性行为**：实现前有能检出目标行为错误的测试；修复前保留失败测试或因果复现，再做最小 GREEN 修复和必要重构，留下永久回归。保留关键正向、反向、边界、失败和禁止副作用断言。
- **探索与模型质量**：先明确实际任务、预期和观察条件，保留真实试验与失败；不伪造确定性 RED。单次成功只证明该场景及其输入、模型、工具和配置条件。
- **纯重构**：保留修改前后 GREEN 与相关等价证据。
- **文档和规范变更**：做相称的一致性、引用和范围复核，不制造产品 RED 或无意义的占位测试。

测试从需求和验收导出，不照着实现重述。环境、导入、定位器或 fixture 失败不算产品 RED；后补测试不能伪造历史失败。测试修改或删除应解释覆盖如何保留，不能通过削弱断言把失败改成成功。

从首个可运行切片起，尽早走用户正常入口、实际配置、代表输入、真实工具及适用的保存/重开、失败、取消和恢复路径。需要模型、数据或外部副作用的检查，沿用有效任务授权；缺少授权时明确未验证范围。Mock、结构校验或 SDK 导入通过不能证明真实分析成功。

同一责任方持续完成诊断、修复和回归。普通修正复用有效规格与授权，不为每次编辑重建文档套件、全量回归或独立审批；新增产品行为、重要契约/持久化结构、数据权限或外部影响边界，先补齐必要决定再实施受影响部分。

## 4. 独立复核与工程完成

日常自检、Codex/Qoder 接口互查和作者测试不能替代最终独立复核。复核者不得是该候选任一部分的作者；两位作者互相看代码，不自动构成完整候选的独立复核。

完整结果收尾时固定候选、规格、输入与证据，覆盖 staged、unstaged 和新增文件。提供候选提交或文件清单与摘要、验收依据、允许检查、现有结果、失败和缺口；复核上下文独立，先从验收导出关键预期，再检查实现和作者测试。

复核保持源文件、测试、规格和固定证据只读；获准检查需要的临时文件、缓存或报告只能写入明确的隔离位置。复核者独立检查关键路径与失败路径，记录检查范围、命令/结果、发现与结论；作者修复后重验受影响范围。候选变化导致的旧 PASS 失效应明确记录，不能沿用不适用的复核或 CI。

工程完成至少具备：

1. 当前规格与已确认验收一致，实际修改在授权范围内。
2. 适用目标测试、回归与质量检查完成，真实集成路径和结果有证据。
3. 独立复核完成，发现已处理；必要的用户风险接受单独记录，不写成复核 PASS。
4. 必要 CI 对应实际交付候选；变更到位后更新规格及结果记录，并完成适用 OpenSpec 归档。局部检查不代表完整交付；原四项批次的延后Git／CI安排已完成，不再作为当前例外。
5. 交付说明给出版本、验证、失败/未验证项、风险与后续点；涉及更新时说明回退方式及其数据影响。

独立复核不可用时，明确未完成的复核及其影响；可继续安全、已授权的实现，但不得用作者自评代替要求的复核或宣称完整工程验收。

产品验收由用户对固定候选的适用体验和结果作出。工程检查、独立复核、CI、Git 推送、产品验收、安装与发布分别报告；任何一项不自动代替另一项。尚未运行、失败、跳过及未知结果如实保留。

## 5. Git 与 CI 的精简节奏

### Git

既有远端为 `https://github.com/gadfly-hbo/OptraCall.git`，`main` 作为集成基线。已完成的空仓库首次提交曾获用户明确批准直接建立 `main`。一般功能和修复在独立工作分支进行，例如 `codex/<slug>`、`work/qoder/<slug>`；同一分支保持清楚的写入归属。原四项批次的Git暂缓期已结束；后续按当前用户授权和本节规则交付，保留既有WIP。

日常在已有 Git 授权内按需要提交、推送工作分支；内部修正和子任务不必每次创建 PR、全量 CI、独立复核或打包。完整变更收尾时集中一个 PR、独立复核、适用检查和获授权的 squash 合并，再安全快进本地 `main`。已有 PR 更新触发的检查照常完成，不为规避 CI 隐藏更新或扩大单个变更。

提交前核对实际暂存清单、差异、身份和公开内容；只纳入本任务文件。保留 WIP 和失败现场，不重置、清理、强制切换、改写历史或覆盖他人工作。基线变化时检查兼容性，重新验证失效部分。推送/合并不自动更新运行服务或其他机器；本项目不建立双开发端同步流程。

### CI

原四项开发与独立复核后已建立[单任务CI](../.github/workflows/check.yml)：Ubuntu／Node25.9.0，锁文件安装后运行 `npm run check` 和高危级别依赖审计，无真实凭据、模型或业务数据。PR检查实际head，合并后main push另行检查；没有空流程或重复矩阵。本地检查不表述为CI PASS，浏览器／macOS真实模型及产品验收分别记录，交付必须核对实际检查与提交身份。

| 修改范围 | 验证选择 |
| --- | --- |
| 纯非运行时文档 | 差异、内容一致性、引用、范围和适用独立复核；不安装无关产品依赖 |
| 已知消费者且影响闭合 | 使用有证据的影响映射运行对应检查，并报告遗漏范围 |
| 运行时、安全/权限、持久化、公共接口、共享依赖、构建/CI 自身或影响不明 | 运行届时定义的完整适用检查及受影响真实路径；平台专有验收另行报告 |

混合变更只有全部对象被可靠覆盖时才能采用定向检查；否则采用完整适用检查。检查选择逻辑不能批准自己降级。每次报告实际选择、结果和未跑项，局部 PASS 不表述为全量通过。保留失败日志，先解释原因再重试；无解释的绿色重跑不关闭原始失败。
