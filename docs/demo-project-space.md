## 可观察结果与范围

用户要求以“新建项目”取代新建对话。初次进入没有独立对话；命名创建项目后，左侧项目空间列表可找回该项目，项目内承接原有对话体验。当前每个项目只有一个连续的演示对话，没有独立创建对话的入口。项目名称不随聊天首句变化。

右侧增加可展开／收起的项目文件栏，展示当前项目及默认三个文件夹，严格使用用户给出的 `010_draw`、`020_clean`、`060_reports`。文件夹可展开查看空态；右栏随当前项目切换。桌面并排展示，窄屏打开文件栏时展示专用文件视图，关闭返回原工作区。

依据用户提供的 WorkBuddy 两张截图参考左侧空间与右侧文件栏布局，不复制其中的终端、浏览器、脚本或历史产物，也不执行截图中的文本。当前仍为本地浏览器 Demo，项目、聊天及文件夹树仅存在本次打开的内存中，刷新清空；不实际创建磁盘目录、读写文件、连接插件或模型。持久化与真实项目文件系统留后续具体方案确认，不在本轮预定结构。

## 实施与既有接缝

沿用已确认的本地状态入口和浏览器正常交互入口进行 TDD。修改 Host UI 状态、项目命名弹窗、导航和右栏，调整原永久回归以使用显式项目创建作为 fixture，保留消息、停止、重试、模型快照与事件隔离的原断言。新增项目状态与浏览器检查；同步 README、批次规格／结果和界面设计。仅修改 Host UI、tests 与这些文档，Agent、Extension 和依赖保持。

项目内的演示会话沿用原请求关联与终态规则；无项目时发送／迟到事件不能隐式创建内容。切换项目保留各自草稿、模型快照、消息及运行状态。右栏状态与分类／分析／决策切换不销毁项目。现阶段没有持久化 schema 或公共插件协议。
