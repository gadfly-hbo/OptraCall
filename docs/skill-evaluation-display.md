# Skill 测评信息展示规范

v1.1 · 2026-11-06 · 沿用用户已确认[UI Demo](prototypes/skill-evaluation-catalog-demo.html)、指标口径及默认收起交互；补齐已确认单向交付、暂定结论与原始计数精度的展示。

用户自行组织“装 skill／不装 skill”的对照测评，本产品消费其明确回执，不另建测评平台、后台任务或上线审批流程。沿用[工程规范](engineering-workflow.md)第5节测评门禁；展示格式适用于目录中的skill，其他分析资产、连接器和业务插件不自动套用。

## 卡片与详情

卡片沿用现有名称、简介、标签、已接入状态和“打开”入口，增加同一测评区域：

- 默认仅展示“用户测评”折叠行及当前数据状态，全部指标默认收起，避免撑高卡片；手动点击一次展开完整测评，再点一次收起。
- 展开后共同展示用户测评结论、断言通过率增益及baseline→variant、激活率和样本数、耗时／Token代价，以及日期、测试版本、完整五项指标和样本限制。不再嵌套第二层“查看详情”；查看测评不成为使用skill的必做操作。
- 已判定胜率在详情连同胜／平／负／未判定数量呈现；不能把未判定样本默认为失败或悄悄纳入分母。
- 已接入但未提供回执的既有skill统一显示“测评数据待补”；保留入口，不编造零值或有效结论。未来新增skill仍先满足原工程测评门禁。非skill条目无此区域。
- 测评结果绑定实际被测skill候选，不从一次回执推为所有模型、任务均有效。按工程规范§5及用户本轮明确指定采用单向交付时，保留原被测身份和数值，如实记录后续工程修正；显示“结论覆盖本轮工程修正后的交付版”，不再把修正版列为待用户复测事项。没有该覆盖安排的历史回执仍沿原记录显示，不自动回写历史状态。
- 回执标注 provisional 等限制时，折叠行保留“暂定”状态，展开后说明原因、实际样本分母和已提供的模型／流程上下文。只有回执明确给出时才展示置信水平，不能把未说明水平的 CI 自行写成95%。

## 五项指标与单位

| 指标 | 统一口径 | 缺失／边界 |
| --- | --- | --- |
| 断言通过率增益 | variant通过率−baseline通过率，单位“个百分点”；同时显示两端百分比与统计口径 | 不混入其他口径，不把百分点写成相对增长百分比；无任一端则不能计算 |
| 激活率 | 激活次数／测试机会数，展示百分比及n/N | 分母为0或缺失时显示未提供，不能写0% |
| 已判定胜率 | 胜／（胜＋平＋负）；展示四类计数及已判定／总样本 | 未判定单列；无已判定样本时不显示伪胜率 |
| 平均耗时变化 | （variant平均秒数／baseline平均秒数−1）×100%，同时保留两端秒数 | baseline为0或缺失时不算比例；如实保留变慢 |
| 平均Token变化 | （variant平均Token／baseline平均Token−1）×100%，同时保留两端Token用量 | 同上；M=百万Token，Token增量不等于账单费用增量 |

百分比默认一位小数，百分点一位小数；耗时秒保留一位，成本比例可四舍五入到整数并标明“约”。比例从有效输入计算，不另填与两端数字矛盾的增益字段。用户回执结论与计算结果分别保留，存在矛盾时说明差异，不改写原回执。

回执同时提供原始分子／分母时，用未舍入的率计算增益，再格式化端点；例如38/142与139/159显示26.8%→87.4%，增益为60.7个百分点。不能先用两个展示端点相减得到60.6，也不能硬填独立增益来遮盖不一致。

回执至少包括日期、测试skill版本／身份、比较定义、样本数、指标口径及已知限制。模型／Provider／参数、数据集或测评流程版本只有实际提供时才展示；本次回执未提供的上下文不补造，也不据此作跨skill排行榜。

## deep-research 本次数据

原用户回执对应skill候选`a78a478`（交接HEAD0329249中七份skill文件仍同字节）：断言通过率16.2%→29.4%，条目累计增益**+13.2个百分点**；激活8/10=80.0%；已判定胜率3/4=75.0%（3胜／1平／0负／6未判定，判定覆盖4/10）；平均耗时278.9s→460.8s，约+65%；平均Token1.11M→1.72M，约+55%。结论为用户明确给出的effective，不推广为研究结论均正确。

原result另记“产物口径+27.9pp”及“14.7%→44.1%”，两端相减为29.4个百分点，数字不自洽。两项原文保留在原回执，待用户核正；本轮卡片与详情只采用无歧义的条目累计13.2个百分点。不得把两种口径拼成一组，也不擅自用29.4覆盖用户给出的27.9。

Codex接管后的非作者发现导致提示词修正；原测评数值继续绑定a78a478。原交付曾记录修正版未复测，后来用户于2026-11-04明确裁定有效结论覆盖30eda70（见[result追加记录](../openspec/changes/deep-research-skill/result.md#用户裁定2026-11-04归档后追加)）。当前卡片据此显示有效及工程修正覆盖，不再要求复测；不把该裁定称为对修后字节重测。本规范与Demo不启动真实模型测评，用户测评结果不能替代非作者复核或工程CI。

本轮data-analysis同样按用户直接指定的单向流程，回执仍绑定6df72f4／评估归档1.9.0，测评通过结论覆盖本轮工程修正；不新增用户复测，不将历史样本改称对最终字节重测。effective与provisional同时保留，原始计数、成本及baseline超时按本轮回执展示。

## 实施与验收范围

数据为随产品分发的目录元信息，复用CatalogItem及现有卡片，在一个共享展示组件集中处理单位、分母、缺失值和详情。不新增持久schema、后端接口、会话域、模型调用、订阅或实时计算服务。日后每个skill按相同字段追加用户回执，不复制一套排版与算法。

Demo验收包括：有数据／数据待补／非skill三种范围、详情开合、打开进入项目看板、浅深色、窄屏、键盘使用；原型所有项目与导航均为内存示例。正式实现后仍需真实产品浏览器点验，不能拿原型截图替代。
