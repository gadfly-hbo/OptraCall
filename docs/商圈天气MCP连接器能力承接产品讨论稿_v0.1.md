## 2 要解决的问题与理念（继承自 data-mcps 的思想内核）

Agent 做选址、经营分析时需要项目上传资料之外的**结构化外部数据**（商圈档案、天气变量）。直接联网抓取的问题：来源与许可不明、口径无版本、部分结果被填零、结果不可复盘。data-mcps 验证过的、值得继承的连接纪律：

1. **来源与许可是接入前提**——每个数据来源的能力、覆盖、许可、成本如实举证，不因"能连上"就默认可用；
2. **结果可复盘**——查询结果带来源身份与数据版本，进入分析时能追溯"当时基于哪一版数据"；部分结果如实呈现缺失，不填零；
3. **副作用与出境有边界**——凭据只存引用、网络出境按白名单、取消/超时/迟到结果的 UNKNOWN 语义不盲重放；
4. **MCP 接缝讲纪律**——工具白名单、目录指纹（工具集变化即冻结重核）、服务端自报的只读提示不作权限依据。

不继承的（data-mcps 具体设计）：数据集市工作台产品形态、自建 UI/CLI、独立 HTTP 服务、四权授权界面、连接管理产品——OptraCall 的连接器是**给项目任务 Agent 用的能力注入**，不是一个面向用户的数据采购工作台。

## 3 产品定义：MCP 连接器接入标准 v1（随首个连接器建立）

一个连接器 = `extensions/connectors/<connector-id>/` 下的一等扩展，向项目任务 Agent 提供某外部/本地数据域的**只读查询工具**。标准要素：

| 要素 | 内容 |
| --- | --- |
| 目录 | `extensions/connectors/<id>/`：`connector.json` 清单、`server/`（MCP server 实现与工具）、`data/`（小型随仓固定资源）、`README.md`（接入说明）。大体量业务数据落 `dataRoot/connectors/<id>/`，**不入公开仓** |
| 清单 connector.json | id/name/version/kind（local-data 或 remote-api）/transport/egress（none 或白名单域清单）/credentials（none 或 referenced）/工具清单（名称+只读声明）/数据版本身份 |
| 工具合同 | 少量、正交、只读；结构化报错信封（参数越界、数据缺失、来源不可用等）供 Agent 自主纠错；服务端自报 hint 不作权限依据 |
| 数据版本 | 本地数据快照式导入（版本=来源身份+内容哈希清单，不可变，更新=显式导入新版本）；远端 API 结果带来源与获取时间标识 |
| 权限与出境 | 无凭据或凭据仅引用（Host 解析）；remote-api 连接器的网络出境按清单白名单在 Host 侧强制；受管执行/封闭资源任务不注入连接器工具 |
| Host 接缝 | 经 SDK 既有 MCP 能力接入（`createMcpExtension` 所依托的 settings `mcpServers` 配置与扩展注册 API，支持自定义/in-process transport）；能力目录"连接器"分区登记"已接入"条目 |
| Agent 自主 | 连接器是能力注入不是流程编排；何时查询、查什么、如何解读由 Agent 决定；无逐调用确认门槛（出境白名单与权限边界除外） |

标准正文随首个连接器交付落为 [docs/mcp-connector-integration.md](mcp-connector-integration.md)，此后连接器均引用该同源文档，不在各连接器内另立标准。

## 4 产品设计：两个独立连接器

### 4.1 商圈数据连接器（首个 · kind=local-data）

把 trade-area 已核定的 **2835 家商圈档案**（12 维度、15 个数值指标、评级、四因子评分）作为本机不可变数据快照，经 3 个正交只读工具供给 Agent（D10）：

| 工具（命名以规格为准） | 职责 |
| --- | --- |
| `tradearea_search` | 按省市/评级/关键词/指标阈值筛选商圈摘要，分页返回 |
| `tradearea_detail` | 单商圈完整档案：12 维度全文+来源+可信度、指标（含推断标记）、评分 |
| `tradearea_score` | 按调用方自定义权重重算选址评分（复用原仓四因子算法，权重、缺失即 null 的严格语义如实） |

多商圈对比等可由既有工具推导的组合能力不设工具（D10），由 Agent 自主组合多次调用完成——工具是能力注入，不预置分析的形状。

- 数据：原仓 ETL 产物（`index.json`+详情分片）快照式导入本机 `dataRoot`；导入记录数据版本身份（原仓 HEAD、generatedAt、条目数、内容哈希）；省份解析脏值在导入或查询层过滤；
- 缺失语义沿用原仓契约：字段缺省=未公开，`inferred` 标记推断值，**不编造、不用占位数**；
- 无网络、无凭据、纯本机只读。

### 4.2 天气连接器（第二个 · kind=remote-api）

Open-Meteo Archive API 适配器，向 Agent 提供历史日天气查询（如日均温、降水）：按坐标+日期区间查询，结果带来源、获取时间与缓存标识；期望日期键与实际结果核对，缺失日期如实呈现不填零；限流/超时/取消按结构化信封与 UNKNOWN 语义处理（借鉴 data-mcps R1 天气闭环的失败路径语义，参考不移植）。出境边界：仅向 `archive-api.open-meteo.com` 发送坐标、日期与字段参数，无密钥。详细合同以规格为准。

## 5 架构与接入

- **统一 Runtime 不变**：连接器工具经项目任务会话的既有 MCP 缝隙进入 Agent 工具集（[project-session.ts](../src/agent/project-session.ts) 普通任务已挂 SDK `createMcpExtension`；受管/封闭执行禁用 MCP 的既有策略保持），不新建会话域、不建平行 Runtime；
- **Host 接缝归属 Codex**（工程规范 v1.3 默认，除非用户对本变更直接指定 Qoder）：连接器注册接线、能力目录"连接器"条目、`dataRoot/connectors/` 分配与数据导入校验、remote-api 出境白名单强制；
- **Qoder 交付连接器本体**：server/工具/适配器/数据导入脚本/测试/README 与适用证据；
- 两个连接器**各自独立分支与变更**（`openspec/changes/trade-area-mcp/`、`openspec/changes/weather-mcp/`），交付顺序：商圈先行奠基标准、天气随后独立交付复用验证（D9）。

## 7 范围与非目标

- 不做云端 MCP、远程部署、跨机服务；商圈数据仅本机；
- 不搬 data-mcps 的工作台 UI/CLI/存储/授权界面；不做通用"数据集市"产品、第三方 MCP 市场或安装平台；
- 天气连接器 v1 只做历史查询，不做预报、订阅刷新、定时采集；
- 商圈连接器不做页面 UI（能力目录条目+导航即可）；不提供写入类工具；
- 不改变既有插件与分析 skill 行为；不为本标准建新的会话域/owner/profile。
