SDK 版本继续锁定 1.4.0；五个模型均有该版本内置定义。真实密钥只定向读取已授权两机 Pi 对应 Provider，经不回显通道送入与前端同一配置导入入口；导入与 UI 文件导入、手动保存共用校验／保存逻辑。源 Pi 文件保持原样，独立保存后不自动重导入旧凭据或载入旧会话／扩展。

配置及密钥重启可恢复。该凭据存储为本地明文文件，由操作系统文件权限保护，用户已同意；密钥不进入前端持久存储、配置读回、日志、报告或会话 JSONL。替换 Provider 密钥从下一请求生效，在途快照不变；清除共享 Provider 凭据先停止相关运行并释放内存，项目／文件／历史保留为待配置，其他 Provider 不受影响。缺密钥不回退模型或线路。

配置与凭据成对提交，私有 `0600` 事务恢复文件记录提交前的一致状态；文件和目录同步后才确认提交。进程在两文件替换之间退出时，下次启动先恢复一致状态，避免新密钥发往旧服务地址。损坏或未知恢复文件保留并报错，不猜测修复。清除凭据也覆盖尚在打开的 SDK 会话，阻止旧凭据继续启动调用。

## 目录、数据与生命周期

```text
/Users/bendandebaba/.optracall/
├── auth.json                              # Pi 原生凭据格式，0600
├── settings.json                          # Host 非密钥配置、版本与默认选择
├── pi/                                    # SDK 原生 settings/skills/extensions/MCP 等资源
└── projects/<项目 UUID>/
    ├── project.json                       # Host 项目、草稿、附件来源、运行状态
    └── sessions/<SDK 文件名>.jsonl         # SDK 原生会话与工具结果

/Users/bendandebaba/OptraCallProjects/<项目 UUID>/
├── 010_draw/                              # 原件归档，前端提示勿放敏感资料
├── 020_clean/                             # 用户指定分析输入，默认过程输出
└── 060_reports/                           # 最终报告与用户显式保存
```

三个名称严格保持 `010_draw`、`020_clean`、`060_reports`。新项目不默默扫描或发送归档原件。上传、复制、打开项目、读取配置和刷新不自动调用模型；用户显式准备020资料后发送任务。Host 不对数据清洗、汇总或选择分析方法。

系统提示词说明：分析不读取010中的数据，使用用户放入020的分析资料；过程文件默认保存020，最终报告保存060。该软约束适用于完整原生工具，不保证模型在所有情况下遵守，也不等于文件权限禁读。UI 在上传及项目文件栏提示当前没有敏感数据隔离，请勿放入敏感数据。

最终报告由 Agent 按约定自行选择输出并保存060，Host 不根据内容猜测“最终报告”、搬运过程输出或补写分析结果。另提供明确的用户“保存为最终报告”按钮，把用户选中的回复文本保存060；下载也由用户显式发起。同名文件生成不同存储名，保留原名、大小、SHA-256、时间及上传／复制／用户保存来源。

Host 小型元数据使用版本化 JSON 与原子替换；SDK JSONL 的格式和迁移使用 SDK，不建立第二套权威消息库。项目字段为 UUID、名称、创建／更新时间、配置 ID／修订与非密钥快照、会话文件引用、草稿、附件来源和最近运行状态；空草稿表示未输入，空会话引用表示尚无持久消息。单机单 Host 写入，重复启动有单写入保护。损坏／未知版本数据或未识别目标目录保留并报错，不清空重置。本期不增加删除、通用索引或血缘数据库。

请求身份关联到 SDK 原生 custom entry；恢复先核对对应请求已落盘终态，不拿上一轮成功认定新一轮成功。无法确认终态时标记 interrupted／远端结果未知，保留已知内容，显式重试才发新请求。回退源码不删除用户数据；旧内存 Demo 项目不冒充真实持久项目迁移。

## Host 与 Agent 接缝

`浏览器 → Node Host → src/agent 统一 SDK 入口 → 官方 Pi SDK`。

Host 管交互、业务与资源上下文、配置、目录、上传、文件保存和事件传输。Agent 直接使用 SDK 的模型调用、工具循环、会话、上下文管理、重试与压缩。项目可以隔离进程／会话以管理生命周期，但统一由同一 SDK 入口和版本承接；这不意味着另造 Agent 分析循环。

macOS 适用原生工具为 read、bash、edit、write、grep、find、ls；Python 通过 bash 直接执行。PowerShell 是 SDK 提供但上游只支持 Windows 的工具，不在 macOS 重造一个替代品。官方 codemode、tool_search、MCP 工厂与正常资源加载器接入，保留用户安装 skills、extensions、prompts 及配置 MCP 的能力。原生自动压缩、重试、会话树／分支等沿用 SDK，不复制第3项连接探针的空工具／关闭资源设置到普通项目运行时。

安装能力、实际安装、实际连接分别记录；不宣称未配置的第三方 MCP 已连接，或所有 CLI TUI 画面已移植到浏览器。需要浏览器承接的状态、工具、会话和用户交互通过接缝展示，不用假成功代替 SDK 返回。

浏览器承接 SDK 公开的选择、确认、输入及编辑对话框、通知和状态；启动阶段的扩展交互也可见、可回答。原生扩展修改输入框时同步项目草稿并持久保存，不自动发送问题。终端专用装饰忽略并提示，必须依赖终端组件或原始终端输入的交互明确报不支持，不伪造用户同意。

普通消息与原生命令共用请求身份、运行／停止及终态关联。SDK 原生 custom entry 保留已接受请求身份，旧请求在后续轮次、分支或重启后仍不重复执行；最初尚无助手消息时，通过 SDK 公开导出和恢复接口落盘原生会话，保留会话树及父会话引用。子进程异常退出后保留未知状态，仅在用户显式提交新请求时重建运行环境，不自动重发。
