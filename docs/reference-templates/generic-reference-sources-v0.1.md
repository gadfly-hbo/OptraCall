# 通用运动鞋服行业与会员运营领域：模板依据与候选模型

版本 v0.1 · 2026-11-12 · 公开参考研究／待审阅

本文件支持两条参考建设线中的起点：通用运动鞋服行业、通用会员运营领域。先给出可供选择和内化的基础模型，不以某个首购、复购或门店分析问题裁剪范围。目标企业的制度、字段、真实记录、身份关系、组织归属和指标口径，待企业资料提供后分别核定。

下文中“候选”表示本次建模建议；“标准词汇”表示在官方资料中查到的术语。二者分别标识。本文件未实现数据导入、标准认证、RDF／OWL／SHACL 接线、正式资产发布或模型实验。

## 1. 一手资料核对结果

公开资料访问日：2026-11-12。Schema.org 此次网页显示 development 版本；若后续实施正式词汇映射，应再固定实际消费的发布版本。本次只提出语义对照。

| 编号 | 一手来源及已核对内容 | 可以支持的模板设计 | 不由此推断的内容 |
| --- | --- | --- | --- |
| S01 | [GS1 GTIN Management Standard，Release 1.1，Sep 2023](https://ref.gs1.org/standards/gtin-management/)：贸易项目标识及产品新增／变化时的 GTIN 管理规则 | 将产品标识、贸易项目及标识变更依据分开记录 | 不把企业任意款号、SKU 或条码无条件等同于 GTIN；不要求目标企业先取得 GTIN 才能建设模型 |
| S02 | [GS1 Global Location Number Data Model Solution Standard，Release 1.0，Nov 2021](https://www.gs1.org/docs/barcodes/GS1_GLN_DataModelSolution_Standard.pdf)：区分法人、职能、固定／移动实体地点和数字地点；检索可读正文，直接 PDF 访问返回 403 | 区分经营主体、职能部门与地点，GLN 作为可选外部标识 | 不把店铺、经营公司和会员部门合成同一实体；不为企业虚构 GLN |
| S03 | [Schema.org Product](https://schema.org/Product)：可表达品牌、颜色、尺码、GTIN 和商家自定 SKU 等 | 商品变体字段与外部词汇的候选对照 | 不推断不同企业 SKU 的实际粒度或跨企业唯一性 |
| S04 | [Schema.org ProductGroup](https://schema.org/ProductGroup)：组合具有颜色、尺码等变体差异的产品；有 `hasVariant`、`isVariantOf`、`variesBy`、`productGroupID` | 款／产品组与可售变体之间的关联 | 不宣称 ProductGroup 必然等同于目标企业 SPU；不把产品组和实际可售变体混为一条记录 |
| S05 | [Schema.org MemberProgram](https://schema.org/MemberProgram)：会员计划、举办组织及可选多等级 | 会员计划与举办主体；等级为扩展模块 | 不假定每个计划都有等级、积分或付费门槛 |
| S06 | [Schema.org ProgramMembership](https://schema.org/ProgramMembership)：主体加入计划的会员关系，有 `member`、`program`、`membershipNumber` 等 | 人／组织、账号、会员关系与计划分开 | 不将会员号直接当自然人身份证明，不推断多账号自动属于同一人 |
| S07 | [Schema.org MemberProgramTier](https://schema.org/MemberProgramTier)：等级、准入条件及权益；[TierBenefitEnumeration](https://schema.org/TierBenefitEnumeration) 当前列积分、会员价、退货、配送权益 | 选用等级模块及部分权益词汇映射 | 通用 `BenefitDefinition` 是本模板扩展，不冒称已核实的 Schema.org 标准类；页面示例不构成企业政策 |
| S08 | [Schema.org Offer](https://schema.org/Offer)：商品或服务要约，可表达适用地点、时间等；[validForMemberTier](https://schema.org/validForMemberTier) 可用于指定要约／价格／配送／退货政策适用的等级 | 将商品本身、价格／服务条件和会员适用资格分开 | 不把 Offer 等同于已发生订单、已领取权益或已兑现权益 |
| S09 | [Schema.org Order](https://schema.org/Order)、[OrderItem](https://schema.org/OrderItem)：订单与订单行分别表达交易确认和明细 | 在本体中关联交易事件／记录与商品、主体和渠道 | 不把交易事实列入稳定的商品／会员主记录；不直接采用网页默认值补企业缺失数据 |
| S10 | [W3C SKOS Reference，2009 Recommendation](https://www.w3.org/TR/skos-reference/)：概念、词表、标签、层次和跨词表映射 | 类目、运动场景、状态等参考词表，以及企业术语对照 | `closeMatch`／`exactMatch` 是概念映射，不作为会员身份合并证据 |
| S11 | [W3C PROV-O，2013 Recommendation](https://www.w3.org/TR/prov-o/)：实体、活动、Agent 及来源关系 | 记录模板来源、内化过程、版本和责任主体 | 来源可追溯不等于企业口径已经正确或获得正式批准 |
| S12 | [W3C SHACL Recommendation](https://www.w3.org/TR/shacl/)：对 RDF 数据图执行条件验证；[OWL 2 Primer，Second Edition](https://www.w3.org/TR/owl2-primer/)：表达类、属性和个体同一性等语义 | 将业务语义、数据约束和身份判断分别建模；需要时再映射为技术校验 | SHACL 结构通过不证明业务正确；`owl:sameAs` 不是“可能同一会员”标签，不能凭相似姓名或手机片段生成 |

## 2. 模板中的四类内容

下列分法是本模板的管理建议，用来避免把一切都塞进“主数据”。

| 内容 | 作用 | 例子 |
| --- | --- | --- |
| 主数据与持久关系 | 多业务过程共同引用的对象及其有效期关系 | 商品、SKU、门店、经营组织、账号、会员关系、会员计划、权益定义；门店经营归属、账号与会员映射 |
| 参考数据与规则定义 | 编码、分类、状态和资格定义，具有版本及适用范围 | 品类、颜色、尺码体系、渠道类型、会员状态、等级、权益准入条件 |
| 交易／事件／时点事实 | 在时间与业务情境中发生的事情 | 入会、退出、账号关联变更、下单、支付、履约、退货退款、权益发放／核销、触达及互动 |
| 指标／分析定义 | 基于明确事件、对象、时间和资格规则产生的计算与解释 | 会员规模、活跃、留存、购买、权益使用等指标族；具体公式、窗口和阈值后续核定 |

“会员等级”作为编码／定义属于参考内容；某会员在某期间取得某等级，是带有效期的关系／状态事实。会员生命周期、分群、偏好和活跃度须区分业务维护值与模型／规则推导结果，并保留计算方法、版本、观察时间和来源。

## 3. 通用字段外壳

以下外壳供主数据、词表、关系及本体定义选用；属于模板约定，不是 GS1 或 Schema.org 强制字段。

| 字段组 | 候选字段 | 说明 |
| --- | --- | --- |
| 身份与含义 | `object_id`、`object_type`、`name`、`definition`、`aliases`、`namespace` | 内部稳定身份和人可读定义；名称相同不自动合并 |
| 外部标识 | `source_system`、`source_object_type`、`source_key`、`identifier_scheme` | 外部键带命名空间；GTIN／GLN 仅在来源真实存在时填入 |
| 适用条件 | `enterprise_scope`、`brand_scope`、`market_scope`、`channel_scope` | 不适用、未知和全范围分别表达 |
| 时间与状态 | `valid_from`、`valid_to`、`recorded_at`、`status`、`version` | 业务生效时间与系统记录时间分开，未知不补造日期 |
| 来源与决定 | `source_ref`、`evidence_location`、`fact_or_proposal`、`owner`、`decision_ref` | 公开事实、模型建议和企业决定分别标识 |
| 映射与差异 | `reference_version`、`mapping_type`、`adaptation_reason`、`unresolved_items` | 记录直接采用、调整、删除、新增及未决项，保留原参考身份 |

## 4. 通用运动鞋服行业主数据候选

| 对象／模块 | 候选字段与关键关系 | 内化时需要核定 |
| --- | --- | --- |
| 企业／法人／组织单元 | 稳定 ID、法定／业务名称、组织类型、上级、市场、生效期；组织单元与法人分别建模 | 实际组织树、法人边界和部门职责；不由品牌名称猜法人 |
| 品牌 | 品牌 ID、名称、持有／经营组织、适用市场、有效期 | 多品牌、授权和代运营关系 |
| 业务伙伴及角色 | 伙伴 ID、组织引用、供应商／经销商／加盟商／物流等角色、合同关系引用及有效期 | 同一伙伴可承担多个角色；是否还需个人伙伴 |
| 商品款／产品组 | 产品组 ID、款号、名称、品牌、类目、运动用途、材质说明、适用尺码体系 | 企业款、款色、SPU、系列等真实层级，不能硬套单一结构 |
| 可售变体／SKU | SKU ID、来源键、所属产品组、颜色引用、尺码引用、包装单位、可选 GTIN、状态 | SKU 是否精确到款色码／包装／市场；唯一键的实际范围 |
| 地点 | 地点 ID、门店／仓／配送点等类型、地址或区域、时区、可选 GLN | 一个地点与多个业务用途的关系 |
| 门店经营单元 | 门店 ID、地点、经营组织、直营／加盟等经营类型、渠道、开闭店有效期 | 经营权变化与物理地址变化分别处理，是否沿用原门店身份 |
| 渠道与触点 | 渠道定义 ID、渠道类型；触点 ID、网站／App／小程序／POS 等类型、运营组织 | 渠道、平台、店铺、客户端与地点的关系，避免混成一个“渠道”字段 |
| 集合／季节／上市批次（可选） | 定义 ID、名称、范围、时间、商品成员关系 | 季节与商品的真实多对多关系，不把季节代码当通用事实 |
| 参考词表 | 商品类目、运动场景、颜色、尺码体系、材质、单位、市场、渠道类型、状态 | 来源、版本、层次、别名及企业编码映射；颜色名和尺码名不直接跨体系等同 |

顾客、账号与会员在行业模板与领域模板之间共用对象身份；供应链订单、库存快照、销售订单、支付、配送、退货退款作为关联事件／事实模块，不作为上述主记录字段不断覆盖。

## 5. 通用运动鞋服行业本体候选

下列关系名为本模板建议；如能准确对应 S03–S04、S08–S10，才添加标准词汇映射。基数和必填性由目标企业证据确定。

| 关系／事件 | 主体 → 客体／主要内容 | 约束候选 |
| --- | --- | --- |
| `operatesBrand` | 组织 → 品牌 | 记录经营角色、市场与有效期，持有和经营可以不同 |
| `hasOrganizationalUnit` | 组织 → 组织单元 | 上下级关系不能仅凭名称生成；组织变更保留历史 |
| `hasVariant` | 产品组 → 可售变体 | 可对照 ProductGroup；款色码层级保留企业定义 |
| `classifiedAs` | 商品／产品组 → 类目／运动场景概念 | 说明分类体系和版本；允许多个用途 |
| `operatesAt`／`operatesThrough` | 经营组织／经营单元 → 地点／渠道触点 | 门店地点、经营主体、销售发生触点分别可追溯 |
| `supplies`／`distributes` | 业务伙伴角色 → 商品／品牌／范围 | 关系有授权来源和有效期，不能由一笔交易推出长期授权 |
| `offeredUnder` | 商品／服务 → 要约／价格政策 | 标价、会员价、实际成交金额分别表达 |
| 采购／调拨／收货／库存时点 | 商品、地点、伙伴、时间、数量、单位及来源单据 | 时间、计量单位与交易粒度明确 |
| 订单／支付／履约／退货退款 | 业务主体、商品行、门店／渠道、时间、状态和原交易引用 | 订单、支付、退款、实物退货各自建事件；不假定一一对应 |

## 6. 通用会员运营领域主数据候选

| 对象／模块 | 候选字段与关键关系 | 范围与待核内容 |
| --- | --- | --- |
| 顾客／主体 `CustomerParty` | 主体 ID、主体类型、可用来源身份、状态与有效期 | 是否自然人可识别；未知身份不靠 LLM 补齐，个人属性按获准范围选用 |
| 账号 `Account` | 账号 ID、系统／平台、来源键、注册／关闭时间、状态 | 账号与自然人、设备、联系方式不是默认一一对应 |
| 身份映射 `IdentityLink` | 两端对象与命名空间、映射类型、证据、来源、有效期、判定状态 | 确证、候选、拒绝、撤销分开；跨系统真实合并规则待企业资料 |
| 会员计划 `MemberProgram` | 计划 ID、名称、举办组织、品牌／市场／渠道范围、加入方式、政策版本 | 对照 S05；允许单一无等级计划 |
| 会员关系 `ProgramMembership` | 会员关系 ID、主体／账号引用、计划引用、会员号、加入／退出时间、状态 | 对照 S06；明确是计划内身份，不当作全局自然人身份 |
| 等级定义（可选） | 等级 ID、计划、名称、资格规则、生效期、权益关联 | 对照 S07；有企业依据才启用，不默认铜银金或消费升级 |
| 权益定义 `BenefitDefinition` | 权益 ID、类型、内容、提供方、适用产品／服务／触点、资格／限额／期限规则、版本 | 本模板扩展；折扣、服务、活动资格等按企业实际选用，部分可对照 S07–S08 |
| 政策／资格规则 | 规则 ID、规则类型、适用范围、条件、例外、生效期、来源及版本 | 加入、退出、权益、等级等规则相互可区分，未知条件不补默认值 |
| 触达与服务定义 | 触点、活动／内容／服务定义、运营组织、适用渠道／市场、有效期 | 触达许可与具体交互事件分别保存；不预设企业拥有任何平台能力 |
| 分群定义（可选） | 分群 ID、规则或模型引用、版本、适用数据和生效期 | 分群定义与时点成员名单分开；规则性标签与人工维护标签区分 |
| 参考词表 | 会员状态、事件类型、权益类型、触点类型、许可用途、业务原因码 | 许可用途只作建模容器，实际要求由目标企业适用政策及获准资料核定 |

积分、储值、付费订阅、家庭会员、推荐关系等均为可选扩展。若启用积分，积分规则定义与积分流水、余额时点事实分别管理；不能仅凭存在会员计划就生成积分账户或等级记录。

## 7. 通用会员运营领域本体候选

| 关系／事件 | 主体 → 客体／主要内容 | 语义及约束候选 |
| --- | --- | --- |
| `hasAccount`／`identifiedBy` | 顾客主体 → 账号／来源身份 | 真实证据与有效期必留；“可能同人”不是 `owl:sameAs` |
| `enrolledIn` | 会员关系 → 计划；会员关系 → 对应主体／账号 | 计划、会员关系、主体三者分开，记录业务有效期 |
| `holdsTier`（可选） | 会员关系 → 等级定义 | 携带有效期及取得／失去依据，未启用等级时关系缺席 |
| `eligibleFor` | 会员关系／分群 → 权益定义 | 资格判定依赖规则版本与当时事实，不等于已发放／已使用 |
| 入会／退出／冻结／恢复 | 会员关系、事件时间、记录时间、原因和来源 | 状态变化事件与当前状态可勾稽，历史规则变更不覆盖原事件 |
| 身份关联／合并／拆分 | 来源身份、目标身份、作用范围、证据与有效时间 | 不强制发生合并，撤销和争议需可表达 |
| 权益授予／领取／预约／使用／撤销／过期 | 会员关系、权益定义、具体实例、触点、时间、关联交易、状态 | 权益资格、权益实例、领取和兑现分别表达；是否存在每一步由实际业务决定 |
| 触达／互动／服务履行／活动参与 | 会员／账号、触点、内容或服务、时间、上下文和结果 | 发送不等于到达、到达不等于阅读、阅读不等于业务效果 |
| 同意／撤回等许可事实 | 主体／账号、用途、渠道、政策版本、时间、证据 | 不能由注册、购买或 App 安装自动推断全部用途获准 |
| 与交易的联系 | 会员／账号／主体 → 订单、订单行、支付、退款等事件 | 保存关联键、映射依据及当时身份；匿名交易可以保持未知 |

本体中可保留会员规模、互动、购买、权益使用、留存等指标族的概念入口；正式计算定义由后续 SAP 资产承载。基础模型阶段不固定某个首购问题、观察天数、营销阈值或企业绩效判断。

## 8. 内化检查候选

1. 每个对象、关系、规则和词表有定义、身份、范围、版本与来源；公开标准、建模建议、企业事实分别标识。
2. 商品组与可售变体、组织与地点、渠道与触点、顾客与账号与会员关系的区别在字段和样例中可验证。
3. 外部键包含来源系统／命名空间；同名、同手机号片段、同设备不自动形成同一人结论。
4. 有效时间、记录时间和计算时点明确；未提供的数据保持未知或不适用，不以空字符串／零值替代业务事实。
5. 必填、唯一、类型、引用、范围和时间约束按企业证据逐项确定；结构校验结果与业务核验结果分开。
6. 可选等级、积分、付费、分群等模块按企业实际采用；缺乏依据的模块不生成企业事实记录。
7. 行业模板、领域模板与标杆模板对同一共享概念形成映射和差异说明；企业内化保留采用／修改／删除／新增依据。
8. 后续通过多个实际使用情境检查覆盖与歧义，再逐步补充分析指标和方法；不以某一个分析题通过推断整个企业基础层完备。
