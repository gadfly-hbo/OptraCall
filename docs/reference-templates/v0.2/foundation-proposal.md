# 企业基础层三类资产建设方案 v0.2

2026-11-12 · 供方案、spec 与 UI Demo 联合审核 · 暂不产品开发

用户已认可三类资产同步建设及优先复用的方向，要求本次形成新版方案、四份模板、工具与流程 spec、可点击 Demo 和目标任务清单。方向认可不代表当前版本 spec、UI、产品实施或目标企业正式资产已获验收。原[调整稿 v0.1](../foundation-adjustment-v0.1.md)、四份 v0.1 模板与既有批准产品方案保留。

## 目标与成果

企业基础层提前建设主数据、数据分析指标体系、本体及三者关联，供同企业合格 Case／项目／任务复用。任务中产生的新资料、规则变化与共享问题通过任务演进层贡献，核定后并回基础层。

| 成果 | 定义内容 | 可审核依据 |
| --- | --- | --- |
| 主数据模型与字典 | 对象、标识命名空间、属性、键、值域、粒度、关系和有效时间 | 参考及企业来源、实际字典、身份与字段映射、质量核查 |
| 指标体系 | 主题与指标族、业务用途、准确指标定义、维度／时间／资格、指标关系与数据条件 | 原 SAP 指标及场景版本、测量依据、数据需求与样本核验 |
| 本体 | 概念、属性、关系、事件、规则及适用条件 | 与主数据、指标和原始资料的逐项对应、例外与未知 |
| 三类关联与内化记录 | 参考项到企业项的采用／修改／排除／新增、准确依赖、差异与影响 | 联合对照表、来源定位、版本、检查、限制和后续使用证据 |

三类成果并行查证和迭代，不要求先做完一类再开始另一类。指标帮助识别统计对象和必要事件，本体帮助发现指标歧义，主数据提供稳定身份。企业基本对象也可因经营需要保留，不要求每项都由一条指标证明存在价值。

基础范围先按行业与领域组织，不绑定首购复购或其他单一分析题。实际分析任务用于后续验证覆盖与可用性，不倒推成唯一基础层范围。

## 两条路线

1. 运动鞋服行业 → Nike 企业公开参考 → 目标企业。
2. 会员运营领域 → Nike 会员运营业务域公开参考 → 目标企业会员运营。

每站都包含三类内容。共享对象使用一致身份，通过参考、扩展和差异连接。Nike 的公开做法不自动成为目标企业政策，公开业务域不虚构为内部部门；参考本身不获得目标企业正式供给资格。

四份模板及共同记录结构见[模板包](README.md)。T01／T02 提供候选指标目录与口径槽位；T03 对公开披露指标单列来源和报告范围；T04 的测量建议与 Nike 未公开内部 KPI 分开。模板中的公式只是候选设计内容，内化后正式定义与公式统一归 SAP，其他资产只引用准确版本。

## 当前能力与拟补差额

| 接缝 | 当前可复用 | 本次拟补的最小差额 |
| --- | --- | --- |
| 资料及会话 | 企业业务资料、项目文件、Studio 建设任务、统一 Pi 生命周期 | 企业基础层建设目标与多主题范围的引导，避免必须先选具体分析题 |
| 模型内容 | Studio `concept/rule/ontology/binding` 正文、来源、依赖、检查、候选／正式版本 | 主数据项、指标体系索引、本体项的轻量结构约定与逐项核验 |
| 指标与场景 | SAP 0.2 包、简单／比率／派生／累计指标、维度、时间粒度、用途角色和方法引用 | 跨包主题组织、逐项语义关联、受影响范围；不重复已有场景或公式权威 |
| 内化与 Binding | 来源版本、工作表、M2 字段观察及语义引用、现有 Python／bash | 参考 item 与目标 item 的差异、对象／事件／维度到实际字段的明确关联及核验依据 |
| 发布与资格 | 准确预览、指纹、正式指针、SAP 分模块实际回执、递归依赖资格 | 三类资产业务相容性与准确版本组合、分项完成状态和影响清单 |
| 使用与演进 | 企业目录、按需准确读取、普通任务贡献、历史保全、可选图 | 让原查读返回清楚的项级含义、关联和限制；联动三类资产影响，不增加手工选材前置 |

现有正文已可保存和读取约定 JSON，不能把新增一套读写工具作为默认方案。优先以样例检查原合同能表达什么，再补无法可靠核验的部分。SAP 严格字段与版本规则保持；不能向 SAP 0.2 直接塞入新字段。需要演进时在 spec 明确兼容与迁移，不借此改造第三方 SDK。

当前 Semantica 已用于抽取候选及正式图投影，但图主要是来源陈述与关系读模型。它不接管主数据、SAP 或本体源资产权威，不把自动抽取当企业真相，不以图刷新阻断独立可用内容。

## 拟补的内容与工具契约

- **结构内容约定**：稳定 item 标识、对象类型与粒度、属性／键／值域、关系两端及条件、准确 SAP 项引用、来源及适用范围。原文字资产继续可读。
- **内化与三类关联**：参考版本及 item、目标项、采用动作、差异依据、Binding、影响用途和四项状态。原 `SourceRef` 保持其权威及 locator 的既有语义；内容内项定位另存 `itemId`／`metricName`，不把指标名或字段路径塞进原 locator。
- **核验与发布准备**：Host 核结构、引用、权限、来源资格、版本和指纹；Agent 自主核业务口径、样本与解释；必要业务决定集中交人。保留 PASS／FAIL／UNKNOWN 及其证据。
- **工作区呈现**：沿原 Studio 增加按需的三类成果总览、关联对照、内化差异和影响查看；指标和方法继续在原专业区维护，不新增平行资产库。

真实需求以[spec](../../../openspec/changes/studio-foundation-three-assets/spec.md)及其验收标识为准。本稿不约定新的固定专家团队、工具调用顺序、返工次数或逐字段审批。正式发布结果分模块留证；局部 UNKNOWN 限制相关用途，其他独立成果继续，不新建全库原子发布引擎。

## Agent、Host 与人工

Agent 负责参考整理、精读、候选、差异、数据映射、样本核查、计算、解释和修订，沿统一 Pi 自主选择工具与内部顺序。Host 提供企业与项目归属、权限、资源、生命周期、持久化和真实回执；不代算业务、不替人决定企业政策。人提供获准资料，处理材料不能决定的实质业务问题，作必要正式发布及产品验收决定。

正常使用无需先维护图、逐项确认读取或逐资产勾选。建设所需默认归属可沿明确的同企业可写项目；只有缺少合格归属或存在实质范围冲突时才增加选择。普通任务缺少某项资产时，受影响结论保留限制，独立分析仍可继续。

## 完成状态与发布边界

每项同时记录四个独立维度：定义是否核定、数据是否映射、当前是否可计算、实际使用是否核验。另保留参考／候选／正式／历史等治理身份。发布不等于可计算，目录可见不等于读过正文，作者引用不等于独立核验。

分阶段核定完成边界：

1. **定义核定**：三类项有身份、含义、范围、来源和版本；统计对象、维度、粒度、单位、时间、资格、依赖与本体规则一致；参考到企业的差异及依据可追溯。影响这些定义的关键未知仍待核，不能勾成完成。
2. **映射与可计算**：有实际字段、键、粒度和事件覆盖，并完成对应样本与边界核查；只有定义、尚缺数据的项保持未映射／不可计算。
3. **正式发布**：沿原门禁核定当前用途下必要证据、检查及准确预览，保留原 FAIL／UNKNOWN 规则。定义合格但缺数据的项可按明确限定的定义参考用途核定发布，不能借此绕过本用途关键失败或未知。
4. **实际使用验收**：普通任务真实读取并应用相应准确版本，计算与业务解释有独立依据；任务贡献和新版再用按对应范围另留证，旧报告保留原版依据。

不按文档数、指标数量、图节点数或一个案例通过宣称整个企业基础层完备。首次达到其范围要求即可发布，不为满足流程故意制造错误再修订。

## 本版变化与来源

相对 v0.1，增加了四模板的实质指标目录、三类联合对照、指标关系分类、四项状态，以及最小工具／流程合同。原主数据与本体范围保留，必要术语共享，首购复购具体题不作为基础层范围。

通用候选依据[既有标准研究](../generic-reference-sources-v0.1.md)；标杆事实依据[Nike 公开研究](../nike-public-reference-sources-v0.1.md)，公开财报度量的本版核查另见 T03。当前实现依据沿[调整稿 v0.1](../foundation-adjustment-v0.1.md)的静态代码核查。方案、原型和结构核查不代表目标企业业务正确性或实际运行采用已通过。
