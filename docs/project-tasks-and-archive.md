## 已确认持久结构与字段语义

这是Host主线元数据调整；消息、工具结果、原生会话树及其格式继续由SDK管理。任务不会形成第二套Agent Runtime。

### Project：一条记录代表一个项目空间

| 字段／字段组 | 格式、必填、默认及含义 |
| --- | --- |
| `schemaVersion` | 必填整数2；只接受支持的版本，未知版本保留并报错。 |
| `id` | 必填UUID；既有项目沿用原值，新项目创建时生成，不从名称推导。 |
| `name` | 必填字符串，去首尾空白后1–80字符、无控制字符；允许重名，以UUID区分；无隐式默认。 |
| `createdAt / updatedAt` | 必填UTC ISO时间；既有创建时间保留，修改名称、归档／恢复及任务元数据时更新修改时间。 |
| `configuration` | 必填，沿用既有非密钥快照的字段和格式，作为新任务默认配置；不静默改写已有任务。 |
| `uploads` | 必填数组，默认空；沿用现有文件UUID、原名、路径、大小、SHA-256、时间与来源结构，归项目所有。 |
| `archivedAt` | 必填 `UTC ISO字符串或null`；新建／迁移／恢复为null表示活动；归档写入实际时间。此字段即归档状态，不重复增加布尔状态。 |
| `tasks` | 必填Task数组；新项目默认空，旧项目迁移为一个任务。Task所属项目由容器确定，不冗余保存另一份parent ID。 |

### Task：一条记录代表项目中的一个独立对话任务

| 字段／字段组 | 格式、必填、默认及含义 |
| --- | --- |
| `id / name` | 必填UUID及1–80字符名称，名称规则同项目；同项目Task ID必须唯一，新任务手动命名，迁移首任务名建议“原有任务”。允许重名，身份靠所属项目与任务UUID；不得跨项目移动或引用别人的任务。 |
| `createdAt / updatedAt` | 必填UTC ISO时间；新任务为创建时间；迁移任务沿用旧项目时间，避免把旧对话伪装成新发生。草稿、会话引用、配置引用或运行状态等元数据变化更新任务及所属项目的updatedAt。 |
| `configuration` | 必填非密钥快照；创建时按D04选择，复制既有字段组 `id/name/provider/model/baseUrl/revision`，保留可选 `api/thinkingLevel`，继续复用既有凭据修订和清除规则。 |
| `draft` | 必填字符串，默认空，最多20000字符；仅属该任务。 |
| `sessionStorage` | 必填枚举 `legacy` 或 `task`；每项目最多一个legacy任务，只由迁移标记，新建一律task，客户端不能任意指定目录，两个任务不得共用原生历史目录。 |
| `sessionFile` | 可选SDK原生当前JSONL引用，尚无持久会话时缺省；只允许所属受控目录内的合法文件，保持既有路径／软硬链接检查。 |
| `lastRun` | 可选；没有接受过请求时缺省。沿用请求UUID、`running/completed/cancelled/failed/interrupted`及起止时间语义；不以其他任务或前一轮成功证明当前终态。 |

项目文件路径、会话目录和API返回的所属项目ID均由Host按UUID派生，不由显示名或前端自由路径决定。不新增数据库、索引、通用审计事件表或业务本体结构；本轮没有跨base联动。SDK JSONL已有的运行身份和原生消息来源继续保留。

```text
.optracall/projects/<projectId>/
├── project.json                           # v2；项目信息与tasks元数据，0700目录／0600文件
├── project.v1.backup.json                  # 迁移前原元数据，0600，保留
├── sessions/*.jsonl                       # 旧首任务保留原路径和字节，含所有原生fork
└── tasks/<taskId>/sessions/*.jsonl         # 新任务独立SDK历史目录

OptraCallProjects/<projectId>/
├── 010_draw/
├── 020_clean/
└── 060_reports/                           # 三目录继续为项目共享，不复制、不改名
```

## 读写入口、验证与迁移

- 项目入口负责列活动／归档项目、创建、重命名、归档、恢复及共享文件操作；任务入口均带所属 `projectId + taskId`，负责创建、草稿、历史、消息、命令、停止、SSE及原生UI回应。路由、缓存与事件均按这对身份区分；查询任务必须验证所属关系，SDK请求去重仅扫描所属任务的历史目录。
- 列表／只读历史／归档文件读取不打开SDK；用户主动进入可用任务时按需激活，已中断任务保持只读历史，显式新执行才恢复。归档任务的写入口包括消息、草稿、上传／复制、显式保存报告、命令和交互回应，均由Host检查生命周期；恢复本身不发模型请求。
- 保持现有单Host写入保护，项目元数据串行原子更新；沿用当前2MiB元数据边界，在写入前校验，超限保留原文件并提示，不另设隐含任务个数上限。不把文件工具或Agent分析步骤锁成自建流程。新任务创建、归档与发送并发时，服务端以实际生命周期为准，不只隐藏按钮。
- 先在合成数据副本验证升级中断、重复启动及恢复；实际升级前确保Host空闲，再暂时停止并备份元数据。原v1备份以独占方式写入、同步后保留，不覆盖既有备份；中断重启时若主文件仍v1且备份存在，校验两者字节一致后继续，否则保留并报错。一次原子切换为v2，文件及父目录同步后确认成功；重启识别v2后不重复生成任务。损坏／未知数据不猜测、不重置。
- 原项目UUID、三目录、上传来源和所有SDK JSONL原路径／字节保留；尤其不改原生fork的 `parentSession`。不导入旧模型凭据、不调用真实模型完成迁移，也不把消息复制进Host元数据。
- 回退必须区分阶段：尚无v2新写入时可以停Host并使用保存的v1元数据恢复；产生新任务或新历史后不能用v1备份覆盖，需保留v2数据并采用兼容版本。旧代码遇schema2明确报错，不静默丢弃任务。
- 本轮主线只包含项目多任务、项目重命名／归档／恢复及兼容迁移。任务删除／任务归档、自动模型命名、独立任务文件根、插件市场和业务分析流程留到后续，不从截图引申实施。
