# Studio 二期交互原型审核说明

本原型与[二期方案 v0.2](../../studio-phase2-proposal-v0.2.md)、[spec](../../../openspec/changes/studio-phase2-unified-assets/spec.md)和[交互状态](../../../openspec/changes/studio-phase2-unified-assets/interaction-states.md)配套，供审核统一 Studio、企业基础层和任务演进层的交互。当前尚未实施产品功能。

## 打开与操作

直接用浏览器打开[交互原型](index.html)。如需本地 HTTP 预览，在仓库根目录运行：

```bash
python3 -m http.server 4188 --bind 127.0.0.1 --directory docs/prototypes/studio-phase2
```

然后访问 [本机预览](http://127.0.0.1:4188/)。该命令只提供本目录的静态文件，与 OptraCall 产品服务无关。

## 建议审核顺序

1. 在“企业基础资产”中筛选企业资料、指标和方法，打开指标详情，核对其定义、制度依据、数据映射及原使用报告是否能连续查阅。
2. 发起“建设基础资产”，填写目标，查看 Agent 与资源的建设工作区，以及可选参考资料的作用。
3. 打开普通分析任务，查看任务已经形成的贡献候选；继续完善，比较其与正式版本的差异。
4. 准备发布预览并确认模拟发布，查看分项结果、基础资产新版和旧报告仍绑定的原版本。
5. 展开“评审场景”，分别查看部分成功、UNKNOWN、版本冲突、原建设项目归档、未归属资产和空库的处理。
6. 切换企业、亮暗主题和窄屏，检查范围、导航及详情是否清楚。

评审场景控制属于原型辅助工具，正常产品流程中不需要选择“成功”或“失败”。场景切换、重置或刷新会重置演示内存状态。

## 演示范围

企业、会员规则、任务、资产版本、Agent 消息、发布结果和报告均为合成预置内容。原型不连接业务 API，不调用模型，不读取企业数据，不写入产品资料库；不证明真实构建、保存、发布、计算、专业质量或产品验收。

示例指标的 `1.2.0 → 1.3.0` 仅演示有业务含义的规则修订。A 企业真正的首购范围、观察期、退款处理及门店归属仍按获准资料核定。

本轮重点模拟统一入口、资料正文工作稿／启停／历史、预置指标与方法的候选差异和发布，以及任务贡献和版本使用。通用 SAP 指标／方法／IR 编辑器、资料附件与生效时间／范围的完整编辑尚未模拟；这些产品期望保留在 spec，不能从本 Demo 推断已经验证。进行中取消与迟到、真实权限和持久化也需后续工程证据。

源码为本目录的 `index.html`、`styles.css`、`app.js`。检查范围、已发现问题及准确候选身份见[准备记录](../../../openspec/changes/studio-phase2-unified-assets/result.md)。
