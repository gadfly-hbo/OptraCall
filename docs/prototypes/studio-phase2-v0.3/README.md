## 打开

直接打开[index.html](index.html)，或在仓库根目录运行本目录的静态预览：

```bash
python3 -m http.server 4189 --bind 127.0.0.1 --directory docs/prototypes/studio-phase2-v0.3
```

访问[本机预览](http://127.0.0.1:4189/)。与产品服务无关，不需要安装依赖。

## 审核重点

1. 从普通分析工作区直接发送门店首购会员复购问题，观察无需先进入 Studio 或手动挑选资产的默认体验。
2. 核对门店结果、分子分母、观察不足提示及“本次依据”；展开准确版本、合成数据和读取／采用的区别。技术调用证据按需查看。
3. 追问先核查哪家门店、核查什么，检查建议与证据的边界，再保存为 Case 决策草稿。草稿不代表采纳、执行或效果。
4. 从分析中的发现形成任务贡献，回 Studio 点击“核对并关联既有候选”，查看 UC／原报告／任务／基于版本；预览模拟发布并确认，再从“创建后续普通任务”进入完整分析、计算新版，对照右侧历史报告的旧结果和旧依据。
5. 在评审辅助场景中分别查看资产缺失、读取失败、正文不完整、冲突和不同企业。临时依据只能限定本任务，不代替企业正式标准。
6. 查看原有的基础建设、企业资料、SAP 指标／方法、两层整合、部分发布、UNKNOWN、归档接续及历史；切换亮暗与窄屏。

场景选择器仅供评审模拟，不是正常用户分析的必经步骤。刷新或重置会清空内存结果。

## 证据与限制

本原型会对内置合成行执行本地确定性计算；这比预置一个“已使用”状态多验证了口径差异对结果的实际影响，但仍不证明真实 Pi Agent 会选择、理解或正确应用资产。所有 Agent 回复、工具事件、资料资格和发布操作均是原型模拟，未调用真实 Pi／模型／业务 API，也不读写产品或企业资料库。

示例30天窗口、首购范围和退款规则仅用于评审，尚未成为目标企业的正式口径。当前组件不能作为通用业务计算引擎或产品实现复用要求。真实权限、公共生命周期、持久化和专业质量保留后续产品验收。

完整检查范围、发现、准确文件摘要及未验证项见[准备记录](../../../openspec/changes/studio-phase2-unified-assets/review-v0.3/result.md)。

## 合成算例核对

明细和示例口径在[fixtures.js](fixtures.js)。模拟企业于2026-01-01开业，本例声明覆盖所列会员自开业以来全部购买；首购队列为2026-09-01至2026-11-01前，数据截止2026-10-31 23:59:59（中国标准时间）。观察窗为首购后30日左闭右开，首购自身不算复购；跨店复购归首购店，未知身份排除并保留缺口。

| 门店 | 旧版1.2 | 新版1.3 | 比较资格 |
| --- | --- | --- | --- |
| 青鹭站 | 2/5，40% | 1/4，25% | 在本示例可比门店中优先核查 |
| 松渡站 | 3/5，60% | 3/5，60% | 可比参考 |
| 雁汀站 | 0/2，0% | 0/2，0% | 分母小于3，只描述不排名 |

新版排除已成功全额退款的订单并重找首购，因此同时影响复购分子与成熟队列分母。部分退款保留；订单和退款事件分别去重；恰第30日的购买在观察窗外。这里的最低样本数3和所有政策均只是交互算例，不是统计充分性或企业正式业务标准。

原 v0.2 未模拟的通用 SAP／IR 编辑器、附件与生效范围完整编辑、真实取消和迟到处理仍不由本次补齐；完整产品权限、持久化和实际工具接线继续按 spec 后续验证。
