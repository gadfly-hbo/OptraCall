个人资料

探索：Agent在工作中自选记录候选，人按需阅读、重点收藏、纠正或排除。无需每天写笔记，也不要求逐条审批；没有候选时也可正常工作。

候选是Agent声明，重点收藏是你的关注；两者都不证明内容正确。这里只阅读和管理资料，M4按需使用尚未实现。

方案审阅说明 · 当前产品差异与6项决定

本页问题：已保存的有效候选能否跨父任务状态与保存路径统一发现，原生失读后仍保留人的必要控制？用户已接受精简方向；v0.2具体合同与更新UI待审阅，本文件尚未成为产品。

当前M3已具备人工笔记、明确保留、版本／归档与来源查找。本页保留原入口和类别，新增的是拟定的Agent候选、原生引用收藏、独立纠正注记及排除；没有重做或完整模拟旧M3编辑／保留流程。原M3 Demo及其确认不被本页替换。

6项推荐A · 精简方向已接受，具体合同与UI待审阅

  1. D01 原生正文：候选正文仅来自Pi原生工具结果details，人的控制只记引用。已有持久能力可复用，避免第二份候选正文。待确认
  2. D02 精确身份：小型版本化声明、真实任务身份和精确原生引用；资料来源沿M3读取。防止把Agent自述当用户确认或真实归属。待确认
  3. D03 原任务自主记录：同一核准普通任务、同一轮Pi；有效返回仍待保存，成功结果精确回读才显示已记录。父任务取消不撤销此前有效保存的候选，明确迟到只进异常历史。修订待审阅
  4. D04 只读发现：各已保存路径的有效候选统一浏览；父任务状态与保存位置分别筛选，fork副本去重。不把保存路径当实时模型上下文。修订待审阅
  5. D05 人的控制：收藏仅关注，纠正追加独立注记。失读后，已有有效人的记录可支持取消收藏、排除／恢复；仍不能新收藏或加纠正，不修复来源。修订待审阅
  6. D06 保存与退出：一个操作标识兼事件标识，同一候选设定才检查冲突，独立意见顺序追加；不迁移M3，不双写候选。原子保存与容量限制属于后续产品实现。修订待审阅

Pi已有原语：同轮工具、原生工具结果details、会话历史／分支和只读内存投影。产品新增：候选声明格式与归属校验、个人资料汇总、人的引用操作与同条冲突规则；它们不是Pi现成记忆功能。保存位置仅据已保存task指针与磁盘快照标注，未持久导航的实时同步未知。

仅unmanaged普通任务拟注入候选工具；受管ordinary／protected、封闭出稿、text-only、独立冷读和历史只读不注入。页面浏览不创建会话。哈希核字节，不是防篡改认证；人的入口与状态不是身份认证或真实事实，重点收藏没有正文备份承诺。

本页只模拟内存规则，未接通真实身份／权限、JSONL、工具、磁盘保存／fsync、跨进程并发或2MiB容量限制。产品仍须保留单文件原子保存、同operationId回读、坏账只读和满额拒绝。M4消费、自动注入、学习评分、语义搜索及实际效果均未实现。
