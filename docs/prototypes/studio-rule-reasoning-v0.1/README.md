## 原型边界

- 全部企业、制度、会员、规则、来源、请求、报告及结果均为合成预置。
- 状态仅在本页面内存，刷新清空；原型脚本没有网络／API请求、SDK／模型调用、数据读取、实际发布或业务写回。页面只加载本地审核文件。
- 预置“成功”不是官方引擎实跑、专业核验或用户产品验收。规则支持范围及本机SDK行为留待未来I01验证。
- 单文件为 index.html／styles.css／app.js 的生成副本，编辑这三份源文件后重新生成；不是第二份产品源码。
- 原 v0.2 方案、模板及Demo未修改。本版沿原中性Studio、紫色主动作及亮暗tokens，增加最少规则与使用状态。

## 建议审核路径

1. **企业基础资产**：看三类总览、八模块、参考与内化，打开会员模型、原SAP、规则和事实。公开标杆信息与目标企业未知分开。
2. **建设基础资产（演示）**：保留默认项目，输入自然语言目标，进入预置任务；不创建项目、登记企业或启动模型。
3. **规则与核验**：查看候选r2、支持子集、事实条件与三类影响；点“查看预置核查”，打开4条虚构样本及限制。
4. **准确发布预览**：可取消，或模拟预览后变稿，确认按钮应失效。正常确认只更新内存中的合格组合。
5. **普通分析任务**：直接发送自然语言问题，查看预置目录、原文、规则调用和报告轨迹；不要求手工选规则。打开实际身份与前提详情。
6. **新版与历史**：先在发布前发送一次普通任务，发布r2后原任务仍r1；新建独立任务再发送才用r2。原报告R01始终r1／SAP1.0.0。
7. **贡献**：普通任务反馈可选仅本案，保存不改企业正式规则，也不自动运行维护任务。

## 受控样例

| 关系 | 状态事实 | 时间事实 |
| --- | --- | --- |
| M-01 | 正常 | 观察时点有效 |
| M-02 | 宽限 | 观察时点有效 |
| M-03 | 正常 | 观察时点有效；缺事实情境时改为缺有效期 |
| M-04 | 已退出 | 明确失效 |

虚构政策r1为“正常＋宽限”，r2为“仅正常”。相应SAP为1.0.0／1.1.0。r1预置3条符合、1条明确不符合；r2为2条符合、2条明确不符合。它们是政策情境变化，不表示旧版故意出错，更不代表Nike或目标企业真实政策。

缺M-03时间事实时，r2只显示1条已推出、2条明确不符合、1条未知，不输出完整有效总数。冲突情境M-02待核；只预览独立门店定义，排除资格规则、计数及其依赖。指标公式与聚合仍属于原SAP和计算工具，不在图中另定义。

## 评审情景

页面底部折叠“评审情景”仅为审核辅助，切换会明确重置内存，不是正常用户新步骤。包括正常、缺事实、规则冲突、不支持、来源撤回、推导未完成／取消、UNKNOWN发布、跨企业受限、空企业、归档只读、加载失败。

自定义编辑生成新候选并使旧检查／预览失效；预置核查不能用于任意稿。显式另存受控样例后才可查看该固定样例结果，已保存自定义原文在候选历史中保持待核。UNKNOWN发布保留同一请求，只能查原结果，禁止再次预览／确认同一未决发布。成功组合也不重复提交。
