## 审核路径

1. 默认进入 **36格全景**。六行视角、六列问题和36个具体含义均可见；窄屏在矩阵容器横向滚动。首批参考14格为R1六格、R2六格、R3的What与Why，其余22格并未隐藏，也不表示不适用或缺资料。
2. 分别点 **R1:What、R2:What、R6:What**，对比经营对象范围、业务对象关系、实际对象记录的片段与资产。每格只显示显式对应记录，没有按列通用片段兜底。
3. 在 **资料与资产** 分别检查13个资料准确版本、6项资产修订及六问摘要。打开同名会员资格制度的2025.1与2026.1，确认分版、分期间；打开未标注的经营目标访谈记录，确认保留材料且未自动填格。每份资料、每项资产可反查关联坐标。
4. 调整“当前查看高亮”，确认只影响临时高亮，首批参考14格不变。所有数字可下钻核对，列／格内重复引用不相加为全局总数，没有完成率或健康分。
5. **联合核查** 比较合法期间差异与同范围同期间疑点，模拟记录原工作项，不自动mark-issue。概念可独立定义，只有计算用途确实需要时才核Binding。
6. **普通使用** 直接发送自然语言问题，查看预置原catalog／read-source／reason轨迹与准确版本。无须先选格、补齐盘点或发布候选。查看历史R01，生成候选r2后旧依据不变；合格新发布是另一显式演示动作。
7. 底部 **评审情景** 检查无报告、仅候选、方法不可读、依据变化、缺映射、争议、空搜索、读取中／失败、损坏／未知格式及候选输入。报告不可读时框架仍可解释，企业证据和资料／资产数量显示未知。生成候选不恢复旧正式资格。
8. 查看浅／深色、390px及常见桌面宽度，Tab进入对话框，Esc关闭后焦点回到触发控件。

## 模拟边界与状态

- 全部企业、资料、片段、版本、原资产、工具轨迹和答复均为合成预置。无fetch、localStorage、产品API、SDK、模型调用或真实资料读取；所有动作只在本页内存，刷新清空。
- “生成／核查／发送／记录／发布”均为演示，不是实际使用回执；作者四项状态、治理身份和独立使用证据分列。
- 报告是现有business类Studio资产body中的可选reportProfile: "studio-coverage/1"待审方案。原revision／sources／deps不变；不改FoundationItem、foundation/1／2、SAP0.2或SourceRef。
- 建设侧候选可按输入资格查看；普通任务只可能消费当前合格正式报告。无报告或不可读时企业数量为未知，不偷用缓存或候选。静态36格及预置参考14格不是企业覆盖结果。
- 正式指针、formalReadStatus、候选读取与输入资格、方法读取状态分开保存。候选生成不修改旧正式存在性／读取状态／来源资格。只有显式成功可恢复相应transport error/loading；损坏、未知格式、依据变化和方法失权不能借候选生成恢复。
- 原报告R01固定盘点r1及当时原业务依据。新盘点／发布不改写它；历史元信息不证明旧正文当前可读。没有独立调查记录的空格仅说明本报告未标证据，不推出“尚未调查”或“不适用”。

### 审核发现与定点修订

非作者复核发现v0.2迁移矩阵时遗漏异常状态操作入口，原读取handlers仍在但无法从页面进入。现仅在异常提示旁恢复原文查看、修复边界及transport error/loading的显式重试／读取成功演示；不改变完整框架和未知计数。方法失权不提供读取成功入口，损坏／未知格式／依据变化仍不能借该动作恢复资格。此修订复用原机制，不新增读取服务。

### F5 窄屏矩阵修订

root最终浏览器发现390px下旧通用表格媒体规则比矩阵选择器更具体，导致矩阵压成490px、单格约47.5px，中文被挤为竖长布局。现仅提高矩阵专属宽度选择器优先级：桌面最小1250px保持不变，窄屏矩阵最小1070px，六列在自身容器滚动；不靠整页隐藏溢出掩盖。实际窄屏回核由主会话继续，原失败截图保留。
