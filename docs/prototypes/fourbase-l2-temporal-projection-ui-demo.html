A · 方案审阅：完整 L2 与首个 P1

方案说明，不是已安装能力

这一层用于整体确认。日常产品用户直接在下方任务提问，不需要选择阶段、组件或维护图谱。

完整 L2 希望解决什么

  • 业务语义组织

    后续待细化

    在后端用本体表达概念、指标、规则和适用范围，让 Agent 理解“净销售额包含什么”“门店与渠道同名是否同义”。原 SAP 与资料继续持有定义权威。

  • 来源、规则约束与冲突

    P1 先核来源

    保留来源性质、适用范围、冲突和未知；让 Agent 查原文判断规则是否适用。结构约束通过不等于业务正确，更不自动决定哪条规则胜出；完整约束检查后续细化。

  • 关系与事实演变

    P1 验证最小一角

    知识图谱组织对象、关系、来源与版本，保留支持、反对、依赖及生效／留存／更新差别。持续事实更新、实体对齐和更复杂演变按具体缺口继续研究。

  • Agent 按需结构化检索

    P1 只做工程对照

    经原 Pi 工具供 Agent 在授权范围内自主取用语义材料，再理解、核适用性和解释冲突。目标回答应主动说明关键口径与限制；Host不规定内部查询顺序或另造修正循环。

这些是完整 L2 的目标范围，尚待按能力补齐规格、结构决定与有效授权。不是全部已实现，也不表示完成某个后续阶段就已交付完整 L2。

Semantica

后端语义支撑优先路线

优先评估其本体／语义组织和知识图谱模块，组织概念、范围、规则、对象、关系、来源与版本，帮助 Agent 正确理解和适用。尚未实装；P1只验证固定发行版的最小来源／显式关系／时间／快照组合，不运行完整本体或规则检查。

Graphiti

有明确缺口再比较

侧重从持续事件组织实体、事实与关系，保留来源及变化历史。若持续更新、实体对齐或时间检索仍有Semantica最小路径未满足的具体缺口，再作同源比较。P1不运行Graphiti，不默认同时维护两个引擎。

二者在来源、关系、检索与时间能力上有重叠：Semantica也有双时间能力，Graphiti也支持实体／关系类型，不按“语义／时间”各自独占。原SAP、企业资料、M2与Case继续是权威来源；Pi继续唯一Agent运行入口。派生图不替人决定口径、取舍或自动改写历史。

本轮 P1 到哪里；哪些能力留待后续
P1 · 首个小切片整体确认后才开始隔离验证
  • 固定 Semantica 0.7.0，只在隔离合成材料中核来源、显式关系、时间、版本快照、持久重开与从源重建。
  • 与当前 L1 使用相同材料、问题和边界对照；如有语义损失或无增益，保留失败并收缩，不先写一套替代引擎。
  • 未来能力 · 未纳入 P1 完整本体治理、自动抽取、持续摄取、Graphiti 运行及正式产品接线。它们属于可能的后续能力，按实际问题另行细化；不是永久排除，也不是本轮已批准开发。

P1只验证接入底座的工程行为，不能据此或据预置界面声称 Agent 语义理解增强。完整后端价值要在后续检验 Agent 能否正确理解、适用规则和处理冲突，不能凭界面页或图节点数通过。
