2026-11-01。本次将反馈闭环、核算材料与版本回读、自动独立核算及主Agent修订、后台资源托管和性能优化一起固定交付。安装及实际采用的提交以界面／`/api/health` 中的运行构建信息为准；包版本号继续沿用，提交SHA区分本次版本。Git／CI与MacBook实际采用分别记录，本文不提前宣称已安装。

## 可以体验的内容

- 从企业业务资料、需求梳理和项目分析进入原决策看板，记录行动／反馈，再显式带入下一轮复盘或需求；原看板功能保留。
- 手动独立核算、固定材料全文／片段回读与下载、逐稿版本归属继续可用。
- 为符合条件的新任务开启自动核算后，独立Agent先核算再看作者稿，意见自动交回原主Agent；由主Agent自主修改、重算、保留或反驳意见，新稿再复查。Host只交材料、管权限和记录，不判断专业结论。

## 自动核算的使用条件

默认关闭时继续普通分析。要体验自动链，请在当前应用启动后**新建一个项目与任务，并在首次执行前开启自动核算**；当前环境需要能确认本项目没有旧未托管写入者。旧任务、重启后失去可信起点的任务和未知fork不能自动获得资格；遇到资格提示可关闭自动核算继续普通分析，已有文件与会话保留，不强制迁移。

开启自动核算使用受管环境，支持任务内Python／bash、并行与跨调用后台计算，正常交接等待计算结束；显式停止收回本任务资源，无法证实收尾时保留UNKNOWN。受管模式暂不开放用户执行扩展和已有／远程MCP，只读skill材料按现有规则提供；不开启自动核算的普通分析仍用原能力。没有新增专业计算器、固定分析套路或必填章节。

自动设置需要明确本次核算问题、源材料及要核算的 `060_reports` 报告路径，不会自动猜测任意文件就是最终报告。

## 当前结果的边界

工程检查、独立复核和1000调用完整技术验证已有记录；自动纠错的真实模型有限验证仍未通过专业标准：有成功纠错，也有重要错误连续漏报及核算自身错误。最终报告需要用户判断与核对，不能因显示“核算完成”直接视为结论正确。实验参考未通过，不加载为产品默认。没有经营系统自动派发或自动取数；行动与反馈仍由用户显式操作。

本次暂停新的模型全链路实验，改由用户实际体验并反馈，不把尚未完成的整包真实模型总验收写成通过。
