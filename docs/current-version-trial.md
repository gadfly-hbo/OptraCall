可以按实际需要体验以下增量，未体验的项目保持未验证：

- 从“战略与目标”直接与Agent讨论组织、部门或个人的方向。已有目标、策略与行动（GSA）可直接承接，平衡计分卡（BSC）在“按需工具”展开，默认不必先填战略表。
- 在“设置→使用用途”保存默认背景；本次工作可以明确不同用途。修改默认值应只影响新背景，不重写旧讨论、已确认目标或项目方案，也不增加资料权限。
- 明确资料项目和本次背景范围后，让Agent自主查找获准背景并按需读取；也可切为“仅使用我手选的资料”或明确排除。目录可见、正文实际读取和方法实质采用分别核对；无项目时仍可直接讨论，但不会开放其他项目背景。
- 按需选择、组合或更换战略方法，核对已有讨论、资料和来源保留。可要求说明候选方向、重要选择、依据、假设、未知和补证，观察是否合理解释目标贡献、必要条件、替代路径和因果证据限制。显示方法名称不证明专业使用正确。
- 核对候选内容并明确采用后，回原目标/GSA查看准确版本和来源，再沿原Case、Project轻量方案进入所选单个或多个Task，并明确由哪个Task承担综合。“仅确认并创建”不执行；“确认并开始”承接确认背景和既有权限，无需逐Task重抄需求或重复启动。
- 核对保存重开、旧准确版本、资料不足、停止后明确续接及重复操作的结果。范围或版本冲突应保留输入和选择，不暗换最新版或自动重放。经营选择、行动授权、实际发生和效果验证继续沿原记录分别维护。

本轮工程没有代跑自由模型或真实业务资料实验。自然语言讨论、实际方法使用、专业与因果正确性需由真实使用另核；经营效果依真实行动和成熟观察窗口判断。工程通过、双机采用和体验准备均不等于用户最终产品验收。

## 自动核算的使用条件

默认关闭时继续普通分析。要体验自动链，请在当前应用启动后**新建一个项目与任务，并在首次执行前开启自动核算**；当前环境需要能确认本项目没有旧未托管写入者。旧任务、重启后失去可信起点的任务和未知fork不能自动获得资格；遇到资格提示可关闭自动核算继续普通分析，已有文件与会话保留，不强制迁移。

开启自动核算使用受管环境，支持任务内Python／bash、并行与跨调用后台计算，正常交接等待计算结束；显式停止收回本任务资源，无法证实收尾时保留UNKNOWN。受管模式暂不开放用户执行扩展和已有／远程MCP，只读skill材料按现有规则提供；不开启自动核算的普通分析仍用原能力。没有新增专业计算器、固定分析套路或必填章节。

自动设置需要明确本次核算问题、源材料及要核算的 `060_reports` 报告路径，不会自动猜测任意文件就是最终报告。

## 当前结果的边界

工程检查、独立复核和1000调用完整技术验证已有记录；自动纠错的真实模型有限验证仍未通过专业标准：有成功纠错，也有重要错误连续漏报及核算自身错误。最终报告需要用户判断与核对，不能因显示“核算完成”直接视为结论正确。实验参考未通过，不加载为产品默认。没有经营系统自动派发或自动取数；行动与反馈仍由用户显式操作。

本次暂停新的模型全链路实验，改由用户实际体验并反馈，不把尚未完成的整包真实模型总验收写成通过。
